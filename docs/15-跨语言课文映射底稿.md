## 1. 复用规则：什么抄、什么必须新写

### ✅ 可以直接复用的（照搬，改语言相关的词）

| 复用什么 | 从哪儿来 |
|---|---|
| **课文骨架**：钩子 → 概念 → 真跑示例 → 常见坑 → 一句话对照表 → 小任务 | 对齐的那节 Python 课（见 §2 表） |
| **教学节奏**：先给一个「看得见的东西」，再给它起名字 | 同上 |
| **坑的「类型」**：边界少算一个、类型对不上、忘了收尾、中文引号 | 同上 |
| **猫娘语气**：本喵 / 主人 / 小鱼干 / 大肥鱼，比喻一律走鱼塘世界观 | `docs/09` §1 |
| **题目配比与字段**：choice / fill / code / codefill / codefix / codewrite | `docs/09` §2.2、§3 |
| **术语映射表** | 由 `gen-batch` 自动注入，**不要手抄**（`docs/09` §4 已说明） |

### ❌ 绝不能照搬的（这四种抄过去就是错的）

1. **代码本身**。一行都别抄。Python 的 `for i in range(3):` 在 C 里是 `for (int i = 0; i < 3; i++)`，在 Java 里还要写类型。
2. **报错原话**。Python 的 `TypeError` 在 C 里根本不存在 —— C 的同类错误往往**编译期**就拦下了，报的是 `error: ...`。**每一条报错原话，必须在你自己的机器上真跑出来再抄**（`docs/09` 的铁律）。
3. **「翻译官喵怎么工作」那一课**。Python 是逐行解释，C 是整套编译成 exe 再跑，Java 是编译成字节码再由 JVM 跑 —— 这三课的**心智模型完全不同**，是最不能复用的一课。
4. **语言特有概念**：C 的指针与内存、Java 的类与包、C++ 的引用与命名空间 —— Python 侧没有对应物，得纯新写。

### ⚠️ 一条容易犯的错

不要用 Python 的说法去解释别的语言。比如：
- ❌「C 的数组就像 Python 的列表」→ 会误导（C 数组长度写死、不检查越界、没有 `append`）
- ✅「C 的数组是一排**钉死的**猫粮碗，碗数在开的时候就定死了，Python 的列表是**会自己长大**的储物柜」

**办法**：讲差异时，先给这个语言自己的比喻，再补一句「它和 Python 的 XX 不一样在哪」。

## 3. 每种语言的「第一章就要立起来的心智模型」

这一节是每门语言前两课的灵魂。**必须讲对，讲错了学员后面全歪。**

### C

- **编译型**：一口气把整份代码翻译成机器能直接跑的 `.exe`，再运行。**翻译不过去就一个都不跑**（Python 是跑到哪错哪）。
- **好处要讲透**：很多错在「翻译」阶段就被拦下了 —— 名字打错、少个分号、类型对不上，**程序根本生不出来**。这和 Python「跑起来才炸」是一组鲜明对比。
- **必须自己管一切**：变量要先说要装什么类型，数组要自己记住几个碗，字符串是 `char` 排成的排 —— **没有 Python 那种「自动长大」**。
- **`main` 是入口**：程序从 `main` 第一行开始跑。

### Java

- **两段式**：先 `javac` 编译成**字节码**（`.class`），再由 JVM 跑。字节码不是给机器看的，是给 JVM 看的 —— 所以同一份 `.class` 在 Windows 和 Mac 上都能跑。
- **强类型 + 一切皆对象**：连「方法」都得住在**类**里。第一个程序就必须写 `public class 名字`。
- **一条硬规矩**：**文件名必须和 `public class` 的名字一模一样**（`Hello.java` 里只能有 `public class Hello`）。这是新手第一天最容易摔的地方。
- **入口签名是固定写法**：`public static void main(String[] args)` —— 先当口诀背下来，含义后面课再拆。

### C++

- **也是编译型**，流程和 C 几乎一样（`g++` 一步到位或分两步）。
- **比 C 多给的**：`string`（会自己长大的字符串）、`cin/cout`（不用记格式符）、`vector`（会自己长大的数组）。**第一课就要让学员感受到「终于不用自己管了」**。
- **命名空间**：`using namespace std;` 这句先当「把工具箱打开」用着，§12 再讲原理。

## 4. 各语言 stage1 特有坑清单（省时间的重点）

> 写课文时从这里挑；写题库 `codefix` 时更要挑这里 —— **这些才是别处学不到的**。
>
> ⚠️ 凡是要写进课文的**报错原话**，仍必须自己真跑出来（见 §5）。

### C 特有

| 坑 | 说明 |
|---|---|
| 少分号 / 少括号 | 编译期直接拦下 |
| `printf` 格式符与类型对不上 | `%d` 配 `int`、`%f` 配 `double`、`%c` 配 `char`；配错了不报错但**印出垃圾**（这条特别适合当改错题） |
| `scanf` 忘了取地址 `&` | 新手最经典的摔法 |
| 数组越界**不报错** | 和 Python 的 `IndexError` 形成鲜明对比 —— C 会**默默读错的内存** |
| 字符串是 `char[]` 不是 String | 比较要用 `strcmp`，不能用 `==`（`==` 比的是地址） |
| 整数除法 | `5 / 2` 得 `2` —— 和 Python 的 `2.5` 不同，这一条必须讲 |
| `int main` 返回值 | 常规写法 `return 0;` |

### Java 特有

| 坑 | 说明 |
|---|---|
| 文件名与类名不一致 | 编译直接失败 |
| 忘了 `String[] args` 或写错 `main` 签名 | 能编译过但**跑不起来**（说找不到 main） |
| 字符串比较用 `==` | 要用 `.equals()`；`==` 比的是「是不是同一个对象」 |
| `int` 与 `double` 混算 / 整数除法 | 同 C，`5 / 2` 得 `2` |
| `Scanner` 读取的坑 | `nextInt()` 之后接 `nextLine()` 会读到空行 —— **经典中的经典**，非常适合改错题 |
| 类型不匹配 | 强类型，`int x = "3";` 编译期就红 |

### C++ 特有

| 坑 | 说明 |
|---|---|
| 少了 `#include <iostream>` / 拼错头文件 | 编译期报「不认识的 cout」 |
| 少了分号 | 同 C |
| `cin >>` 读字符串遇到空格就停 | 读一整行要用 `getline`（和 `cin >>` 混用还有坑） |
| `using namespace std;` 忘了写 | 得改写成 `std::cout` |
| 整数除法 | 同 C |
| 引用 `&` 与取地址 `&` 长得一样 | 语义完全不同，讲引用时要点出来 |

## 5. 铁律（一个字都不许省）

1. **每一段代码都必须真跑**。`check:samples` / `check:questions` / `check-bank` 会真的起编译器，抄错一个字就红。
2. **每一条报错原话都必须现场跑出来再抄**。不同语言、不同编译器、不同版本的措辞完全不同。参考 `docs/09` 的相关章节与本项目 `scripts/审计/` 的实测台。
3. **起编译器请排队**：跑自检前先拿锁 ——
   `node scripts/verilock.mjs shell <你的标签> "npm run check:samples"`
   写作可以并行，**起编译器必须排队**，否则几路的编译器互抢 CPU 会跑出**复现不出来的假红**。
4. **中文标点、花括号样例输出**等老坑，`docs/14` §5.4 与 §9.7 有完整记录，**写题库前必读**。
5. **不确定的版本行为**：能真跑就真跑；跑不了就**不写**，别写「据说」。

## 7. 「代码一行都不许抄」怎么**量**（2026-09-16 实测，stage1 全量）

§1 的复用规则是主人拍板的，可它听起来像一句没法验证的口号。它是能量的。

**量具**：`node <workspace>/_probe-crosslang-summary.mjs 1`（仓库外，`stage1` 传 1/2/3）
**判据**：同号课的代码块做行级比对，**同时报「相似度」和「实际重合行数」**。

> ⚠️ **只看相似度会得出错误结论**（本喵第一支探针就栽在这）：它报过 cpp↔java 变量课
> **1.00**，看着像铁证如山的抄袭 —— 打出原文一看，那是**一行** `int fish = 3;`，
> 两种语言本来就一字不差。**一个 1 行的块完全相同时相似度必然是 1.00，这个数字没有意义。**
> 所以判据必须是「重合 ≥5 行」才算实质重合。

**stage1 全量实测结果（c/cpp/java/python 四个语言、全部同号课、共 200+ 对）**：

| 观察 | 数据 |
|---|---|
| **python ↔ 任何一门语言** | **相似度全部 0.00、重合 0 行**（块大小非零，排除「没抽到代码」） |
| 唯一高分对 | 全部落在 **C ↔ C++** |
| 最高的一对 | `c/07 ↔ cpp/07` = **0.58、重合 7 行** |

**最高那一对的原文**（判例，以后拿这条比着看）：

```c
#include <stdio.h>          |  #include <iostream>
                            |  using namespace std;
int main() {                |  int main() {
    int fish = 0;           |      int fish = 0;
    do {                    |      do {
        fish = fish + 1;    |          fish = fish + 1;
    } while (fish < 3)      |      } while (fish < 3)
    printf("%d\n", fish);   |      cout << fish << endl;
    return 0;               |      return 0;
}                           |  }
```

**判定：不是抄。** 重合的 7 行是 `do { } while (cond)` 这类**两种语言写法本来就完全相同**的骨架
（C++ 继承了 C 的 do-while，没有第二种写法）；而**该不同的地方一行都没含糊** ——
`<stdio.h>` ↔ `<iostream>`、`printf` ↔ `cout << endl`。
真「逐行翻译」的样子是**连输出语句都长得一样**，这里没有。

**留一句给主人裁决的话**：C↔C++ 的骨架行是**字节相同**的，因为这两门语言在那几行上就是同一门语言。
要把它压到 0，只能靠给同一课换变量名/换个例子 —— 那不是「语言差异」，是噪声，
而且会毁掉 §2 要的「同一件事在两种语言里长什么样」的对照。
**本喵按「不抄」判，但这个边界值由主人定。**

**stage2 / stage3 开写后必须重跑这一支**（同一门语言的高阶段课，模板化的诱惑比 stage1 大得多）。
