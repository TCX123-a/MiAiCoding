## §2 三个开源插件：借什么、不借什么

### 2.1 三家各自的一句话核心

| 项目 | 架构一句话 | 核心机制 | 我们要的那一口 |
|------|-----------|----------|----------------|
| **lxj5820/dsh-boot-animation** | 宿主把覆盖层脚本注入 DSH 页面 `<head>`，页内 `div` 盖满视口（z-index 上到 int32 上限） | 无 autoplay 属性、显式 `play()` 驱动；**首帧解码到位才显形**；退场是**片尾剩余时间驱动的整层交叉溶解**；**双条件交接**（片子放完 ∧ 内核就绪，谁后到谁触发）；全链路毫秒上界（10s/6s/1.2s/20s/15s）；素材要求 moov 前置（faststart） | 交接节奏 + 首帧门控 + 兜底上界表 |
| **NativeDog1/dsh-boot-animation** | 覆盖层浮在始终运行的宿主界面上，**从不隐藏宿主** | 「什么时候播」= 纯函数 `decidePlay()` + 单一记账 `recordDecision()`；**先记账后播放**（崩溃也不重播）；无任何淡入淡出（硬切）；素材前置检查只读 64KB 判 faststart；媒体响应 no-cache+ETag | 决策纯函数 + 先记账后播放 + 素材检查法 |
| **KDDKBD/DeepSeek-splash-animation** | 宿主首帧注入 3 条遮盖 CSS + 10 秒守卫脚本；覆盖层 portal 到 body | 最简链：`ended` → **渐隐 300ms（CSS ease）** → 同一时长后卸载；自动播放降级链（被拒 → 静音重试 → 放弃）；救援定时器（时长+5s / 未知 120s） | 渐隐参数（300ms ease）+ 单向退场状态机 |

### 2.2 搬过来的设计（逐条带出处）

| # | 设计点 | 出处 | 我们怎么用 |
|---|--------|------|-----------|
| 1 | **双条件交接**：媒体播完 ∧ 主界面就绪，谁后到谁触发；先到的一方原地等 | lxj5820 `boot-screen.js` maybeEnter | 交接条件 = `splashDone` ∧ `mainReady`（§4.3） |
| 2 | **首帧门控**：视频初始透明度 0，解码数据到位（readyState≥2 / loadeddata / canplay / rVFC / timeupdate 五路取先到）才显形；`play()` 的 Promise 兑现**不算数**（它只代表已开始加载） | lxj5820 whenFramePresents | splash 页内同款五路判定（§5.2） |
| 3 | **有界兜底链**：装饰层任何失败都必须放行，且每一环有毫秒上界 | 三家（10s/6s/20s/15s；25s 看门狗；error 逗留 8s） | §7 兜底矩阵，全部收敛到 `handoff()` |
| 4 | **退场 = 整层一次淡出**，跳过也走同一条淡出路径（不是快进、不是立即消失） | kddkbd dismiss→out→done | 250ms CSS 淡出后销毁（§5.2） |
| 5 | **先记账后播放**：「今天/这次播过了」在请求播放**之前**就落账，中途崩溃也不重播 | NativeDog1 `recordDecision()` | `decideSplash()` 判定后立即落 `lastPlayedDay`（§8） |
| 6 | **单一决策纯函数 + 单一记账**：「什么时候播」可在测试里穷举，而不是渲染界面反推 | NativeDog1 `decidePlay()` + 31 项矩阵测试 | `decideSplash()` 纯函数 + 单测穷举（§8/§12） |
| 7 | **faststart 是硬规范**：moov 不前置时首帧要读完整个文件才出画面（实测 8~10MB 偏移→32 字节的差别）；检查法=只读前 64KB | 三家共识 + nativedog1 clip-registry | 素材入库检查（警告不阻断），§6.3 |
| 8 | **失败不打扰、但必须可诊断**：失败在界面上沉默跳过，把「首帧时刻/错误码/放弃时刻」留在日志与时间线里 | nativedog1 四条无条件日志 | 启动时间线埋点（§9.2） |
| 9 | **不设「不能退出」的模式**：kddkbd 的 `skip:'never'` 叠加「元数据前无定时器」= 永久黑幕（真洞） | kddkbd 反面教材 | 跳过**永远可用**，不进配置（§5.3） |

### 2.3 明确**不借**的（架构不同，照抄会南辕北辙）

- **z-index 军备 / portal / 宿主注入**：它们是「页内覆盖层」插件，一辈子在和宿主 CSS 层叠上下文打架；我们是独立顶层窗口，整类问题天然不存在。
- **静音解锁舞蹈 / 点击开声音两步走**：那是浏览器的用户手势政策产物。Electron 44.3.0 的 `autoplayPolicy` 默认值**本来就是** `no-user-gesture-required`（已按本机 `electron.d.ts` 核对）——带不带声纯粹是产品选择，不是平台限制。跳过因此可以做成「一点就走」。
- **会话语义**：「每会话只播一次」在桌面应用里坍缩——每次启动就是一个新进程，所以选项退化为「每次启动 / 每天一次」（§8）。
- 两处 README 与代码不一致的坑（lxj5820 的缓存策略与「重启才生效」说法）已按代码为准，不引用过时口径。

## §3 现状盘点（决定方案形状的六件事）

1. **主窗今天本来就不闪白**：`show:false` + `ready-to-show` 才显形（`src/main/index.ts:419,446`）。开屏要接管的不是「防白屏」，而是**「双击图标 → 主窗可见」之间那段无反馈的黑箱等待**——18.6MB 未压缩 bundle 解析 + wall-壁纸挂载的 2~3 秒。这是整个功能的价值所在。
2. **仓库零先例**：第二个 `BrowserWindow`、`transparent`、多 preload、第二个 HTML 入口——全是首次（§11 清单里每一处都按「首次」标注了要实测的加载路径）。
3. **部署口径**：桌面版=整份 Electron 发行目录，部署脚本**只换 `out/` 一棵树**；`resources/` 从不随包；`process.resourcesPath` 全仓零使用。「素材放仓库 `resources/`」的直觉在本仓库**不成立**。
4. **协议出生锁**（三次实锤的教训）：`miai-wall://` 的 handler 必须早于**任何窗口出生**，晚了该窗口所有请求 `ERR_UNKNOWN_URL_SCHEME` 且 reload 救不回（而主进程 fetch 却正常——最难查的静默坏法）。
5. **四条闸门会管到新文件**：`ipc-wiring.test.ts`（只读 `src/preload/index.ts` 与 `src/main/index.ts` 两个文件）/ `vitest.config.ts` include 白名单（新目录不登记=测试静默不跑）/ `copy.test.ts`（扫 `src/**` 中文；`.html` 不在扫描面）/ `wall-glass.test.ts`（玻璃令牌 9 文件 15 处+全库 opacity=46 精确账）。
6. **既有 CDP 探针体系（~25 个脚本）按「第一个 page target」取窗口**——多出来一个开屏窗会污染它们（探针附错窗口、红绿全不可信）。回归通道必须统一上 `MIAI_NO_SPLASH=1`（§10）。

## §4 总体设计

### 4.1 两个窗口，一张图

```
┌────────────────────────────────────────────────────────┐
│ 开屏窗口 splashWin（透明 · 无边框 · 置顶 · 不进任务栏）      │
│  ┌──────────────────────────────────────┐              │
│  │ splash.html：不透明品牌底 → 视频 → 提示行  │              │
│  └──────────────────────────────────────┘              │
│  职责：只做「好看与体面地等待」；不碰任何业务逻辑              │
└────────────────────────────────────────────────────────┘
          ↓ 播完/跳过/失败 → 淡出 250ms → 销毁
┌────────────────────────────────────────────────────────┐
│ 主窗口 mainWindow（隐藏加载 → 交接时刻才 show）              │
│  职责：照常加载（这是要掩盖的对象）；隐藏期间壁纸自动暂停      │
└────────────────────────────────────────────────────────┘
```

### 4.2 启动时序（写死顺序，逐条有理由）

```
whenReady
 ├─ 既有全部初始化（IPC / 媒体回采）…等（原样不动）
 ├─ primeWallProtocol()                    ← 必须早于一切窗口（出生锁）
 ├─ mainWindow = createWindow()            ← 先建主窗；show:false，但**不自动 show**
 │                                          （ready-to-show 改为「记一笔就绪」由交接状态机消费）
 ├─ plan = decideSplash()                  ← 纯函数：开关/频率/素材/低配/旗标（§8）
 ├─ if plan.action === 'play':
 │    ├─ splashWin = createSplashWindow()  ← 建开屏窗（§5.1 全选项表）
 │    ├─ splashWin.loadFile('splash.html')→ ready-to-show → show()（先出画面）
 │    └─ 装表：事件、跳过、计时器、时间线
 ├─ mainWindow.load()                      ← 紧随其后立即开始加载（见下）
 └─ …（无开屏时：mainWindow.load() → ready-to-show → show()，原行为）
```

**为什么主窗先建、开屏后建**（对抗复核逮出的两个 blocker，必须按此顺序）：

1. **零窗口瞬间会退出整个应用**：`window-all-closed` 在非 mac 直接 `app.quit()`（`index.ts:982-984`）。若开屏先建，任何「开屏异常销毁而主窗未建」的瞬间 = 应用秒退（症状是「素材坏了但表现为闪退」）。主窗先建后，从第一个窗口诞生起**永远有窗口**。
2. **`applyNativeTheme` 的 for-all-windows 循环会摸到开屏窗**（`index.ts:507-514` 给每个窗口刷不透明背景色 + WCO 标题栏色）——建窗顺序让首次调用天然扫不到开屏窗；另在循环里**再显式跳过 splashWin** 作第二道防线（防 `config:save` 运行期命中）。

**为什么主窗 load 紧接着立即开始**：掩盖加载是开屏的**目的**——把加载启动推迟到开屏首帧之后（省一点点抢 IO）会让主窗来不及就绪，交接时反倒要多停几秒最后一帧（§4.3 B4），得不偿失。触发点做成 A/B 旋钮（`MIAI_SPLASH_ARM=2` 可在实施期量一把），默认臂 1 = 立即加载。

### 4.3 交接状态机

```
状态：splashDone(媒体真实播完=ended | 跳过=skip | 失败=error/timeout | 到点=maxMs)
      mainReady (ready-to-show 已触发，一次性事件→建窗时立刻缓存成 promise/布尔)
      mainFailed(主窗 did-fail-load / render-process-gone)

规则（谁后到谁触发，永远走同一个 handoff()）：
  splashDone ∧ mainReady        → handoff()
  splashDone ∧ ¬mainReady       → 视频停在最后一帧继续等；
                                  超过 1.2s 出现「加载中…」小提示（防「静帧=卡死」观感）
  ¬splashDone ∧ mainReady       → 开屏照常播到自然结束（不提前交接——播完才体面）
  mainFailed（任意时刻）         → mainReady 视为 true + 记日志 → 走 handoff()
  总硬顶 15s（墙钟）            → 无条件 handoff()（主窗没就绪就显示主题底色，如实记录）

handoff()（幂等单入口，顺序写死）：
  ① 确保主窗已建（恒成立）且 show() → 主窗拿到焦点
  ② 通知开屏页：开始淡出（页面内 CSS opacity，250ms）+ setIgnoreMouseEvents(true)
  ③ 主进程自持计时器：250ms + 150ms 余量后 destroy() 开屏窗（**不依赖渲染层回执**——
     渲染层死了也照常销毁，销毁即兜底）
  ④ 广播 splash:done（渲染层放行「启动静默期」延迟的初始化，§9.3）+ 记时间线
```

**渐隐为什么用页面内 CSS、不用 `win.setOpacity()`**：复核按 Electron 44.3.0 源码核对——`setOpacity` 在 Windows 走 `SetLayeredWindowAttributes`，会把窗口**永久改成 layered 窗口**（一次 250ms 的渐隐留下一辈子的原生副作用），且与逐像素透明窗口的叠加行为在本仓库无先例。页面内 CSS 是同一条合成器动画，零原生副作用；「摧毁动作」由主进程计时器拥有，永不悬挂。

### 4.4 状态机数值（**【待 2G 实测定标】**）

| 计时器 | 起算点 | 默认值 | 到点动作 |
|--------|--------|--------|----------|
| 媒体死线 | splash 窗 show | 6s | 素材一直没元数据 → 记 `no-frame` → handoff |
| 卡顿判据（stalled） | 播放中 | `currentTime` **连续 2s 不前进** | 单次只记诊断；连续两轮才 handoff（防一次读盘抖动掐掉整段开屏） |
| 开屏最长播时 maxMs | splash 窗 show | 8s | 视频暂停 + 淡出 → handoff（素材再长也拖不死启动） |
| 静帧提示 | 进入 hold | 1.2s | 页面出「加载中…」提示 |
| 总硬顶 | splash 窗 show | 15s | 无条件 handoff（**墙钟计时**，休眠唤醒后不累积漂移） |
| 淡出 | handoff | 250ms（CSS ease） | +150ms 余量后 destroy |

## §5 窗口与页面规格

### 5.1 开屏窗口选项全表（每一项带理由）

```ts
new BrowserWindow({
  width: 1280, height: 720,          // 16:9；再与主屏工作区×0.85 取小；DIP 单位
  show: false,                        // 就绪才显形（沿用主窗防闪方案）
  transparent: true,                  // 【待拍板#6】淡出溶解 + 视频比例不符时留边透桌面
  frame: false,                       // 透明窗在 Windows 必须无边框
  resizable: false, movable: false,   // 开屏不是给人摆弄的
  minimizable: false, maximizable: false, fullscreenable: false,
  skipTaskbar: true,                  // 不进任务栏（已知行为：这期间 Alt-Tab 找不到它，≤8s，别当 bug）
  alwaysOnTop: true,                  // ★必须有：主窗 show() 会激活并抬到普通窗之上，
                                      //   开屏不置顶则淡出被盖住＝静默退化成硬切
  hasShadow: false,
  focusable: /* 保持默认 true */,      // ★不许设 false：Windows 上 focusable:false 隐含 skipTaskbar
                                      //   且收不到键盘，「任意键跳过」会被杀死
  backgroundColor: '#00000000',       // 透明底（#AARRGGBB 合法）
  roundedCorners: false,              // Win11 无边框窗默认带 DWM 圆角，会裁掉直角视频的四角；实测为准
  // paintWhenInitiallyHidden：★不许设置——保持默认 true。
  //   一旦设 false，ready-to-show 永不触发，整个交接状态机失去主窗就绪信号（且静默）
  webPreferences: {
    preload: join(__dirname, '../preload/splash.js'),  // 极小专用 preload（§5.3）
    contextIsolation: true, nodeIntegration: false, sandbox: true
  }
})
```

**尺寸与定位**：建窗前算好——目标 1280×720，与「主屏 `workArea` × 0.85」取小、保持 16:9、手动居中于主屏工作区（多显示器/高 DPI 下不靠系统猜）。
**不做运行时改尺寸**：复核 blocker——Windows 上 `resizable:false` 的窗口 `setSize` 只能变大不能变小（还静默不报错）。所以**尺寸一次定死**，视频用 `object-fit: contain` 适配（比例不符处露透明/底色边），不做「按视频元数据缩窗」。

### 5.2 splash.html（单文件内联 · 放 `src/renderer/public/`）

**放 `src/renderer/public/` 的原因**：Vite 把 `public/` **逐字拷贝**进 `out/renderer/`——正好落在「只换 out/ 一棵树」的部署口径里，dev 与打包两条路径同构（`/splash.html` / `loadFile(join(__dirname,'../renderer/splash.html'))`）。方案草案 v0 曾写 `src/splash/`——那**不在 renderer 构建根内**，构建产物里根本不会有这个文件（打包版必白屏的 blocker）。
页面是**独立文档**：自带 CSP meta（主页面 `index.html` 的 CSP 不继承），`media-src` 放行 `miai-wall:`。

**页面三层结构**（自上而下）：

```
① 不透明品牌底（t=0 就画上，纯 CSS）        ← 防「透明洞」：窗口显形到视频出帧之间，
                                              用户看到的是底色，不是自己的桌面
② <video>（宽高 100%，object-fit:contain）   ← 初始 opacity:0；解码到位（§2.2 第 2 条五路判定）
                                              才「显形」（短淡入），杜绝黑块/半帧
③ 提示行：跳过提示 + 「加载中…」（按需出现）    ← 文案见下
```

**材质**：品牌底色建议取深海蓝黑（与现有夜间色系同族，具体色值素材到了配）。**fit 默认 `contain`**（不裁切品牌画面）；素材若按「满屏沉浸」设计，可改 `cover`（实施时按素材定，一个 CSS 类的事）。

**文案与闸门**：`splash.html` 是 `.html`，**不在 `copy.test.ts` 扫描面**——这是文案真源的第一条缝。处理：新加一条静态断言（照 `index.html <title>` 先例）把 splash 页内的中文串钉死，改文案必须过闸。

### 5.3 跳过（三条腿，全部幂等）

| 通道 | 覆盖 | 说明 |
|------|------|------|
| 页面 `pointerdown` / `keydown`（任意键）→ 专用小 preload `skip()` | 鼠标 + 触屏 + 键盘，**页面活着时全收** | `sandbox:true` 的 preload 只能用 `ipcRenderer`/`contextBridge`，刚好够 |
| 主进程 `webContents 'before-input-event'` | 键盘，**首帧前（页面还没解析）也有效** | 只收键盘（已核对） |
| 主进程 `webContents 'before-mouse-event'`（滤 `mouseDown`） | 鼠标，首帧前兜底 | Electron 44 已有此事件（已按本机 d.ts 核对） |

- 多路来源会重复触发 → 主进程侧 `skip()` 处理**幂等**（handoff 单入口天然吸收）。
- **不设 skipEnabled 配置**——永久可用（§2.2 第 9 条的教训）。
- 透明窗口**不接受点击穿透**（Windows 透明像素照样命中窗口）——对我们是好事：全窗任意点=可跳。

## §6 素材管线

### 6.1 存放位置

| 来源 | 路径 | 随不随包 | 说明 |
|------|------|----------|------|
| **用户素材（本期主力）** | 便携版：`<咪爱编程>/data/splash/`；安装版：`%APPDATA%` 用户目录下同名 | 不随包，**天然在仓库外** | 直接把 mp4 丢进这个文件夹即生效；部署换 out/ 树不碰它 |
| 内置默认素材（**后议**，【待拍板#5】） | `src/renderer/public/splash/` | 随包（经 out/ 树） | 素材交付后再定；要求 ≤6MB |

多文件规则：扫 `*.mp4 / *.webm / *.m4v / *.mov` 按文件名排序取第一个（多素材随机是之后一行代码的扩展，本期不做）。

### 6.2 读取方式：**复用 `miai-wall://` 协议，不新开 scheme**

`miai-wall://` 已具备本需求的一切（Range/206/416 流式、CORS、MIME 表、路径围栏含 `%2E%2E` 拦截）——只要把 `data/splash/` 加进协议的**白名单读取根**（现为壁纸目录清单，`catalog.ts` 的活读口）。
不新开 scheme 的理由：新 scheme 要在 ready 前登记特权 + 一套新 handler，多一套出生锁风险，收益为零。
**缓存语义保持现状 `no-store`**：`miai-wall` 现行口径防的是「播放器中途换元素留下截断体毒缓存」；素材 ≤6MB 本地读，重下代价可忽略，不学 NativeDog1 的 immutable 建议。

### 6.3 素材规格（硬约束，入库检查）

| 项 | 要求 | 理由 |
|----|------|------|
| 容器/编码 | MP4 / H.264 (**8bit 4:2:0**) | 本机唯一实测可播格式；10bit/H.265/AV1 在老核显上掉软解 |
| **faststart** | **moov 必须前置**（`-movflags +faststart`） | 不前置=首帧要读完整个文件才出画面（三家实测 8~10MB→几 KB 的差别） |
| 分辨率 | ≤720p（1280×720） | 窗口上限 720p，更高纯浪费解码 |
| 帧率 | 24~30fps | 60fps 解码成本翻倍 |
| 时长 | ≤5s | 开屏超 5s 就嫌长；且 maxMs=8s 封顶 |
| 体积 | ≤6MB（建议 ~2MB / 3Mbps） | 首读量与磁盘占用 |
| 容器检查 | 读**前 64KB** 判 moov/mdat 先后（nativedog1 的做法） | 不达标**警告不阻断**（如实记录，素材是你的） |
| 音轨 | 有/无均可 | 无音轨素材走静音路径，不需要代码分支 |

### 6.4 素材缺失 = 跳过开屏

`data/splash/` 为空 → `decideSplash()` 判 `no-material` → 直接走无开屏路径（**这不是错误**，是正常分支；不弹任何提示）。
探针里钉两条反静默断言：**默认素材存在性** + **实际播放过视频**，防止「素材缺失兜底」把「开屏根本没播」伪装成全绿。

## §7 兜底矩阵（总表：全部收敛到 `handoff()`）

| # | 情形 | 检测方式 | 动作 |
|---|------|----------|------|
| 1 | 配置为关 / 今天已播 / 旗标跳过 / 低配 | `decideSplash()` 建窗前判定 | 不开屏，原路径直达主窗 |
| 2 | 素材缺失 / 素材目录不可读 | 建窗前扫描 | 同上 |
| 3 | 协议加载失败（404/白名单外） | `video 'error'` | 记 code → handoff |
| 4 | 元数据 6s 不出 | 计时器 | 记 `no-frame` → handoff |
| 5 | 播放中卡顿 | `currentTime` 连续 2s 不前进 | 单次记诊断；连续两轮 → handoff |
| 6 | 视频播完 | `ended` | `splashDone`（正常路径） |
| 7 | 用户跳过 | 三条腿任一（§5.3） | `splashDone` |
| 8 | 开屏超 maxMs | 计时器 | 暂停 + 淡出 → handoff |
| 9 | 开屏页渲染进程崩溃 | `render-process-gone`（挂在 splashWin） | 直接 destroy → handoff（主窗恒在，无退出死角） |
| 10 | 主窗加载失败 | `did-fail-load` / `render-process-gone`（挂主窗） | 记日志 + `mainReady := true` → handoff（显示主窗现状；如实记录，不假装成功） |
| 11 | 主窗迟迟不就绪 | 总硬顶 15s（墙钟） | 无条件 handoff（主窗未就绪=显示主题底色窗；这是设计内降级，不是 bug） |
| 12 | 第二次点图标（开屏期间） | `second-instance` | splashWin 在场 → `focus()`；否则主窗 `restore+focus`——**永不在交接前对隐藏主窗 show()** |
| 13 | 系统休眠/唤醒 | —— | 全部计时用**墙钟差值**，唤醒后补判；兜底是硬顶 |

**不做**的兜底：不重试换片（单素材没有候选池）、不做海报降级（那是三期素材话题）、失败不弹任何对话框（开屏失败的唯一正确姿势是沉默放行）。

### 8.1 config v14 · splash 块

```ts
splash: {
  enabled: boolean,        // 【待拍板#1】总开关
  mode: 'every' | 'daily', // 【待拍板#2】每天一次用 lastPlayedDay 比对（todayKey()，本地时区——

  sound: boolean,          // 【待拍板#3】默认静音

```

- **`decideSplash()` 纯函数**（放 `src/shared/splash.ts`，可穷举测试）：

```
输入：{ enabled, mode, lastPlayedDay, today, noSplashFlag, totalMemGB, minMemGB, materialFiles }
输出：{ action:'play', file, reason:'ok' }
    | { action:'skip', reason: 'disabled' | 'flag' | 'daily-done' | 'no-material' | 'low-mem' }
```

- 旗标/环境变量：`--no-splash` 与 `MIAI_NO_SPLASH=1`（探针与回归通道用，§10）。

## §9 性能（2G 目标机）

### 9.1 立项纪律：先定「怎么证明 2G 可活」，再宣称

现有全部性能数字来自 **32 核开发机**（整机工作集 598.8MB 无壁纸 / 717.1MB 视频壁纸 / 765.9MB 大视频，均 5 进程）；**2G 机上开屏的真实开销没有任何实测**。开屏会加出第 6 个进程 + 第二路视频解码，峰值叠在 18.6MB bundle 解析之上。所以：

- **验证方法（实施期 P2 的第一个动作）**：用 Windows 作业对象（Job Object）给应用进程树设 commit 上限，或用 2GB 虚拟机，复现换页压力。
- **预算读数表**（过闸才算数）：整机峰值 commit / 换页计数 / splash 掉帧率 / 主窗首 2s 帧间隔 / 启动时间线全段。
- **在过闸之前，对外口径不许写「2G 可活」**——如实标注「待 2G 实测」。

### 9.2 启动时间线埋点（失败可诊断）

主进程记一条启动时间线（探针可读，`window.__splashStats` 风格）：`进程创建(getCreationTime) → splash show → splash 首帧(页面上报) → main ready-to-show → handoff 开始 → splash 销毁`。

目标口径（**待 2G 定标**）：双击→**首个可见像素** ≤1.2s（弱机上限 3s）；→视频首帧 ≤+0.8s。感知档：<300ms 瞬时、≤1s 可接受、>1s 必须已有反馈（开屏窗本身就是反馈）。测试计划里 A2 判据由「3 秒内出现主窗口」改写为「**3 秒内出现首个窗口（开屏或主窗），全程无黑/白闪**」。

### 9.3 「启动静默期」延迟清单（2G 的性价比之王）

主窗隐藏 ≠ 轻载：今天它照常做壁纸取流+解码、音频回采、目录扫描——和开屏视频抢同一份 CPU/磁盘。机制：主进程在开屏存续期推 `splash:phase=active`，渲染层挂起点等待（丢失广播时用 invoke 读口 + splash 销毁事件自愈）。

| 延迟项 | 现状 | 处理 |
|--------|------|------|
| 壁纸/场景挂载与解码 | 启动即 mount + 静音 `play()` 启动解码 | 推到交接后（`splash:done`） |
| 音频回采（getDisplayMedia） | 开着时 onMounted 即发起 | 同上 |
| 工作坊目录扫描 | 启动路径触发 | 同上 |

开哪几项、阈值多少，**以 9.1 的实测定标**；`MIAI_SPLASH_HOLD=0` 可整组关闭做 A/B。
（注：隐藏主窗的 winState 本来就会推 `visible:false` → 壁纸暂停——这条现成语义是「隐藏不叠加解码负载」的地板；静默期清单管的是「连启动一下都别启动」。）

### 9.4 掉帧与卡顿判据

- splash 播放期：`getVideoPlaybackQuality().droppedVideoFrames` 占比 ≤1%（30fps×5s 即 ≤1~2 帧）+ rVFC 呈现间隔 p95 ≤45ms，两条同记。
- stalled 分级见 §4.4（单次只记诊断——**不许把一次读盘抖动放大成整段开屏被掐掉**）。
- 交接：主窗 show 后 2s 内主渲染 rAF 间隔 p95 ≤33ms、无 >100ms 长任务；壁纸恢复的 300ms 去抖与 250ms 淡出重叠是**已接受口径**（淡出盖住恢复期）。

### 9.5 候选优化（记录在案，**不默认做**）

- **renderer minify A/B**：18.6MB 未压缩产物是启动面最大的单笔成本（且「不 minify」在仓库里没有任何配置背书，只是现状）。这是**全局启动优化**，不止惠及开屏——单独立项，不混进本期。
- 素材再降规格（540p/24fps）作为 9.1 不过闸时的第一降级。
- 多素材随机、cover 模式，均为素材到位后的观感项。

   - **正常臂**：两 target 出现顺序（先 splash 后 main）→ 视频 `currentTime` 推进（≥2 个采样点）→ ended→淡出**连拍 3~4 张**（画面类判据不许单张定生死——第 25 次探针事故的教训）→ splash target 消失 → 主窗可见 → 时间线读数（首帧毫秒）→ 主窗首 2s 帧 p95。
   - **跳过臂**：CDP 真点 splash 页 + 真按键 → handoff 计时；**连点两下**验证幂等。
   - **种坏臂**：往 `data/splash/` 放损坏 mp4 → error 兜底放行、主窗正常、**断言输出区先空后红**（尺子自检）。
   - **回归臂**：`MIAI_NO_SPLASH=1` → 无 splash target、主窗直达（既有行为零变化）。
   - 全部：状态轨与画面轨分开记；CDP 截图单张 ~0.5s 已知，计时口径用状态。
3. **2G 实测**（§9.1 方法）过预算闸门，数值回填 §4.4 定标。
4. **真机透明取证**：目标机冷启动截图（透明窗口驱动风险只在这一刻暴露）。
5. **A/B**：主窗 load 触发点（臂1 立即 / 臂2 首帧后）用数据定序（§4.2）。

## §14 已知边界（如实清单）

- 2G 结论**尚未实测**（§9.1）；当前所有性能数字来自 32 核开发机。

- 开屏期间窗口不在 Alt-Tab / 任务栏（≤8s）；开发期开 DevTools 会让透明失效（探针不碰 DevTools）。
- 「renderer 不 minify」在仓库里没有任何配置/注释背书（只是现状事实）——与本方案解耦，另行立项。
- 素材是主人后续提供的：在素材到位前，P1 用本地测试片跑通流程，规格检查器只警告不阻断。
