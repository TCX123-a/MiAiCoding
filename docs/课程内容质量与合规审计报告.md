## 🔴 致命错误（学生一定会被坑到）

### 🔴-1 Java 的「引号没漏关」永远得到错误解释，学生会绕很久

**现象**：学生在 Java 里漏写右引号，比如 `String s = "abc;`。

**实测结果**：javac 会**同时报两句错**：

```
Main.java:1: error: unclosed string literal      ← 真正的原因：字符串没有收尾
Main.java:1: error: reached end of file while parsing
```

应用取**文件里排在前面**的那条规则。而 `reached end of file while parsing` 这条
（编号 java #7，意思是「少了几个右花括号喵」）**排在 `unclosed string literal`（java #14）前面**，
所以**每一次都是「少了几个右花括号喵」赢**。

**后果**：学生看到「少了几个右花括号喵」，就会老老实实去补 `}`。
可是补再多 `}` 也没用——真正的问题只是漏了半个引号。
零基础的学生很可能在这里卡十几分钟甚至放弃。

**修的办法（就一步）**：把 `unclosed string literal` 这条规则挪到 `reached end of file` 前面。

|---|---|---|
| 函数 | 技能 / 招式 | **56** |
| 编译器 | 翻译官喵 | **44** |
| 变量 | 小鱼干仓库 | **35** |
| 数组 | 一排贴编号的猫粮碗 | 13 |
| 循环 | 绕鱼干跑圈 | 13 |
| 列表 | 会自己长大的储物柜 | 11 |
| 参数 | 投喂的小鱼干 | 10 |
| 字符串 | 一串小鱼干的项链 | 10 |
| 类 | 猫猫图纸 | 10 |
| 递归 / 对象 / 指针 / 返回值 / 输入输出 | … | 13 |
| **合计** | | **215** |

**这不是「藏起来的边角文字」**——学生**每次运行出错**都会看到它：

> **java #2 的标题**：「`{1}`」这个**变量**还不存在喵
> **cpp #9 的整张卡**：你调用「{1}」时给的**参数类型**……C++ 允许同名**函数**有好几个版本（**参数类型**不同）……
> **编译器**只好说「没找到」喵。……或者要的是**引用**，你给了别的喵。
> *（一张卡片里塞了 4 个原术语）*

**为什么这是 🔴**：学生刚在第 1 课学会「翻译官喵」，一报错就冒出个「编译器」——
**两套说法在同一个软件里打架**。而项目自己的风险表（`docs/01-开发计划.md:62`）写着
「术语错用/口吻走样 → **核心卖点受损**」。术语一致性就是这个软件的卖点本身。

**最麻烦的地方**：自动校验**压根看不见这块**（它只扫课文正文），所以这个问题**会一路溜到发布**。

### 🟡-1 九类最常见的报错，规则库里**一条都没有**

实测：下面这些代码跑出来的报错，**没有任何规则能接住**，学生只会看到一串英文天书：

| 语言 | 学生写错的样子 | 报错原文 | 有兜底吗 |
|---|---|---|---|
| Python | `print((1 + 2` （括号没关） | `SyntaxError: '(' was never closed` | ❌ 无 |
| C++ | `int a = 1` 后面漏分号 | `expected ',' or ';' before 'return'` | ❌ 无 ← **最常撞** |
| C | `struct S { int x }` （结构体里漏分号） | `expected ';', identifier or '(' before 'int'` | ❌ 无 |
| C++ | `s.b = 1`（结构体里没这个成员） | `'struct S' has no member named 'b'` | ❌ 无 |
| C | void 函数里 `return 1;` | `'return' with a value, in function returning void` | ❌ 无 |
| Java | 同一个变量定义两次 | `variable x is already defined in method main(...)` | ❌ 无 |
| Java | `new String(1, 2, 3)`（参数个数不对） | `no suitable constructor found for String(int,int,int)` | ❌ 无 |
| Java | 多打了一个 `}` | `class, interface, enum, or record expected` | ❌ 无 |
| C | 中文分号 `int a = 1；` | 被判成「少了分号」→ **提示学生加分号，可加完还是错** | ❌ **方向错** |

> 对最常出现的中文分号、中文逗号无效——实测验证过。）

### 🟡-2 「程序崩溃」在 Windows 上是一条**死胡同**

**实测**：让一个 C 程序因空指针崩溃，结果 **stderr 和 stdout 都是空的**
（Windows 不像 Linux 会打印 `Segmentation fault`）。

**应用的显示逻辑**（`src/renderer/src/lib/run-result-view.ts:124-129`）：
没有输出 → **讲解卡直接不显示**。

**学生看到的是**：结果条红着脸说「运行失败喵」，输出区一片空白，**没有任何解释**。

**为什么这条排得这么前**：数组越界、空指针是新手**最高频**的运行错误。
而「程序为什么崩」恰恰是零基础的人**最需要**被告诉的事。

**连带**：规则库里有 4 条专门管这类情况的规则，在 Windows 上**永远匹配不上**：

| 规则 | 匹配的文字 | 为什么永远不出现 |
|---|---|---|
| common #5 | `Segmentation fault` | Windows 不打印这句 |
| common #6 | `Aborted` / `core dumped` | 同上 |
| common #9 | `timed out` | 同上；而且超时时界面走的是「跑太久被掐断」那句提示，这条规则**轮不到出场** |
| common #10 | `Killed` / `terminated` | 同上 |

### 🟡-3 十三条规则「该出场却永远出不来」

这 13 条是**真需要处理**的（本喵逐条实测过）。原因分三类：

**A. 规则自己写错了（5 条）——改规则就能修**

| 规则 | 规则里写的 | 真实报错长什么样 | 有没有别的规则接住 |
|---|---|---|---|
| python #10 这个左括号没有关上喵 | `SyntaxError: [(]' was never closed` | `SyntaxError: '(' was never closed`（**引号位置反了**） | ❌ 没有 |
| c #19 这个函数说不带东西回来的喵 | `return with a value, ...` | `'return' with a value, ...`（**真实的多一对引号**） | ❌ 没有 |
| java #24 「X」被定义了两次喵 | `error: X is already defined` | `error: variable x is already defined`（**中间多了 variable**） | ❌ 没有 |
| java #27 new 的时候给的东西对不上喵 | `constructor .* cannot be applied` | `no suitable constructor found for String(int,int,int)`（**措辞完全不同**） | ❌ 没有 |
| common #1 「X」只有名字，没有身体喵 | `undefined reference to 'X'`（**直引号**） | ``undefined reference to `f'``（MinGW 用**反引号+撇号**） | ✅ 有（common #2「零件都对，拼不到一起喵」） |

**B. 用错了别的编译器的措辞（3 条）——本机是 GCC/MinGW，不是 Clang**

| 规则 | 写的是 | 本机实际是 |
|---|---|---|
| cpp #8 「Y」身上没有「X」喵 | `no member named 'X' in 'Y'`（Clang 说法） | `'struct S' has no member named 'b'`（GCC 说法） |
| cpp #16 编译器不认识「X」喵 | `use of undeclared identifier 'X'`（Clang 说法） | `'X' was not declared in this scope`（GCC 说法，**已有别的规则接住**） |
| common #8 喵找不到这个工具喵 | `is not recognized as an internal or external command` | 中文 Windows 输出**中文**：`'X' 不是内部或外部命令，也不是可运行的程序或批处理文件。` |

**C. 规则本身没错，但应用的呈现逻辑让它永远没机会出场（2 条）**

| 规则 | 情况 |
|---|---|
| c #13 printf 里 `%d` 的位置对不上喵 | **实测：规则写对了**，能精确匹配 gcc 的原文并抓到 4 个参数。**但 gcc 把格式不匹配算「警告」不算「错误」，编译成功**；而应用只在**编译失败**时才展示 stderr → 这条规则永远轮不到出场。学生看到的是程序带着错跑出乱码，没有任何解释 |
| cpp #3 这里少了一个分号喵 | 只在 `struct`/`class` 成员声明漏分号时命中；**函数体里漏分号（最常见的）**没人管（见 🟡-1） |

**另外 4 条「匹配不上但无害」，不用动**：c #3、cpp #16、common #1、java #10 ——
它们**都被另一条意思相同的规则接住了**，学生拿到的解释是对的。

### 🟡-5 通用模块（common 12 课）缺了「一排数据」

通用模块的骨架是：变量(04) → 条件(05) → 循环(06) → 函数(07) → 输入输出(08) → 算法(09)。

**少了「十个数字怎么存」。** 没有数组、列表、集合的**概念课**。
学生学完 12 课，会判断会循环会打包函数，却不知道怎么把 10 个分数存起来 ——
而 `common-09 算法入门` 讲「顺序 / 选择 / 循环」时，例子（比如求平均分）**必然需要一排数据**。

四个语言的路线里各自有数组课（`c-stage1-09`、`java-stage1-08` 等），
但**语言无关的通用部分断了一环**，而且这一环是编程最基础的四块基石之一（变量/条件/循环/一排数据）。

### 🟡-7 术语闸门有**两个洞**，而且是「看不见」的那种

`npm run validate:content` 现在报 **0 错误**——但它**只扫课文正文**。

**洞一：四个面向用户的地方它从来没看过**（本喵补扫了一遍）：

| 扫描面 | 结果 |
|---|---|
| 课文正文（闸门能看到的） | ✅ 干净 |
| **报错规则 132 条文案** | ❌ **87 处文本、215 个原术语**（见 🔴-2） |
| 大纲 192 课标题+outline | ⚠️ 121 处／269 个（**其中大部分是设计如此**，标题格式是「猫娘说法——原术语」，见 🟢-2） |
| 题库题干/解析/选项 | ⚠️ 5 处／8 个（**其中 q3/q5 是「题目本身就在考这个术语」，属于必须出现**，不用改） |

**洞二：豁免规则太宽，可以整篇绕过**

闸门为了允许「首次对照」（`原术语（猫娘说法）`），写了一条豁免：

```js
text.replace(/([一-龥A-Za-z]+)（[^）]{1,12}）/g, '')   // 任何汉字 + 不超过 12 字的括号 → 整段删掉
```

这条规则有三个问题：

1. **不认方向**：`变量（小鱼干仓库）` 被删掉是对的，但 `小鱼干仓库（变量）` 也会被删掉；
2. **不看内容**：`循环（loop）`、`数组（array）` 这种**中英对照**也会被删掉；
3. **不限次数**：规范里写的是「首次出现**对照一次**」，机器上**没有次数限制**——
   一节课里把每个术语都写成「原术语（说法）」形式，就能**全篇零告警通过**。

### 🟡-11 验收标准只要求「代码能跑」，没要求「代码没毛病」

主人点名要查「示例代码有没有内存泄漏 / 未定义行为」。**目前查不出问题，但不是因为写得好，是因为还没有。**

  「**课文中所有示例代码必须真实可运行**」。
