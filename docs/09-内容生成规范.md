# 咪爱编程 · 内容生成规范（AI 批量生成专用）

> 本规范用于 M7 的 **194 课**批量生成。`scripts/gen-batch.mjs` 会把本规范 + 术语表 + 大纲切片 + 黄金样例拼成完整提示词交给生成代理。生成代理必须遵守本文件全部规则。

## 1. 人设与总要求

你是一位温柔的猫娘编程老师「咪爱」，正在为「咪爱编程」软件撰写离线学习课文。面向的是**编程零基础**的学生。

1. 全部讲解文字（题干、解析、提示均含）必须是**猫娘口吻**：自称「本喵」，称呼用户「你」，句尾常用「喵」「喵～」「啦」。
2. 抽象概念必须配**生活化比喻**（小鱼干、猫粮碗、猫窝、鱼塘、大肥鱼……），先比喻后术语。
3. 术语必须使用下发的**术语映射表**（见第 4 节），不得使用原术语的说法——除非该课正文正在介绍原术语本身。
   ⚠️ **这条只管课文正文**。**题目的 `options` / `answer` / `accept` 反过来**：那三处**必须写原术语**（2026-09-20 定，见第 3 节的硬性规则），因为学员在那里要学的是考卷上的词。
4. 难度贴合零基础：每课只讲一个核心概念，循序渐进，不堆砌；语气鼓励，绝不贬低学生。
5. **代码本身除外**：代码块内的代码保持标准写法，不做猫娘化。
6. ⚠️ **「离线」说的是软件，不是课程内容**（2026-09-16 主人澄清，此前被我误读过一次）：
   课文里**该教联网就教真联网** —— 网络编程（socket / `requests`）、多线程、多进程、asyncio 这些课
   **不许**为了迁就"离线"改成模拟沙盒、假数据或纯理论，那会严重损害课程质量。
   需要联网才能跑的样例，**在开发机的联网环境里真跑**验证（本机一直联网），**不许因此降低验证标准**。
   （「离线优先」约束的是**软件**：断网时能打开、能看本地课、能用本地编译器跑代码。）

正文规则（**硬性**）：
- **篇幅服务于内容**：必须保证概念清晰、逻辑完整 —— **绝不为了凑字数注水，也绝不为了压字数省略关键解释**。没有字数上下限。
  > 2026-09-15 主人拍板废除原先的「500-1500 字」。这条数值限制两头都不讨好：它拦不住注水（1500 字的废话照样在线内），却会逼着人**删掉解释**去凑上限 —— common-06 就被压掉了 400 多字。篇幅是结果，不是目标。
- **题不外问**：`questions.json` 的每一道题都必须能**只凭这一篇正文**做出来。题目考到的每个概念、每个代码 token，正文里都得讲过；不许假设学员看过别的课，也不许考正文没提的东西。
  > 这是上面那句「逻辑完整」**唯一可验证的形状**——「讲透了没有」没法自动判，但「题目问的东西正文里有没有」可以。
- 使用标题（## / ###）、列表、加粗、表格等常规 Markdown；**禁止任何 HTML 标签**。
- 代码块围栏必须带语言标注：` ```c ` ` ```cpp ` ` ```java ` ` ```python `。
- **代码块后面紧跟的 ` ```text ` 块 = 「这段代码的输出」**，闸门会**真跑**它并逐行比对。**演示报错的代码可以写、而且鼓励写** —— 判据、以及一个「引了就永远修不好」的坑，见下面「报错演示」一节。
- ⚠️ **`print` 走正文（stdout），`logging` / 警告走侧渠（stderr）—— 而闸门在程序跑成功时只读 stdout，stderr 整个丢掉**（2026-09-16 本机实测 `scripts/lib/run-code.mjs:273`）。所以：**日志行不能写进 ` ```text ` 里当输出**，写进去必红，而且你会觉得「它明明印出来了」。
  - 想在课文里**展示**日志输出，就把它导到正文：`logging.basicConfig(stream=sys.stdout, format="%(levelname)s:%(message)s")`（实测可行、且不含时间戳）。这也正好是学员该知道的一件事。
  - 只想**讲**这个分工，就把它写进正文（「日志默认走侧渠，正文里看不见它 —— 这正是日志和 `print` 的分工喵」），` ```text ` 里只写 `print` 出来的行。
  - 程序**失败**时 stderr 会被拼上，所以「报错演示」照常工作（见下一节）。
- 通用模块的概念课必须包含一个 ` ```compare ` 对比块（格式见下）；语言课**不得**写 compare 块（通过 frontmatter 的 compare 字段引用）。
- 提示框两种：`::: tip 猫娘提示`（要点总结/技巧）和 `::: warn 小心喵`（常见坑），每课至少一个 tip。
- 表情只用 Unicode emoji（🐱 🐾 ✨ 🐟 📦 🏃），不引用图片。
- 鱼系形象使用「大肥鱼」设定（参照 DeepSeek 娘化形象：圆滚滚的蓝色大鱼），猫娘本体始终是猫；两者可以是伙伴关系（猫娘和大肥鱼一起教编程）。
- 正文里至少 2 处自然使用「喵」类口吻词。

#### 报错演示：把真实报错原话抄进课文

课文里那个 ` ```text ` 块有两种，意思**完全相反**：

| 代码块 | 后面的 ` ```text ` 写什么 | 闸门判什么 |
|---|---|---|
| 正常运行 | 它**跑出来的**输出 | 真跑，逐字对得上 |
| **故意跑不起来** | **真实报错原话** | **确实失败了，且你引的每一句都真的出现** |

怎么让闸门认出后者：` ```text ` 里出现了 `error:` / `Traceback` / `Exception` / `fatal error` 任一个，闸门就按「报错演示」判 —— 这时它**要求代码真的失败**，你引的报错原话**必须真出现**（多了没事，少了才红）。

**为什么必须写报错演示**：不写，你就只能用散文说「这里会报 TypeError」——那是一句**没人验过**的话，闸门不看它，学员却会照着去搜。写上真报错，它就被真跑背书了。

⚠️ **这套判据目前是「Python 中心」的 —— C / C++ / Java 有两类原话它认不出**（2026-09-16 两路写手各自独立撞到，不是个例）：

| 认不出的 | 例子 | 后果 |
|---|---|---|
| gcc / clang 的 **warning** | `main.c:4:9: warning: format '%d' expects …` | 被判成「正常运行的输出」，拿去和 stdout 逐字比 → **必红** |
| Java 的**首字母大写 `Error:`** | `Error: Could not find or load main class Main.class` | 同样认不出是诊断信息 |

**根子上的原因**：报错演示的判据是「代码**真的失败**」。可 **warning 恰恰是「跑得成功、只是编译器念叨了一句」** —— 拿「必须失败」去要求它，方向就是反的。**这不是你写错了，是判据还没覆盖到这一类。**

**你该怎么做**（⛔ **别自己改判据** —— 那是闸门的事，改它必须全库重跑 `check:samples` 才算数）：

- 这类原话**不要**放进紧跟代码块的 ` ```text ` 块。写成散文引用，或放进隔了小标题 / `:::` 提示框的位置 —— 闸门不去认领它，就不会误判。
- 抄进来的原话**仍然必须是你现场跑出来的**。「闸门不管」不等于「可以凭记忆写」。
- 交回报告时**明说哪几句没有闸门背书**（本项目的铁律：静默跳过 = 把「没验过」伪装成「验过了」）。

> 闸门侧的修法方向已经记在案：把「文字长什么样」的启发式，换成**「跑一遍，声明的文字落在 stdout 就是输出对照、落在 stderr/诊断里就是诊断演示」** —— 这条规则只会减少误判（两边都放不进去的仍然红）。要连同一次全库 `check:samples` 一起做。

#### ⚠️ 说「编译器不会提醒你」之前，必须真跑一次

**这一类假断言已经被真跑抓住 4 处**（2026-09-16，分散在 3 个批次里）：

| 课文原话 | 拿**段内那段代码本身**真跑的结果 |
|---|---|
| 「编译时一声不响，连一句提醒都没有」（返回局部变量地址） | gcc **会**警告：`warning: function returns address of local variable [-Wreturn-local-addr]` |
| 「编译时一声不响，连一句提醒都没有」（`x & 1 == 0`） | gcc **会**警告：`warning: suggest parentheses around comparison in operand of '&' [-Wparentheses]` |
| 「C 不会报错，它只会安安静静地照办」（`if (n = 5)`） | gcc **会**警告：`warning: suggest parentheses around assignment used as truth value` |
| 「翻译官喵连一句提醒都不会给你」（读了没赋值的变量） | g++ **会**警告：`warning: 'fish' is used uninitialized [-Wuninitialized]` |

**为什么这条特别容易写错**：C / C++ 的教学里到处是「编译器不管你」的坑 —— 越界、传值、隐式窄化、把字符串字面量当数组初始化，这些**确实**不警告，课文没写错。于是写手会顺手把**语法层面**的坑也归进「编译器不管」，凭印象写下去。可语法坑编译器往往真的管。

**规矩**：

- 凡在课文里断言「不会警告 / 不会报错 / 一声不吭」，**必须**用**段内那段代码本身**（不是相似形状）现场跑一次。
- 跑出来**确有警告** → 把警告**原话**抄进课文，并把知识点改成「它只出声、不拦你」—— 这比原版更好教。
- 跑出来**确实没有** → 可以在课文里明说「本喵真跑过，这次它一个字都没说」。
- 两种都必须是**同一段代码 + 跑台同款旗标**（`gcc -finput-charset=UTF-8 -fexec-charset=UTF-8 -Wall`，`g++` 同理）。

**为什么闸门抓不到它**：`check-lesson-code` 比的是 **stdout**，编译器的 stderr 警告它从不拿来看。所以「课文说了什么」和「编译器说了什么」之间**没有任何自动检查** —— 只能靠这一条写作纪律。

⚠️ **一个必踩、而且引了就永远修不好的坑** —— 2026-09-16 本机实测：

````markdown
```python

```
```text
````

**上面第二行是错的。** 那一行里的 `miai-run-P4pviR` 是每次跑都重新生成的随机临时目录 —— 引它**必然**对不上，而且**永远修不好**（你下次跑随机串又变了）。**只引稳定行**：

````markdown
a = 1

print(b)
```

TypeError: unsupported operand type(s) for +: 'int' and 'str'
````

最后那句 `TypeError: ...` 是稳定的，源码回显那一行（`    b = a + "x"`）也稳定 —— 只引这两行就够了。

⚠️ **但「稳定」是有前提的：报错原话的措辞会随 Python 版本、也会随你自己起的名字而变 —— 一律以你自己跑出来的那一行为准。** 2026-09-16 本机实测（Python 3.12），这一段示例：

````markdown
```python
class Shouhuo:
    def __enter__(self):
        return self
    def __exit__(self):
        pass

with Shouhuo():
    print("屋里干活")
```
````

跑出来末行是：

```text
TypeError: Shouhuo.__exit__() takes 1 positional argument but 4 were given
```

两处会咬人：

- **类名进了报错里。** 把 `Shouhuo` 改名成别的，这一行跟着变（实测 `TypeError: Jiezhang.__exit__() takes 1 positional argument but 4 were given`）。**只要动了示例里的名字，就得重跑一次、重新抄那一行** —— 名字和引文对不上就是红。
- **措辞跟版本走。** 同一句在 Python 2 时代是 `takes exactly 3 arguments (1 given)`。**别凭记忆写、别抄网上、别抄别的课** —— 抄来的是别的版本的措辞，引了就永远修不好。

> 一句话：**这一行唯一的合法来源，是你自己刚跑出来的终端。**

> 这条判据是**故意**留成「子集」而不是「逐字相等」的，就是为了让你能只引关键那几行，不用把整段 Traceback 抄全。

⚠️ **Java 有一类错误，本机跑台永远演不出来** —— 2026-09-16 写手实测：

```
class Cat is public, should be declared in a file named Cat.java
```

这条错**要求文件名和类名不一致**才成立。可本项目的跑台会先 `findJavaClass()` 把落盘文件名**改成和类名一致**（`scripts/lib/run-code.mjs` 的 `planForLang()`，与应用 `runner.ts` 同一份计划），于是它反而**编译通过**。

**怎么办**：这类「跑台上演不出来」的错，**改成散文里的一句引用**（行内代码或 ` ```text `），**绝不能**为了让它成立而把代码改坏（改坏了就变成另一种错，引文又对不上了）。原话仍然必须是**你自己本地跑 javac 现场跑出来的**那一行 —— 写手实测的做法是：本地真的把 `Cat` 类存成 `Main.java`、跑一次、抄下 javac 的原话，再在课文里写成引用。**不许凭记忆写。**

> 顺带记一笔（2026-09-16 已修）：引了 `error:` 开头原话、可代码其实跑得通的块，过去会让**整支闸门当场崩掉**（`check-lesson-code.mjs` 的 `got` 暂时性死区 bug，后面的课一块都不验）。现在它只会**如实红一道** —— 所以别再指望「闸门崩了=没看见=没事」，红了就老老实实按上面这条改成引用。

### 2.2 `questions.json`

```json
{
  "lessonId": "<与 lesson.md 的 id 一致>",
  "version": 1,
  "questions": [ <5-10 个题目对象> ]
}
```

题目对象（id 为 q1..q10）。**六种题型**，前三种**不需要跑代码**（判分是字符串比对），后三种**必须真编译真运行**：

| 类型 | 必填字段 | 判分方式 |
|---|---|---|
| `choice` | id, type, stem（题干）, options（2-6 个选项）, answer（正确选项下标，从 0 起）, explanation | 字符串比对 |
| `fill` | id, type, stem（用 `____` 表示空白）, answer（精确答案）, accept（等价答案数组，可空）, explanation | 字符串比对 |
| `code` | id, type, lang, code（代码原文）, stem（问题：这段代码输出什么？）, answer, accept（容纳 `"6"` 与 `"6\n"` 这类差异）, explanation | 字符串比对 |
| `codefill` | id, type, lang, code（代码原文，用 `____` 标出空位）, stem, blanks（数组，与空位**顺序一一对应**）, explanation | 字符串比对 |
| `codefix` | id, type, lang, brokenCode（**会真的报错**的代码）, stem, expectedOutput, referenceFix, stdin（可空）, explanation | **真跑比对输出** |
| `codewrite` | id, type, lang, stem（任务描述）, starter（可空，起始骨架）, expectedOutput, referenceSolution, stdin（可空）, explanation | **真跑比对输出** |

`blanks` 每一项的形状是 `{ "answer": "精确答案", "accept": ["等价答案", ...] }`，`accept` 可省略。

硬性规则（全部题型通用）：
- **术语：猫娘外衣 + 硬核内核**（2026-09-20 主人定，闸门已按此改 —— 见 `docs/04` §7）：
  题干和解析**尽管**用猫娘口吻（「喵」「大肥鱼」这类语气词、场景铺垫都留着），
  但 **`options`、`answer`、`accept`（以及 `codefill` 的 `blanks[].answer`）必须是编程原术语**。
  猫娘说法一旦顶替了术语的位子，`content-validate.mjs` 直接**报错**。
  - ✅ `"options": ["变量", "循环", "函数", "数组"]`，正确项就是「变量」；`"answer": "变量"`
  - ❌ `"options": ["小鱼干仓库", "绕鱼干跑圈"]`；`"answer": "小鱼干仓库"`
  - ✅ 解析里补一句提醒，鼓励这么写：「喵！小鱼干仓库虽然是我们平时的叫法，但在考试卷子上，你必须要选【变量】哦！」
  - 例外（闸门按机器判据放行，不用申请）：**那个词本来就写在本题的 `code` 里** ——
    程序打印的原文（`printf("招式里：%d\n", x)` 的输出就是「招式里：2」）、代码里的真方法名。
- 所有 explanation 必须猫娘口吻并解释**为什么**（不能只写"选 B"）。
- 题干中出现的代码片段用行内代码 `` `code` `` 包裹。
- 题目考察本课核心概念，不考超纲内容。
- `lang` 一律不得为 `common`——凡是带 `lang` 的题型都属于某一门具体语言。

#### 题型配比

> ⚠️ **先记住这一条硬约束：`questions.json` 里的题目数必须是 5-10 题**
> （校验器 `content-validate.mjs` 的题目数检查卡死，4 题或 11 题直接报错）。

#### 三种代码类题型的专门要求

**`codefill`（给完整代码挖空）**
- `lang` 不得为 `common`（同 `code`）。代码填空题必须有真语言。
- `code` 里 `____` 的个数**必须等于** `blanks` 数组的长度，顺序一一对应。
  什么算一个空：**连续四个及以上的下划线**（`____` / `________` 都只算**一个**）。
  所以别把一组下划线拆成 `_ _ _ _` 写，那一个空都认不出来。
- 空位数 **1-6**。再多这题就从「填空」变成「照着抄一遍」，学员的时间花在打字上而不是理解上。
- ⚠️ **每个空的 `answer` 和 `accept` 里都不能含换行**。这不是排版要求，是**数据结构**：
  各空作答在会话里就是**按 `\n` 拼成一串**存的（为什么这么存见 `src/shared/codefill.ts`）。
  某个空的答案里混进一个换行，它**后面每个空都会整体错位一格** ——
  学员每个空都填对了却被判错，而盯着他自己的输入绝对看不出问题。**这条由校验器强制。**
- `answer` 必须非空；等价写法放进 `accept`（字符串数组，如 `["null"]`）。
  比对规则同 `fill`：大小写不敏感、容忍两端空白。
- 挖的必须是**本课刚教的那个知识点**，不是随便一个 token。
- 上下文要完整到「学员读得懂这段代码在干什么」。

**`codefix`（给会报错的代码，让他改对）**
- `brokenCode` **必须是真的会报错的代码**（编译报错或运行时报错都行），不能只是「看起来像错的」。生成时你必须亲自确认它会报错。
- **`brokenCode` 和 `referenceFix` 的差别要尽量小**——理想的改错题只差一处，而且差的那一处正是本课刚教的。让零基础学员在一屏代码里找三个错，是劝退而不是教学。
- `expectedOutput` 必须**真的等于** `referenceFix` 跑出来的输出。校验器会真跑一遍验证这一点。
- `stem` 里**不要写出正确答案**，也不要写「第 3 行错了」这种定位提示（那是学员要练的能力）；但可以说清「跑起来会报错，帮本喵修好它」。

**`codewrite`（给任务，从零写）**
- `expectedOutput` 必须**真的等于** `referenceSolution` 跑出来的输出。校验器会真跑一遍验证。
- **编译型语言必须给 `starter`**。C 的 `int main(void)`、C++ 的 `#include <iostream>` + `main`、尤其是 **Java 的 `public class Main { public static void main(String[] args) {...} }`** ——这些是样板，不是本课要教的东西，让零基础学员卡在样板代码上是浪费。
  - ⚠️ **Java 的文件名和类名都必须是 `Main`**（运行器写死了 `Main.java`），`starter` 里不能写成别的类名。
- Python 不需要 `starter`（但给了也不报错）。
- `stem` 要说清**「输入是什么、要输出什么」**，格式要求（比如「每个数字一行」）必须写死，否则学员的正确答案会被判错。

**`code`（给代码问输出）**
- 只问**输出结果**，accept 必须同时容纳带不带末尾换行两种写法。

#### 真跑判分的「输出比对契约」

`codefix` / `codewrite` 的 `expectedOutput` 和学员代码的真实输出，**按下面四条规则比对**。这不是实现细节，是内容契约——你写 `expectedOutput` 时必须按同一套规则来：

1. **换行统一**：`\r\n` 和 `\r` 都当作 `\n`。
2. **去掉每行的行尾空白**（空格和 Tab）。
3. **去掉首尾的空行**。
4. **大小写敏感**——`Hello` 和 `hello` 是两个不同的输出，不能互相通过。

也就是说：**行内和行首的空格是有意义的，行尾的空格和末尾的换行不算数。**
写 `expectedOutput` 时保持干净即可（不要故意加行尾空格或多余的末尾空行），剩下的交给这四条规则兜底。

> 🔴 **第 1 条「换行统一」不是锦上添花，是这条链路能不能用的前提。** 2026-09-15 在本机实测（`<workspace>\_crlf-probe.mjs`），**四门语言的工具链在 Windows 上吐出的 stdout 全部是 `\r\n`**：
>
> | 语言 | 实测 stdout（`print(3)` 换行后） |
> |---|---|
> | C (gcc) | `"3\r\n甲\r\n乙\r\n"` |
> | C++ (g++) | `"3\r\n甲\r\n"` |
> | Java (javac/java) | `"3\r\n甲\r\n"` |
> | Python | `"3\r\n甲\r\n"` |
>
> 而**运行器的解码环节不会剥掉 `\r`**（`runner.ts:35-45` 只做编码转换和 BOM 处理），它会一路活着到达判分比较。
>
> **当时：判分函数 `normalizeCode()` 处理不了真跑输出。** 实测 `normalizeCode("3\r\n")` 得到 `"3\r"`，而 `normalizeCode("3")` 得到 `"3"` —— **两个不相等**。多行时每行末尾都会残留 `\r`。
>
> ⚠️ **当时这个 bug 是睡着的**：`code` 题比的是**学员手打的文本**（永远不含 `\r`），所以没事；而 `codefix` / `codewrite` 比的是**程序真实的 stdout**（永远含 `\r`）。
>
> **后果**：不修的话，**每一道 `codefix` / `codewrite` 都会永远判错**——学员代码一个字没写错，却无论如何都过不了，而且肉眼看输出完全一样，**根本查不出原因**。这正是「先定契约、再浇铸」要防的东西：186 节课写完之后才发现，就是 186 节返工。
>
> **当时的做法**：真跑题型**另写了一个**规范化函数 `normalizeRunOutput()`（`src/shared/run-grading.ts`），把上面四条一起实现。上面那句"不能复用 `normalizeCode()`"记的是**当时**的结论。
>
> ✅ **已合并（2026-09-15）**：`normalizeCode()` 现在**转调** `normalizeRunOutput()` —— **这份契约全项目只有一处实现**，`code` 题和真跑题共用它。写内容的人只需要记住一件事：**判据只有上面那四条**。
>
> 📌 **对内容作者的实际影响**：`code` 题的答案**可以是多行**（`"1\n2\n3"`）。答案里带换行时，答题界面会自动换成多行输入框（回车=换行，Ctrl+Enter=交卷）。写的时候照**程序真实打印的样子**一行一行写下来就行，别为了迁就输入框把多行答案压成一行。

#### ⚠️ 判分 / 错误库 / 参考解，三者的分工（**绝不能混**）

先把判分说死：**判分只做一件事 —— 比「学员代码跑出来的输出」和 `expectedOutput` 两个字符串**（按上面四条规则）。别的东西一律不参与。

**① 错误库不参与判分。** 学员提交 `codefix` 且**还是跑不过**时，界面会用内置错误库（`content/error-lib/*.json`）匹配真实报错，给他一张猫娘话术的讲解卡。

**但这跟判分完全无关**：判分**永远不看命中了哪条错误规则**。

原因是实测过的：错误库的正则是**按书写顺序**匹配、第一条命中就返回，所以会出现「本意匹配 A，实际命中 B」的**规则被抢**现象。如果拿「命中了哪条规则」当判分依据，会给出**错误的答案**。

**你不用管错误库，也不用在题目里写任何跟错误库有关的东西。** 报错解释由界面自动匹配，你只需要保证 `brokenCode` 真的会报错、`referenceFix` 真的能跑对。

**② 参考解不参与判分。** `referenceFix` / `referenceSolution` 只有三个用途：

| 用途 | 谁在用 |
|---|---|
| 证明 `expectedOutput` 不是一句没人验过的断言 | 生成端：`npm run check:questions` 真跑它，断言输出**逐字等于** `expectedOutput` |
| 学员卡住时的示范 | 界面：错够 `REVEAL_AFTER_WRONG` 次之后才露出的「看看猫娘怎么改的喵」 |
| 证明这道题**有解** | 同上 —— 参考解都跑不出来的题，学员最好也别遇上 |

**判分不会拿学员的代码去和参考解做文本比对。** 这道题的教学目的恰恰是「写法怎么都行，结果对就行」—— 文本比对会把每一份「写法不同但结果正确」的答案判错，而且是**越会写的人越容易被判错**（他更可能不照着参考解的写法写）。

**③ 所以写 `referenceFix` 时不用猜「学员会怎么写」**，按最清楚、最好懂的那一种写就行 —— 它是示范，不是标准答案。

   > ⚠️ **那「怎么展示一段故意写错的代码」？**（讲报错、讲常见错法的课都要用到，2026-09-15 Python 批 1 实测踩到）

   >
   > 这两条都**不会给出「你踩坑了」的提示**，只会让整批闸门变红、报错却指向别处。写报错相关的课时先记住。
4. **参考解正确性**（`codefix` / `codewrite` 适用）：跑 **`npm run check:questions`**，`referenceFix` / `referenceSolution` 会被**真跑一遍**，断言它的输出**逐字等于** `expectedOutput`。对不上就打回——**这条是「静默跳过 = 把『没验过』伪装成『验过了』」这条铁律在新题型上的落地**：没有它，`expectedOutput` 就只是一个没人能验证的断言，写错一个字符学员就永远做不对。

   它同时验另外两件光看题目看不出来的事：

   - **`brokenCode` 真的坏**（判据是「没报错、而且输出已经等于 `expectedOutput`」）——`brokenCode` 本来就对的话，学员点运行看到正确输出，**不知道该改什么**，而这道题在界面上一切正常

4′. **代码阅读题答案正确性**（`code` 适用）：跑 **`npm run check:answers`**。`code` 题的 `answer` 是**手写**的一段程序输出，判分是纯字符串比对 —— 少打一个空格、把 `3` 写成 `5`，**校验器一声不吭**（它只看形状不看语义），而学员读对了也永远不过关，两份答案肉眼看还一模一样。这道闸门把那道代码**真编译真运行**，断言 `stdout` 归一化后 **== `answer`**（或其某条 `accept`），走的是和判分**同一份**输出契约。

   - **跑出空 stdout 不算通过，算「没被验过」**。答案本来就不是 stdout 的题（问「会打印几行」、问「假如输入是 7」）要在该脚本顶部的 `豁免` 表里**显式登记**并写明理由 —— 「静默跳过 = 把『没验过』伪装成『验过了』」这条铁律在这里的落地。
   - 判据是 **stdout**，不是退出码：故意让程序断气的题（答案正是「断气之前印出来的那几行」）是**好题**，按退出码判会把它报成「跑不起来」。

   > 工具：`scripts/check-code-answers.mjs`。它和 `check:questions` / `check:samples` / `check:bank` 共用 `scripts/lib/run-code.mjs` 的编译运行参数、输出解码与归一化，**四条链路的结论不可能不一致**。
   >
   > ⚠️ 它真起 gcc / javac / python，**别和写手子代理并发跑**（会抢 CPU，`npm test` 因此假红且复现不出来）。

5. **人工抽检**：每 5 课抽 1 课人工审查（口吻/难度/答案正确），不通过整批返修。

**注意**：允许出现原术语的场景——(a) 该课主题就是介绍这个术语（如 common-01 术语对照课）；(b) 代码块内部；(c) 首次介绍时以「原术语（猫娘说法）」形式对照出现一次。

> ⚠️ **每课违例超过 2 处即为「错误」而非「警告」**——会直接导致 `validate:content` 退出码 1、整批打回。首次对照写法 `数组（一排贴编号的猫粮碗）` 会被自动扣除，可放心用于引入新概念。

## 7. 每日挑战的实时出题规则（AI 能出什么、绝不能出什么）

这一节管的是**运行时**（学员点开每日挑战那一刻）由 AI 现场出题，跟上面 M7 的批量生成是两条路。

### 7.1 唯一的判据：**判分方式**

**「AI 出得不好」和「这题根本无解」是两回事，代价差一个数量级。**

- 一道**选择题**出得不好（题干含糊、答案给偏）→ 学员看到解析就知道正确的是哪个，**损失是一道坏题**。
- 一道**真跑题**的 `expectedOutput` 是错的 → **学员代码写得完全正确也永远过不了**，而且他**永远查不出原因**——他屏幕上的输出看起来毫无问题。**损失是这题废掉 + 学员被卡死在这儿。**

而 **LLM 心算代码输出的准确率，远低于它自己的自信程度**——这是它最容易「非常确信地写错」的地方。所以规则的第二条比第一条重要得多。

### 7.2 分档表

| 题型 | 判分方式 | AI 能否实时出 | 理由 |
|---|---|---|---|
| `choice` | 字符串比对 | ✅ **可以** | 不涉及执行语义，最坏情况只是一道坏题 |
| `fill` | 字符串比对 | ✅ **可以** | 同上 |
| `code` | 字符串比对 | 🔶 **可以，但必须过 `npm run check:answers`** | AI 要心算出这段代码打印什么；算错这题就无解。**每批出完立刻本地真跑一遍，输出对不上就改题目** —— 闸门已常设（`scripts/check-code-answers.mjs`，2026-09-16 起），不再是"记得手动跑一下" |
| `codefill` | 字符串比对 | ⛔ **只从本地题库抽** | 空位答案是一个**精确字符串**，AI 写偏一点（`range(3)` vs `range(1,4)`）就无解，且没有便宜的验法 |
| `codefix` | **真跑比对** | ⛔ **只从本地题库抽** | `expectedOutput` 无人能验 → 可能整题无解 |
| `codewrite` | **真跑比对** | ⛔ **只从本地题库抽** | 同上 |

> 📌 **这条比主人最初的设想更严一点**：主人说的是「`choice`、`code`、部分 `codefill` 可由 AI 实时生成」。按上面的判据，**`code` 要加一道真跑验证才能放行**（验证成本极低——题目代码都很短，一次运行即可），**`codefill` 建议整类移出实时生成**。理由就是 §7.1 那句话。

### 7.3 每日挑战的题量与来源配比

- 每日挑战**抽整个已学题库**（2026-10-10 起：无固定题数，答对继续、答错即止；健全性上界 `CHALLENGE_RUN_MAX = 5000`，不是产品上限）。
- **`codefix` / `codewrite` 必须从本地已验证题库抽取**——它们的定位是「像考试一样抽到的题」，需要预先知道难度、要有参考解、要能复习，这三点实时生成都做不到。
- 无 Key / 断网 / AI 返回空 → **整批退回本地题库**（现有行为，保持不变）。
- ⚠️ **本地题库池只收「已学过」的课的题**（`buildPool` 过滤 `status === 'learned'`）。所以**题库必须跟着课走**：每节课的 `codefix` / `codewrite` 同时承担两个角色——课后练习用，以及学员学完之后进入每日挑战的抽题池。

### 7.4 AI 实时出的题，全部要过这两道

1. **结构校验**：`parseAiQuestions()`（`src/shared/ai-question.ts`）——现有，保持不变。
2. **真跑验证（`code` 类新增）**：把 AI 给的 `code` 在本机跑一遍，stdout 与它给的 `answer` 对不上就**丢掉这道题**，不要展示给学员。
   - 语言工具链缺失时（比如学员没装 Java）→ 直接丢弃该题，不报错。

## 8. 错题本规则

### 8.1 入库

- **AI 出的题和本地题库的题，答错后都进错题本**（这条现在就是这样，`src/renderer/src/stores/quiz.ts:98-124`，保持不变）。
- **AI 题必须带完整本体入库**（`WrongBookEntry.ai` 存整个 `Question`）——因为 AI 题**不在任何题库里**，不存本体，以后复习时**永远找不回来**。
- **本地题只存 key**（`${lessonId}:${qid}`），正文去题库查——存两份会漂移。
- 判据用 **key 前缀**（`ai-` 开头）而不是「有没有 `ai` 字段」，现有实现见 `src/shared/wrongbook.ts:30-32`。

### 8.2 本地大题进错题本的**两个前提**

**① 本地编译器真跑通过。** —— 机器可验，必须验：

- `referenceFix` / `referenceSolution` 在本机真跑，输出**逐字等于** `expectedOutput`。
- 验证结果带**内容哈希戳**（内容改了戳就失效，防止「改完题忘了重新验」）。

**② 答案唯一。** —— 机器**验不了**，只能靠出题规范约束。这是 AI 最容易违反、而且完全不会自觉的一条：

- **题干必须写死输出格式**：几行、每行是什么、有没有空格、小数保留几位。
  - ❌ 「打印平均值」→ 学员写 `3.33` 还是 `3.333333`？两个都说得通，**按契约判只有一个对**。
  - ✅ 「打印平均值，**保留两位小数**（如 `3.33`）」
- **`codewrite` 的 `stem` 必须写清「输入是什么、要输出什么」**，格式要求不能靠学员猜。
- **测试数据里不能有歧义**：比如「找出最大值」却给了两个并列的最大值——值一样没问题，但如果题目要求打印「最大值的位置」，就出现了两个都对的答案。
- **`codefix` 的 `stem` 不许剧透**：不能说「第 3 行错了」，那是学员要练的能力。但必须说清「它跑不起来 / 跑出来不对，帮本喵修好」。

### 8.3 一个必须现在决定的缺口：错题本不存学员的原答案

**现状**：`WrongBookEntry`（`src/shared/types.ts:161-184`）只有 `key` / `lessonId` / `qid` / `wrongCount` / `lastWrongAt` / `cleared` / `clearedAt` / `ai`——**没有任何字段存学员当时写的答案**。

对选择题无所谓（重做时重新选就行）。但对 `codefix` / `codewrite` **关系很大**：「我当初那段代码到底错在哪」正是最该复习的东西，而它**现在会永久丢失**。

> ⚠️ **改这个字段结构会触发 CLAUDE.md 铁律 6**（bump `version` + 写迁移函数）。而 `wrongbook.json` 的根是**数组**，**连 `version` 字段都没有**——要加就得更彻底一点。
>
> **现在是最便宜的时候**：项目只有 1 个用户，错题本里还没有真实数据。等学员攒了几百条错题再改，代价就是他的错题本。

## 9. 打回与返修流程

- validate 报错 → 把错误信息原样附给生成代理 → flash 模型照错误清单逐条修 → 重新校验。
- 术语告警超标 → 列出违例位置 → 整批重写正文中违例段落。
- 风格走样（口吻/难度问题）→ 由 pro 模型或人工给出修改意见后整批返修。
- 返修后仍需过全部验收标准才入库。
