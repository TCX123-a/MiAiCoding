# 模型切换省钱指南（随时翻喵～）

> 本项目的开发完全靠 AI 模型（在 Claude Code 对话框里手动切换）。不同任务对模型要求不同，**用对模型 = 又快又省钱**。本指南是活文档，开发中发现新的切换时机随时补充。

## 一、核心原则（一句话版）

**费脑子的活用 deepseek-v4-pro（贵但少走弯路）；堆字数的活用 deepseek-v4-flash（便宜且质量差别不大）。**

## 二、什么时候用 deepseek-v4-pro（质量优先）

| 场景 | 为什么 |
|---|---|
| 写代码逻辑、构建工程框架 | 架构与逻辑错误最贵——返工成本远超模型差价 |
| 调试修复 Bug | 排查需要深度推理，flash 容易绕远路甚至引入新 bug |
| 设计数据 schema、IPC 契约、技术选型 | 这些一旦定错，后面所有代码跟着改 |
| 写内容流水线脚本（validate/build/gen-batch） | 校验器逻辑复杂，是内容质量的闸门，必须可靠 |
| 内容生成规范、提示词模板的设计 | 模板质量决定 194 课的整体质量上限 |
| 黄金样例（common-01）的撰写与打磨 | 全量内容的风格基准，值得反复精修 |
| 手工验收清单执行与问题定位 | 判对错需要严谨，不能漏检 |
| 打包/发布期的问题排查 | 环境类报错千奇百怪，需要强推理 |

## 三、什么时候用 deepseek-v4-flash（省钱优先）

| 场景 | 为什么 |
|---|---|
| **批量生成猫娘课文**（M7 全部 41 批） | 文案类输出量大，flash 的猫娘文风和 pro 差别不大；每课独立，错了单课打回成本低 |
| **批量写练习题**（题干 + 答案 + 解析） | 同上；有 validate 脚本 + 运行校验兜底 |
| 大量文案：空状态、提示语、FAQ、错误库解释文案 | 纯文字润色/扩写，flash 完全胜任 |
| 后续功能扩展或小修小补 | 改动面小、风险低 |
| 文档起草（本目录 docs/ 的初稿） | 格式类内容，初稿 flash、终审 pro 或人工 |
| 批量翻译/改写/统一口吻（如把某批课文口吻调一致） | 机械性批量润色 |

## 四、按里程碑的推荐模型

| 里程碑 | 推荐模型 | 备注 |
|---|---|---|
| M0 立项与文档 | pro | 文档定基调 |
| M1 内容体系与流水线 | **pro** | schema/脚本/黄金样例都是关键闸门 |
| M2-M5 功能开发 | **pro** | 全是代码逻辑 |
| M6 复习引擎与 AI 兜底 | pro | 调度逻辑 + 网络边界处理 |
| M7 内容批量生成 | **flash**（提示词模板用 pro 写好） | 41 批 × 5-6 课，省钱大头在这里；抽检修订用 pro |
| M8 整合测试 | pro | 验收不能糊弄 |
| M9 打包发布 | pro | 环境问题排查 |

**省钱大头**：M7 内容生成占全项目文字产出 80% 以上，全程 flash 是本指南最大的省钱点；而它恰恰是对质量最不敏感的部分（有 validate 兜底 + 单课打回成本低）。

## 五、实用技巧

1. **先 pro 后 flash**：任何新类型任务（如「写第一批 C 课」）先让 pro 做 1-2 个样例，确认质量与风格没问题，再切 flash 批量复制这个模式。
2. **打回也用 flash**：内容校验不通过的课，让 flash 照着报错重写（错误信息具体，flash 照改即可），除非是风格走样等需要「悟性」的问题才上 pro。
3. **切换时机**：在 Claude Code 对话框里随时可以切换模型，不必等任务结束；发现 flash 连续 2 次答不对同一个问题，立刻切 pro。
4. **组合拳**：flash 批量初稿 → validate 自动筛 → 人工抽检标问题 → pro 修疑难、flash 修常规。
5. **别让 pro 干体力活**：重复性复制粘贴、批量替换、生成 100 道雷同题——这些 flash 又快又省。
