### 2.2 资产传输：`miai-wall://` 特权协议（首选）

**为什么需要一条传输通道**（不是拍脑袋）：引擎取字节全部走 `fetch()`——`source.ts:287` 对 `scene.pkg`/散装文件**整包 `arrayBuffer()`**（无流式、无 Range，服务器只要真实 200 + 完整 body）；但视频壁纸的默认路径（静音+循环）是 **WebCodecs + mediabunny 的 `UrlSource` 随机读**：发 `Range: bytes=N-`、依赖 `206/Content-Range/Content-Length` 与 **ReadableStream 响应体**（`video-webcodecs.ts:259`；bundle 内逐字 `Missing HTTP response body stream` 报错）。场景内嵌视频反而简单：pkg 字节直接在渲染层造 `Blob → objectURL → <video>`（`scene-mount.ts:2231`），不经网络。

**方案对比与推荐**：

| 方案 | 优点 | 代价 | 结论 |
|---|---|---|---|
| **A. `miai-wall://` 自定义特权协议**（`protocol.handle`，注册 `standard/secure/supportFetchAPI/stream/corsEnabled`） | 不开 TCP 端口（本机其它进程不可达）；流式 + 可做 Range/206；CSP 白名单加一个 scheme 即可；（v2 预留 web shim 注入位——其正确出处是 WebWallGL 仓 `host/we-web-html.mjs`，不在 DSH 仓） | 需自己实现 Range/416/MIME（照抄 DSH serveFile 语义）；Electron 44 下与 fetch/WebCodecs 的配合要在原型里实测（P0-E4） | **首选** |
| B. loopback http（`127.0.0.1:随机端口` + token） | DSH 同款、语义最熟 | 开端口（可被本机其它进程探测/DoS 面）；token 表要自管；CSP 放行 http://127.0.0.1:* | 备选（协议路线在 E4 翻车时启用） |
| C. 纯 IPC 传字节 + `bytesSource`/`fileSource` | 零网络 | 336MB 级 pkg 经结构化克隆整份复制进渲染层（2G 机器风险）；**视频 WebCodecs 默认路径写死 UrlSource(URL)**，走不通就得降回 A/B `<video>`（`file://` 媒体加载器可用但引擎不处理 file://） | 只做场景形态的退路，不做主路 |

**Range 最小实现**（照 DSH `lib/index.js:3196-3264` 语义）：`Accept-Ranges: bytes`、`206 + Content-Range + Content-Length`、越界 `416 + bytes */size`、404 无缓存头、ETag/Last-Modified 可选（省流量）。

**CSP 增补**（现在是唯一一处 `src/renderer/index.html:6-9`，无第二设置点）：

```
default-src 'self'; script-src 'self' 'unsafe-eval'; style-src 'self' 'unsafe-inline';
img-src 'self' data: miai-wall:;
media-src 'self' blob: miai-wall:;
font-src 'self' data: blob:;
connect-src 'self' miai-wall:;
frame-src 'self' blob: miai-wall:;
worker-src 'self' blob:
```

四处放行都是代码取证逼出来的，不是保守加码：

- **`script-src` 加 `'unsafe-eval'`**：引擎用 `new Function` 编译 WE 场景的作者脚本（`text.js:813/:2256`）；不放行时编译抛错且**被 catch 吞成 warn**——场景照常渲染、脚本层静默全灭，普通判据抓不到。E4 必须加「带脚本场景的脚本层生效、console 无 CSP 违规、warn 计数 0」判据。（若主人不接受 unsafe-eval：则 §6 明写「WE 脚本层 v1 不支持」，其余照做。）
- **`worker-src 'self' blob:`**：2.1.0 官方产物内确有 blob: Worker（mediabunny 的 alpha 合并管线，`renderer-AJkjEL9i.js`，报错串 `Color/alpha merge worker error.`）——**它只存在于构建产物、grep 源码树必漏**；缺此指令时回退 `script-src 'self'` 被拒。
- **`font-src` 加 `blob:`**：WE 自定义字体经 `FontFace(url(blob:…))` 装配（`scene-mount.ts:4562`），被拒不报错、静默回退系统字体。
- **`frame-src blob:` 只放行外壳**：跨源 web 壁纸的 blob: iframe 文档会**继承应用页 CSP**（Chromium 策略容器继承），注入的 shim 与壁纸内联脚本仍被 `script-src 'self'` 拒——这是 web 形态 v1 裁掉的直接原因（§6/决策点 11）。

放行面仍然收窄：只加自家 scheme 与 blob:，无 remote 源。**协议处理器内部再做路径围栏**：只允许读「已扫描到的壁纸库根」「我们的帧缓存目录（视频抽帧主图，§4.5）」「引擎静态资源目录」三处，其余一律 404；响应带 `Access-Control-Allow-Origin`（渲染层 file:// origin 下 fetch 需要，E4 加断言）。

### 2.4 性能与省电（硬性要求）

**触发链**（三层，逐级兜底）：

1. **主进程事件（主判据）**：`mainWindow.on('minimize'|'hide'|'blur')` → 推送 `{paused:true, reason}`；`'restore'|'show'|'focus'` → 恢复（恢复延迟 ~300ms 防抖动）。**失焦也停**（按主人硬性要求在默认档落实；DSH 桌面壳因"壁纸仍可见，暂停会定格"刻意不提供失焦档（`pauseOnBlur` 门控），我们把选择权做成设置项：默认停，可选"失焦降档到 10fps 不暂停"）。
2. **`document.hidden`（副判据）**：Electron 最小化时页面可见性会变 hidden，作为第二信源做一致性断言；两者取并集。
3. **3s 复核自愈**：照抄 DSH `OCCLUSION_RECHECK_MS=3000`——每 3 秒重查一次真实状态，防"原生模态丢 focus 事件永久卡暂停"（DSH 踩过的坑，注释在案）。

**暂停动作清单**（单一判定源 `isEffectivelyPlaying`，照 DSH 口径）：引擎实例 `pause()`；`<video>.pause()`；web iframe 无独立暂停——直接把 iframe 从 DOM 摘掉（或置 `visibility:hidden` 省合成）**（web 形态 v1 已裁，此条随 v2 生效）**；视差 rAF 停；音频泵停（可选保留轻量采集，频谱不推）。

**引擎自带省电 API（备用层）**：`SceneInstance.setOcclusion(payload|null)` —— 宿主推矩形、引擎算可见比例，三档 `pause(≤0.05)/heavy(≤0.30, 24fps)/light(≤0.70, 40fps)` + 迟滞 0.05 + dwell 400ms + fail-open 心跳 1s（`shell.ts:709-711`，只在遮挡态存在期间跑）＋推送失联 3s 判死恢复满帧（`occlusion.ts` `OCCLUSION_STALE_MS=3000`）。Electron 窗口被其它窗口盖住时主进程拿不到可信遮挡几何（跨进程无 API），**v1 不用它做窗口遮挡判断**，保留给"画布被内部大弹窗盖住"这类自知的场景（可选增强）。

**2G 预算默认档**：场景 fps 30、`renderDpr` 跟随自动（软渲染探测会自己压到 0.5）、`quality:'auto'`（引擎自适应降档：fps 比例 <0.85 连续 3 次 → 降档，冷却 6s）、切换先垫海报、单实例 + `release()`。低内存策略（决策点 8）：检测 `os.totalmem() < 4GB` ⇒ 场景默认只出海报+视差，设置里可强制打开。

## 3. 四个特性的源码解读与移植设计

### 3.1 特性①：音频监控（音乐反应）

#### 3.1.1 上游全貌（DSH 最新版怎么做的）

- **采集全在外部 Rust 进程 media-bridge v0.1.5**（DSH 仓内**零实现**，只有下载/校验/监督/回退）：Windows = GSMTC（Now Playing）+ **WASAPI loopback**（`windows.rs:357 AUDCLNT_STREAMFLAGS_LOOPBACK`，系统无声时输出静默）；macOS = CATapDescription 进程 Tap（首次要 TCC"音频录制"授权）；Linux = MPRIS + parec/pw-record。
- **DSH 宿主侧 5 条路由**（`lib/routes/now-playing.js`）：`/media-status:76`、`/audio-spectrum:86`、`/now-playing:105`、`/now-playing/artwork:119`、`/media-control:137`。懒启动 `ensureMedia`：`audioSource==='off' && mediaIntegration===false` 不启动；`DSH_WE_MEDIA_NO_AUDIO=1` 连采集都不碰。
- **契约**：`/audio-spectrum` 返回 `{ok, bands, running}`——`running=false` 时客户端**不装桥**（`client.js:1686` 装/卸载成对）；频谱帧 **64 段/声道、0-255、对数 -70dB..0dB、Hann 窗**；宿主经纪 **50ms**（`SPECTRUM_INTERVAL_MS=50`）逐帧推给客户端；客户端 50ms 轮询 → `__wp.setAudioBridge`（左右引用同一数组）。
- **引擎侧是拉模式**：宿主注入 `() => {left,right} | null`，**注入优先**，引擎每帧拉一次；`null` = 本帧无数据（网页形态回落全零、**场景形态回落实况源/已恒静默的模拟源**——两条路径不同，别按一个语义移植）。场景 BGM 分析器仍会把频段按逐段 max 并入快照（`scene-mount.ts:6538`）。
- **标定**：宿主频谱典型 0.1~0.3，作者阈值写 0.5~0.8 → 引擎带 `createSpectrumCalibrator`（targetPeak 0.92 / gain 钳 1..12 / noiseFloor 0.02）把量级拉回作者直觉。

#### 3.1.2 引擎接口（我们要对接的契约，逐字）

```ts
// 库模式（api/types.ts:131-132、:404）
audio?: AudioSource | null
interface AudioSource { snapshot(): { left: Float32Array|number[]; right: Float32Array|number[] } }  // 各 64 段，0..1
instance.setAudio(src | null)
// null 语义（mount.ts:319 注释）：audio:null / setAudio(null) = 显式禁用（频谱恒 0）；bridge 回调返回 null = 本帧无数据 → 回落
```

#### 3.1.3 miai 移植设计

`lib/wallpaper/audio.ts` 实现 `AudioSource`：内部维护 `{left,right}` 各 64 段（Float32Array），以 ~20-33Hz 刷新（对齐 DSH 50ms 与网页形态 30Hz 两档），`snapshot()` 直接返回当前缓存（引擎每帧拉，O(1)）。频谱计算链照抄契约：FFT → Hann 窗 → 对数映射 **-70dB..0dB → 0..1** → **二次分箱**到 64 段 → 校准器（移植 `createSpectrumCalibrator`，五常量照抄：0.92/1/12/0.02）。

#### 3.1.4 两条采集路线（**决策点 4，原型里 A/B 实测后裁定**）

| | A. Electron 原生 loopback（推荐先试） | B. media-bridge 二进制（DSH 同款） |
|---|---|---|
| 机制 | `session.setDisplayMediaRequestHandler` 回 `{ video: 屏幕源, audio: 'loopback' }` → 渲染层 `getDisplayMedia` 拿系统混音流 → `AudioContext + AnalyserNode` → 自算 64×2 段 | 主进程拉起 `media-bridge` 子进程，NDJSON 收 50ms 频谱帧 |
| 新增物 | 零二进制 | win32-x64.exe **7.7MB**（MIT）、监督器、崩溃重拉 |
| 优点 | 无端口无授权弹窗（Windows）、无 Defender/SmartScreen 风险、代码全在我们手里 | 一线成熟；附带 Now Playing（曲目/封面）与 `/media-control`（5 动作） |
| 缺点 | Electron 44 的 audio loopback 行为**本机未实测**（E2 验证项）；无曲目元数据 | 未签名 exe 可能被 Defender 拦（低风险但存在）；体积 |
| v1 范围 | **够用**：音乐反应只需要频谱 | 全量（但 Now Playing 要额外 UI，v1 可先裁） |

**默认推荐**：v1 走 A（零二进制），把 B 作为"设置项里的增强包"或 E2 失败时的兜底；**Now Playing / media-control 两个子特性 v1 砍掉**（决策点 9）。

**口径澄清**：两条路线拿到的都是**整机输出混音**（A=桌面捕获 loopback；B=WASAPI loopback `windows.rs:357`）——「按应用单独采集」v1 两条都不支持、不承诺；GSMTC 能识别媒体会话（歌名/封面）但那属 Now Playing 元数据、不是应用级音频流（决策点 4 同此口径）。
**2G 预算**：频谱计算在渲染层（AnalyserNode 本身很轻，20Hz 级刷新），暂停档停泵；不常驻任何采集进程（路线 A 的 stream 随暂停释放）。

#### 3.2.2 DSH 自研（图片/视频/降级路线可抄的唯一先例）

#### 3.2.3 miai 移植设计

- **统一入口**：`WallpaperLayer` 内一个 `pointermove`（passive）+ `resize` 监听（照 DSH，不加 DOM 节点）；坐标 `clientX/innerWidth, clientY/innerHeight` → 0..1。

- **与过场互斥纪律**：过场进行中暂停视差写值（过场层在动，视差由过渡函数接管），过场结束恢复——避免两套写法打架（DSH 同款纪律：过场 `resetLayerSwitchStyles` 清 transform，视差只动独立属性所以天然不冲突，但幅度叠加仍要错峰）。

### 3.3 特性③：切换壁纸渐变（crossfade 与切换机制）

#### 3.3.1 上游机制（未发布段的最新版，逐条）

- **过场族**：`SWITCH_TRANSITIONS` 7 种（cut/fade/push/wipe/iris/zoom/bars）+ 速度 0.6/1/1.6 + 方向感 + bars 齿数 7。
- **铁律**（CHANGELOG 与 `layer-core.js` 双证）：**只动 `transform/opacity/clip-path`**（mask/filter 在 video/iframe 上踩过坑）；**旧层必须不透明垫底**——"淡到黑"的中间态被**禁止**（玻璃 `backdrop-filter` 采样到透明背景会静默失效；对我们的价值：过场中途任何一帧都必须有完整画面，不能露底板）。
- **内容闸门**：新层挂 `we-layer--pending`（opacity:0）→ 内容就绪判据分级（视频放行**只认当下这一帧**：海报图已加载/`readyState≥2`，属性存在不算）→ 挂 `we-layer--switch` 起过场。视频预算 `VIDEO_POSTER_BUDGET_MS=1200`（`video-layer.js:33`）、停滞 `VIDEO_STALL_GIVE_UP_MS=15000`（:47）就放弃改留旧壁纸（**绝不铺底色**）；**视频不参与准备链预热**（避免双解码，`media-prep.js:112-121`）；另有 DSH 同款「提交前预热」可选移植：hover/pointerdown 时 `preload="metadata"` 单槽位预取、**绝不 play()**、TTL 20s（`video-layer.js:50-105/:219-221`、`client.js:4519-4526`）——v1 可不做，列为 P1 观察项。
- **层切换核心**：`layer-core.js:84 startLayerTransition`（zIndex=-3、强制重排 `offsetWidth`、`tr.ms+60` 清场）；轮播 `prepare→commit`：提交后新层静音闸（先静音出声）、旧层退场后恢复设置音量；隐藏页延后轮播。
- **轮播**：`rotationEnabled` + 候选≥2 才武装；分钟制间隔；`ROTATION_PREP_TIMEOUT_MS=20000`；`ROTATION_FADE_MS=1800`。
- **reduced-motion**：系统开减弱动画 → 走 cut。

#### 3.3.2 miai 移植设计

`WallpaperLayer.vue` 双槽 A/B（两个 `<div class="wp-slot">`，各装一台引擎实例/DOM），状态机：

```
idle → prepare(新槽起、paused、pending opacity:0、垫海报) →
  ready(内容闸门过：场景=引擎 mount() resolve 且首帧 stats.running；
        视频=video.readyState≥2 或 poster loaded；
        图片=img.decode() resolve) →
  switching(旧槽不动，新槽起过场，两侧都保持不透明) →
  commit(音频/音量切到新槽、旧槽 release()/destroy()、清场) → idle
```

**超时组合规则**（三个数字不许各写各的）：首帧预算 `B = clamp(15s…90s, 包大小/8MBps)`＝传给引擎的 `mountTimeoutMs`（引擎默认看门狗 60s 被它覆盖）；**prepare 超时 = max(20s, B+5s)**（手动切换；DSH 轮播的固定 20s 只用于常规尺寸候选）；超时即放弃本次切换、留旧壁纸（绝不露底）。低内存档下 B>60s 的大包直接走海报、不切。

**垫底约定**：壁纸层最底始终垫一层内置 CSS 微渐变（主题双套色、零渲染成本，兼作决策点 7「默认开」的兜底底）；所有槽与过场都叠在它上面——这是「旧层不透明垫底」铁律之外的第一道保险。

- **过场**：v1 实现 cut/fade/push/wipe/iris/zoom/bars 全 7 种（纯 CSS，函数式生成 keyframes/transition，全部只写 transform/opacity/clip-path）。
- **超时与诚实**：prepare 超时按上方组合规则（max(20s, B+5s)）→ 放弃本次切换、留旧壁纸、记 warn（绝不中途露底板）；视频 1200ms 海报预算。
- **轮播**：设置 `rotationEnabled` + 间隔（分钟）+ 顺序（顺序/随机——确定性种子用现有 store 惯例）；隐藏/暂停态延后。
- **`prefers-reduced-motion`**：走 cut。

### 3.4 特性④：自定义调节面板

#### 3.4.1 上游机制（v1.2.0 最新形态）

- **Schema 单一真源**：`lib/settings-schema.js`（80KB）持全量键/默认/范围/净化守卫；UI 滑杆的 min/max 虽手写，但**运行时钳制的唯一真源是 schema**（`clampNum(..., schemaRange(key), DEFAULTS.key)` + 守卫断言两处一致——上游出过"手写数字漂移导致玻璃透明度只能到 20%"的事故，R4 教训）。
- **拖动两档提交**（v1.2.0）：拖动中 `commitLiveSetting` **只写值 + `applyEffects({live:true})` 不落盘**（判据：拖动档 0 次 `getComputedStyle`、不碰字体样式表/场景音频、照写 ≥15 个样式变量）；`change` 才完整走 + emit 落盘。滑块轨道 `--we-fill` 直写。
- **外观参数 → CSS 变量单点投影**：`scrim→--we-scrim-color`、`border→--we-border-alpha`、`wallpaperBlur/backgroundBrightness/backgroundContrast/backgroundSaturate→单条 --we-media-filter`（默认 none）、模糊边缘补偿 `scale=1+blur*0.006`、`flip=CSS scaleX(-1)`、`wallpaperOpacity`；**不透明度依赖实色垫底**（`.we-layer` 必须垫 `--we-wallpaper-fade-bg` 主题实色，否则玻璃采样失效）。
- **液态玻璃配方**（若做）：`linear-gradient` 顶重 specular + `backdrop-filter: blur(16px) saturate(1.3) brightness(1.04) contrast(1.01)` + inset 高光三条 + 0.5px 发丝线 + 软阴影；两级写入（全局 + 按面 `glassMode: inherit|custom`，data-* 门控属性是"证书"）；性能纪律：blur 只在 >0 进链、identity 写 `none`、`backdrop-filter` 放 `::before`（防 fixed 后代的 containing block 事故）。

### 4.2 vdf 解析：**我们写严格版**（不照抄 DSH 的子串匹配）

DSH 实现（`lib/index.js:330-337`）逐字：`/^\s*"path"\s+"([^"]+)"\s*$/` 取 path；`current = m[1].replace(/\\\\/g, '\\')` 去转义；**`if (current && line.includes('431960'))` 全行子串匹配**——已实测假阳性：某库 `update_clean_bytes_tally` 写 `"1431960"` 就会被误判为拥有 WE。miai 版：解析到 `"apps"` 块内后，**按"引号内键名完全等于 `431960`"匹配**（正则 `^\s*"431960"\s`），并把"path→apps"结构显式建模（不进 apps 块就不认）。

**本机实测基线**（真样本对拍已做）：vdf 574 字节、LF、单库、path 存双反斜杠转义形、apps 块 13 条、431960 在 `:16`。**多库分支本机无样本** ⇒ 夹具必须自造，四类用例：①库A无 WE / 库B有；②子串假阳性（tally=1431960，**我们的解析器必须绿、DSH 口径必须红**——这就是差异判据）；③CRLF + 单反斜杠路径；④path 在 apps 块后 / 缺 path 属主。

### 4.4 场景形态判定与 pkg 解析（口径按代码，不按注释）

- 形态判定（`source.ts`）：`project.file` 以 `.json` 结尾 → 试**散装**（loose），否则/失败 → pkg；`PKG_PATHS=["scene.pkg","scenes/scene.pkg","gifscene.pkg"]`；**两个例外分支必须实现**：`preview.*` → pkg 豁免（:47）、project.json 声明的自定义 `*.pkg` 先于 PKG_PATHS 尝试（:275-279）。
- pkg 解析是引擎内建（`renderer/vendor/we-scene/pkg/`）：magic **只查 `startsWith('PKGV')`**（"0012~0023" 只是注释里的实测说明，**不是**版本区间校验）；LZ4 探测 + 链校验；解压目标闸门是 `assertDecodeSize`，上限 = `TEX_LIMITS.maxPixels×4 = 512MB`（语料实测最大 256MB、留 2× 余量）。注意别混记：DSH **宿主侧**另有一个单包常量 `MAX_DECOMPRESSED_BYTES=256MB`（`lib/pkg-read.js:22`），与引擎侧闸门含义不同。移植**零成本**（浏览器进 bundle）。
- 尺寸护栏（引擎侧无 pkg 字节上限）：场景缓存＝**总预算 512MB 且至多 2 份**（超限从最旧淘汰、当前使用的一份豁免，`scene-mount.ts:236-277`）、`MOUNT_WATCHDOG_MS=60000`（可被 `mountTimeoutMs` 覆盖）、纹理 `TEX_LIMITS`（maxDim 16384 / maxPixels 1<<27；解压闸=maxPixels×4=512MB）。**进度与首帧超时宿主自理**——miai 版：协议层报字节进度（Content-Length 已知）；首帧预算 `B=clamp(15s…90s, 包大小/8MBps)` 作为 `mountTimeoutMs` 传入，与 prepare 超时的组合规则见 §3.3.2。

### 4.5 降级链（"高清主图 + 动态微调"，不许廉价）

```
选中壁纸
 ├─ scene：引擎 mount()（协议供 pkg/散装）
 │    成功 → 场景渲染（首帧后 resolve）
 │    失败/超时/低内存策略 → 进降级主图
 ├─ video：默认 WebCodecs+UrlSource（静音+循环时引擎自选，协议需 Range/206）；
 │    失败或带音量 → 回退 A/B <video muted loop>
 ├─ web：v1 裁掉（§6/决策 11）——web 型壁纸直接走降级主图
 └─ 降级主图（分级来源，按序）：
      ① video 型：本机抽一帧（<video> seek → canvas.drawImage → JPEG，
         零依赖零转码，分辨率≈源视频；写帧缓存目录复用）＋CSS 视差微调；
      ② scene 型：preview 主图（Steam preview.jpg，本机实测最高 1024²、
         最低 192²；<512² 时如实标注「预览图清晰度有限」）；
      ③ 全失败：提示 + 保持当前壁纸（绝不铺底色）
      全部叠 §3.2.3 视差 + 可选极缓慢平移（scale 1.06 范围，30s 周期）；
      UI 如实标注降级来源（DSH 诚实化原则：不替作者猜图）
```

**不做「gpu 抓帧回填」**（DSH 的 `gpu 抓帧 → next frame` 是它实时渲染页的机制，我们 v1 不建渲染页），列为 v2 候选；注意它与 ① 的「视频抽帧」是两回事——后者只是读源文件一帧、零依赖。

### 4.6 口径修正备忘（首轮四条 partial，防照注释抄错）

1. 音频桥 `null` 语义分叉：网页形态=全零；**场景形态回落实况源/恒静默模拟源**——移植按"场景"路径设计。
2. `mount()` 首帧门控：**场景形态**=首帧画完 resolve + 60s 看门狗；**网页形态**=iframe load 即 resolve（别当"首帧已渲染"用）。
3. PKGV 只查前缀（见 §4.4），兼容口径**不得写死版本区间**。
4. 场景形态判定有 `preview.*` 豁免与自定义 `.pkg` 优先两分支（见 §4.4）。
