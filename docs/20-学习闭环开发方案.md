### 2.2 IPC 新增与实现纪律（通道走既有 4 步套路 + `ipc-wiring.test.ts` 静态闸门）

- `wrongbook:record` 入参扩展 `source`（不加新通道）
- `wrongbook:update`：**一批** `{ key, patch: { removed?, hole? } }[]` → 返回新列表（软删/恢复/标漏洞共用一条；主进程合并写，不给渲染层整份覆盖的机会。**2026-09-29 实现时定为一批**：清空 = 批量软删，要一发做完——一条一趟的话中途失败会留下"删了一半"的状态，而列表页拿到的快照也就对不上了。找不到 key 跳过不抛（列表是快照，手速会超过刷新）；整个入参写错照抛）
- `favorites:get` / `favorites:save`（整份保存，仿 profile 的防抖落盘——收藏文件只有渲染层一个写方，安全）
- `practice:record`（一次完成落一条 history）/ `practice:get`
- `gallery:save-image`：奖励图下载（主进程 `dialog.showSaveDialog` + 落盘；渲染层只传**图 id**，主进程按 `app.isPackaged` 在 out/renderer 或 src 源目录解析文件——不走 file:// URL，避开 dev/prod 两套路径；**用户取消返回"取消"值而不是抛异常**，照 `AiResult` 失败即值的语义。**实现随阶段 5（奖励图库就位时），阶段 0 不建空 handler**）

## 3. 模块一 · 题库与难度体系

### 3.1 类型（`src/shared/types.ts`）

```ts
export type Difficulty = 'easy' | 'medium' | 'hard' | 'challenge'  // 简单/中等/困难/挑战，显示名进 copy.ts
```
- 六种题型统一加 `difficulty?: Difficulty`（**可选覆盖字段**；缺省由 §3.2 规则解析；AI 题缺省 medium）。
- **questionIndex 不进 bundle**：实测 bundle 已 16.1MB（lessons 12.3MB + searchIndex 3.8MB），再塞 4023 条 ≈ +2~3MB，且 content.ts 是静态 import、每次启动都要解析这些字节，而 `check:packed` 看不见体积暴涨。改为**运行时**构建：`src/shared/question-index.ts` 的 `buildQuestionIndex(lessons)`（毫秒级），条目 `{ key, lessonId, lang, stage, type, difficulty(解析后), tags, stem }`，附按 lang/stage/难度/标签的纯函数查询（全部单测）。
- 课级 tags 维持自由文本不重构（108 个取值、多为单例，不适合当主键）；**知识点单位 = 课**，标签只做匹配辅助。

### 3.2 难度规则（唯一定义在 `src/shared/difficulty.ts`，不批量改写内容文件）

- `src/shared/difficulty.ts`：`Difficulty` 值域 + `resolveDifficulty(q, stage)` + 显示名映射 —— 运行时与守卫共用**这一份**（不做第二份 .mjs 拷贝；gen-bank 只透传模板里的显式值，用不到规则）。默认规则表（主人可点名改）：

| 来源 | 题型 | 难度 |
|---|---|---|
| 手写 | choice / fill | 简单 |
| 手写 | code / codefill | 中等 |
| 题库 | codefix（stage1-2 / stage3） | 中等 / 困难 |
| 题库 | codewrite | 困难 |
| 精选模板（显式 `difficulty:"challenge"` 写进模板 JSON，可审可改） | codefix/codewrite | **挑战** |

- **不批量改写 439 份内容文件**（229 手写 + 210 题库）：默认值运行时解析，显式 `difficulty` 字段只在要覆盖时出现。既不产生噪声 diff，也不怕 `gen-bank --force` 重算把谁手盖的值冲掉。`contentHash` 字段集**原样不动**（已核实不含 difficulty，2553 条验证戳保持有效）。
- gen-bank：模板 schema 加可选 `difficulty`，显式值原样透传进新条目；**现有条目不动、不加 --force**。
- 校验三处：① `content-validate.mjs` 逐题链（:390 起）加「显式 difficulty（若有）必须在值域内」；② 新增 **vitest 内容测试**（照 `content-reachability.test.ts` 先例加载真内容）：每课合并题池**非挑战题 ≥5** + 难度分布打表（即"难度分布报告"）+ 挑战题清单快照；③ `content-build.mjs` 不动。守卫先跑现有内容，**红了先当发现报告给主人，不静默放宽**。

### 3.3 组卷过滤（挑战题的使用范围 = 规格里的"只在阶段/整门/每日挑战出现"）

- 过滤发生在**调用方选池时**（不要给 `buildPaper`/`buildPool` 加参数——它们签名被测试钉着，`buildPool` 还有 host lesson 保底教训）：lesson / random / wrong / fav / review / extend / search 七类组卷**排除 challenge**；stage / lang / 每日挑战**不排除**（每日挑战池维持 learned-only，不掺难度过滤）。
- 筛选不足时**按邻近难度放宽补齐**，绝不出空卷或重复题（单测钉住补齐边界）。
- 阶段/整门卷的配比（纯函数 `shared/stage-paper.ts`）：跨课取样（≥60% 的题来自不同课）、困难+挑战占比有下限（阶段卷 ≥40%，整门卷 ≥50%），题量默认阶段 10 / 整门 15（可调）。

### 3.4 题库扩充（尤其是代码大题/改错题）
