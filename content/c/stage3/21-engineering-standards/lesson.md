## 钩子：能跑的代码，和读得下去的代码

大肥鱼交上来一段开头。本喵接过来读了三行，眉毛就立起来了：

```text
#define max_count 42
int FishCount = 3;
int useremail = 2;
```

能跑 —— 可这代码写得太丑啦喵！

「丑」不是审美问题：名字一乱，读的人（包括三个月后的你自己）每读一行都要停下来猜；注释要么没有、要么全是废话；招牌本上不站守卫，被抄两遍就炸。

这一课借几把很有名的尺子（以 Google 的 C++ 风格指南为主，加上几把同样流行的小尺子），把 C 工程里最常照面的几条规矩立起来。先记本课的底层判据：**规范的目的是让下一个读代码的猫少费点劲** —— 想不通的条目，回到这句话上多半就通了。

## 一、名字的规矩：小仓库写小写，招式看尺子

工程里最常起名的是两样东西：**变量（小鱼干仓库）**和**函数（招式）**，另外还有宏（下一节单说）。

**小仓库的规矩干脆：全小写 + 下划线分词。**

```text
int fish_count = 3;      // 体面：全小写、下划线分词，一眼读出「鱼的条数」
int FishCount = 3;       // 大小写混搭：读的人得停一下
int useremail = 2;       // 两个词糊成一坨：最糟
```

第三种最要命：`useremail` 到底该断成 user + email，还是 use + remail？读的人得自己猜；写成 `user_email`，谁都一眼读懂。

**招式的规矩，江湖上有两把尺子。** Google 那把说：普通招式用**大驼峰**（PascalCase）—— `AddTableEntry`、`DeleteUrl`，每个词首字母大写、不加下划线。可同样流行的一把尺子（很多系统向的 C 工程在用）说：招式也该**全小写 + 下划线** —— `add_entry`、`delete_url`。两把尺子各有各的道理；最要紧的不是选哪把，是**在一个工程里挑一把、从一而终** —— 同一个文件里两种写法打架，那才是真的丑。所以本课出题时，专挑没有争议的规矩考：小仓库全小写、宏全大写，这两条在哪把尺子下都不翻案。

最后一条铁律：**全大写是留给宏的**。招式要是写成 `MAXSIZE` 这种样子，就像小仓库穿礼服 —— 一眼就知道穿错了。**名字长什么样，先告诉读的人它是哪种东西。**

## 二、宏和常量：全大写

宏的规矩干脆：**全大写 + 下划线分词** —— `MAX_SIZE`、`FISH_LIMIT`。为什么对它这么严？因为宏是预处理阶段的**原地替换**：名字起得太随便（`max`、`size`），替换起来六亲不认，撞上别人的名字就是事故。Google 那把尺子还加一条：宏名带**工程前缀**（`MYPROJECT_ROUND`），免得和别的工程、系统里同名的宏打架。

顺带把这队也归了：用 `const` 存下来的固定值（常量），一样全大写。**「一眼看出它是固定值」比「省两个字符」值钱。**

```text
#define MAX_SIZE 100      // 体面
#define max_count 42      // 该改：全大写 → MAX_COUNT
```

## 三、头文件的规矩：招牌本上站守卫

招牌本（头文件）会被 `#include` 原样抄进好几个本子里 —— 这件事上一阶段「多文件编译与头文件」那一课就讲过，第 19 课（多文件那一课）又重温了一遍。同一本招牌被抄两遍，里面的东西就重复两遍 —— 声明重复还好，**万一有人把完整做法塞进去，重复就是事故**（还记得「同一份工报了两次」吗）。所以招牌本头上要站守卫：

```text
#ifndef FISH_TANK_WATER_H_
#define FISH_TANK_WATER_H_

int water_level(void);

#endif  // FISH_TANK_WATER_H_
```

守卫三步：`#ifndef` 先问一句「没定义过这个记号吧？」；没定义过就 `#define` 当场记下、继续往下读；等它被抄第二遍时，第一句就把整段拦掉了。收尾的 `#endif` 后面把记号名原样再写一遍配成对 —— 长文件里一眼找到边界。

守卫的记号名怎么起？Google 那把尺子给的形状：**`<项目名>_<路径>_<文件名>_H_`**，全大写，斜杠和点都换成下划线。工程叫 `fish`、文件住在 `fish/tank/water.h`，记号名就叫 `FISH_TANK_WATER_H_` —— **带上路径和文件名是为了重名不打架**：哪天又冒出一个同名的 `water.h`，记号名照样分得开。

最后一条分工铁律：**头文件只放声明，不放做法**。第 19 课那两个坑（找不到、找多了）有一半就是分家没分干净惹出来的。

## 四、注释的规矩：写「为什么」，不写「是什么」

```text
i++;  // i 加一 —— 这叫「复述代码」：看着像在讲解，其实一个字没多说，删掉
```

这种注释写了等于没写 —— **代码自己会说「是什么」**。注释的金贵位置，是写代码说不出来的东西：

- **招式旁边**：写「怎么用它」—— 什么情况下该喊它、有什么讲究；
- **做法里头**：写「为什么这么写」—— 那些不显然的决定，比如一个来路奇怪的数字，注释里说清它的出处，别人改的时候才不敢乱动：

```text
// 财务的结算口径按整点日切，所以这里要手动补一小时
```

- **文件头**：每个 `.c` 文件（头文件也一样）最上头，写两件事 —— 项目要求的**许可/版权行**，和一句话说清**这个文件负责什么**。Google 那把尺子还有个反着来的讲究：**新文件不写作者行** —— 人会走、会换，写上去很快就不作数，想找负责人去看提交记录。

最后是 **TODO 便签**：临时放着、以后要回来处理的事，要写成能被搜出来的样子。Google 的格式：`TODO` 后面跟**一对括号**，里面放一个能提供来路的线索 —— 单号、名字、邮箱都行；冒号后面写清楚要干什么。

```text
// TODO(bug 12345): 结算口径要和财务对齐
// TODO(2026-12-31): 等结算线上线后，拆掉这段过渡代码
```

反例就是 `// TODO: 以后再说` —— 将来搜出一屏「以后再说」，一条都认不出该找谁。要点是**可检索**：挂上具体的人、单号或日期，三个月后的你才回得来。

## 五、正反例对照：一段开头，两种命运

```text
// 不体面的开头                // 体面的开头
#define max_count 42            #define MAX_COUNT 42
int FishCount = 3;              int fish_count = 3;
int useremail = 2;              int user_email = 2;
// TODO: 以后再说                // TODO(bug 12345): 结算口径要和财务对齐
```

同一段开头，左边读三行要停三次，右边一顺到底。差别就这么大 —— **而它一分性能都不花**。规范每一条都是这么来的：不是为了让代码「好看」，是为了让下一个读它的猫少卡壳。

::: tip 交一部分给机器
格式这种事（缩进、空格、对齐），本来就该让机器去挑刺：社区有把常用的自动橡皮擦叫 `clang-format`，吃一份风格配置就能把整份文件重排一遍（`-style=Google` 就是照 Google 那把尺子重排；`-n` 可以先比划、不落笔）。本项目的工具链里暂时没有它 —— 但先记住有这么个出路：**能交给机器的一致性问题，别靠人眼硬盯**。
:::

::: tip 猫咪提示
今天收六句话：

1. **小仓库全小写 + 下划线**：`fish_count`，不是 `FishCount`、更不是 `useremail`。
2. **招式挑一把尺子、从一而终**：一个工程里别让两种写法打架。
3. **全大写留给宏和常量**：`MAX_SIZE`；宏名可以带工程前缀。
4. **守卫的记号名照 `<项目名>_<路径>_<文件名>_H_` 起**：`#endif` 后面配同名注释；头文件只放声明。
5. **注释写「为什么」**：复述代码的删掉；文件头写许可 + 职责；新文件不写作者行。
6. **TODO 要可检索**：`TODO(bug 12345):` —— 括号里是能找回来路的线索。
:::

## 小任务

1. **改一段丑名字。** 把钩子里那段开头（`max_count`/`FishCount`/`useremail`）亲手改成体面版，编译跑一遍：功能一个不许动，只动名字。
2. **给守卫起名。** 给自己工程里的某个头文件补上守卫：照 `<项目名>_<路径>_<文件名>_H_` 的样式起记号名，`#endif` 后面写同名注释。想想「路径」要不要写全。
3. **清一遍注释。** 翻出最近写的一段代码：删掉一条「复述代码」的注释，换一条「为什么」的进去；再找一处最该挂便签的地方，写一条能被搜到的 `TODO(...)`。
4. **挑一把尺子。** 去翻翻你现在工程里的招式命名 —— 是不是两种写法混杂？选定一把，把另一把写法的地方清一遍（哪怕只改你这一周碰过的文件）。

规范这一课，没有报错让你撞、也没有闪光的新工具 —— 它管的是「三个月后的你」和「坐在你旁边的猫」。大肥鱼把那段开头改完，自己读了一遍，满意地眯起眼：「这回读得下去了喵。」—— 恭喜，C 语言主线三阶段，到这里全部收工。见喵～ 🐾
