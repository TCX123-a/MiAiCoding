## 钩子：数不对，屏幕上却什么都没有

本喵的稿子跑得起来、印得出数，屏幕上**一句提示都没有** —— 可那个数不对喵。本喵拿爪头数了三遍，该是 14，它印的是 11。

这种虫最气人：翻译官喵不拦、程序不崩，就是**安安静静地错**。光靠盯着稿子看，看到眼睛发酸也未必找得着。前面「高级宏技巧」那一课，本喵给过你一个「抓虫开关」—— 让稿子自己说话，把仓库里的数印出来。可有些地方你压根不知道该印哪个仓库 —— 这时候就得请一个**看守**来，它能让稿子**停在你指定的地方**，再把那儿的东西一件件翻给你看。

那个看守叫 `gdb`，本机工具房里就有喵。

## 请个看守：进门四件事

请看守之前，稿子得先**留下爪印**：编译的时候带上 `-g`，它才会记住「哪一行对应哪条机器指令」。不带 `-g`，看守只认一串地址，读不出「第几行」。

```text
gcc -g -Wall -o sum.exe sum.c
gdb ./sum.exe
```

进门以后，四件事就够本喵用了喵：

| 想干什么 | 敲什么 |
| --- | --- |
| 让稿子跑到某个地方**停下来** | `break 名字`（或者 `break 文件名:行号`） |
| **开跑**（跑到断点就停） | `run`，也可以只敲 `r` |
| **接着跑**到下一个断点 | `continue`，也可以只敲 `c` |
| **收工**出来 | `quit`，也可以只敲 `q` |

停在某处之后，还有两件趁手的：

- `print 仓库名`（可以只敲 `p`）：把这个小鱼干仓库（或者一排猫粮碗里的某一碗）里的东西**翻出来看**；
- `next`（`n`）和 `step`（`s`）：**一步一步走**。`next` 遇到招式**当一步跨过去**；`step` 遇到招式就**走进去**看。

## 断点：让它跑到这儿就停下

本喵那份稿子长这样（先带 `-g` 编出来）：

```c
#include <stdio.h>

int sum_from(int fish[], int start, int count) {
    int sum = 0;
    for (int i = start; i < count; i++) {
        sum += fish[i];
    }
    return sum;
}

int main(void) {
    int fish[5] = {3, 1, 4, 1, 5};
    int sum = sum_from(fish, 1, 5);
    printf("总数是 %d\n", sum);
    return 0;
}
```

```text
总数是 11
```

五个数是 `3 1 4 1 5`，加起来明明是 14 喵。本喵在 `sum_from` 这招的门口撂一个断点：

```text
(gdb) break sum_from
Breakpoint 1 at 0x...: file sum.c, line 4.
```

「`Breakpoint 1`」就是「**1 号断点**」的意思，后头跟着它落在哪一行。

## 观察：把每个仓库翻出来看

（会话里的地址、编号这些每台机器都不一样，本喵抹成了 `...`，别的原样喵。）

```text
(gdb) run
Thread 1 hit Breakpoint 1, sum_from (fish=0x..., start=1, count=5) at sum.c:4
4	    int sum = 0;
(gdb) backtrace
#0  sum_from (fish=0x..., start=1, count=5) at sum.c:4
#1  0x... in main () at sum.c:13
(gdb) print start
$1 = 1
(gdb) print count
$2 = 5
(gdb) print fish[0]
$3 = 3
(gdb) next
5	    for (int i = start; i < count; i++) {
(gdb) next
6	        sum += fish[i];
(gdb) next
5	    for (int i = start; i < count; i++) {
(gdb) print i
$4 = 1
(gdb) print sum
$5 = 1
(gdb) next
6	        sum += fish[i];
(gdb) print i
$6 = 2
(gdb) print sum
$7 = 1
(gdb) continue
总数是 11
```

一眼就看见了喵：停在招式刚进门的地方，`start` 是 **1**。绕鱼干跑圈从 `i = start = 1` 开始，于是排在最前头那碗 `fish[0]`（里头是 `3`）**压根没进过圈** —— 加起来自然少了 3。

（跑起来的时候，`print` 印出来的 `$1`、`$2`…… 是看守给每次翻出来的东西编的号，方便你回头再拎它出来 —— 比如敲一句 `print $3`，它就把那件东西重新叼给你看。）

要是本喵把 `start` 传对了（传 `0`），这一圈就会从 `fish[0]` 开始 —— 不过这种事别猜，**让看守说话**：改完再跑一遍，看它印出来的数对不对。

## 一摞猫粮碗：`backtrace` 看「谁喊了谁」

上面那句 `backtrace`（也可以敲 `bt`）印出来的两行，就是**一摞叠起来的猫粮碗**喵：

```text
#0  sum_from (fish=0x..., start=1, count=5) at sum.c:4
#1  0x... in main () at sum.c:13
```

最上头 `#0` 是**现在停住的那一层**，往下 `#1` 是「**谁喊了它**」—— 这里是 `main` 在第 13 行喊的 `sum_from`。要是招式一层套一层，这摞碗会一叠叠往上长；哪一层出的岔子，顺着看下去就找到了。

本喵最爱它的一点是：**每一层连递进去的东西都替你翻出来**。刚才那行 `#0` 里，`start=1` 明明白白摆在那儿 —— 本喵都不用敲 `print`，一眼就看见虫了喵。

## 内存泄漏排查思路

换了虫的品种：这回稿子**数全对**，可跑久了机器越来越喘。多半是「**现要现租的仓库**」只租不还 —— `malloc` 租了一间仓库，用完了忘了 `free` 还回去，那一间就一直挂在账上。跑一次看不出、跑一万次就爆仓库喵。

```c
#include <stdio.h>
#include <stdlib.h>

int main(void) {
    int *bowl = NULL;
    for (int i = 0; i < 3; i++) {
        bowl = malloc(4 * sizeof(int));
        if (bowl == NULL) {
            return 1;
        }
        bowl[0] = i;
        printf("[租] 第 %d 回，放的是 %d\n", i + 1, bowl[0]);
    }
    free(bowl);
    printf("[还] 第 1 回\n");
    printf("收工\n");
    return 0;
}
```

```text
[租] 第 1 回，放的是 0
[租] 第 2 回，放的是 1
[租] 第 3 回，放的是 2
[还] 第 1 回
收工
```

数一数：**租了三回、还了一回**。差出来的两间就是漏掉的喵 —— 前两回那张猫爪指向牌，被 `bowl = malloc(...)` 这一句**顶掉**了：牌子上写着新仓库的地址，旧仓库的地址再也没人记得，想还也还不回去了。

排查的思路就四步，不靠好工具也能摸到线索：

1. **配对**：把稿子里每一处 `malloc` 和每一处 `free` 各点一遍，看看是不是**一处租配一处还**。这一步用眼睛就能做完，漏得最多的就是它。
2. **编号对账**：给每次租、每次还各配一句**带编号的打印**（就像上面那几行 `[租] 第 N 回`），跑一遍把两串编号对一对 —— 差几个号，就是漏了几间。好处是**跑起来才算数**，不用猜。
3. **缩小范围**：编号对不上时，别盯着整份稿子看。把可疑的那一小段**单独拎出来**跑（本喵上面那段就是拎出来的），范围一小，虫自己就露头了。
4. **特别盯「绕圈里租」**：每一圈都租一间、绕完圈只还最后一间 —— 漏的正好是「**圈数 − 1**」间。上面那段就是一模一样的形状喵。

> 本喵试过偷懒：让 gdb 直接在 `malloc` 上打断点，想让它替本喵数。结果它**一口气停下来好几回** —— 连工具房自己内部租的仓库都被绊住了，数起来反而更绕。所以这条路上本喵还是信「编号对账」这只笨办法：**它慢，但它不骗你**喵。
>
> （Linux 那边的工具房里有专门数租借的家伙，比如 valgrind，一跑就把漏在哪儿报出来。本课教的是**没有它也能摸到线索**的思路 —— 对账这件事，一张纸和一双眼睛就够了。）

::: tip 猫咪提示
抓虫的口诀，记四条就够喵：

1. **编译带 `-g`**，看守才认得出「第几行」；
2. 先想清楚「**该在哪儿停下**」再敲 `break` —— `break 招式名` 停门口、`break 文件:行号` 停精确位置；
3. 停下之后**别急着改**：`print` 翻仓库、`backtrace` 看那摞碗、`next` 一步一步走 —— 先看清**实际**发生了什么，再动手；
4. 租了的仓库要还（`malloc` 配 `free`），对不上账就先**数编号**、再**缩小范围**。

最后一条最要紧：**别猜**。你猜「大概是这儿吧」，看守只用一行 `$1 = 1` 就能把你打回原形喵。
:::

## 小任务

1. 把课文里那份「数不对」的稿子敲进去（带 `-g` 编译），用 `break`／`print`／`next` 亲手把 `start` 是 `1` 这件事**抓出来**；
2. 把它改对（`start` 传 `0`），再跑一遍，看总数变成 14；
3. 再写一段「绕圈里租、圈外只还一回」的稿子，给每次租和还配编号，跑起来数一数漏了几间；
4. 最后试一试：在绕圈里**每一圈都还回去**（记住：圈里还了，圈外**原来那一句 `free(bowl)` 就得删掉** —— 留着它就是把同一间仓库还了第二回）。这么改完，编号对账两串就一样长了喵。

   踩错了是这个下场：本喵真试过，屏幕上**一个字都不会有**（连前面那几行 `[租]` 都被一起吞掉），程序直接断气，退出码是 `0xC0000374` —— Windows 那边管它叫「仓库账本对不上」。**多还一次和少还一次，一样要命**喵。
