## 钩子：贴在墙上的那张配方卡

本喵的鱼塘小屋墙上贴着一张配方卡：「每只猫 3 条小鱼干」。这张卡不是菜谱，也不是招式 —— 它是**开工之前先照抄一遍的条子**喵。

翻译官喵每天早上开工的第一件事，就是把墙上的卡一张张念一遍，然后把卡上的字**原样抄**到稿子里凡是用到它的每个地方。之后它才开始正经翻译。这些贴在墙上、开工前就被照抄出去的条子，就叫**宏**。

「照抄」这两个字是这一课的全部要害：抄出去的是**字**，不是**意思**。字一旦抄错地方，意思就跟着歪 —— 而且翻译官喵**一声都不会吭**。

## 宏的第一种：不带投喂的条子

最老实的宏就是给一个数起个名字：

```c
#include <stdio.h>

#define FISH_PER_CAT 3

int main(void) {
    int cats = 4;
    printf("%d 只猫，一共要 %d 条小鱼干\n", cats, cats * FISH_PER_CAT);
    return 0;
}
```

```text
4 只猫，一共要 12 条小鱼干
```

`#define FISH_PER_CAT 3` 这一行没有分号，也不占内存 —— 它只是墙上的条子。稿子里写 `FISH_PER_CAT` 的地方，翻译官喵开工前统统换成 `3`，所以最后算的是 `4 * 3`。

好处是「只改一处」：哪天想让每只猫多分一条，只动墙上那张卡就行，稿子里一个字都不用找。往后你会看到，大写字母加下划线的名字（`FISH_PER_CAT`）是给宏起名的老规矩，为的是让读稿子的猫一眼认出「这是照抄的条子，不是招式」喵。

## 边界一：投喂和整体，都要穿小括号

带投喂的宏，长得像招式：

```c
#define DOUBLE(x) x * 2
```

它抄的时候是**连投喂一起照抄**的。所以要是你喂进去的不是一个数、而是一个式子，事情就热闹了：

```c
#include <stdio.h>

#define DOUBLE_BAD(x) x * 2
#define DOUBLE_GOOD(x) ((x) * 2)

int main(void) {
    printf("不带括号：%d\n", DOUBLE_BAD(1 + 2));
    printf("带括号：%d\n", DOUBLE_GOOD(1 + 2));
    return 0;
}
```

```text
不带括号：5
带括号：6
```

`DOUBLE_BAD(1 + 2)` 抄出来是 `1 + 2 * 2` —— 乘号先算，成了 `1 + 4 = 5`，而本喵明明是想要 `(1 + 2) * 2 = 6`。`DOUBLE_GOOD` 抄出来是 `((1 + 2) * 2)`，括号把它夹住了，答案才对。

**时机就这两拍**：翻译官喵先把字照卡抄完（这一步**一个数都不算**），抄完才轮到它按优先级算。5 和 6 的差别，全藏在**抄出来的那串字**里 —— 所以括号是卡上就得写好的，事后补不回来喵。

这里头其实有**两层**括号，少一层都会漏：

- **投喂各穿一层**：`(x)` —— 管住「喂进来的式子别被扯开」。
- **整体再穿一层**：`( ... )` —— 管住「整个结果别被外面的运算吃掉」。

整体那一层最容易被忘。看这段：

```c
#include <stdio.h>

#define HALF_BAD(x) (x) / 2
#define HALF_GOOD(x) ((x) / 2)

int main(void) {
    printf("不带括号：%d\n", 100 / HALF_BAD(4));
    printf("带括号：%d\n", 100 / HALF_GOOD(4));
    return 0;
}
```

```text
不带括号：12
带括号：50
```

`HALF_BAD` 的投喂穿了括号，看着挺像样，可整体光着 —— `100 / (4) / 2` 从左往右算成了 `12`。`HALF_GOOD` 才是本喵要的 `100 / 2 = 50`。

::: warn 小心喵
带投喂的宏，**每个投喂都穿衣、整体再穿衣**，这是死规矩喵。少穿一层，翻译官喵不会报错、不会警告，它只会照抄出一句你没写过的式子，然后安安静静地算错。上面两个例子里，不带括号的版本都印出了一个**看着很像那么回事**的数（5、12）—— 这才是它最坏的地方。
:::

## 边界二：宏会把投喂算两遍

招式是**先算好投喂再进门**；宏是**照抄**，抄几遍就写几遍。要是一个宏里某个投喂出现了两次，那个投喂就会被算两遍：

```c
#include <stdio.h>

int fish = 5;
int take_one(void) {
    fish = fish + 1;
    return fish;
}

#define BIGGER(a, b) ((a) > (b) ? (a) : (b))

int main(void) {
    int biggest = BIGGER(take_one(), 3);
    printf("最大的是 %d，鱼缸里现在是 %d\n", biggest, fish);
    return 0;
}
```

```text
最大的是 7，鱼缸里现在是 7
```

`BIGGER` 的条子上，`a` 出现了两次。抄完以后成了「先比一比、再挑一只」，于是 `take_one()` 被喊了**两遍**：鱼缸从 5 变成 6、又变成 7，`biggest` 拿到的是第二遍的 7。本喵只想喂一条鱼，结果喂掉了两条喵。

换成真招式就没事了 —— 招式**进门之前**投喂只算一次：

```c
#include <stdio.h>

int fish = 5;
int take_one(void) {
    fish = fish + 1;
    return fish;
}

int bigger(int a, int b) {
    return a > b ? a : b;
}

int main(void) {
    int biggest = bigger(take_one(), 3);
    printf("最大的是 %d，鱼缸里现在是 %d\n", biggest, fish);
    return 0;
}
```

```text
最大的是 6，鱼缸里现在是 6
```

同样是「挑大的那只」，喂一条就是一条。**所以：带投喂的条子，投喂里别放「算一次就会变一点」的东西**（自增、收输入、喊招式都属于这一类）。真要放，就老老实实改成招式写。

## 边界三：好几句话的宏，要用 `do { ... } while (0)` 包起来

宏还能一次抄好几句话。可它一旦被塞进 `if` 后面，就会出事。本喵真写了这么一段，翻译官喵当场翻不下去：

```c
#include <stdio.h>

#define REPORT(msg) { printf("收货：%s\n", msg); printf("记账完毕\n"); }

int main(void) {
    int fish = 7;
    if (fish > 3)
        REPORT("小鱼干");
    else
        printf("今天没收到\n");
    return 0;
}
```

```text
main.c: In function 'main':
main.c:9:5: error: 'else' without a previous 'if'
```

抄出来的样子是 `if (fish > 3) { ... }; else ...` —— **花括号后面那个分号把 `if` 收尾了**，后面的 `else` 就没了主，翻译官喵不干了。

规矩的写法是拿一对「跑一次的圈」把它包住：

```c
#include <stdio.h>

#define REPORT(msg) do { printf("收货：%s\n", msg); printf("记账完毕\n"); } while (0)

static void deliver(int fish) {
    if (fish > 3)
        REPORT("小鱼干");
    else
        printf("今天没收到\n");
}

int main(void) {
    deliver(7);
    deliver(2);
    return 0;
}
```

```text
收货：小鱼干
记账完毕
今天没收到
```

`do { ... } while (0)` 外加一个分号，整段就成了**一句话**：它既能顶在 `if` 后面不散架，自己也算收过尾了。那个 `while (0)` 的意思是「这圈只跑一次」—— 它的用处不是转圈，是**把一摊子话绑成一句**喵。

## 条件编译：开工前就定下来的岔路口

有些岔路，是翻译官喵**开工之前**就要选好的 —— 选完的那一半稿子根本不会被翻译。这就是条件编译。

最常用的是抓虫开关：

```c
#include <stdio.h>

#define DEBUG 1

int main(void) {
#if DEBUG
    printf("[抓虫] 碗里的数现在是 %d\n", 7);
#endif
    printf("开饭啦\n");
    return 0;
}
```

```text
[抓虫] 碗里的数现在是 7
开饭啦
```

把墙上那张卡改成 `#define DEBUG 0`，同一个稿子就变成：

```c
#include <stdio.h>

#define DEBUG 0

int main(void) {
#if DEBUG
    printf("[抓虫] 碗里的数现在是 %d\n", 7);
#endif
    printf("开饭啦\n");
    return 0;
}
```

```text
开饭啦
```

开关一关，那行抓虫用的字**在翻译之前就被扔掉了** —— 不是「跑了但不印」，是**压根没进稿子**。所以正式版里它连一点点影子都不留，这也是它比 `if` 强的地方。

⚠️ 这里最容易踩的是**两个开关长得像、判的东西不一样**：

| 写法 | 判的是 |
|---|---|
| `#if DEBUG` | `DEBUG` 的**值**：`0` 就是关 |
| `#ifdef DEBUG` | `DEBUG` **有没有定义过** —— 哪怕写成 `0`，在它眼里也算「有」 |

所以 `#define DEBUG 0` 配 `#ifdef`，开关是**关不掉的** —— 关了也照样印。想判值就用 `#if`，想判「这条卡贴没贴」才用 `#ifdef`。老前辈的稿子里常写 `#ifndef NDEBUG`，读作「没贴 `NDEBUG` 这张卡的时候就干活」，正式发布时只要在翻译命令里塞一个 `-DNDEBUG`（等于从外面贴一张卡上去），所有抓虫的话就一起消失了。

::: tip 猫咪提示
今天记三件事：**宏是开工前照抄的条子**，抄的是字不是意思；**投喂和整体都要穿小括号**，少一层就静悄悄算错；**条件编译是开工前定下的岔路**，`#if` 判值、`#ifdef` 判有没有定义。最要紧的一句：宏出错时翻译官喵**往往一声不吭**，所以别指望它替你抓，自己把括号数清楚喵。
:::
