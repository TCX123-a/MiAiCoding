## 钩子：本喵的家当，分三处放喵

本喵的猫窝里有三样东西：爪子上正啃的那条小鱼干、临时租来堆杂物的小仓库、还有门口那排上了锁的**固定储物柜**。

你写的程序也是这个脾气。程序一跑起来，翻译官喵先划出一大片地方当「猫猫仓库大院」，再把它分成几间用途不同的屋子。你写下的每一个贴着名字的小鱼干仓库（变量），都住在其中某一间里 —— **它住哪一间，决定了它什么时候来、什么时候走、谁说了算**。今天本喵就带你把这院子逛一圈喵 ✨

## 大院子里的四间屋

**秘籍架（代码区）** —— 翻译官喵把你的招式翻成一条条指令，整整齐齐码在这儿。开跑之后它**只读不写**，谁都别想改它。你把一句话写在引号里（比如 `printf` 里那句问候），那份字也会被码在这儿，因为你改不了它。

**门口那排上了锁的固定储物柜（静态区）** —— 程序一开跑就把柜子摆好，一直摆到程序结束。写在所有招式**外面**的全局仓库、还有被 `static` 点过名的仓库，都住这儿。它们的记性最好：**从头活到尾，只此一份**。

**现要现租的仓库（堆区）** —— 这就是上一阶段学过的 `malloc` 要来的地方。想用了才开口租，用完了得**自己**还（`free`）。租来的仓库很老实：你不还，它就一直占着。

**一摞叠起来的猫粮碗（栈区）** —— 翻译官喵给每只进门干活的猫（也就是每喊一次招式）在碗摞上摆一层碗，这一层里放着这招的局部仓库和投喂进来的小鱼干。招式一出门，它那层碗**当场收走**，又快又干净 —— 但也就没了喵。

## 谁住在哪一间

| 住哪一间 | 谁住这儿 | 什么时候来 | 什么时候走 | 要自己管吗 |
|---|---|---|---|---|
| 固定储物柜 | 招式外面的仓库、`static` 的仓库 | 程序一开跑 | 程序结束 | 不用 |
| 现要现租的仓库 | `malloc` 要来的那块地方 | 你喊 `malloc` 那刻 | 你喊 `free` 那刻 | **要** |
| 一摞碗 | 招式里的局部仓库、投喂进来的小鱼干 | 招式进门 | 招式出门 | 不用 |
| 秘籍架 | 翻译好的指令、引号里的字 | 程序一开跑 | 程序结束 | 只读，改不了 |

这张表就是今天的全部家当。往后读别人的代码卡住时，先问一句「这块东西住哪间屋」，一大半的疑问会当场散掉喵。

## 亲眼看看：固定柜的记性 vs 碗摞的记性

光看表记不住，跑一遍就忘不掉了。本喵写了一个小程序：同样叫 `counter` 的两间仓库，一间被 `static` 点过名（住固定柜），一间隔壁就是（住碗摞）：

```c
#include <stdio.h>

int g_count = 100;          /* 全局仓库：住门口那排固定柜 */

int next_id(void) {
    static int counter = 0; /* static 仓库：也住固定柜，只摆一份 */
    counter++;
    return counter;
}

int fickle(void) {
    int counter = 0;        /* 局部仓库：住碗摞上，每次进门都是新的 */
    counter++;
    return counter;
}

int main(void) {
    g_count = g_count + 1;
    printf("全局仓库 g_count = %d\n", g_count);
    for (int i = 1; i <= 3; i++) {
        int a = next_id();
        int b = fickle();
        printf("第 %d 次：固定柜的 counter = %d，碗摞上的 counter = %d\n", i, a, b);
    }
    return 0;
}
```

```text
全局仓库 g_count = 101
第 1 次：固定柜的 counter = 1，碗摞上的 counter = 1
第 2 次：固定柜的 counter = 2，碗摞上的 counter = 1
第 3 次：固定柜的 counter = 3，碗摞上的 counter = 1
```

看出区别了吗喵？喊了三遍，固定柜里的 `counter` 一路记到 3，而碗摞上的 `counter` 每次都是 1 —— 不是它「忘了」，是那层碗**每次进门都重新摆过一遍**。`static` 这两个字的全部本事，就是把仓库从碗摞上搬进固定柜里。

## 危险动作：把碗摞上的牌子递出去

还记得现要现租那课讲的「牌子」吗？牌子就是写着仓库地址的猫爪指向牌，拿到牌子才能找到仓库。现在你知道仓库分四间了，就能看懂一个特别隐蔽的坑：

```c
int *give_me_a_number(void) {
    int local = 42;   /* 这间仓库摆在碗摞上 */
    return &local;    /* 危险：把碗摞上的牌子递了出去 */
}
```

`local` 住在碗摞上，招式一出门那层碗就收走了；可这招偏偏把它的牌子（`&local`）递了出去。牌子看着好好的，牌子指的那间仓库**早就换主人了**。

本喵把这段补上 `main` 真跑了一遍。翻译官喵其实**嘀咕了一句**（原话）：`warning: function returns address of local variable [-Wreturn-local-addr]`。

但它只是**警告**，不是拦路虎：编译照样过，跑起来才当场摔 —— 本机上退出码是 `3221225477`，意思是「踩到了不属于自己的地方」。换个翻译官喵、换个优化档，也可能先印出一个看着挺对的小数字再摔。**这两种结果都不能信**：那间仓库已经不归你管了喵。

这件事比它看起来重要：翻译官喵的**警告就是它把知道的告诉你**，可它不负责拦住你。以后看到 `warning:` 开头的那几行，别当背景音划过去喵。

## 想让牌子活着出门，就租一间仓库

把仓库从碗摞上搬到现要现租的那间屋，同一个招式立刻变得靠得住 —— 只要别忘了还：

```c
#include <stdio.h>
#include <stdlib.h>

int *make_box(int value) {
    int *p = (int *)malloc(sizeof(int));  /* 现租一间仓库 */
    if (p == NULL) {
        return NULL;
    }
    *p = value;
    return p;          /* 仓库还开着，牌子可以放心递出去 */
}

int main(void) {
    int *box = make_box(42);
    if (box == NULL) {
        printf("仓库没租到喵\n");
        return 1;
    }
    printf("盒子里装着 %d\n", *box);
    free(box);
    box = NULL;
    printf("还掉之后，牌子也收起来了\n");
    return 0;
}
```

```text
盒子里装着 42
还掉之后，牌子也收起来了
```

同样是「招式里造一间仓库，把牌子递出去」，这一版为什么靠得住？因为这块地方住在**现要现租的仓库**那间屋，招式出门时它不跟着走。可它也**不会自己消失** —— 所以 `main` 里那句 `free(box)` 一个字都不能省。本喵在最后把 `box` 设成空牌子，也是这个习惯：还掉的牌子别再拿来用喵。

::: warn 小心喵
三句话记住今天：**碗摞上的仓库，招式一出门就没了**（所以绝不能把它的牌子递出去）；**固定柜里的仓库从头活到尾**（`static` 的记性就是这么来的，全局仓库也是）；**现租的仓库要自己还**。C 里一大半「玄学 bug」，根子都是同一句话：「我以为这间仓库还归我管。」
:::

::: tip 猫咪提示
翻译官喵给你划的四间屋各有各的脾气：**秘籍架**只读、**固定柜**最长久、**租来的仓库**最自由也最费心、**碗摞**最勤快（自动来、自动走）。判断一段代码里的东西住在哪，只看两条：它写在招式**里面**还是**外面**，有没有被 `static` 点过名喵。
:::
