## 钩子：一池子乱编号的碗

鱼塘边摊着一排 **1024 只**贴着编号的猫粮碗，编号全乱了。本喵要把它们按编号从小到大摆好。

摆法有两条路可走：

- **憨办法**：拿起一只碗，跟剩下每一只都比一比，挑出最小的挪到最前面；再拿第二只，跟它后面每一只比一比……一路比到底。
- **砍半法**：先把相邻的两只碗合成一小排（顺手摆好这一小排），小排再合成中排，中排再合成大排，一层层往上合。

**两条路都能把碗摆好。** 可它们要干的活差得远 —— 差多少呢？本喵先把数数给你看，再说这门口诀叫什么喵。

## 一、为什么要量代价：秒表靠不住

本喵第一反应是**掏秒表**：跑一遍、掐个时间，谁快谁慢不就知道了？于是真跑了一次：

```text
1024 只碗 干法一 523776 圈，0.000 秒
1024 只碗 干法二 10240 圈，0.000 秒
```

（这两行是本喵在这台机器上真跑出来的读数，干法一就是憨办法、干法二就是砍半法，后面第二节会讲那两个数是怎么来的。）

两行都是 `0.000` —— **秒表上一点差别都看不出来**。1024 只碗的本子太小，两条路在本喵这台机器上都是「一眨眼就完」。

那就把碗加到 30000 只再看：

```text
30000 只碗 干法一 449985000 圈，0.137 秒
30000 只碗 干法二 420000 圈，0.000 秒
```

这回差距出来了。**可你注意到那 0.137 没有？** 本喵前后连着重跑了五次，读数有 `0.123`、`0.121`、`0.137`、`0.149`、`0.151` —— 从 `0.12` 到 `0.15` 都有。同一段程序、同一个本子，秒表自己在跳。

这就是秒表的毛病，而且有三个：

1. **同一台机器上它自己都会抖。** 后台在忙别的、风扇转得快一点，读数就变。同一段程序、同一个本子，两次读数对不上。
2. **换台机器它更没法比。** 本喵这台是老笔记本，鱼塘对面那台新机器可能 `0.01` 秒就跑完了 —— 那能说明那台机器上的本子更聪明吗？不能，只说明**机器快**。
3. **最小能读到的刻度有限。** 1024 只碗那两行全是 `0.000`，秒表压根读不出差别来。

所以比「谁更快」不能拿秒表，得换一把**跟机器无关的尺子**。这把尺子叫 **操作次数** —— 本喵习惯喊它「圈数」：**不管谁跑、跑到哪台机器上，这段代码最里面那个动作一共要跑几次，那就是几圈。**

数圈数有个额外的好处：**它跟机器无关，所以谁都能复核。** 你说这段要跑 523776 圈，本喵拿纸笔也能推出来，不用占用你的电脑。

## 二、数圈数：从 523776 到 10240

那把尺子怎么用？本喵把上面两条路各写成一个招式，**在最里面那个动作上挂个计数器**，让它自己报数。

```c
#include <stdio.h>

/* 干法一：拿每一只碗，跟它后面的每一只都比一遍 */
long long pairs(int n) {
    long long rounds = 0;
    for (int i = 0; i < n; i++) {
        for (int j = i + 1; j < n; j++) {
            rounds = rounds + 1;
        }
    }
    return rounds;
}

/* 干法二：一层层砍半，每一层都要把这 n 只碗整个过一遍 */
long long layers(int n) {
    long long rounds = 0;
    int size = n;
    while (size > 1) {
        rounds = rounds + n;
        size = size / 2;
    }
    return rounds;
}

int main(void) {
    int n = 1024;
    printf("碗数 n = %d\n", n);
    printf("干法一：%lld 圈\n", pairs(n));
    printf("干法二：%lld 圈\n", layers(n));
    return 0;
}
```

```text
碗数 n = 1024
干法一：523776 圈
干法二：10240 圈
```

**523776 和 10240** —— 同样的 1024 只碗，同样的「摆好」这个目标，干活量差了**五十多倍**。这两串数不是本喵编的，是上面那段代码自己跑出来的。

拆开看它们各是怎么数出来的喵。

### 干法一：为什么是 523776

里面那个 `for (int j = i + 1; j < n; j++)` 是「拿第 `i` 只，跟它**后面每一只**比一遍」。每一只碗要跟后面几只比呢？

- 第 1 只碗要跟后面 **1023** 只比；
- 第 2 只碗要跟后面 **1022** 只比；
- ……
- 最后一只碗后面空了，比 **0** 次。

加起来就是 `1023 + 1022 + ... + 1`。这个和有个现成的算法：**首项加末项、乘项数、除以二** —— `(1023 + 1) × 1023 ÷ 2 = 523776`。写成跟 `n` 有关的式子就是：

```text
n × (n - 1) / 2
```

### 干法二：为什么是 10240

砍半法是一层一层往上合的。**每一层都要把这 1024 只碗整个过一遍**（每只碗从它那一小排搬进新的一排，就过一次），所以：

```text
每一层的圈数 = 1024
一共有几层 = 1024 一路砍半，砍到 1 为止
```

砍一半要砍几刀？本喵让翻译官喵数了一遍：

```c
#include <stdio.h>

/* 一路砍半，砍到只剩一只碗为止，答「砍了几刀」 */
int halve_steps(int n) {
    int steps = 0;
    while (n > 1) {
        n = n / 2;
        steps++;
    }
    return steps;
}

int main(void) {
    printf("%d 只碗 → %d 刀\n", 1024, halve_steps(1024));
    printf("%d 只碗 → %d 刀\n", 2048, halve_steps(2048));
    printf("%d 只碗 → %d 刀\n", 1048576, halve_steps(1048576));
    return 0;
}
```

```text
1024 只碗 → 10 刀
2048 只碗 → 11 刀
1048576 只碗 → 20 刀
```

1024 砍到 1，正好 **10 刀**。所以干法二一共 `1024 × 10 = 10240` 圈。

**这一行输出你多看两眼**：碗从 1024 只涨到 1048576 只，翻了一千倍，刀数只从 10 涨到 20 —— **翻倍**。这是本课最值钱的一句喵。

### 碗数变大，两条路会怎么拉开

单看 1024 那一站还不够过瘾。本喵让它一次报五档：

```c

        }
    }

    long long rounds = 0;
    int size = n;

        rounds = rounds + n;
        size = size / 2;
    }

    int ns[5] = {8, 16, 32, 64, 1024};

```

数圈数的时候，**装圈数的仓库得够宽**。1024 只碗的圈数才五十万，随便一个 `int` 都装得下；可 30000 只碗那一段，干法一要跑 `449985000` 圈 —— 快四亿五千万了，再大一点 `int` 就装不下。

本喵真跑过一段用窄仓库的，翻译官喵只念了一句、**没拦**：

```text
main.c:14:19: warning: format '%d' expects argument of type 'int', but argument 2 has type 'long long int' [-Wformat=]
```

它的意思是「这个数是个宽仓库里的数，你拿窄格子去印它」。**念归念，程序照样被编了出来**，而且这次印出来的数碰巧还是对的 —— 最容易一眼扫过去。

所以本喵这里两个计数器都写成 `long long`，印的时候配 `%lld`。**数圈数的仓库，宁可宽一号。**
:::

## 三、大 O 记号入门

现在本喵手上有两条路的确切圈数：`n × (n - 1) / 2` 和 `n × 10`（本子里 `n` 就是 1024，换成别的数你会发现第二串其实是 `n × log₂n`，1024 的对数正好是 10）。

可每次都要报这么长的式子太啰嗦了。本喵只想知道「**碗变多的时候，圈数大概怎么涨**」—— 于是有了 **大 O 记号**。

它的规矩就两条，简单得像猫的脾气：

1. **只留长起来最快的那一项。**
2. **常数不要。**

拿干法一试试。把 `n × (n - 1) / 2` 拆开：

```text
n × (n - 1) / 2 = n²/2 - n/2
```

里面有两项：`n²/2` 和 `n/2`。`n` 一变大，谁跑得快？`n²` 长得比 `n` 快得多 —— `n` 是 1024 的时候 `n²` 是一百多万，`n` 才一千出头，**后者连零头都算不上**。所以第二项扔掉，只留 `n²/2`。再把常数 `1/2` 扔掉：

```text
干法一 是 O(n²)
```

干法二是 `n × log₂n`，两项都是必须留着的（`n` 和 `log₂n` 谁也压不住谁），常数本来就没有，所以：

```text
干法二 是 O(n log n)
```

::: tip 猫咪提示
**`O` 说的是「涨得多快」，不是「确切几次」。**

这两句都要刻进脑子里喵：

- **`O` 是一个上界。** 说「挨着看是 `O(n)`」，意思是「最多也就随着 n 线性地涨」。它**不保证**你每次都跑满 n 圈 —— 第二节课的本子里，第一只碗就是你要找的那只，一圈就收工了。
- **`O` 丢掉的是常数，丢不掉的是增长趋势。** `523776` 和 `600000` 都是 `O(n²)`，因为它们涨起来是同一个脾气；而 `10240` 是 `O(n log n)`，脾气完全不同。**别拿 O 去比谁快一点点** —— 它管的是 n 大到你没脾气的时候。

最后一条最容易忘：**`n` 得够大，O 才说了算。** 8 只碗的时候 `O(n²)` 那条路（28 圈）其实比 `O(n log n)` 那条（24 圈）**还快一点点**。O 管的是长跑，不管前一百米喵。
:::

## 四、常见量级对照

把常见的几档摆成一张表。**从下往上看**，越往下的越吓人：

| 大 O | 一段能看出它的代码 | 碗多起来的时候 |
|---|---|---|
| `O(1)` | `int first = bowls[0];` | 一亿只碗，也只动这一下 —— **跟碗数完全无关** |
| `O(log n)` | `while (n > 1) { n = n / 2; }` | 碗从 1024 涨到 1048576（一千倍），圈数只从 10 涨到 20 |
| `O(n)` | `for (int i = 0; i < n; i++) { ... }` | 碗翻一倍，圈数就翻一倍 —— 老实人 |
| `O(n log n)` | 一层层砍半再合并：10 层 × 每层过 1024 只碗 | 碗翻一倍，圈数只多一丁点（2 倍出头） |
| `O(n²)` | 两层 `for` 套着：外层每走一步，内层都陪着走一整遍 | 碗翻一倍，圈数变**四倍** |

每一档配一句话：

- **`O(1)` 是「不数了」。** 问它圈数是多少，它答「一次」。不管本子上有几只碗，它都只动这一下 —— 报第几只碗的编号，就是一下的事。
- **`O(log n)` 是「砍着数」。** 1024 到 1048576 翻了一千倍，圈数只从 10 涨到 20。**本子越大，这一档越占便宜。**
- **`O(n)` 是「挨着数」。** 老老实实一只只看过去。碗翻倍，圈数翻倍。
- **`O(n log n)` 是「又砍又挨着」**，也就是本课的砍半法：层数是 `log n` 层，可每一层都得把 `n` 只碗整个过一遍。它比 `O(n)` 慢一点，但比 `O(n²)` 好到不知道哪里去了 —— **这是「把一排碗排排坐」能做到的好成绩**。
- **`O(n²)` 是「两两都比」。** 碗翻一倍，圈数变四倍。64 只碗才 2016 圈，1024 只碗就五十多万圈 —— **它的脾气就是「大一点就爆炸」**。

::: warn 小心喵
**`O(log n)` 这一档最容易被想歪。** 它里面的 `log` 是**底数几都无所谓**的（本喵这儿是「每次砍一半」，所以是 2），因为不同底数之间只差一个常数倍，而常数在 O 里是要扔掉的。

要紧的是这一点：**它的圈数涨得比 `n` 慢得多。** `n` 翻一倍，`O(n)` 的圈数翻一倍，`O(log n)` 的圈数只**加一**。你以后看到某段代码「每次都砍掉一半」，就该想到这一档喵。
:::

## 五、最好、最坏、平均：圈数不是一个数

前面两条路都是「不管本子里装的是什么，圈数都一模一样」—— 所以本喵能报出一个确切的数。可**有一种活儿，圈数得看运气**：在一排碗里找一个编号。

本喵拿 100 只碗试了一次，编号 1 到 100 好好摆着，从第一只开始挨着看（`line_find` 就是这一招），把「找每一只各要几圈」全跑了一遍：

```c
#include <stdio.h>

int bowls[100];

/* 挨着看：从第一只开始一只一只比过去，答「比了几次」 */
int line_find(int n, int want) {
    int tries = 0;
    for (int i = 0; i < n; i++) {
        tries++;
        if (bowls[i] == want) {
            return tries;
        }
    }
    return tries;
}

int main(void) {
    int n = 100;
    for (int i = 0; i < n; i++) {
        bowls[i] = i + 1;
    }

    int best = 0;
    int worst = 0;
    long long total = 0;
    for (int want = 1; want <= n; want++) {
        int t = line_find(n, want);
        if (want == 1) {
            best = t;
        }
        if (want == n) {
            worst = t;
        }
        total = total + t;
    }

    printf("最好：%d 次\n", best);
    printf("最坏：%d 次\n", worst);
    printf("平均：%.1f 次\n", (double) total / n);
    return 0;
}
```

```text
最好：1 次
最坏：100 次
平均：50.5 次
```

三个数，三件不同的事：

- **最好**：要找的那只**正好摆在第一只**。一比较就中，**1 圈**收工。
- **最坏**：要找的那只摆在最末尾 —— 或者本子里压根没有这一只，那就得把 100 只全看一遍。**100 圈**。
- **平均**：把这 100 种情况**一次一次全跑一遍**，把圈数加起来除以 100。算出来的 `50.5` 一眼就懂：要看的碗平均下来在正中间。

那挨着看这一招该报哪个 `O` 呢？**看中间那个 —— 最坏。** 说「挨着看是 `O(n)`」，本喵指的是**最坏情况下**它随 n 线性地涨。理由很实在：**最好的情况（1 圈）是运气，最坏的情况才是你必须扛住的**。你要是拿「运气好时只要 1 圈」去跟人保证，那本子里没有这一只的时候，你就得当着人家的面看满 100 只碗。

::: tip 猫咪提示
今天收四句话：

1. **比快慢数圈数，不掐秒表** —— 圈数跟机器无关，秒数每台机器、甚至每跑一次都不一样。
2. **圈数 = 最里面那个动作跑了几次。** 1024 只碗：干法一 523776 圈，干法二 10240 圈。
3. **大 O 只留涨得最快的那一项、常数不要**，说的是上界和增长趋势，不是确切次数，也不是「n 小的时候谁快」。
4. **同一段代码可能有三个圈数**（最好 / 最坏 / 平均），报 O 的时候按**最坏**那一个来。
:::

## 小任务

1. **先猜再跑。** 把第二节那个五档本子改成 `{8, 16, 32, 64, 128, 256, 512, 1024, 2048}`（九档），先拿纸笔猜猜 `n = 2048` 那一行两条路各是多少圈，再真跑一次对照。提示：干法一的式子是 `n × (n - 1) / 2`，干法二是 `n × 层数`。
2. **改一段代码看它翻倍。** 把第五节的 `int n = 100;` 改成 `int n = 200;`，先猜「最坏」和「平均」会变成多少，再跑一次对照。`O(n)` 的脾气在这一步里看得最清楚。
3. **认出这是哪一档。** 下面三种干法各是几档 O？先自己判，再想想为什么：① 报出第一只碗的编号；② 把一排碗从头到尾看一遍求最大编号；③ 把一排碗两两都比一遍。
4. **给一个「砍一半」找个数。** 1024 只碗按编号摆好，本喵要找一个编号：每次都先看正中间那一只，比它小就往左半边找、比它大就往右半边找。猜猜最坏要几圈，再写出来真跑一遍验证。
