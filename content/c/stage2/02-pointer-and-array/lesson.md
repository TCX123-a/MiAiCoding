## 钩子：上一课那句轻描淡写的话

上一课开头，本喵随口说过一句：「一排碗的名字交出去的时候，交的正是**第一只碗的门牌号**」。

说完就翻篇了，当时只顾着讲牌子怎么挪。可这句话越想越不对劲喵 —— 一排碗的**名字**，凭什么会是一块**门牌号**？

今天本喵把这件事摊到桌面上讲清楚。你会看到它俩亲近得有点过分：**报编号取用这件事的真身，本喵一直在骗你。** 它不是「取碗」，它是「挪牌子，再顺着拿」喵。

## 一、排的名字，就是第一只碗的门牌号

先别信本喵，自己看一眼：

```c
#include <stdio.h>

int main(void) {
    int bowls[3] = {10, 20, 30};

    printf("%d\n", bowls == &bowls[0]);
    printf("%d\n", *bowls);
    return 0;
}
```

```text
1
10
```

- **`bowls == &bowls[0]`** 印出 `1` —— 「这一排的名字」和「第一只碗的门牌号」**是同一个东西**。不是像，是**就是**。
- **`*bowls`** 印出 `10` —— 既然名字就是门牌号，那前面挂一颗星，当然就顺着走到了第一只碗前面。

所以上一课那个「整排碗交出去的是原件」的谜团，谜底特别朴素：**交出去的压根不是「一整排」，是一块牌子** —— 指着第一只碗的牌子。招式顺着它当然能改到你本人的碗喵。

## 二、报编号的真身：`*(bowls + i)`

现在把两件事拼起来：牌子能**挪**（上一课），排的名字**就是牌子**（刚讲完）。那 `bowls[1]` 到底是什么？

```c
#include <stdio.h>

int main(void) {
    int bowls[3] = {10, 20, 30};

    printf("%d\n", bowls[1]);
    printf("%d\n", *(bowls + 1));
    return 0;
}
```

```text
20
20
```

两行印出来一模一样，因为**这两句本来就是同一件事**：

> **`bowls[i]` 就是 `*(bowls + i)` 的甜写法。**

拆开念一遍：**先把门牌号往后挪 `i` 只碗，再顺着拿。** 方括号里的编号，干的活儿正是「挪几步」。这也顺手解释了从前的两条怪规矩喵：

- **为什么编号从 0 开始？** 因为挪 `0` 步就是第一只碗。要是从 1 开始数，第一只碗反而要写成「往后挪一步」，那才别扭。
- **为什么最大编号是碗数减一？** 三只碗，你想拿第三只，得挪 `2` 步 —— `bowls[2]`。挪三步就跨到整排外面去了。

所以「报编号」这个名字其实是本喵偷懒的叫法，它的真身是**偏移**：偏移 0 是第一只，偏移 1 是第二只，偏移 2 是第三只喵。

## 三、牌子也能报编号

既然方括号只是「挪 + 顺着拿」的甜写法，那**任何一块牌子**都该能用它：

```c
#include <stdio.h>

int main(void) {
    int bowls[3] = {10, 20, 30};
    int *p = bowls;

    printf("%d\n", p[0]);
    printf("%d\n", p[2]);
    printf("%d\n", *(p + 1));
    return 0;
}
```

```text
10
30
20
```

- **`p[0]`** —— 挪 0 步，第一只碗，`10`。
- **`p[2]`** —— 挪 2 步，第三只碗，`30`。
- **`*(p + 1)`** —— 这就是上一课的写法，和 `p[1]` 是同一件事。

看出来了吗：**方括号不是「一排碗」的特权，它是「牌子」的特权。** 名字能用，是因为名字本来就是一块牌子；牌子能用，是因为它就是牌子。一家人不说两家话喵。

## 四、用牌子走一遍整排

把这个新认识拿去跑圈，遍历一排碗就有了另一种写法：

```c
#include <stdio.h>

int main(void) {
    int bowls[4] = {10, 20, 30, 40};

    for (int *p = bowls; p < bowls + 4; p++) {
        printf("%d\n", *p);
    }
    return 0;
}
```

```text
10
20
30
40
```

读法是：「**牌子从第一只碗出生；只要它还落在整排里面就进圈；每圈把牌子往后挪一只碗。**」圈里那句 `*p` 拿到的，就是牌子当下指着的那只碗里的数。

眼色那句 `p < bowls + 4` 值得拆一下喵：

- `bowls` 是第一只碗的位置，`bowls + 4` 是**第四只碗再往后挪一只**的位置 —— 也就是「整排之外」的第一格。所以「小于它」正好把这**四只碗**都走一遍，一个不多一个不少。
- 要是写成 `p <= bowls + 4`，牌子就会挪到整排外面去一格 —— 而**C 不会拦你**（上一课那口「小心喵」说的就是这个）。

## 五、招式拿到的，只有「从哪儿开始」

现在回头看一个更要紧的问题：把一排碗交进招式，招式手里究竟有什么？

```c
#include <stdio.h>

void show(int *p) {
    printf("%d\n", *p);
    printf("%d\n", *(p + 1));
}

int main(void) {
    int bowls[4] = {10, 20, 30, 40};
    show(bowls);
    return 0;
}
```

```text
10
20
```

招式头上写着 `int *p`，说明它收的是**一块牌子**。所以招式里能干的，只有「顺着牌子拿」和「挪牌子再拿」。它能印出 `10` 和 `20`，是因为本喵告诉它「往后挪一格」。

可它**不知道这一排有几只碗**。它手里的全部信息，就是「第一只碗在哪儿」加上「每只碗多大」。这是一排碗和牌子的**唯一区别**：整排碗的「长度」是写在声明里的（`bowls[4]` 那个 `4`），而牌子身上没有这个数。

所以想让招式照顾整排碗，得**额外把长度喂进去**：

```c
#include <stdio.h>

void fill(int *p, int n) {
    for (int i = 0; i < n; i++) {
        p[i] = (i + 1) * 10;
    }
}

int main(void) {
    int bowls[3] = {0};
    fill(bowls, 3);
    printf("%d %d %d\n", bowls[0], bowls[1], bowls[2]);
    return 0;
}
```

```text
10 20 30
```

胃口不错的一块牌子：它收下门牌号 `p`，又收下「有几只」这个数 `n`，然后自己用 `p[i]` 挨个填进去。回到 `main` 一印，你本人的碗**真的变了** —— 招式改的是原件，这一点和上一课一模一样喵。

::: warn 小心喵
招式不知道有几只碗，这件事有两副面孔：

- 你**喂**进去的长度比这排碗实际有的只数还大（一排只有 3 只碗，你却喊了 `fill(bowls, 5)`），招式不知道这件事，它会**从第一只碗一路往外写**。翻译官喵一个字都不说（本喵真跑过，连一声嘀咕都没有），碗架外面的东西会被一只只写坏 —— 而且本喵那一次压根没等到「写坏别处」，程序当场就断气了，屏幕上一个字都没印出来。
- 你自己在招式里**挪过了头**也一样：`p + 9` 在一排只有三只碗的地方，照样算得出来、照样能顺着拿 —— 拿回来的是哪一格，谁也说不准（本喵拿 `bowls + 5` 试过：翻译官喵一声不吭，印出来一个垃圾数 `828372976`，还可能是别的）。

所以「有几只碗」这个数，从今往后你走到哪儿带到哪儿。它不是给翻译官喵看的，是给你自己当刹车用的喵。
:::

## 六、排的名字挪不动

最后讲一个今天最扎心的地方。既然名字就是牌子，那名字能不能也像牌子那样挪一挪？

```c
#include <stdio.h>

int main(void) {
    int bowls[3] = {1, 2, 3};

    bowls++;
    printf("%d\n", bowls[0]);
    return 0;
}
```

```text
main.c:6:10: error: lvalue required as increment operand
    6 |     bowls++;
```

翻译官喵的原话意思是：**「`bowls` 这个名字，不能当成一只仓库来改。」**

原因想想就通：一排碗是**实实在在摆在架子上的一整排**，它的名字是这排碗挂的那块**牌子**（也就是第一只碗的位置），不是一只可以随手改的仓库。你让这个名字往后挪，那这排碗的第一只到底还算不算第一只？C 干脆不让喵。

**这一条正好把两者分清楚了**：

| 谁 | 是什么 | 能不能挪 |
|---|---|---|
| 一排碗的名字 | 第一只碗的门牌号（写死的） | **不能**，`bowls++` 编不过去 |
| 一块牌子 | 一只装着门牌号的仓库 | **能**，`p++` 随便挪 |

想把一排碗从头走到尾，你得**备一块牌子**（像第四节那样 `int *p = bowls;`）让它代你走 —— 那才是牌子该干的活喵。

::: tip 猫咪提示
今天四句话：

1. **一排碗的名字 = 第一只碗的门牌号**，`bowls == &bowls[0]` 是真的。
2. **`bowls[i]` 就是 `*(bowls + i)` 的甜写法** —— 先挪 `i` 只碗，再顺着拿；它就是编号从 0 开始的原因。
3. **方括号是牌子的特权**，`p[i]` 一样能用；用牌子遍历整排就跑圈 + `p++`。
4. **招式只知道「从哪儿开始」**，不知道有几只碗 —— 长度得你亲手喂进去；名字挪不动，要挪就备一块牌子。
:::

2. 把第四节那段跑圈的眼色 `p < bowls + 4` 改成 `p <= bowls + 4`，跑一跑 —— 多出来的那一行是什么数？能说清它的来历吗？
3. 写一排 `{3, 1, 4, 1, 5}`，用牌子的写法找出里面**最大**的那只碗（提示：备一只「目前最大」的小碗，牌子从第二只碗开始走）。
4. 试一试（**先猜再跑**）：把第五节 `fill(bowls, 3)` 里的 `3` 改成 `5`，会发生什么？翻译官喵会拦吗？跑出来的三只碗还是 `10 20 30` 吗喵？
