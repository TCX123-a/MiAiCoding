## 钩子：翻译官喵开工之前，先听几句吩咐

上一课结尾本喵说过：这一课要教你**在下锅之前就动点手脚**喵。

翻译官喵有个干活习惯 —— 拿到你的代码，它**不会立刻开始翻译**。它先把整篇从上往下扫一遍，专门挑出那些**以 `#` 开头的行**，把这些先办完。这些行不是正经的 C 话，而是**写给翻译官喵的吩咐**：

- 「先把档案室里那本 `stdio.h` 整本抄到这儿来」→ `#include`
- 「这篇文章里凡是见到 `MAX_FISH`，一律换成 `100`」→ `#define`
- 「`DEBUG` 这个记号登记过的话，这一段留着；没登记就丢掉」→ `#ifdef`

「翻译之前先把这些办掉」的整套活，猫猫们叫它**预处理**。今天本喵就把这三种吩咐都给你下一遍。

## 一、`#include`：开工前先把书抄进来

先看一段**漏了吩咐**的代码 —— 正文写好了，却忘了叫它抄书：

```c
int main(void) {
    printf("你好喵\n");
    return 0;
}
```

```text
main.c:2:5: error: implicit declaration of function 'printf' [-Wimplicit-function-declaration]
main.c:1:1: note: include '<stdio.h>' or provide a declaration of 'printf'
```

翻译官喵的原话 `implicit declaration of function 'printf'`，翻成猫话是「`printf` 这一招本喵没见过喵」。后面那句更贴心：`include '<stdio.h>' or provide a declaration of 'printf'` —— 「要么把 `stdio.h` 抄进来，要么自己先告诉本喵 `printf` 长什么样」。

那 `#include` 到底干了什么？土得有点可爱：**它把那一本文件的内容，原样抄到你写下这一行的位置上。** 就这样，没有别的花样。补上吩咐就没事了：

```c
#include <stdio.h>

int main(void) {
    printf("抄了书，本喵就认得 printf 了喵\n");
    return 0;
}
```

```text
抄了书，本喵就认得 printf 了喵
```

两种写法要分清：

- **尖括号包起来**的（比如 `stdio.h`、`string.h` 这些别人给你准备好的）—— 意思是「先去翻译官喵自己那排书架上找」。
- **用引号包起来**的（比如 `"sum.h"` 这种你自己写的）—— 意思是「先在本喵自己的地盘上找」。

## 二、`#define`：给一个值起个外号

第二种吩咐是**换名字**：

```c
#include <stdio.h>

#define MAX_FISH 100

int main(void) {
    printf("本喵最多能囤 %d 条小鱼干\n", MAX_FISH);
    printf("再来 %d 条就满仓了\n", MAX_FISH - 20);
    return 0;
}
```

```text
本喵最多能囤 100 条小鱼干
再来 80 条就满仓了
```

读法就是三段：`#define 名字 换成的样子` —— 「以后见到 `MAX_FISH`，一律换成 `100`」。三句话记牢：

1. **没有等号，也没有分号。** 中间只用空格分开。
2. **它是「换字」，不是「算数」。** 那行吩咐本身不做任何计算，只是登记了一条替换规则（你看 `MAX_FISH - 20` 照样能算，因为替换之后是 `100 - 20`）。
3. **从那一行往下才生效。** 吩咐下面的行听得见，上面的行听不见。

第三条最容易忽略。本喵真跑过一遍，把吩咐挪到了最后：

```c
#include <stdio.h>

int main(void) {
    printf("%d\n", MAX_FISH);
    return 0;
}

#define MAX_FISH 100
```

```text
main.c:4:20: error: 'MAX_FISH' undeclared (first use in this function)
    4 |     printf("%d\n", MAX_FISH);
```

翻译官喵说「`MAX_FISH` 这个名字本喵不认得」—— 因为它读到第 4 行的时候，那条吩咐还在第 8 行躺着呢喵。

这条吩咐从登记、换字到翻译，一路是怎么走的？本喵拆成一步一步给你看：

### 手滑多打了一个分号

还有一个几乎人人挨过一次的坑：**别顺手在屁股后面加分号**。

```c
#include <stdio.h>

#define MAX_FISH 100;

int main(void) {
    printf("%d\n", MAX_FISH);
    return 0;
}
```

```text
main.c:3:21: error: expected ')' before ';' token
main.c:6:20: note: in expansion of macro 'MAX_FISH'
```

第二行的原话里有 `in expansion of macro 'MAX_FISH'` —— **macro 就是宏**，它在告诉你：「这句怪话，是把 `MAX_FISH` 换开之后才长出来的。」你写的是 `100;`，于是第 6 行替换完变成了 `printf("%d\n", 100;);`：括号还没闭上先撞上一个分号，它当然要拦。

⚠️ 顺带说一句：**`#define` 后面那个分号不是「被忽略」，而是会被一起换进去** —— 它只是有时候运气好没碍事，等它碍事的时候，报错长什么样就由不得你了。

## 三、像招式那样收小鱼干的宏

宏还能「收投喂」，长得跟招式很像：

```c
#include <stdio.h>

#define SQUARE(x) x * x

int main(void) {
    printf("%d\n", SQUARE(1 + 2));
    printf("%d\n", SQUARE(4));
    return 0;
}
```

```text
5
16
```

（本喵真跑过：这一段翻译官喵**一个字都没说**，安安静静交了活。）

哎？`SQUARE(4)` 是 16 没错，可 `SQUARE(1 + 2)` 怎么不是 9，而是 **5**？

因为**宏不是招式，它只是换字**。翻译官喵把 `SQUARE(1 + 2)` 按规则整段换下来，换的时候**不做计算、也不替你加括号**：

```text
1 + 2 * 1 + 2
```

先乘后加，于是 `1 + 2 + 2` = **5**。翻成猫话：**它把 `1 + 2` 这一坨原样塞进了 `x` 的位置上。**

这就是宏最经典的坑，也是宏和真招式的分水岭：**真招式会先把你投喂的小鱼干算好再进门，宏不会**。所以给宏套括号是写宏的规矩：

```c
#include <stdio.h>

#define SQUARE(x) ((x) * (x))

int main(void) {
    printf("%d\n", SQUARE(1 + 2));
    printf("%d\n", SQUARE(4));
    return 0;
}
```

```text
9
16
```

多套两层：**每一个 `x` 各包一层，整个身子再包一层。** 少一层，早晚有一天被它咬。

宏还有个特点：**它不挑类型**。同一句话套在小数身上照样干活（换字本来就不看类型）：

```c
#include <stdio.h>

#define SQUARE(x) ((x) * (x))

int main(void) {
    printf("%.2f\n", SQUARE(2.5));
    printf("%d\n", SQUARE(3));
    return 0;
}
```

```text
6.25
9
```

真招式得先写清收的是小鱼干还是小鱼苗；宏不用。省事的另一面是：**没人替你把关**。

### 宏还能当缩写用

宏换的是名字，所以它连招式名都能换：

```c
#include <stdio.h>

#define SHOW(n) printf("有 %d 条小鱼干\n", (n))

int main(void) {
    SHOW(6);
    SHOW(6 + 1);
    return 0;
}
```

```text
有 6 条小鱼干
有 7 条小鱼干
```

（把一长串写起来啰嗦的东西收成一个短名字，是宏最常见的用法。）本喵提醒一句：宏收下的**是一段字**，那串字里该有的括号、分号，一个都不能少写 —— 宏不会替你补。

::: tip 猫咪提示
宏名习惯写成**全大写**（`MAX_FISH`、`SQUARE`），这是给读代码的猫看的约定：**一眼认出「这是个宏，不是真招式」**。写成小写也能跑（本喵跑过），可读代码的猫会误会。
:::

## 四、`#ifdef`：按记号决定留哪一段

第三种吩咐是**挑段落**：

```c
#include <stdio.h>

#define DEBUG 1

int main(void) {
#ifdef DEBUG
    printf("调试里的话\n");
#endif
    printf("正经活儿\n");
    return 0;
}
```

```text
调试里的话
正经活儿
```

读法两句：

- `#ifdef DEBUG` —— 「`DEBUG` 这个记号登记过的话，从这里往下都留着」
- `#endif` —— 「留到这儿为止」

有登记就留，没登记就**整段丢掉**。把最上面那行 `#define DEBUG 1` 删掉再跑，就只剩 `正经活儿` 了。而且是**连翻译都轮不到它** —— 那段话在开工前就被扔了，所以里面就算写错东西也不碍事（本喵真往那段里塞过一句不成样子的东西，翻译官喵照样把程序交了出来）。

配套的还有两个：

- `#ifndef` —— 「**没**登记过才留」（跟 `#ifdef` 正好相反）
- `#else` —— 老熟人，前面的话不成立就轮到它

```c
#include <stdio.h>

int main(void) {
#ifndef DEBUG
    printf("安静干活\n");
#else
    printf("边干边念叨\n");
#endif
    return 0;
}
```

```text
安静干活
```

::: warn 小心喵
**`#ifdef` 只问「登记过没有」，不问登记的是什么。** 本喵真跑过：写成 `#define DEBUG 0`，那一段**照样留着**（`0` 也算登记过）。想在「关了」的时候走另一条路，得用 `#ifndef`，或者把值拿去做 `#if` 的判断。

还有一条最容易挨的：**`#ifdef` 开了门，就一定要配一个 `#endif` 关门。**
:::

### 丢了 `#endif` 会怎样

```c
#include <stdio.h>

#define DEBUG

int main(void) {
#ifdef DEBUG
    printf("调试里的话\n");
    return 0;
}
```

```text
main.c:6: error: unterminated #ifdef
    6 | #ifdef DEBUG
```

翻译官喵的原话是 `unterminated #ifdef` —— 「这扇门开了没关」喵。它找不到 `#endif`，就不知道剩下的东西要留到哪儿，只好停手。

::: warn 小心喵
宏还有个地方会咬人：**宏只能写一行。** 想把好几句包成一个宏，得在每行末尾写一个反斜杠接着写 —— 可那样包出来的东西是**原样掉进**你使用它的地方的。要是它掉在一个 `if` 后面，那个 `if` 后面的 `else` 就找不到自己的 `if` 了（本喵真跑过，翻译官喵当场问：`error: 'else' without a previous 'if'`）。

老前辈们的办法是把多行宏包成 `do { ... } while (0)` 的样子，让它天生长着完整的骨架。这一招先记个名字，等你要写多行宏的时候再回来看喵。
:::

::: tip 猫咪提示
今天收四句：

1. **`#include` 是「开工前把那本文件整本抄进来」**：别人给的书用尖括号，自己写的书用引号。
2. **`#define 名字 换成的样子`** 是给一个值起外号 —— 没等号、没分号，而且**从那一行往下才生效**。
3. **宏只是换字，不是招式**：投喂的东西整段塞进去、不替你算、不替你加括号，所以**每个 `x` 都得自己套括号**。本喵真跑过：`SQUARE(1 + 2)` 不套括号是 `5`，套上才是 `9`。
4. **`#ifdef` / `#ifndef` / `#else` / `#endif`** 是挑段落；开了条件，别忘了关门。
:::
