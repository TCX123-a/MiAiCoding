## 钩子：一只猫干不完的活

上一课末尾本喵说过，要把一只猫干不完的活拆开分给好几只猫。可真拆开的那一刻，麻烦立刻来了：

**本喵写好的招式，别的猫怎么知道？**

主猫的本子里要用鱼塘工具本里的 `add` —— 可它凭什么知道有这么一招、要投喂几条鱼干、叼回来的是什么？两只猫各写各的本子，谁也没翻过谁的。

老前辈猫们定下的办法很朴素：**另立一本「招牌本」，专门写「有这么一招、它长什么样」；谁的活谁写进自己的「干活本」**。翻译官喵翻主猫的本子时，翻到「这儿要抄一本招牌本」，就把那本招牌**整本抄进来**。

今天就把这套拆活的规矩认全喵。🐾

## 一、分工：招牌本写「长什么样」，干活本写「怎么干」

先认两个词：

| 本子 | 后缀 | 里头放什么 |
|---|---|---|
| 招牌本 | `.h` | **宣告** —— 有这么一招、叫什么、要投喂几条、叼回什么。**一行，结尾是分号** |
| 干活本 | `.c` | **身子** —— 这一招真正怎么干，老老实实写在花括号里 |

**宣告和身子是两件事。** 本喵真跑了一段给你看 —— 下面这张纸上，招牌那一行和身子那一份都在（真实工程里，招牌那一行是抄进来的，本课的跑台一次只翻一张纸，所以本喵把两处摊开写在同一张纸上）：

```c
#include <stdio.h>

/* ── 招牌上抄的那一行：只写着这一招长什么样 ── */
int add(int a, int b);

/* ── 身子：真正干活的那一份 ── */
int add(int a, int b) {
    return a + b;
}

int main(void) {
    printf("结果 %d\n", add(3, 5));
    return 0;
}
```

```text
结果 8
```

盯着这两处看：`int add(int a, int b);` —— **结尾只有一个分号**，没有花括号，这就是招牌上的那一行；底下那份带花括号的，才是干活的身子。

::: tip 猫咪提示
一眼分宣告和身子：**结尾是分号的就是宣告，带花括号的就是身子。**

招牌本是**给别人抄的**，所以里头只放宣告 —— 别人抄走招牌，就只是知道了「有这么一招、长这样」，至于怎么干，那是干活本的事。
:::

## 二、抄进来 = 原样落在那一行

「抄一本招牌本」在 C 里就是一行吩咐，写在你想抄的位置上：

- `#include "tool.h"` —— 抄**自己写的**招牌本（引号：先在自己身边找）
- `#include <stdio.h>` —— 抄**别人给的**书（尖括号：去翻译官喵的档案室找）

这一行干的活土得有点可爱：**它把那本文件的内容，原样抄到你写下这一行的位置上**。就这样，没有别的花样。

「原样」两个字，是今天所有麻烦的根。同一本招牌被抄两遍，那两遍的内容就**真的在纸上出现了两份**。

两份内容会不会打架，全看那两份里装的是什么。先看装**身子**的：

```c
#include <stdio.h>

int add(int a, int b) {
    return a + b;
}

/* ── 另一处又抄了一遍同一份招牌（身子也跟着来了）── */
int add(int a, int b) {
    return a + b;
}

int main(void) {
    printf("结果 %d\n", add(3, 5));
    return 0;
}
```

```text
main.c:8:5: error: redefinition of 'add'
    8 | int add(int a, int b) {
      |     ^~~
main.c:3:5: note: previous definition of 'add' with type 'int(int,  int)'
    3 | int add(int a, int b) {
      |     ^~~
```

`redefinition` 就是「又定义了一遍」喵。注意它念的是 `add` 这个名字 —— **两处都带着身子，它当然要说「你已经教过一遍了」**。

那换成**只装宣告**的招牌呢？本喵也真跑了一遍，还特意把 `-Wall` 打开（那是让翻译官喵把话匣子全打开的开关），看它会不会念叨一句：

```c
#include <stdio.h>

/* ── 两处都抄了同一行宣告 ── */
int add(int a, int b);
int add(int a, int b);

int main(void) {
    printf("结果 %d\n", add(4, 6));
    return 0;
}

/* ── 身子只留一份 ── */
int add(int a, int b) {
    return a + b;
}
```

```text
结果 10
```

**它一个字都没说。** 两处写着同一行宣告，那不叫重复 —— 宣告只是「有这么一招」，同一句话说两遍，它认得出这是同一句话。**怕抄两遍的是身子，不是宣告。**

那怎么办？两只猫都想要这本招牌，总不能规定「谁也不许抄两遍」吧 —— 工程一大，谁都记不住自己抄过哪些。老前辈猫的办法是：**让招牌本自己带上卫士，抄第二遍的时候自己把自己挡住。**

## 三、守卫三行：一个名字，三道门

卫士长这样，一共三行，套在招牌内容的外面：

```c
#ifndef ADD_H
#define ADD_H

int add(int a, int b) {
    return a + b;
}

#endif
```

念一遍这三行的意思：

- `#ifndef ADD_H` —— 「`ADD_H` 这个记号**没**登记过的话，就从这儿往下读」
- `#define ADD_H` —— 「现在把它登记上，下回再来就拦住你」
- `#endif` —— 「读到这儿为止」

下面是同一段被抄两遍、但**两份都套了守卫**的样子 —— 本喵真跑过，翻译官喵一句话都没说：

```c
#include <stdio.h>

#ifndef ADD_H
#define ADD_H

int add(int a, int b) {
    return a + b;
}

#endif

#ifndef ADD_H
#define ADD_H

int add(int a, int b) {
    return a + b;
}

#endif

int main(void) {
    printf("结果 %d\n", add(3, 5));
    return 0;
}
```

```text
结果 8
```

第一遍抄进来的时候：`ADD_H` 还没登记过 → `#ifndef` 放行 → `#define` 把它登记上 → 身子抄了进来。第二遍抄进来的时候：`ADD_H` **已经登记过了** → `#ifndef` 一看「登记过了，别进来」→ 整段直接跳过。所以身子的的确确只有一份。

这两遍是怎么走过来的，本喵拆成一步一步给你看（本课的跑台一次只翻一张纸，所以这两份摊在同一张纸上）：

::: warn 小心喵
守卫**三行缺一不可**，而且最容易忘的就是中间那句 `#define`。

少写它的后果，本喵分两种情形真跑过：

- **两份都少写** `#define` —— 记号**永远没登记过**，第二遍上门问「登记了没」，它照样回「没登记，进来吧」→ 还是 `redefinition`；
- **只有第二份少写** —— 第一份已经把名字登记上了，所以第二遍照样被挡住，跑起来没事（就是这么阴：**少写一句的毛病，要等下一次抄同一份才现形**）。

判断补在哪儿也有讲究：**登记的那一句得在第一份里**。只补在第二份里不管用 —— 读到第二份的时候，第一份的内容早抄进去了，那才叫晚。
:::

## 四、一本书一个记号名

守卫最阴的地方，是它**不报错**。

记号名是可以自己起的，起什么都行 —— 可它管的事是「**这本招牌**是不是已经抄过了」。两只猫各写一本招牌，**顺手用了同一个记号名**，会怎样？本喵真跑了一遍：

```c
#include <stdio.h>

/* ── 甲招牌 ── */
#ifndef TOOL_H
#define TOOL_H
#define CAP 20
#endif

/* ── 乙招牌（另一本，仓容后来改过）── */
/* 它顺手也用了 TOOL_H 这个名字 */
#ifndef TOOL_H
#define TOOL_H
#define CAP 35
#endif

int main(void) {
    printf("仓容 %d 条\n", CAP);
    return 0;
}
```

```text
仓容 20 条
```

**乙招牌整个被丢掉了，而且翻译官喵一句话都没说。** 原因：甲招牌先把 `TOOL_H` 登记上了，乙招牌一上门问「`TOOL_H` 登记了没」—— 得到的回答是「登记过了」，于是它以为「这本已经抄过了」，整本跳过。可它挡掉的**不是重复的那一份，是「凡是叫这个名字的、后面来的全挡」**。

把乙招牌的名字改对，**数目就对了**（`35`），可翻译官喵**还有一句话要说**：

```c
#include <stdio.h>

#ifndef TOOL_H
#define TOOL_H
#define CAP 20
#endif

#ifndef TOOL2_H
#define TOOL2_H
#define CAP 35
#endif

int main(void) {
    printf("仓容 %d 条\n", CAP);
    return 0;
}
```

```text
仓容 35 条
```

编的时候它跟的那句是 `warning: 'CAP' redefined`（「`CAP` 这个名字你定了两回」）—— 本喵确实定了两回：甲招牌定 `20`、乙招牌定 `35`，两个定义都被抄了进来，**后定的那一个赢**，所以印的是 `35`。

对照着看这两段：**差别只有乙招牌那一行的记号名**，结果却从 `20` 变成了 `35` —— 而第一段是编得过、跑得起来、看着毫无毛病的。**这一类错最难抓：第一段连一句红字都没有**；第二段也只是多一句「名字定了两回」的念叨，**没有哪一句会告诉你「你的守卫把整本招牌吃掉了」**。

::: tip 猫咪提示
记号名起法的口诀：**一本书一个名字，书里书外从头到尾都用它。**

- 同一本招牌被抄两遍 → **两份用同一个名字**（守卫才认得这是同一本）；
- 两本不同的招牌 → **各用各的名字**（顺手共用一个，后一本会被悄悄扔掉）。

名字本身起得糙一点没人管（`ADD_H`、`TOOL2_H` 都行），**叫得对不对**才要命。
:::

## 五、招牌该放什么，不该放什么

收一收今天的三条界线喵。

**第一，招牌里只放宣告。** 身子进了招牌，那份招牌只要被抄两遍就会撞上 `redefinition`（第二节那段就是）。身子只留一份，放在干活本里。

**第二，招牌那一行不能省。** 反过来也不行 —— 光有身子、没有那一行宣告，主猫的本子照样用不了这一招：

```c
#include <stdio.h>

int main(void) {
    printf("结果 %d\n", add(3, 5));
    return 0;
}
```

```text
main.c:4:25: error: implicit declaration of function 'add' [-Wimplicit-function-declaration]
```

`implicit declaration` 翻成猫话就是「这一招本喵没听说过」喵。C 里的规矩是：**用一招之前，得先让它被「见过」** —— 要么它的身子就写在前头，要么**先抄一行宣告进来**。所以招牌本不是可有可无的装饰，它是「让别人能用上你的招」的唯一凭据。

**第三，抄进来的东西是原样的。** 所以「抄几遍」这件事挡不住，只能靠招牌自己带着的守卫去挡。

::: tip 猫咪提示
今天收三句：

1. **招牌本（`.h`）放宣告、干活本（`.c`）放身子** —— 结尾是分号的就是宣告，带花括号的就是身子，身子只留一份。
2. **`#include` 是「把那一本原样抄到这一行」** —— 别人给的用尖括号，自己写的用引号。抄两遍，内容就真有两份，所以招牌要自带守卫。
3. **守卫三行 `#ifndef` / `#define` / `#endif`，缺一不可**；同一本招牌两份共用一个记号名，两本不同的招牌各用各的名字 —— 名字撞了**不报错**，后一本会被悄悄扔掉。
:::

2. 把第三节那两处守卫里的 `ADD_H` 全都改成 `CAP_H`，跑一遍看看结果变没变（口诀：**改名要整本一起改**）。
3. 把第四节第一段的乙招牌记号名改成 `TOOL2_H`，跑一遍 —— 数一数从 `20` 变成 `35` 只动了几个字。
4. 想一想：如果同一本招牌**被抄了三遍**，第三遍会被谁挡住？提示 —— 第一遍就把名字登记上了。

下一课本喵要讲一件每个仓库都躲不掉的事：**同一只碗，摆的地方不一样，能活的时间就不一样** —— 有的碗出了花括号就没了，有的一直记着你上次放进去的东西，还有的得先挂个牌子、缸摆在别的纸上。摆错地方，程序有时不会报错，只会算错喵。🐾
