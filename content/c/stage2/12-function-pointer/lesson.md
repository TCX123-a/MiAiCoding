## 钩子：本喵想让「哪一招上」这件事能改

本喵有个小算盘：有时候要把两位朋友的鱼干数**加起来**，有时候要**比一比谁多**。可要是每换一种活法就得回去改代码，那也太笨了。

要是能**把「哪一招」当小鱼干递进去**就好了：递「加」，它就加；递「减」，它就减。同一段代码，换一张牌子就换一种活法 —— 这正是今天要学的本事喵。

可招式怎么递呢？招式是一大段代码，搬不动。真正能递的，是**它在哪儿** —— 就像你想请某只猫来干活，你手里攥着的不是那只猫，而是一张写着「它住在哪儿」的牌子。写「某某住在哪儿」的，正是前面学过的**猫爪指向牌**。

本喵管今天这张牌子叫招式的猫爪指向牌（函数指针）——**牌子不干活，牌子上写着哪一招干活。**

## 一、先认清牌子的长相

本喵有一招「加」：

```c
int add(int a, int b) {
    return a + b;
}
```

现在本喵想摆一只碗，里面装**这张「加」的牌子**。写出来是这样：

`int (*op)(int, int) = add;`

这一行长得很怪，本喵把它拆成三段念，你就不怕它了 —— **从里往外、从右往左念**：

1. **最右边那两个 `(int, int)`**：这招要投喂什么？ —— 两个整数。
2. **最左边那个 `int`**：它叼回来的战利品是什么？ —— 一个整数。
3. **中间那包 `(*op)`**：这只碗叫 `op`，里面装的是一张牌子。**包着 `*op` 的那对小括号一个都不能省** —— 第六节有个坑专门讲它。

摆好碗之后，用它跟用招式一模一样：

```c
#include <stdio.h>

int add(int a, int b) {
    return a + b;
}

int sub(int a, int b) {
    return a - b;
}

int main(void) {
    int (*op)(int, int) = add;
    printf("%d\n", op(7, 2));
    op = sub;
    printf("%d\n", op(7, 2));
    return 0;
}
```

```text
9
5
```

头一句 `int (*op)(int, int) = add;` 把「加」的牌子放进 `op`。第二句 `op(7, 2)` 就照着牌子上写的去喊那招，得到 9。

然后 `op = sub;` —— **碗没换，牌子换了**。再喊 `op(7, 2)`，这回照着新牌子走，得到 5。

**同一只碗、同一个写法，换张牌子就换了一套活。** 这就是今天所有本事的种子喵。

## 二、加不加 `&` 和 `*`，翻译官喵都认得

刚学到这里的人常犯迷糊：牌子到底是 `add` 还是 `&add`？喊的时候是 `op(...)` 还是 `(*op)(...)`？

本喵把四种写法都写出来跑了一遍：

```c
#include <stdio.h>

int add(int a, int b) {
    return a + b;
}

int main(void) {
    int (*p1)(int, int) = add;
    int (*p2)(int, int) = &add;
    printf("%d %d\n", p1(1, 2), p2(1, 2));
    printf("%d %d\n", (*p1)(3, 4), (*p2)(3, 4));
    return 0;
}
```

```text
3 3
7 7
```

四行四种写法，出来的数是同一对。原因很简单：

- **招式名单独写出来（`add`）的时候，它自己就等于那张牌子**，所以 `add` 和 `&add` 是一回事；
- **拿着牌子喊的时候（`op(...)`），翻译官喵本来就按牌子走**，所以你写不写那个 `*` 都一样。

本喵的建议：**平时就写 `add` 和 `op(...)`**，最干净。看到别人写 `&add`、`(*op)(...)` 也别慌，那是同一件事的另外几种说法喵。

::: warn 小心喵
**唯一不能省的，是 `(*op)` 外面那对小括号。** 写成 `int *op(int, int)` 意思就完全变了 —— 那是「一招名叫 `op`、叼回来的是一张整数牌子」，根本不是「一只装牌子的碗」。第六节本喵会把这个坑当场弄炸给你看喵。
:::

## 三、把牌子当小鱼干递出去

牌子既然是「一只碗里的东西」，那它就能**当小鱼干递进别的招式里**：

```c
#include <stdio.h>

int add(int a, int b) {
    return a + b;
}

int mul(int a, int b) {
    return a * b;
}

int apply(int (*op)(int, int), int a, int b) {
    return op(a, b);
}

int main(void) {
    printf("%d\n", apply(add, 3, 4));
    printf("%d\n", apply(mul, 3, 4));
    return 0;
}
```

```text
7
12
```

看 `apply` 头上的第一样投喂：`int (*op)(int, int)` —— 它要的不是一个数，**是一张牌子**，而且牌子的长相写清楚了（投喂两个整数、叼回一个整数）。

本喵喊 `apply(add, 3, 4)`，就是把「加」的牌子递进去。`apply` 内部那句 `return op(a, b);` 照着牌子上写的去喊 —— 递「加」就加，递「乘」就乘。

**`apply` 自己完全不知道进来的是加还是乘。** 它只管照着牌子干活。这就是牌的威力：**把「怎么干」从「什么时候干」里拆了出来。**

## 四、回调：回头喊你一声

再看一个更能看出味道的：

```c
#include <stdio.h>

void show(int x) {
    printf("碗里是 %d\n", x);
}

void show_double(int x) {
    printf("翻倍是 %d\n", x * 2);
}

void each(int a[], int n, void (*visit)(int)) {
    for (int i = 0; i < n; i++) {
        visit(a[i]);
    }
}

int main(void) {
    int bowl[3] = {3, 5, 7};
    each(bowl, 3, show);
    each(bowl, 3, show_double);
    return 0;
}
```

```text
碗里是 3
碗里是 5
碗里是 7
翻倍是 6
翻倍是 10
翻倍是 14
```

`each` 走到每个碗前面，就**回头喊一声那块牌子上写的招式**，把碗里的数喂给它。至于喊出来的是「印一遍」还是「印两遍」，`each` 不管 —— 那是牌子的事。

这种「**先递一张牌子过去，等合适的时机到了，再回头喊你一声**」的干法，本喵管它叫**回调**：不是你追着喊它，是它到了时候回来喊你。

回想一下上一课的倒计时：`countdown` 喊的是**自己**；今天的 `each` 喊的是**别人递进来的牌子**。两件事长得像，劲头不一样喵。

::: tip 猫咪提示
回调的好处一句话说完：**同一段框架，配不同的牌子，就能干不同的活。** `each` 只写一遍，想怎么处理每个数，就换一张牌子 —— 不用把 `each` 抄成两份、三份。
:::

## 五、真实世界里最有名的一张牌子：`qsort`

「给一排小鱼干排排坐」是每门语言都自带的活。C 里负责这件事的招式叫 `qsort`，它住在头文件 `stdlib.h` 家里。

有意思的是：**它不知道怎么比大小** —— 整数、小数、名字，规矩都不一样。所以它让**你**把规矩写成一张牌子递进去：

```c
#include <stdio.h>
#include <stdlib.h>

int cmp(const void *a, const void *b) {
    return (*(const int *)a) - (*(const int *)b);
}

int main(void) {
    int nums[5] = {5, 2, 9, 1, 7};
    qsort(nums, 5, sizeof(int), cmp);
    for (int i = 0; i < 5; i++) {
        printf("%d ", nums[i]);
    }
    printf("\n");
    return 0;
}
```

```text
1 2 5 7 9 
```

`qsort` 收到四样投喂：

| 投喂 | 是什么 |
|---|---|
| `nums` | 要排的那一排碗 |
| `5` | 一共几只碗 |
| `sizeof(int)` | 每只碗占多大 |
| `cmp` | **「谁该站前面」的规矩在哪张牌子上** |

至于 `cmp` 头上那串 `const void *a`：`void *` 是「**不知道是什么的牌子**」的意思 —— `qsort` 要能排整数、排小数、排名字，只好假装不知道里面是什么。所以轮到本喵自己动手时，得先把它转回「指向整数的牌子」（`(const int *)a`），再把数取出来（前面那个 `*`）。

这一段**今天只要眼熟**，不用背：记住那张牌子是「比的规矩」，整段代码里唯一一张由你提供的牌子，就是它喵。

## 六、括号丢了，意思就全变了

这是本课最容易摔的一跤。本喵把它真跑了一遍：

```c
#include <stdio.h>

int add(int a, int b) {
    return a + b;
}

int main(void) {
    int *p(int, int) = add;
    printf("%d\n", p(1, 2));
    return 0;
}
```

```text
main.c:8:5: error: function 'p' is initialized like a variable
```

翻译官喵最上面那句原话是「**招式 `p` 怎么可以像一只碗那样给初值**」（底下还跟着一串抱怨，都是从这句牵出来的）。

道理在于：少了那对小括号，`int *p(int, int)` 读出来是「**一招名叫 `p`，叼回来的是一张指向整数的牌子**」—— 它认为你在**定义一招**，可后面你又给了它一个等号加初值，招式是不能这样赋值的，于是当场翻脸。

补上括号 `int (*p)(int, int) = add;`，它就乖乖认了。**包着 `*p` 的那对小括号，是「这是只碗」和「这是一招」的分界线**喵。

## 七、牌子上的长相，必须和招式对得上

还有一种错法：牌子拿到了，可**牌子上写的长相和招式不一样**。

```c
#include <stdio.h>

void hello(void) {
    printf("你好喵\n");
}

int main(void) {
    int (*p)(int) = hello;
    printf("%d\n", p(1));
    return 0;
}
```

```text
main.c:8:21: error: initialization of 'int (*)(int)' from incompatible pointer type 'void (*)(void)' [-Wincompatible-pointer-types]
```

翻译官喵的原话是「**长相对不上**」：左边这只碗要装的是「投喂一个整数、叼回一个整数」的牌子；右边的 `hello` 是「不投喂、也不叼回」的招式。两边的长相不一样，它就不许你把它们放进同一只碗。

要修也好修：让招式长得和牌子一致 —— 比如写一招「投喂一个整数、印一句、再把那个数叼回来」的招式，装进去就对了。

**牌子是「这招长什么样」的承诺。** 承诺和实物不一致，翻译官喵在翻的阶段就拦下了 —— 这正是 C 让人安心的地方：这一类错**根本跑不起来**，你不可能带着它上考场喵。

::: tip 猫咪提示
今天收四句话：

1. **`int (*op)(int, int)`** 从里往外念：`op` 是装牌子的碗，两头的 `int` 说的是「投喂什么、叼回什么」。
2. **招式名单独写出来就是那张牌子**，`add` 和 `&add` 一样、`op(...)` 和 `(*op)(...)` 一样。
3. **牌子能当小鱼干递进别的招式**，于是「怎么干」和「什么时候干」就被拆开了 —— 这就是回调。
4. **包着 `*op` 的括号不能丢**，牌子上的长相也必须和招式对得上。
:::
