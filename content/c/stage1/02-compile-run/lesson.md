## 钩子：两种翻译官喵

本喵想请一位翻译官喵，把厚厚的《鱼塘水位手册》翻成大肥鱼看得懂的话。它有两种干法喵：

- **念一句、翻一句**：坐在你旁边，你念一句它翻一句，你当场就能照着做。好处是快、灵活；坏处是你得一直在场，而且它翻错的时候，前面翻过的那些已经散出去了。
- **整本抱走、关起门翻完**：把整本书抱回家，从头到尾翻完，再交给你**一叠誊好的稿子**。你要先等一会儿，可拿到手之后，照着念就行——而且这叠稿子能留一辈子，想用几次用几次。

上一课的本喵用的 C，请的就是**后面这位**。这种「整本翻完再开演」的干法，正式名字叫**编译**。

## 编译型：先说清三件后果

C 是**编译型**的语言。「编译型」这三个字听起来唬人，其实它只说了三件事，每一件你都马上能感受到喵。

**第一件：翻不过去，就一句都不跑。**

这是最要紧的一条。你要是把稿子里的一句话写坏了，翻译官喵**不会**帮你把前面好的那几句先念出来——它翻不过去，就一份都不交，程序连一行都不许跑。

换个说法你就懂了：**边念边翻的翻译官喵是「做到哪儿错在哪儿」，编译型的翻译官喵是「开门之前先把整本检查完」**。前者你会看到程序跑到一半忽然炸掉；后者你只会看到一段报错，然后屏幕上干净得像什么都没发生。

**第二件：翻完之后跑起来快。**

因为交到你手里的那叠稿子，已经是电脑能直接照着念的了，中间不再需要任何猫替它转话。

**第三件：翻一次，能跑很多次。**

那叠誊好的稿子会**存成一份文件**好好躺在那儿。往后想跑几遍跑几遍，不用重新翻。

## 那位翻译官喵叫什么

它有个名字：**gcc**。本喵喊它「翻译官喵」，可电脑不认猫话，你在命令窗口里得喊它 `gcc`。

喊它干活的写法是：**先说 gcc 的名字，再报上要翻的稿子，最后用 `-o` 指名把成品放哪儿**。

::: tip 猫咪提示
`gcc` 这个名字的三个字母，是「C 语言翻译官」的缩写（本喵就不逐字拼给你听了，喊得应就行）。往后你在别处撞见它，记得它就是本喵说的那位翻译官喵喵。
:::

## 四道工序：一份稿子怎么变成能跑的东西

翻译官喵抱着你的稿子回家，其实关起门来干了**四道工序**。平时你不必管它们，但哪天程序出了怪毛病，知道这四道工序在哪儿断的，你会省下大把抓耳挠腮的时间喵。

拿上一课那份「你好，喵」当稿子，本喵把四道工序一道道走给你看。

### 第一道：预处理——把请来的档案抄进来

上一课那句 `#include` 是请档案管理员出场，对吧？这一道工序干的就是把这几位管理员家里的内容**原样抄到你的稿子开头**。

```text
gcc -E main.c -o main.i
```

产出一份 `main.i`。它是一份**被抄大了的稿子**——手工敲的那七行没变多少，可上面多出了一大堆从档案里抄来的东西。这一步还顺便把 `#define` 那类替身名字换掉，今天先不管它。

### 第二道：编译——把 C 翻成汇编

第二道工序，才真的在「翻」：把 C 的句子翻成一种更接近机器、但还留着一行行人话的稿子。

```text
gcc -S main.i -o main.s
```

产出一份 `main.s`。想看热闹可以打开它瞄一眼——本喵劝你只看一眼就好，那里面的写法是给机器看的，不是给你看的喵。

### 第三道：汇编——翻成目标文件

```text
gcc -c main.s -o main.o
```

产出一份 `main.o`，叫**目标文件**。它里面已经是机器能读的东西了，可它**还不能跑**——因为它是一块缺了零件的半成品。

缺什么零件呢？你用了 `printf` 这一招，可这一招的**身子**（真正干活的那些机器码）并不在你的稿子里，它住在档案管理员家里。目标文件里只留了一张欠条：「这里缺一个 `printf`」。

### 第四道：链接——把零件拼上，才能跑

```text
gcc main.o -o prog.exe
```

这道工序叫**链接**：翻译官喵拿着你的目标文件，把它欠的那些零件一件件找来、缝上去，最后交出一份**完整、能自己跑**的成品。

成品就是那个 `.exe`。翻到这里才算真的翻完。

### 一条命令，四步全办

四道工序走完，你手上有 `.i`、`.s`、`.o`、`.exe` 四份文件。可平时本喵从来不这么敲——**一条命令就够**：

```text
gcc main.c -o prog.exe
```

这一条命令，翻译官喵会自己把四道工序跑一遍，中间那三份半成品它用完就扔，只把最后的成品留给你。所以你在软件里点了「运行」之后看到的那一闪，背后就是这两件事：

```text
gcc main.c -o prog.exe
./prog.exe
```

先**翻**，再**跑**。这一步千万别记反：`.exe` 不会自己出现，`main.c` 也不会自己跑起来喵。

本喵把这四道工序拆成一步一步，走给你看：

```demo

| gcc -E main.c -o main.i
| gcc -S main.i -o main.s
| gcc -c main.s -o main.o
| gcc main.o -o prog.exe
| ./prog.exe

step 起手：手里只有一份稿子

meow: 翻到一半，不算数喵

meow: 欠条先收好，回头还喵

meow: 零件全缝上，齐活喵！
pose: yay

say: 翻完才轮到这一行 `./prog.exe`。屏幕上那行字是**跑出来的，不是翻出来的** —— 翻译官喵从头到尾一声没吭。所以 C 里「翻」和「跑」永远是先后两声，不会合到一起。
meow: 跑起来啦，屏幕有字了喵

手上的东西 = prog.exe（成品）
```

四道工序走完，手里才第一次有能跑的东西 —— 然后才轮到跑那一下。**「翻」和「跑」在 C 里永远是先后两声**；哪天你见到一位「念一句、翻一句」的翻译官喵，那是别人家的干法，别拿这四道工序去套它喵。

## 亲手走一遍：稿子 → 屏幕上的字

那两条命令办完之后，屏幕上到底是什么样子？本喵把稿子和真跑出来的结果都摆在这儿：

```c
#include <stdio.h>

int main(void) {
    printf("翻译官喵把整本翻完啦\n");
    return 0;
}
```

```text
翻译官喵把整本翻完啦
```

请留神一件事喵：**屏幕上只有念话的结果**。「翻译完成」「链接成功」这类话，翻译官喵一个字都不会念——它翻完就收工，一声不吭。

所以往后你会撞上一种很迷惑的场面：**「没反应」和「跑成功了」经常长得一模一样**。想分清它们，看的不是翻译官喵有没有说话，而是——屏幕上有没有出现你让它念的那句话。

::: warn 小心喵
**不写 `-o` 会怎样？** 翻译官喵会用一个默认的名字。本喵真跑过：它会生出一份叫 `a.exe` 的东西，安安静静地躺在那儿。

问题是——**它不报错**。你敲完命令看到光标回来了，会以为万事大吉，然后到处找 `prog.exe` 找不到。所以本喵的规矩是：**每次都写 `-o`**，指名道姓，省得回头找文件喵。
:::

## 翻不过去的时候，屏幕上是什么样

现在来看那条最要紧的后果。本喵写了一份两句念话的程序，**第一句完全正确**，第二句末尾漏了分号：

```c
#include <stdio.h>

int main(void) {
    printf("第一句：先把碗摆好\n");
    printf("第二句：再倒猫粮\n")
    return 0;
}
```

```text
main.c: In function 'main':
main.c:5:33: error: expected ';' before 'return'
```

请盯着这段报错看三秒，然后回答本喵一个问题：**「第一句：先把碗摆好」念出来了吗？**

**没有。一个字都没有。**

这就是编译型的脾气：第一句明明是对的，可翻译官喵整本翻到第二句时卡住了，于是**整份稿子一份都不交**，程序根本没开跑，哪一句都轮不上。换个做法验证一下你就信了——如果这是边念边翻的语言，屏幕上本该先出现第一句，然后才炸。

所以往后你看到 C 的程序「什么都没输出」时，第一个要想到的不是「我的 `printf` 是不是坏了」，而是：**它到底有没有翻过去？** 报错里那句 `main.c:5:33` 就是翻译官喵在告诉你，它卡在第 5 行的第 33 个字符。

### 它连稿子本身都找不到的时候

还有一种更早的失败：稿子压根不在那儿。本喵敲错了文件名，翻译官喵当场就急了：

```text
cc1.exe: fatal error: meiyou.c: No such file or directory
compilation terminated.
```

`No such file or directory`——「没有这份文件，也没有这个目录」。看到这一句，先去数一数文件名有没有敲错、是不是和稿子待在同一个目录里，别急着怀疑自己写的代码喵。

::: tip 猫咪提示
今天记住这条链子：**`main.c` --（gcc 翻四道工序）--> `prog.exe` --（跑）--> 屏幕上的字**。

中间那个箭头**不能跳过**：稿子改了一个字，就必须**重新翻一次**。改完忘了翻，你跑的还是上一版——这是新手最常见、也最冤枉的一种「改了没用」喵。
:::

## 小任务

1. 把上一课那份「你好，喵」敲进编辑器、存成 `hello.c`，在软件里点一次运行，看看它念出什么。
2. 故意把末尾那个分号删掉，再点一次运行。屏幕上还会不会出现「你好，喵！」？把你看到的报错抄在手边，对着课文比一比：它说的是第几行第几个字符？
3. 把分号补回去，再把引号里的字改一改，重新跑一次——这回念出来的是新句子还是旧句子？想想为什么必须**重新翻**。
