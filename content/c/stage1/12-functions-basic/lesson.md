## 钩子：同一句话，念到第三遍就烦了喵

本喵每天早上要跟鱼塘边的三只猫打招呼，开场白都得重念一遍：

```text
小橘，早上好，今天也要好好吃饭喵～
狸花，早上好，今天也要好好吃饭喵～
三花，早上好，今天也要好好吃饭喵～
```

三天下来，本喵的舌头都打结了：**只有名字不一样，其余每个字都得重敲一遍。** 更糟的是，哪天想改一句台词，本喵得把三行一起改 —— 漏掉一行，三花就要听到过期的话。

要是能把这段活儿**打包**起来、钉上一块名牌，往后只报名字、顺手把「今天轮到谁」喂进去，那该多省事喵。

这个「打包」，就是今天的主角：**招式**。一次登记、随叫随到 —— 这是你亲手造的第一个零件喵。

## 一、把自己的第一招记下来

C 里登记一招，得在名字前面**先把两件事说清楚**：这招叼不叼东西回来、要不要喂东西进去。先看一个最小的：

```c
#include <stdio.h>

void greet(void) {
    printf("你好喵～\n");
}

int main(void) {
    printf("上课前\n");
    greet();
    printf("下课后\n");
    return 0;
}
```

```text
上课前
你好喵～
下课后
```

咦，屏幕上第一条怎么是「上课前」？本喵明明把 `greet` 写在最上面呀。把招式头从左往右拆开读一遍，就明白了：

- **第一个 `void`** —— 这是**战利品的类型**。写 `void` 的意思是：「这一招只管干活，不叼任何东西回来。」
- **`greet`** —— 招式的名字，随你起。起好之后要**一个字母都不差**地喊它，写成 `Greet` 或 `gree` 它都认不出来。
- **括号里的 `void`** —— 这是**空碗位**。写 `void` 的意思是：「这一招什么都不用喂。」
- **后面那对花括号 `{ }`** —— 招式身体。缩进的那一句就是它要干的活儿。
- **`greet();`** —— 这才叫**施展**（喊一声）。招式名后面跟一对小括号、一个分号，招式簿上包着的活儿就从第一句跑到最后一句。

**「登记」和「施展」是两件事** —— 这是今天的第一个坑，也是最容易摔的那个：**登记招式的时候，它一步都不会动**，翻译官喵只是把它记在本子上。真正开动，是在 `main` 里喊它那一下。

光登记不喊会怎样？本喵真跑给你看：

```c
#include <stdio.h>

void greet(void) {
    printf("你好喵～\n");
}

int main(void) {
    printf("本喵把 greet 记在招式簿上了\n");
    return 0;
}
```

```text
本喵把 greet 记在招式簿上了
```

看清楚：`你好喵～` **一个字都没出现**。翻译官喵心里想的是「你让我记下来，我记下来了；你又没喊我，我干嘛要动」—— 它一点毛病都没有，你也**没法从报错里看出问题**，屏幕上就是安安静静。

::: warn 小心喵
「忘了喊一声」是零基础最容易摔、而且**最查不出来**的坑：不报错、不警告、屏幕上什么都没有。本喵教你一句自检口诀喵：

**屏幕上一片安静的时候，先回头看招式簿 —— 我真的喊过它吗？**

往后写的招式越多，这一条越要记牢。
:::

## 二、招式头上的第一个词：叼不叼东西回来

上一招的头上写着 `void`，意思是**不叼战利品**。要是这招算完还有东西要交给你，那个位置就得换成**战利品的类型**：

```c
#include <stdio.h>

int add(int a, int b) {
    return a + b;
}

int main(void) {
    int total = add(3, 5);
    printf("%d\n", total);
    printf("%d\n", add(10, 1));
    return 0;
}
```

```text
8
11
```

- **`int add(...)`** —— 最前面那个 `int` 说的是：「这招会叼回一个整数。」**它和招式里 `return` 的东西必须对得上**，这是 C 的硬规矩。
- **`return a + b;`** —— 算完 `3 + 5`，把 `8` **叼回**到喊它的那个地方。术语表里管它叫**叼回来的战利品**喵（原文叫返回值）。
- **`int total = add(3, 5);`** —— 战利品直接落进 `total` 这只碗。它和普通的数一样：**能存进仓库、能接着算、能再喂给别的招式**。
- **`printf("%d\n", add(10, 1));`** —— 这一趟喊招式的地方直接就是打印的投喂口，`11` 一被叼回来就顺手印了出去。

一句话分清楚：**头上写 `void` = 本喵只干活，不带东西回来；头上写 `int` = 这招会叼一个整数给你。**

### 不叼东西的招式，你接不到

头上写了 `void`，你却伸手去接，翻译官喵当场拦下：

```c
#include <stdio.h>

void greet(void) {
    printf("你好喵～\n");
}

int main(void) {
    int x = greet();
    printf("%d\n", x);
    return 0;
}
```

这是它的原话喵：

```text
main.c:8:13: error: void value not ignored as it ought to be
    8 |     int x = greet();
```

翻成猫话：**「这一招压根不叼东西回来，你怎么还伸手去接？」** —— 它连编译都不肯往下走，直接把单子退回来了。

### `return` 一执行，招式当场收工

`return` 除了叼东西，还有个脾气：**它一跑，这一招就结束了** —— 后面就算还排着活儿也不干了。

```c
#include <stdio.h>

void check(int n) {
    if (n > 0) {
        printf("还有鱼干喵\n");
        return;
    }
    printf("碗空了喵\n");
}

int main(void) {
    check(5);
    check(0);
    return 0;
}
```

```text
还有鱼干喵
碗空了喵
```

- 第一次喊 `check(5)`：眼色答「真」，`return` 当场收工，**下面那句打印根本没轮到**。
- 第二次喊 `check(0)`：眼色答「假」，先印那句话，再走到末尾收工。
- 注意这一招头上写的是 `void`，所以这里的 `return` **后面什么都不带**，光溜溜一个 `return;` —— 意思是「不叼东西，就地收工」。

所以 `return` 还有个别名：**提前收工**。想让它别急着走，就把 `return` 挪到招式的最末尾。

## 三、投喂的小鱼干：让招式别再写死

刚才那一招太死板 —— 想让三只猫各听各的那一句，就得写三招。本喵换个写法：在招式头上先摆几只**空碗**，每只碗写个名字，施展的时候往里放东西。

```c
#include <stdio.h>

void greet(char name[]) {
    printf("你好，%s喵～\n", name);
}

int main(void) {
    greet("小橘");
    greet("狸花");
    return 0;
}
```

```text
你好，小橘喵～
你好，狸花喵～
```

- **`void greet(char name[])`** —— 括号里摆了一只碗，碗上写着 `name`，前面那个 `char name[]` 说好它装的是**一串小鱼干的项链**。
- **`greet("小橘")`** —— 施展时把 `"小橘"` 这条小鱼干**喂进碗里**。这一趟跑起来，招式里的 `name` 就当作 `"小橘"` 用。
- **`greet("狸花")`** —— 同一招，第二次喂的是 `"狸花"`。所以屏幕上多了一行，两行只差名字。
- 招式里的 `name` 是**招式自己内部的叫法**，和你外头建的仓库互不打扰：招式跑完，这只碗也就收起来了。

**一次登记，喂什么都行** —— 这才是「打包」最值钱的地方：重复的话只写一遍，剩下的交给喂进去的小鱼干。术语表里管这叫**投喂的小鱼干**喵（原文叫参数）。

::: warn 小心喵
这里藏着一个**很大的古怪**，本喵必须提前打招呼喵：

上面这一招，招式里拿到的**不是抄件** —— 项链的碗是摊在外头的，招式伸手就能摸到原件。而普通的数字碗不一样：招式拿到的是**抄的一份**，在招式里怎么改都动不了外面那只原碗。

这两种投喂**脾气完全不同**，是 C 里最要紧的一件事之一。本喵下一课专门讲它，今天你只要先见一面、知道「有这么回事」就够了。
:::

### 好几只碗：按顺序一一对应

要喂两样东西，就在括号里摆两只碗，用逗号隔开：

```c
#include <stdio.h>

void report(int a, int b) {
    printf("第一位是 %d，第二位是 %d\n", a, b);
}

int main(void) {
    report(3, 5);
    report(5, 3);
    return 0;
}
```

```text
第一位是 3，第二位是 5
第一位是 5，第二位是 3
```

- 登记时 `(int a, int b)` 摆了两只碗，施展时就得喂两样，**按顺序一一对应**：第一位喂给 `a`，第二位喂给 `b`。
- 喂反了会怎样？写 `report(5, 3)`，翻译官喵**不会拦你** —— 它老实照做，印出「第一位是 5，第二位是 3」。碗是照名牌收东西的，它不检查你喂进来的到底是不是那个意思。
- 想把名字和条数一起喂进去也行，摆两只碗、各写各的类型就可以：

```c
#include <stdio.h>

void greet(char name[], int count) {
    printf("%s，今天有 %d 条鱼干喵～\n", name, count);
}

int main(void) {
    greet("小橘", 3);
    greet("狸花", 5);
    return 0;
}
```

```text
小橘，今天有 3 条鱼干喵～
狸花，今天有 5 条鱼干喵～
```

## 四、C 独有的一条硬规矩：每只碗都要写类型

这是 C 和别的语言最不一样的地方，也是最容易摔的一跤。本喵故意少写一个类型给你看：

```c
#include <stdio.h>

int add(int a, b) {
    return a + b;
}

int main(void) {
    printf("%d\n", add(3, 5));
    return 0;
}
```

翻译官喵当场拦住，这是它的原话喵：

```text
main.c:3:16: error: unknown type name 'b'
    3 | int add(int a, b) {
```

它说的是：**「`b` 是什么东西？本喵没听说过这个名字。」** —— C 的规矩是**每摆一只碗，都要在碗前面写清楚它装什么**，一只都不能省。写成 `int add(int a, int b)` 就对了。

### 少喂一样、多喂一样，都拦住

摆了几只碗，就得喂几样。少喂一样：

```c
#include <stdio.h>

int add(int a, int b) {
    return a + b;
}

int main(void) {
    printf("%d\n", add(3));
    return 0;
}
```

```text
main.c:8:20: error: too few arguments to function 'add'; expected 2, have 1
    8 |     printf("%d\n", add(3));
```

多喂一样，它也照样翻脸：

```c
#include <stdio.h>

int add(int a, int b) {
    return a + b;
}

int main(void) {
    printf("%d\n", add(3, 5, 7));
    return 0;
}
```

```text
main.c:8:20: error: too many arguments to function 'add'; expected 2, have 3
    8 |     printf("%d\n", add(3, 5, 7));
```

两句原话里都带着 **`expected 2, have ...`** —— 翻译官喵把「说好几样」和「你实际喂了几样」都报了出来，照着它改就行。

**摆了几只碗就喂几样：一样不多、一样不少、顺序不错。**

::: tip 猫咪提示
今天五样东西，一句话串起来喵：

**招式头登记（先说清叼什么、喂什么）→ 报名字带 `()` 施展 → 括号里的空碗接住投喂的小鱼干 → `return` 把战利品叼回喊它的地方、顺便收工。**

再补两条 C 的硬规矩：**每只碗前面都要写类型**；**摆几只碗就喂几样**。这两条错了翻译官喵都会在翻译阶段就拦下你，程序根本生不出来 —— 报错看着吓人，其实是它在帮你挡刀喵。
:::

| 写什么 | 本喵的说法 | 干什么用的 |
|---|---|---|
| `void greet(void) { }` | 招式头 | 登记一招。前面的 `void` = 不叼战利品；括号里的 `void` = 不用喂 |
| `int add(int a, int b)` | 招式头 + 两只碗 | 前面的 `int` = 会叼回一个整数；括号里摆好碗和类型 |
| `greet();` | 喊一声施展 | 让招式真的跑一遍 |
| `int a` | 投喂的小鱼干 | 招式内部对「喂进来那样东西」的叫法，**前面必须写类型** |
| `return a + b;` | 叼回来的战利品 | 把结果交回喊它的地方，**同时当场收工** |

## 小任务

1. 写一招 `int add3(int a, int b, int c)`，把三个数加起来 `return` 出去，再 `printf("%d\n", add3(1, 2, 3))`，看看是不是 `6`。
2. 在 `greet` 那一招上再加一只碗，做成 `void greet(char name[], int count)`，让三只猫各听各的那一句。
3. 故意把某只碗的类型漏掉写一次（`int add(int a, b)`），亲眼读一遍那句 `unknown type name` 的原话。看完记得补回来喵。
4. 把 `report(3, 5)` 那两行对调一下，改成 `report(5, 3)`，**先猜**两行分别印什么，再跑一遍对答案喵。

下一课，本喵要讲两件更要紧的事：**招式拿到的是抄件还是原件**，还有招式里建的仓库到底能活多久 —— 外加那张「招式还没写出来，就先打个招呼」的预告单。去吧喵～ 🐾
