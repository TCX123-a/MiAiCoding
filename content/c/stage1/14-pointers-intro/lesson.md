上一课结尾留了个尾巴：为什么**整排的碗**交进招式，改的却是你本人的碗？

本喵当时的说法是：因为交出去的不是抄件，而是「碗架在哪儿」这条信息。

今天就把这条信息拎出来单独看 —— 它长什么样、怎么捏在手里、怎么用。这是 C 家里最有脾气的一样东西，摸透了它，你才算真正摸到 C 的性子喵。

## 一、每只碗都有门牌号，`&` 就是去问它

鱼塘边那排碗不是乱扔在地上的：每只碗都摆在架子上一个固定的位置，**都有自己的门牌号**。

平时你只管报名字取碗（写 `fish` 就行），从来不用操心它在哪儿。可要是你想把「**fish 碗在哪儿**」这件事本身交出去，就得先把门牌号问出来。问门牌号的写法，是在名字前面加一个 `&`：

```c
#include <stdio.h>

int main(void) {
    int fish = 5;
    int *p = &fish;

    printf("%d\n", p == &fish);
    printf("%d\n", *p);
    return 0;
}
```

```text
1
5
```

一行一行看喵：

- **`&fish`** —— 问出来 `fish` 那只碗的门牌号。
- **`int *p = &fish;`** —— 把门牌号记在一块**猫爪指向牌（指针）**上，这块牌子就叫 `p`。整句念作：「`p` 是一块指向整数碗的牌子。」
- **`p == &fish`** 印出 `1` —— 说明**牌子上写的内容，和 `fish` 的门牌号一模一样**。
- **`*p`** 印出 `5` —— 顺着牌子走到那只碗前面，看看里面装的是几。这一步叫「顺牌子（解引用）」：`*` 就是「顺着走」。

一句话：**`&` 是问门牌号，`*` 是顺着门牌号走到碗前面。**

::: tip 门牌号本喵不打算印给你看喵
用 `%p` 能把门牌号印成一串像 `000000C22AFFF8CC` 的编号。但同一份代码跑两趟，印出来的编号**是不一样的**（本喵真跑给你看过了），那是电脑临时安排的位置，看一眼也记不住。

所以你只要记住：**它是一块牌子，指着某一只碗。** 至于那串编号本身，交给电脑操心就行喵～
:::

## 二、顺着牌子，能拿也能改

上面那个 `*p` 是「顺牌子**拿**东西」。反过来，顺着牌子**放**东西也一样成立：

```c
#include <stdio.h>

int main(void) {
    int fish = 5;
    int *p = &fish;

    *p = 99;
    printf("%d\n", fish);
    return 0;
}
```

```text
99
```

`*p = 99;` 的意思是：走到 `p` 指的那只碗前面，把 `99` 放进去。所以最后印 `fish`，出来的是 `99` —— 你那只碗**真的被改了**。

这四行是本课的心脏，本喵把它拆成一格一格给你看喵。「门牌号」和「5」这两个值要分清楚：一个说的是**碗摆在哪儿**，一个说的是**碗里装着什么** —— 这一课全部的难，都在这一条线上面。

这就是牌子和抄件的分水岭喵：

- 喂进去**一个数** → 交的是抄件，招式里怎么改都改不到你；
- 交出去**一块牌子** → 牌子指着原件本人，顺着它改，改的就是你的碗。

两只牌子还能指着同一只碗：

```c
#include <stdio.h>

int main(void) {
    int fish = 5;
    int *p = &fish;
    int *q = p;

    *q = 42;
    printf("%d\n", fish);
    printf("%d\n", *p);
    return 0;
}
```

```text
42
42
```

`int *q = p;` 是**把牌子上的内容（门牌号）抄给另一块牌子**。所以 `q` 和 `p` 指着的是同一只碗：顺着 `q` 放了个 `42`，`p` 走过去一看，也是 `42`。

牌子可以印发很多张，但门牌号只有一个 —— **它们指的都是同一只碗**。

## 三、牌子自己的长相：怎么声明一块牌子

`int *p;` 这行字要**分两半读**：

- **`int`** —— 说的是「它指的那只碗里装的是整数」；
- **`*`** —— 说的是「这是一块牌子」。

两半合起来：**`p` 是一块指向整数碗的牌子**。碗里装小数就写 `double *p`，装字符就写 `char *p` —— 牌子上得写清楚它指的是什么碗。

还有一条容易摔的地方：这个 `*` **只管紧挨着它的那一个名字**，不是一行全管。

```c
#include <stdio.h>

int main(void) {
    int a = 1, b = 2;
    int *p, q;

    p = &b;
    q = 7;
    printf("%d %d %d\n", a, *p, q);
    return 0;
}
```

```text
1 2 7
```

`int *p, q;` 里**只有 `p` 是牌子**，`q` 是一只普普通通的整数碗 —— 所以后面能直接写 `q = 7;`。要是 `q` 也是牌子，这一句就编不过去了。想声明两块牌子，得老老实实写两遍：`int *p, *q;`。

::: warn 野牌子，千万别顺喵
要是你写了 `int *p;` 却没让它指向任何一只碗，那它就是一块**野牌子** —— 上面写着一串没意义的编号。

这时候**绝对不许**顺着它拿东西（`*p`）或者放东西（`*p = 1;`）：那多半不是你的碗，C 也不会拦你，接下来发生什么谁也说不准。

所以本喵给你一条死规矩：**牌子当场声明，当场指碗。** 这一课里每一块牌子都是这么写的，你写的时候也照做喵～
:::

## 四、把牌子喂进招式

现在回到上一课那个谜团 —— 你已经有本事把它彻底拆开了。

想让招式**真的改到你的碗**？把门牌号喂进去：

```c
#include <stdio.h>

void treat(int *p) {
    *p = *p * 10;
}

int main(void) {
    int fish = 3;
    treat(&fish);
    printf("%d\n", fish);
    return 0;
}
```

```text
30
```

看招式里那句 `*p = *p * 10;`：先顺着牌子把碗里的数拿出来（`3`），乘十，再顺着牌子放回去。招式拿到的就是**你那只碗的门牌号**，所以改完之后回到 `main` 一印，是 `30`。

和上一课对照一下就明白了：

- `void feed(int n)` 配 `feed(fish)` → 招式拿到**抄件**，改了外面不变；
- `void treat(int *p)` 配 `treat(&fish)` → 招式拿到**牌子**，改了外面**真的会变**。

**那整排的碗为什么是例外？** 因为整排碗交出去的时候，交的正是**第一只碗的门牌号**：

```c
#include <stdio.h>

void treat(int *p) {
    *p = 99;
}

int main(void) {
    int bowl[3] = {1, 2, 3};
    treat(bowl);
    printf("%d\n", bowl[0]);
    return 0;
}
```

```text
99
```

看出来了吗喵：`treat(bowl)` 这里，那排碗的名字 `bowl` **自己就充当了门牌号** —— 招式里的 `int *p` 接的正是它。所以招式里 `*p = 99;` 改的，就是你本人的第一只碗。

上一课那条「整排的碗是例外」，不是 C 在照顾你，而是**它把第一只碗的门牌号交了出去** —— 和这一课的牌子，是同一回事。

## 五、三个最容易摔的地方

**摔法一：把普通的碗当牌子顺。**

```c
#include <stdio.h>

int main(void) {
    int fish = 5;
    printf("%d\n", *fish);
    return 0;
}
```

```text
main.c:5:20: error: invalid type argument of unary '*' (have 'int')
    5 |     printf("%d\n", *fish);
```

顺着走的前提是**它得是块牌子**。`fish` 是一只装整数的碗，`*fish` 等于拿着一个数字当门牌号去敲门 —— 翻译官喵当场拦下：`invalid type argument of unary '*'`，意思是「这颗星用错地方了」。

**摔法二：牌子说的，和碗里装的不是一回事。**

```c
#include <stdio.h>

int main(void) {
    double price = 3.5;
    int *p = &price;
    printf("%d\n", *p);
    return 0;
}
```

```text
main.c:5:14: error: initialization of 'int *' from incompatible pointer type 'double *' [-Wincompatible-pointer-types]
    5 |     int *p = &price;
```

`price` 那只碗装的是小数，给它配的牌子必须是 `double *`。写成 `int *`，两边对不上 —— `incompatible pointer type`。注意这种「说好装什么就得是什么」的规矩，也是 C「什么都要自己管」的一部分喵。

**摔法三：给一个孤零零的数字要门牌号。**

```c
#include <stdio.h>

int main(void) {
    int *p = &5;
    printf("%d\n", *p);
    return 0;
}
```

```text
main.c:4:14: error: lvalue required as unary '&' operand
    4 |     int *p = &5;
```

门牌号只有**碗**才有。`5` 是个孤零零的数字，没摆在架子上，哪来的门牌号？`lvalue required` 的意思就是「这里得放一只碗」。

::: warn 老朋友 `scanf` 里那个 `&`，现在你看懂了喵
你第一次见 `&` 是在 `scanf("%d", &n)` 里。现在你能读懂它了：**那是把 `n` 这只碗的门牌号交出去**，好让 `scanf` 把读到的数**放进你的碗里**。没有门牌号，它就只能把数放回自己家 —— 那你可就白读了。

漏了 `&` 会怎样？翻译官喵会给你一句：

`warning: format '%d' expects argument of type 'int *', but argument 2 has type 'int' [-Wformat=]`

注意它只是**警告**：程序照样生得出来，然后跑起来拿着一个根本不是门牌号的数字去砸别人的门。接下来发生什么谁也说不准 —— 所以这段本喵**不给你演示**，你也千万别试喵。
:::

## 一句话对照表

| 写法 | 念作 | 干什么 |
|---|---|---|
| `&fish` | 问门牌号 | 问出来 `fish` 那只碗摆在哪儿 |
| `int *p;` | 声明一块牌子 | `p` 是一块指向整数碗的牌子 |
| `*p` | 顺牌子 | 走到 `p` 指的那只碗前面，看里面装的是几 |
| `*p = 99;` | 顺着牌子放东西 | 把 `99` 放进那只碗（原件真的变） |
| `p = &b;` | 换一只碗指 | 让这块牌子改指 `b` 那只碗 |
