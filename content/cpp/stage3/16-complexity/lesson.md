## 钩子：主人问「差多少」，本喵答不上来

本喵给主人写了两段代码，干的是**同一件事**：把 1024 条小鱼干按重量排排坐。

第一段跑起来，本喵去倒了杯水、回来还没动静；第二段眨个眼就完事了。主人问：「差多少喵？」

本喵差点张口就说「差一点点吧」—— 幸亏忍住了。真去数了一遍：一段要 **523776 圈**，另一段只要 **10240 圈**，差**五十多倍**。

「快不快」这种事，靠感觉是要翻车的。今天本喵要教两件事：**怎么把代价量出来**，还有量出来之后**怎么把它写在纸上** —— 那个写法叫**大 O 记号**。

## 一、为什么要量代价：别拿秒表当尺子

本喵见过太多猫掐着秒表说「我这写法更快」。可那个数**靠不住**，有三个地方会骗你：

1. **机器不一样。** 本喵这台笔记本上跑 3.7 秒的代码，搬到鱼塘边那台老机器上可能要 30 秒。同一段代码、两个秒数 —— 到底哪个才算它的代价？
2. **同一台机器也不稳。** 后台还有别的猫在干活（本喵的鱼干下载器正开着），它一抢，秒数就飘。
3. **数据不一样。** 换一批小鱼干、把 1024 换成 2048，秒数又变了。

看出来了吗：**「秒」不是这段代码自己的属性**，它是「代码 + 机器 + 当时环境」三样搅在一起的结果。

真正属于代码自己的那把尺子是：**这件事要跑多少圈。**

同样的问题、同样的条数，两两比一遍就**一定是** n(n-1)/2 圈 —— 搬到哪台机器上都是这个数，跟后台有没有别的猫也没关系。能拿来互相比较的，是它。

::: tip 猫咪提示
本课说的「代价」，只指一件事：**这件事要跑多少圈**（要做多少次最基本的动作）。

它和「跑几秒」是两把尺子，别混：圈数是代码自己的性质，秒数是机器的事。量圈数量到底量的是什么？—— **这件事会不会随着数据变大而爆炸**。
:::

## 二、数圈数：从 523776 到 10240

把条数定成 **1024**（本喵那批小鱼干的条数），本喵真的跑了一段程序去数：同一件事的两种写法，各要跑多少圈。

```cpp
#include <iostream>

int main() {
    const int n = 1024;

    // 笨办法：每两条都比一遍
    long long pairs = 0;
    for (int i = 0; i < n; i++) {
        for (int j = i + 1; j < n; j++) {
            pairs = pairs + 1;
        }
    }

    // 聪明办法：分成两半、一层层合并；每一层把 n 条挨个过一次
    long long layers = 0;
    for (int width = 1; width < n; width = width * 2) {
        for (int i = 0; i < n; i++) {
            layers = layers + 1;
        }
    }

    std::cout << "两两比一遍：" << pairs << " 次" << std::endl;
    std::cout << "一层层合并：" << layers << " 次" << std::endl;
    return 0;
}
```

```text
两两比一遍：523776 次
一层层合并：10240 次
```

这两个数是怎么来的，一句一句数给你听：

- **笨办法（两两比一遍）**：第一个碗跟它**后面**的 1023 个碗各碰一次；第二个碗跟后面 1022 个各碰一次……最后一个碗后面没人了，一次都不碰。加起来是 `1023 + 1022 + ... + 1`，也就是 **n(n-1)/2** —— 把 1024 代进去，正好是 **523776**。
- **聪明办法（一层层合并）**：每一层把 1024 条**挨个过一次**；那要过几层呢？1024 一直砍一半、砍到 1 为止：1024 → 512 → 256 → …… → 1，正好 **10 层**（因为 2 的 10 次方就是 1024）。10 层 × 1024 条 = **10240**。

（这里数的是「每一层挨个过一次」这种最省事的数法。真合并的时候，某一层不一定每次都碰到底 —— 但**「一层一层、一共 10 层、每层差不多 n 次」**这件事不会变，量级就在这儿。）

同一批 1024 条小鱼干、同一件事：一个 **523776**，一个 **10240** —— 差五十多倍。这个差距不是本喵吹出来的，是数出来的。

### 想偷懒改 n？翻译官喵不让

本喵本来想省事：就在同一段程序里把 n 一格一格往上调，一屏看完所有情况。写下去，翻译官喵当场把本喵拦住了：

```cpp
#include <iostream>

int main() {
    const int n = 1024;
    long long pairs = 0;

    for (n = 8; n <= 1024; n = n * 4) {
        for (int i = 0; i < n; i++) {
            for (int j = i + 1; j < n; j++) {
                pairs = pairs + 1;
            }
        }
        std::cout << "n=" << n << "  两两比=" << pairs << std::endl;
    }
    return 0;
}
```

```text
main.cpp:7:12: error: assignment of read-only variable 'n'
```

翻译官喵的原话是「`n` 是一格**只读**的小鱼干仓库，不许再往里塞」。`const` 的意思就是「这一格从一开始就说好了、往后不许改」—— 它拦得对，本喵认了。

那本喵怎么把上面那几个 n 都试出来的？**把 n 抄成另一只仓库**（`for (int n = 8; n <= 1024; n = n * 4)` 里的那个 n 是新造的、可以改），或者干脆改一次源码跑一次。这不是什么高深技巧，就是别跟 `const` 硬碰喵。

## 三、大 O 记号：只留长得最快的那一项

523776 这个数是**数出来的**，可它太长了，而且**太依赖 n 的具体值**：换成 512 条，它立刻变成 130816；换成 2048 条，又是 2096128 —— 谁记得住？

于是人们换了个写法：**只留长得最快的那一项，常数一律扔掉。**

- 两两比一遍：`n(n-1)/2` 摊开是 `n²/2 - n/2`。里面有两项：一项是「两个 n 相乘」，一项是「一个 n」。n 一大，n² 那一项会把 n 那一项甩得没影（n = 1024 时：n²/2 是五十多万，n/2 才 512）。所以只留 n²、再扔掉那个 1/2，写成 **O(n²)**（读作「大 O n 平方」）。
- 一层层合并：`n × log₂n`（n 条货，砍一半砍了 10 次）。写成 **O(n log n)**。

扔掉东西的规矩一共三条：

1. **只留长得最快的那一项** —— 加法里谁大留谁（`n² + n` 留 `n²`）。
2. **乘上去的常数不要** —— `3n` 也好、`n/2` 也好，都写成 `n`。
3. **加上的常数不要** —— `n + 100` 也写成 `n`：n 一大，那 100 就跟没有一样。

::: warn 小心喵
**大 O 说的不是精确圈数，别把它当计数器用。**

- 523776 圈的那段代码是 O(n²)；本喵把它改成「只数一半的对」（大约 n²/2 圈）—— **还是 O(n²)**，因为常数不算数。
- 反过来，写着 O(n²) 的代码，跑出来可能是 n²/2 圈，也可能是 3n² + 7 圈。大 O 只保证一件事：**n 大到一定程度以后，圈数被「n² 乘一个固定的倍数」罩住，跑不出这个罩子。**

一句话：**O 说的是上界、是增长趋势** —— 它管的是「n 变大时它会怎么涨」，不管「这一趟到底跑了几圈」。
:::

那「增长趋势」是怎么看出来的？光看 n = 1024 那一行不够，得把好几个 n 排在一起：

```cpp
#include <iostream>

int main() {
    for (int n = 4; n <= 1024; n = n * 4) {
        long long pairs = 0;
        for (int i = 0; i < n; i++) {
            for (int j = i + 1; j < n; j++) {
                pairs = pairs + 1;
            }
        }
        long long layers = 0;
        for (int width = 1; width < n; width = width * 2) {
            for (int i = 0; i < n; i++) {
                layers = layers + 1;
            }
        }
        std::cout << "n=" << n << "  两两比=" << pairs << "  一层层合=" << layers << std::endl;
    }
    return 0;
}
```

```text
n=4  两两比=6  一层层合=8
n=16  两两比=120  一层层合=64
n=64  两两比=2016  一层层合=384
n=256  两两比=32640  一层层合=2048
n=1024  两两比=523776  一层层合=10240
```

这张表里有个**反常识**的地方，本喵要专门指给你看：**n = 4 的时候，笨办法反而更省**（6 圈 vs 8 圈）。

因为「一层层合并」每一步都自带开销（分层、记着哪一半是哪一半），条数少的时候，这些开销比它省下来的圈数还多。**要 n 大起来，趋势才说话。**

- n 从 4 涨到 1024（涨了 **256 倍**）；
- 笨办法从 6 涨到 523776（涨了 **八万多倍**）；
- 聪明办法从 8 涨到 10240（涨了 **一千两百多倍**）。

同一个 256 倍，一个涨出八万多倍、一个涨出一千多倍 —— 这就是 O(n²) 和 O(n log n) 的区别，也是本喵为什么盯着「量级」而不是盯着「这一趟跑了几圈」喵。

## 四、常见量级对照

把那三条规矩用熟，你迟早会碰上这五位常客。它们从省到费排成一队：

| 量级 | 读作 | 长什么样（代码里的样子） | n 翻一倍，圈数怎么变 |
|---|---|---|---|
| O(1) | 常数级 | 按编号直接把第 1024 个碗端出来、`total = n * 2;` | 一次都不变 |
| O(log n) | 对数级 | 每次把范围砍一半、`width = width * 2;` | 只多一圈 |
| O(n) | 线性级 | 一整排挨个过一遍、`for (int i = 0; i < n; i++)` | 翻一倍 |
| O(n log n) | 线性对数级 | 每层过一遍、一共 10 层（上面那个聪明办法） | 翻一倍再多一点点 |
| O(n²) | 平方级 | 每两条都碰一次（上面那个笨办法） | 翻四倍 |

「翻四倍」这种事，在纸上看着还好。本喵把它按**一秒一亿圈**粗算一下（这只是个假设，方便你有个数感）：

| 写法 | n = 十万条时的圈数 | 按一秒一亿圈算 |
|---|---|---|
| 两两比一遍 O(n²) | 一百亿圈 | 约 **100 秒** |
| 一层层合并 O(n log n) | 约一百七十万圈 | 约 **0.017 秒** |

n 才十万条 —— 在一个程序里根本不算多 —— O(n²) 就已经要一分半钟了，而 O(n log n) 还是眨个眼。**差好几千倍**。

还不止「慢」这一件事。本喵真跑过两段：

```cpp
#include <iostream>

int main() {
    int n = 100000;
    int total = n * n;
    std::cout << "n 平方 = " << total << std::endl;
    return 0;
}
```

```text
n 平方 = 1410065408
```

n 平方明明是一百亿，它却叼回来一个十四亿多的数：**仓库太窄，装不下，高位就漏掉了**。这一段翻译官喵**一声没吭**（本喵真跑过，一个字都没说）。

把两个数**直接相乘**（不经过小鱼干仓库一趟）、结果照样装进同一只窄仓库，它倒是会念一句：

```cpp
#include <iostream>

int main() {
    int total = 100000 * 100000;
    std::cout << "n 平方 = " << total << std::endl;
    return 0;
}
```

```text
n 平方 = 1410065408
```

它念的是这一句（本喵现场跑出来的原话）：

```text
main.cpp:4:24: warning: integer overflow in expression of type 'int' results in '1410065408' [-Woverflow]
```

`integer overflow` 就是「装不下了、溢出来了」。⚠️ 但注意：**它只是出声，不是拦人** —— 念完这一句，程序照样编出来、照样跑，照样给你一个错的数。

一句话收尾：**圈数会爆炸，装圈数的仓库也得跟着加宽**。这就是本喵在第二节那段程序里把计数器写成 `long long` 的原因喵。

## 五、最好、最坏、平均：同一个写法，圈数也不止一个数

「在一整排小鱼干里翻出某一碗」这件事，要跑多少圈，**得看运气**：

```cpp
#include <iostream>

int main() {
    const int n = 16;

    // 最好：要找的那一条就摆在第一个碗里
    int best = 1;

    // 最坏：一整排翻完了都没有，白翻
    int worst = n;

    // 平均：假设它可能落在任何一条上，把每一种落点都走一遍
    long long total = 0;
    for (int pos = 1; pos <= n; pos++) {
        total = total + pos;
    }
    std::cout << "最好：" << best << " 次" << std::endl;
    std::cout << "最坏：" << worst << " 次" << std::endl;
    std::cout << "平均：" << (double)total / n << " 次（" << n << " 种落点，圈数加起来 " << total << "）" << std::endl;
    return 0;
}
```

```text
最好：1 次
最坏：16 次
平均：8.5 次（16 种落点，圈数加起来 136）
```

- **最好**：要找的那条就摆在第一个碗里 —— 1 圈就收工。
- **最坏**：一整排翻到底都没翻到 —— 16 圈，白跑了。
- **平均**：它可能落在任何一条上；把 16 种落点全部走一遍、圈数加起来是 136，平均下来 **8.5 圈**。

要紧的是这一句：**这三种情况的量级是同一个 —— 都是 O(n)**。所以本喵能只写一个 O(n)，不用写三个。

往后你会碰上「最好和最坏**差着量级**」的招式，那时候就必须分开写了。本喵先给你留个例子：有一种排排坐的写法，平时是 O(n log n)，可要是碰上一批特别倒霉的货，会掉到 O(n²) —— 那时候只写一句「它是 O(n log n)」，就是把最坏的那一趟藏起来了喵。

## 六、往后看：这一招的替身，STL 里早就备好了

上面那个「两两比一遍」，本喵是**故意**写得又笨又清楚的 —— 它是用来数圈数的，不是拿来用的。

真实的 C++ 工具箱里，有一个叫 `algorithm` 的工具格子，里面有一招 `std::sort`：给一堆货排排坐，它的量级是 **O(n log n)** —— 本喵今天数的那个「聪明办法」，就是它这一类写法的底子。

同一格里还有别的手艺，量级各不相同：

- 翻一圈找最大的一条、挨个过一遍数数 —— **O(n)**；
- 在一堆排好队的东西里找一件（也是每次砍一半）—— **O(log n)**。

也就是说：**本喵今天数的那些圈，往后你都能在 STL 里找到现成的、量级已经替你选好了的替身。** 什么时候该请 `std::sort`、什么时候一趟 O(n) 就够，往后讲到那个格子的时候，本喵带你把它们一个一个请出来喵。

::: tip 猫咪提示
今天收五句话：

1. **量代价用圈数，不用秒** —— 秒会被机器和环境骗，圈数是代码自己的性质。
2. **数圈数就是数圈数**：把 n 代进去、一层层数清，别猜。
3. **大 O = 只留长得最快的那一项、常数全扔**。它说的是**上界和增长趋势**，不是精确圈数。
4. **五位常客**：O(1) / O(log n) / O(n) / O(n log n) / O(n²)。n 翻一倍，它们分别不变 / 加一点 / 翻倍 / 翻倍再多一点 / 翻四倍。
5. **同一个写法可能有最好 / 最坏 / 平均三种圈数**：量级一样就写一个；差着量级就必须分开说。

## 小任务

1. 先猜再跑：把第二节那段数圈数的程序里 `const int n = 1024;` 改成 `512`，再改成 `2048`。两个数各会变成多少？猜完真跑一遍对照。
   （提示：别指望整整齐齐的四倍 —— 式子里的「零头」和「层数」都会跟着动，这正好能让你看清什么叫「趋势」。）
2. 先猜再跑：把第五节那段程序里的 `const int n = 16;` 改成 `32`，先猜平均是多少，再跑一遍对照。想想这个数为什么不是 16。
3. 自己数一次：把第二节的「两两比一遍」改成「三个一组，每组里两两碰一次」。n = 9 的时候一共碰几圈？先想清楚每一条跟谁碰，再写出来跑一遍验证。
4. 粗算一遍：按「一秒一亿圈」算，O(n²) 的写法要在 n 是多少条的时候才「一秒都跑不完」？算完自己写个程序验证一下这个 n 的平方是多少。
