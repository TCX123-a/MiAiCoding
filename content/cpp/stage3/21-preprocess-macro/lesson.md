## 钩子：递出去的条子，叼回来的数不对

本喵给翻译官喵递了张条子，条子上写着 `#define SQ(x) x * x`。

本喵心里的算盘是「平方」—— 于是理直气壮喊了一声 `SQ(1 + 2)`：一加二得三，三的平方得九，稳了。

翻译官喵叼回来的是 **5**。

本喵以为自己算错了，再喊一声 `SQ(4)` —— 这回它老老实实叼回 16，一点没错。

差的不是算数。**是这张条子从头到尾就没打算「算」。**

这门「开工前的准备」手艺，正式的名字叫**预处理**。翻译那一课里它是四道工序里的第一道，本喵当时只说了「把请来的家当抄进来」；今天把这道工序整个拆开看：它手里都办哪些事、怎么办的、以及它最容易咬人的那几口喵。

## 一、开工前那一步，先看清楚它把稿子改成了什么样

原稿是这样一份小东西：

```cpp
#include <iostream>
using namespace std;

#define GREET "开工前先把书抄进来"

int main() {
    cout << GREET << endl;
    return 0;
}
```

```text
开工前先把书抄进来
```

它完完整整跑得通，印出来的就是上面那一行。

现在本喵让翻译官喵**只办开工前那一步，办完就停**。它有专门的喊法：`-E`。

```text
g++ -E main.cpp > full.i
g++ -E -P main.cpp > plain.i
```

本喵真跑了两条，量了数：

- 原稿 `main.cpp`：**一百四十三字节**；
- `-E` 出来的 `full.i`：**一百三十八万七千三百九十三字节**，四万四千一百二十六行；
- 再加 `-P` 的 `plain.i`：**一百一十八万六千五百零九字节**，三万一千五百四十二行。

`-P` 干的活儿很小：`-E` 的稿子里夹着 `# 0 "main.cpp"`、`# 0 "<built-in>"` 这样的**行标**，用来告诉后面的工序「这段其实是从哪儿来的」；`-P` 就是「行标不要」。两个数一减 —— 二十万零六百八十四字节、一万两千五百八十四行，全是行标。

稿子有一百多万字节，本喵掐一段尾巴给你看：

```text
}
using namespace std;
int main() {
    cout << "开工前先把书抄进来" << endl;
    return 0;
}
```

看这段尾巴，三件事就够了：

1. **`#include <iostream>` 那一行不见了** —— 它原来的位置上，是搬进来的那一整本家当（一百多万字节里的绝大多数都是它）；
2. **`#define` 那一行也不见了** —— 那张条子是「嘱咐」，不是稿子的一部分；
3. **`GREET` 这个名字没了，原地换上了它后面那段字** —— 变回成 `cout << "开工前先把书抄进来" << endl;`。

本喵还扫了一遍整份稿子：`GREET` 出现 **0** 次、`#define` 出现 **0** 次。**开工前这一步办完，条子和名字就都不在了** —— 后面真正翻译的工序，从头到尾没见过「条子」这种东西。

这就是预处理的全部内容：**开工之前，照着你留的嘱咐，把稿子改成另一份稿子。** 下面这张演示把它走的几步摊开给你看喵。

## 二、条子只照字换：`SQ(1 + 2)` 是 5 不是 9

把钩子那段真跑一遍。这是第一节那份稿子的精简版：

```cpp
#include <iostream>
using namespace std;

#define SQ(x) x * x

int main() {
    cout << SQ(1 + 2) << endl;
    cout << SQ(4) << endl;
    return 0;
}
```

```text
5
16
```

第二行 16 是对的：`SQ(4)` 换成 `4 * 4`，怎么算都对。第一行不是。

翻译官喵的干法是：**见到 `SQ` 后面跟着一对圆括号，就把括号里那一整坨原样搬过去，塞进 `x` 出现的地方。** 这张条子里 `x` 出现两次，那一整坨就被塞了两次，稿子上那一行变成了：

```text
cout << 1 + 2 * 1 + 2 << endl;
```

**换完就走 —— 不算、不补括号、也不看前后。** 至于 `1 + 2 * 1 + 2` 算出几，那是**后面翻译那道工序**的事：先乘后加，二乘一得二，剩下 `1 + 2 + 2`，**5**。

所以头一条规矩是：**条子换的是「字」，不是「值」。** 你以为递过去的是「3」，它拿到手的其实是 `1 + 2` 这几个字符，而且拿到两遍。

## 三、每个投喂口都要套括号，整个身子还要再套一层

修法很朴素：**每一处投喂口各套一层括号，整个身子再套一层。**

```cpp
#include <iostream>
using namespace std;

#define SQ(x) ((x) * (x))

int main() {
    cout << SQ(1 + 2) << endl;
    cout << SQ(4) << endl;
    return 0;
}
```

```text
9
16
```

9 回来了。拆开看这两层各管什么：

- **投喂口那两层（`(x)`）** 管的是「喂进来的是一整坨式子」：套上之后换完是 `((1 + 2) * (1 + 2))`，一整坨被圈住，先加后乘，得 9；
- **最外面那层（把整个身子圈起来）** 管的是「换完之后，别被旁边的运算抢走」。

这一层在这个例子里看不出好处，得换个例子才现形：

```cpp
#include <iostream>
using namespace std;

#define PLUS_ONE(x) (x) + 1

int main() {
    cout << PLUS_ONE(4) * 2 << endl;
    cout << PLUS_ONE(4) << endl;
    return 0;
}
```

```text
6
5
```

第二行 5 是对的（4 加 1）。第一行本喵心里想的是「4 加 1，再乘 2」得 10，叼回来的是 **6**：

```text
(4) + 1 * 2
```

括号只圈住了 `4`，`+ 1` 露在外面，于是乘号先跟 1 抱成了一对。补上外面那层：

```cpp
#include <iostream>
using namespace std;

#define PLUS_ONE(x) ((x) + 1)

int main() {
    cout << PLUS_ONE(4) * 2 << endl;
    cout << PLUS_ONE(4) << endl;
    return 0;
}
```

```text
10
5
```

::: warn 小心喵
**缺里面那层，和缺外面那层，坏起来不是一个样子。**

- 缺投喂口那层：**数当场就不对**（5 而不是 9）—— 至少你还看得出怪；
- 缺最外面那层：**太平的时候一点事都没有**（`PLUS_ONE(4)` 印 5，完全正确），只有它站到别的运算旁边才翻车。这种「平时全对、偶尔错一个」最难查。

所以一步都不能省：**每一处投喂口各套一层，整个身子再套一层。** 本喵宁愿多敲几个括号，也不想哪天半夜去查一个「十次里错一次」的数喵。
:::

## 四、它不认花括号，也不挑你喂什么

**先说不认花括号。** 一般的东西写在哪里就管哪一块地方（招式身上起的名字，别的招式看不见）。条子不是这样：**它从写下那一行起，往下一路管到底。**

```cpp
#include <iostream>
using namespace std;

void greet() {
    #define WORD "你好喵"
    cout << WORD << endl;
}

int main() {
    cout << WORD << endl;
    greet();
    return 0;
}
```

```text
你好喵
你好喵
```

`#define` 那一行明明写在 `greet` 的身子里，可 `main` 在它下面 —— 于是 `main` 里那句 `WORD` 照样被换掉了。**花括号划出来的地盘，条子一眼都不看；它只认「哪一行在前、哪一行在后」。**

**再说不挑你喂什么。** 整数、小数、一整坨式子，它都照字换：

```cpp
#include <iostream>
using namespace std;

#define SQ_M(x) ((x) * (x))

int main() {
    cout << SQ_M(2.5) << endl;
    cout << SQ_M(3) << endl;
    return 0;
}
```

```text
6.25
9
```

喂 2.5 进去，它换完是 `((2.5) * (2.5))` —— 6.25，一点没跟你商量。**条子身上没写「我收什么」，所以它什么都不会拦。**

## 五、`#define` 后面别顺手加分号

这是新手必踩的一口。别的东西句尾都要写分号，手一滑，条子尾巴上也来一个：

```cpp
#include <iostream>
using namespace std;

#define MAX 100;

int main() {
    cout << MAX << endl;
    return 0;
}
```

翻译官喵当场犯难：

```text
main.cpp: In function 'int main()':
main.cpp:7:17: error: expected primary-expression before '<<' token
```

它指的是 `cout << MAX` 那一行 —— `MAX` 换成 `100;` 之后，那一行中间多出一个分号，一句被劈成了两截。

去掉那个分号就完了：

```cpp
#include <iostream>
using namespace std;

#define MAX 100

int main() {
    cout << MAX << endl;
    return 0;
}
```

```text
100
```

**更阴的是另一种场合。** 同一个带分号的条子，换个地方用：

```cpp
#include <iostream>
using namespace std;

#define FISH_MAX 100;

int main() {
    int bowl = FISH_MAX;
    cout << bowl << endl;
    return 0;
}
```

```text
100
```

它编过了，还印出了 100 —— 因为换完是 `int bowl = 100;;`，多出来的那个分号是个空句子，翻译官喵当没看见。

同一个毛病，上一种场合当场拦你，这一种一声不吭。**「这次没报错」证明不了「写法是对的」** —— 这是本课最值钱的一条经验喵。

::: tip 猫咪提示
`#define` 那一行是**嘱咐**，不是句子 —— 嘱咐没有标点，所以它后面**不写分号**。

要记牢就记这句：**带上分号的条子，换到哪儿，哪儿就多一个多余的标点。**
:::

## 六、条子会把你说的话抄两遍

上一节说过：条子换的是「字」。**字换几遍，那句话就干几遍活。**

```cpp
#include <iostream>
using namespace std;

int calls = 0;

int next() {
    calls = calls + 1;
    return calls;
}

#define TWICE_M(x) ((x) + (x))

int twice_f(int x) {
    return x + x;
}

int main() {
    cout << TWICE_M(next()) << endl;
    cout << "宏这边 next 被喊了 " << calls << " 次" << endl;
    calls = 0;
    cout << twice_f(next()) << endl;
    cout << "招式这边 next 被喊了 " << calls << " 次" << endl;
    return 0;
}
```

```text
3
宏这边 next 被喊了 2 次
2
招式这边 next 被喊了 1 次
```

`next()` 每被喊一次，就把 `calls` 加一、把此刻的数叼回来。两边的差别一眼就看出来了：

- **宏这边**：`TWICE_M(next())` 换完是 `((next()) + (next()))` —— `next()` **被抄了两遍**，于是真被喊了两次（第一次叼回 1，第二次叼回 2），加起来是 3，`calls` 停在 **2**；
- **招式这边**：`twice_f(next())` 是**真招式** —— 翻译官喵先在门口把你喂进去的东西算好（只喊一次 `next()`，拿到 1），再进门做 `1 + 1`，`calls` 停在 **1**。

**「招式先把你喂的东西算好再进门，条子照着字换」** —— 这是它俩最实在的一条差别。你只打算让它动一次，它偷偷动了两次；数看着还对（3 就是 1 加 2），可旁边那只计数的碗已经不对了。

再说一个更险的。要是喂进去的是「自己会动一下」的东西，比如 `i++`：

```cpp
#include <iostream>
using namespace std;

#define SQ(x) ((x) * (x))

int main() {
    int i = 3;
    cout << SQ(i++) << endl;
    cout << i << endl;
    return 0;
}
```

翻译官喵会给一句嘱咐：

```text
main.cpp:8:17: warning: operation on 'i' may be undefined [-Wsequence-point]
main.cpp:4:17: note: in definition of macro 'SQ'
```

（这句话它会念两遍 —— `SQ` 展开出来的两处，各念一遍。）

**它出声了，可它没拦你** —— 程序照样编出来、照样交到你手里。本喵故意不写它会算出几：同一个式子里动两次 `i`，规矩上就没定它该是几（这台机器上它印 12，换一台未必）。这正是翻译那一课那句老话：**「警告」不是「错误」** —— 错误是拦下来的那只手，警告只是它顺口提醒的一句，而这一句最容易被一眼扫过去。

::: warn 小心喵
两层坑，一层套一层喵：

1. **条子把你的话抄几遍，就干几遍活** —— 轻则多算一次、多动一格，重则像上面那样掉进「规矩上没定」的地界；
2. **真出了这种事，翻译官喵给的是警告，不是错误** —— 东西照交，洞也照留。

要算的东西，交给招式；只有「开工前换字」这种活，才轮得到条子。
:::

## 七、什么时候用条子，什么时候用招式

同一件事（算平方），两种写法摆在一起：

```cpp
#include <iostream>
using namespace std;

#define SQ_M(x) ((x) * (x))

constexpr int sq_c(int x) {
    return x * x;
}

int main() {
    cout << SQ_M(1 + 2) << endl;
    cout << sq_c(1 + 2) << endl;
    cout << SQ_M(2.5) << endl;
    cout << sq_c(2.5) << endl;
    return 0;
}
```

```text
9
9
6.25
4
```

前两行一样（都是 9）：`sq_c` 是**常驻招式**（`constexpr`），它也会先把你喂的东西算好再进门，`1 + 2` 只算一遍。

后两行不一样，露的正是它俩的本性：

- `SQ_M(2.5)` 换完是 `((2.5) * (2.5))` —— **6.25**。条子不挑形状，你喂小数它就算小数；
- `sq_c(2.5)` 是 **4**。这一招在门口就写明了自己收整数（`int x`），那个 2.5 在门口被收成 2，进门是 `2 * 2`。

哪个才算对？看你想要什么。真正的差别不在数上，在**「说没说好」**上：招式在门口就把「我收什么、还你什么」写在明面上，不合形状的它当场处理（或者拦下来）；条子什么都收，等你发现不对，它早照字换完、悄悄走远了。

还有两件只有招式才有的好事：

- **它按形状收东西。** 条子连形状都不看，喂它一串字它照样换，捅出来的漏要等翻译那一步才露头；
- **它有地盘。** 招式写在哪块地方就管哪块地方；条子是从那一行一路管到底（上一节那两句 `你好喵` 就是它干的）。

下面这段就能看出「地盘」那一条的差别：

```cpp
#include <iostream>
using namespace std;

#define MAX 100

int main() {
    int MAX = 5;
    cout << MAX << endl;
    return 0;
}
```

翻译官喵在这就编不过去了：

```text
main.cpp:4:13: error: expected unqualified-id before numeric constant
main.cpp:7:9: note: in expansion of macro 'MAX'
```

它说：`int MAX = 5;` 里的 `MAX` 是张条子，换过去就成了 `int 100 = 5;`。把条子换成常驻的小碗，同样一段就好好编过了：

```cpp
#include <iostream>
using namespace std;

constexpr int MAX = 100;

int main() {
    int MAX = 5;
    cout << MAX << endl;
    return 0;
}
```

```text
5
```

`constexpr int MAX = 100;` 也登记了一个叫 `MAX` 的常量，可它在自己的地盘里待着；`main` 里那句 `int MAX = 5;` 是在里头新起了一只同名的仓库 —— 印 5，一点不打架。

那宏还留着干嘛？**管该由「开工前的准备」来判的事。** 下一课要学的「按记号挑段落」就是它正经的用场 —— 那时候条子不是拿来算数的，是拿来**指挥翻译官喵少翻几段**的。

::: tip 猫咪提示
今天收五句话：

1. **条子（宏）干的是「开工前照抄一遍」** —— 见到名字就换成后面那段字，换完就走；
2. **它只换字：不算、不补括号、不看花括号、不挑形状**；
3. **每一处投喂口各套一层括号，整个身子再套一层** —— 少一层就出事，而缺最外面那层时，平时还看不出来；
4. **`#define` 后面不写分号** —— 写了可能当场报错，也可能一声不吭，两种本喵都真见过；
5. **要算的东西交给招式（`constexpr` 更稳当）；条子只用来干「开工前换字」。**
:::
