## 钩子：第七课那条规矩，要过一次大考

第七课讲了「用完就还」：出生招式领牌子、收尾招式还牌子，一出了作用域自动还账。当时本喵留了一句话没说 —— **半路出事的时候，这条规矩还作数吗？**

今天请出来的就是那个「出事」：**扔出去的一句话**（`throw`）。它一扔，出事那个地方**后面的行全都不跑了** —— 包括本喵手写的那些收尾。第七课那套规矩到底值不值钱，就看这一课。

## 一、出事的那一刻，后面的行全没了

先看手写的收尾会怎么死：

```cpp
#include <iostream>
#include <string>
using namespace std;

void work(bool bad) {
    cout << "开门" << endl;
    if (bad) {
        throw string("门口摔了一跤");
    }
    cout << "关门" << endl;
}

int main() {
    try {
        work(true);
    } catch (string e) {
        cout << "接住：" << e << endl;
    }
    return 0;
}
```

```text
开门
接住：门口摔了一跤
```

盯着看喵：印了「开门」，**「关门」那一行没了**。`work` 半路上把一句话扔了出去，这一扔**当场把 `work` 剩下的行全掐掉** —— 那句印「关门」的活儿连碰都没碰到。

扔出去的那句话一路往上飘，飘进本喵在 `main` 里支起来的那张网里被接住，于是印了「接住：门口摔了一跤」。程序**没崩**，接着往下跑 —— 可开门和关门这一对，**只办了前一半**。

::: warn 小心喵
出事最坑的地方正是这个：它**不从出事的那个地方接着往下走**，而是直接跳到最近的那张网。中间那些收尾的活儿 —— 关门的、还牌子的、放下锁的 —— **一句都不会跑**。手写的收尾写得越多，散架得越厉害。
:::

## 二、第七课那套规矩，正是在这儿救场

现在把第七课那只「领了就还」的守卫请出来（出生招式加收尾招式，一模一样的老朋友）：

```cpp
#include <iostream>
#include <string>
using namespace std;

struct Gate {
    string name;
    Gate(string n) : name(n) { cout << "开门 " << name << endl; }
    ~Gate() { cout << "关门 " << name << endl; }
};

void work(bool bad) {
    Gate g("库房门");
    if (bad) {
        throw string("门口摔了一跤");
    }
    cout << "活儿干完了" << endl;
}

int main() {
    try {
        work(true);
    } catch (string e) {
        cout << "接住：" << e << endl;
    }
    return 0;
}
```

```text
开门 库房门
关门 库房门
接住：门口摔了一跤
```

跟第一节对着看喵 —— 这一回**「关门 库房门」跑掉了**！而且它排在「接住」**前面**。

道理还是第七课那一句：门是那只守卫**看着**的 —— 守卫一出生门就开，守卫一死门就关。半路上扔出去的那句话，掐得掉 `work` 剩下的行，**掐不掉「这只守卫生出来过、所以它一定会死」这件事**。

所以第七课那条规矩的价钱，正好在这一节课上一分不少地找回来：**出事的那条路上，手写的收尾会漏，看着东西的守卫不会漏。**

## 三、出事时，外面那些东西怎么办

收尾还回去了，这只是解决了一半。另一半更麻烦：**半路上已经动过的东西**。

本喵数了数，出事有三档：

| 档 | 意思是 |
|---|---|
| 出事就出事，外面乱不乱本喵不管 | 最省事，也最容易给后面留一堆烂摊子 |
| 出事的时候，外面**原封不动** | 干活之前先看明白、先备齐，最后一步才动外面的账 |
| 连「它绝不出事」都敢打包票 | 由本喵拍着胸脯保证 —— 这一档就是下一节那个记号 |

第二档是本喵最常要的，写法就一句话：**检查在前，动账在后。**

```cpp
#include <iostream>
#include <string>
using namespace std;

int stock = 10;

void take(int n) {
    if (n > stock) {
        throw string("不够了");
    }
    stock -= n;
    cout << "领走 " << n << "，还剩 " << stock << endl;
}

int main() {
    try {
        take(4);
    } catch (string e) {
        cout << "接住：" << e << endl;
    }

    try {
        take(99);
    } catch (string e) {
        cout << "接住：" << e << endl;
    }

    cout << "仓库里还是 " << stock << endl;
    return 0;
}
```

```text
领走 4，还剩 6
接住：不够了
仓库里还是 6
```

看最后一行喵：第二次领货**没领成**（那句「不够了」是在动手之前扔出来的），所以仓库那笔账**一点没动**，还是 6。

要是本喵把那段检查挪到减账那一句**后面**，事情就完全变了个样：账已经减了、货没领成，仓库凭空少了一笔 —— 这就叫**留了个烂摊子**。所以本喵动手的顺序是：**能检查的全检查完，动账那一下尽量放在最后。**

## 四、打了包票的招式

有些招式本喵敢拍着胸脯保证：它绝不会扔东西出来。写出来就是在招式后面加一个记号：

```cpp
#include <iostream>
using namespace std;

void safe() noexcept {
    cout << "本喵打包票" << endl;
}

void risky() {
    cout << "本喵没打包票" << endl;
}

int main() {
    safe();
    risky();
    cout << "safe 那张票：" << noexcept(safe()) << endl;
    cout << "risky 那张票：" << noexcept(risky()) << endl;
    return 0;
}
```

```text
本喵打包票
本喵没打包票
safe 那张票：1
risky 那张票：0
```

后面那两个数就是「**这张票打没打**」：`1` = 打了包票，`0` = 没打。问一句 `noexcept(...)`，翻译官喵当场就能告诉本喵答案。

打包票是一件**要命**的事喵：既然本喵说了「它不会扔东西出来」，那么它里面真扔出来的时候，程序**不会去找网**，而是**当场停下** —— 那张网连看都看不到这一句话。所以本喵敢打包票的只有两类：

- **收尾那一路的活儿** —— 守卫的收尾招式、搬家那条近路，它们自己出事的话，本喵本来也没地方去接；
- 本喵**看得清清楚楚**、只会做几个不会摔跤的小动作的招式。

::: tip 猫咪提示
第七、八两课那两个老朋友（会自己还仓库的牌子、搬家那条近路）在标准库里**都是打了包票的**。它们里边只做「换个归属」这一种绝不会摔跤的活 —— 正因为如此，本喵才敢在半路上出事的时候，把还账这件大事交给它们。
:::

## 一句话对照表

| 想干什么 | 写什么 |
|---|---|
| 出事：扔一句话出去 | `throw` 一句话 |
| 接住：别让程序带着它一路飘 | `try` 里干活，`catch` 里接 |
| 出事也要还回去 | 把东西交给一只**守卫**看着（第七课那套） |
| 出事时外面别留烂摊子 | **检查在前，动账在后** |
| 本喵保证这一处不出事 | 招式后面加 `noexcept` |
| 打了包票的招式真出事 | 程序**当场停**，那张网接不住 |
