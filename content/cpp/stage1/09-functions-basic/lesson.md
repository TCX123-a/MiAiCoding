## 钩子：同一段活儿，写到第三遍

上一课的小任务里，本喵让你把一排碗里的数加起来。你写的大概是这么一串：

```text
先起一只小碗，洗成 0
跑圈，把每一格加进碗里
把碗端出来印一下
```

写第一遍还行，写得挺顺。可要是本喵今天想加那排碗、明天想加另外一排、后天还想加一堆别的数呢？

**同一段活儿抄三遍。** 哪天本喵想把「端出来印一下」改成「端出来四舍五入一下」，三个地方都得改 —— 漏掉一个，就留下一个和别处不一样的地方等着咬你。

电脑最擅长「同一套动作反复做」——本喵居然还在替它抄！今天就把这件事解决掉：**给一段活儿起个名字、把它包起来，以后喊一声，整段就照着跑一遍。**

本喵管这个活儿叫**自创招式（函数）**。今天五件事，一件一件来：

1. **定义** —— 把一段活儿包起来、起名字；
2. **喊它** —— 名字后面一对括号；
3. **塞料** —— 让同一招每次干的活有点不一样；
4. **叼回来的东西** —— 让这一招干完带个结果出来；
5. **同名多招** —— 两招重名，翻译官喵怎么知道该跑哪一招。

## 定义：给一段活儿起个名字

本喵的第一招，就干一件事：打个招呼。

```cpp
#include <iostream>
using namespace std;

void meow() {
    cout << "喵～本喵来啦" << endl;
}

int main() {
    meow();
    meow();
    return 0;
}
```

```text
喵～本喵来啦
喵～本喵来啦
```

先看清楚**它写在哪儿**：这一招在大括号外面、在 `main` 的**上面**，和 `main` 平起平坐。**它不是写在 `main` 里面的东西** —— 它是本喵自己新添的一招，跟 `main` 站在同一层。

它的形状固定成四块：

```text
返回什么   名字( 塞进来的料 ) {
    一堆活儿
}
```

一块一块认：

- **最前头那一个词（这里是 `void`）** —— 说的是「这一招干完活儿，会不会带东西回来」。`void` 的意思是**空手**：干完就干完，什么都不带出来。这个词你先照着抄，等讲到「叼东西回来」那一节，你会一眼看懂它为什么长这样。
- **`meow`** —— 本喵给这一招起的名字，随你起，能一眼看出它干什么就行。
- **`()`** —— 那对小括号里现在**空着**，意思是「喊这一招不用往里塞东西」。
- **`{ ... }`** —— 一对大括号包住的，就是**这一招要干的整段活儿**。这一对括号和 `if`、跑圈的那些是同一副，写法也一样。

### 喊一声，它就整段跑一遍

`main` 里那两句 `meow();`，就是**喊这一招**：

- 写法是**名字 + 一对括号 + 一个分号** —— 括号和分号一个都不能少；
- 喊一次，大括号里那整段活儿就跑一遍；喊两次就跑两遍。**本喵的爪子不用再抄第二遍。**

这就是它最大的好处：**一段活儿只写一遍，想跑几遍就喊几遍。**

哪天本喵想把招呼改成「喵～本喵又来了」，只改招式里那**一个**地方，`main` 里那两句一个字都不用动。

### 招式要写在喊它的上面

这一条是新手最容易摔的地方，本喵单独拎出来。

C++ 是**从上往下一行行读**的。读到 `main` 里那句 `meow();` 的时候，翻译官喵会问一句：「`meow` 是什么？本喵没见过这个名字。」

要是你把招式写到了 `main` 的**下面**，它读到那一句时确实还没见过：

```cpp
#include <iostream>
using namespace std;

int main() {
    meow();
    return 0;
}

void meow() {
    cout << "喵～本喵来啦" << endl;
}
```

```text
main.cpp:5:5: error: 'meow' was not declared in this scope
```

翻译官喵这句话的意思是：**「`meow` 这个名字，本喵站在这儿没见到过。」**

看到 `was not declared in this scope`，第一件事就是**往上看**：喊它的那一句上面，有没有把这一招好好写出来？没有的话挪上去，立刻就好喵。

## 塞料：让同一招每次有点不一样

只会喊「喵～本喵来啦」的招式有点笨 —— 每次喊出来的话一模一样。本喵想让它每次能说点不同的，就该**往括号里塞料**了。

括号里那几样东西，本喵管它叫**塞进去的料（参数）**：

```cpp
#include <iostream>
#include <string>
using namespace std;

void feed(string name, int count) {
    cout << name << " 领到 " << count << " 条鱼干喵" << endl;
}

int main() {
    feed("大肥鱼", 3);
    feed("小黄鱼", 5);
    return 0;
}
```

```text
大肥鱼 领到 3 条鱼干喵
小黄鱼 领到 5 条鱼干喵
```

看这一招的开头：

- **`(` 里那两样** —— `string name` 和 `int count`，中间**用逗号隔开**。一样料写一份：**先写它是什么样，再写它在这一招里叫什么名字**。
- **招式里那两句话，用的是这两个名字。** `name` 和 `count` 只在这一招的大括号里活着 —— 出了这对括号，谁都不认识它们。
- **喊的时候，括号里按顺序一份份塞进去。** `feed("大肥鱼", 3)` 就是「把 `"大肥鱼"` 交给 `name`，把 `3` 交给 `count`」。

**顺序是对着来的**：第一份料给第一个名字，第二份料给第二个名字。你要是写成 `feed(3, "大肥鱼")`，那就是把 `3` 交给 `name` —— 翻译官喵当场翻脸（`3` 没法交给装字的柜子）。

### 少塞了一份料会怎样

```cpp
#include <iostream>
using namespace std;

void feed(string name, int count) {
    cout << name << " 领到 " << count << " 条鱼干喵" << endl;
}

int main() {
    feed("大肥鱼");
    return 0;
}
```

```text
main.cpp:9:9: error: too few arguments to function 'void feed(std::string, int)'
```

`too few arguments` 就是**「塞进来的料太少了」**。这一招说好要两样，本喵只给了一样，翻译官喵不给开工。

它报错那行还把这一招的完整长相抄给你看了 —— **括号里两样，一样都不能少**。看到 `too few arguments`，就去数括号里的逗号：这一招定义时要几样、喊的时候给了几样，对得上吗喵？

## 叼东西回来：`return`

上面两招都是「空手」的：干完活，什么也不带回来。可本喵常常想让一招**干完顺手带个结果出来** —— 比如「把两个数加起来」。

还记得第一段那个形状吗？最前头那个词管的就是这件事。把它从 `void` 换成一个装数的名字，招式就有东西可叼了：

```cpp
#include <iostream>
using namespace std;

int add(int a, int b) {
    return a + b;
}

int main() {
    int total = add(3, 5);
    cout << total << endl;
    cout << add(10, 20) << endl;
    return 0;
}
```

```text
8
30
```

- **最前头的 `int`** —— 这一招干完会**叼一个数回来**。这就跟本喵满月时那句 `int fish = 3;` 是同一个 `int`：它说的都是「这里装的是一个数」。
- **`return a + b;`** —— 这一招的收尾。**`return` 干两件事：把后面的东西交出去，然后这一招立刻收工。** 大括号里排在它后面的活儿，一句都不会再跑。
- **叼回来的东西可以当场用掉**：`int total = add(3, 5);` 是先把叼回来的 8 装进小碗再印；`cout << add(10, 20);` 是直接拿去印，连碗都省了。

**喊一声就跳进招式身体，`return` 一到就跳回来** —— 招式最要紧的魔法就这两下；叼回来的东西能装进小碗，也能当场用掉。

::: tip 猫咪提示
**空手还是叼东西，只看最前头那一个词：**

- 写成 **`void`** —— 空手，干完活什么都不带回来。这种招式**不能**塞进 `cout` 里印，也不能装进碗里 —— 它没有东西可给。
- 写成 **`int`**（或者别的装数的名字）—— 干完会叼一个数回来，可以直接拿去印、拿去算、装进碗里。

还有一个新手最常犯的：**招式里说好要叼东西回来，可 `return` 从头到尾没写。** 翻译官喵**不拦你** —— 它只在旁边留一句警告（`no return statement ...`），编译照样过，看着像没事。可这样写出来的程序**一跑起来多半当场就崩掉**，结果根本拿不到。

**警告不是「没事」**，它就是来提醒你这一句的。写招式时先问自己：这一招答不答话？答话就得有 `return`。
:::

### 叼回来的东西还能喂给下一招

既然叼回来的就是一个数，那它当然能直接塞给另一招当料：

```cpp
#include <iostream>
using namespace std;

int add(int a, int b) {
    return a + b;
}

int main() {
    cout << add(3, 5) << endl;
    cout << add(add(1, 2), 4) << endl;
    return 0;
}
```

```text
8
7
```

第二句读起来是**从里往外**的：先算里面那层 `add(1, 2)`，叼回来 3；再把 3 当成第一份料，喊一次 `add(3, 4)`，叼回来 7。

这个形状看着眼熟吧？—— 上一课那排碗、你学过的加减乘除，都是这么一层套一层拼起来的。**招式叼回来的东西，就是一个能接着用的结果**，可以往外套无数层喵。

## 同名多招：翻译官喵怎么知道喊的是哪一招

最后一件事，C++ 独有的一手。

本喵想给同一件事起同一个名字，只是料不一样：**塞给它一个数，就翻倍；塞给它一串字，就把这串字接两遍。**

```cpp
#include <iostream>
#include <string>
using namespace std;

int more(int n) {
    return n * 2;
}

string more(string s) {
    return s + s;
}

int main() {
    cout << more(21) << endl;
    cout << more("喵") << endl;
    return 0;
}
```

```text
42
喵喵
```

**两招的名字一模一样，都叫 `more`。** 翻译官喵不糊涂 —— 它挑哪一招，看的是**你塞进去的是什么**：

- 塞进去的是 `21`（一个数），就走第一招，叼回来 42；
- 塞进去的是 `"喵"`（一串字），就走第二招，叼回来「喵喵」。

学名管这叫**同名多招**，本喵更爱说「一名的多招」。要同时站着，规矩只有一条：

> **同样多的料 + 每样料什么样不一样，才能重名。**

比如说，`int more(int n)` 和 `string more(string s)` 都是一份料，可一份是数、一份是字，翻译官喵分得清；要是你再写一个 `int more(int n2)` —— 也是「一份数」，那就和第一招**撞得一模一样**了，它会说分不清。这种错误很少见，今天认个脸就好喵。

## 小抄表

| 本喵想问的 | 记这个 |
|---|---|
| 一段活儿要反复用 | 给它起个名字、拿大括号包起来，写在 `main` 上面 |
| 这一招要怎么喊 | `名字(料);` —— 括号和分号一个都不能少 |
| 喊的时候要带东西进去 | 括号里按**顺序**一份份塞 |
| 干完要带个结果出来 | 最前头写 `int`，末尾 `return 结果;` |
| 干完什么都不带 | 最前头写 `void` |
| 名字一样的两招 | 翻译官喵看你**塞进去的是什么** |

::: warn 小心喵
本课最容易摔的三处：

1. **招式写到了喊它的地方下面。** 报 `was not declared in this scope` —— 把这一招挪到 `main` 上面。
2. **塞的料少了一份。** 报 `too few arguments` —— 数一数括号里的逗号，两边的份数对得上吗。
3. **说好要叼东西回来，却忘了写 `return`。** 编译能过，翻译官喵只在旁边留一句警告 —— 看着像没事，可一跑起来多半**当场崩掉**。这种最阴，它不拦你，得靠你自己检查。
:::
