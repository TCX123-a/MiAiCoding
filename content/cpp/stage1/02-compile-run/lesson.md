## 钩子：点单铺的两种规矩

大肥鱼问本喵：「你这铺子，是客人念一句、你就做一道吗？」

本喵摇头：「不是喵。本喵是**先把整本点菜单抄好**，抄完了才开火。抄的时候一个字都还没下锅；等整本抄完，照着往下做，一路都不会停。」

「要是抄到一半发现有个字看不清楚呢？」

「那就**整本都不做**。」本喵说，「一个字看不清楚，本喵就不敢保证后面那几十道菜是对的——所以一个字都不动，先把那页纸还给客人，让他改。」

这就是 C++ 请的那位翻译官喵的干法，正式名字叫**编译**：**整本翻完再开演，翻不过去就一份都不交**。

## 先说清三件后果

「编译型」这三个字只说了三件事，每一件你马上就能感受到喵。

**第一件：翻不过去，一行都不跑。**

这是最要紧的一条。稿子里只要有一处翻不通，翻译官喵**不会**帮你把前面写对的几句先念出来。它一份都不交，程序连一行都不许跑。所以往后你看到屏幕上「什么都没输出」时，第一个该想的是：**它到底翻过去了没有？**

**第二件：翻完再跑，跑起来快。**

因为交到你手里的那份东西，已经是电脑能直接照着念的了，中间不再需要谁替它转话。

**第三件：翻一次，能跑很多次。**

那叠誊好的稿子会**存成一份文件**躺在硬盘上。往后想跑几遍跑几遍，不用重新翻——这一条下面有个坑，本喵要专门讲。

## 那位翻译官喵叫 g++

本喵喊它翻译官喵，可电脑不认猫话，你在命令窗口里得喊它的名字：**g++**。

这名字挺好认：C 那门语言的翻译官叫 `gcc`，C++ 的翻译官就是在名字后面挂了两个加号。这两个加号说的正是上一课那句话——**在 C 的底子上又加了几样东西**，翻译官喵也跟着学了一手新的。要是你在别处见过那位不带加号的，往下照旧，喊法一个样喵。

喊它干活的写法，和上一课一个样子：**先说名字，再报上要翻的稿子，最后用 `-o` 指名把成品放哪儿**：

```text
g++ main.cpp -o prog.exe
```

`main.cpp` 是你的稿子（本喵的软件里默认就叫这个名字），`prog.exe` 是你要它交出来的成品。

::: tip 猫咪提示
`.cpp` 是 C++ 稿子的门牌，`.exe` 是能跑起来的成品的门牌。

往后看到 `.cpp`，你就知道「这是一份还没翻的稿子」；看到 `.exe`，就是「这是一份翻好的成品」。两者长得完全不一样，别把它们弄混——**`.cpp` 不能跑，`.exe` 不用翻**喵。
:::

## 四道工序：一份稿子怎么变成能跑的东西

翻译官喵抱着你的稿子回去，关起门来干的其实是**四道工序**。平时你不必管它们，但哪天程序出了怪毛病，知道是哪一道断的，能省下大把抓耳挠腮的时间喵。

拿下面这份稿子当例子，本喵把四道工序一道道走给你看。稿子一共一百七十六字节，就是它：

```cpp
#include <iostream>
using namespace std;

int main() {
    cout << "翻译官喵把整本翻完啦" << endl;
    cout << "现在轮到本喵跑一遍" << endl;
    return 0;
}
```

```text
翻译官喵把整本翻完啦
现在轮到本喵跑一遍
```

### 第一道：预处理——把请来的管理员家里的东西抄进来

上一课那句 `#include` 是请管理员出场，对吧？这一道工序干的就是把管理员家里的内容**原样抄到你的稿子开头**。

```text
g++ -E main.cpp -o main.i
```

产出一份 `main.i`。本喵真跑过：那份一百七十六字节的小稿子，抄出来变成了一百三十八万七千多字节——**大了将近八千倍**。你自己写的那几行原封没动，多出来的全是从管理员家里搬来的家当。

### 第二道：编译——把 C++ 翻成汇编

第二道工序才真的在「翻」：把 C++ 的句子翻成一种更接近机器、但还留着一行行人话的稿子。

```text
g++ -S main.i -o main.s
```

产出一份 `main.s`，本喵这份是一千九百多字节。想看热闹可以打开它瞄一眼——本喵劝你只看一眼就好，那里面的写法是给机器看的，不是给你看的喵。

### 第三道：汇编——翻成目标文件

```text
g++ -c main.s -o main.o
```

产出一份 `main.o`，叫**目标文件**，本喵这份一千八百多字节。它里面已经是机器能读的东西了，可它**还不能跑**——它是一块缺了零件的半成品。

缺什么零件呢？你用了 `cout` 这一招，可这一招的**身子**（真正干活的那些机器码）并不在你的稿子里，它住在管理员家里。目标文件里只留了一张欠条：「这里缺一个 `cout`」。

### 第四道：链接——把零件拼上，才能跑

```text
g++ main.o -o prog.exe
```

这道工序叫**链接**：翻译官喵拿着你的目标文件，把它欠的零件一件件找来、缝上去，最后交出一份**完整、能自己跑**的成品。本喵这份成品六万两千多字节——比稿子大了三百多倍，里面装的全是给你兜底的家伙什。

到这一步才算真的翻完。

翻译官喵关起门走的这四道工序，本喵拆成一步一步，走给你看：

四道工序的**次序不能换**：先抄家当、再翻成汇编、再变成缺零件的半成品，最后把零件缝上 —— 到这一步才有能跑的成品，屏幕上才可能出现你写的那句话。平时不用一道一道敲：一条命令 `g++ main.cpp -o prog.exe` 就能把四道全办，中间那三份半成品它用完就扔，下一条就说这件事喵。

### 一条命令，四步全办

四道工序走完，你手上有 `.i`、`.s`、`.o`、`.exe` 四份文件。可平时本喵从来不这么敲——**一条命令就够**：

```text
g++ main.cpp -o prog.exe
```

这一条命令，翻译官喵会自己把四道工序跑一遍，中间那三份半成品它**用完就扔**，只把最后的成品留给你。本喵试过：敲完这一条，目录里只剩 `prog.exe`，`.i`、`.s`、`.o` 一份都不见了。

所以你在软件里点「运行」之后看到的那一闪，背后就是这两件事：

```text
g++ main.cpp -o prog.exe
./prog.exe
```

先**翻**，再**跑**。这一步千万别记反：`.exe` 不会自己出现，`.cpp` 也不会自己跑起来喵。

还有一件事要提醒你：翻译官喵翻完就收工，**一声不吭**。它不会念「翻译完成」「链接成功」这类话。所以「没反应」和「跑成功了」经常长得一模一样——想分清它们，看的不是它有没有说话，而是**屏幕上有没有出现你让它念的那句话**。

::: warn 小心喵
**不写 `-o` 会怎样？** 翻译官喵会用一个默认的名字。本喵真跑过：它会生出一份叫 `a.exe` 的东西，安安静静地躺在那儿。

问题是——**它也不报错**。你敲完命令看到光标回来了，会以为万事大吉，然后到处找 `prog.exe` 找不到。所以本喵的规矩是：**每次都写 `-o`**，指名道姓，省得回头找文件喵。
:::

## 翻不过去的时候，屏幕上是什么样

现在来看那条最要紧的后果。本喵把上面那份稿子的**第二句**弄坏——末尾漏了个分号，第一句是完好的：

```cpp
#include <iostream>
using namespace std;

int main() {
    cout << "翻译官喵把整本翻完啦" << endl;
    cout << "现在轮到本喵跑一遍" << endl
    return 0;
}
```

```text
main.cpp: In function 'int main()':
main.cpp:6:41: error: expected ';' before 'return'
```

请盯着这段报错看三秒，然后回答本喵一个问题：**「翻译官喵把整本翻完啦」念出来了吗？**

**没有。一个字都没有。**

这就是编译型的脾气：第一句明明是对的，可翻译官喵整本翻到第二句时卡住了，于是**整份稿子一份都不交**，程序根本没开跑，哪一句都轮不上。要是换成「边念边翻」的语言，屏幕上本该先出现第一句、然后才炸——C++ 不会给你这个机会。

报错里那句 `main.cpp:6:41` 是翻译官喵在告诉你：它卡在第 6 行的第 41 个字符。顺着它指的地方看一眼，分号就补上了。

### 它连稿子本身都找不到的时候

还有一种更早的失败：稿子压根不在那儿。本喵把文件名敲错一个字，翻译官喵当场就急了：

```text
cc1plus.exe: fatal error: meiyou.cpp: No such file or directory
compilation terminated.
```

`No such file or directory`——「没有这份文件，也没有这个目录」。看到这一句，先去数一数文件名有没有敲错、稿子是不是和你在同一个目录里，别急着怀疑自己写的代码喵。

::: warn 小心喵
**改了稿子忘了重新翻，是新手最冤枉的一种「改了没用」。** 本喵真跑过这么一遍：

1. 先把稿子改坏一点点，再敲一次 `g++ main.cpp -o prog.exe`——这次翻不过去，翻译官喵报了错；
2. 可本喵低头一看，**上一版留下的 `prog.exe` 还老老实实躺在原地**，一个字节都没变；
3. 本喵顺手跑了一下 `./prog.exe`——屏幕上念出来的**还是旧的那两句**。

翻译官喵翻不动，是**它不给你新成品**，而不是**把旧的删掉**。你要是不看报错、直接跑，看到的就是旧成品的结果，怎么改都不变，越改越糊涂。

所以记住这条链子：**稿子改一个字，就得重新翻一次**；翻完先看有没有报错，再看屏幕。改动 → 重翻 → 跑，一步都不能跳喵。
:::

::: tip 猫咪提示
今天记住这条链子和它的两部：

**`main.cpp` --（g++ 四道工序）--> `prog.exe` --（跑）--> 屏幕上的字**

1. **命令的形状**：`g++ 稿子.cpp -o 成品.exe`，`-o` 是「指名成品放哪儿」，别省；
2. **先翻再跑**：`.cpp` 不能跑，`.exe` 不用翻，中间那一步不能跳。

再加一句：软件里点「运行」，做的就是这两步——先替你翻，再替你跑。你看到的报错，就是翻译官喵在翻的那一步拦下来的。
:::

## 小任务

1. 把上面那份稿子一字不差地敲进编辑器，存成 `main.cpp`，点一次运行，看看屏幕上是不是那两句话。
2. 把第二句末尾的分号删掉，再点一次运行。屏幕上还会不会出现第一句？把你看到的报错抄在手边，数一数它说的是第几行第几个字符。
3. 把分号补回去，再把引号里的字改成「本喵改过啦」，**先别重编，直接跑一次**——屏幕上念的是新的还是旧的？然后再翻一次，是不是就变了？
4. 如果软件里有命令窗口，试着敲一次 `g++ main.cpp -o prog.exe`，再敲 `./prog.exe`，亲眼看看「翻」和「跑」是两步。
