## 钩子：两只猫，两种数碗法

鱼塘边晒着刚洗好的猫粮碗，摞成高高的一摞。狸花猫蹲在旁边一只一只点：「1、2、3……」点到一半，被一只飞过的蝴蝶岔了神，回来忘了数到几，只好从头再点。

橘猫过来瞟了一眼，连点都懒得点，换了个**聪明的数法**：

> 这一摞有几个？ —— 最上面那个算 1 个，**再加上「剩下那一摞」有几个**。
> 「剩下那一摞」有几个？ —— 还是同一道题呀！照样是最上面算 1 个，再加剩下那摞。

一路问下去，什么时候停？**剩下那摞空的时候停** —— 空的当然就是 0 个。

看出来了吗：这个数法每一层问的都是**同一个问题**，只是每回问的东西小了一圈。C++ 里也能这么写 —— **在自己的招式里，再喊一次自己**。这门本事本喵管它叫自己咬自己尾巴的招式（递归）。

## 一、招式里喊自己：先数个数

```cpp
#include <iostream>

void countdown(int n) {
    if (n == 0) {
        std::cout << "到站喵" << std::endl;
        return;
    }
    std::cout << n << std::endl;
    countdown(n - 1);
}

int main() {
    countdown(3);
    return 0;
}
```

```text
3
2
1
到站喵
```

拆开看这个招式：投喂一个小鱼干 `n` 进去，然后它干三件事 ——

1. **先看要不要停。** `if (n == 0)` 成立的时候，印一句「到站喵」就 `return` 收工，**不再喊自己**。
2. **干自己的那点活。** `std::cout << n << std::endl;` 把当前这个数印出来。
3. **喊自己，并且把投喂的数目减一。** `countdown(n - 1);` —— 这就是「咬住自己尾巴」的那一口。

走一遍就明白了：进去时 `n` 是 3，它印 3、喊 `countdown(2)`；那一位印 2、喊 `countdown(1)`；再一位印 1、喊 `countdown(0)`；最后一位看到 `n == 0`，印「到站喵」，收工。一共四位，一层层到底，再一层层结束。

## 二、基线条件：那句「什么时候停」

上面那句 `if (n == 0)`，本喵管它叫**基线条件（刹车）**。

那把刹车拆了会怎样？本喵在跑台上真跑过这么一段（故意把刹车拿掉，所以只放在这儿给你看）：

```text
#include <iostream>

void countdown(int n) {
    std::cout << n << std::endl;
    countdown(n - 1);
}

int main() {
    countdown(3);
    return 0;
}
```

翻译官喵**出声了** —— 它给本喵留下这么两句：

```text
main.cpp:3:6: warning: infinite recursion detected [-Winfinite-recursion]
main.cpp:5:14: note: recursive call
```

它甚至一眼就看出来了（`infinite recursion detected` 就是「发现有个停不下来的自己喊自己」）。

**可它只是出声，没把本喵拦下** —— 程序照样被编了出来，交到本喵手里。**「警告」不是「错误」**：错误是拦下的那只手，警告只是它顺口提醒的一句，而这一句最容易被一眼扫过去。

真正没辙的在后面那一下：**一跑起来，它先一路往下数** —— 3、2、1、0、-1、-2……一直数到把「记着待会儿要回到哪儿」的那一摞碗摞爆，这才「啪」地一下没了：本喵这边收到的，是刷了一大片数字之后**突然断掉**，加上一个异常的退出状态。

道理不复杂：每一位都在喊下一位，永远没人喊停，于是「记着待会儿要回到哪儿」的那一摞碗越摞越高，最后把地方撑爆了。

**写自己咬自己尾巴的招式，第一件事就是先想清楚「什么时候停」。** 这里还有两条硬要求：

1. **停的那一句，得真有可能轮到。** `if (n == 0)` 配 `countdown(n - 1)` 是好的；配 `countdown(n + 1)` 就永远轮不到。
2. **每一步都要离停更近一点。** 这里每次都把 `n` 减一，所以一定走得到 0。

::: warn 小心喵
**别指望翻译官喵每次都出声。** 上面那一段它确实看出来了（「一直在喊自己」这件事摆在明面上）；可只要换个形状 —— 刹车写对了、但**每一步都往反方向挪**（`countdown(n + 1)` 那样），它就**一个字都不说**：跑起来照样收不了场，数字一路往上数，最后撑爆。

所以「忘了写刹车、或者刹车够不着」是本课最贵的坑：**它可能一声不响，也可能只出声不拦你** —— 等到跑起来，已经救不回来了。

还有一条：**每一次喊自己，投喂的东西都要往停的方向挪。** 挪反了方向，等于踩了油门去撞刹车，效果和没写刹车一样喵。
:::

## 三、去的时候一路往下，回来的时候一路收尾

再看一段更能看出「往返」的：

```cpp
#include <iostream>

void down(int n) {
    int mine = n * 10;
    if (n == 0) {
        std::cout << "到底了，本喵碗里是 " << mine << std::endl;
        return;
    }
    std::cout << "往下走之前，本喵碗里是 " << mine << std::endl;
    down(n - 1);
    std::cout << "回来之后，本喵碗里还是 " << mine << std::endl;
}

int main() {
    down(2);
    return 0;
}
```

```text
往下走之前，本喵碗里是 20
往下走之前，本喵碗里是 10
到底了，本喵碗里是 0
回来之后，本喵碗里还是 10
回来之后，本喵碗里还是 20
```

`mine` 是每一位自己的小鱼干仓库（`int mine = n * 10;`），**每一位都有新的一只**。所以：

- **往下走的那一趟**（在 `down(n - 1)` 之前）：印 20、印 10；
- **到底折回来之后**（在 `down(n - 1)` 之后）：印 10、印 20。

要紧的是这一句：`down(2)` 里那只碗装的是 20，它喊完 `down(1)`、等那一位全部收工回来之后，自己那只碗**还在，还是 20**。一层一层的碗不会互相覆盖 —— 「每个自己都有一套自己的仓库」就是这套写法能立住的地基喵。

「往下走」和「折回来」这两趟，是这一课最看不见的东西 —— 屏幕上印出来的五行里面，藏着一次**没印出来**的下钻和一次**没印出来**的回程。下面这段把它俩摊开给你看喵。

记着它的就是那一摞碗 —— 第二节里那个反例，就是把它摞爆了。反过来，每一层攥着的那个数（3、2、1）**不在**这一摞上：那些是各层私有的，随招式出生、随招式消失。两样东西都叫「碗」，别混喵。
:::

## 四、阶乘：数学书上的老例子

一说到自己咬自己尾巴，书上都爱举这个例子：`5!`（读作「5 的阶乘」）等于 `5 × 4 × 3 × 2 × 1`。

换个角度念：**`5!` 就是 `5 × 4!`**，而 `4!` 就是 `4 × 3!` —— 又是同一道题、小一圈。什么时候停？**`0!` 规定等于 1**，那就是它的刹车。

```cpp
#include <iostream>

long long fact(int n) {
    if (n == 0) {
        return 1;
    }
    return n * fact(n - 1);
}

int main() {
    std::cout << fact(5) << std::endl;
    std::cout << fact(10) << std::endl;
    return 0;
}
```

```text
120
3628800
```

看第二行那句 `return n * fact(n - 1);` 里的 `return`：它**不是**先算完再回来 —— 是「喊完那一位、等它把战利品叼回来，本喵再拿它跟自己乘」。所以每一位都要**等**下一位，一层层等到底，再一层层把战利品叼上来。上面那段演示演的就是这件事喵。

::: tip 猫咪提示
`long long` 是「更宽的仓库」，装得下更大的整数。`12!` 已经上亿了，用窄的那种仓库会装不下、印出一堆怪数字 —— 本喵这里给它留宽一点，你就不用操心了喵。
:::

## 五、一次喊自己两次：斐波那契

斐波那契数列是这样的：头两个数是 0 和 1，**后面每一个数都是前面两个相加**。

0、1、1、2、3、5、8、13……

自己咬自己尾巴的写法几乎是照抄这句话：

```cpp
#include <iostream>

int fib(int n) {
    if (n <= 1) {
        return n;
    }
    return fib(n - 1) + fib(n - 2);
}

int main() {
    for (int i = 0; i < 8; i++) {
        std::cout << fib(i) << " ";
    }
    std::cout << std::endl;
    return 0;
}
```

```text
0 1 1 2 3 5 8 13 
```

注意这句 `return fib(n - 1) + fib(n - 2);` —— **一次喊了两个自己**。这是允许的，一位喊两位、两位各喊四位，像树一样岔开。

**可这份好看是有代价的。** 本喵给这段程序加了个计数器，数了数它一共喊了多少次：

```cpp
#include <iostream>

int calls = 0;

int fib(int n) {
    calls = calls + 1;
    if (n <= 1) {
        return n;
    }
    return fib(n - 1) + fib(n - 2);
}

int main() {
    std::cout << "fib(6)=" << fib(6) << std::endl;
    std::cout << "一共喊了 " << calls << " 次招式" << std::endl;
    return 0;
}
```

```text
fib(6)=8
一共喊了 25 次招式
```

才算出 7 个数，招式被喊了 **25 次**。因为 `fib(4)` 会被算好几遍、`fib(3)` 更多遍 —— 同一道小题被反反复复重算，越往大数字越夸张。

这不是「写法错了」，是这套好看写法的**脾气**：省了代码，费了功夫。往后学到更省事的写法时，你会想起今天这 25 次喵。

## 六、招式得先打过招呼才能用

翻译官喵是从上往下读代码的。它在 `main` 里见到一个名字，如果**上面还没见过这个名字**，就会当场停下：

```cpp
#include <iostream>

int main() {
    std::cout << sum(3) << std::endl;
    return 0;
}

int sum(int n) {
    if (n == 0) {
        return 0;
    }
    return n + sum(n - 1);
}
```

```text
main.cpp:4:18: error: 'sum' was not declared in this scope
```

翻译官喵的原话是「`sum` 这个招式本喵没见过就先用上了」。**注意它不是说 `sum` 不能喊自己** —— 招式在自己的身体里喊自己，名字早就登记好了，不算没见过。它卡住的是 `main` 喊它这一次。

改法很朴素：把招式整个搬到 `main` 前面去，或者只在 `main` 前面先写一行「招牌」—— 只报名字和形状、不带身体，比如 `int sum(int n);`，那样招式本身留在后面也认得。**自己咬自己尾巴，和「先打招呼」是两件事，别混喵。**

## 七、自己咬尾巴，还是绕圈跑？

同一件事，绕圈跑（用 `for` 挨个走一遍）往往也能干，而且**更快、更省地方**：不用一层层喊自己，也就没有那一摞碗要摞。

那为什么还要有自己咬自己尾巴这套写法？因为有些题**用「小一圈的同一道题」讲起来最顺** —— 像斐波那契那样，一句话就说清了它是什么。两种写法都收在工具箱里，用哪把看你顺手喵。

::: tip 猫咪提示
今天收五句话：

1. **自己咬自己尾巴的招式 = 在自己的身体里再喊一次自己。**
2. **基线条件就是刹车**，而且必须「轮得到」并且「每步都更靠近它」。
3. **每一位都有自己的一份东西**，回来之后还在。
4. **一次可以喊好几个自己**，但要注意重复计算（`fib(6)` 被喊了 25 次那件事）。
5. **招式要先打过招呼才能被别人喊** —— 这和它能不能喊自己是两码事。
:::

## 小任务

2. 写一个招式，算出「第 `n` 摞碗有几个」：仿照钩子里那个数法，一摞碗的数量减一，刹车的条件是「一个都不剩」。
3. 先猜再跑：把第四节的 `if (n == 0)` 改成 `if (n == 1)`，`fact(5)` 会印出什么？先写下你的猜测，再真跑一次对照，想清楚**为什么**它会算错。
4. 先猜再跑：把第五节的 `fib(6)` 换成 `fib(4)`，计数器会报多少？猜完再跑，然后想想这个数是怎么涨上去的。
