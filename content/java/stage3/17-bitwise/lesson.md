## 钩子：只有两格水的格子

`common-03` 里那口鱼塘，本喵再舀一瓢出来看：水深只有两档 —— **满**和**空**，写成数字就是 `1` 和 `0`。8 个格子捆成一排，一共能排出 256 种花样。

那一课讲的是「这一排整体是多少」；今天本喵要干的是另一件事：**不看整体，一位一位地下手**。想干的活儿就四样：

- 把某几格**关掉**，别的格一格不动；
- 把某几格**点亮**，别的格一格不动；
- 把某几格**翻个面**（原来是 1 就变 0，反过来也一样）；
- 把整排**挪几格**，挪出去的就不要了。

四样活儿各有各的手法。而且 Java 这边还埋着三个坑：`int` 给的是 **32** 格不是 8 格、负数在格子里长得不像负数、还有一只**只此一家**的 `>>>`。今天一次讲清喵。

## 一、四只手指头：`&` `|` `^` `~`

先摆两排格子出来，本喵把四种手法各按一遍：

```java
public class Main {
    public static void main(String[] args) {
        int a = 0b11001010;
        int b = 0b10110110;

        System.out.println("a     = " + bits(a));
        System.out.println("b     = " + bits(b));
        System.out.println("a & b = " + bits(a & b));
        System.out.println("a | b = " + bits(a | b));
        System.out.println("a ^ b = " + bits(a ^ b));
        System.out.println("~a    = " + bits(~a));
    }

    static String bits(int n) {
        String s = Integer.toBinaryString(n & 0xFF);
        while (s.length() < 8) {
            s = "0" + s;
        }
        return s;
    }
}
```

```text
a     = 11001010
b     = 10110110
a & b = 10000010
a | b = 11111110
a ^ b = 01111100
~a    = 00110101
```

这四行是**一位一位对着看**出来的：每一位各算各的，绝不串门。规矩就四条：

- `a & b` —— 两边**都**是 1，才留 1。两位都满才满。
- `a | b` —— 有**一边**是 1，就留 1。有一位满就满。
- `a ^ b` —— 两位**不一样**才留 1。本喵管它叫「找不同」。
- `~a` —— 每一格都反过来。满变空、空变满。

拿上面这两排数逐位对一遍 `a & b`：最左边那格是 1 和 1，留 1；再往右一格是 1 和 0，变 0；再往右是 0 和 1，也变 0……八格问完，就是 `10000010`。`a | b` 反过来，只要有一边是 1 就写 1，所以只会越并越多。`a ^ b` 问的是「这两位一样吗」，一样写 0、不一样写 1。

`~a` 是**单只手**：它不用配对的另一个数，直接把每一格反过来。上面那行 `~a = 00110101` 是本喵**只画最右边 8 格**给你看的样子 —— 为什么要加这句限定，下一节就说喵。

::: warn 小心喵
`~` 和 `!` 长得像，干的活却完全不搭界。大肥鱼把 `~a` 写成了 `!a`（他以为那是「取反」），翻译官喵当场把稿子退回来：

```java
public class Main {
    public static void main(String[] args) {
        int a = 0b1100;
        System.out.println(!a);
    }
}
```

```text
Main.java:4: error: bad operand type int for unary operator '!'
        System.out.println(!a);
                           ^
1 error
```

念起来是：「`!` 只管**真假的答案**（`true` / `false`），这一格里装的是个整数，本喵不认。」`!` 是「不是」，`~` 才是「每一格反过来」—— 一个问真假，一个动格子喵。
:::

## 二、`int` 是 32 格，不是 8 格

上一节本喵只画了 8 格 —— 那是**为了给你看清楚**，不是 `int` 的真实尺寸。Java 的 `int` 一格不少，是 **32 格**。把 `~a` 的真实样子印出来：

```java
public class Main {
    public static void main(String[] args) {
        int a = 0b11001010;
        System.out.println("a 是多少：" + a);
        System.out.println("~a 是多少：" + ~a);
        System.out.println("~a 的格子：" + Integer.toBinaryString(~a));
        System.out.println("一共几位：" + Integer.toBinaryString(~a).length());
    }
}
```

```text
a 是多少：202
~a 是多少：-203
~a 的格子：11111111111111111111111100110101
一共几位：32
```

三件事一起看：

1. `0b11001010` 就是 **202** —— `0b` 打头的写法，`common-03` 里四门语言都认，它和写成十进制的 `202` 是同一样东西。
2. `~a` 不是「只剩 8 格」的数：它把 **32 格**全反过来。前头那 24 格原本全是 0，一取反全成了 1。
3. 结果印出来是 **-203**，一个负数。

最后那句 `一共几位：32` 是数出来的，不是本喵背的 —— 本喵拿 `Integer.toBinaryString(~a).length()` 当场量了一遍。为什么前头全是 1 就变成负数？这就是下一节的事喵。

::: tip 猫咪提示
`int` 是 32 格，`long` 是 64 格。这一课里凡是画 8 格的图，都是**只画最右边那 8 格**；真正的数比图长得多。想看真实的，用 `Integer.toBinaryString(n)` 印一下：正数只给「有意义的那几位」，负数会给满 32 位。
:::

## 三、负数在格子里长什么样

```java
public class Main {
    public static void main(String[] args) {
        for (int n : new int[] { 6, -6, 1, -1, 0 }) {
            System.out.println(n + " 的格子：" + Integer.toBinaryString(n));
        }
        System.out.println("6 每一位反过来再加一：" + (~6 + 1));
    }
}
```

```text
6 的格子：110
-6 的格子：11111111111111111111111111111010
1 的格子：1
-1 的格子：11111111111111111111111111111111
0 的格子：0
6 每一位反过来再加一：-6
```

念这几行：

- **正数**从最右边那格开始装，装不下了再往左扩 —— 所以 `6` 只占了 3 格，左边那些 0 在印的时候被省略掉了。
- **`-1` 是 32 格全满**。这不是巧合：`-1` 就是「`0` 再往回退一格」，往回退一步的算法是**每一位反过来、再加一** —— `0` 反过来是 32 个 0，加一就得 32 个 1（一路进位上去）。
- **`-6` 和 `6` 的关系**也是这一套：把 `6` 每一位反过来再加一，屏幕上印出来的就是 `-6`（最后一行真的算了一遍，没骗你）。

这套「每一位反过来、再加一」的规矩，正式名字叫**补码**（two's complement）。它白送一个好处：**加减法不用为负数另写一套**。有一条恒等式正好印证：`~n` 加上 `n` 永远等于 `-1`（每一位都反过来了嘛）—— 拿上面那两个数试：`-203 + 202 = -1`。

于是有三条结论，往后整节课都要用：

1. **最左边那一格是「符号格」**：它是 1，这个数就是负的。
2. **能装的范围对半分**：`int` 装得下 −2147483648 到 2147483647 —— 负数那一头比正数那多一格。
3. **32 格满了就往回绕**：`2147483647` 再加一，当场变成 `-2147483648`。

## 四、整体挪位置：`<<` 和 `>>`

```java
public class Main {
    public static void main(String[] args) {
        int a = 0b1011;
        System.out.println("a 是多少：" + a);
        System.out.println("a << 1：" + (a << 1));
        System.out.println("a << 2：" + (a << 2));
        System.out.println("-8 >> 1：" + (-8 >> 1));
        System.out.println("-8 >> 2：" + (-8 >> 2));
        System.out.println("-1 >> 1：" + (-1 >> 1));
    }
}
```

```text
a 是多少：11
a << 1：22
a << 2：44
-8 >> 1：-4
-8 >> 2：-2
-1 >> 1：-1
```

念这几行：

- `<<` 是**整体往左挪**，右边空出来的格子一律补 0。`a = 11`（格子是 `1011`）挪一格得 22，挪两格得 44 —— **每挪一格就是翻一倍**。挪到左端挤出去的那几格**不要了**。
- `>>` 是**整体往右挪**，右边挤出去的格子（也就是除法的余数）也不要了。`-8 >> 1` 得 `-4`，正好是 −8 ÷ 2；`-8 >> 2` 得 `-2`，正好是 −8 ÷ 4。
- 可 `>>` 在**左边补什么**，是要害：它补的是「**原来最左边那一格**」。正数最左边是 0，就补 0；负数最左边是 1，**于是一路补 1**。看最后一行：`-1 >> 1` 还是 `-1`，那 32 个 1 一格都没少。

## 五、Java 独一份：`>>>`

要是本喵**不管正负，左边空出来的一律补 0** 呢？那就要请出 `>>>` 这只手了：

```java
public class Main {
    public static void main(String[] args) {
        int n = -8;
        System.out.println("n 的格子：" + Integer.toBinaryString(n));
        System.out.println("n >> 1：" + (n >> 1) + "，格子：" + Integer.toBinaryString(n >> 1));
        System.out.println("n >>> 1：" + (n >>> 1) + "，格子：" + Integer.toBinaryString(n >>> 1));
        System.out.println("-1 >>> 1：" + (-1 >>> 1));
    }
}
```

```text
n 的格子：11111111111111111111111111111000
n >> 1：-4，格子：11111111111111111111111111111100
n >>> 1：2147483644，格子：1111111111111111111111111111100
-1 >>> 1：2147483647
```

两行对照着读，一眼就看出来了：

- `n >> 1` 往左边补了一个 **1**，所以格子还是 32 个 1 打头，数出来还是 **-4**。
- `n >>> 1` 往左边补了一个 **0**，原来顶在最左边那个 1 被挤出去了，数出来是 **2147483644** —— 一个很大的正数。

（第二行的格子比第一行短一格，是印的时候把前头的 0 省了，不是算错了。）

`-1 >>> 1` 更极端：32 个 1 挪一格、左边补 0，最左边那格从 1 变成 0，于是得到一个 **2147483647** 这个 `int` 能装的最大正数。

别的语言不一定有这只手：C 那边的 `>>` 对负数补什么，标准里**没写死**，留给各家的翻译官喵自己挑（想「一律补 0」得先声明成不带正负号的那种装法）；Python 那边的整数**没有固定格数**，想多长自己长，所以压根没有 `>>>` 这一手。这一节和 `c-stage3-02` 讲的是同一件事，那边用的是 C 的写法，可以对着看喵。

## 六、挪过头会绕回来

```java
public class Main {
    public static void main(String[] args) {
        System.out.println("1 << 30：" + (1 << 30));
        System.out.println("1 << 31：" + (1 << 31));
        System.out.println("1 << 32：" + (1 << 32));
        System.out.println("1 << 33：" + (1 << 33));
        System.out.println("2 << 62：" + (2 << 62));
    }
}
```

```text
1 << 30：1073741824
1 << 31：-2147483648
1 << 32：1
1 << 33：2
2 << 62：-2147483648
```

念这三件事：

- `1 << 31` 已经是能挪到的最左边那一格了。那一位是**符号格**，它一变成 1，这个数当场成了负的：`-2147483648`，也就是 `int` 能装的最小那个数。
- **`1 << 32` 不是 0，是 1**。为什么？因为 Java 只取挪动格数的**最低 5 位**（32 格用 5 位二进制就能表示 0~31 这些格号），`32` 的低 5 位是 `00000`，等于没挪；`33` 的低 5 位是 `00001`，等于挪一格。最后一行 `2 << 62` 也是同一回事：`62` 的低 5 位是 `11110`（30），`2 << 30` 正好落在符号格上。

::: warn 小心喵
**这是位运算里最贵的一个坑，而且它不报错。** 本喵写 `1 << 32`，大肥鱼写 `1 << 33`，屏幕上印出来的东西都「像那么回事」，只是全错。规矩记死：**`int` 的挪动格数只有 0 到 31 是有效的**（`long` 是 0 到 63）。想挪更多格，把数换成 `long` 那种装法，或者先问问自己到底想干什么喵。
:::

## 七、拿格子纸做手脚：最常用的四件事

把「**只有第 k 格是 1**」的那张纸先做出来（`1 << k`），再配不同的手，就是最常用的四件事：

```java
public class Main {
    public static void main(String[] args) {
        int n = 0b00001010;

        System.out.println("本喵手上这排：" + bits(n));
        System.out.println("第 0 位是 1 吗：" + ((n >> 0 & 1) == 1));
        System.out.println("第 6 位是 1 吗：" + ((n >> 6 & 1) == 1));
        System.out.println("点亮第 6 位：" + bits(n | (1 << 6)));
        System.out.println("关掉第 3 位：" + bits(n & ~(1 << 3)));
        System.out.println("翻转第 1 位：" + bits(n ^ (1 << 1)));
    }

    static String bits(int n) {
        String s = Integer.toBinaryString(n & 0xFF);
        while (s.length() < 8) {
            s = "0" + s;
        }
        return s;
    }
}
```

```text
本喵手上这排：00001010
第 0 位是 1 吗：false
第 6 位是 1 吗：false
点亮第 6 位：01001010
关掉第 3 位：00000010
翻转第 1 位：00001000
```

对应关系是这样的：

- **问第 k 格开不开**：`(n >> k & 1) == 1` —— 先把那一格挪到最右边，再和 1 比。
- **点亮第 k 格**：`n | (1 << k)` —— 有一位是 1 就是 1，别的格原样不动。
- **关掉第 k 格**：`n & ~(1 << k)` —— 格子纸先用 `~` 反过来，变成「只有这一格是 0、别处全是 1」，再盖上去。
- **翻转第 k 格**：`n ^ (1 << k)` —— 和 1 比「一样吗」，那一格必然翻面。

::: tip 猫咪提示
记一句就够：**`1 << k` 是「第 k 格是 1」的那张纸，`~` 把它翻成「第 k 格是 0」的纸。** 想开灯就 `|`、想关灯就 `& ~`、想翻面就 `^` —— 三件事各配一只手。配错了照样跑得起来，只是白干一趟，所以下手前先想清楚要的是哪一件喵。
:::
