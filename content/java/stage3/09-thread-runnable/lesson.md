## 钩子：本喵一个人忙不过来

到今天为止，本喵写过的每一段程序都是一条路走到底：一件事做完，下一件才开始。搬账本是这样，念文件也是这样。

可鱼塘大了就不一样：三个塘都要捞，本喵一个塘一个塘地捞，捞到天黑都捞不完。要是**再派两只猫出去**，三路一起动手，那就快多了。

这套本事在 Java 里就是「同时派好几只猫」：一只猫自己往下走，被派出去的猫自己也往下走，谁也不等谁。今天四件事：

1. 怎么**派一只猫**出去干活；
2. 派了两只之后，屏幕上**谁先说话**为什么说不准；
3. 怎么**站在门口等它们都回来**（收工前点人头）；
4. 另一种派法：不用新画图纸，直接把**一段活**交出去。

## 一、派一只猫：`Thread`

先看一只猫是怎么派出去的：

```java
public class Main {
    public static void main(String[] args) throws Exception {
        Cat 一只 = new Cat("小橘");

        一只.start();
        一只.join();

        System.out.println("本喵这边接着干活");
    }
}

class Cat extends Thread {
    String 名字;

    Cat(String 名字) {
        this.名字 = 名字;
    }

    public void run() {
        System.out.println(名字 + "捞到一条");
    }
}
```

```text
小橘捞到一条
本喵这边接着干活
```

三个动作，各管一件：

- **`class Cat extends Thread`** —— 图纸名字后面接上 `extends Thread`，读作「**照这张图纸长出来的，就是一只会干活的猫**」。`Thread` 是 Java 里「一路活」的家什，本喵不用自己造它，只要在图纸上多写一段：
- **`public void run()`** —— 这段里写的是「**这只猫要去干的那件活**」。本喵这只猫的活很简单：捞一条，印一行，干完自己就结束了。注意它**没有** `static`、也**不能少** `public` —— 它就是图纸上的一段活，写法是定死的。
- **`一只.start()`** —— 「派它出去开跑」。这一句一喊，本喵这条线继续往下走，被派出去的猫**自己也在往下走** —— 两路同时进行，这就是今天的全部魔法。

还有第四样，落在最后：

- **`一只.join()`** —— 「**站在这儿等它干完**」。本喵要是把这一句去掉，母猫很可能在猫还没印出那一行之前就跑到下面去了（「本喵这边接着干活」先冒出来）。要按次序印，就得等。

## 二、两只一起派：谁先说话，说不准

再看派两只：

```java
public class Main {
    public static void main(String[] args) throws Exception {
        Cat 甲 = new Cat("小橘");
        Cat 乙 = new Cat("狸花");

        甲.start();
        乙.start();

        甲.join();
        乙.join();

        System.out.println("两只都回来了");
    }
}

class Cat extends Thread {
    String 名字;

    Cat(String 名字) {
        this.名字 = 名字;
    }

    public void run() {
        System.out.println(名字 + "捞到一条");
    }
}
```

这两句 `println` 的**先后，本喵不写给你** —— 因为写不了。

本喵自己连跑了五趟：其中两趟是狸花那一行先冒出来，另外三趟是小橘先冒出来。同一份代码、同一台机器，先后就是这么飘。原因不神秘：`start()` 只负责「把它派出去」，派出去之后，两只猫**各自**往下走，谁先跑到印那一句，看机器当时先轮到谁。

::: warn 小心喵

**这一节的输出本喵一个字都没写。** 这不是偷懒 —— 一份代码要是今天印这个次序、明天印那个次序，那**任何写死的次序都是假的**。往后你也会遇到这种程序：**它跑得对，只是先后不由你定**。

有一点可以放心：本喵这两只猫各自只印**一整行**，所以不会出现「小橘狸花」这种粘在一起的怪行。飘的只是**行与行之间**的先后。

:::

## 三、等它们都回来：`join()` 和各自的小格子

更常见的情形是：好几只猫各自干活，母猫**等它们都回来**再汇总。这时候每一只都得有自己的**小格子**记账：

```java
public class Main {
    public static void main(String[] args) throws Exception {
        Cat 甲 = new Cat("小橘");
        Cat 乙 = new Cat("狸花");

        甲.start();
        乙.start();

        甲.join();
        乙.join();

        System.out.println(甲.名字 + "捞到：" + 甲.捞到 + " 条");
        System.out.println(乙.名字 + "捞到：" + 乙.捞到 + " 条");
        System.out.println("一共：" + (甲.捞到 + 乙.捞到) + " 条");
    }
}

class Cat extends Thread {
    String 名字;
    int 捞到 = 0;

    Cat(String 名字) {
        this.名字 = 名字;
    }

    public void run() {
        for (int i = 0; i < 3; i++) {
            捞到 = 捞到 + 1;
        }
    }
}
```

```text
小橘捞到：3 条
狸花捞到：3 条
一共：6 条
```

这一份的次序是**稳的**，因为两处都做了安排：

- **每只猫记在「图纸上的那一格」里。** `捞到` 画在图纸上，所以**每一只猫都有一份自己的 `捞到`**：小橘那只数它的三下，狸花那只数它的三下，互不干扰。汇总的时候母猫问的是「小橘那一只猫的格子」和「狸花那一只猫的格子」，两份都对得上。
- **汇总之前先 `join()`。** 两句 `甲.join(); 乙.join();` 就是「站门口等它俩都回来」。要是把这两句挪到印汇总的后面去，母猫可能在两只猫数完之前就报数 —— 那就是另一回事了。

## 四、另一种派法：把**一段活**交给一只猫

上一节是「新画一张图纸，图纸本身就是一只会跑的猫」。还有另一种派法：**不用新画猫的图纸，把一段活交给一只现成的猫**。

先说那段活长什么样 —— 它也是一张图纸，只是这张图纸上没有别的，只有一段 `run()`：

```java
public class Main {
    public static void main(String[] args) throws Exception {
        Thread 一只 = new Thread(new FishJob("小橘"));

        一只.start();
        一只.join();

        System.out.println("家什收好了");
    }
}

class FishJob implements Runnable {
    String 名字;

    FishJob(String 名字) {
        this.名字 = 名字;
    }

    public void run() {
        System.out.println(名字 + "这一趟捞完了");
    }
}
```

```text
小橘这一趟捞完了
家什收好了
```

对照着看，两种派法的差别只有一处：

| | 图纸上写的 | 派出去的那一句 |
|---|---|---|
| 第一种 | `class Cat extends Thread` | `new Cat("小橘").start()` |
| 第二种 | `class FishJob implements Runnable` | `new Thread(new FishJob("小橘")).start()` |

- 第一种是「**猫的图纸**」：图纸名字后面接 `extends Thread`，长出来的就是一只猫。
- 第二种是「**活的图纸**」：图纸名字后面接 `implements Runnable`，读作「这张图纸写的是**一段可以交给猫去干的活**」；它自己不会跑，得**塞给一只猫**（`new Thread(那张活的图纸)`），那只猫才有名字、才能 `start()`。
- 两种派法里，那段活**都叫 `run()`**、都得是 `public void` —— 这一点是共通的。

什么时候用哪种？**只想干一段活、不打算给它记别的**，第二种更省事（不用为一段活特意画一张猫的图纸）；**这只猫身上还要带点它自己的东西**（比如本喵这里要给每只猫记一个名字、记一个 `捞到`），第一种写起来更顺手。

## 五、自己动手，和派一只猫，是两件事

`run()` 和 `start()` 长得像，干的事差得远。本喵真跑给你看 —— 这一份**故意**喊的是 `run()`：

```java
public class Main {
    public static void main(String[] args) {
        Cat 一只 = new Cat("小橘");

        一只.run();
        System.out.println(Thread.currentThread().getName() + "：本喵这边也在干活");
    }
}

class Cat extends Thread {
    String 名字;

    Cat(String 名字) {
        this.名字 = 名字;
    }

    public void run() {
        System.out.println(Thread.currentThread().getName() + "：在捞鱼");
    }
}
```

```text
main：在捞鱼
main：本喵这边也在干活
```

两行**都是 `main`**。`Thread.currentThread().getName()` 问的是「**现在这一句是谁在干**」，答出来的是那路活的名字 —— 本喵自己这一路叫 `main`。两行都是它，说明**根本没有猫被派出去**：那句 `一只.run()` 只是「母猫照着那张图纸，自己动手把这段活干了」。

把那一句换成 `start()`，同一段活就是猫在干了：

```java
public class Main {
    public static void main(String[] args) throws Exception {
        Cat 一只 = new Cat("小橘");

        一只.start();
        一只.join();

        System.out.println("本喵这边接着干活");
    }
}

class Cat extends Thread {
    String 名字;

    Cat(String 名字) {
        this.名字 = 名字;
    }

    public void run() {
        System.out.println(Thread.currentThread().getName() + "：在捞鱼");
    }
}
```

```text
Thread-0：在捞鱼
本喵这边接着干活
```

第一行变成了 `Thread-0` —— 这是机器给第一只派出去的猫起的名字，看到它就说明**这一行真的是一只猫在干**。

记住这一条：**`run()` 是「这段活本身」，`start()` 才是「派一只猫去干这段活」。** 直接喊 `run()` 不红不响、活也真干了，只是**没多出一路** —— 往后想同时干活却发现「怎么还是串着的」，多半就是这一脚。

## 六、同一只猫，不许派两次

一只猫只有一辈子。派出去、干完，它就结束了：

```java
public class Main {
    public static void main(String[] args) throws Exception {
        Thread 一只 = new Thread(new FishJob("小橘"));

        一只.start();
        一只.join();
        一只.start();

        System.out.println("这边还在往下走");
    }
}

class FishJob implements Runnable {
    String 名字;

    FishJob(String 名字) {
        this.名字 = 名字;
    }

    public void run() {
        System.out.println(名字 + "这一趟捞完了");
    }
}
```

```text
小橘这一趟捞完了
Exception in thread "main" java.lang.IllegalThreadStateException
```

读作：**「这只猫的状态不对，不许再派」**。第一趟干得好好地印了一行，第二句 `start()` 当场翻脸 —— 因为它已经**干完结束了**，一只结束了的猫不能重新开跑。

想再干一趟，就得**另派一只**：`new Cat("小橘").start()` 是你的事，别指望叫醒同一只。

顺一遍今天这只猫的一生：

| 时候 | 它是什么状态 | 本喵做的事 |
|---|---|---|
| `new Cat("小橘")` | 刚画出来，还没动 | 递名字 |
| `一只.start()` | 出去干活了 | 派它走 |
| `run()` 跑完 | 干完，结束了 | —— |
| `一只.join()` | 结束了 | 站门口等它回来 |

::: tip 猫咪提示

1. **书上管这套叫「多线程」**：好几路活同时往前走。本喵这边就说「同时派好几只猫」。
2. **`run()` 写活，`start()` 派猫**，两个不能换着用。
3. **要按次序印东西、要汇总，就得先把猫 `join()` 回来。** 不 join 就直接汇总，汇总里可能少几只猫干的活。
4. **每只猫的东西要放在图纸的格子里**（`名字`、`捞到`），这样每只猫各有一份；放在母猫那边一路共用的地方就不一样了。
5. **猫干了多少活，机器说了算。** 两只猫谁先谁后、谁先印，本喵写不了保证书。

:::

| `class FishJob implements Runnable` | 画一张「一段活」的图纸 |
| `public void run()` | 图纸上那段活本身 |
| `一只.start()` | 派一只猫出去开跑 |
| `一只.join()` | 站门口等它干完再往下走 |
| `一只.run()` | 母猫自己动手干那段活（**没派猫**） |
| `new Thread(一段活)` | 把一段活塞给一只猫 |
| `Thread.currentThread().getName()` | 问「现在这一句是谁在干」 |
| 同一只猫第二次 `start()` | 当场红：`IllegalThreadStateException` |

## 小任务

1. 把第一节那只猫原样跑一遍，再把 `join()` 那一句去掉跑一遍 —— 看看「本喵这边接着干活」是不是跑到前面去了（多跑几趟，感受一下）。
2. 第二节那两只猫多跑几趟，数一数小橘先冒头几趟、狸花先冒头几趟 —— 亲眼确认「说不准」是什么意思。
3. 第三节那份改成三只猫：图纸不用动，多生一只、多 `join` 一次、汇总多问一格。
4. 第五节那个 `run()` 的版本，把 `Thread.currentThread().getName()` 换成把这一行直接写死成 `"小橘"` —— 想想为什么这么一改，这个坑就更难发现了。
5. 第六节那个坑，改成「另派一只新猫」再跑一遍 —— 确认第二趟干活的是一只**新**猫（名字会变成 `Thread-1` 或者别的，看机器给它起什么）。
