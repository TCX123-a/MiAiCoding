## 钩子：同一个坑，前辈猫早就踩过

本喵前些日子收拾旧本子，翻出一段半年前写的账。当时为了「全窝只用一只猫粮碗」这件事，本喵折腾了一整个下午：改了七八处，改完还漏了两处 —— 第二天早上，另一处的猫往碗里添了鱼干，本喵这边去看，碗还是空的。

上礼拜本喵在隔壁猫的本子里，看见了**一模一样的麻烦**：她也改了七八处，也漏了两处，也对着空碗发了一早上呆。

这事让本喵琢磨明白一件不小的事：**有些麻烦不是本喵一个人的**。是猫都会撞上。前辈猫们撞完、疼完，把管用的摆法记了下来，还各自起了名字，好让后辈一句「这用某某摆法」就能说清。

这种记下来的摆法，正式名字叫**设计模式（前辈猫的套路）**，往后本喵只说**套路**两个字喵。

先把一条岔路堵上：**套路不是代码，是摆法。** 它讲的是「这块该谁管、那块该谁管、谁该不认识谁」—— 同一个套路，可以写成十行，也可以写成两百行，长得完全不一样。所以这一课的三段代码，你要看的是**谁手里攥着什么**，不是那几个字怎么写。

## 一、套路一：全窝只有一只的那件东西

**麻烦长这样：** 本喵的窝里其实只有**一只**猫粮碗。可谁想用碗，就在自己那一处写一句「造一只碗」—— 三处写了三句，就造出三只碗。三只碗各记各的存量：本喵往自己这只里添了五条鱼干，另一处去看还是空的。

**摆法：** 让「拿这只碗」这件事**怎么喊都只给同一只**。

```java
public class Main {
    public static void main(String[] args) {
        猫粮碗 甲 = 猫粮碗.拿碗();
        猫粮碗 乙 = 猫粮碗.拿碗();
        甲.存量 = 甲.存量 + 5;
        System.out.println("是同一只碗吗：" + (甲 == 乙));
        System.out.println("乙 里看到的存量：" + 乙.存量);
    }
}

class 猫粮碗 {
    private static 猫粮碗 唯一的一只;

    int 存量;

    private 猫粮碗() {
    }

    static 猫粮碗 拿碗() {
        if (唯一的一只 == null) {
            唯一的一只 = new 猫粮碗();
        }
        return 唯一的一只;
    }
}
```

```text
是同一只碗吗：true
乙 里看到的存量：5
```

拆开看，这段摆法就三样东西：

- **`private static 猫粮碗 唯一的一只;`** 是写在**图纸上**的一格。`static` 那句的意思是「这一格归图纸自己，不归哪只真猫」—— 所以它是全窝**共用**的那一格，本喵把唯一那只是不是已经造出来了记在这儿。
- **`private 猫粮碗()`** 是把**产房锁上**。别人想自己造一只？翻译官喵这一关就过不去：

```java
public class Main {
    public static void main(String[] args) {
        猫粮碗 碗 = new 猫粮碗();
        System.out.println("造出来了：" + 碗.存量);
    }
}

class 猫粮碗 {
    private static 猫粮碗 唯一的一只;

    int 存量;

    private 猫粮碗() {
    }

    static 猫粮碗 拿碗() {
        if (唯一的一只 == null) {
            唯一的一只 = new 猫粮碗();
        }
        return 唯一的一只;
    }
}
```

```text
Main.java:3: error: 猫粮碗() has private access in 猫粮碗
```

- **`static 猫粮碗 拿碗()`** 才是门口那个口子。它的心思只有一句：**图纸那一格还空着，就造一只、造完顺手记进去；已经记着了，就直接把那一只递出去。** 所以 `甲` 和 `乙` 拿到的是**同一只**碗 —— 往里添五条鱼干，两边看都是五条。`甲 == 乙` 那句问的就是「是不是同一只」，答 `true`。

> **猫在院里踩的坑：画在 `Main` 里面的图纸，锁不住自己人。**
> 本喵头一回演示「不许自己造」，是把 `猫粮碗` 画在 `Main` **里面**的 —— 结果 `new 猫粮碗()` 居然**放行了**。原因跟第 16 课那个盖子是同一条：画在自己身上的图纸，自己人够得着。想演示「被拦下来」，得把两张图纸**平着摆**（像上面这样：一张 `Main`、一张 `猫粮碗`），谁都够不着谁的口袋。

还有第二种摆法：**一上来就造好**，不等谁来喊。

```java
public class Main {
    public static void main(String[] args) {
        猫粮碗 甲 = 猫粮碗.拿碗();
        猫粮碗 乙 = 猫粮碗.拿碗();
        System.out.println("是同一只碗吗：" + (甲 == 乙));
    }
}

class 猫粮碗 {
    private static final 猫粮碗 唯一的一只 = new 猫粮碗();

    int 存量;

    private 猫粮碗() {
    }

    static 猫粮碗 拿碗() {
        return 唯一的一只;
    }
}
```

```text
是同一只碗吗：true
```

那一格直接写死成 `new 猫粮碗()`，拿碗的时候连判都不用判，直接递出去。两种摆法都对：前一种是**用到才造**，后一种是**一上来就造好**。规矩少的窝用后一种更省事；那只碗造起来很贵（比如要连一趟远处鱼塘）的时候，用前一种更划算喵。

这个套路的正式名字叫**单例** —— 一窝只留一例。什么时候值得这么摆：全窝**真的只有一份**的东西 —— 一份共用的设置、一个连远处鱼塘的口子、一本账。什么时候**别**这么摆：只要本喵自己都说不清「为什么只能有一只」，那就别硬凑 —— 造两只碗不会塌天喵。

## 二、套路二：领养处

**麻烦长这样：** 来领猫的猫，其实**不关心**自己领的是橘猫还是狸花猫 —— 她只想知道「我要一只猫」。可她得亲手写下品种的名字、还得知道新品种是怎么造出来的。哪天窝里多一个品种，她那段代码就得跟着改。

**摆法：** 开一间**领养处**。来领猫的只报一句「要什么样的」，剩下的事领养处自己掂量。

```java
public class Main {
    static abstract class 小猫 {
        abstract String 叫声();
    }

    static class 橘猫 extends 小猫 {
        @Override
        String 叫声() {
            return "喵～";
        }
    }

    static class 狸花猫 extends 小猫 {
        @Override
        String 叫声() {
            return "喵嗷";
        }
    }

    static 小猫 领养一只(String 花色) {
        if (花色.equals("橘")) {
            return new 橘猫();
        }
        return new 狸花猫();
    }

    public static void main(String[] args) {
        for (String 花色 : new String[]{"橘", "狸花", "花"}) {
            System.out.println(花色 + " -> " + 领养一只(花色).叫声());
        }
    }
}
```

```text
橘 -> 喵～
狸花 -> 喵嗷
花 -> 喵嗷
```

拆开看：

- **`领养一只(花色)`** 就是门口那间领养处。你报花色，它去后面挑一只递给你；你拿到手就能喊 `叫声()`，**从头到尾不知道**它是照哪张图纸生出来的。递回来的东西写在上一代那张图纸的名字上（`static 小猫 领养一只(...)`）—— 所有品种都是它的后辈，所以哪个都装得下。
- 好处落在**改一处**上：将来窝里添一个品种，改动只发生在**领养处这一处**；所有来领猫的地方一个字都不用动。
- 上面第三行「花」拿到的是狸花猫 —— 因为领养处只认「橘」这个字，别的都走最后那条兜底的路。**兜底给谁，你说了算**：想让它兜给橘猫，就把最后那句改成 `new 橘猫()`，别的都不用动喵。
- 这个套路的正式名字叫**工厂** —— 造东西的地方。别人不自己造，来这儿领。

## 三、套路三：摇铃与听众

**麻烦长这样：** 开饭要通知全窝的猫。要是摇铃那位手上**攥着一份名单**、还得挨个知道「小橘听见了会冲向碗、煤球听见了会先翻个身」，那每加一只猫，她手里那份名单和那一串「谁听见了会怎样」都得改。

**摆法：** 摇铃的**只管摇**，谁要听谁自己**订**上来。

```java
import java.util.ArrayList;
import java.util.List;

public class Main {
    interface 听众 {
        void 听见了(String 菜名);
    }

    static class 开饭铃 {
        List<听众> 名单 = new ArrayList<>();

        void 订上(听众 一位) {
            名单.add(一位);
        }

        void 摇铃(String 菜名) {
            for (听众 一位 : 名单) {
                一位.听见了(菜名);
            }
        }
    }

    static class 猫 implements 听众 {
        String 名字;

        猫(String 名字) {
            this.名字 = 名字;
        }

        public void 听见了(String 菜名) {
            System.out.println(名字 + " 冲向 " + 菜名);
        }
    }

    static class 懒猫 implements 听众 {
        String 名字;

        懒猫(String 名字) {
            this.名字 = 名字;
        }

        public void 听见了(String 菜名) {
            System.out.println(名字 + " 翻了个身，继续睡");
        }
    }

    public static void main(String[] args) {
        开饭铃 铃 = new 开饭铃();
        铃.订上(new 猫("小橘"));
        铃.订上(new 懒猫("煤球"));
        铃.摇铃("小鱼干");
        铃.摇铃("猫粮");
    }
}
```

```text
小橘 冲向 小鱼干
煤球 翻了个身，继续睡
小橘 冲向 猫粮
煤球 翻了个身，继续睡
```

拆开看：

- **`听众` 是一份约定**：说好会这一招的都算数。铃的名单里收的就是「会这一招的猫」（`List<听众> 名单`），所以它**不知道**名单上坐着的到底是猫还是懒猫。
- **`开饭铃` 只管两件事**：谁能订上（`订上`）、摇的时候挨个通知（`摇铃`）。它**不知道**每只猫听见了会做什么 —— 它只负责挨个喊一句 `听见了`，剩下的是每只猫自己的事。
- 这正是前辈猫那句「**一声开饭，各猫各样**」：同一句 `听见了` 喊出去，`猫` 冲过来了、`懒猫` 翻个身继续睡 —— **说好的那一招名字一样，各猫按自己的性子接**。你只管在每只猫自己的图纸上写它的接法（那两个 `implements 听众` 后面的写法，就是干这个的）。
- 好处还是**改一处**：明天要加一只三花猫，**铃那边一个字都不用改**，只要她自己也 `订上` 就行。
- 这个套路的正式名字叫**观察者** —— 一件东西动了，所有订上来的都跟着动。什么时候值得：一件事发生了，**有一个以上的地方要跟着动**，而且这些地方**将来还会增减**。人少又固定的时候，直接挨个喊名字反而更清楚喵。

## 四、套路怎么认、怎么用

三个套路长得差得远，可它们仨身上有个共同点：**都在把「改一处」变成现实。**

- 单例：想知道「哪儿有那只碗」，只有一处 —— 门口那个口子。
- 工厂：想添一个品种，只有一处 —— 领养处。
- 观察者：想加一个听众，只有一处 —— 她自己订上来那一下。

所以认套路的法子很简单：**看这段代码里，「将来要变的那件事」被关在了几个地方。** 关在一处，就是好摆法；散在七八处，就是本喵开头那段账。

还有三句实话得说在前头：

- **别为了用套路而用套路。** 只有一份的东西才叫单例；只造一个品种的地方，直接 `new` 反而更清楚。前辈猫记这些摆法，是为了**少疼几回**，不是为了让稿子看起来高级。
- **套路有名，但名字不是重点。** 本喵这一课只说了三个；往后你会在别人的本子里撞见更多名字。撞见的时候别急着记名字，先看**谁手里攥着什么、谁不认识谁** —— 看懂了那一层，名字自己就挂上去了。
- **这一课学的三个摆法，都是用来「少改几处」的。** 第 17 课那张纸条也一样（「这招过时了」一句话，全窝的猫都看得见）—— 前辈猫的套路和纸条是一路的：**把话留在一个地方，让别的猫自己来读**。

## 一句话小抄

| 本喵想干什么 | 摆法 |
| --- | --- |
| 全窝只留一只 | 图纸上留一格 `private static 猫粮碗 唯一的一只;` |
| 不许别人自己造 | 产房锁上：`private 猫粮碗()` |
| 用到才造 | `拿碗()` 里判一下空着没有，空着才 `new` |
| 一上来就造好 | 那一格直接写死 `private static final ... = new 猫粮碗();` |
| 别人不自己造、来领 | 一间 `static 小猫 领养一只(花色)`，报花色给东西 |
| 兜底给谁 | 领养处最后那一句 `return`，你说了算 |
| 谁要听谁自己订 | 铃里一个柜子 `List<听众> 名单`，`订上()` 塞进去 |
| 摇铃不知道细节 | 名单里只收「会那一招的猫」（那份约定），不写品种 |

::: tip 猫咪提示

- **套路不是代码，是摆法**：这一课要看的是「谁手里攥着什么、谁该不认识谁」，不是那几个字怎么写。
- **三个套路干的是同一件事**：把「将来要变的那件事」圈在一处 —— 单例圈在门口那个口子、工厂圈在领养处、观察者圈在「谁要听谁自己订」那一下。
- **摇铃的那位只管摇**：它不认识名单上坐的是谁，也不管各猫听见了会做什么。
- **别为了用套路而用套路**：只有一份的东西才叫单例，只造一个品种的地方直接造反而更清楚喵。
- **演示「不许自己造」的时候，两张图纸得平着摆** —— 画在自己身上的图纸，锁不住自己人。

:::

## 小任务

1. 给单例那口碗添一招 `void 添(int 几条)`，在两处各添一次，再清点一遍 —— 数对不对？再想想：要是本喵偷偷把产房那把锁去了，会出什么事（本喵试过：`new 猫粮碗()` 的画法在**平着摆**的图纸里是会被拦下的）。
2. 给领养处添一个品种（比如三花猫），数一数**总共改了几处**；再多喊几个花色去领，看看兜底那一支都给了谁。
3. 给观察者加一只「只记账、不出声」的听众（拿个柜子把菜名收着，摇完铃再一次性印出来），加完之后看**铃那一张图纸动没动**。
