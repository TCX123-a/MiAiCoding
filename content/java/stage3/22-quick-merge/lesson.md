## 钩子：一千只鱼干，憨办法顶不住了

上一课的三招本喵都学会了，可心里有个疙瘩：它们的力气都花在「两两比一比」上，鱼干一多，次数就按 **n 乘 n** 那个形状往上涨。本喵算给你看，一千多只鱼干的时候有多吓人：

```java
public class Main {
    public static void main(String[] args) {
        int n = 1024;
        int layers = 0;
        int size = n;
        while (size > 1) {
            size = size / 2;      /* 每次对半砍 */
            layers++;             /* 砍了几刀 */
        }
        System.out.println(n + " 只鱼干：憨办法要比 " + (n * (n - 1) / 2) + " 次，拆开办只比 " + (n * layers) + " 次");
    }
}
```

```text
1024 只鱼干：憨办法要比 523776 次，拆开办只比 10240 次
```

同样一摊鱼干，一个要五十多万次，一个只要一万次 —— 差了五十倍。差别不在爪子上，在**想法**上：这两招的老前辈想通了一件事 —— **一大摊不好办，那就拆成两小摊分头办，办完再合起来**。这个想法有个正经名字：**拆开分头办（分治）**。今天本喵教你按这个想法造出来的两招：尺子法和合并法喵 ✨

## 尺子法：挑一只当尺子，短的站左边

第一招的关键是随手挑一只鱼干当**尺子**（本喵挑最右边那只），然后把这一摊分成两拨：比尺子短的站尺子左边，比尺子长的站尺子右边。分完之后，尺子自己站到两拨中间 —— 它的位子就**定死了**，往后再也不用动它。

```java
public class Main {
    /* 把 [lo, hi] 这一段理好：挑最右边那只当尺子 */
    static <T extends Comparable<T>> void quick_sort(T[] fish, int lo, int hi) {
        if (lo >= hi) {
            return;                       /* 只剩一只、或者一只都没有，本来就是理好的 */
        }

        T ruler = fish[hi];
        int small = lo;                   /* 下一只「比尺子短」的鱼干该放哪儿 */

        for (int i = lo; i < hi; i++) {
            if (fish[i].compareTo(ruler) < 0) {
                T t = fish[i];
                fish[i] = fish[small];
                fish[small] = t;
                small++;
            }
        }

        T t = fish[small];                /* 把尺子换到分界线上 */
        fish[small] = fish[hi];
        fish[hi] = t;

        quick_sort(fish, lo, small - 1);  /* 比尺子短的那一半，照同样的办法再来一遍 */
        quick_sort(fish, small + 1, hi);  /* 比尺子长的那一半 */
    }

    public static void main(String[] args) {
        Integer[] fish = {5, 2, 9, 1, 7, 3};
        quick_sort(fish, 0, fish.length - 1);
        System.out.print("尺子法：");
        for (int i = 0; i < fish.length; i++) {
            System.out.print(fish[i] + " ");
        }
        System.out.println();
    }
}
```

```text
尺子法：1 2 3 5 7 9
```

三处值得多念两遍喵：

1. **`small` 是「下一只短的该放哪儿」**：扫一圈，遇到比尺子短的，就把它换到 `small` 那个位子上，然后 `small` 往后挪一格。扫完之后，`small` 左边全是短的、右边（到尺子前）全是长的 —— 这条分界线就是这么攒出来的。
2. **尺子最后才换过去**：扫完再把尺子和 `fish[small]` 换个位子。这时候尺子才真正站在两拨中间，位子定死。
3. **左右两半各自再来一遍** —— 这就是自己咬自己尾巴的招式：招式里又喊了自己两次，只不过任务一次比一次小，小到只剩一只就收手（`lo >= hi` 那一句）。注意这排碗从头到尾只递过一张猫爪指向牌，**没有抄过任何一份**：拆出来的两半是**同一排碗**上的两段，靠 `lo`、`hi` 两个门牌号划开。

::: warn 小心喵
尺子挑得好不好，差别很大喵。要是每回挑中的尺子**正好是这一摊里最短或最长的**，那分出来的两拨就是一拨空、一拨只少一只 —— 白拆了，力气跟憨办法差不多。所以「随手挑最右边那只」只是最省事的挑法，讲究的做法会挑中间那只、或者随手挑一只再换过去。零基础阶段先记住：**尺子别老是挑到最大最小**就行喵。
:::

## 合并法：拆到底，再一层层合起来

第二招换个方向干：不去「边拆边站队」，而是**先对半拆、拆到没法再拆，再一层层合回去**。拆到只剩一只，那一只本身就整齐了 —— 这是它的收手条件。合的时候才是真功夫：两段都是理好的，那就**各看头一只，短的先出**，出完再比下一只。

```java
import java.util.ArrayList;

public class Main {
    /* 合：把已经理好的两段 [lo, mid] 和 [mid+1, hi] 并成一段 */
    static <T extends Comparable<T>> void merge(T[] fish, int lo, int mid, int hi) {
        ArrayList<T> tmp = new ArrayList<>();   /* 临时仓库：不用先量长度，它自己会长 */
        int i = lo;                   /* 左边那段的头 */
        int j = mid + 1;              /* 右边那段的头 */

        while (i <= mid && j <= hi) {
            if (fish[i].compareTo(fish[j]) <= 0) {
                tmp.add(fish[i++]);     /* 谁短谁先出 */
            } else {
                tmp.add(fish[j++]);
            }
        }
        while (i <= mid) {
            tmp.add(fish[i++]);         /* 左边还有剩的，接着出 */
        }
        while (j <= hi) {
            tmp.add(fish[j++]);         /* 右边还有剩的，接着出 */
        }
        for (int t = 0; t < tmp.size(); t++) {
            fish[lo + t] = tmp.get(t);  /* 搬回原来的摊子上 */
        }
    }

    /* 对半拆到底，再一层层合起来 */
    static <T extends Comparable<T>> void merge_sort(T[] fish, int lo, int hi) {
        if (lo >= hi) {
            return;                       /* 只剩一只，本身就是理好的 */
        }
        int mid = (lo + hi) / 2;
        merge_sort(fish, lo, mid);
        merge_sort(fish, mid + 1, hi);
        merge(fish, lo, mid, hi);
    }

    public static void main(String[] args) {
        Integer[] fish = {5, 2, 9, 1, 7, 3};
        merge_sort(fish, 0, fish.length - 1);
        System.out.print("合并法：");
        for (int i = 0; i < fish.length; i++) {
            System.out.print(fish[i] + " ");
        }
        System.out.println();
    }
}
```

```text
合并法：1 2 3 5 7 9
```

最后那个搬回去的圈**不能省**喵 —— 两段是在 `tmp` 里合好的，不搬回来，原来那摊还是老样子（这正是下一课「改错题」里最爱考的坑）。另外两次 `while` 的收尾也别省：比赛结束时，总有一段会先出完，另一段剩下的都直接跟上就行。

## 为什么它俩比憨办法快这么多

关键在**拆的层数**。一摊鱼干对半拆、再对半拆，拆到只剩一只要走多少刀？1024 只走 10 刀，2048 只才走 11 刀 —— 鱼干翻一倍，只多走一刀。这个「翻倍只加一」的涨法，比 n 乘 n 那个涨法慢太多啦。

而每一刀前后，本喵都得把这摊鱼干**扫一遍**（尺子法扫一遍分两拨、合并法扫一遍合一段）。所以总的力气大约是：

```text
一共要花的力气 ≈ 鱼干只数 × 拆的层数
```

1024 只鱼干就是 1024 乘 10，一万次上下；憨办法是五十多万次。这就是为什么两招老前辈都叫「高级」：**它们把一个 n 乘 n 的活，换成了一个 n 乘「层数」的活**喵。

## 什么时候用哪一招

| 办法 | 它的脾气 | 什么时候喊它 |
|---|---|---|
| 尺子法 | 拆得快、不用另租仓库；但尺子挑得不好会变慢 | 摊子大、乱，想要原地动手的时候 |
| 合并法 | 稳定（两只一样长时先来后到不变）；但要临时租一段仓库 | 要求「一样长也得保持原来次序」的时候 |

本喵说「稳定」是指：两只鱼干一样长，合并法保证原来站前面的合完之后还在前面；尺子法在换位子的时候，就有可能把两只一样长的**换了次序**。这个差别平时看不出来，可要是每条鱼干上还挂着一个「谁是先来的」的记号，那它就很要命了喵。

::: tip 猫咪提示
今天记住三句话：**拆开分头办** = 一大摊拆成两小摊、办完再合；**尺子法** = 挑只尺子、短的站左边、尺子站中间；**合并法** = 拆到只剩一只，再一层层「谁短谁先出」。两招都比憨办法快，因为它们的力气是「只数乘层数」，不是「只数乘只数」喵。

写给学过 C 的猫：这两招在 C 里还要自己备一段 `int tmp[64]` 当仓库、再拿一个 `k` 记着放到第几格了。Java 这两样都能省 —— `ArrayList` 就是那只**会自己长大的储物柜**，`tmp.add()` 放一只、它自己长一格，你不用管它现在多长。为什么不用定长的一排碗当仓库？招式写成那张**会量体裁衣的图纸（泛型）**之后，定长的一排碗在 Java 里得写成 `(T[]) new Comparable[...]` 那种带警告的绕口样子；会自己长大的储物柜才是 Java 里最顺手的写法，也正好和 C++ 的 `std::vector` 那一版对上喵。

顺便说一句：这两课的活 Java 都有**现成的招式**替你干 —— 排排坐有 `Arrays.sort`、`Collections.sort`，接过来一行就完事。今天先自己动手写一遍，才看得懂它们替你做了什么喵。
:::
