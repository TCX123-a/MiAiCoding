## 钩子：改了半行，鱼干分错了

本喵有一招「平分小鱼干」：捞起一堆小鱼干，按猫头数分下去，除不尽的先放着。这招稳稳当当用了小半年。

前天本喵顺手把里面的一行改了改，看着挺顺眼。结果今天分给三只猫的时候，每只猫面前多出了一条 —— 猫都愣住了，本喵也愣住了。

毛病不在那一行改得多难，在于**改完以后没人复查**。本喵当时确实瞄了一眼，可让眼睛盯着代码找毛病，跟让猫盯着一盘小鱼干不许动一样不靠谱。

有没有办法让**招式自己报告自己坏没坏**？有喵 —— 这就是今天这一课：给招式**定期体检**。

（Python 那条线上本喵已经带你体检过一回了，那会儿用的是 Python 自带的一套体检盒子。今天换成 Java：本喵**不装任何东西**，用手搓的一只小台子把同一件事做出来。手搓一遍，你才知道那套盒子替你干了多少活。）

## 一、体检的内核：四句话

把体检这件事剥到最里面，就剩四句：

1. **隔离**：一次只盯一个招式。别的招式、键盘输入、外面的文件都不许掺进来 —— 掺进来的东西一变，红了你也说不清是谁的错。
2. **把「我以为」写成「必须」**：六条鱼干分给两只猫，本喵**以为**是三条。那就把这个「以为」写下来，写成一句机器能判真假的话：`平分(6, 2)` 必须等于 `3`。这句「必须等于」，正式的名字叫**断言**。
3. **可重复**：今天跑是这样，明天跑还是这样。它不许看时间、不许看运气、不许看本喵今天心情好不好。
4. **红了要能定位**：不能只说一声「坏了」，得说清**是哪一条**坏了、叼回来的和该是的各是多少。

这套东西的正式名字是 单元测试（给招式定期体检）—— 名字里那个「单元」说的正是上面第 1 条：一次只盯一个。往后本喵只说「体检」两个字，你脑袋里要自动把它翻译成「让招式自己报告自己对不对」喵。

## 二、手搓一只体检台

先把「全绿」长什么样看清楚。下面这段是**完整的、直接能跑**的程序：一招「平分小鱼干」，加一只极简的体检台。

```java
public class Main {
    static int 查了几项 = 0;
    static int 红了几项 = 0;

    static void 查相等(String 名字, int 叼回来, int 该是) {
        查了几项++;
        if (叼回来 == 该是) {
            System.out.println("绿 " + 名字);
        } else {
            红了几项++;
            System.out.println("红 " + 名字 + "：叼回来 " + 叼回来 + "，该是 " + 该是);
        }
    }

    static void 查接近(String 名字, double 叼回来, double 该是) {
        查了几项++;
        if (Math.abs(叼回来 - 该是) < 1e-9) {
            System.out.println("绿 " + 名字);
        } else {
            红了几项++;
            System.out.println("红 " + 名字 + "：叼回来 " + 叼回来 + "，该是 " + 该是);
        }
    }

    static int 平分(int 总数, int 猫数) {
        return 总数 / 猫数;
    }

    public static void main(String[] args) {
        查相等("两只猫平分六条", 平分(6, 2), 3);
        查相等("除不尽时向下取整", 平分(7, 2), 3);
        查相等("一条都没有也分得动", 平分(0, 3), 0);
        查相等("只有一只猫，全都叼走", 平分(7, 1), 7);
        查相等("顶到上限的数", 平分(2147483647, 2), 1073741823);
        查接近("小数允许一点点误差", 0.1 + 0.2, 0.3);
        System.out.println("体检了 " + 查了几项 + " 项，红了 " + 红了几项 + " 项");
    }
}
```

```text
绿 两只猫平分六条
绿 除不尽时向下取整
绿 一条都没有也分得动
绿 只有一只猫，全都叼走
绿 顶到上限的数
绿 小数允许一点点误差
体检了 6 项，红了 0 项
```

跑它只有两条命令：先让翻译官喵翻一遍（`javac`），再把翻好的跑起来（`java`）—— 和前面每一课一样。

这只台子上就三样东西：

- **两只小碗**：`查了几项` 和 `红了几项`。它们从第一项跟到最后一项，谁也不用回头去数屏幕上的字。
- **两条判据招式**：`查相等` 收三样东西 —— 一个名字、一个「叼回来的」、一个「该是的」。相等就印一行「绿 …」；不等就印一行「红 …：叼回来 4，该是 3」。第 4 条内核「红了要能定位」，落的就是这一行。`查接近` 是给小数准备的，第四节说它为什么必须存在。
- **`main` 里那六句话**：一句就是一个体检项目。每一句念出来都是人话：`查相等("两只猫平分六条", 平分(6, 2), 3);` 读作「六条鱼干分给两只猫，这一招**必须**叼回三条」。

注意那一行左边的写法：`平分(6, 2)` 是**招式真的跑了一遍**叼回来的东西，`3` 是**本喵写死的**标准答案。判据从来不问「这个数看着像不像」，它只问「两边一样不一样」。这也是体检最值钱的地方 —— 它逼你把「该是多少」当场写下来，写错了立刻露馅。

::: tip 猫咪提示
项目名字起得越清楚，红了越省事喵。名字就是报告里念出来的那一行 —— 起成「第一项」，红了你还得翻回去数它排第几。
:::

## 三、把招式改坏一处

现在把**同一张体检单原封不动**地留着，只动招式里的一行 —— 把「向下取整」改成「向上取整」：

```java
public class Main {
    static int 查了几项 = 0;
    static int 红了几项 = 0;

    static void 查相等(String 名字, int 叼回来, int 该是) {
        查了几项++;
        if (叼回来 == 该是) {
            System.out.println("绿 " + 名字);
        } else {
            红了几项++;
            System.out.println("红 " + 名字 + "：叼回来 " + 叼回来 + "，该是 " + 该是);
        }
    }

    static void 查接近(String 名字, double 叼回来, double 该是) {
        查了几项++;
        if (Math.abs(叼回来 - 该是) < 1e-9) {
            System.out.println("绿 " + 名字);
        } else {
            红了几项++;
            System.out.println("红 " + 名字 + "：叼回来 " + 叼回来 + "，该是 " + 该是);
        }
    }

    static int 平分(int 总数, int 猫数) {
        return (总数 + 猫数 - 1) / 猫数;
    }

    public static void main(String[] args) {
        查相等("两只猫平分六条", 平分(6, 2), 3);
        查相等("除不尽时向下取整", 平分(7, 2), 3);
        查相等("一条都没有也分得动", 平分(0, 3), 0);
        查相等("只有一只猫，全都叼走", 平分(7, 1), 7);
        查相等("顶到上限的数", 平分(2147483647, 2), 1073741823);
        查接近("小数允许一点点误差", 0.1 + 0.2, 0.3);
        System.out.println("体检了 " + 查了几项 + " 项，红了 " + 红了几项 + " 项");
    }
}
```

```text
绿 两只猫平分六条
红 除不尽时向下取整：叼回来 4，该是 3
绿 一条都没有也分得动
绿 只有一只猫，全都叼走
红 顶到上限的数：叼回来 -1073741824，该是 1073741823
绿 小数允许一点点误差
体检了 6 项，红了 2 项
```

这一幕有三眼值得盯：

1. **红了的那两条，名字和数字都报出来了。** 「除不尽时向下取整：叼回来 4，该是 3」—— 哪一项出的问题、差了多少，一眼看完。这就是「红了要能定位」。
2. **绿着的那四条，这一处毛病一个都没咬住。** 比如最普通的那一项：六条分给两只猫，向上取整和向下取整**算出来一模一样**，所以它稳稳地绿着。要是这张单子上只有它，这个毛病会一路绿到学员手里 —— **咬住它的是「除不尽」这条边角料。**
3. **顺手还咬出第二条。** 顶上那个 `总数 + 猫数 - 1` 在 `2147483647` 这种大数上直接翻过了界，叼回来一个负数。**这一项是本喵特意挑上去的极值** —— 挑边角料的好处，就是它连你没打算抓的虫也一起抓。

::: warn 小心喵
红了以后，**第一件要改的永远是招式**。

本喵见过一只猫这么干：判据不过，就把「该是 3」改成「该是 4」，屏幕上立刻全绿。可这跟体温计读数不好看、就把温度计按进冰水里，是一码事 —— 病一点没好，只是量不出来了。

判据那一行写的是**你要的东西**，招式那一行才是**做出来的东西**。两边对不上时先问自己一句：本喵要的到底是什么？
:::

## 四、小数不能拿等号硬比

再看一段特别短的：

```java
public class Main {
    public static void main(String[] args) {
        double 甲 = 0.1;
        double 乙 = 0.2;
        System.out.println("两条加起来：" + (甲 + 乙));
        System.out.println("拿等号硬比：" + (甲 + 乙 == 0.3));
        System.out.println("允许一点点误差：" + (Math.abs(甲 + 乙 - 0.3) < 1e-9));
    }
}
```

```text
两条加起来：0.30000000000000004
拿等号硬比：false
允许一点点误差：true
```

`0.1 + 0.2` 不是 `0.3`。这不是 Java 的毛病，是**小数在机器里本来就存不成精确的比例**：`0.1` 和 `0.2` 都是近似存下来的，两条近似值加起来，末尾会多出一丁点。屏幕上那个 `0.30000000000000004` 就是那一丁点。

所以体检台上给小数准备的那条判据**不敢拿 `==` 去比**，它比的是「差得够不够小」：

> `Math.abs(叼回来 - 该是) < 1e-9`

`1e-9` 就是本喵允许的那一点点误差（十亿分之一）。两边差得比它还小，就当一样。`==` 问的是「一模一样吗」—— 对小数来说，这个问题的答案**几乎永远是「不」**；`Math.abs(…) < 1e-9` 问的是「近到可以当一样吗」，那才是你真正想问的。

::: tip 猫咪提示
凡是要比两个小数，先停一秒：**本喵允许的误差是多少？** 把它写下来，写成那句 `Math.abs(甲 - 乙) < 误差`。
:::

## 五、体检单要挑边角料

回头看第二节那张单子 —— 六项里只有第一项是「最正常的那种情况」，另外五项全是特意挑出来的边角料：

| 类别 | 单子上的那一行 | 它想咬住的毛病 |
|---|---|---|
| 除不尽 | `平分(7, 2)` 该是 `3` | 有余数时，取整取对了吗 |
| 空 | `平分(0, 3)` 该是 `0` | 一条鱼干都没有时会怎样，会不会叼回个负数 |
| 一个 | `平分(7, 1)` 该是 `7` | 只有一只猫，它该把全部叼走 |
| 极值 | `平分(2147483647, 2)` | 数顶到上限时，中间那一步加法会不会翻过界 |
| 小数 | `查接近(0.1 + 0.2, 0.3)` | 小数不能拿等号硬比，得给一点误差 |

本喵真跑过：那张单子上最普通的第一项，在两种写法下**都是绿的**；真正把毛病揪出来的是「除不尽」和「极值」两项。

所以给招式配判据的时候，顺序建议是这样：

1. 先写一条最普通的，确认它平时走得通；
2. 再补**空**：一份都没有的时候，它会不会当场炸；
3. 再补**一个**：只有一份的时候，它拿得对不对；
4. 最后补**极值**：数目顶到上限、或者大得离谱的时候，中间那几步还算不算得过来。

::: warn 小心喵
只写「正常情况」的体检单，等于没体检。

本喵第三节那一处改动，正是靠「除不尽」这一项才被揪出来的 —— 它在正常值上一点毛病都看不出来。**毛病最爱躲在边角料里**，因为那里平时没有猫去。
:::

## 六、翻译官喵退稿：招式忘了 `static`

体检台里有这么两行：

```java
static int 查了几项 = 0;
static int 红了几项 = 0;
```

要是把判据那条招式抄成下面这样（少了一个 `static`）：

```java
public class Main {
    static int 查了几项 = 0;

    void 查相等(String 名字, int 叼回来, int 该是) {
        查了几项++;
        System.out.println("查了 " + 名字);
    }

    public static void main(String[] args) {
        查相等("两只猫平分六条", 6 / 2, 3);
        System.out.println("体检了 " + 查了几项 + " 项");
    }
}
```

翻译官喵把稿子退了回来：

```text
Main.java:10: error: non-static method 查相等(String,int,int) cannot be referenced from a static context
```

它说的是：「`查相等` 是**挂在某一只猫身上**的招式；可 `main` 是这张图纸的**门口**，门口喊招式的时候，喊到的必须是**整张图纸共用**的那一份。」

`static` 就是「整张图纸共用」这四个字。体检台上的两只小碗、几条判据招式，都要被 `main` 从门口直接喊到，所以它们全得带上 `static`。补上这一个词，它就过去了。

::: tip 猫咪提示
这条报错是本喵特意留着给你看的喵 —— 第一次手搓体检台的人，十个里有九个会栽在它上面，而且那句 `cannot be referenced from a static context` 看着一点也不像人话。记住形状就行：**门口喊的招式要带 `static`**。
:::

## 七、再往前一步：构建工具在解决什么

到这里，「体检」这件事你已经会做了。最后再说一件更大的事。

本喵现在写一个 `Main.java`，跑它的动作就两条命令：先让翻译官喵翻一遍（`javac`），再把翻好的东西跑起来（`java`）。一个文件的时候，这么干一点问题都没有。

可一个真项目不是一只手数得过来的文件，它长这样：

- **要用别人写好的招式包**。几十个包，谁要谁、哪个包要哪个版本，手抄一张清单根本管不过来。这就是**依赖管理**：把「本喵要哪些包、各要什么版本」写成一张清单，工具照着把缺的取回来、顺手把版本对齐。
- **每天要按同一个次序干好几件事**：翻一遍 → 跑一遍体检 → 打包。这三步的次序是死的。**构建工具**把这条流水线写成一个名字，之后喊一声就跑完一整条。这叫**生命周期**。
- **干完要交出去**。一堆翻译好的东西得装进一个压缩包（`jar`），还要写清楚从哪张图纸的门口开始跑，别人才敢拿去用。这一步叫**打包**。

干这些活的前辈猫有两位，一位叫 `Maven`，一位叫 `Gradle`。它们解决的正是上面这三件事 —— 所以在真实项目里，体检不是本喵手动敲两条命令，而是**流水线上的第二站**：第一站翻代码，第二站跑体检，第三站打包；哪一站没过，后面的都不许走。

::: warn 小心喵
本喵这台机器上**没有**装 `Maven` 和 `Gradle`（它们不在手边，本喵也不会为了这一节让你去下载什么东西 —— 下载之前先确认安全，这是规矩）。

所以这一节**只看懂它们在解决什么问题，不动手跑**。你今天真正会用的，仍然是 `javac` 和 `java` 这两条命令；上面那只手搓的体检台，也照样跑得起来。等哪天你的项目大到需要它们了，你会很清楚自己在指望它们替你干哪三件事。

顺带说一句：真实项目里还有一套叫 `JUnit` 的专业体检台，它跟本喵手搓的这一只是**同一样东西** —— 一样是「喂进去知道的数，看叼回来的对不对」，只是报告更花哨、单子可以分成好几份放着。今天手搓一遍，就是为了你日后碰到它的时候，知道它替你干了什么。
:::

## 小任务

1. 先猜再跑：把第二节那段程序里的 `平分` 改成 `总数 / (猫数 + 1)`（多算了一只猫），猜猜哪几项会红，再真跑对照。
2. 给体检台加一条判据：`查相等("一只猫分顶格的数", 平分(2147483647, 1), 2147483647);` 先猜它是绿是红，再跑一遍，然后想想为什么这一条没被第三节那个毛病咬到。
3. 把 `查接近` 里的误差从 `1e-9` 改成 `0`，看小数那一项会怎样；再改成 `0.1`，然后想一想：误差放宽到这么大，还能抓住多大的错？
4. 从前几课的作业里挑一个你自己写过的招式，给它配三项体检：一个正常值、一个空、一个极值。
