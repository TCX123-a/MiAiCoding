## 钩子：把好几道活儿串成一条线

上一课那一小截直接写出来的招式，本喵是**当规矩递给别人用**的。今天换个用法：**把好几道活儿串成一条流水线** —— 从柜子头上接出来，中间挂上过筛子、加工几道，最后挂一道收尾，一口气把活干完。

这条线上的每一道，本喵写的都是上一课那种一小截；而**串起来**这件事本身，是今天新讲的东西。三件事：

1. 一条线**从哪儿接出来**；
2. 中间那几道挂上去的时候，为什么**一件东西都还没动**；
3. 什么时候这条线能干得比绕圈更省事。

## 一、一条线从哪来：从柜子头上接出来

```java
import java.util.ArrayList;
import java.util.List;
import java.util.stream.Collectors;

public class Main {
    public static void main(String[] args) {
        List<Integer> nums = new ArrayList<>();
        nums.add(3);
        nums.add(8);
        nums.add(1);
        nums.add(9);
        nums.add(4);

        List<Integer> big = nums.stream()
                .filter(n -> n >= 5)
                .map(n -> n * 10)
                .collect(Collectors.toList());

        System.out.println(big);
    }
}
```

```text
[80, 90]
```

一句一句念：

- **`.stream()`** —— 读作「从这只柜子**头上接一条线出来**」。注意它**不是在柜子上动手**，原柜子从头到尾一件都没变；
- **`.filter(n -> n >= 5)`** —— **过筛子**：只让够得上 5 的过去；
- **`.map(n -> n * 10)`** —— **加工**：过去的每一件都翻十倍；
- **`.collect(Collectors.toList())`** —— **收起来**：把流过来的一件件收成**一只新柜子**，叼回来。

每一道都**挂在上一道后面**，一路接着往下写。最后本喵**伸手接住了**叼回来的那只新柜子（用一只新柜子把它装起来），再印出来就是 `[80, 90]`：原来那五件里够得上 5 的是 8 和 9，翻十倍就是 80 和 90 喵。

这条线**是怎么流的**？本喵拆成一步一步，走给你看 —— 柜子里本来就装着 `3`、`8`、`1`、`9`、`4` 五件：

## 二、中间那几道挂上去的时候，一件都还没动

这条线有个很特别的脾气，得单独讲：

```java
import java.util.ArrayList;
import java.util.List;

public class Main {
    public static void main(String[] args) {
        List<Integer> nums = new ArrayList<>();
        nums.add(1);
        nums.add(2);
        nums.add(3);

        nums.stream().map(n -> {
            System.out.println("被加工了 " + n);
            return n * 2;
        });

        System.out.println("没挂收尾那一道，中间这几道一道都没跑");
    }
}
```

```text
没挂收尾那一道，中间这几道一道都没跑
```

那句「被加工了」**一次都没印出来**。

道理是这样：中间那两道（过筛子、加工）写下去的时候，**只是把「要做什么」登记在这条线身上** —— 一件东西都不会真的过。非得挂上**收尾那一道**（`collect`、`count`、`sum` 这种**要给你吐出点结果**的），前面登记的才真的动起来跑一遍。

所以这条线可以这么理解：**中间几道是记账，收尾那一道才是开工。** 没挂收尾，整条线一声不吭 —— 不是坏了，是它还没开工。

这条脾气有个很实在的好处：中间那几道可以放心**一路拼成一长条**，翻译官喵会自己安排哪一道先走、哪几道能顺手合并掉。本喵只管把「要做什么」写清楚。

## 三、把结果弄丢了：一个不红、但是错的写法

这条线上最容易踩的一脚，是**收尾那一道叼回来的东西没伸手接**：

```java
import java.util.ArrayList;
import java.util.List;
import java.util.stream.Collectors;

public class Main {
    public static void main(String[] args) {
        List<Integer> nums = new ArrayList<>();
        nums.add(3);
        nums.add(8);
        nums.add(1);
        nums.add(6);

        nums.stream()
                .filter(n -> n >= 5)
                .map(n -> n * 10)
                .collect(Collectors.toList());

        System.out.println("撑过筛子的：");
    }
}
```

```text
撑过筛子的：
```

它**跑得成功**，一个字红都没有。可印出来**后面空着** —— 本喵要的那一串不见了。

要害在：`.collect(...)` 这一手**是要叼东西回来的**（叼回一只新柜子）。本喵没伸手接，它叼回来的东西**当场就丢了**，谁也没拿到。于是下一句只能印出一句空话。

这种错**没有红字**，只能靠本喵自己盯着 —— 跟上一课那句「交出去之后不许再改」不一样，那一种翻译官喵会拦，这一种它**一声不吭**。分清这两类，是这一课最要紧的一件事。

改法就一句话：**伸手接住它**。

```java
import java.util.ArrayList;
import java.util.List;
import java.util.stream.Collectors;

public class Main {
    public static void main(String[] args) {
        List<Integer> nums = new ArrayList<>();
        nums.add(3);
        nums.add(8);
        nums.add(1);
        nums.add(6);

        List<Integer> big = nums.stream()
                .filter(n -> n >= 5)
                .map(n -> n * 10)
                .collect(Collectors.toList());

        System.out.println("撑过筛子的：" + big);
    }
}
```

```text
撑过筛子的：[80, 60]
```

叼回来的东西被一只新柜子接住了，再拼到印的那句后面，那串就出来了。今天这一脚踩下去**不红不响**，只让本喵少看见一串东西 —— 所以养成一个习惯：**收尾那一道写完，先看一眼它叼回来的东西被谁接住了。**

## 四、两笔小账：不另起绕圈也能算

```java
import java.util.ArrayList;
import java.util.List;

public class Main {
    public static void main(String[] args) {
        List<Integer> nums = new ArrayList<>();
        nums.add(3);
        nums.add(8);
        nums.add(1);
        nums.add(9);
        nums.add(4);

        long count = nums.stream().filter(n -> n >= 5).count();
        int sum = nums.stream().mapToInt(n -> n).sum();

        System.out.println("够大的有 " + count + " 件");
        System.out.println("加起来是 " + sum);
    }
}
```

```text
够大的有 2 件
加起来是 25
```

- **`.count()`** 是一道收尾，报的是**流过来几件**；
- **`.mapToInt(n -> n).sum()`** 里，`mapToInt` 是中间那一道（把每一件从「装东西的口袋」换成**光溜溜的整数**），`.sum()` 才是收尾 —— 求和那一手**只认光溜溜的整数**，所以中间必须加那一小截。

有个细节要看出来：这里本喵**从原柜子重新接了两次线**（写了两次 `.stream()`）。为什么？因为**收尾那一道一条线只能挂一次，挂完这条线就用过了** —— 想在同一个柜子上算两笔账，就得重新接一条出来。

顺带记一句：这两笔账要是用「挨个过一遍」的写法，本喵得自己立两个攒数的小篮子；这里两句话就完了，而且**一个编号都没写**。

## 五、这套写法好在哪：一串儿项链

```java
import java.util.ArrayList;
import java.util.List;
import java.util.stream.Collectors;

public class Main {
    public static void main(String[] args) {
        List<String> names = new ArrayList<>();
        names.add("小橘");
        names.add("大肥鱼");
        names.add("狸花");

        List<String> longOnes = names.stream()
                .filter(n -> n.length() >= 3)
                .collect(Collectors.toList());

        System.out.println(longOnes);
    }
}
```

```text
[大肥鱼]
```

这串项链里只有 `大肥鱼` 够得上三个字，所以筛完只剩它。

一路看下来，这条线的好处其实就是**读起来像一句话**：「**从这堆东西里，挑出够大的、每一件翻十倍、收起来**」—— 写下来的顺序**就是**本喵脑子里想的顺序。换成「挨个过一遍」，本喵得先把绕圈、条件、攒数的小篮子一一摆好，读的人得自己在脑子里把它们还原成一句话。

**代价也说清楚**：线短的时候（就一两道活儿）它并不比绕圈省事，反倒多了一层要理解的东西。三五道活儿串起来的时候，它的好处才真正显出来。

::: warn 小心喵

- **不挂收尾，整条线一声不吭。** 中间那几道只是登记，一件东西都不动。看着「没反应」不是坏了，是还没开工。
- **收尾叼回来的东西必须伸手接住。** 常见的收尾是 `collect`、`count`、`sum` 这几个 —— 它们**都给东西**，不接就当场丢了，而且**一个字都不会红**。
- **一条线只能挂一次收尾。** 挂过一次的线再用第二次，**翻译稿子这一关根本不管** —— 翻译官喵只认类型，这条线有没有被用过它看不见。所以是**跑到第二道那儿才炸**：`IllegalStateException: stream has already been operated upon or closed`，而且**第一道的结果早就印出来了**，前面半截活干完了它才翻脸。（反过来，把第二道**直接接在**第一道叼回来的东西上，比如 `.count().sum()`，翻稿子时确实会红 —— 可那是**类型不对**的红：`count()` 叼回来的是光溜溜的整数，整数身上没有 `.sum()`，不是它在查你用没用过。）想算两笔账，就写两次 `.stream()` 重新接一条。
- **`.stream()` 不会弄脏原柜子。** 过筛子和加工动的都是**流过去的那些东西**，原柜子从头到尾一件不少 —— 这也是它比直接在路上改更稳的地方。
- **过筛子和加工这两小截里别去动外面的东西。** 上一课那条「交出去之后不许再改」这里照样管用，而且这里更严：这两小截可能会被翻译官喵**挪到别的时候**去跑，动了外面的东西，什么时候动的就说不清了。

:::

## 一句话对照表

| 本喵写下的 | 它的意思 |
|---|---|
| `.stream()` | 从柜子**头上接一条线出来**（原柜子一件不动） |
| `.filter(n -> n >= 5)` | **过筛子**：只让够得上 5 的过去 |
| `.map(n -> n * 10)` | **加工**：过去的每一件都翻十倍 |
| `.collect(Collectors.toList())` | **收起来**：收成一只新柜子叼回来 |
| 中间两道挂了、`collect` 没接住 | **跑得成功、一个字不红**，可东西当场丢了 |
| `nums.stream().filter(n -> n >= 5).map(n -> n * 10).collect(Collectors.toList())` | 一整条线连着写下来的样子：接出来 → 过筛子 → 加工 → 收起来 |
| 只写 `.stream().map(...)`、不挂任何收尾 | **一件都不跑**：中间那几道只是在登记 |
| `.count()` | 一道收尾：报**流过来几件** |
| `.mapToInt(n -> n).sum()` | 先换成光溜溜的整数，再求和 |
| 一条线上挂两道收尾 | 挂的时候不红，**跑到第二道才炸**：`IllegalStateException` |
| 同一个柜子算两笔账 | 写两次 `.stream()`，重新接一条线出来 |

::: tip 猫咪提示

- **一条线上，中间那几道是记账，收尾那一道才是开工** —— 没挂收尾，整条线一声不吭，不是它坏了。
- **收尾叼回来的东西必须伸手接住**：不接就当场丢了，而且一个字都不会红 —— 写完先看一眼它被谁接住了。
- **一条线只能挂一次收尾**：想在同一个柜子上算两笔账，就写两次 `.stream()` 重新接一条。
- **`.stream()` 不会弄脏原柜子**：过筛子和加工动的都是流过去的那些东西。
- **线短的时候它并不比绕圈省事** —— 三五道活儿串起来，好处才真正显出来喵。

:::

## 小任务

1. 把第一节那条线抄进练习场，把过筛子那一句改成「**只要偶数**」（`n % 2 == 0`），先猜结果再跑一遍。
2. 把第二节那个例子**原样跑一遍**，确认那句「被加工了」一次都没印出来；然后给它补一道收尾（`.count()` 就行），再跑一遍，看看印了几行、什么顺序。
3. 第三节那个「丢结果」的例子原样跑一遍，确认它**真的不红**；再把接住的那一句补上，比较两次的输出。
4. 同一道收尾**挂两次**试试：把线接出来在一旁收着（`Stream<String> s = names.stream();`），挂一道 `.count()`，再挂一道 `.count()`。**先猜** —— 是翻稿子时就红，还是先好好印出第一道的结果、再翻脸？跑一遍看谁猜对了，再去小心喵那一栏核对原因。
5. 用一条线把「柜子里够大的那些加起来」写出来（过筛子 + `.mapToInt` + `.sum`），跟上一课那种自己立小篮子的写法比一比行数。
6. 想一想：为什么「中间几道先登记、收尾才开工」这件事，能让翻译官喵有机会**把好几道活儿合并着跑**？

下一课，本喵要处理一件让所有猫都头疼过的事：**要找的东西可能压根不在**。从前这种事只能靠本喵心里记着，忘了就是一行红字；下一课要把它**写在名分上**，让用的人非交代一句不可喵～ 🐾
