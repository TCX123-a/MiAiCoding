## 钩子：同一件事，两种数法

本喵摆出一排猫粮碗：1 号碗里 1 条小鱼干，2 号碗里 2 条……一直摆到 1024 号碗里 1024 条。本喵想知道一件事：**有几对碗，合起来正好是 1025 条？**

法子有两个。

- **笨办法**：两只猫爪各按住一只碗，两两试一遍。
- **好办法**：先让这一排碗按条数排好坐（它们本来就排着），然后一只一只地问：「本喵的另一半，在候补的那一半里吗？」

两个法子数出来的答案是**一样的**（都是 512 对）。可它们跑起来的代价，一个天上一个地下：

- 笨办法要绕 **523776** 圈；
- 好办法只要问 **10240** 句。

这两个数不是本喵编出来的，是真跑出来的。这一课就教你**怎么数它、怎么比它、怎么一眼看出谁贵**喵。

## 一、为什么要量代价：别拿「秒」当尺子

最顺手的那把尺子是秒表。本喵真按过一次：把 3 万条小鱼干接成一串，一种写法花了 100 多毫秒，另一种连 2 毫秒都没到。

**可这串毫秒数当不了尺子。** 三条理由：

1. **换台机器就变了。** 本喵这台快还是慢、当时有没有别的猫在抢着干活，都会改这个数。
2. **同一台机器重跑也会变。** 本喵连按了三次，三次的毫秒数各不相同。
3. **事情小的时候看不出来。** 接两条鱼，两种写法都是「一瞬间」，秒表上什么都读不到。

秒表量的是「**这一次、在这台机器上**花了多久」，而本喵真正想知道的是「**这件事本身有多费劲**」。所以换一把尺子：**数圈数**。

> **圈数** = 这套写法从头到尾，最少要做多少次**最基本的那个动作**。

「最基本的动作」是什么，由你说了算 —— 可以是「内层那条语句被跑了几遍」，也可以是「两个数比了几次大小」。**只要同一场比较里，两边用的是同一把尺子**，比出来的高低就是可信的。

::: tip 猫咪提示
拿圈数当尺子的另一个好处是：它**跟机器无关**。同一段代码，在本喵这台机器上是 523776 圈，在你那台上也还是 523776 圈 —— 因为圈数是**代码自己写出来的**，不是机器跑出来的喵。
:::

## 二、数圈数：523776 和 10240 是怎么数出来的

把两个法子写进同一段程序，各自带一只小碗专门记数：

```java
public class Main {
    public static void main(String[] args) {
        int n = 1024;
        int[] bowls = new int[n];
        for (int i = 0; i < n; i++) {
            bowls[i] = i + 1;
        }
        int want = 1025;

        long laps = 0;
        int pairs1 = 0;
        for (int i = 0; i < n; i++) {
            for (int j = i + 1; j < n; j++) {
                laps++;
                if (bowls[i] + bowls[j] == want) {
                    pairs1++;
                }
            }
        }
        System.out.println("笨办法：" + laps + " 圈，数出 " + pairs1 + " 对");

        long asks = 0;
        int pairs2 = 0;
        for (int i = 0; i < n; i++) {
            int target = want - bowls[i];
            int pos = 0;
            for (int step = n / 2; step > 0; step = step / 2) {
                if (pos + step < n && bowls[pos + step] <= target) {
                    pos = pos + step;
                }
                asks++;
            }
            if (bowls[pos] == target) {
                pairs2++;
            }
        }
        System.out.println("好办法：" + asks + " 句，数出 " + (pairs2 / 2) + " 对");
    }
}
```

```text
笨办法：523776 圈，数出 512 对
好办法：10240 句，数出 512 对
```

两个数分别是怎么来的，拆开看。

### 笨办法的 523776

外圈每按下一只碗（`i`），内圈就把它**后面的**每一只都试一遍 —— 内圈从 `i + 1` 起步。所以内层那条 `laps++` 一共被跑了

0 + 1 + 2 + … + 1022 + 1023（次）

这串数有现成的算法：**`n × (n - 1) ÷ 2`**。代进去就是 `1024 × 1023 ÷ 2`，等于 **523776**。本喵真跑了一遍，屏幕上印的就是这个数。

为什么是「除以 2」？因为这一排碗里每一**对**都被数了**一次**：1 号和 2 号配成一对，在按下 1 号那趟里数掉了；等外圈走到 2 号，内圈从 3 号起步，就**不会再回头跟 1 号配一次**。`i + 1` 这个起点，正是「每对只数一次」的那道闸。

### 好办法的 10240

好办法里，每一只碗都要问一轮。一轮要问几句？候补范围一开始是全部 1024 只碗，**每问一句砍掉一半**：

1024 → 512 → 256 → 128 → 64 → 32 → 16 → 8 → 4 → 2 → 1

数一数箭头：**10 刀**砍到只剩一只。1024 只碗，每只问 10 句，就是 `1024 × 10` = **10240**。

好办法那句 `for (int step = n / 2; step > 0; step = step / 2)` 就是「一刀砍一半」：步子从 512 起步，每问一句缩一半 —— 512、256、128、64、32、16、8、4、2、1，正好十步走完。**步子开多大，是这套写法的全部本事。**

### 边界松一格，圈数就多一行

那 `i + 1` 这个起点到底有多要紧？本喵把眼色写松了一格（内圈从 `i` 起步、到 `<= n` 才停），拿 8 只碗试：

```java
public class Main {
    public static void main(String[] args) {
        int n = 8;
        int[] bowls = new int[n];
        int laps = 0;
        for (int i = 0; i < n; i++) {
            for (int j = i; j <= n; j++) {
                bowls[j] = bowls[j] + 1;
                laps++;
            }
        }
        System.out.println(laps);
    }
}
```

翻译官喵编译的时候一句话都没说，可它一跑起来就当场没了：

```text
Exception in thread "main" java.lang.ArrayIndexOutOfBoundsException: Index 8 out of bounds for length 8
```

这句话的意思：「**8 号碗**？这一排只有 8 只，编号最多到 7 喵。」—— **多绕出来的那一圈，正好撞到碗排外面。**

圈数这件事就是这么实在：边界松一格，圈数就多一行，而多出来的那一行往往就是踩空的那一脚。

## 三、大 O 记号入门

圈数的算式常常又长又难写（好办法那个 10240，还得先知道「1024 砍半 10 次」）。所以本喵要一个**只记大势**的记号：**大 O 记号**。

写它只有三步，像收拾房间一样：

1. **只留长起来最快的那一项。**
2. **常数项丢掉。**
3. **系数丢掉。**

拿笨办法的圈数试一遍：

```text
n × (n - 1) ÷ 2   =   n² ÷ 2 - n ÷ 2
```

- 两项里，`n²` 那一项长起来最快（n 一大，`n × n` 远远甩开 `n`）→ 留下它；
- `÷ 2` 是系数 → 丢掉。

于是笨办法的圈数是 **O(n²)**。好办法的 `1024 × 10`（也就是 `n × log₂n`）里两边都是「长起来的东西」，留到最后就是 **O(n log n)**。

::: warn 小心喵
**O 说的是「长大的形状」，不是「精确跑了几圈」。**

- `523776` 圈是 O(n²)，`523775` 圈也是 O(n²)，两段完全不同、圈数差好几倍的代码都可以是 O(n²) —— 系数不一样。
- 但**「谁的 O 更小，谁就更耐用」**这件事不会变：碗数往上翻，O(n log n) 那一边迟早会把 O(n²) 甩开，而且越甩越远。

还有一个更爱忘的点：**大 O 说的是上界** —— 也就是「最坏能坏到哪一步」。它是从那句「n 一直变大」里长出来的结论，**不是**「这段代码这次跑了这么多圈」的记录喵。
:::

五个最常见的记号，本喵按「n 翻一倍时会怎样」摆给你看：

| 量级 | 长什么样 | n 翻一倍时 |
|---|---|---|
| `O(1)` | 一句就完事，跟 n 没关系 | 一点都不变 |
| `O(log n)` | 每问一句砍掉一半 | 只多 1 句 |
| `O(n)` | 挨个摸一遍 | 翻一倍 |
| `O(n log n)` | 每层都摸一遍，一共 log n 层 | 多一倍多一点 |
| `O(n²)` | 每一对都试一遍 | 变四倍 |

## 四、常见量级对照

光看记号还不够，得能**对着代码看出它是哪一档**。本喵写了段实测台，把五档各跑一遍（碗数 1024 和 2048）：

```java
public class Main {
    public static void main(String[] args) {
        for (int n : new int[] { 1024, 2048 }) {
            long one = 1;
            long half = 0;
            int left = n;
            while (left > 1) {
                left = left / 2;
                half++;
            }
            long single = 0;
            for (int i = 0; i < n; i++) {
                single++;
            }
            long nlogn = 0;
            for (int i = 0; i < n; i++) {
                nlogn += half;
            }
            long pairs = 0;
            for (int i = 0; i < n; i++) {
                for (int j = i + 1; j < n; j++) {
                    pairs++;
                }
            }
            System.out.println("n = " + n + "：一句就完事 " + one
                    + " ／ 砍半 " + half
                    + " ／ 挨个摸一遍 " + single
                    + " ／ 排排坐那种 " + nlogn
                    + " ／ 两两试 " + pairs);
        }
    }
}
```

```text
n = 1024：一句就完事 1 ／ 砍半 10 ／ 挨个摸一遍 1024 ／ 排排坐那种 10240 ／ 两两试 523776
n = 2048：一句就完事 1 ／ 砍半 11 ／ 挨个摸一遍 2048 ／ 排排坐那种 22528 ／ 两两试 2096128
```

对着这两行，五档各长什么样就全在眼前了：

| 量级 | 一段看得出它的代码 | 1024 → 2048 时 |
|---|---|---|
| `O(1)` | `int first = bowls[0];` —— 报个编号就拿，跟碗有几只无关 | 1 → 1 |
| `O(log n)` | `left = left / 2;` —— 每问一句砍掉一半 | 10 → 11 |
| `O(n)` | 单层绕圈：`for (int i = 0; i < n; i++)` 挨个摸一遍 | 1024 → 2048 |
| `O(n log n)` | 每只碗都要「砍半问一遍」，一共 `n × log₂n` | 10240 → 22528 |
| `O(n²)` | 双层绕圈：`for (i…) { for (j = i + 1…) }` 每一对都试 | 523776 → 2096128 |

::: tip 猫咪提示
一眼认量级的小窍门：**数它是几层绕圈**。

- 一层绕圈、里面不做别的绕圈 → `O(n)`；
- 两层绕圈（外面走一步，里面也走一遍）→ 多半是 `O(n²)`；
- 绕圈里每走一步都**把范围砍一半** → `O(log n)`；
- 绕圈里套着「砍半」→ `O(n log n)`。

不过这只是个手感，不是判据 —— 有些看着是两层的，实际上是 O(n)；有些看着一层的，里面那句自己就是 O(n) 的事。**真拿不准就数圈数**喵。
:::

## 五、最好、最坏、平均

有一样东西会让人误以为「量级靠不住」：**同一套写法，碰上的情况不一样，圈数也不一样。**

拿「在一排排好坐的碗里找一只碗」举例（n = 1024），本喵真跑了四种情况：

```java
public class Main {
    static int[] bowls = new int[1024];
    static int asks = 0;

    static int find(int target) {
        asks = 0;
        int lo = 0;
        int hi = bowls.length - 1;
        while (lo <= hi) {
            int mid = (lo + hi) / 2;
            asks++;
            if (bowls[mid] == target) {
                return mid;
            }
            if (bowls[mid] < target) {
                lo = mid + 1;
            } else {
                hi = mid - 1;
            }
        }
        return -1;
    }

    public static void main(String[] args) {
        for (int i = 0; i < bowls.length; i++) {
            bowls[i] = i + 1;
        }
        find(512);
        System.out.println("刚好问到正中间那只：" + asks + " 句");
        find(1024);
        System.out.println("问到最边上那只：" + asks + " 句");
        find(0);
        System.out.println("问一只根本不存在的：" + asks + " 句");

        long total = 0;
        for (int t = 1; t <= 1024; t++) {
            find(t);
            total += asks;
        }
        System.out.println("1024 只挨个找一遍，一共 " + total + " 句");
        System.out.println("平均每只 " + (total / 1024) + " 句多一点");
    }
}
```

```text
刚好问到正中间那只：1 句
问到最边上那只：11 句
问一只根本不存在的：10 句
1024 只挨个找一遍，一共 9228 句
平均每只 9 句多一点
```

三个名字：

- **最好的情况**：头一句就问到正中间那只，**1 句收工**；
- **最坏的情况**：问的是最边上那只（或者压根不在这一排里），**11 句**；
- **平均**：1024 只挨个找一遍，加起来 9228 句 —— 平均每只 **9 句多一点**。

看出关键了吗：**这三个数都在 10 上下打转。** 因为 `log₂ 1024 = 10` —— 不管走哪条路，范围每次都被砍掉一半，最多最多也就 10 刀多一点。所以：

> **最好／最坏／平均的差别，在这套写法里只是「常数级别」的抖动，量级没变，都是 O(log n)。**

::: warn 小心喵
但这不是普遍规律：有些写法，**最好和最坏差着整整一个量级**。

比如「给一堆小鱼干排排坐」那种分治的写法：如果每次挑的分界鱼干都好巧不巧是当前最大或最小的那条，它就会一路退化成 `O(n²)` —— 从 `O(n log n)` 掉到 `O(n²)`，这才是「最坏情况」值得单独拿出来说一句的原因。

所以看一段代码的量级，**先问它是拿哪种情况在说**：最坏？平均？还是最好？大 O 默认说的是**最坏**的那个上界喵。
:::

## 六、Java 的抓手：在绕圈里拼一串小鱼干

这一节是 Java 特有的一个经典陷阱 —— 而且它正好是「同一个需求、两种写法、量级差整整一档」的活标本。

需求很简单：**接一串 1024 条小鱼干的项链。**

```java
public class Main {
    public static void main(String[] args) {
        int n = 1024;

        long moved = 0;
        String s = "";
        for (int i = 0; i < n; i++) {
            moved += s.length();
            s = s + "鱼";
        }
        System.out.println("直接拼：搬了 " + moved + " 个字符");

        long placed = 0;
        StringBuilder sb = new StringBuilder();
        for (int i = 0; i < n; i++) {
            sb.append("鱼");
            placed++;
        }
        System.out.println("StringBuilder：每趟只塞一条，一共塞了 " + placed + " 次");
        System.out.println("两边一样长：" + (s.length() == sb.length()));
    }
}
```

```text
直接拼：搬了 523776 个字符
StringBuilder：每趟只塞一条，一共塞了 1024 次
两边一样长：true
```

**为什么 `s = s + "鱼"` 是二次数？** 因为这一串**拼不长**：每一次 `+` 都要**另开一串新的**，把手上那串**整个抄过去**，再把新的一条接在末尾。于是：

- 第 1 趟抄 0 个字符；
- 第 2 趟抄 1 个；
- 第 3 趟抄 2 个……
- 第 1024 趟抄 1023 个。

加起来就是 `0 + 1 + 2 + … + 1023` —— 又是 **523776**。**和第二节那个两两试，是同一个形状的二次数**：一条是「每一对都试一遍」，一条是「每一条都把前面所有条抄一遍」。表面上一个是找配对、一个是拼项链，账本长得一模一样。

**`StringBuilder` 那边为什么不是？** 因为它手上有一块**预留的空地**：`append` 直接把新的一条塞进空位里，**旧的一条都不用抄**。所以它每一趟只做一件事，一共做 1024 次 —— **O(n)**。

差多少？碗数 1024 时，`523776` 对 `1024` —— 整整差了 512 倍。而 n 越大，这个倍数越大。

::: tip 猫咪提示
这条经验在四门语言里都能用上，只是说法不同：**凡是要在绕圈里「一段一段接出结果」的，先看看能不能一次接好、或者接进一块会自己长大的地方。**

Java 这边的答案就是 `StringBuilder`（会自己长大的那一把）。下次在绕圈里看到 `s = s + 什么`，先停一秒喵。
:::

还有一条要记：**接之前，那一串得先真的存在**。本喵把「先备一条空项链」那一句漏了：

```java
public class Main {
    public static void main(String[] args) {
        int n = 1024;
        long moved = 0;
        String s;
        for (int i = 0; i < n; i++) {
            moved += s.length();
            s = s + "鱼";
        }
        System.out.println("搬了 " + moved + " 个字符");
    }
}
```

翻译官喵当场把稿子退了回来：

```text
Main.java:7: error: variable s might not have been initialized
```

它的原话是：「`s` 这一格，**本喵还没往里放过东西**，你就要读它。」补一句 `String s = "";` 就过去了 —— 注意是**空的一串**，不是「留着不管」：空的能读长度、能往上接、能问它多长；**没有**的那个，连编译都别想过。
