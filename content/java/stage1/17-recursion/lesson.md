## 钩子：偷懒的数碗法

本喵把晒好的猫粮碗摞成一摞，刚念出「1」就没了耐心 —— 这么多碗，一只只点太憨了。本喵干脆换了个**偷懒的问法**：

> 这一摞有几个？ —— 最上面那个算 1 个，**再加上「剩下那一摞」有几个**。
> 「剩下那一摞」有几个？ —— 还是同一道题呀！照样是最上面算 1 个，再加剩下那摞。

一路问下去，什么时候停？**剩下那摞空的时候停** —— 空的当然就是 0 个。

看出来了吗：这个数法每一层问的都是**同一个问题**，只是每回问的东西小了一圈。Java 里也能这么写 —— **在自己的招式里，再喊一次自己**。这门本事本喵管它叫自己咬自己尾巴的招式（递归），它的正式长相就一句话：**招式在身子里面喊自己，而且每一回喂进去的料，都比上一回更靠近「停」。**

## 一、招式里喊自己：先数个数

```java
public class Main {
    public static void countDown(int n) {
        if (n == 0) {
            System.out.println("到站喵");
            return;
        }
        System.out.println(n);
        countDown(n - 1);
    }

    public static void main(String[] args) {
        countDown(3);
    }
}
```

```text
3
2
1
到站喵
```

拆开看这一招（它跟上一课的招式长得一模一样：`public static` 打头、住在 `Main` 这张图纸里）：

1. **先看要不要停。** `if (n == 0)` 成立的时候，印一句「到站喵」再 `return` 收工，**不再喊自己**。
2. **干自己的那点活。** `System.out.println(n);` 把当前这个数印出来。
3. **喊自己，并且把投喂的小鱼干减一。** `countDown(n - 1);` —— 这就是「咬住自己尾巴」的那一口。

走一遍就明白了：进去时 `n` 是 3，它印 3、喊 `countDown(2)`；那一位印 2、喊 `countDown(1)`；再一位印 1、喊 `countDown(0)`；最后一位看到 `n == 0`，印「到站喵」，收工。一共四位，一层层到底，再一层层结束。

**喊自己和喊别人（`greet()` 那种）在写法上没有任何区别** —— 招式名在招式脑袋上就登记好了，身子里面照样喊得到它。翻译官喵不会因为「它在喊自己」多问一句，也不会少问一句喵。

## 二、基线条件：那句「什么时候停」

上面那句 `if (n == 0)`，本喵管它叫**基线条件（刹车）**。

那把刹车拆了会怎样？本喵在跑台上真跑过这么一段（故意把刹车拿掉，所以只放在这儿给你看）：

```java
public class Main {
    public static void countDown(int n) {
        System.out.println(n);
        countDown(n - 1);
    }

    public static void main(String[] args) {
        countDown(3);
    }
}
```

翻译官喵**这次一个字都没说** —— `javac` 干干净净地把它翻了出来（本喵真跑过，编译那一步屏幕上零输出）。可一跑起来就收不了场：

```text
3
2
1
0
-1
-2
Exception in thread "main" java.lang.StackOverflowError
	at Main.countDown(Main.java:4)
```

本喵只抄了开头这几个数 —— 真跑那一下，它 3、2、1、0、-1、-2 一路往下数，一直数进负数、屏幕上整整数了两万多行才断气，最后甩出这一句 `Exception in thread "main" java.lang.StackOverflowError`。（数到哪个数断气，每台机器、每一趟都不一样：本喵这台上前后两回跑，末了就差了七十来层 —— 那跟那摞碗能摞多高有关，第四节讲。）

`StackOverflow` 翻成猫话就是**摞碗摞爆了**。为什么爆、爆的又是哪一摞碗，第四节讲；这里先记住这一条：**Java 里没有刹车的自己咬尾巴招式，不是「算错一个数」，是这只猫当场地断气** —— 屏幕上你看到的那些数字，全是它断气之前印下来的。

**写自己咬自己尾巴的招式，第一件事就是先想清楚「什么时候停」。** 这里还有两条硬要求：

1. **停的那一句，得真有可能轮到。** `if (n == 0)` 配 `countDown(n - 1)` 是好的；配 `countDown(n + 1)` 就永远轮不到 —— `n` 只会越走越大，0 这辈子等不到。
2. **每一步都要离停更近一点。** 这里每次都把 `n` 减一，所以一定走得到 0。

::: warn 小心喵
**别把「翻译官喵不吭声」当成「没问题」。** 上面那一段 `javac` 一个字都没说（本喵真跑过），跑起来却当场爆掉 —— **这门本事最贵的坑，全都在编译期看不见**：刹车忘写、刹车够不着、递推的方向挪反了（`countDown(n + 1)` 那样），`javac` 一律不吭声，只有真跑起来才知道。

对照一下上一课：`missing return statement`、`non-static method ... cannot be referenced` 那几条，翻译官喵**编译当场就拦**。可它拦的都是「写法」层面的毛病；**「你这串数对不对」它管不了**。

还有一条：**每一次喊自己，投喂的东西都要往停的方向挪。** 挪反了方向，等于踩了油门去撞刹车，效果和没写刹车一样喵。
:::

## 三、去的时候一路往下，回来的时候一路收尾

再看一段更能看出「往返」的：

```java
public class Main {
    public static void down(int n) {
        int mine = n * 10;
        if (n == 0) {
            System.out.println("到底了，本喵碗里是 " + mine);
            return;
        }
        System.out.println("往下走之前，本喵碗里是 " + mine);
        down(n - 1);
        System.out.println("回来之后，本喵碗里还是 " + mine);
    }

    public static void main(String[] args) {
        down(2);
    }
}
```

```text
往下走之前，本喵碗里是 20
往下走之前，本喵碗里是 10
到底了，本喵碗里是 0
回来之后，本喵碗里还是 10
回来之后，本喵碗里还是 20
```

`mine` 是每一位自己的小鱼干仓库（`int mine = n * 10;`），**每一位都有新的一只** —— 上一课讲作用域那条规矩在这儿照旧：招式一喊起来，它就有一套自己的仓库。所以：

- **往下走的那一趟**（在 `down(n - 1)` 之前）：印 20、印 10；
- **到底折回来之后**（在 `down(n - 1)` 之后）：印 10、印 20。

要紧的是这一句：`down(2)` 里那只碗装的是 20，它喊完 `down(1)`、等那一位全部收工回来之后，自己那只碗**还在，还是 20**。一层一层的碗不会互相覆盖 —— 「每个自己都有一套自己的仓库」就是这套写法能立住的地基喵。

**印的那句写在「喊自己」的哪一边，就决定了它属于哪一趟**：写在上边 = 去程（数字从大到小），写在下边 = 回程（数字从小到大）。排错了不是乱序，是**正好反过来**。

## 四、调用栈直觉：那一摞碗到底是什么

第二节里「摞碗摞爆了」，摞的到底是哪一摞碗？

本喵拿 `countDown(3)` 那一刻拆给你看。每一位喊下一位的时候，它自己那点活**还没干完** —— `countDown(n - 1)` 这行的后面还排着句子呢，它得记住「等会儿回来，接着往下走」。记这件事的，就是**一摞碗**：每喊一次自己，就往摞顶上再放一只碗，碗里写着「本喵是从哪儿来的、回来要接着干哪句」。这一摞碗的正式名字叫**调用栈**。

于是三件事对上了：

- **往下喊 = 往摞上放碗**，一只比一只新；
- **折回来 = 从摞顶上拿碗** —— 谁最后放上去，谁最先被拿走（最后喊的那位最先回来）；
- **爆掉 = 碗摞得太高，地方不够了** —— 就是那句 `java.lang.StackOverflowError`。

⚠️ 而每一层自己那只 `mine`（或者倒计时的那个 `n`）**不在这一摞上**：那些是各层私有的，随招式出生、随招式消失。两样东西都叫「碗」，别混喵。

**Java 这边还有两条硬限制**，都跟这一摞碗有关。

**① Java 不会把「尾巴上那一喊」改写成绕圈跑。** 本喵真跑过一次：递推那一步写成**尾巴上直接交回**的样子（最后那一行的 `return` 后面只跟着下一喊，一声多余的活都没有），喂十万进去 ——

```java
public class Main {
    public static long sumTo(long n, long acc) {
        if (n == 0) {
            return acc;
        }
        return sumTo(n - 1, n + acc);
    }

    public static void main(String[] args) {
        System.out.println(sumTo(100000, 0));
    }
}
```

```text
Exception in thread "main" java.lang.StackOverflowError
	at Main.sumTo(Main.java:6)
```

照样爆。这门本事在别处有个正式名字叫**尾递归优化（改写成绕圈跑）**—— 尾巴上那一喊要是能被改写成绕圈跑，碗就不用摞了。**Java 不做这件事**。所以本喵这边一句话：**你写多深，它就摞多高。**

**② Java 的招式没有默认参数（不喂就按它算的那种）。** 想给上面那个 `acc` 小碗配一句「不写就按 1 算」？Java 不认：

```java
public class Main {
    public static int fact(int n, int acc = 1) {
        if (n == 0) {
            return acc;
        }
        return fact(n - 1, n * acc);
    }

    public static void main(String[] args) {
        System.out.println(fact(5));
    }
}
```

翻译官喵当场拦下：

```text
Main.java:2: error: ',', ')', or '[' expected
    public static int fact(int n, int acc = 1) {
1 error
```

念起来是：**「投喂口里只能写『料型 + 名字』，别的记号本喵不认喵。」** 换成别的语言，那个 `= 1` 就是默认值（不喂就按它算）；**Java 这边你得每次自己把料喂全** —— 五个投喂口就得喂五样。所以「把小碗藏进投喂口里讨巧」这件事，在 Java 这儿走不通；也正因为这样，本喵这边的写法反而更直白：**要喂什么，脑袋上写得清清楚楚。**

## 五、阶乘：数学书上的老例子

一说到自己咬自己尾巴，书上都爱举这个例子：`5!`（读作「5 的阶乘」）等于 `5 × 4 × 3 × 2 × 1`。

换个角度念：**`5!` 就是 `5 × 4!`**，而 `4!` 就是 `4 × 3!` —— 又是同一道题、小一圈。什么时候停？**`0!` 规定等于 1**，那就是它的刹车。

```java
public class Main {
    public static long fact(int n) {
        if (n == 0) {
            return 1;
        }
        return n * fact(n - 1);
    }

    public static void main(String[] args) {
        System.out.println(fact(5));
        System.out.println(fact(10));
        System.out.println(fact(20));
    }
}
```

```text
120
3628800
2432902008176640000
```

看那一句 `return n * fact(n - 1);` 里的 `return`：它**不是**先算完再回来 —— 是「喊完那一位、等它把战利品叼回来，本喵再拿它跟自己乘」。所以每一位都要**等**下一位，一层层等到底，再一层层把战利品叼上来。

::: tip 猫咪提示
`long` 是「更宽的仓库」：`int` 装得下大约 21 亿，`long` 装得下大约 900 亿亿。阶乘长起来快得吓人，本喵真跑过一段把战利品写成 `int` 的：`fact(12)` 还老老实实给 `479001600`，`fact(13)` 就交给了本喵一个 `1932053504` —— 而 `13!` 的真值是 `6227020800`，早把 `int` 撑破了。**翻译官喵一个字都没说**，安安静静给了一个错的数。要装大数，脑袋上就写 `long` 喵。
:::

::: warn 那一摞碗，就是「记着待会儿回到哪儿」
上面从「第 1 层 · 喊下一位，然后停住等」到「第 1 层 · 醒来」这几步里，一直有一栏叫「停在半路的层」。那是这一课唯一一件**屏幕上看不见**的事：每一位喊完下一位就停在那儿了，而「停在哪」这件事得有个地方记着。

记着它的就是那一摞碗 —— 第二节里那个反例，就是把它摞爆了。反过来，每一层攥着的那个数（3、2、1）**不在**这一摞上：那些是各层私有的，随招式出生、随招式消失。两样东西都叫「碗」，别混喵。
:::

## 六、自己咬尾巴，还是绕圈跑？

同一件事，绕圈跑（用 `for` 挨个走一遍）往往也能干，而且**更快、更省地方**：不用一层层喊自己，也就没有那一摞碗要摞。

第四节那个「1 加到 100000」，本喵用绕圈跑改写了一遍：

```java
public class Main {
    public static void main(String[] args) {
        long acc = 0;
        for (long i = 1; i <= 100000; i++) {
            acc = acc + i;
        }
        System.out.println(acc);
    }
}
```

```text
5000050000
```

同一个任务、同一个答案 —— 可这一次一只碗都没摞，跑多深都行。**自己咬尾巴那份好看是有代价的：省了代码，费了地方。**

那为什么还要有这套写法？因为有些题**用「小一圈的同一道题」讲起来最顺** —— 像阶乘那样，一句话就说清了它是什么。两种写法都收在工具箱里，用哪把看你顺手喵。

::: tip 猫咪提示
今天收五句话：

1. **自己咬自己尾巴的招式 = 在自己的身子里再喊一次自己**，喊法和喊别人一模一样。
2. **基线条件就是刹车**，而且必须「轮得到」，并且**每一步都更靠近它**。
3. **每一位都有自己的一份东西**，回来之后还在；印的那句写在「喊自己」的上边还是下边，决定了它属于去程还是回程。
4. **谁来记「等会儿回到哪儿」？一摞碗（调用栈）** —— 摞爆了就是 `StackOverflowError`。Java 不做尾递归优化（改写成绕圈跑），也不给招式备「不喂就按它算」的默认料，所以**写多深就摞多高**。
5. **绕圈跑更省地方**；能用「小一圈的同一道题」讲清楚的活儿，才轮到自己咬尾巴上场。
:::

## 小任务

1. 把第一节的倒计时改成「从 `n` 一直数到 1，然后再数回 `n`」—— 提示：一句 `System.out.println` 写在喊自己**之前**，另一句写在**之后**。
2. 写一招 `public static int countBowls(int n)`：仿照钩子里那个数法，「第 `n` 摞碗有几个」—— 一摞碗的数量减一，刹车的条件是「一个都不剩」。
3. 先猜再跑：把第五节的 `if (n == 0)` 改成 `if (n == 1)`，`fact(5)` 会印出什么？先写下你的猜测，再真跑一次对照 —— 本喵跑过，它**照样是 120**（因为 `1!` 和 `0!` 都等于 1，链子只是早停了一层）；再把 `fact(0)` 也印出来看看，想一想这一回为什么它收不了场。
4. 先猜再跑：把第四节那个 `sumTo(100000, 0)` 的十万改成 `10000`，它还会爆吗？猜完再跑 —— 你会发现「爆不爆」跟本喵这台机器给的那摞碗有多高有关，而不是跟代码写得对不对有关。

下一课本喵要带你认识一只**最常用的大鱼缸**：一串字符小鱼干怎么装、怎么量长短、怎么拼起来 —— 往后每一课都离不开它喵～ 🐾
