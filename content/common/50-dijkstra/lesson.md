## 钩子：通不够，我要最便宜的那条

上一课的并查集，本喵和面试官大肥鱼只练了一句话：谁和谁是一伙的。问的是「通不通」——两只猫是不是同一伙、两个点是不是连在一起，答案只有「是」或者「不是」，干脆利落。

可今天大肥鱼没拿名单来。他铺开一张皱巴巴的地图，上面每个路口画一个圈，每两个圈之间画一条路，路旁边还标着一个数字——过路费。他用爪尖敲了敲桌子：

> 「通不够。我要最便宜的那条。」

本喵凑过去一看：从猫窝到鱼干铺，确实有三条路都通。可一条绕了半个城，一条要过两座收费桥，还有一条看着近，每小段却都贵得离谱。**「到得了」只是入场券，「花最少的路费到」才是面试官要的答案。**

这一课请出的，是图论里最有名的一招：**Dijkstra（迪杰斯特拉）**——一只每次只挑「目前最便宜」的路口往前拱的猫。它不靠运气，靠的是一条铁律：

> 只要每条路的路费都不是负数，那么每轮从「还没定下来的路口」里挑出路费最少的那个，它此刻的最便宜走法就已经定死了，后面绕什么路都超不过它。

这话听着有点狂。凭什么「现在最便宜」就等于「最终最便宜」？本喵带你从一张只有五个路口的小地图开始，一步一步把这条铁律走成看得见的过程。

## 先把地图写成路费表

本课从头到尾只用一张固定的地图，五个路口，编号 0 到 4，六条路：

| 路 | 过路费 |
|---|---:|
| (0, 1) | 4 |
| (0, 2) | 1 |
| (1, 2) | 2 |
| (1, 3) | 1 |
| (2, 3) | 5 |
| (3, 4) | 3 |

注意两件事喵。

第一，**这里每条路都是双向的**：从 0 走到 1 要 4 块，从 1 走回 0 也照样要 4 块。所以写进代码时，一条边要在两边的邻居表里各记一次；只记一次，回头的方向就断了。

第二，**路旁边那个数字叫「权值」，本喵管它叫路费**。不带数字的图只回答「谁连着谁」；带上路费，问题立刻变成「怎么走最省」。上一课的并查集只关心两点在不在同一伙，这一课关心的是在连着的前提下，哪条路的账最便宜。

先把六条边的路费在脑子里过一遍：0 到 1 直达要 4，可要是先花 1 块到 2、再花 2 块到 1，总共才 3——**直达不一定最便宜，这是整节课的戏眼**。0 到 4 更绕：0→2→1→3→4，账是 1 + 2 + 1 + 3 = 7。先把这个 7 记在心里，等会儿代码会把它算出来。

没有画出来的那两个圈之间，就是走不通；走不通在程序里不写 0，而写「无穷大」——0 块的意思是「免费就能到」，和「根本到不了」完全是两码事，这一点下面马上会用到喵。

## 一张价签表：dist 是什么意思

本喵在每个路口门口挂一块小牌子，牌子上写一个数。这个数叫 **dist[i]**，意思是：

> 从起点 0 出发，走到路口 i，**目前知道的**最便宜路费。

「目前知道的」五个字很关键。一开始本喵只知道起点在自己脚下，别的路口连影子都没见着，所以：

| 路口 | 0 | 1 | 2 | 3 | 4 |
|---|---:|---:|---:|---:|---:|
| dist | 0 | ∞ | ∞ | ∞ | ∞ |

起点 0 到自己的路费是 0——一步没走，一分没花。其余四个先挂上「无穷大」，不是说到不了，而是说「本喵还没找到任何一条能过去的走法」。随着一轮轮往外拱，这些无穷大会一个个被换成真数字，而且只会越换越小，绝不会越换越大。

这里要跟「一圈一圈往外扩」那一课的 BFS 打个照面。BFS 也算「从起点到各点多远」，可它数的是**走了几条边**：0 到 1 隔一条边，距离就是 1。这一课数的是**路费总和**：0 到 1 直达是 4，绕道 2 反而只要 3。**边的条数和路费总和是两把不同的尺子**——地图一旦标上价，BFS 那把「数步数」的尺子就不够用了。

还有一句丑话说在前头：牌子上的数在没「定下来」之前，都只是暂定。谁有资格把「暂定」改成「定死」？答案是：**当前还没定下来的路口里，牌子数字最小的那个**。下一节就讲为什么。

## 每次取最小的那只：堆上场

每轮都要从「还没定下来的路口」里挑出牌子数字最小的那个。最笨的办法是把所有没定的路口扫一遍，挑最小的；可路口一多，每轮都扫一遍太磨爪子。前面「每次取最小的那只」那一课，我们养过一只特别会「每次取最小」的猫——这一课请它来值班：**优先队列（每次挑最小的小鱼干堆）**，底层通常用二叉堆实现。

它干的事很单纯：本喵把一张张写着「(路费, 路口)」的小票丢进去，它每次递回来的，一定是路费最小的那张。于是整节课的主跑圈可以写成一句人话：

1. 从堆里取出一张小票 (d, u)。
2. 如果这张票上的 d 已经过期（u 的牌子早换成更小的数了），把票一扔，继续取下一张。
3. 否则，u 的牌子数字就**定死**了。
4. 拿 u 的每条出边去试一试，看能不能把邻居的牌子改小（这一步叫松弛，下一节细讲）。

为什么「取出即定死」？本喵把道理掰成三步：

- 堆顶的 d，是所有还没定下来的路口里最小的。
- 假设存在另一条更便宜的走法能到 u，那它总得从「已经定死的区域」迈出去，走到某个还没定下来的路口 x。
- 可 x 的牌子数字本来就 ≥ d（不然堆顶就是 x 了），从 x 再走到 u 的剩余路费又不可能为负，所以那条走法只会 ≥ d，不可能更便宜。

**没有负路费，就没有「后来居上」**——这就是整招的命门。要是哪条路边标着负数，第三步的「剩余路费不为负」就塌了，后面会专门讲这个坑。

来，把五个路口完整走一遍。下表的「堆里剩什么」按路费从小到大写，方便看：

| 轮 | 取出 (路费, 路口) | 动作 | 现在的 dist[0..4] | 堆里剩什么 |
|---:|---|---|---|---|
| 0 | — | 起点 0 挂 0，压进堆 | `0 ∞ ∞ ∞ ∞` | `(0,0)` |
| 1 | (0, 0) | 0→1 记 4；0→2 记 1 | `0 4 1 ∞ ∞` | `(1,2) (4,1)` |
| 2 | (1, 2) | 2→1：1+2=3，比 4 便宜，改；2→3：1+5=6 | `0 3 1 6 ∞` | `(3,1) (4,1) (6,3)` |
| 3 | (3, 1) | 1→3：3+1=4，比 6 便宜，改 | `0 3 1 4 ∞` | `(4,1) (4,3) (6,3)` |
| 4 | (4, 1) | 旧票：dist[1] 已经是 3，扔掉 | `0 3 1 4 ∞` | `(4,3) (6,3)` |
| 5 | (4, 3) | 3→4：4+3=7 | `0 3 1 4 7` | `(6,3) (7,4)` |
| 6 | (6, 3) | 旧票：dist[3] 已经是 4，扔掉 | `0 3 1 4 7` | `(7,4)` |
| 7 | (7, 4) | 4 没有别的出边，收工 | `0 3 1 4 7` | 空 |

盯着第 2 轮看：本喵先按 0→1 直达记了 4，可后来从 2 绕过去只花 3，牌子当场被改小。**「先记下的」不等于「对的」**，价签就是拿来反复改的。再盯第 4 轮：1 号路口被取出过两次——第 3 轮那张 3 块钱的是真票，第 4 轮这张 4 块钱的才是旧票。旧票不用删，取出来一看数字对不上，扔了就行；这叫「懒删除」，省得在堆里翻箱倒柜。

最后一行就是答案：`0 3 1 4 7`。0 到 4 最便宜 7 块，走法是 0→2→1→3→4。

## 松弛：把更便宜的价签写下来

刚才反复出现的那个动作，有个正经名字：**松弛（relaxation）**。名字听着玄，做的事只有一句：

> 对当前点 u 的每条出边 (u, v, w)，如果 dist[u] + w < dist[v]，就把 dist[v] 改成 dist[u] + w，并把 v 连同新路费压进堆。

拿课文的地图举个例子。第 2 轮本喵取出 2 号路口，dist[2] = 1。它有一条通往 1 号的路，路费 2：

- 从 2 绕过去的总账：1 + 2 = 3。
- 1 号牌子上原来写着 4。
- 3 < 4，价签从 4 松到 3，再把 (3, 1) 压进堆。

要是算出来不比原来便宜呢？那就不动。比如第 3 轮从 1 号试 1→0：dist[1] + 4 = 7，可 dist[0] 是 0，7 不小于 0，什么都不做。**松弛不是「见邻居就改」，而是「发现更便宜才改」**——价签只会往下走，不会往上走。

为什么要叫「松弛」喵？本喵的理解是：原来的价签像一根绷紧的皮筋，绷着一个「以为的最便宜」；一旦发现更便宜的走法，皮筋就松一松，落到更低的数上。每松一次，牌子上的数就更接近真正的答案。

有个细节要交代：同一个路口可能被压进堆很多次，每次都带着当时的价格。本喵不急着把旧票从堆里抠出来，等它被取到面前，看一眼 `d != dist[u]`——对不上就说明它过期了，直接扔掉。**堆里允许有旧票，但只有和当前价签对得上的那张才算数**。这样代码简单，代价只是堆里多躺几张废纸。

## 复杂度：堆帮本喵省了多少爪子

先数清楚一共干了多少活。

- 每个路口最多被「真正定下来」一次（旧票不算），所以从堆里取有效点的次数是 V 次。
- 每条边在它两个端点被取出时各看一次（无向图两边都存了），总共看 2E 次；每次成功改小价签，就压一张新票，所以压票次数不会超过看边的次数，也就是 O(E)。
- 堆的一次取出、一次压入，代价都是 O(log V)。

合起来：**用二叉堆的 Dijkstra，复杂度是 O((V + E) log V)**。连通图里 E 至少是 V - 1，所以也常写成 O(E log V)。

要是不用堆呢？每轮把所有还没定的路口扫一遍，挑出最小的，一轮 O(V)，一共 V 轮，光挑点就是 O(V²)；再加上看边，总体 **O(V²)**。注意，**O(V²) 不是「错的算法」**，它只是另一种取舍：

| 挑最小的方法 | 每轮挑点代价 | 总复杂度 | 适合的地图 |
|---|---|---|---|
| 每次线性扫一遍 | O(V) | O(V²) | 路口少、边特别密 |
| 二叉堆 | O(log V) | O((V+E) log V) | 路口多、边相对稀 |

所以面试时别背一句「Dijkstra 是 O(V²)」就完事，也别背一句「一定是 O(E log V)」；**先问清楚用什么结构挑最小、图是稠密还是稀疏**，再报复杂度。本喵见过有猫把「每个点只取一次」直接说成 O(V+E)——取最小那一下的 log 可不是白送的喵。

## 为什么不能有负边

前面讲「取出即定死」时，第三步用了一句话：从 x 走到 u 的剩余路费不可能为负。整招就架在这句话上。要是路边真标了负数，会出什么事？本喵画一个三只路口的有向小地图：

| 路 | 路费 |
|---|---:|
| 0 → 1 | 2 |
| 0 → 2 | 5 |
| 2 → 1 | -4 |

从 0 出发，先挂价签：`dist = [0, 2, 5]`。堆里最小的是 (2, 1)，本喵取出 1 号，宣布「0 到 1 最便宜就是 2」，把它定死。接着取出 (5, 2)，从 2 试 2→1：5 + (-4) = 1，比 2 还便宜，1 号的真正最便宜其实是 1！

可 1 号早就被本喵「定死」了。要是程序按教科书里「取出就不再回头」的规矩办事，它交出的答案是 2，**正确答案是 1**——不是慢了一点，是**算错了**。

根子在哪？负边让「后面绕的路只会更贵」这句话失效了。本来堆顶是全场最小，可一条负边能把后面的总账拉到比它还低，于是「现在最小」不再等于「最终最小」，铁律当场断裂。

无向图里出现负边更糟：同一条负路边，猫可以来回走，走一趟倒贴 4 块，走两趟倒贴 8 块……**越走越便宜，压根不存在「最便宜」**，这叫负环。所以「边权非负」不是 Dijkstra 的性能建议，而是它成立的前提条件。

> **小心喵**：很多猫把「Dijkstra 能不能跑负边」记成「跑得慢一点」，这是错的——它会**静静地给出错答案**，连报错都没有。

那带负边的图怎么办？换一招：**Bellman-Ford**。它的做法是把所有边一轮一轮地松，重复 V - 1 轮；因为最长的简单路径最多 V - 1 条边，足够把负边的影响一层层传开。它还能在第 V 轮再扫一遍，如果还能松，就说明图里有负环，最短路根本不存在。代价是 O(V × E)，比 Dijkstra 慢，但能处理负边。

## 和 BFS 的关系：路费全一样时

现在回头看「一圈一圈往外扩」那一课的 BFS。BFS 从起点出发，先看隔一条边的，再看隔两条边的，一圈一圈往外扩；它默认每条边的「代价」都一样，所以先遇到的层一定更近。

把地图上的路费全改成 1，Dijkstra 会变成什么样？每轮堆顶都是「已经走了 k 条边」的点，取出之后把邻居的价签记成 k+1，再压回去。于是它恰好按 k = 0, 1, 2, … 的层次往外取——**它按层展开的顺序和 BFS 一模一样**。所以有一句话：

> BFS 就是每条边路费都相同的 Dijkstra；Dijkstra 就是带路费的 BFS。

可路费一旦不一样，BFS 就撑不住了。拿本课的地图试：BFS 从 0 出发，第一步就看到 1 号（0→1），认为它离起点一条边，价签记 4；然后它按层数走，再也不会回头考虑「0→2→1 虽然多一条边，但总路费只要 3」。**BFS 数的是边数，不是钱数**，多走一条边在它眼里一定更远，可在带路费的地图上，多走一条边完全可能更便宜。

这就是 Dijkstra 多出来的那件武器：它不按「第几层」排队，而按「目前总共花了多少」排队。每轮挑最便宜的那个先定下来，贵的往后排；等便宜的路把价签改小，贵的旧票自然作废。**BFS 的「先来后到」换成了「谁便宜谁先上」**，一字之差，能算的地图就宽了一大截。

顺带说一句：如果边权只有 0 和 1 两种，还有更省事的 0-1 BFS，用双端排队就能做，不必上堆。本课先把标准 Dijkstra 吃透，这种小变种知道有这么回事就行喵。

## 落到代码上：heapq 跑一遍

道理讲完，落到爪子上。Python 自带一个现成的堆工具 `heapq`，往里丢元组，它按元组第一个数从小到大递回来；本喵把「(路费, 路口)」丢进去，正好就是「每次取最小」。

```python
import heapq

graph = [
    [(1, 4), (2, 1)],
    [(0, 4), (2, 2), (3, 1)],
    [(0, 1), (1, 2), (3, 5)],
    [(1, 1), (2, 5), (4, 3)],
    [(3, 3)],
]

n = 5
INF = float("inf")
dist = [INF] * n
dist[0] = 0
heap = [(0, 0)]

while heap:
    d, u = heapq.heappop(heap)
    if d != dist[u]:
        continue
    for v, w in graph[u]:
        if dist[u] + w < dist[v]:
            dist[v] = dist[u] + w
            heapq.heappush(heap, (dist[v], v))

print(*dist)
```

```text
0 3 1 4 7
```

逐段看：

- `graph` 是邻居表，`graph[u]` 里每一对 `(v, w)` 表示从 u 到 v 有一条路费 w 的路。因为是无向图，六条边在两边各写了一次——你看 `graph[0]` 里有 `(1, 4)`，`graph[1]` 里也有 `(0, 4)`。
- `dist` 一开始全是 `INF`，只有起点是 0；`heap` 里先放一张 `(0, 0)`，表示「站在起点，已经花了 0 块」。
- `d != dist[u]` 就是扔旧票：票上的价和当前价签对不上，说明这张票过期了。
- 内层那个 `if` 就是松弛：只有 `dist[u] + w` 真的更小，才改写价签、压新票。

`print(*dist)` 把五个数摊开打印，中间用空格隔开，正好是 `0 3 1 4 7`。第一个 0 是起点自己，第二个 3 是绕到 2 再拐去 1 的账，第三个 1 是直达 2 的账，第四个 4 是再走 1→3 的账，最后一个 7 是全程。每个数都能在刚才那张七轮表里找到出处喵。

同一张五点地图、同一个堆、同一套松弛，换成 C++、Java、Python 各写一遍。三份程序的输出必须一字不差：

#include <iostream>
#include <vector>
#include <queue>
#include <functional>
#include <utility>

int main() {
    const int n = 5;
    std::vector<std::vector<std::pair<int, int> > > graph(n);
    graph[0].push_back(std::make_pair(1, 4));
    graph[1].push_back(std::make_pair(0, 4));
    graph[0].push_back(std::make_pair(2, 1));
    graph[2].push_back(std::make_pair(0, 1));
    graph[2].push_back(std::make_pair(1, 2));
    graph[1].push_back(std::make_pair(2, 2));
    graph[1].push_back(std::make_pair(3, 1));
    graph[3].push_back(std::make_pair(1, 1));
    graph[2].push_back(std::make_pair(3, 5));
    graph[3].push_back(std::make_pair(2, 5));
    graph[3].push_back(std::make_pair(4, 3));
    graph[4].push_back(std::make_pair(3, 3));

    const int INF = 1000000000;
    std::vector<int> dist(n, INF);
    dist[0] = 0;
    typedef std::pair<int, int> P;
    std::priority_queue<P, std::vector<P>, std::greater<P> > heap;
    heap.push(std::make_pair(0, 0));
    while (!heap.empty()) {
        P top = heap.top();
        heap.pop();
        int d = top.first;
        int u = top.second;
        if (d != dist[u]) continue;
        for (int i = 0; i < (int)graph[u].size(); ++i) {
            int v = graph[u][i].first;
            int w = graph[u][i].second;
            if (dist[u] + w < dist[v]) {
                dist[v] = dist[u] + w;
                heap.push(std::make_pair(dist[v], v));
            }
        }
    }
    for (int i = 0; i < n; ++i) {
        if (i > 0) std::cout << " ";
        std::cout << dist[i];
    }
    std::cout << std::endl;
    return 0;
}

三位翻译官喵的写法几乎是一个模子：一份邻居表、一排从无穷大起步的价签、一个每次取最小的堆、一圈松弛、最后摊开打印。C++ 用 `priority_queue` 配 `greater`，Java 用 `PriorityQueue` 配比较器，Python 用 `heapq` 配元组——叫法不同，干的是同一件事。地图一换、路费一改，三份程序会一起给出同一个新答案，这就是「同一套思路，三种方言」喵。

> **本喵提醒**：想少踩坑，记住三句话。
> 1. **无向边要加两次**：只往一个方向写，回头的路就断了，算出来的 dist 会莫名其妙偏大。
> 2. **旧票顺手扔**：`d != dist[u]` 这一行不是装饰——不扔也能算对，可过期的旧票会被反复取出来空跑一遍，白花时间；扔了它，堆里就只剩还没过期的票。
> 3. **堆里放的是 (路费, 路口)**：元组第一个数才是比较依据；放反了，堆就按路口编号排队，取出来的根本不是最便宜的那张。
