## 钩子：名册写到第三十个学员，本喵的爪子开始抖了

猫窝学堂开学了喵。本喵揽下一件正经活儿：给学堂管一本**学员名册** —— 每个人记两样，**名字**和**分数**。

上一课本喵刚砌好一堵看不见的墙：用的人只走本喵留好的那几个口子，里面怎么摆随本喵换。今天本喵要拿这门手艺去干真活儿 —— 这本名册会变长、会改名，还会时不时冒出新花样来。

先说清楚一件事：今天写出来的东西**能用，也确实比从前好用**。本喵不是来拆台的，是来和你一起算一笔账的喵。

## 一、先画图纸：这一步是真进步

本喵摊开纸，画一张学员图纸，再把名册摆出来：

```c
typedef struct {
    char name[20];
    int score;
} Student;

Student list[100];
int count = 0;
```

一句话读完：**一个学员，有一格名字、一格分数**。拆开看喵：

- **开头那个 `typedef`** —— 给这张图纸登记一个学名。登记完，写 `Student` 就是指「照这张图纸的那一整样东西」，去哪都不用再带着 `struct` 那几个字母。
- **`char name[20];`** —— 名字那一格是一排字符碗（就是项链的家），最多住得下 20 个；
- **`int score;`** —— 分数是一格普通的整数碗。

从前记三十个学员，本喵得摆六十只仓库：`p1name`、`p1score`、`p2name`……现在**一条记录就是一样东西**，还能整只搬（这一手，往后 C 线「图纸」那一课里会正式讲：整只可以整个搬）。这是真进步，本喵一点不否认喵。

图纸下面那两行就是名册本身：

`list` 是一排 100 格的位置，`count` 记着现在装了几个人。这两样站在所有招式都看得见的地方，谁都够得着。

## 二、招式住在图纸外面

接下来把要干的活写成招式。第一招：**收一个新学员**。

```c
void add_student(char name[], int score) {
    strcpy(list[count].name, name);
    list[count].score = score;
    count = count + 1;
}
```

读法三行喵：

- **`strcpy(list[count].name, name);`** —— 把名字一颗一颗搬进名册里下一个空位（`count` 正好指着那个空位）。名字是一排字符碗，不能整个换，得请档案管理员 `strcpy` 下手（这一手往后 C 线「图纸」那一课里也会正式讲）。
- **`list[count].score = score;`** —— 分数是普通整数碗，直接写。
- **`count = count + 1;`** —— 装好一个人，人数自己长一，下一位才排得上号。

第二招：**按名字找人**。

```c
int find_by_name(char name[]) {
    for (int i = 0; i < count; i++) {
        if (strcmp(list[i].name, name) == 0) {
            return i;
        }
    }
    return -1;
}
```

一排挨个比，比到了就把位置叼回来；一圈走完都没有，叼回 `-1`（「没这个人」）。

第三招：**把名册印出来**。

```c
void print_all(void) {
    for (int i = 0; i < count; i++) {
        printf("%s %d\n", list[i].name, list[i].score);
    }
}
```

三招都写完了，都能用。**现在请你看一眼它们的站位**：这三招，一个都不在图纸的花括号里，全在图纸外面另起一段。它们干活时动的是谁？动的是全局那一排 `list`，还有那个 `count` —— 伸手去够。

也就是说：**图纸管「长什么样子」，招式管「干什么」，两样东西各站各的，中间没有一根线连着。** 它们能凑到一起干活，全靠本喵记性好：记得名册摆在哪儿、记得每一招该喂什么喵。

再看一眼招式收东西的样子，这里有个很容易忘的坑：

```c
Student add_points(Student s, int n) {
    s.score = s.score + n;
    return s;
}
```

喊它的时候得这么喊：

```c
a = add_points(a, 5);
```

招式收下的，是**整只抄的一份**（这一手往后 C 线「图纸」那一课里会正式讲：整只可以整个搬）。招式在抄件上加完分，得有人把改进过的那份**叼回来、重新装回原处** —— 那个 `a =` 就是干这个的。忘了叼回来，名册上的数字纹丝不动：**数据不是招式的，招式只是中间那个搬货的。**

本喵做那台小鱼干计算器的时候，加减乘除也是这么散着站的 —— 那会儿没有数据要管，散着站一点不碍事。这回名册和招式得天天打照面，账就不一样了喵。

## 三、让改需求说话：来了几个交换生

名册用了一阵子，新需求来了：学堂要来几个**交换生**。交换生也是学员，只是——

1. 他们的记录要多记一样：**来自哪个学堂**；
2. 印名册的时候，交换生的名字后面**要多印一行小字**。

本喵不打折扣，把要动的地方从头数一遍：

1. **图纸要加一格** —— 比如加一行 `char from[20];`，多出来的那样东西才有地方住。
2. **入住那一招要改** —— `add_student` 现在只收名字和分数，得把「从哪儿来」也收进来，再写进新格。
3. **印名册那一招要改** —— `print_all` 得先分辨：这一行是普通学员还是交换生；是交换生，就多印一行。

**三处。** 而且第三处会一直长下去：它本来只是印字的一句活，从今往后**里面长出一条岔路**。下次再来一种「旁听生」，还得回这儿再岔一次 —— 每多一种学员，这一招就胖一圈喵。

比「三处」更值得记住的，是**为什么得挨个找**：图纸和招式站在两边，谁也不知道对方改了没有。名册改一下，本喵得凭记性把所有碰过它的招式都翻出来改；漏掉一处，一点红都不给你报 —— 名册就安安静静少印一行字。

这笔账本喵先记着，往后有一课专门带你去收拾它。

## 四、四位翻译官喵：招式都站在哪儿

同一件事，四位翻译官喵各写一遍：**一个学员，名字和分数，加一次分，印出来**。

```compare
c::
#include <stdio.h>
#include <string.h>

typedef struct {
    char name[20];
    int score;
} Student;

Student add_points(Student s, int n) {
    s.score = s.score + n;
    return s;
}

void report(Student s) {
    printf("%s：%d 分喵\n", s.name, s.score);
}

int main(void) {
    Student a;
    strcpy(a.name, "小橘");
    a.score = 60;
    a = add_points(a, 5);
    report(a);
    return 0;
}

cpp::
#include <iostream>
#include <string>
using namespace std;

class Student {
public:
    string name;
    int score;

    void add_points(int n) {
        score = score + n;
    }

    void report() {
        cout << name << "：" << score << " 分喵" << endl;
    }
};

int main() {
    Student a;
    a.name = "小橘";
    a.score = 60;
    a.add_points(5);
    a.report();
    return 0;
}

java::
public class Main {
    static class Student {
        String name;
        int score;

        void addPoints(int n) {
            score = score + n;
        }

        void report() {
            System.out.println(name + "：" + score + " 分喵");
        }
    }

    public static void main(String[] args) {
        Student a = new Student();
        a.name = "小橘";
        a.score = 60;
        a.addPoints(5);
        a.report();
    }
}

python::
class Student:
    def __init__(self, name, score):
        self.name = name
        self.score = score

    def add_points(self, n):
        self.score = self.score + n

    def report(self):
        print(f"{self.name}：{self.score} 分喵")

a = Student("小橘", 60)
a.add_points(5)
a.report()
```

```text
小橘：65 分喵
```

看出来了吗喵：四段干的是同一件事，**差别全在招式站在哪儿**：

- **C**：图纸里只有格子，招式站在外面；招式收东西收的是整只抄件，改完还得叼回来装好 —— 本喵就是那个搬运工。
- **C++**：招式画进了图纸的大括号里，身子里写的 `score`，指的就是**这一只自己**那一格，谁都不用搬。
- **Java**：也是招式画在图纸里；喊招式之前，得先 `new` 出一只来。
- **Python**：一样画在图纸里，`self` 就是「这一只自己」。

**先别急着下结论。** 把招式搬进图纸，只是让「长什么样」和「会什么」住到了同一张纸上 —— **这算不算把差的那半补齐了，还得过本喵在「两条路」那一课立下的判据句**：**封装＝藏数据、露行为**。下一课本喵并排摆两版给你看的时候，咱俩拿它一条一条对喵。

::: tip 猫咪提示
今天的账，三句话喵：

1. **C 的图纸只画格子** —— `struct` 里摆的全是数据，招式一只都进不去，只能站在外面。
2. **招式站在外面，就得有人搬货** —— 每次出手都要把学员、名册喂进去，改完了还得把结果叼回来装好；两边之间没有一根线连着，全靠本喵记性好。
3. **改需求最能说明问题** —— 加一样「来自」，就得挨个把碰过学员数据的招式翻出来改。这就是那半张图纸欠下的账。

术语表里，给「藏起数据、只露出口子」这一手起的名字叫**封装（带盖的小鱼干盒）**；量它够不够格的判据句，就是「两条路」那一课立下的那句：**封装＝藏数据、露行为**。往后每往前一步，本喵都拿它量一量喵。
:::

::: warn 小心喵
三个坑，标给你：

- **图纸加了新格，别的招式不会自己知道。** 谁碰过这张图纸，谁就得自己回去看一眼 —— 漏掉的那处不会报错，只会安安静静印错一行。
- **「招式收下的是整只抄的一份」这条别忘了。** `a = add_points(a, 5);` 里那个 `a =` 不是多余的，它就是「把改好的那份叼回来装回原处」；写成 `add_points(a, 5);`，名册上那个数一动不动。
- **别急着把 C 的写法判死刑。** 数据少、招式少的时候它确实好用；本喵这一课不是拆台，是让你亲眼看见**账是怎么一点一点欠下的**喵。
:::

## 一句话对照表

| 谁写的 | 招式住在哪儿 | 出手时，谁把学员交给招式 |
|---|---|---|
| C | 图纸外面 | 本喵亲手搬：整只抄一份，改完叼回来 |
| C++ | 图纸里面 | 不用搬，先说哪一只、再喊招式 |
| Java | 图纸里面 | 不用搬，`new` 出一只来喊 |
| Python | 图纸里面 | 不用搬，喊哪一只、哪一只自己动手 |

## 小任务

1. **数账练习**：如果下一个需求是「把每个学员的分数都加 10 分」，要动几处？先别动手，把要碰的地方一条一条列出来（提示：数一数有几招碰过 `score` 这一格）。
2. **上手跑一跑**：把本课 `add_points` 那几行抄进练习场，先原样跑一遍 `a = add_points(a, 5);`，再把 `a.score` 印出来；然后把前面的 `a =` 删掉、再印一遍。两次数不一样，分别说说是为什么喵。
3. **想一想**：下一课本喵把同一本名册写成两版并排给你看。你觉得过了那条判据句的那一版，在「加交换生」这个实验里会动几处？先猜，不许翻答案喵。
