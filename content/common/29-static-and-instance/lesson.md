## 钩子：门口那行字，本喵抄了一遍又一遍

上一课《盒子上留的口子》，本喵给图纸上的格子都盖好了盖子 —— 数据藏进盒子，只留几道口子给外面办事，「藏数据、露行为」这句判据句也就立住了。临下课，本喵留了个问题喵：

> 为什么每个程序一上来都是 `public static void main(String[] args)`？`static` 到底是块什么砖？

本喵把这几课写过的每一份程序翻出来对了一下：C 的开头是 `int main(void)`，C++ 的开头是 `int main()`，Java 的开头是 `public static void main(String[] args)`，Python 的开头是文件尾巴上那句 `if __name__ == "__main__":` —— 四块门牌长得各不相同，可「从哪儿进」这件事，四家都躲不开。

今天就把门口这行字拆开看。顺带回答标题里那个问题：**一个类（一张图纸）到底能造几只猫？**

## 门是门，院子是院子

一份程序从哪里开始跑？从门口进。门后面才是院子 —— 院子里有几只猫、活该怎么分、账该怎么记，那是**设计**的事；门只回答一件事：**从哪儿进**。

- **C 的门**：`int main(void) { ... }`，整份程序从这儿开始；
- **C++ 的门**：`int main() { ... }`，也是从这儿开始；
- **Java 的门**：`public static void main(String[] args) { ... }`，挂在一张图纸上；
- **Python 的门**：文件尾巴上那句 `if __name__ == "__main__":` —— 意思是「只有本文件被直接跑起来，才从这儿进」。

门就一扇，**别把家当都堆在门口**：门口堆满了东西，进出的人得先绕着走一圈 —— 这门就成了仓库喵。

## `static`：画在图纸上的那一份

前几课立过一条规矩：图纸上写着「每只猫都有名字、都有账」，照它生出来的每一只，**各带各的仓库** —— 改橘猫的名字，狸花那份一动不动。

可有一类东西，不按这条规矩走。

本喵拿「一共开过几局」这种数试了试：记在小橘那局头上？那狸花那局开局的时候，谁跑去把小橘的数加一？小橘那局先散了，数又该寄在哪儿？—— 记在哪一局头上都不对喵。

它**不属于任何一局，它属于整张图纸**。这种成员，术语表里的说法是**静态成员（画在图纸上的那一份）**，写法就是在前面加一个关键字 `static`。跟它相对的、每只真猫自己带着走的那一份，叫**实例成员（每只真猫自己带的那一份）** —— 照图纸生出来的每一只，就是一个**实例**。

（本喵的猫猫图纸，换个比方说就是一张**蓝图** —— 蓝图只有一张，照着它盖出来的房子，才是一栋栋能住人的。）

念法上也分了家喵：

- **画在图纸上的那份，拿图纸名去念**：Java 写 `Game.plays`，C++ 写 `Game::plays`；
- **每局自己那份，拿真猫名去念**：`game.fish`。

`Game.plays` 读作「`Game` 这张图纸上的 `plays`」。多写那几个字母不是啰嗦 —— 它一眼就告诉读代码的人：**这一份不是哪一局自己的东西**。

## 第一版：把整份程序塞进门里

光讲道理没意思，本喵摆两份代码给你看喵。

先照老习惯来：一局猫猫游戏整个塞进门口。规则很简单 —— 报开局、抓三圈（2、1、3 条）、收工报总数。

```java
public class Main {
    static int fish = 0;                        // 一局的账，挂在门口
    static void play(int round, int got) {      // 抓一圈
        fish = fish + got;
        System.out.println("第 " + round + " 圈：抓到 " + got + " 条");
    }

    public static void main(String[] args) {
        System.out.println("开局！");
        play(1, 2);
        play(2, 1);
        play(3, 3);
        System.out.println("收工！一共 " + fish + " 条");
    }
}
```

```text
开局！
第 1 圈：抓到 2 条
第 2 圈：抓到 1 条
第 3 圈：抓到 3 条
收工！一共 6 条
```

能跑，本喵认账喵。可盯住看 —— 这一版里**每一件家当都挂着 `static`**：`static int fish`（账）、`static void play`（抓一圈的招式），连 `main` 自己也是 `static`。

拆开看，这三者性质并不一样：

- **门挂 `static`，是被逼的**：程序起步那一刻，一局游戏都还没生出来。没有真猫站在旁边，能喊的就只有画在图纸上的招式 —— 门那行的 `static` 不加，程序根本跑不起来喵（翻译官喵放行，一按运行就被拦下来）。
- **账和招式也挂着，是没人逼的**：`fish` 明明是「一局的账」、`play` 明明是「一局在抓」，却被钉在了门口。

这正是把 C 那套原样搬进图纸的样子：**一扇门 + 一叠自由招式**，数据与动作分开住。这份写法在 C 的地盘上**不丢人** —— C 里本来就没有图纸这回事。可原样搬进图纸里还这么写，就是给过程式的程序**套了层壳**：外头像图纸，里头还是老样子喵。

## 第二版：生一只真猫，让它自己跑

同一局游戏、同一份输出，只换写法喵：

```java
class Game {
    int fish = 0;                       // 这一局自己的账

    void play(int round, int got) {
        fish = fish + got;
        System.out.println("第 " + round + " 圈：抓到 " + got + " 条");
    }

    void run() {
        System.out.println("开局！");
        play(1, 2);
        play(2, 1);
        play(3, 3);
        System.out.println("收工！一共 " + fish + " 条");
    }
}

public class Main {
    public static void main(String[] args) {    // 门：只剩两行
        Game game = new Game();                 // 生一局
        game.run();                             // 喊它自己跑
    }
}
```

```text
开局！
第 1 圈：抓到 2 条
第 2 圈：抓到 1 条
第 3 圈：抓到 3 条
收工！一共 6 条
```

同一份输出，差别不在「能不能用」，在**谁的活**：

- `int fish` 前面没有 `static` —— 账跟着每一局自己走；
- `play`、`run` 前面也没有 `static` —— 它们不是画在图纸上的，它们在**等一只真猫来喊**；
- 门里只剩两行：**生一局，喊它自己跑**。

第一版里，门厅塞着整份游戏；这一版里，设计全长在图纸上，门退回了它本来的角色 —— 一扇门喵。

## 一个类（一张图纸）能造几只猫？

回到标题里那个问题。

第二版里本喵只写了 `new Game()` 一次。想再开一局？**再喊一声就行**：

```java
Game a = new Game();
Game b = new Game();
```

一张图纸，两局游戏。喊三声三局，喊一百声一百局 —— 图纸一个字都不用改。每一局各带各的账（`a.fish` 是 a 的，`b.fish` 是 b 的），谁也碰不着谁。

而画在图纸上的那一份（比如「一共开过几局」那种数）**全院只有一份**：两局都念得到它、动得了它 —— 因为它本来就不属于任何一局喵。

所以边界的判据句可以立起来了：

> **它是不是每一只（每一局）自己都得有一份？**
> 是 → 跟着真猫走（不加 `static`）；不是 → 画在图纸上（加 `static`）。

## 四位翻译官喵，同一局游戏

同一件事：**开一局猫猫游戏** —— 报开局、抓三圈（2、1、3 条）、收工报总数喵。C 拿得出的只有「门里全塞满」那一版；后三位都把设计放回了图纸，门里只剩两三行。

```compare
c::
#include <stdio.h>

int fish = 0;                        /* 账飘在门厅里，谁都能碰 */

void play(int round, int got) {
    fish = fish + got;
    printf("第 %d 圈：抓到 %d 条\n", round, got);
}

int main(void) {
    printf("开局！\n");
    play(1, 2);
    play(2, 1);
    play(3, 3);
    printf("收工！一共 %d 条\n", fish);
    return 0;
}

cpp::
#include <iostream>
using namespace std;

class Game {
public:
    int fish;                        // 这一局自己的账

    Game() : fish(0) {}              // 出生那一刻把账起成 0

    void play(int round, int got) {
        fish = fish + got;
        cout << "第 " << round << " 圈：抓到 " << got << " 条" << endl;
    }

    void run() {
        cout << "开局！" << endl;
        play(1, 2);
        play(2, 1);
        play(3, 3);
        cout << "收工！一共 " << fish << " 条" << endl;
    }
};

int main() {
    Game game;                       // 生一局
    game.run();                      // 它自己跑
    return 0;
}

java::
class Game {
    int fish = 0;                    // 这一局自己的账

    void play(int round, int got) {
        fish = fish + got;
        System.out.println("第 " + round + " 圈：抓到 " + got + " 条");
    }

    void run() {
        System.out.println("开局！");
        play(1, 2);
        play(2, 1);
        play(3, 3);
        System.out.println("收工！一共 " + fish + " 条");
    }
}

public class Main {
    public static void main(String[] args) {    // 门：两行
        Game game = new Game();                 // 生一局
        game.run();                             // 它自己跑
    }
}

python::
class Game:
    def __init__(self):
        self.fish = 0                # 这一局自己的账

    def play(self, r, got):
        self.fish = self.fish + got
        print(f"第 {r} 圈：抓到 {got} 条")

    def run(self):
        print("开局！")
        self.play(1, 2)
        self.play(2, 1)
        self.play(3, 3)
        print(f"收工！一共 {self.fish} 条")

if __name__ == "__main__":           # 门：只有直接跑本文件，才从这儿进
    Game().run()
```

```text
开局！
第 1 圈：抓到 2 条
第 2 圈：抓到 1 条
第 3 圈：抓到 3 条
收工！一共 6 条
```

看出来了吗喵：

- **C**：C 只有第一版 —— 门里就是全部家当，账（`fish`）飘在外面谁都能碰。这份写法在 C 的地盘上不丢人；本课只提醒一句：**别把它原样搬进图纸里**。
- **C++**：生一局写 `Game game;`，喊它跑写 `game.run();`。C++ 里「画在图纸上」也有一模一样的正牌写法：招式前面写 `static`，之后拿图纸名喊 `Game::run()` —— 和 Java 的 `Game.run()` 是一个意思；那一门课里细讲。
- **Java**：入口那行的 `static` 这回彻底拆明白了 —— 起步时一局都没有，门只能挂在图纸上；`new Game()` 生一局，`game.run()` 由它自己跑。
- **Python**：文件尾巴那句 `if __name__ == "__main__":` 就是 Python 的门 —— 它管「从哪儿进」，不管设计。想在 Python 里写「挂在图纸上、不用哪一局自己」的招式，要在招式头上盖一个小戳 `@staticmethod` —— 今天点到为止，往后见到它认识就行。

四句话收拢：**门，每门语言都有一扇，只负责进；`static` 回答的是「这东西属于谁」；设计放回图纸上，门里就只剩「生一只、喊一声」**。

::: tip 猫咪提示
今天记住三句话喵：

1. **`main` 是一扇门**：只管「从哪儿进」，不管设计。门里该只剩「生一只、喊一声」，别把家当都堆在门口。
2. **`static` ＝画在图纸上的那一份**：属于整张图纸、不属于任何一只真猫；念它的时候拿图纸名去念（`Game.plays`、`Game::plays`），读代码的人一眼就分得清。
3. **一个类能造几只猫？想几只生几只**：每一只各带各的**实例成员（每只真猫自己带的那一份）**；图纸上那份，全院只有一份。
:::

::: warn 小心喵
三个坑，本喵标出来：

- **别给「每一只自己都要有」的东西加 `static`**：名字、这一局自己的账，加上它就变成全院共用一份 —— 三局下来互相盖住，只剩最后动过的那个数。加之前先过一遍判据句：**它是不是每一只（每一局）自己都得有一份？**
- **「编译不过」不是加 `static` 的信号**：在 Java 里，图纸上的招式回头去碰某只真猫自己的格子，翻译官喵会当场拦下：`non-static variable fish cannot be referenced from a static context` —— 它说的是「你现在站的这招旁边没有真猫，够不着人家的格子」。正解是**把这一招也交还给真猫**（去掉 `static`、拿真猫名喊），而不是给格子贴一个 `static` 了事。
- **`Game.run()` 和 `game.run()` 打在两个东西上**：前者喊的是画在图纸上的招式（得先画上 `static`）；后者喊的是一局真游戏自己会的招式。少看一个大小写，意思就跑到对面去了喵。
:::

## 一句话对照表

| 本喵写下的 | 它的意思 |
|---|---|
| `public static void main(String[] args)` | Java 的门：程序从这儿进；那个 `static` 是被逼的 —— 起步那一刻还没有任何一局 |
| `if __name__ == "__main__":` | Python 的门：只有直接跑本文件，才从这儿进 |
| `static int plays = 0;`（画在图纸里） | 画在图纸上的那一份：整张图纸共用，不属于哪一局 |
| `Game.plays` / `Game::plays` | 拿图纸名念：这是图纸上的东西，不是哪一局自己的 |
| `game.fish` | 拿真猫名念：每一局自己那本账 |
| `Game game = new Game();` | 照图纸生一局真游戏 |
| `game.run();` | 喊这一局自己会的那一招 |
| `Game.run()`（C++ 里写作 `Game::run()`） | 想拿图纸名喊招式：那招式得是先画上 `static` 的 |
