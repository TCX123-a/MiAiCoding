## 钩子：招聘启事上的第一题，不是两个数

上一课，本喵跟着老祖宗学了一招：大的减小的、一次减到底，两个数被越啃越小，最后停在 21——那把能同时量尽两根鱼干的最长尺子。那一课的世界很小，小到一张桌子上只摆两个数，爪子一左一右就够用了喵。

可大肥鱼贴出来的招聘启事上，第一题压根不是两个数，而是一整张网：鱼塘和鱼塘之间谁认识谁、哪条小路通向哪、从本喵坐的这个点出发能摸到哪些点。面试官大肥鱼把这张网往桌上一拍：「先别急着走，你打算怎么把它记下来？」

两个数能装进两个仓库，一张网可装不进去。这一课就干一件事：**给「谁认识谁」找一种记得住、查得快的写法**。

## 图是什么：点、边，还有方向

一张图其实只有两样东西：

- **点**，也叫**顶点**：一个具体的东西——一个鱼塘、一只猫、一座城市、一件任务。
- **边**：两个点之间的一条关系——一条小路、一次认识、一趟航班、一句「我得先等你完成」。

拿大肥鱼世界的鱼塘举例：0 号塘、1 号塘、2 号塘、3 号塘、4 号塘。塘与塘之间有小路，那「塘」就是点，「小路」就是边。这张图只关心一件事：**谁和谁连**。塘画在地图左边还是右边、路是直的还是弯的，都不影响这张图。所以画图的时候，本喵经常把点随手一摆，只要连线的两头对得上，图就没变喵。

边还有几种脾气，面试里会直接考：

**无向边**：小路两头都能走。0 号塘和 1 号塘之间有条小路，那从 0 能到 1，从 1 也能到 0。猫和猫「互相认识」也是无向的——本喵认识你，你也认识本喵。画的时候就是一条没有箭头的线。

**有向边**：单行道，或者「关注」这种一头热的关系。本喵关注了大肥鱼，不代表大肥鱼关注了本喵。3 号猫关注 7 号猫，就画一条从 3 指向 7 的箭头；反过来有没有路，得看有没有 7 → 3 那根箭头。

**带权边**：边上还写了个数。两塘之间的小路走一趟要 8 分钟，那这条边的权就是 8；不带权就只记「通」或「不通」。带权图在后面算最省时间的那条路时是主角，这一课先记住「边上可以挂数字」这回事。

面试里说「图」，默认就是「点 + 边」这两样，别的都是修饰。有向、无向、带权、不带权，是把这四件事交叉着问。

## 两种记法之一：一张大表格（邻接矩阵）

最直白的记法：既然点都有编号，那就摆一张 n 行 n 列的大表格——**行是出发的点，列是到达的点**。

n 个点就 n×n 格。格子里写 1 表示有边，写 0 表示没边；带权图就把 1 换成权，没边的地方写 0 或者一个很大的数（看题目怎么约定）。查的时候，第 i 行第 j 列那个格子，回答的就是「i 到 j 有没有一条直接的边」。

用本喵那 5 个塘、5 条小路走一遍：0—1、0—2、1—2、2—3、3—4。

| 从\到 | 0 | 1 | 2 | 3 | 4 |
|---|---|---|---|---|---|
| 0 | 0 | 1 | 1 | 0 | 0 |
| 1 | 1 | 0 | 1 | 0 | 0 |
| 2 | 1 | 1 | 0 | 1 | 0 |
| 3 | 0 | 0 | 1 | 0 | 1 |
| 4 | 0 | 0 | 0 | 1 | 0 |

看第 2 行：2 号塘到 0、1、3 有路，到 4 没路，所以这一行从左到右是 `1 1 0 1 0`（列号 0 到 4，2 号自己那一格是 0）。再看整张表——它沿着对角线对称：0 能到 2，2 也能到 0；1 能到 2，2 也能到 1。无向图的表格天生对称，这是个很好用的自查办法：写完表格瞄一眼，不对称就说明某条边漏记了一半喵。

邻接矩阵的好处很干脆：**查「i 和 j 之间有没有边」，抬爪子就是 O(1)**——直接翻到第 i 行第 j 列，不用找。

坏处也一样干脆：**格子数是 V²，跟边多边少没关系**。10000 个点就是 1 亿格，哪怕整张图只有 20000 条边，那 1 亿格也得老老实实摆着。所以它适合**稠密图**——边数接近 V²、表格里大部分格子都不空的时候，这些格子不算白占。

还有一个容易说错的点：查一条边 O(1)，**不等于邻接矩阵什么都快**。要列出某个点的全部邻居，还是得把它那一整行 n 格从头看到尾，是 O(V)；要是把每个点的邻居都找齐，总共 O(V²)。「快」是分动作的，面试官问「查询快不快」时，得先问清楚查的是一条边，还是一整串邻居喵。

## 两种记法之二：每个点挂一串邻居（邻接表）

换个思路：本喵不摆大方阵，**每个点只开一格，格子里挂一串「我直接认识谁」**。

还是那 5 个塘、5 条小路：

| 点 | 挂着的邻居 |
|---|---|
| 0 | 1, 2 |
| 1 | 0, 2 |
| 2 | 0, 1, 3 |
| 3 | 2, 4 |
| 4 | 3 |

在 Python 里，这正好是一只大柜子：柜子的钥匙是点的编号，抽屉里是一串邻居。写法就是 `adj = {}`，`adj[0]` 取出来的就是 0 号的邻居串。点如果就是从 0 到 n-1 的连续编号，也可以直接摆 n 个格子，拿编号当位置去取，省掉查找这一步。

它的账得这么算：

- **占的地方**：V 个点各开一格，加上真实存在的边。无向图每条边要在两头各记一次，所以总共存 2E 条邻居记录——记作 **O(V+E)**。
- **看某一个点的全部邻居**：顺着它那一串从头走到尾，串有多长就走多久，代价是 **O(这个点的度数)**。
- **把所有点的邻居都看一遍**：每条邻居记录正好被走一次，总共 **O(V+E)**。

跟矩阵比，差别就在「只记真的有的」。稀疏图里 E 远小于 V²，邻接表能把大片空格子全省下来；可要是图很稠密，几乎每两个点都连着，那 2E 也快赶上 V² 了，这时邻接表省不出多少空间，反倒多了一层「顺着串找」的麻烦。所以「邻接表一定比矩阵省」这句话是不成立的，得看图稠不稠喵。

## 一条边记几笔：无向两边记，有向记出发

这是建图时最容易翻车的地方，单独拎出来说。

**无向图，一条边记两次。** 0—1 这条小路：往 0 号的串里加一个 1，也要往 1 号的串里加一个 0。为什么？因为无向边两个方向都能走。要是只记了 0 号这边，从 0 号出发能找到 1 号，可从 1 号出发就找不到 0 号了——同一张图，换个起点就少了一半路，后面不管算什么都跟着错。

**有向图，只记出发方向。** 3 → 7 这根箭头：只在 3 号的串里加 7，7 号的串里**不加** 3。除非另有一根 7 → 3 的箭头，那才在 7 号的串里加 3。箭头朝哪，邻居就往哪边挂。

这里还藏着一个能省很多事的结论：**无向图里，所有点的度数加起来 = 2E**。每条边有两个端点、被数两次；反过来，把总度数除以 2，就是边数。这个等式后面既能用来验算，也能直接用来做题。有向图里也有对应的一句：所有点的出度加起来 = 所有点的入度加起来 = E，因为每根箭头正好给出发那一头记一次出度、给到达那一头记一次入度。

## 度数：数一数谁认识谁

**度数**就是「这个点身上挂着几条边」。

- **无向图**：度数 = 邻居个数。2 号塘有三条小路通出去，度数就是 3。
- **有向图**：分成两本账。**出度** = 从这个点指出去的箭头数；**入度** = 指到这个点上的箭头数。

把前面那张 5 点图完整走一遍：

| 点 | 邻居 | 度数 |
|---|---|---|
| 0 | 1, 2 | 2 |
| 1 | 0, 2 | 2 |
| 2 | 0, 1, 3 | 3 |
| 3 | 2, 4 | 2 |
| 4 | 3 | 1 |

全部加起来：2 + 2 + 3 + 2 + 1 = 10。图里正好 5 条边，10 = 2 × 5，对上了「总度数 = 2E」喵。要是你算出来是 9 或者 11，别怀疑公式，回头查边表——多半是某条边的某一头漏记了。

再看一张有向的：箭头是 3 → 7、7 → 9、3 → 9。

| 点 | 入度 | 出度 |
|---|---|---|
| 3 | 0 | 2 |
| 7 | 1 | 1 |
| 9 | 2 | 0 |

3 号猫关注了 7 号和 9 号，自己没被谁关注，所以出度 2、入度 0；9 号被 3 和 7 关注，自己谁也不关注，入度 2、出度 0。所有点的入度加起来是 0 + 1 + 2 = 3，出度加起来是 2 + 1 + 0 = 3，都等于边数。面试里让你「数一下入度和出度」，其实就是在考你有没有分清箭头的两头喵。

## 为什么大厂爱考图

面试官大肥鱼不是随便挑的题。现实世界里「谁和谁有关系」的东西太多了，图就是它们的通用写法：

- **社交关系**：好友是互相的，无向图；关注是一头热的，有向图。找「共同好友」「几度人脉」都是在图上走。
- **地图导航**：路口是点，路是边，路的长度、堵不堵是权。找最快路线，就是在带权图上找一条代价最小的路。
- **依赖关系**：装一个工具要先装另一个，编一个大项目要先编某个模块——点是一件任务，边是「必须先完成」。这种图要是有向、又没绕回来的圈，就能排出一个先后次序。
- **状态转移**：游戏里每个局面是一个点，走一步能到的局面连一条有向边；自动售货机、电梯、红绿灯，都能这么画。

这些题有个共同的开头：**先把图建出来**。建图这一步选错记法、或者无向边只记了一边，后面的搜索、最短路线、先后次序全是空中楼阁。所以面试官爱看你怎么建，比看你怎么背结论更准喵。

## 落到代码上：从边表建邻接表

原始数据常常是**边表**：一行一条边，`[0, 1]` 就表示 0 号和 1 号之间有一条边。它最省事，可查「0 号认识谁」得把整张边表从头扫一遍。所以第一步永远是：**边表 → 邻接表**。

```python
edges = [[0, 1], [0, 2], [1, 2], [2, 3], [3, 4]]

adj = {}
for u, v in edges:
    adj.setdefault(u, []).append(v)
    adj.setdefault(v, []).append(u)

total = 0
for v in range(5):
    print(f"{v}: 邻居{adj[v]} 度数{len(adj[v])}")
    total += len(adj[v])
print(f"总度数 {total}, 边数 {total // 2}")
```

```text
0: 邻居[1, 2] 度数2
1: 邻居[0, 2] 度数2
2: 邻居[0, 1, 3] 度数3
3: 邻居[2, 4] 度数2
4: 邻居[3] 度数1
总度数 10, 边数 5
```

`adj.setdefault(u, []).append(v)` 这一句是整段的核心，拆开看是两件事：`setdefault(u, [])` 说「如果 u 号还没有格子，就先给它开一个空抽屉；已经有了，就把原来的抽屉拿出来」，后面 `.append(v)` 再把 v 塞进去。**无向图所以写两行**：`adj[u]` 里加 v，`adj[v]` 里也加 u——一条边记两笔，一笔都不能少。

最后那个圈把每个点的邻居串印出来，顺手把串的长度（也就是度数）加起来。总度数 10，除以 2 得 5，正好是边表的行数——这就是「总度数 = 2E」在代码里的样子喵。你也可以把 `edges` 里的某条边删掉再跑一遍，看看度数和边数是不是一起变，验算的感觉就出来了。

## 三位翻译官喵：数度数

同样的 4 条边，三份程序都只干一件事：把每条边的两个端点各加一度，再印出每个点的度数，最后印出边数。看的时候盯住两处——**每条边加了哪两个点的度数**，以及**最后一个数是边表有几行**。

```compare
cpp::
#include <iostream>
#include <vector>

int main() {
    std::vector<std::vector<int>> edges = {{0, 1}, {0, 2}, {1, 2}, {2, 3}};
    std::vector<int> degree(4, 0);
    for (const auto& e : edges) {
        degree[e[0]]++;
        degree[e[1]]++;
    }
    for (int i = 0; i < 4; i++) {
        std::cout << "degree[" << i << "]=" << degree[i] << std::endl;
    }
    std::cout << "edges=" << edges.size() << std::endl;
    return 0;
}

java::
public class Main {
    public static void main(String[] args) {
        int[][] edges = {{0, 1}, {0, 2}, {1, 2}, {2, 3}};
        int[] degree = new int[4];
        for (int[] e : edges) {
            degree[e[0]]++;
            degree[e[1]]++;
        }
        for (int i = 0; i < 4; i++) {
            System.out.println("degree[" + i + "]=" + degree[i]);
        }
        System.out.println("edges=" + edges.length);
    }
}

python::
edges = [[0, 1], [0, 2], [1, 2], [2, 3]]
degree = [0] * 4
for u, v in edges:
    degree[u] += 1
    degree[v] += 1
for i in range(4):
    print(f"degree[{i}]={degree[i]}")
print(f"edges={len(edges)}")
```

```text
degree[0]=2
degree[1]=2
degree[2]=3
degree[3]=1
edges=4
```

三份输出一个字不差喵。0 号连着 1、2，度数是 2；2 号连着 0、1、3，度数是 3；四个度数加起来 2 + 2 + 3 + 1 = 8，正好是 4 条边的两倍。这就是「无向图每条边被数两次」在三种语言里同一个样子。

1. **选记法看两件事**：图稠不稠、你接下来要干什么。稠密图、又常查「两点之间有没有边」，n×n 表格顺手，查一条 O(1)；稀疏图、又要顺着邻居一圈圈走，每个点挂一串更省，占 O(V+E)。没有哪一种是「一定更好」的喵。
2. **无向图的两笔是成对的**：看到 `adj[u].append(v)`，就顺手想一下 `adj[v].append(u)` 写了没有；看到总度数，就顺手想一下它是不是 2E。
:::

::: warn 小心喵
两个坑：

- **无向边只记一边**：从没记的那头出发，会以为这条路不存在。建图时漏一笔，后面搜索会少一整片点，还不报错——这种错最难抓，得靠「总度数 = 2E」这种等式当场验。
- **把「查一条边 O(1)」当成「邻接矩阵什么都快」**：要列出一个点的全部邻居，矩阵还是得扫一整行，O(V)；把所有点的邻居都列齐是 O(V²)。邻接表列某个点的邻居是 O(度数)，把所有邻居都走一遍总共 O(V+E)。快慢要看你让它干什么活喵。
:::

## 小任务

1. 拿本课那张 5 点图，把 2 号点在邻接矩阵里的那一行写出来，再把邻接表里 2 号挂的邻居写出来；两个答案对一对，想想为什么它们说的是同一件事。
2. 给 5 点图再加一条边 0—4，重新算每个点的度数和总度数，用「总度数 = 2E」验算一遍。
3. 有向图的箭头是 0 → 1、1 → 2、2 → 0，算算三个点各自的入度和出度；再想想：为什么不管怎么加箭头，总入度永远等于总出度？

图记住了，可面试官大肥鱼问：**从本喵坐的这个点出发，到底能走到哪些点？** 邻接表只告诉本喵「一步能到谁」，可一步之后呢？两步之后呢？哪些点根本摸不到？下一课，本喵就顺着邻居串一路往下摸，摸到没路可走再退回来——一条路走到黑。去『一条路走到黑——深度优先搜索』看看喵～ 🐾
