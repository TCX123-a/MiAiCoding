## 钩子：一嗓子喊下去，各吃各的

上一课《先抄三遍，再抽一张公共图纸》里，本喵把两张几乎一样的图纸往上提成了一张**公共图纸（父类）**：小图纸「照着它来」，白捡全部设定，只补自己那一条不一样的地方。上一课还先露了一手**盖掉、换自己那版** —— 小图纸把大图纸的一招换成自己那一版 —— 本课要把它真正用起来。

今天本喵站在碗边，手里攥着开饭的名单，喊一声：

> **开饭啦 —— ！**

名单上站着一排住户：猫、鸟，往后还可能有狗、有鱼。本喵指望的是：猫吃小鱼干、鸟啄谷子，**一嗓子下去，各吃各的**。

可本喵现在这套家伙什，是「给每位住户贴个编号、再在外面写一句 `switch`」的老写法。能跑，可本喵心里发毛：**园里每添一位新住户，本喵都得回来动这同一句老代码。**

今天分三幕：第一幕看它怎么跑；第二幕等新住户上门，看它怎么疼；第三幕把它请出去。走喵。

## 第一幕：老写法，先看个够

先照老习惯写一版。两格数据装进盒子，开饭那一招站在盒子**外面**，靠编号分流：

```c
#include <stdio.h>
#include <string.h>

typedef struct {
    char name[20];
    int type;                 /* 0 = 猫，1 = 鸟 */
} Animal;

void feed(Animal *a) {        /* 开饭这一招，站在盒子外面 */
    switch (a->type) {
        case 0:
            printf("%s：吃小鱼干\n", a->name);
            break;
        case 1:
            printf("%s：啄谷子\n", a->name);
            break;
    }
}

int main(void) {
    Animal cat;
    strcpy(cat.name, "小橘");
    cat.type = 0;

    Animal bird;
    strcpy(bird.name, "小啾");
    bird.type = 1;

    feed(&cat);
    feed(&bird);
    return 0;
}
```

```text
小橘：吃小鱼干
小啾：啄谷子
```

能跑，跑得还挺好。拆开看，这一版有三样东西值得盯住喵：

1. **盒子里装着一个编号** `type`：说好 0 是猫、1 是鸟 —— 这份「对照表」不写在任何图纸上，只活在写代码的人脑子里；
2. **开饭那一招站在盒子外面**：它得同时知道「猫吃什么、鸟吃什么」—— 园里有多少种住户，这一招就得背下多少套吃法；
3. **谁来吃，靠一句 `switch` 分流**：编号是几，就走哪一支。

丑话说在前面：**这一版一点都不丢人**。前面那些课本喵全是这么写的，它也是 C 世界里最常见的写法 —— C 里没有「每只动物自己会一招」这台现成的机器，招只能站在外面，靠编号认人。

## 第二幕：新住户上门，回来改同一句 switch

园里来了条狗「大黄」，它啃骨头。本喵抄起家伙什，数一数要动几处：

- 脑子里那份对照表得补一句「2 = 狗」—— **一处**；
- `feed` 里再添一支 `case 2:` —— **两处**；
- 最要命的是第三样：这句 `switch` 一改，**原来那两支也得跟着重测一遍** —— 猫还吃小鱼干吗？鸟还啄谷子吗？本喵动的是两行字，「心里要过的账」却是一整段。

**改一处，惊动全城。** 而且这不是一次性的疼：园里每添一位新住户，就再来一轮。养到三十只，这句 `switch` 长成半屏，本喵每回动它都手抖。

等一下 ——「改一处惊动全城」这句，本喵听着耳熟。上一课把两张图纸的公共部分往上提，治的也是「同一件事写在两处」的病：一处改了、另一处忘了跟上，两处就打架喵。可那回治的是**重复**；这回这句 `switch` 一点都不重复 —— 它错在**把所有住户的饭量都塞进了同一个脑袋**。新住户跟它八竿子打不着，可它一到，本喵就得动这句老代码。

新东西来了，老东西不该被惊动。有没有办法？

## 第三幕：把「吃」交给每只动物自己

办法是把「吃」这件事**从外面搬回家**：谁吃，谁自己会。就两句主心骨：

1. **大图纸上写下一招** `eat` —— 先把「住户都有这招」这层约定立在图纸上；
2. **每张小图纸把它换成自己那一版**：猫那版印「吃小鱼干」，鸟那版印「啄谷子」。这一手就是上一课见过的**盖掉、换自己那版**。

搬完家，外面那句 `feed` 不见了，只剩一句话：轮到谁，喊谁的 `eat()`。

**这一句话凭什么就「各吃各的」？** 因为它不是照着纸面念的。本喵把名单摆出来说：

- 名单的每一格，都是一只**遥控器**，遥控器上印的画，是「动物」；
- 可遥控器对着的那台**电视机**，一只是猫、一只是鸟；
- 按同一个键 `eat()` 的那一瞬，**电视机自己放自己那一版** —— 挑哪一版，看它**对着谁**（也就是真身是谁），不看遥控器上印的字。

（这个比喻前几课就立下了，本课要背着用：**写着名字的那张纸是遥控器，不是电视机本身。**）

「小图纸生出来的，装进印着大图纸的格子」这件事，行话里叫**向上转型** —— 一支印着「动物」的遥控器，对着的可以是一只猫，因为猫本来就是动物。

这一手，术语表里叫**多态（一声开饭，各猫各样）**：同一句喊话，各猫各样 —— 本课这声喊话更实在：各吃各的。本喵在《两条路》那课墙上钉过一张路线图 —— 上面这一站早就钉好了，就叫**一声开饭各吃各的**，今天兑现喵。

「挑哪一版，跑起来那一瞬才定」这件事，行话里叫**动态绑定**。本喵把两个时刻摆开看：

- **写代码那一关**：翻译官喵只看得见遥控器上印的字 —— 它只查一件事：「动物这张图纸上有没有 `eat` 这招？」有，这行就放行；至于跑的是哪一版，这一关**根本不管**；
- **跑起来那一瞬**：电视机的真身是谁，就放哪一版。

于是那句让本喵卡了半天的话 —— `Animal a = new Cat(); a.eat();` 凭什么出猫那一版 —— 谜底就在这一行里：**左边写的是遥控器的型号，右边 new 出来的是电视机的真身。** 按下去，看真身。

## 四位翻译官喵，同一嗓子开饭

同一件事：喊一声开饭，让猫和鸟各吃各的。

```compare

cpp::
#include <iostream>
#include <string>
using namespace std;

class Animal {
protected:
    string name;
public:
    Animal(string n) : name(n) {}
    virtual void eat() {          // virtual：小图纸那一版才盖得上
        cout << name << "：……" << endl;
    }
};

class Cat : public Animal {
public:
    Cat(string n) : Animal(n) {}
    void eat() {                  // 重写：猫自己那一版
        cout << name << "：吃小鱼干" << endl;
    }
};

class Bird : public Animal {
public:
    Bird(string n) : Animal(n) {}
    void eat() {                  // 重写：鸟自己那一版
        cout << name << "：啄谷子" << endl;
    }
};

int main() {
    Cat cat("小橘");
    Bird bird("小啾");
    Animal *pets[2] = { &cat, &bird };   // 印着「动物」的遥控器，对着两只真身
    for (int i = 0; i < 2; i++) {
        pets[i]->eat();                  // 一行字，各答各的
    }
    return 0;
}

java::
class Animal {
    protected String name;

    Animal(String name) {
        this.name = name;
    }

    void eat() {
        System.out.println(name + "：……");
    }
}

class Cat extends Animal {
    Cat(String name) {
        super(name);
    }

    @Override
    void eat() {
        System.out.println(name + "：吃小鱼干");
    }
}

class Bird extends Animal {
    Bird(String name) {
        super(name);
    }

    @Override
    void eat() {
        System.out.println(name + "：啄谷子");
    }
}

public class Main {
    public static void main(String[] args) {
        Animal[] pets = { new Cat("小橘"), new Bird("小啾") };
        for (Animal pet : pets) {
            pet.eat();
        }
    }
}

python::
class Animal:
    def __init__(self, name):
        self.name = name

    def eat(self):
        print(f"{self.name}：……")

class Cat(Animal):
    def eat(self):
        print(f"{self.name}：吃小鱼干")

class Bird(Animal):
    def eat(self):
        print(f"{self.name}：啄谷子")

pets = [Cat("小橘"), Bird("小啾")]
for pet in pets:
    pet.eat()
```

```text
小橘：吃小鱼干
小啾：啄谷子
```

看出来了吗喵：**四段都在完成「喊一声、各吃各的」，可只有后三位不用回来改老代码。**

- **C**：还是第一幕那一版 —— 招站在外面，靠 `type` 分流。想添住户，就得回来改这句 `switch`。C 里没有「大图纸挂一招、小图纸自己写一版」这台现成的机器，想这么干得自己动手搭；
- **C++**：大图纸那一招前面挂上 `virtual`，小图纸那版才盖得住。**记住这个词：忘写，它就退回「照遥控器上印的字念」的老脾气，而且不报错** —— 详见下面的「小心喵」；
- **Java**：`@Override` 是给翻译官喵看的记号：它帮本喵盯着「名字有没有抄对、括号里那几样有没有抄歪」，抄错了当场拦下；不写也能跑，但写下它就是给自己请了个校对员；
- **Python**：直接写一个同名的 `def eat` 盖上，没有 `virtual` 这种开关 —— 喊 `pet.eat()` 能不能应、应哪一版，全看它自己。

四位翻译官喵的共识一句话：**老世界把「各吃哪一口」收在一句 `switch` 里；新世界把它交还给每只动物自己。**

## 大图纸上写不出的那一招

刚才大图纸上那版 `eat`，印的是「……」。本喵盯着它看了一会儿，越看越别扭：**「动物吃」这个动作，大图纸自己真会做吗？** 猫吃小鱼干、鸟啄谷子 —— 一只「普普通通的动物」，该怎么吃？写不出来。

写不出来，就别硬装。干脆只留一张标签：大图纸那一招只写名字、不写身体。挂着这种标签的图纸，行话里叫**抽象类（写不出动作的图纸）**。

- **Java** 把标签写成 `abstract`，图纸名和招名上各挂一个：`abstract class Animal { abstract void eat(); }`（招式后面连花括号都省了）。这样的图纸**不能直接拿来生** —— `new Animal()` 会被翻译官喵拦下：世上没有「纯粹的动物」这一只；
- **C++** 的写法是给那一招挂上 `virtual`、再补一句 `= 0`：`virtual void eat() = 0;`，同样生不出本体；
- **Python** 不管这道关：大图纸上那一招你不写内容（写个 `pass` 占位），它也不拦你生猫 —— 想把「必须自己实现」立成规矩，得额外请一个工具（`abc`），往后学到那儿再细说。

再往上走一步：有时本喵要的不是一张图纸，而是一份**约定** —— 不管你是猫、是鸟、还是机器人，只要「会打招呼」就能签。这份约定，术语表里叫**接口（与猫的约定）**。这两种写法要回答的问题不同，本课先记最要紧的一句对照：

- **`extends` 回答「你是**什么**」** —— 猫是动物，讲亲缘，白捡大图纸的设定；
- **`implements` 回答「你会**做**什么」** —— 会打招呼的都算数，讲的是一份行为契约，跟亲缘毫无关系。

::: tip 猫咪提示
今天记住三句话喵：

1. **一句话，各答各的**：调用处只留 `pet.eat()` —— 写的时候不用管手里是谁，跑起来那一瞬，由它**对着的那台电视机**（真身）决定应哪一版。这一手叫**多态（一声开饭，各猫各样）**；
2. **`extends` 是「你是什么」，`implements` 是「你会做什么」**：前者讲亲缘（猫是动物），后者讲契约（会打招呼的都算数）；
3. **判据句**：新住户进门，老代码动没动？—— **一个字都不用改**，才算把这声开饭请出去了。
:::

::: warn 小心喵
两个坑，本喵提前标出来：

- **C++ 忘写 `virtual` = 安静地退回老脾气**：大图纸那一招不挂 `virtual`，`Animal* p = &cat; p->eat();` 就会跳出**大图纸兜底那版** —— 不报错、不崩溃，行话里叫静态绑定。这个坑的脾气是：错了不喊疼，只有盯着结果才能发现。解法就一个词，写上；
- **重写 ≠ 重载**：中文名长得像，机制是两码事。**重写（override）**是「小图纸把大图纸那一招换成自己一版」（名字、括号里那几样都一样）；**重载（overload）**是「同一个名字配好几副括号」，跟图纸套图纸毫无关系 —— 往后学语言线会专门讲它。今天先立块界碑：**看它换掉的是不是大图纸上的那一招**。
:::

## 一句话对照表

| 本喵写的 | 它的意思 |
| --- | --- |

| `virtual void eat();` | C++：大图纸那招挂上开关，小图纸那版才盖得住（忘写就退回兜底版） |
