## 钩子：一箱活，本喵不知道发给谁

上一课《Python 的底牌：连 3 都是对象》里，本喵换了一副眼镜看 Python —— 变量（贴在本体上的名字），不是装东西的盒子；连 3、连招式都有自己的底牌。世界是看清了，可回到桌上，本喵手里还是一箱没派出去的活喵。

这回的活叫「小鱼干银行」：猫们把吃不完的小鱼干存进来，要用的时候再取。仔细一数，牵进来的角色不止一个：

- **账上的数**有规矩：余额不能乱改，每一笔支出都得先验一验够不够；
- **猫**有规矩：一次买几袋、花掉的要记到自己今天的账上；
- **狗粮店**有规矩：摆出今天的货、报出价格。

本喵摊开纸要动手，笔悬在半空 —— 每一句其实都写得出来（这一路的本事都学过了），可**谁守哪条规矩、谁跟谁打交道、要改动时该找谁**，一样都还没想清楚。等写歪了再回头，要动的地方就不是一处了。

今天不学新语法喵。今天学的是一件**动手之前的手艺**：把这箱活摊在卡片上，先问明白 —— **这是谁的活？**

## 老习惯：先列两栏清单

按着 C 里养成的老习惯，本喵会先列两张单子：

- **数据结构这一栏**：银行要有「余额」；猫要有「名字」和「今天花了多少」；狗粮店要有「货架」和「价签」。
- **招式这一栏**：`spend`（先校验、再扣账）、`buy`（替猫跑一趟）、`restock`（狗粮店补货）……

单子列得齐，代码也跑得动 —— 本喵不宣布这条路输了喵。前面几十课，这两栏一直是好帮手。可今天要盯着看一个字：所有活**混在同一张单子上**的时候，改动来了，找谁？

比如哪天规矩改了：「花超了得给个提示」。这一笔该动哪儿 —— 是账上的规矩动了，还是猫买东西的手法变了，还是店里的价签摆错了？单子上**没有一栏叫「这是谁的活」**，本喵只能把整个故事在脑子里重过一遍。角色一多，这一遍就过不起了喵。

## 三列卡片：它叫什么、守什么、找谁

老前辈猫留了一件小工具：一个角色一张卡片，卡片上竖着三列喵。

| 卡片（谁） | 职责：它守的规矩 | 协作：它的活要找谁 |
|---|---|---|
| **FishBank 小鱼干银行** | 守余额；每一笔支出先校验，过了才扣账 | DogFoodStore 狗粮店（付出去的钱要拨到店里的账上） |
| **Cat 猫** | 决定买几袋；花掉的记到自己今天的账上 | FishBank 小鱼干银行 |
| **DogFoodStore 狗粮店** | 摆出今天的货、报出价格 | —— |

这样的卡片，行话叫 **CRC 卡片** —— 三个字母取的是三栏名的头一个字母：Class（图纸）、Responsibility（职责）、Collaboration（协作）。本喵管它叫**分工卡片**喵。

三列的读法：

- **第一列是「谁」**：一个角色一张卡，卡名就是图纸要起的名字。**卡片不是图纸本身** —— 它是动手之前，把「这个角色的活」先写清楚的草稿。
- **第二列是职责**：这个角色**得守的规矩**。注意它可不是「会做哪些动作」的花名册 —— 写职责的口诀是**按变化的原因切，不按动词切**。
- **第三列是协作**：**它的活要找谁**。银行要跟店结账，写 DogFoodStore；猫花钱要找银行，写 FishBank。这一栏是把角色之间那几根线画下来 —— 谁喊谁，照着看就行。

「按变化的原因切」是什么意思喵？本喵拿银行试一条：哪天新增规矩「每一笔支出留一条流水」—— 这是**账怎么记**的规矩，和「先校验、再扣账」是同一个缘由，写进银行卡；再来一条「一天最多买五袋」—— 那是**猫怎么花**的规矩，写进猫卡。哪块改动来了只有哪张卡片要动，职责就算切对了。

列卡片的顺序也有讲究：**先把角色找出来，再各自写职责，最后把线连上**。哪一栏卡了壳，就说明这块活本喵还没想明白 —— 卡壳的收获，比顺笔写下去大得多喵。

## 从卡片到代码：四位翻译官喵的骨架

卡片填完，动手就有谱了 —— 照着它，同一场「买几袋（花 30 条小鱼干）」，四门语言各搭一副骨架喵：

```compare
c::
#include <stdio.h>

typedef struct {
    int balance;                  /* 银行的家底：一格余额 */
} FishBank;

int spend(FishBank *bank, int n) {    /* 「先校验、再扣账」站在图纸外面 */
    if (n > bank->balance) {
        return 0;                     /* 不够：一分钱都不动 */
    }
    bank->balance = bank->balance - n;
    return 1;
}

int main(void) {
    FishBank bank = {100};
    if (spend(&bank, 30)) {           /* 「猫」这个角色没落到纸上，买由 main 演 */
        printf("橘猫：买到了\n");
    } else {
        printf("橘猫：余额不够\n");
    }
    printf("余额：%d\n", bank.balance);
    return 0;
}

cpp::
#include <iostream>
#include <string>
using namespace std;

class FishBank {
    int balance;
public:
    FishBank() : balance(100) {}

    bool spend(int n) {               /* 职责：守余额、先校验再扣账 */
        if (n > balance) {
            return false;
        }
        balance = balance - n;
        return true;
    }

    void show() {
        cout << "余额：" << balance << endl;
    }
};

class Cat {
    string name;
    int spent;
public:
    Cat(const string &n) : name(n), spent(0) {}

    void buy(FishBank &bank, int n) { /* 职责：买、记账；协作：银行是参数表里的一位 */
        if (bank.spend(n)) {
            spent = spent + n;
            cout << name << "：买到了" << endl;
        } else {
            cout << name << "：余额不够" << endl;
        }
    }
};

int main() {
    FishBank bank;
    Cat cat("橘猫");
    cat.buy(bank, 30);
    bank.show();
    return 0;
}

java::
class FishBank {
    private int balance = 100;

    public boolean spend(int n) {
        if (n > balance) {
            return false;
        }
        balance = balance - n;
        return true;
    }

    public void show() {
        System.out.println("余额：" + balance);
    }
}

class Cat {
    private String name;
    private int spent = 0;

    public Cat(String n) {
        name = n;
    }

    public void buy(FishBank bank, int n) {
        if (bank.spend(n)) {
            spent = spent + n;
            System.out.println(name + "：买到了");
        } else {
            System.out.println(name + "：余额不够");
        }
    }
}

public class Main {
    public static void main(String[] args) {
        FishBank bank = new FishBank();
        Cat cat = new Cat("橘猫");
        cat.buy(bank, 30);
        bank.show();
    }
}

python::
class FishBank:
    def __init__(self):
        self._balance = 100

    def spend(self, n):               # 职责：守余额、先校验再扣账
        if n > self._balance:
            return False
        self._balance = self._balance - n
        return True

    def show(self):
        print(f"余额：{self._balance}")

class Cat:
    def __init__(self, name):
        self._name = name
        self._spent = 0

    def buy(self, bank, n):           # 职责：买、记账；协作：银行由参数递进来
        if bank.spend(n):
            self._spent = self._spent + n
            print(f"{self._name}：买到了")
        else:
            print(f"{self._name}：余额不够")

bank = FishBank()
cat = Cat("橘猫")
cat.buy(bank, 30)
bank.show()
```

```text
橘猫：买到了
余额：70
```

看出来了吗喵：**四段照着同一张卡片，可「谁落在纸上」差得可远了**。

- **C**：卡片的「谁」栏只落得下一半 —— 银行是一个装数据的 `struct` 加一招站在外面的 `spend`，两样还是分家的；**「猫」这个角色连图纸都没有**，「买」由 `main` 里几行自己演。角色没画出来，协作那根线也就无处可落。
- **C++**：两张图纸都立起来了。看 `Cat::buy` 的参数表：多了一位 `FishBank &bank` —— 卡片「协作」栏那一行，在 C++ 里就是**参数表里的一位**。
- **Java**：同样两张图纸，生角色喊 `new`。递进 `buy` 的那位 `bank`，是**遥控器不是电视机** —— 猫按一下，动的就是真银行。
- **Python**：`_balance`、`_spent` 前面那一个下划线就是盖子（家规守的）；协作也一样，是参数表里递进来的一位。

四位翻译官喵的共识只有一句：**协作栏写谁，参数表里就多一位** —— 角色之间的线，落到代码里就是「谁把谁递进来」喵。

## 先问三句，再决定要不要套图纸

卡片填顺了，路口还有一个坑等着：两位角色之间画了一根线，这根线要不要画成图纸套图纸（继承）？老习惯是看见两个东西有关系，手就痒 —— 本喵在这里立三句口诀，写完卡片先问自己一遍喵：

- **is-a：它是它的一种吗？** 「橘猫是猫的一种」—— 这才轮到**图纸套图纸**：把公共的那半截提上去，小图纸白捡大图纸的设定。
- **has-a：它身上带着一位它吗？** 「猫身上带着一只碗」—— 这种关系用**组合**：把帮手请进自己身上，当自己的一份家底。一句话记法：**组合＝请帮手进门**。
- **uses-a：只是喊它来干一次活吗？** 「画布喊笔刷来涂一次色」—— 投喂一次就够，谁也不搬进谁家。

判据句跟图纸套图纸那几课立下的那句接得上 —— **「是一种」才套图纸，「有一条」放进格子**。换上小名就是：**只有 is-a 才配套图纸**；剩下两种关系，图纸套图纸一个都不配。本喵见过最典型的写反：「猫有一种碗」，有人手一抖写成 `class 碗 extends 猫`。碗是猫的一种吗？不是 —— 碗只是猫身上带着的一位帮手：请进门（组合），别套图纸喵。

还有一句要摆正：**has-a 优先**。不是「逮着关系就套图纸」，是「**拿不准就先请帮手**」。帮手看得见、换得掉、拆得动；图纸套图纸把两代图纸焊在一起，往后动大图纸，小图纸全跟着动 —— 所以真要套图纸，先过了 is-a 那一关再说喵。

## 什么时候，别硬套图纸

最后一个过冲要拦住：卡片这么好用，是不是**每样东西都该照图纸生一只**？本喵把同一件小事写两版给你看 —— 把一条账单印成一串字：

```python
class BillPrinter:
    def format(self, name, n):
        return f"{name} 买了 {n} 袋，花了 {n * 5} 条小鱼干"
```

```python
def format_bill(name, n):
    return f"{name} 买了 {n} 袋，花了 {n * 5} 条小鱼干"
```

两版**一模一样地干活**。可第一版多套了一层壳 —— 拿三句话量一量它喵：

1. **它有自己的家底吗？** 没有 —— 它一次都没记住过东西，来了就印、印完就走；
2. **它守一条规矩吗？** 没有 —— 印错了也怪不着它；
3. **它有不止一种做法吗？** 没有 —— 就这一种印法，改也是直接改这一句。

三问全「没有」，那这层壳就是白套的：**留它当一道招式就很好**。真正该上卡片的，是像银行、猫这样 —— **有家底、有规矩、有人跟它打交道**的角色。纯数据的小脚本也一样：几张单子、几步算完，用招式列着走，又快又清楚喵。

换句话收束：**图纸这一手是给「有规矩要守的角色」准备的**，不是给全天下每样东西发户口。

::: tip 猫咪提示
今天的手艺，一句话一套喵：

1. **动手之前先摆三列卡片**：谁 / 职责 / 协作 —— 它叫什么、守哪条规矩、活要找谁，先落到纸上；
2. **职责按变化的原因切**，不按动词切 —— 哪块改动来了只有哪张卡片要动，就算切对了；
3. **关系先问三句**：is-a 才配套图纸；has-a 请帮手进门（拿不准就先组合）；uses-a 投喂一次就够；
4. **不是所有东西都该照图纸生一只**：没有家底、不守规矩、就一种做法的活，留在招式里。
:::

::: warn 小心喵
两个坑，本喵标出来：

- **「卡片写得越细越好」是错觉**：职责不是动词清单 —— 把「存钱、取钱、算利息、发短信、打印回执」一股脑挤进银行卡片，看着热闹，可利息的规矩和短信的规矩根本不是一回事，一处改动拖着一整张卡片动。按**变化的原因**拆开，才对得上「谁的活」这四个字喵。
- **套图纸的肌肉记忆要按住**：看见两个角色有关系，就 `extends` 一挥 —— 十条里九条走反。记住判据：**只有 is-a 才配套图纸**；拿不准就先组合 —— 帮手看得见、换得掉、拆得动。
:::

## 这张卡片，会跟你走多远

三列卡片不是本课用完就收的道具喵。语言线那边的综合项目，开工时都在做同一件事：

- C++ 线的《综合项目：猫猫宠物管理系统》—— 托儿所开张，登记、念名册、分大小之前，先把自己问明白：一只猫得记哪几格、会哪几手、哪几格扣盖子；
- Java 线的《综合项目：待办事项管理器》—— 一条事项长什么样、谁收着一摞事项、谁管存进册子和读回来，先分家；
- Python 线的《综合项目：通讯录（文件版）》—— 谁守那本「喊名字就说话」的本子、谁管档案的存与读，同理。

到那时候你会发现：**今天这三列，就是那些大项目的第一张草稿** —— 卡片先站住，代码才不乱喵。
