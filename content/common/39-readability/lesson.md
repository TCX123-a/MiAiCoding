## 钩子：祖传文件里的一声惨叫

上一课本喵刚把「管家」请进门 —— 构建这事写成了文件，一条命令替你造。可管家再能干，它造的还是**一行行代码**。代码打哪儿来？打人手里来喵。

今天本喵翻到一份不知哪一任前辈留下的文件。爪子点开它，本喵当场叫出了声：

**「这代码写得太丑啦喵！」**

```python
a1 = 5
a2 = 3
a3 = (a1 if a1 > a2 else a2) + (a2 if a1 > a2 else a1)
print(a3)
```

```text
8
```

它跑得动 —— 屏幕上老老实实印出一个 `8`（这一段本喵真跑过）。可它到底在算什么？本喵盯了半分钟：括号套着问句，`a1`、`a2` 像两张没写用途的账单 —— 原来它在「取大的那个，再加小的那个」，把两个数求和绕成了三重问句喵。

跑得动，不等于没事。这一课就来说清楚：**丑的代价是什么，公司为什么要立规矩。**

## 代码被读的次数，是写出来的十倍

写的时候总觉得「写」是主角。可工程圈有一句话本喵越用越服：**代码被读的次数，是它被写出来的次数的十倍。**

- 写：一次，也许五分钟；
- 读：改需求要读、抓虫要读、三个月后接锅的**还是你** —— 早忘了当初怎么想的。

所以「丑」不是审美问题，是**成本问题**：每丑一分，读的人多花一分钟；一万人读过它，账单就乘一万。翻译官喵（编译器 / 解释器）从来不在乎名字美不美 —— 叫 `a1` 还是叫好名字，它都照跑不误；**读代码的不是它，是下一位同行，是未来的你。**

## 炫技的三种长相

写代码的人都有过一段手痒期，工程圈管这类毛病叫**炫技** —— 把「显得会得多」放在「让人读得懂」前面。本喵把见过的炫技数了数，逃不出三种长相喵。

**第一种：一行里塞三个三目。** 「不成立就换那个」的问句本身没错，错的是把它们挤成一团：

```c
#include <stdio.h>

int main(void) {
    int x = 5;
    int y = 3;
    printf("%d\n", x > y ? (x > 0 ? x : 0) : (y > 0 ? y : 0));
    return 0;
}
```

```text
5
```

三位「审问官」挤在同一行，读的人得在脑子里给每个括号配一张地图。输出是 `5` —— 可读完这行的人，先得喘口气喵。

**第二种：`a1`、`a2`、`a3` 当名字。** 钩子里那段已经现过身：三个名字念出来像报账，看不出哪个装鱼、哪个装猫。名字是读代码的人**唯一不用往回翻的线索**，省这几个字符，亏的是后面每一次阅读。

**第三种：把简单的事写成谜语。** 比如求 1 到 5 的和，偏要写成 `print((lambda n: (n * (n + 1)) // 2)(5))` —— 一条藏起来的公式，读的人得先解谜才知道它和求和有关。写得短，读得长，账不划算喵。

三种长相有个共同的病根：**写的时候只想着自己，没想着读的人。**

## 走一遍：丑名字与好名字

同一个「5 加 3」，本喵摆两版给你看 —— 一版丑、一版好，一句一句跟着读喵：

```demo
title: 丑名字与好名字
code:
| a1 = 5
| a2 = 3
| a3 = a1 + a2
| print(a3)
| fish_in_basket = 5
| fish_in_bowl = 3
| total_fish = fish_in_basket + fish_in_bowl

step 丑版第一行：名字读不出意思
at: 1
say: `a1 = 5` —— 5 是什么？5 条小鱼干，还是 5 只猫？名字没说。读代码的人第一眼就得开始猜 —— **猜，就是丑名字收的第一笔过路费**。
meow: a1 是什么？猜猜看～
pose: think
屏幕上的输出 = 还没跑
读代码的橘猫 = 眉头拧成麻花

step 丑版接着走：算式也是谜语
at: 3
say: `a3 = a1 + a2` —— 现在能猜到「两个数相加」了，可加的是哪两个数？明天要改需求，谁敢动这一行？**丑名字的债，记在每一次回头改的路上。**
meow: 能跑，但读不懂喵……
pose: soothe
屏幕上的输出 = 还没跑
读代码的橘猫 = 眉头皱着

step 好版登场：名字开始说人话
at: 5
say: `fish_in_basket = 5` —— 同一个 5，换了个读完就懂的名字：筐里有 5 条。名字是给读代码的人看的，不是给翻译官喵看的。
meow: 筐里有 5 条，一眼就懂喵！
pose: guide
屏幕上的输出 = 还没跑
读代码的橘猫 = 眉头舒开了

step 好版收官：一行的意图
at: 7
say: `total_fish = fish_in_basket + fish_in_bowl` —— 一眼读出：总数 = 筐里的 + 碗里的。名字换好，连注释都省了 —— **自解释**说的就是这个味。
meow: 总数 = 筐里的 + 碗里的，读得真顺～
pose: proud
屏幕上的输出 = 8
读代码的橘猫 = 点点头
```

两版跑出来一样，都是 `8` —— 翻译官喵分不出谁美谁丑。**这笔账，只有读代码的人来结。**

## 丑代码的三种代价

丑不是白丑的，账单会分三期来喵：

- **第一期：改一处，坏一片。** 名字含糊的代码像没贴标签的抽屉，改的人只能「先动了再说」，一动手就碰倒别的格子。抓虫时最要命 —— 你盯着 `a3` 想半天：它是求和还是求差？猜错方向，一下午就没了。
- **第二期：新人上不了手。** 团队来了新人，读你的文件像读天书，带他的老手一天里半天在当翻译 —— 这部分工资，是丑代码发的。
- **第三期：未来的你，认不出过去的你。** 三个月后需求回来了，你点开文件：这写的什么？……认真一看，写的人是你自己。**未来那个你，是读代码的名单里最常出现的一位**，别让他天天骂街喵。

## 企业为什么立规矩

一个人写代码，「丑」顶多烦自己。可公司里是**一群人往同一个地方写** —— 张三的 `a1`、李四的 `user_name`、王五的 `UserName` 挤在一起，谁都不肯让步，读的人当场崩溃。

于是有了**规范**。先把一件事想明白：规范不是审美警察，它解决的是**协作**问题 ——

- 十个人写出来像**一个人**写的，读到陌生文件不用重新适应口音；
- 新的名字照着老名字起，猜中率极高：**一致的丑，好过混乱的美**；
- 规矩上墙之后，讨论「该叫什么」的时间就省下来了 —— 那是团队最贵的成本之一。

一句话：**规范是团队省钱的办法，不是管人的鞭子。** 企业立规矩，降的全是协作成本。

::: tip 猫咪提示
今天立的规矩，一句话收好喵：

1. **代码是写给人看的** —— 翻译官喵不在乎，同行在乎、未来的你在乎；
2. **可读性大于炫技** —— 一行三个三目、`a1` 当名字、把求和写成谜语，三种长相都别再犯；
3. **丑的代价分三期** —— 改一处坏一片、新人上不了手、未来的自己骂街；
4. **规范是协作的省钱法** —— 一致 > 好看，先求全队一个口音。
:::

## 同一件小事，四位翻译官喵的好名字

道理讲完，看活的喵。同一件小事 —— **求 1 到 5 的和** —— 四门语言各按自家的习惯起名字：

```compare
c::
#include <stdio.h>

int sum_to(int limit) {
    int total = 0;
    for (int i = 1; i <= limit; i++) {
        total += i;
    }
    return total;
}

int main(void) {
    printf("合计 %d 条小鱼干喵\n", sum_to(5));
    return 0;
}

cpp::
#include <iostream>

int SumTo(int limit) {
    int total = 0;
    for (int i = 1; i <= limit; ++i) {
        total += i;
    }
    return total;
}

int main() {
    std::cout << "合计 " << SumTo(5) << " 条小鱼干喵" << std::endl;
    return 0;
}

java::
public class Main {
    static int sumTo(int limit) {
        int total = 0;
        for (int i = 1; i <= limit; i++) {
            total += i;
        }
        return total;
    }

    public static void main(String[] args) {
        System.out.println("合计 " + sumTo(5) + " 条小鱼干喵");
    }
}

python::
def sum_to(limit):
    total = 0
    for i in range(1, limit + 1):
        total += i
    return total


print(f"合计 {sum_to(5)} 条小鱼干喵")
```

```text
合计 15 条小鱼干喵
```

四段本喵全真跑过，印出来**逐字相同**。名字呢，一个比一个有讲究：

- **C**：`sum_to` —— 全小写、词之间用下划线，C 家族的老口音；
- **C++**：`SumTo` —— 招式名开头大写，是 Google 那本尺子定的；
- **Java**：`sumTo` —— 小驼峰，头一个字小写、后面每个词的首字母抬头；
- **Python**：`sum_to` —— 下划线写法，跟 C 家有点像亲戚。

「谁家为什么这么写」下一课、下下课慢慢拆 —— 今天先记一件事：**它们有一处完全一致 —— 名字都老老实实说了「求和」，没有一个叫 `f` 或 `js`。** 好名字的方言各有各的，说人话这件事，四家是一伙的喵。
