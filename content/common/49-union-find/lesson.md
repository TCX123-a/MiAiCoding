## 钩子：面试官只问一句「他俩一伙吗」

上一课，你为了回答一个「到底行不行」，把所有摆法都试了一遍：走不通就退回来，退回来再换一条，直到把整棵决策树摸了个遍，才敢开口。面试官大肥鱼听完，摆摆爪子：「太慢。我不问你怎么走，也不问你走了几步。我只问一句——他俩是不是一伙的。」

这一问，把题目的味道全换了。上一课关心的是「把所有方案都摆出来」；今天连方案都不用摆，只关心「这两个点是不是在同一个圈子里」。给你一堆「谁和谁认识」的消息，然后反复问「这两个是不是一伙」，这种问题有个正经名字叫**并查集**，本喵管它叫**帮派户口本**。

## 一伙一伙：每个帮派推一个老大

操场上蹲着五只猫，编号 0 到 4。有人递来三张纸条：0 和 1 是朋友，1 和 2 是朋友，3 和 4 是朋友。

现在问：0 和 2 是一伙的吗？1 和 4 是一伙的吗？

笨办法是顺着朋友关系一条一条走——0 认识 1，1 认识 2，所以 0 和 2 一伙；1 和 4 之间怎么走都走不通，所以不是。这不就是前面「一条路走到黑」那一课的本事吗？能答对，但每次问都要重新走一遍。

并查集换了个存法：**每个帮派推一个代表，叫根；每只猫只记一件事——我的上级是谁。** 整本户口本就长这样：

| 点 | 0 | 1 | 2 | 3 | 4 |
|---|---|---|---|---|---|
| parent | 0 | 0 | 1 | 3 | 3 |
| 怎么读 | 自己当根 | 上级是 0 | 上级是 1 | 自己当根 | 上级是 3 |

`parent[x]` 就是「x 的上级是谁」的座位号。`parent[0] = 0` 表示 0 没有上级，自己管自己——这样的点就是**根**。`parent[2] = 1` 表示 2 的上级是 1；1 的上级又是 0；0 是根。于是 2 这一伙的代表就是 0。

这里只有一排格子，没有邻接表，也没有整张图的边。为什么够用？因为「是不是一伙」等价于「顺着上级爬到顶，根是不是同一个」。你不需要知道 0 和 2 中间隔了几层，只要它俩最后都爬到同一个根，就是一个帮派。

更重要的一点：**合并两个帮派时，只需要改一个根的上司**，不用挨个通知全帮派的人。这是并查集快起来的根本原因——它从不维护「每个人属于哪个帮派」这种要全员更新的信息，只维护「我的上级是谁」。

举个反例就明白了：假如每个点直接记「我属于 0 号帮派」，那 0 号和 3 号帮派合并时，3 号帮派里每个人都要把记录改一遍；人越多，改得越多。parent 只记上级，合并时改一个根就够——剩下的点下次被问到的时候，顺着上级自然就爬到新根了。

## find：顺着上级一路问到顶

`find(x)` 干的事就一句话：**从 x 出发，顺着 parent 一路往上，直到遇到一个自己管自己的点。**

拿上面的户口本走一遍 `find(2)`：

| 现在问谁 | parent[它] | 下一步 |
|---|---|---|
| 2 | 1 | 去 1 |
| 1 | 0 | 去 0 |
| 0 | 0 | 自己管自己，停：根是 0 |

所以 `find(2) = 0`。再走 `find(4)`：4 的上级是 3，3 的上级是 3，停，根是 3。`find(2)` 和 `find(4)` 一个报 0、一个报 3，根不同，说明 2 和 4 不是一伙。

写成代码就一行：`while parent[x] != x: x = parent[x]`。

停下来的条件很关键：`parent[x] == x`。这时候 x 没有上级，它就是根。反过来，要是 `parent[x] != x`，说明 x 上面还有人，继续往上问。

再强调一次：根不是哪个固定的「帮派编号」，它会随着合并变。今天 0 是根，明天 3 号帮派并过来、按大小挂到 0 下面，根还是 0；反过来要是 0 那伙更小，根就可能变成 3。所以判断两个人是不是一伙，不能背「他属于 0 号帮」，必须现场顺着上级爬一遍，看终点是不是同一个。

这一步的代价要看链子有多长。最坏的情况，所有点挂成一条直链 0→1→2→…→n-1，`find(0)` 得走 n-1 步。问一次还好，问一万次就难受了。后面两个优化，一个管「走一次就把路拉直」，一个管「别让链子长起来」。

## union：两个帮派拜把子

`union(a, b)` 要把 a 和 b 所在的两个帮派并成一个。做法分三步：

1. 先找 `ra = find(a)`、`rb = find(b)`；
2. 如果 `ra == rb`，说明他俩早就是一伙的，什么都不用做；
3. 如果不一样，就把其中一个根挂到另一个根下面，比如 `parent[rb] = ra`。

注意第 3 步挂的是**根**，不是 a 本人。要是写成 `parent[a] = b`，而 a 又不是根，那就出事了：a 原来那伙的其他人还指着老根，a 自己却跑去了 b 那一伙，一个帮派被劈成两半，`find` 会给出自相矛盾的答案。**合并只能动根的上司。**

拿 5 个点、3 条边实际走一遍。一开始每个点自己一伙，parent 是 `[0, 1, 2, 3, 4]`，每伙的人数都是 1：

| 加的边 | 两端的根 | 谁挂到谁下面 | parent 变成 |
|---|---|---|---|
| 初始 | — | — | [0, 1, 2, 3, 4] |
| (0, 1) | 0 和 1 | 平手，1 挂到 0 | [0, 0, 2, 3, 4] |
| (1, 2) | 0 和 2 | 2 挂到 0 | [0, 0, 0, 3, 4] |
| (3, 4) | 3 和 4 | 平手，4 挂到 3 | [0, 0, 0, 3, 3] |

三条边处理完，数一数谁还是根：`parent[0] == 0`、`parent[3] == 3`，一共 **2** 个根。根有几个，帮派就有几个——所以连通块数量是 **2**：一伙是 {0, 1, 2}，另一伙是 {3, 4}。

这个「数根」的收尾很常用：一个点要么是根，要么上面还有人；每个帮派恰好有一个根。扫一遍所有点，数 `parent[i] == i` 的个数，就是连通块数。

## 路径压缩：问一次，全帮派直连老大

假设前面几次合并偷了懒，把点挂成了一条链：

| 点 | 0 | 1 | 2 | 3 |
|---|---|---|---|---|
| parent | 1 | 2 | 3 | 3 |

`find(0)` 要走 0→1→2→3，三步才见到根 3。下次再问 `find(0)`，还是这三步——明知道答案，路却一点没变短。

**路径压缩**就是在这时候动手：既然这一趟已经知道了根是 3，那回头的路上，把经过的每个点都直接挂到 3 下面。parent 从 `[1, 2, 3, 3]` 变成 `[3, 3, 3, 3]`。下次 `find(0)` 一步到根，`find(1)` 也是一步。树被压扁了，深度从三层变成一层。

实现上分两趟走：

- 第一趟只问路：从 x 一路往上，找到根；
- 第二趟回头拉直线：再从 x 出发，把沿途每个点的 parent 直接改成根。

第二趟必须等根确定了才能干，所以不能一边往上走一边改——你还不知道终点在哪呢。

具体到代码，先用 `nxt` 把旧的上级存下来，再把 `parent[x]` 改成根，最后让 x 跳到 `nxt`。这个顺序不能乱：先改 parent 再记 nxt，就把下一步的路踩断了；忘了跳到 nxt，x 就会在原地打转。

路径压缩只改「上级」这一件事。压缩前后，根没变、帮派成员没变、`find` 的答案也没变，变的只是路的形状。要是压缩完答案变了，那就是把谁的上级改错了。

> **本喵提醒**：路径压缩不是「每次都能一步到根」。第一次碰到长链子，该走的步一步都少不了；它的好处是「问过一次之后，后来的人就快了」。所以分析代价时要说**摊还**，不能拍着胸口说每次都严格 O(1)。

## 按大小合并：小帮派并进大帮派

路径压缩管的是「已经走出来的路」，可要是合并的顺序不讲究，链子还是会越接越长。

比如每次都无脑写 `parent[ra] = rb`，拿边 (0,1)、(1,2)、(2,3)、(3,4) 这么并：

| 边 | 无脑挂法 | parent |
|---|---|---|
| (0, 1) | 0 挂到 1 | [1, 1, 2, 3, 4] |
| (1, 2) | 1 的根挂到 2 | [1, 2, 2, 3, 4] |
| (2, 3) | 2 的根挂到 3 | [1, 2, 3, 3, 4] |
| (3, 4) | 3 的根挂到 4 | [1, 2, 3, 4, 4] |

五只猫挂成了一条 0→1→2→3→4 的长蛇，`find(0)` 要走四步。要是有一万个点，就是九千九百九十九步。

**按大小合并**（有的书上叫按秩合并，思路一样）就是给每个根记一笔「我这伙有多少人」：合并时比较两伙的大小，**把小树的根挂到大树的根下面**，再把人数加到大树头上。

同样这四条边，改用按大小合并：

| 边 | 两个根与大小 | 怎么挂 | parent |
|---|---|---|---|
| (0, 1) | 0(1)、1(1) | 平手，1 挂到 0 | [0, 0, 2, 3, 4] |
| (1, 2) | 0(2)、2(1) | 2 挂到 0 | [0, 0, 0, 3, 4] |
| (2, 3) | 0(3)、3(1) | 3 挂到 0 | [0, 0, 0, 0, 4] |
| (3, 4) | 0(4)、4(1) | 4 挂到 0 | [0, 0, 0, 0, 0] |

每次都是单个点并进越来越大的那伙，树高始终是一层。

为什么这招能压住高度？因为一棵树只有在被挂到**不小于自己**的树下面时，高度才可能加一；而每加一次，包含某个点的树至少翻一倍。一个点最多翻 log₂(n) 次，所以树高不会超过 log₂(n)。直链那种「一万个点九千九百九十九层」的惨状，构造不出来了。

把两个优化一起用：**单次操作的摊还代价是 O(α(n))**。α 是一个增长慢到离谱的量，来自阿克曼构造的反向——日常能遇到的规模里，它最多也就是 4 左右，所以实际用起来可以近似看成常数。但请注意两个词：**摊还**、**近似**。摊还是「偶尔一次慢，摊到很多次操作上平均很便宜」，不是「每一次都保证一步到位」；只做路径压缩也能用，只是别把它的单次代价说成严格 O(1)。

::: warn 小心喵
两个最容易在面试里说错的点：

- **并查集只回答「通不通」，不回答「多远」**。它不知道两点之间隔几条边，更不知道带权的路哪条最便宜。拿它求最短路，是让户口本去干导航仪的活。
- **「摊还 O(α(n))」不等于「严格 O(1)」**。单次 `find` 碰上长链子，照样可能走很多步；两个优化保证的是长期平均下来的代价。
:::

## 落到代码上

把上面的东西拼起来。`find` 用两趟走法做路径压缩，`union` 用按大小合并，最后扫一遍数根：

```python
parent = [0, 1, 2, 3, 4]
size = [1, 1, 1, 1, 1]

def find(x):
    root = x
    while parent[root] != root:
        root = parent[root]
    while parent[x] != root:
        nxt = parent[x]
        parent[x] = root
        x = nxt
    return root

def union(a, b):
    ra = find(a)
    rb = find(b)
    if ra == rb:
        return False
    if size[ra] < size[rb]:
        ra, rb = rb, ra
    parent[rb] = ra
    size[ra] += size[rb]
    return True

edges = [(0, 1), (1, 2), (3, 4)]
for a, b in edges:
    union(a, b)

count = 0
for i in range(5):
    if parent[i] == i:
        count += 1
print(count)
```

```text
2
```

几个地方值得盯一眼：

- `find` 的第一段 `while parent[root] != root` 只负责找根；第二段 `while parent[x] != root` 才回头改上级。`nxt` 先把旧的上级存下来，再改 `parent[x]`，不然一改就把下一步的路踩断了。
- `union` 里 `if size[ra] < size[rb]: ra, rb = rb, ra` 是保证 `ra` 永远是大树的根。平手时按原样，把 `rb` 挂到 `ra` 下面。
- `union` 返回 `False` 表示「两端本来就在一伙」——这个信息后面判环要用。
- 最后数根：`parent[i] == i` 的点就是根。例子跑完 parent 是 `[0, 0, 0, 3, 3]`，根是 0 和 3，所以印出 **2**。

## 三位翻译官喵，同一本户口本

同样的五个点 0~4、同样的三条边 (0,1)、(1,2)、(3,4)，三位翻译官各写一遍。它们都用路径压缩加按大小合并，最后印出连通块数量。

```compare
cpp::
#include <iostream>
#include <vector>
#include <algorithm>
using namespace std;

vector<int> parent, sz;

int findRoot(int x) {
    int root = x;
    while (parent[root] != root) root = parent[root];
    while (parent[x] != root) {
        int nxt = parent[x];
        parent[x] = root;
        x = nxt;
    }
    return root;
}

void unite(int a, int b) {
    int ra = findRoot(a), rb = findRoot(b);
    if (ra == rb) return;
    if (sz[ra] < sz[rb]) swap(ra, rb);
    parent[rb] = ra;
    sz[ra] += sz[rb];
}

int main() {
    parent = {0, 1, 2, 3, 4};
    sz.assign(5, 1);
    int edges[3][2] = {{0, 1}, {1, 2}, {3, 4}};
    for (auto &e : edges) unite(e[0], e[1]);
    int count = 0;
    for (int i = 0; i < 5; i++)
        if (parent[i] == i) count++;
    cout << count << endl;
    return 0;
}
```

## 这招能干什么

**连通块计数**。就是本课的例子：一堆边把点连成一伙一伙，最后数有几个根，就是有几个连通块。社交网络里数「有几个互不相识的小圈子」，用的是同一招。

**无向图判环**。一条一条加边，每次加之前先看两端：`find(u) == find(v)` 说明两端早就在同一棵树里，再加这条边就会绕出一个圈；`find(u) != find(v)` 就正常合并。拿三角形举例：先加 (0,1)、(1,2)，此时 0、1、2 同根；再加 (0,2)，两端同根——环找到了。反过来说，如果所有边加完都没撞上同根，这张图就是一片没有环的森林。

**朋友圈**。每个人是一个点，认识就合并。问「这两个人是不是一个圈子」，就是问根是否相同；问「一共有几个圈子」，就是数根。

**Kruskal 最小生成树**。把边按长短排排坐，从最短的开始拿：两端不同根就收下这条边并合并，同根就跳过——同根说明收了它会成环。比如四个点、四条候选边长度分别是 1、2、3、100，其中 3 那条连着 0 和 2：先收 1 和 2，0、1、2 成了一伙；再看 3 那条，两端已经同根，收下就成环，跳过；最后收 100 那条，把 3 号点接进来。收够 n-1 条边，得到的就是让所有点连通、总长度最小的那组边。这里要分清：它求的是「把大家连起来最便宜」，不是「两点之间最短的路」。

最后把边界说清楚：并查集只回答「是不是一伙」。它不记两点之间隔多远，不记路上有几条边，更不记每条边有多重。所以它可以判环、可以数连通块，但**不能拿来求最短路**——那是下一课的活。
