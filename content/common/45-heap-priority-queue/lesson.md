## 钩子：先到先领，不灵了

上一课「一圈一圈往外扩」，本喵爪子里捧着一支队伍：谁先被放进队尾，谁就先被拎出来往外扩——**先到先领，后来的乖乖排后面**。那一招靠的是「排队领小鱼干」的铁律：**顺序只看谁来得早**，跟鱼干本身值多少钱一点关系都没有。

可这回面试官大肥鱼把规则牌一翻：

> 「不管谁先到。每次，都得先领走**最便宜**的那只小鱼干。」

本喵当场愣住喵。一只后到的、只要三块钱的小鱼干，得越过前面十几只插到最前头；一只先到的、九块钱的，反而要一直往后排。**顺序不再看谁来得早，改看谁更值**——这就是今天要讲的「堆」，和它撑起来的那只队伍。

## 一、把会分叉的猫爬架压扁

堆长什么样？它是一棵**完全二叉树（会分叉的猫爬架）**：每个节点最多两个孩子，而且每一层都从左往右填满，最后一层也只从左边开始连续地填，中间不许留空。

按常理，一棵分叉的爬架得用指针（猫爪指向牌）把节点一个个串起来。可堆偏不——它直接把整棵树**压扁、铺平**，塞进数组（一排贴编号的猫粮碗）里。这种「铺平」能成立，全靠「完全」两个字：形状固定了，位置本身就说明了关系，一根指向牌都不用。

设这一排碗的编号从 **0** 开始（0 号、1 号、2 号……），那么任意一只碗 `i`：

- 父亲在 `(i - 1) // 2` 号碗；
- 左孩子在 `2 * i + 1` 号碗；
- 右孩子在 `2 * i + 2` 号碗。

`//` 是「除完向下取整」，也就是 Python 里的整除。

拿 `[1, 3, 2, 5, 9, 8]` 这排碗对一对：

| 这只碗 | 装的值 | 父亲下标 | 左孩子下标 | 右孩子下标 |
|---|---|---|---|---|
| 0 号 | 1 | 没有（它就是顶） | 1 | 2 |
| 1 号 | 3 | 0 | 3 | 4 |
| 2 号 | 2 | 0 | 5 | 6（越界） |
| 3 号 | 5 | 1 | 7（越界） | 8（越界） |
| 4 号 | 9 | 1 | 9（越界） | 10（越界） |
| 5 号 | 8 | 2 | 11（越界） | 12（越界） |

看 4 号：`(4 - 1) // 2 = 1`，父亲真是 1 号；反过来 1 号的两个孩子 `2×1+1=3`、`2×1+2=4`，也正是 3 号和 4 号。**父亲和孩子这两套公式是同一件事的两种问法**，背一套就够，另一套现场推。

为什么压扁不会乱？因为「完全」保证了一件事：**从上往下、从左往右数，第 k 个节点就住 k 号碗**，中间没有空位。空位一没有，父子关系就只跟编号有关，跟「谁先来、谁后到」一点关系都没有。这也是堆能省下指向牌的原因喵。

## 二、小根堆的家规：父亲不大于孩子

铺平只是形状。堆还有一条**家规**：

> 每一只碗里的数，都**不大于**它两个孩子碗里的数。（孩子不存在就跳过，不违反。）

注意这条家规只管「父亲对孩子」，**不管兄弟之间**——1 号和 2 号谁大谁小，家规一个字都没说。也正因为它只管上下、管得松，插入和弹出才能那么快，后面就讲。

来验一遍 `[1, 3, 2, 5, 9, 8]`：

| 父亲 | 值 | 孩子们的值 | 合规吗 |
|---|---|---|---|
| 0 号 | 1 | 3、2 | 1 ≤ 3、1 ≤ 2 ✓ |
| 1 号 | 3 | 5、9 | 3 ≤ 5、3 ≤ 9 ✓ |
| 2 号 | 2 | 8 | 2 ≤ 8 ✓ |

全都合规。那**堆顶（0 号碗）里装的就是整堆最小的那只**——因为家规是一层一层往下的：0 号不大于它的孩子，孩子又不大于孩子的孩子……顺着任何一条往下的路走，数只会越来越大。于是从顶上出发，哪条路都找不到比顶更小的数。这就是「每次取最小的那只」的底气喵。

反过来，家规写成「父亲**不小于**孩子」，就是**大根堆**，堆顶变成最大的那只。名字只差一个字，方向完全相反，写代码时最容易被它坑——**先问清楚你要的是小根堆还是大根堆**。

## 三、插一只：扔到末尾，往上浮

往堆里加一只新鱼干，分两步：

1. **先扔到末尾**——也就是这一排碗的最后一个位置。这样形状还是「完全」的，家规却可能被破坏：新来的可能比它父亲小。
2. **往上浮**：只要它比父亲小，就跟父亲换位；换完接着跟新父亲比，直到不比父亲小、或者已经坐上 0 号顶。

拿 `[1, 3, 2, 5, 9, 8]` 插一只 **0** 进去，走一遍：

| 走到哪 | 这一排碗 | 在比谁 | 动作 |
|---|---|---|---|
| 刚扔到末尾 | `[1, 3, 2, 5, 9, 8, 0]` | 6 号 0 对父亲 2 号 2 | 0 < 2，换 |
| 换完 | `[1, 3, 0, 5, 9, 8, 2]` | 2 号 0 对父亲 0 号 1 | 0 < 1，换 |
| 再换完 | `[0, 3, 1, 5, 9, 8, 2]` | 0 号没有父亲 | 停，收工 |

验一下：0 ≤ 3、1；3 ≤ 5、9；1 ≤ 8、2，家规全守住了。**0 一路上浮两层就坐上了顶**，一步没多走。

再看本课那组 `5, 3, 8, 1, 9, 2` 依次插进去，每一只各浮了几次：

| 插入 | 插完这一排碗 | 上浮次数 | 堆顶 |
|---|---|---|---|
| 5 | `[5]` | 0 | 5 |
| 3 | `[3, 5]` | 1 | 3 |
| 8 | `[3, 5, 8]` | 0 | 3 |
| 1 | `[1, 3, 8, 5]` | 2 | 1 |
| 9 | `[1, 3, 8, 5, 9]` | 0 | 1 |
| 2 | `[1, 3, 2, 5, 9, 8]` | 1 | 1 |

注意到没有：**这一排碗从头到尾都不是排好序的**——`[1, 3, 2, 5, 9, 8]` 里 3 明明白白排在 2 前面。可堆顶一直是当前最小的那只。这正是堆的脾气：**它只把「最小」摆在明面上，别的不管**。

**要浮多少层？** 最多等于这棵爬架的高度。n 只碗排成的完全树，高度是 ⌊log₂ n⌋，所以上浮最多走 log n 层、每层一次交换——**插入是 O(log n)**。一万只碗，最深的叶子往上爬也才十三段，顶多换十三次。

## 四、弹一只：末尾搬到顶，往下沉

弹出堆顶稍微绕一点。堆顶一拿走，0 号碗就空了；要是让所有碗往前挪一格，整棵树的形状就散了。所以堆的招是：

1. **先把末尾那只搬到 0 号顶**，再把末尾删掉——形状保住了，长度减一。
2. 可这位「末位替补」多半比孩子大，家规破了。于是**往下沉**：把它跟两个孩子里**更小的那个**换位；换完接着比，直到它不大于两个孩子、或者已经没有孩子。

为什么挑**更小的孩子**换，而不是随便挑一个？因为换上去的那只要当新父亲，必须同时不大于两个孩子。要是跟大的那个换了，小的那个还留在原地，比新父亲还小，家规照样破——还得再换一次，白忙。

还是拿 `[1, 3, 2, 5, 9, 8]` 弹一次：

| 走到哪 | 这一排碗 | 在比谁 | 动作 |
|---|---|---|---|
| 记下堆顶 | `[1, 3, 2, 5, 9, 8]` | 答案 = 1 | 先记住 1 |
| 末尾搬到顶 | `[8, 3, 2, 5, 9]` | 8 对两个孩子 3、2 | 孩子里 2 更小，跟 2 换 |
| 换完 | `[2, 3, 8, 5, 9]` | 2 号 8 的孩子 | 5 号越界，没有孩子 |
| 收工 | `[2, 3, 8, 5, 9]` | 堆顶 = 2 | 弹出去的是 1 |

验一遍：2 ≤ 3、8；3 ≤ 5、9。家规守住了，新的堆顶 2 就是剩下这几只里最小的。

**要沉多少层？** 同样最多树高那么多层，**O(log n)**。注意一件事：**弹出只保证拿走了最小的那只，不保证剩下的是现成的顺序**——`[2, 3, 8, 5, 9]` 里 8 还排在 5 前面呢。

## 五、建堆：从最后一个非叶子往前沉

如果手里已经有一整排乱序的碗，一只一只插进去建堆要 O(n log n)。其实有更省力的办法：**原地建堆（heapify）**。

做法一句话：

> 从**最后一个非叶子节点**开始，倒着往前，每一只都往下沉一次。

0 下标时，最后一个非叶子节点的下标是 `n // 2 - 1`。比如 n = 6，就是 `6 // 2 - 1 = 2` 号——2 号往后（3、4、5 号）全是叶子，没有孩子可沉，不用管。

拿 `[5, 3, 8, 1, 9, 2]` 走一遍（n = 6，从 2 号开始）：

| 沉谁 | 之前 | 怎么沉 | 之后 |
|---|---|---|---|
| 2 号（8） | `[5, 3, 8, 1, 9, 2]` | 唯一的孩子是 2，8 > 2，换 | `[5, 3, 2, 1, 9, 8]` |
| 1 号（3） | `[5, 3, 2, 1, 9, 8]` | 孩子是 1 和 9，跟更小的 1 换 | `[5, 1, 2, 3, 9, 8]` |
| 0 号（5） | `[5, 1, 2, 3, 9, 8]` | 孩子 1、2，先跟 1 换；落到 1 号后孩子 3、9，再跟 3 换 | `[1, 3, 2, 5, 9, 8]` |

最后这一排正是刚才插出来的那个堆，一只不差。

**为什么是 O(n)，不是 O(n log n)？** 关键在「越靠底层的节点越多、能沉的距离越短」：一半的碗是叶子，一步都不用沉；四分之一的碗在上面一层，最多沉一层；八分之一最多沉两层……总工作量是

> n/2 × 0 + n/4 × 1 + n/8 × 2 + … 

这个和收敛到 n 的量级（不到 2n），**所以建堆是 O(n)**。

对比一下：一只一只插进去，是 n 次 O(log n) 的插入，那是 O(n log n)；倒着沉，**最多的节点只需要沉最短的距离**，加起来就只有 O(n)。差别就在这喵。

## 六、Python 的 heapq：只有小根堆

Python 标准库里的 `heapq` 就是一只小根堆，常用的招只有几手：

- `heapq.heappush(h, x)`：插一只，O(log n)；
- `heapq.heappop(h)`：弹出堆顶，O(log n)；
- `heapq.heapify(h)`：就地把一整排碗建堆，O(n)；
- `h[0]`：看一眼堆顶，O(1)。

**`heapq` 是小根堆。** 想要大根堆？把数存成**相反数**：3 存 -3、9 存 -9，小根堆一比较，-9 最小、排在最上面，弹出来再取反，就是最大的 9。这一招在面试卷子上要写「取相反数」，别写「用 `heapq` 建大根堆」——没这个东西喵。

## 七、Top K：只留 k 只的小根堆

「从 n 只鱼干里挑出最贵的 3 只」——这叫 **Top K**。标准解法是：

1. 准备一只**只能装 k 只**的小根堆；
2. 一只一只往里塞，塞完如果超过 k 只，就**弹掉堆顶**——堆顶是这 k 只里最小的，正好该淘汰；
3. 全部走完，堆里剩的就是最大的 k 只。此时**堆顶是「当前第 k 大」**，是这 k 只里最不争气的那只。

为什么不反过来用大根堆装 k 只？因为要淘汰的是「k 只里最小的那只」，而大根堆的顶是最大的，最小那只藏在堆底，你得把整堆翻一遍才找得到。**小根堆的顶正好就是最该被淘汰的那只**，看一眼就知道该不该换。

代价：每只鱼干最多进堆一次、弹一次，每次 O(log k)，一共 **O(n log k)**。k 比 n 小得多的时候，比「全部排好再取」的 O(n log n) 省得多。

本课那组 `[5, 3, 8, 1, 9, 2]`，k = 3，走一遍：

| 来的是 | 塞完再淘汰，堆里变成 | 堆顶 |
|---|---|---|
| 5 | `[5]` | 5 |
| 3 | `[3, 5]` | 3 |
| 8 | `[3, 5, 8]` | 3 |
| 1 | 塞成 `[1, 3, 8, 5]`，弹顶后 `[3, 5, 8]` | 3 |
| 9 | 塞成 `[3, 5, 8, 9]`，弹顶后 `[5, 9, 8]` | 5 |
| 2 | 塞成 `[2, 5, 8, 9]`，弹顶后 `[5, 9, 8]` | 5 |

最后堆里三只是 **5、8、9**，堆顶 5 正是「第 3 大」。把它们从大到小摆出来，就是 **9 8 5**，加起来 **22**。

## 八、堆不是「排好序的一排碗」

> **本喵提醒**：这一条最容易考，也最容易错。

很多猫第一次看见 `[1, 3, 2, 5, 9, 8]`，会以为「堆嘛，就是排好序的吧」。**不是。** 3 明明排在 2 前面。堆的家规只管父亲和孩子，兄弟之间、叔叔和侄子之间，谁大谁小它一概不管。

所以两件事要分清：

- **能 O(1) 拿到最值**：堆顶就是最小（小根堆）或最大（大根堆），看一眼就行。
- **不能 O(log n) 找任意一个值**：这一排碗只是「位置碰巧能算出父子关系」，跟大小顺序没关系。想在堆里找 8，只能从 0 号一路扫过去，O(n)。想二分？门都没有——二分要的是**整排有序**，堆只保证了「上下有序」。

要是真想让它整排有序，怎么办？**把堆顶一只一只弹出来**，弹出来的顺序就是从小到大的顺序。弹 n 次、每次 O(log n)，总共 O(n log n)——这条路的学名就叫**堆排序（用堆一只只弹出来排队）**。它跟「建堆 O(n)」是两回事：建堆只是把家规立起来，不是把队排好。

## 九、落到代码上

```python
import heapq

nums = [5, 3, 8, 1, 9, 2]
k = 3

heap = []
for x in nums:
    heapq.heappush(heap, x)
    if len(heap) > k:
        heapq.heappop(heap)

top = sorted(heap, reverse=True)
print(*top)
print(f"sum={sum(top)}")
```

```text
9 8 5
sum=22
```

逐句看：

- `heap = []`：一只空的小根堆。
- 圈里每来一只 `x`，先 `heappush` 塞进去；塞完如果超过 `k` 只，就 `heappop` 弹掉堆顶——弹掉的正是这 `k + 1` 只里最小的，留下来的始终是「目前见过的最大的 3 只」。
- `sorted(heap, reverse=True)`：堆里三只是 5、8、9，但要按从大到小印出来，得再摆一次；这一步是 O(k log k)，k 很小时可以忽略。
- `print(*top)`：前面的 `*` 把三只摊开，用空格隔开，印出 `9 8 5`。
- `print(f"sum={sum(top)}")`：三只加起来 9 + 8 + 5 = 22，印出 `sum=22`。

整段最贵的是那个圈：n 只各进堆一次、最多各弹一次，每次 O(log k)——**O(n log k)**。要是老老实实全部排好再取前三个，就是 O(n log n)。n 大、k 小的时候，这只小根堆省下来的可不是一点半点喵。

## 十一、三位翻译官，各自的优先队伍

同一组 `[5, 3, 8, 1, 9, 2]`、同样 k = 3，三位翻译官手里的「优先队伍」长得还不太一样：C++ 的 `std::priority_queue<int>` 默认就是大根堆；Java 的 `PriorityQueue` 默认反而是小根堆，想要大根堆得加一句 `Collections.reverseOrder()`；Python 的 `heapq` 只有小根堆，只好把数存成相反数。**三条路写法各异，吐出来的四行一个字不差。**

```compare
cpp::
#include <iostream>
#include <vector>
#include <queue>

int main() {
    std::vector<int> nums = {5, 3, 8, 1, 9, 2};
    std::priority_queue<int> pq(nums.begin(), nums.end());
    int total = 0;
    for (int i = 0; i < 3; ++i) {
        int v = pq.top();
        pq.pop();
        std::cout << v << std::endl;
        total += v;
    }
    std::cout << "sum=" << total << std::endl;
    return 0;
}

java::
import java.util.*;

public class Main {
    public static void main(String[] args) {
        int[] nums = {5, 3, 8, 1, 9, 2};
        PriorityQueue<Integer> pq = new PriorityQueue<>(Collections.reverseOrder());
        for (int x : nums) {
            pq.add(x);
        }
        int total = 0;
        for (int i = 0; i < 3; i++) {
            int v = pq.poll();
            System.out.println(v);
            total += v;
        }
        System.out.println("sum=" + total);
    }
}

python::
import heapq

nums = [5, 3, 8, 1, 9, 2]
heap = [-x for x in nums]
heapq.heapify(heap)
total = 0
for _ in range(3):
    v = -heapq.heappop(heap)
    print(v)
    total += v
print(f"sum={total}")
```

```text
9
8
5
sum=22
```

看仔细：C++ 和 Java 都是把全部六只塞进大根堆，再连弹三次；Python 把每只取反塞进小根堆，弹出来再取反——**负负得正，最大的还是最大**。三条路的共同点：**只关心谁在顶上**，谁也不去把整排摆好。

要注意，这三份走的是「全员进堆、弹 k 次」；正文里那个「只留 k 只的小根堆」是另一种更省地方的写法。两种都算 Top K 的正路，区别只在「n 大不大、k 小不小」：n 很大而 k 很小时，只留 k 只的那只堆更省地方。

::: tip 猫咪提示
1. **堆顶是唯一「有保证」的位置**：小根堆的 0 号碗一定最小，其他任何一只碗都不敢保证什么。想要第 2 小？弹掉堆顶再弹一次，别去猜 1 号碗。
2. **下标公式只认 0 开始**：本课的这排碗都从 0 号起，所以父亲是 `(i - 1) // 2`。要是有人从 1 号开始数，公式会变成 `i // 2`、`2i`、`2i + 1`——**换个起点，公式就得换**，混着用必错。
3. **它还会再出场**：等学到「地图上的最短腿」那一课，这只「每次取最小」的队伍还要挑大梁——现在把上浮和下沉练熟，到时候就只剩套公式了喵。
:::

::: warn 小心喵
两个坑，都是真踩过的：

- **大小根堆写反**：要「每次取最小」，家规必须是「父亲不大于孩子」（小根堆）；写成「父亲不小于孩子」，堆顶就变成最大的那只，代码不报错、结果全反。Python 的 `heapq` 是天生的**小根堆**，别在卷子上写「用 `heapq` 建大根堆」——**要最大就存相反数**。
- **以为堆里这一排是排好序的**：`[1, 3, 2, 5, 9, 8]` 里 3 就在 2 前面。堆只保证「父亲 ≤ 孩子」，兄弟之间不管；想按顺序全拿出来，只能一只一只弹顶，O(n log n)。拿它当有序的一排去二分，是必错的喵。
:::
