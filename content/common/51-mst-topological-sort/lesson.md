## 钩子：整张地图拍在桌上

上一课，大肥鱼给本喵的题目是：从本喵脚下这个点出发，走到地图上任意一个点，怎么走最便宜。本喵把 Dijkstra 那套「每次取最小的那只」搬出来，一圈一圈往外扩，最后每个点旁边都写上了「最便宜多少钱到这儿」。

本喵叼着笔，正等着它点头，大肥鱼却一爪子把整张地图拍在桌上，鱼脸凑过来：

> 「我不从哪儿出发。我要把**所有点都连起来**，总路费最省。」

本喵当场卡住。不出发，那还算什么路？

它说的不是一条路，是**一整套路**：几个猫窝散在地图上，要修若干条双向的路，要求从任何一个窝都能走到任何另一个窝，还要总造价最低。这跟上一课是两道题——上一课问的是「**一对点之间**怎么走最便宜」，这一课问的是「**所有点**怎么连成一片最便宜」。

这道题的答案，有个正式名字：**最小生成树**。

地图收起来之后，大肥鱼又翻出一张表，往桌上一推：「路修完了，活还没排呢——这些事，谁先谁后？」本课就把这两件事一起收拾干净喵。

## 最小生成树：不出门，只把点连成一片

先把地图摆成本喵看得懂的样子。四个猫窝，编号 0、1、2、3；能修的路和造价如下：

| 路 | 造价 |
| 0–1 | 1 |
| 1–2 | 2 |
| 0–2 | 3 |
| 2–3 | 4 |

这些路有两个特点：**没有箭头**，修好之后来回都能走，这叫无向；每条都标着价钱，这叫带权。所以这是一张**无向带权图**，跟上一课那张边上有长度、还专门叮嘱过「不能有负边」的地图，不是一回事。

**最小生成树**要做的事，一句话：挑出若干条边，满足下面三条，而且总权重最小。

1. **所有点连成一片**：从任意一个窝出发，顺着选中的路，都能走到任意另一个窝。
2. **不许有环**：选中的路不能绕成一圈。真绕成一圈，那一圈上必定有一条是白修的——把它去掉，各个窝照样通，钱还省下来。
3. **总权重最小**：所有满足前两条的挑法里，总造价最低的那一组。

为什么叫「树」喵？因为**连成一片、又没有环**的图，长得就像一棵树：从一个点往外分杈，任意两个点之间只有一条路。多一个环，就成了树上缠了个圈，不再是树。

那要挑几条？**恰好 n-1 条**（n 是点的个数）。

道理很朴素：一开始只有 1 个点算「已经连好的那片」，外面还剩 n-1 个。每挑一条边，最多只能把**一个新点**拉进这片——要是两端都已经在这片里，这条边就只是在这片内部绕圈，选它必成环。所以要把 n-1 个点全拉进来，至少要 n-1 条边；而 n-1 条刚好够用，多一条就必然成环。**n 个点，n-1 条边，不多不少。**

四个窝，那就是选 3 条路。本喵把几种挑法摆出来比一比：

| 挑哪三条 | 总造价 | 结果 |
| (0,1) (1,2) (2,3) | 1+2+4 = **7** | 连成一片，没有环，最省 |
| (0,1) (0,2) (2,3) | 1+3+4 = 8 | 也连成一片，但贵了 1 |
| (1,2) (0,2) (2,3) | 2+3+4 = 9 | 也通，更贵 |
| (0,1) (1,2) (0,2) | 1+2+3 = 6 | 总价最低，可点 3 掉了队，还绕成 0–1–2–0 一个圈 |

最后一行最值得盯：**它最便宜，却根本不是生成树**。所以这道题不能只盯着总价——先把「全都连上、不许绕圈」做对，再谈省不省。考试卷子上看到「总权重最小」这几个字，前面那两个条件也得一并满足喵。

还有一句要紧的：最小生成树**不一定唯一**。图里要是有两条一样便宜的边，换着挑可能得到另一棵，总权重一样。所以问「总权重是多少」才有唯一答案；问「挑了哪几条」，有时会有好几种合法答法。

## Kruskal：把边排成一条长龙

**Kruskal** 的招数，就是把「挑最便宜的」贯彻到底，但每拿一条都要多问一句：这条边会不会把已经连好的那片绕出圈来？

它的流程只有五句：

1. 把所有边按权重**从小到大**排成一条长龙。
2. 从队头拿一条，看它两端**是不是已经在同一伙**。
3. 不在同一伙 → 选上，把两伙并成一伙。
4. 已经在同一伙 → 跳过，选它必然成环。
5. 选满 n-1 条 → 立刻收手，后面再便宜也不要了。

「在不在一伙」这件事，前面「谁和谁是一伙的」那一课刚练过——**并查集**。每个点记住自己的上级，一路往上找，最后找到的那个「根」就是这一伙的旗号。两端的根一样，就是一伙；不一样，就是两伙，可以牵这条线，牵完把两个根接起来。

还拿那四个窝走一遍。排好的边是 (0,1,1)、(1,2,2)、(0,2,3)、(2,3,4)：

| 第几条 | 边 | 权重 | 两端各在哪一伙 | 判断 | 累计总权重 | 已选 |
| 1 | (0,1) | 1 | {0} 与 {1} | 不同伙，选上 | 1 | 1 |
| 2 | (1,2) | 2 | {0,1} 与 {2} | 不同伙，选上 | 3 | 2 |
| 3 | (0,2) | 3 | {0,1,2} 与 {0,1,2} | 同根，跳过 | 3 | 2 |
| 4 | (2,3) | 4 | {0,1,2} 与 {3} | 不同伙，选上 | 7 | 3 |

选到第 4 条时，已选条数正好凑够 n-1 = 3，收工，总权重 **7**。挑中的是 (0,1)、(1,2)、(2,3)，跟上一节表里那组一模一样。

第 3 条被跳过，是整招的命门：0 和 2 早就通过 1 连在一起了，再加一条 0–2，只会绕出一个 0–1–2–0 的圈，钱白花。**并查集存在的全部意义，就是一眼看出「这两只已经是一伙的，别再牵线」。**

「按权重从小到大排」这一步，就是前几课那只猫说的「给小鱼干排排坐」。排这一趟要 M log M（M 是边的条数）；之后每条边查两次根，并查集带上路径压缩之后近似当常数看。所以 Kruskal 的时间主要花在排边上，整体 O(M log M)。

## 为什么先挑最便宜的不吃亏：割性质

有人要问：贪心不是万能的呀（前面「眼前最好的一定对吗」那一课，那只猫就栽过跟头），凭什么每次都挑当前最便宜的边，最后就一定最省？

这里有一条定理撑腰，叫**割性质**：把图里的点随意分成两堆，像横着切一刀；所有**一头在这堆、一头在那堆**的边里，**最便宜的那条，一定可以进某棵最小生成树**。

道理可以用「换一条」讲清楚。假设某棵最小生成树没选这条最便宜的横切边，那它总得有别的边跨过这道口子——那条不会比它便宜。把那条贵的换成本喵手里这条最便宜的：两边照样连着（都是跨这道口子的边），也不会多出环，总权重只会不变或者更小。既然换了不亏，最优解里就没有理由放着便宜的不选。

Kruskal 从小往大挑、挑之前先查环，每一步其实都在用这条性质：当前这条边，正是某个「一刀切」里最便宜的横切边。**先挑最便宜的不是碰运气，是有定理兜底的。**

**Prim** 是同一道题的另一条路，换个方向长：

- 随便挑一个点，算作「已经连好的那片」。
- 每次只在「一头在片里、一头在片外」的边里挑最便宜的那条，把外面的点拉进来。
- 拉够 n 个点就停。

选边标准和 Kruskal 一样是「最便宜」，可范围小得多——只看跨在边界上的那些边。想快速取出最小的那条，拿一只**小根堆**装着候选边就行，每次取堆顶；整趟下来 O((V+E) log V)。

有意思的是，上一课 Dijkstra 也是「每次取最小」，Prim 还是「每次取最小」。区别在**比什么**：Dijkstra 比的是「从起点到那个点累计走了多远」，Prim 比的是「这条边自己的价钱」。同样是堆，量的东西换了。

本课重点走 Kruskal，因为并查集刚学过，接得最顺；Prim 知道有这么一条路、知道它跟 Dijkstra 差在哪儿，就够了。

## 排期：箭头只能往前走

地图收起来，大肥鱼换了一张纸：「路修好了。接下来是活——这些事，谁先谁后？」

先看一张小图。四件事，编号 0 到 3：

- 0 → 1
- 0 → 2
- 1 → 3
- 2 → 3

箭头的意思是「必须先做完」。0 做完才能做 1 和 2；1 和 2 都做完，才能做 3。

这张图也有两个特点：

1. **有向**：箭头只有一个方向。修路是双向的，排期是单向的——「淘米必须在煮饭之前」，反过来可不成。
2. **无环**：顺着箭头怎么走，都回不到自己。要是出现 0 → 1 → 3 → 0 这样的圈，意思是「0 得等 3、3 得等 1、1 又得等 0」——谁也开不了工，整件事卡死。

有向、又没有环的图，本喵叫它**有向无环图**，缩写 **DAG**。

要在这张图上排出一条线，让每一条箭头都**从排在前面的点，指向排在后面的点**。这样一条线，叫**拓扑序**；把它求出来这件事，就是**拓扑排序（把先后的活排成一条线）**。

上面那张图，`0 1 2 3` 就是一条合法的线：0 在 1、2 前面，1 在 3 前面，2 也在 3 前面，每条箭头都朝后。`0 2 1 3` 同样合法——1 和 2 之间没有箭头，谁先谁后都行。

**拓扑序不唯一**，这一点跟最小生成树有点像（那边总权重唯一，挑法可能不唯一）。所以题目要是问「给出一个拓扑序」，给得出一个就行；要检查对不对，就回去把每条边过一遍：**起点是不是都排在终点前面**。

## Kahn：入度归零就放行

怎么排？本喵用**入度**这个尺子。

一个点的**入度**，就是有几条箭头指着它——说人话：**有几件活必须排在它前面**。入度是 0，说明没有前置，可以马上开工。

**Kahn** 的招数只有三步：

1. 数出每个点的入度，把所有入度为 0 的点放进一条长队。
2. 从队头取出一只，写进结果；把它指向的每个点的入度**减 1**——意思是「我压在你们身上的那件前置活，干完了」。
3. 谁被减到 0，谁就进队。队空了就停。

还是那四件事，本喵拿爪子走一遍。一开始的入度：0 是 0，1 是 1（被 0 指着），2 是 1（被 0 指着），3 是 2（被 1 和 2 指着）。

| 步骤 | 取出 | 写进结果 | 入度怎么变 | 队里还有谁 |
| 开始 | — | — | 0:0 1:1 2:1 3:2 | [0] |
| 1 | 0 | 0 | 1 减成 0 进队；2 减成 0 进队 | [1, 2] |
| 2 | 1 | 0 1 | 3 从 2 减成 1 | [2] |
| 3 | 2 | 0 1 2 | 3 从 1 减成 0，进队 | [3] |
| 4 | 3 | 0 1 2 3 | 它不指向谁，没得减 | [] |

队空了，四只全出来了，顺序是 **0 1 2 3**。

每一步其实都在干同一件事：**把「没有前置」的点放行，放行一个，就给它后面的点松一道绑**。松到 0 的那个，就成了下一批能开工的。这也解释了为什么 1 排在 2 前面：取出 0 的时候，先给它指向的 1 松绑，再给 2 松；1 先进队，就先出来。这两件活之间本来没有先后，顺序纯看出队那一刻谁在队头。

写成代码就这么几行：

```python
n = 4
edges = [(0, 1), (0, 2), (1, 3), (2, 3)]

indeg = [0] * n
out = [[] for _ in range(n)]
for u, v in edges:
    out[u].append(v)
    indeg[v] += 1

queue = [i for i in range(n) if indeg[i] == 0]
order = []
while queue:
    u = queue.pop(0)
    order.append(u)
    for v in out[u]:
        indeg[v] -= 1
        if indeg[v] == 0:
            queue.append(v)

print(*order)
```

```text
0 1 2 3
```

`indeg` 数入度，`out` 记每个点指向谁；开局把入度为 0 的请进 `queue`；每次从队头取一个写进 `order`，顺手把它的下游入度减 1；减到 0 的进队。`print(*order)` 会把这一串数摊开印出来，中间用空格隔开。

## 排不完，就是有环

Kahn 还白送一个好处：**它能顺手告诉你图里有没有环**。

队空了，可还有点儿没出来，说明什么？说明剩下的每一个点，都至少还有一条箭头指着它——它们互相等着，等成一个死结，那就是环。

举个具体的：在上面四件事上加一条 3 → 0（装完盘还得回去淘米）。这一下入度变成 0:1、1:1、2:1、3:2，**一开局就没有入度为 0 的点**，队是空的，一条都排不出来。四个点全卡住。

再看一个只卡一半的：0 → 1、0 → 2、1 → 3、2 → 3，再加一条 3 → 1。入度是 0:0、1:2、2:1、3:2。开局只有 0 能走；排出 0，1 减成 1、2 减成 0，队里就剩 2；排出 2，3 减成 1；队空了。结果只有 `0 2` 两个点，剩 1 和 3 互相咬着——环就藏在这两个点里。

所以判据很干脆：**排出来的点少于 n 个，就说明有环，拓扑序不存在。** 反过来，n 个点全出来了，每条箭头都被顺利松了绑，这张图就是有向无环图。

最后把两件事分清楚。它们都长在图上，可问的根本不是一回事：

| | 最小生成树 | 拓扑序 |
| 图长什么样 | 无向、带权 | 有向、无环 |
| 要什么 | 挑 n-1 条边，全部点连成一片，总权重最小 | 排一条线，每条箭头都从前往后 |
| 用什么招 | Kruskal（配并查集）、Prim（配小根堆） | Kahn（数入度） |
| 碰到环 | 挑边时跳过会成环的边 | 有环就排不出来 |
| 每步挑什么 | 当前最便宜的边 | 当前入度为 0 的点 |

一句话：**最小生成树管「连得上、最省钱」，是无向图的活；拓扑序管「排得开、不打架」，是有向无环图的活。** 把这两张地图看串，是面试里最常见的翻车点喵。

## 落到代码上：Kruskal 的完整一趟

把上面那张表翻译成 Python，就是下面这段。四个窝、四条边，一行都不用改就能跑：

```python
n = 4
edges = [(1, 0, 1), (2, 1, 2), (3, 0, 2), (4, 2, 3)]
edges.sort()

parent = list(range(n))

def find(x):
    while parent[x] != x:
        parent[x] = parent[parent[x]]
        x = parent[x]
    return x

total = 0
picked = 0
for w, u, v in edges:
    ru = find(u)
    rv = find(v)
    if ru != rv:
        parent[ru] = rv
        total += w
        picked += 1
        if picked == n - 1:
            break

print(total)
```

```text
7
```

逐段对一遍：

- `edges` 里每条边写成 `(权重, 一端, 另一端)`，**把权重放在每组最前面**，这样 `sort()` 一跑，天然就按权重从小到大排好了，不用另写比较规则。
- `parent` 是并查集的「上级表」，一开始每个点自成一伙，自己就是自己的根。
- `find` 顺着上级一路往上爬；顺手把路上的点直接挂到爷爷底下（路径压缩），下次再找就短一截。
- 圈里先查两端是不是同根：不同根才选，选上就把两个根接起来、加钱、记一条。
- 选够 `n - 1` 条就 `break`，后面再便宜的也不看了——因为已经连全了，再多连就是白花钱。

跑出来是 `7`，正是本喵在表里算的那 1 + 2 + 4。这张图里最后一条边正好就是第三条被选中的边，所以有没有 `break` 都会跑满四条、答案一样；换一张边更多的图，`break` 就能让本喵选够 n-1 条就收爪，后面再便宜的也不看了。

## 三位翻译官，同一张图

同一套 Kruskal，换三种方言各写一遍。三份都只做一件事：在那张四点的图上求最小生成树的总权重。

```compare
cpp::
#include <iostream>
#include <algorithm>

struct Edge {
    int w, u, v;
};

bool cmp(const Edge& a, const Edge& b) {
    return a.w < b.w;
}

int parent[4];

int findRoot(int x) {
    while (parent[x] != x) x = parent[x];
    return x;
}

int main() {
    int n = 4;
    Edge edges[4] = {{1, 0, 1}, {2, 1, 2}, {3, 0, 2}, {4, 2, 3}};
    std::sort(edges, edges + 4, cmp);
    for (int i = 0; i < n; i++) parent[i] = i;
    int total = 0, picked = 0;
    for (int i = 0; i < 4; i++) {
        int ru = findRoot(edges[i].u);
        int rv = findRoot(edges[i].v);
        if (ru != rv) {
            parent[ru] = rv;
            total += edges[i].w;
            picked++;
            if (picked == n - 1) break;
        }
    }
    std::cout << "最小生成树总权重 = " << total << std::endl;
    return 0;
}
```

三份的骨架一模一样：**排边 → 建上级表 → 逐条查根 → 不同根就合并加钱 → 凑够 n-1 收手**。C++ 得自己写个比较规则，Java 得让边能比大小（`Comparable`），Python 的元组天生会按第一个数比——方言不同，套路一个字都没变喵。

::: tip 猫咪提示
1. **认题先认图**：题目说「所有点连起来、总花费最低」「铺光纤」「修路」，是无向图上的最小生成树；题目说「谁先谁后」「有前置条件」「课程安排」，是有向无环图上的拓扑序。
2. **Kruskal 的两件兵器**：一条「按权重从小到大排好的边」，一本「并查集」。缺了并查集，就没法一眼看出两端是不是一伙，只能每条都重新搜一遍，慢得掉毛。
3. **Kahn 的一条尺子**：入度。开局入度为 0 的全进队，出队一个就把下游减 1，谁归零谁进队——整招就这一句话。
:::

::: warn 小心喵
三个坑，考试前各摸一遍：

- **图不连通，就没有最小生成树**：Kruskal 挑到最后也凑不够 n-1 条边（比如四个窝分成两座岛，中间一条路都没有）。这时不是算法坏了，是这张图上根本不存在「全都连上」的方案。题目里写「连通无向带权图」这几个字，就是为了排除这种情况。
- **有环的图没有拓扑序**：Kahn 排出来的点少于 n 个，就该答「不存在」，别硬凑一条写上去。有向无环图这几个字，是拓扑序存在的前提。
- **两个问题别混**：最小生成树是无向图的活，拓扑序是有向无环图的活。拿并查集去数入度、拿入度去挑最便宜的边，都是把两张地图看串了。
:::
