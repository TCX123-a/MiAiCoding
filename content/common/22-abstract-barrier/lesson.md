## 钩子：换一种记法，整张地图全歪了

本喵的鱼塘边有一张**地图**。地图上每个位置都摆着一只小木牌，牌上刻两个数：**朝东走几步、朝北走几步** —— 那块地方就在这儿。

本喵写地图上的活计时，手伸得特别长：要横的数，直接抠第一格 `a.x`；要纵的数，直接抠第二格 `a.y`。算中点、报位置、量远近，处处都是这么伸的手。

后来本喵发现，地图上的活计十有八九是**顺着塘边**量的，「朝东、朝北」这种记法不顺手了 —— 本喵想给木牌换一种摆法。

这个念头刚起，本喵的爪子就僵住了喵：地图上几十处 `a.x`、`a.y`，全得翻出来改。本喵改了一个下午，还漏掉两处 —— 地图上的猫全站歪了。

有没有一种写法，能叫「**里面随便换，外面一个字不用改**」？

有。今天本喵要砌一道墙。

## 楼上楼下，隔着一道墙

本喵把那件事分成两层楼：

- **楼上**坐着「**用点的人**」：画地图、算中点、量远近的活计都在这层。它们嘴里说的只有三件事 —— 「造一只点」「报这只点的横」「报这只点的纵」。
- **楼下**坐着「**造点的人**」：一只点里头存什么、怎么摆、怎么造、怎么从里面取出一样来，全归它管。

两层楼之间砌一道墙。这道墙有个名字，行话里叫**抽象屏障** —— 上一课说过，「抽象」的老家是**给重复出现的模式起个名字**；今天这一手也一样：把楼下那一摊收进一个名字里，名字就叫「**一只点**」。楼上念着名字办事，念不进名字背后的东西；名字一立，屏障就在了喵。拆开看：

- 「抽象」是说，楼上看见的只有「**一只点**」这样东西：要横有横、要纵有纵，能造、能问；至于里面是几个数、哪一格放哪样，楼上**用不着知道**。
- 「屏障」就是这道墙本身：楼上楼下的来往，**一律从墙上开好的门走**。

先别急着把「屏障」读成「禁止通行」喵。这道墙**不是拦人的**：

- 门就开在墙上，**谁都能走**；
- 它真正要拦的，是**翻墙** —— 楼上绕过门，自己伸手进楼下仓库里掏东西。

一句话：墙不是「不让你用」，是「**约好只在门口办事**」喵。

## 墙上只开三个口子

墙上开的门，一共**三扇**，两边把说法都约好了：

1. **造的口子**：`make_point(x, y)` —— 喂进去横、纵两个数，还回来**一只点**；
2. **问的口子**：`point_x(p)` —— 喂进去一只点，还回来它的横；
3. **问的口子**：`point_y(p)` —— 喂进去一只点，还回来它的纵。

行话里，第 1 个叫**构造器**（负责「造」的口子）；第 2、3 个叫**选择器**（从一只点里「挑出」一样来问的口子）。

这套「给一件东西开好口子、把里面挡起来」的手艺，行话里叫**数据抽象** —— 楼上楼下的接头，只有墙上的门。

看图不如看代码。楼下那一头，三个口子长这样：

```c
typedef struct {
    int x;
    int y;
} Point;

Point make_point(int x, int y) {
    Point p;
    p.x = x;
    p.y = y;
    return p;
}

int point_x(Point p) {
    return p.x;
}

int point_y(Point p) {
    return p.y;
}
```

（图纸那张 `typedef struct`，C 线有整整一课讲它：「结构体」那一课，就是给猫猫画第一张图纸那一课；今天先看个大概就行喵 —— 楼下画了一张两格的图，又给这两格配上三个口子。）

楼上写活计的时候，每一句都长这样：`make_point(...)`、`point_x(...)`、`point_y(...)` —— **这三个名字，就是楼上知道的全部**。

## 同一条需求，三份写法

举一条真实需求：**报两只点的中点**。楼下给的那三个口子，楼上能拼出三份写法 —— 本喵把三份都摆在下面：

```c
/* 甲：全走口子 */
Point m1 = make_point((point_x(a) + point_x(b)) / 2,
                      (point_y(a) + point_y(b)) / 2);

/* 乙：绕开问的口子，直接抠格子 */
Point m2 = make_point((a.x + b.x) / 2,
                      (a.y + b.y) / 2);

/* 丙：连格子的名字都不认，照着「里面怎么排」硬抠 */
Point m3 = make_point((((int *)&a)[0] + ((int *)&b)[0]) / 2,
                      (((int *)&a)[1] + ((int *)&b)[1]) / 2);
```

三份分开看喵：

- **甲**：横的走 `point_x`、纵的走 `point_y`，算好的横和纵再用 `make_point` 装回一只点 —— **每一步都在门里走**，规规矩矩。
- **乙**：它不用问的口子，直接写 `a.x`、`b.x` —— 门摆在旁边不走，自己伸手进了楼下仓库。这**越了一层**：它把自己**贴**在了楼下「里面那格叫 x、那格叫 y」这件事上。
- **丙**：它连格子的名字都不提，假定自己知道「里面是两格挨着排的整数、第一格是横、第二格是纵」—— 把整只点当成**一排整数**硬抠。这**越了两层**：门也绕了，仓库怎么摆也当成了自己的地盘。（丙那一行的符号你现在不用认全，抓住它的**形状**就行：它一个字都没提楼下给的名字，全是「按位置伸手」。）

三份稿子今天都能算出同一个中点 —— 这正是「越层」最坏的地方：**它平时不响**。要等楼下换里子那天，账单才来。

## 四位翻译官喵，同一道墙

同一件事：**造一只点 (3, 4)，报出它的横**。四门语言写出来是这样喵：

```compare
c::
#include <stdio.h>

typedef struct {
    int x;
    int y;
} Point;

Point make_point(int x, int y) {
    Point p;
    p.x = x;
    p.y = y;
    return p;
}

int point_x(Point p) {
    return p.x;
}

int point_y(Point p) {
    return p.y;
}

int main(void) {
    Point a = make_point(3, 4);
    printf("横坐标是 %d\n", point_x(a));
    return 0;
}

cpp::
#include <iostream>

class Point {
public:
    Point(int x, int y) : x_(x), y_(y) {}

    int x() const {
        return x_;
    }

    int y() const {
        return y_;
    }

private:
    int x_;
    int y_;
};

int main() {
    Point a(3, 4);
    std::cout << "横坐标是 " << a.x() << std::endl;
    return 0;
}

java::
public class Main {
    static class Point {
        private int x;
        private int y;

        Point(int x, int y) {
            this.x = x;
            this.y = y;
        }

        int getX() {
            return this.x;
        }

        int getY() {
            return this.y;
        }
    }

    public static void main(String[] args) {
        Point a = new Point(3, 4);
        System.out.println("横坐标是 " + a.getX());
    }
}

python::
class Point:
    def __init__(self, x, y):
        self._x = x
        self._y = y

    def get_x(self):
        return self._x

    def get_y(self):
        return self._y

a = Point(3, 4)
print(f"横坐标是 {a.get_x()}")
```

```text
横坐标是 3
```

四段都是同一件事，可墙的样子差得挺远：

- **C**：那张两格的图（`typedef struct`）是楼下画的；三个口子是**另外单独写的三个招式**。口子和图是分开的两样，全靠**两边约好**：谁都别去碰那两格。
- **C++**：口子**长在图纸上**了 —— `a.x()` 就是「问这只点的横」；里面两格被 `private` 关着，外面伸手够不着。（这门语言里盖子怎么盖、门怎么开，本喵在 C++ 那条线上会细讲。）
- **Java**：和 C++ 一个心思：`new Point(3, 4)` 是造的口子，`a.getX()` 是问的口子。
- **Python**：口子就是图纸上的招式 —— `Point(3, 4)` 造点，`a.get_x()` 问横。

四门语言里，**墙的位置是同一个：造一个、问两个**。C 那一头靠约定守墙；C++、Java 那两头，语言自己帮你拦翻墙的手；Python 这头摆的还是约定 —— 名字前面那根下划线（`self._x` 那样）是家规不是锁，本喵在封装（带盖的小鱼干盒）那一课细讲喵。

## 换一趟里子，试试这道墙

现在楼下要办一件自己的事：**换里子**。

原来仓库里摆的是「横、纵」两格；现在楼下要摆另两个数 —— 本喵管它们叫 `u` 和 `v`（`u` 是横纵相加、`v` 是横纵相减得来的）。为什么这么摆？楼下说：顺着塘边量的活计，这样摆省事 —— **这是楼下的账，楼上不用懂**。

三个口子的**里面**跟着换：

| 口子 | 换之前（里面） | 换之后（里面） |
|---|---|---|
| `make_point` | 横、纵照原样摆进两格 | 横纵相加得 `u`、相减得 `v`，摆进两格 |
| `point_x` | 直接报第一格 | 反推回来：`(u + v) / 2` |
| `point_y` | 直接报第二格 | 反推回来：`(u - v) / 2` |

（为什么要「反推」？把两个算式摆一起就看见了：`u + v` 就是「横加纵」再加「横减纵」，一加一减里的「加纵」和「减纵」刚好抵消，剩下两个横 —— 再除以 2，就是横。）

口子的**名字、喂什么、叼回什么**，一个字没动；动的只有「里面」。

楼上那一头呢？本喵拆成一步一步走给你看：

**这就是那道墙换来的东西**：楼下换里子，楼上**一个字不用改**。

顺手看一眼甲、乙、丙的下场喵：甲一路走口子，照样拿到 3；**乙**里那句 `a.x` 当场被翻译官喵拦下了（楼下仓库里已经没有一个格子叫 `x` 了）—— 拦住了，反而是好事；**丙**呢？翻译官喵一声不吭放它过去，可它抠出来的已经**不是横**了，算出来的中点悄悄地错。越两层最坏，就坏在这儿：**它不报错，只是错**。

::: tip 猫咪提示
今天记住三句话喵：

1. **墙上开三个口子**：一个**构造器**（`make_point`，负责造）、两个**选择器**（`point_x`、`point_y`，负责问）。楼上楼下的事，全从这三个口子办。
2. **墙两边各管各的**：楼上只管「用点」，楼下只管「里面怎么摆」—— 楼下换几次里子，都不该惊动楼上。
3. **越层分两种深浅**：绕开口子、直接抠格子名，是**越一层**；连「里面怎么摆」都当成自己的，是**越两层**。
:::

::: warn 小心喵
两个坑，本喵替你标出来：

- **别把「屏障」读成「禁止访问」喵。** 门就开在墙上，三个口子人人能走；墙真正拦的是**翻墙**的手 —— 绕过门、自己进仓库掏东西。
- **「多写三个口子纯属麻烦」这笔账要往长了算。** 今天多写三个小口子，等楼下换里子那天，省下的是「翻遍全地图改几十处、还漏掉两处」的功夫。开头那只把猫全摆歪的本喵，就是没算这笔账喵。
:::

## 小任务

1. 动脑不动手喵：楼上要用三个口子拼出一个新口子 —— **报两只点的中点**。只准走 `make_point`、`point_x`、`point_y`，把这个 `point_middle(a, b)` 拼出来。
2. 接着上一题想：要是楼下**又**换了一趟里子，你这个新口子要不要跟着改？为什么喵？（提示：回头看看甲稿、乙稿、丙稿各自的下场。）
3. 学过 C 的「结构体」那一课（画图纸那一课）的话，把课文里楼下那三个口子亲手敲一遍、再补一句 `printf` 把中点报出来跑一跑；然后照着**乙稿**写一句 `a.x` —— 看看翻译官喵拦不拦你、拦的时候说的是什么喵。
