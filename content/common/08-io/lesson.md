## 钩子：只会念稿子，不会听

上一课本喵学会了把一整套动作打包成**招式**，还能往招式里投喂小鱼干。可你回头看看 —— 那些小鱼干，全是本喵**在代码里提前写死**的：

```python
name = "橘猫"
print(name, "开饭啦")
```

```text
橘猫 开饭啦
```

念是念出来了。可要是来的不是橘猫，是狸花猫呢？要是本喵想让你**敲上你自己的名字**呢？那本喵就得在代码里把「你是谁」提前猜准 —— 这显然办不到喵。

问题出在：到这儿为止，本喵的程序只有**一张嘴**（会念），没有**一只耳朵**（会听）。今天本喵就给它装上一只耳朵。

## 投喂与叼回：程序的两个口子

程序跟外面的世界打交道，靠的是两个方向的口子：

```text
你敲键盘  ——投喂——→  【程序】  ——叼回——→  屏幕上出现字
```

- **投喂**：东西从**外面**进到程序里。
- **叼回**：东西从程序里出来，送到屏幕上给你看。

一进一出这两件事合起来，术语表里给它起的原名是**输入输出（投喂与叼回）** —— 今天的主角喵。

「叼回」你其实早就会了：`print` 就是它。第一课你就让程序念过「你好，喵」，那是猫把东西叼回你脚边放下。今天要学的是**反过来的那一边 —— 投喂**。

能投喂进来的东西有很多种：你敲键盘打的字、你点鼠标的位置、别人发来的一条消息、文件里躺着的一整本账……今天本喵只讲最要紧、也最常用的那一种：**你敲键盘**。

还有一条现在就得记住，它是新手最容易犯迷糊的地方：**程序会停下来等你。** 代码本来是一路从上往下小跑的，可一跑到投喂口，它就像猫蹲在门口那样**一动不动地等**，一直等到你喂了东西、按下回车，才肯接着往下跑。屏幕上半天没动静 ≠ 程序坏了，它是在等你喵。

## 命令行交互：`input()` 这只投喂口

Python 里给程序装一只耳朵，喊的是 `input`（英文 input 就是「送进去」的意思）。最小的一问一答长这样：

```python
try:
    name = input("你是谁喵？")
except EOFError:
    name = "大肥鱼"

print(name)
```

```text
你是谁喵？大肥鱼
```

拆开看，每一步都有讲究喵：

- **`input("你是谁喵？")`** —— 括号里那句是**提示词**：程序先把这句话喊出来，让你知道它在问什么。
- 喊完它**不换行**，就张着嘴等 —— 你敲的字会紧跟在问号后面。这就是为什么输出里 `你是谁喵？` 和 `大肥鱼` 挤在同一行，一个换行都没有。
- 你敲完、按下回车，这一行字就被叼进程序，装进 `name` 这只小鱼干仓库。
- **`print(name)`** —— 再把它念回给你看。

**程序问一句、你答一句，这就是命令行交互。**（「命令行」就是那个等着你敲字的地方：你敲一行，它答一行，一来一往。）

程序在这个投喂口上一停一等，到底是怎么走的？本喵把它拆成一步一步，走给你看：

**投喂这一路的节奏就这四拍**：先喊提示词 → 蹲下来等你 → 你喂的那行被叼进仓库 → 才接着往下跑。中间那一拍**等多久全看你** —— 这就是「程序会停下来等你」喵。

提示词也可以不写：括号里空着、光秃秃一个 `input()`，它就一声不吭地等，屏幕上什么也不先印出来。

::: warn 小心喵
你大概正盯着上面那个 `try` 和 `except` 发愣 —— 别看它长得凶，本喵给你解释。

翻译官喵有个脾气：**投喂口空着的时候，它什么都读不到，会当场炸毛**，甩给你一段 `EOFError`（EOF 是「投喂口到头了」的意思），程序就断在半路。在练习场里，**输入框空着就点运行**，你也会看到它。

所以本喵给课文里这几段代码都系了一条**保险绳**：

- `try:` —— 先试着做下面那件事。
- `except EOFError:` —— 万一它因为没读到东西炸毛了，就改走这一段：本喵提前备好一条备用鱼干（`name = "大肥鱼"`）。

系上保险绳，这段代码**有没有人喂都能平平安安跑完**。这两行的来龙去脉，等本喵讲到「抓虫」那一课再细说，今天照着抄就行喵。

反过来说：**你自己写的时候不必系它**。在练习场里跑之前先把输入框填好，直接写 `input("你是谁喵？")` 也是好的。
:::

### 它叼回来的是一条项链，不是数

这是零基础最容易摔的一跤，本喵单独拎出来讲喵。

不管你在输入框里敲的是数字还是字，`input()` **一律当成一串小鱼干的项链**叼回来 —— 就是一串文字。你敲的 `3`，装进仓库的是 `"3"`：带引号的一串字，**不是整数罐**。

本喵试给你看：

```python
try:
    n = input("喂本喵一个数喵？")
except EOFError:
    n = "3"

print(n + n)
```

```text
喂本喵一个数喵？33
```

本喵想要的是 `3 + 3 = 6`，屏幕上却冒出来 `33`。为什么喵？因为 `n` 里装的是项链 `"3"`，而**两串项链用 `+` 是「接起来」**，不是加起来：`"3"` 接上 `"3"`，就成了一串更长的 `"33"`。

想真的算数，得先把项链上的数字**摘下来、变成整数罐**。干这件事的招式叫 `int`：

```python
try:
    n = input("喂本喵一个数喵？")
except EOFError:
    n = "3"

print(int(n) + int(n))
```

```text
喂本喵一个数喵？6
```

只改了一处：`n` 外面套了一层 `int(...)`。`int` 是英文 integer（整数）的前三个字母，本事就一句话：**把一串写着数字的项链，变成一个真正的整数罐**。不套这一层，`+` 就会一直给你接项链喵。

引号是这件事的照妖镜：`"3"` 是项链，`3` 是数 —— 讲小鱼干仓库那一课你就见过这条分界线，屏幕上写 `33` 还是 `6`，差别就在这一对引号上。

::: tip 猫咪提示
**`input()` 叼回来的永远是一串项链。** 想拿去算数，先 `int(...)` 套一层。

这一跤最难的地方在于：**忘了套，程序不会报错。** 它会欢快地印出一个 `33` 交给你，看着像跑通了，其实是本喵接错了。这种「不报错的错」往后还有很多，它就是最典型的那一个喵。
:::

### 一问一答：程序问几次，你就得喂几次

投喂口用起来的节奏是这样：

```text
【程序】你是谁喵？          ← 先把提示词喊出来
（然后张着嘴，一动不动地等）
你喂进去：大肥鱼            ← 你敲一行、按回车
【程序】大肥鱼              ← 它接着往下跑，把东西叼回屏幕上
```

**一次 `input()` 只吃一行。** 程序里写了两处 `input()`，它就要问你两遍，你也得准备两行来喂它。要是它问第二遍的时候输入框里已经没有东西了 —— 又是那段 `EOFError` 喵。所以本喵在点运行之前会先数一数：**这段代码要问几句？**

### 四只翻译官喵，各读各的输入

同一件事 —— 「从投喂口读一样东西进来」—— 四门语言的喊法差得很远喵：

| 语言 | 读进来喊的是 | 大约长这样（看个形状，不用记） |
|---|---|---|
| C | `scanf` | `scanf("%d", &n);` |
| C++ | `std::cin >>` | `std::cin >> n;` |
| Java | 请一位叫 `Scanner` 的帮手 | `int n = sc.nextInt();` |
| Python | `input()` | `n = input()` |

今天你只要认牢最下面那一行：**Python 读一样东西进来，一个 `input()` 就够**。另外三只，等本喵带你学具体语言那几课，再一个一个认喵。

### 在练习场里，投喂口在哪儿？

打开「**▶️ 运行代码**」这一页，工具栏上有一个框，上面写着「**程序要你输入什么吗？（不需要就留空）**」—— 那个框就是投喂口。要喂的东西写在里面，点运行，程序里的 `input()` 就会把那一行叼走。它问几句，你就喂几行；多喂的它不吃喵。

## 结果展示：把叼回来的东西念得漂亮

「叼回」这件事你在第一课就会了：`print`。可一旦有了投喂，**展示**就有了新的讲究 —— 本喵得把「你说的话」和「本喵要说的话」拼成一句，念给你看。拼法有两种，看清楚这两种的差别喵：

```python
name = "橘猫"
print("你好，", name, "喵")
print("你好，" + name + "喵")
```

```text
你好， 橘猫 喵
你好，橘猫喵
```

- **逗号拼法**（第一行）：`print` 会把逗号隔开的每样东西**各垫上一个空格**再印出来 —— 这条规矩你在绕鱼干跑圈那一课就见过。所以屏幕上多出来两个空格：`你好， 橘猫 喵`。
- **加号拼法**（第二行）：`+` 的本事是「把两串项链**接**成一串」（刚才那个 `33` 就是它干的）。它只管接，**不管垫空格** —— 缝要留多宽，得你自己把空格写进引号里。写紧了，出来就是 `你好，橘猫喵`。

另外还有一件小事值得亲眼看看：上面两句 `print` 打出了**两行**字。**一句 `print` 管一行** —— 你想分几行念，就写几句 `print`。

哪种拼法好？看你要什么喵：**想让东西之间留缝，用逗号；想让它们贴紧，用加号。** 拿不准就先用逗号 —— 它是 `print` 自己带的规矩，不容易写错。

::: tip 猫咪提示
「投喂与叼回」这一课，记住三句话就够用啦：

1. **投喂 = 东西进来，叼回 = 东西出去**；程序跑到投喂口会**停下来等你**。
2. **`input()` 读一行，叼回来的永远是一串项链** —— 要算数，先 `int(...)`。
3. **逗号垫空格，加号贴紧**；一句 `print` 管一行。
:::

## 四只翻译官喵一起报菜名

同一个任务：把「橘猫」和它今天吃的 `3` 条小鱼干，拼成一行 `橘猫 今天吃了 3 条小鱼干` 叼回屏幕上。

```compare
c::
#include <stdio.h>

int main() {
    printf("%s 今天吃了 %d 条小鱼干\n", "橘猫", 3);
    return 0;
}

cpp::
#include <iostream>
#include <string>

int main() {
    std::string name = "橘猫";
    int fish = 3;
    std::cout << name << " 今天吃了 " << fish << " 条小鱼干" << std::endl;
    return 0;
}

java::
public class Main {
    public static void main(String[] args) {
        String name = "橘猫";
        int fish = 3;
        System.out.println(name + " 今天吃了 " + fish + " 条小鱼干");
    }
}

python::
name = "橘猫"
fish = 3
print(name, "今天吃了", fish, "条小鱼干")
```

```text
橘猫 今天吃了 3 条小鱼干
```

同一句话，四只翻译官喵喊法各不相同喵：

- **C**：`printf` 靠**占位符** —— `%s` 的位置留给一串文字，`%d` 的位置留给一个整数，后面的东西**按顺序对号入座**。行尾的 `\n` 是「换行」，C 得自己写上，不写就全挤在一行里。
- **C++**：`std::cout << 一样 << 另一样` —— 顺着一个个丢到屏幕上。
- **Java**：`System.out.println(name + " 今天吃了 " + fish + " 条小鱼干")` —— Java 靠 `+` 把它们串成一整句再印。
- **Python**：`print(name, "今天吃了", fish, "条小鱼干")` —— 逗号隔开，每个逗号的位置自动垫一个空格。

看出门道了吗？**Python 那句里的空格是逗号垫出来的，另外三只是本喵自己写进引号里的** —— 可拼出来的句子一模一样。这就是「气质不同，做的都是同一件事」喵。
