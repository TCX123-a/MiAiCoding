## 钩子：面试官换了一道题

上一课，本喵学会了每次取最小的那只：桌上不管还剩多少鱼干，眼睛只盯住眼前最小的那一只，先拿走，再回头找下一只。靠着这股「只顾眼前」的劲头，本喵把一堆鱼干收拾得服服帖帖，尾巴都快翘到天上去了。

面试官大肥鱼没有夸本喵，反而笑了。他把题板翻到背面，尾巴尖在上面点了两下：「那我换个题：每次拿眼前最好的，你能保证最后最好吗？」

题板上摆着三种亮闪闪的硬币，面额分别是 4、3、1，每一种都堆了一小堆（想用几枚拿几枚），旁边写着一个数：6。大肥鱼推过来一只小碟子：「用最少的硬币凑出 6，你先拿拿看。」

本喵想都没想，伸爪就抓了最大的 4——眼前最好的，不拿它拿谁？可爪子刚落下，本喵就发现有点不对劲：碟子里只剩 2 了，3 再也用不上，只能拿两个 1，三枚。大肥鱼慢悠悠地把两枚 3 推到桌子中央：「两枚。」

本喵的耳朵一下子塌了。**每一步都拿眼前最好的，最后却不一定是最好**——这就是今天要讲的「贪心」，以及它什么时候会翻车喵。

## 贪心：每一步都拿眼前最好的

先把话说清楚。**贪心**是一种做选择的策略：

> 每一步都只看眼前，挑出当前看起来最好的那个选择，拿完就定下来；不回头改，也不把别的方案留着备用。

它像一只在鱼干货架前走路的猫：走到哪一格，就把那一格里最香的一根叼进篮子，然后继续往前走，绝不回头把篮子里的东西换掉。走到头，篮子里就是它交出的答案。

这个策略有两个很讨喜的地方：

- **快**：不用把所有可能的组合都摆出来比较，走一步算一步。
- **省地方**：只记住「当前最好的那个」，不用记住一大摞备选方案。

但它的代价也藏在这两个优点里：**它把「眼前最好」当成了「全局最好」**。一旦这个假设不成立，它就会一本正经地交出一个错的答案，而且因为没有留后路，连改都改不了。

还要注意：贪心不是一招固定的招式，而是一整族招式。同一道题，可以定出好几种「眼前最好」的规则——找零时可以「先拿最大面额」，区间调度时可以「先接结束最早的」。这些规则长得不一样，有的对，有的错。所以面试里说「用贪心」还不够，得说清楚**按什么贪、为什么这样贪是对的**。

本喵先给一个让猫放松警惕的例子。硬币面额是 1、2、5，要凑 6：先拿 5，剩 1，再拿 1，两枚搞定。换别的拿法：2 + 2 + 2 要三枚；想拿两枚，只能是 5 + 1。所以两枚确实是最好的，贪心在这里干得漂漂亮亮。

可大肥鱼题板上的那套硬币是 4、3、1。同样的「先拿最大面额」，同样的目标 6，结果就完全不一样了喵。

## 找零翻车：4 + 1 + 1 输给 3 + 3

本喵把大肥鱼那道题一步一步走一遍。规则是：**每次拿面额最大、但不超过剩余金额的那枚硬币**。

| 第几步 | 还要凑多少 | 眼前能拿的最大面额 | 拿完还剩 | 已经拿了 |
|---|---|---|---|---|
| 1 | 6 | 4 | 2 | 4 |
| 2 | 2 | 1（3 超过 2，拿不动） | 1 | 4, 1 |
| 3 | 1 | 1 | 0 | 4, 1, 1 |

三枚：**4 + 1 + 1 = 6**。

可大肥鱼给出的答案是两枚：**3 + 3 = 6**。

三枚对两枚，贪心输了。输在哪一步？就输在第一步那个看起来最漂亮的 4 上：

- 拿了 4，剩下 2。手里只有 1、3、4 三种面额，能填满 2 的只有 1 + 1，于是总枚数被顶到 3。
- 要是第一步忍住不拿 4、改拿 3，剩下正好是 3，第二枚 3 直接收工，总枚数 2。

4 是「眼前最大的」，可它也是「最堵路的」——它把剩下的 2 变成了一个只能用两个小硬币填的坑。贪心不会回头，所以它看不见「拿 3 更好」这条岔路。

这个具体的例子，就叫**反例**：一条规则说得再顺口，只要找到一个它能算错的输入，这条规则就被推翻了。面试的时候，**找反例往往比讲一堆道理更快**——大肥鱼后来说，他最喜欢看的就是候选猫能不能在三分钟内把 4、3、1 凑 6 这个坑挖出来喵。

这里还要补一句，免得把话说死：**不是所有找零都会翻车**。面额是 1、2、5 的时候，先拿大面额往往没事；面额是 1、3、4 的时候，同样的规则就栽了。贪心对不对，取决于题目的结构，不取决于规则听起来顺不顺耳。

## 贪心要成立，得凑齐两个条件

那怎么判断一条贪心规则靠不靠得住？教科书给了两个条件。

**第一个条件：贪心选择性质。**

意思是：**存在一个全局最优方案，它愿意把这一步的贪心选择收进去**。注意，不是「贪心随手一拿就一定在最优方案里」，而是「至少有一个最优方案，第一步可以按贪心的拿法来」。如果所有最优方案都绕开了贪心挑的那个，这条规则就废了。

拿找零来说：最优方案是 3 + 3，里面根本没有 4。第一步贪心拿 4，就找不到任何一个包含 4 的最优方案了——贪心选择性质当场失败。后面再怎么努力，也只能在「已经拿了 4」这个坑里打转。

**第二个条件：最优子结构。**

意思是：**拿掉这一步之后，剩下的问题还是同一道题；原问题的最优解，可以拆成「这一步的选择 + 剩下问题的最优解」**。

找零的剩下部分其实是有最优子结构的：拿了 4 之后，剩下 2 的最优解就是 1 + 1。问题出在前一个条件，不在后一个。区间调度则两个条件都满足，所以那条规则能站住。

那「最优子结构」和「贪心选择性质」怎么证明？面试里最常用的是**交换论证**。它的直觉不复杂：

> 先随便拿一个最优方案。如果它的第一步不是贪心挑的那个，就把贪心的选择**换进去**，证明换完以后「不冲突、数量不掉」。既然换完还是一个最优方案，那就说明「存在一个按贪心第一步走的最优方案」。剩下的部分再重复同一招。

本喵用区间调度把这句话落地。设 E 是所有活里**结束最早**的那一张。随便拿一个最优方案，把它接的第一张活叫 F。

- 因为 E 结束得最早，所以 E 的结束时间不晚于 F 的结束时间。
- 把 F 换成 E。原来排在 F 后面的那些活，本来就要等 F 结束才开始；现在 E 结束得更早或一样早，它们照样能接，一个都不用动。
- 换完，数量一张没少，还是一个最优方案，而且它包含了 E。

于是「先接 E」不亏。接完 E，剩下的活还是同一道「接尽可能多」的题，继续用同一招就行。**每一步都换掉也不亏，一路换到底，贪心拼出来的就是最优解**。

这就是交换论证的味道：不是拍脑袋说「最早结束看起来最划算」，而是能指着任意一个最优方案说「把它换成我的选择，它不会变差」。面试官要听的是后半句喵。

> **本喵提醒**：交换论证不是「听起来有道理」；要能说清「换进去为什么不冲突、数量为什么不掉」，才算把这招讲明白了。

## 区间调度：一屋子活，接哪几张

现在换一道更典型的贪心题。

大肥鱼在黑板上贴了一排便利贴，每张贴着一个活：`[开始, 结束]`。规则是：**同一时间只能接一张活**；一张活结束的那一刻，下一张活就可以开始（下课铃一响就进下一间教室，不算冲突）。问：**最多能接几张？**

比如三张活：`[(1, 10), (2, 3), (4, 5)]`。

本喵先试「按开始时间从早到晚，能接就接」：

| 顺序 | 活 | 判断 |
|---|---|---|
| 1 | (1, 10) | 开始最早，接 |
| 2 | (2, 3) | 开始 2 早于 10，和 (1, 10) 重叠，跳过 |
| 3 | (4, 5) | 开始 4 早于 10，还是重叠，跳过 |

只接到 **1 张**。可要是接 (2, 3) 和 (4, 5)，两张活首尾不打架，明明能接 **2 张**。按开始时间排，被那张又长又早的 (1, 10) 挡住了。

再试「按时长从短到长，能接就接」。三张活 `[(1, 4), (3, 5), (4, 7)]`，时长分别是 3、2、3：

| 顺序 | 活 | 判断 |
|---|---|---|
| 1 | (3, 5) | 时长最短，接 |
| 2 | (1, 4) | 和 (3, 5) 重叠，跳过 |
| 3 | (4, 7) | 开始 4 早于 5，还是重叠，跳过 |

只接到 **1 张**。可 (1, 4) 和 (4, 7) 在 4 点整交接，能接 **2 张**。时长最短的那张夹在中间，把左右两边都堵死了。

正确的规则是：**按结束时间从早到晚排序（给小鱼干排排坐），然后一张一张看，能接就接**。

具体做法只有三句话：

1. 把活按结束时间从早到晚排好；
2. 记住「上一张接的活什么时候结束」，一开始设成 0；
3. 当前这张的开始时间如果不早于上一张的结束时间，就接；否则跳过。

为什么是结束时间，不是开始时间、也不是时长？因为**结束得越早，留给后面的时间就越多**。开始时间早不早，管不了后面；时长短不短，也管不了后面——一张夹在中间的短活，照样能把左右两边的活全挡住。只有「什么时候收工」这个刻度，决定后面还能塞下多少活。

上一节的交换论证已经说明了：最早结束的那张，总能换进某个最优方案而不让数量变少。所以「按结束时间、能接就接」不是碰巧对，是能讲出道理的喵。

## 十一张活走一遍：为什么是 4

现在上大肥鱼压箱底的那组数据：

原来的顺序是：`(1, 4)、(3, 5)、(0, 6)、(5, 7)、(3, 9)、(5, 9)、(6, 10)、(8, 11)、(8, 12)、(2, 14)、(12, 16)`。

先把它们按结束时间从早到晚排好，顺序变成：

`(1, 4) → (3, 5) → (0, 6) → (5, 7) → (3, 9) → (5, 9) → (6, 10) → (8, 11) → (8, 12) → (2, 14) → (12, 16)`

然后一张一张看，「上一张的结束时间」一开始是 0：

| 顺序 | 活 | 上一张结束 | 这张开始 | 接不接 | 接完的结束 | 已接数量 |
|---|---|---|---|---|---|---|
| 1 | (1, 4) | 0 | 1 | 接 | 4 | 1 |
| 2 | (3, 5) | 4 | 3 | 跳过 | 4 | 1 |
| 3 | (0, 6) | 4 | 0 | 跳过 | 4 | 1 |
| 4 | (5, 7) | 4 | 5 | 接 | 7 | 2 |
| 5 | (3, 9) | 7 | 3 | 跳过 | 7 | 2 |
| 6 | (5, 9) | 7 | 5 | 跳过 | 7 | 2 |
| 7 | (6, 10) | 7 | 6 | 跳过 | 7 | 2 |
| 8 | (8, 11) | 7 | 8 | 接 | 11 | 3 |
| 9 | (8, 12) | 11 | 8 | 跳过 | 11 | 3 |
| 10 | (2, 14) | 11 | 2 | 跳过 | 11 | 3 |
| 11 | (12, 16) | 11 | 12 | 接 | 16 | 4 |

最后接到的四张是：

> **(1, 4)、(5, 7)、(8, 11)、(12, 16)**

四张之间还留着缝：4 到 5、7 到 8、11 到 12。**答案是 4**。

同一组数据如果按开始时间从早到晚排，会先接 (0, 6)，再接 (6, 10)，最后接 (12, 16)，只有 **3 张**——又一次证明「按开始时间」会吃亏。按结束时间排，才能把 (1, 4)、(5, 7)、(8, 11) 这些短活一张张塞进去，最后再补上 (12, 16)。

为什么 4 就是最多的？还是上一节那句话：最早结束的那张总能换进某个最优方案，接完它，剩下的活还是同一道题。每一步都没有把最优解换丢，走到最后当然就是最优喵。

## 贪心与动态规划：一条路走到黑，还是把账记下来

看到这里，本喵心里冒出一个问题：贪心翻车的时候，难道就没救了吗？

有救，但得换一条路。先把两条路的差别摆清楚：

| | 贪心 | 动态规划 |
|---|---|---|
| 手里留着什么 | 当前这一步的最好选择 | 一张记满小问题答案的表 |
| 会不会回头 | 不会，拿完就定 | 会把多个选择摆出来比较 |
| 什么时候靠谱 | 两个条件满足，或交换论证讲得通 | 子问题重复、选择互相牵连 |
| 典型场景 | 区间调度、按面额找零 | 找零的最优解、带收益的区间选择 |

**贪心不保存所有方案，只保留当前最好**。它像一条路走到黑：每一步都只带「眼下最满意的那件东西」，别的全扔了。这样当然轻快，可一旦眼下的选择把后路堵死，它也没有第二套方案可以拿出来。

动态规划不一样。它会把小问题的答案**记下来**：凑 0 要几枚、凑 1 要几枚、凑 2 要几枚……算过的不再重算，遇到更大的问题时直接翻账本。找零 [1, 3, 4] 凑 6，动态规划会老老实实比较「最后放一枚 1」「最后放一枚 3」「最后放一枚 4」三条路，算出 3 + 3 才是两枚；贪心只走了「先放 4」这一条，就交卷了。

那什么时候该用哪条路？本喵的经验是：

1. 先试着证明贪心：两个条件能不能对上？交换论证能不能讲通？
2. **不确定的时候，先找反例**。找到一个小反例，就说明这条贪心规则不能用，别再硬凑证明。
3. 找不到反例，也不等于就一定对；只能先把它当成「待验证的猜想」，面试时把理由讲清楚。
4. 如果贪心确实站不住，而题目又有「同一小段被反复算」的味道，那就该把算过的答案记下来了——这正是下一课要干的事。

## 代码：让程序替本喵数一遍

把刚才那张表写成程序：

```python
jobs = [(1, 4), (3, 5), (0, 6), (5, 7), (3, 9),
        (5, 9), (6, 10), (8, 11), (8, 12), (2, 14), (12, 16)]
jobs.sort(key=lambda job: job[1])
end = 0
count = 0
picked = []
for start, finish in jobs:
    if start >= end:
        picked.append((start, finish))
        end = finish
        count += 1
print(count)
print(picked)
```

```text
4
[(1, 4), (5, 7), (8, 11), (12, 16)]
```

三处要看清楚：

- `jobs.sort(key=lambda job: job[1])`：按每张活的**第二个数**（结束时间）排好。第一个数是开始，第二个数是结束，别按错了。
- `end` 是「上一张接的活什么时候结束」，一开始是 0；`start >= end` 就是「这张活开始得不早于上一张结束」，能接。
- 只有真的接了，才更新 `end` 和 `count`；跳过的时候这两个数一动不动。要是跳过也更新了 `end`，答案就会少得莫名其妙。

## 三位翻译官喵，同一组活

同样的规则换成三门语言，写出来像三只猫用不同的爪法干同一件事：先把活按结束时间排好，再一张张看能不能接，最后数一数。

```compare
cpp::
#include <iostream>
#include <vector>
#include <utility>
#include <algorithm>

int main() {
    std::vector<std::pair<int, int>> jobs = {
        {1, 4}, {3, 5}, {0, 6}, {5, 7}, {3, 9},
        {5, 9}, {6, 10}, {8, 11}, {8, 12}, {2, 14}, {12, 16}
    };
    std::sort(jobs.begin(), jobs.end(),
              [](const std::pair<int, int>& a, const std::pair<int, int>& b) {
                  return a.second < b.second;
              });
    int end = 0;
    int count = 0;
    for (const auto& job : jobs) {
        if (job.first >= end) {
            end = job.second;
            count++;
        }
    }
    std::cout << count << std::endl;
    return 0;
}

java::
import java.util.Arrays;

public class Main {
    public static void main(String[] args) {
        int[][] jobs = {
            {1, 4}, {3, 5}, {0, 6}, {5, 7}, {3, 9},
            {5, 9}, {6, 10}, {8, 11}, {8, 12}, {2, 14}, {12, 16}
        };
        Arrays.sort(jobs, (a, b) -> Integer.compare(a[1], b[1]));
        int end = 0;
        int count = 0;
        for (int[] job : jobs) {
            if (job[0] >= end) {
                end = job[1];
                count++;
            }
        }
        System.out.println(count);
    }
}

python::
```

三份程序的数据和规则一模一样，屏幕上落下的都是 **4**。语言换了一门又一门，贪心的那三句话没变：**按结束时间排、看上一张何时结束、能接就接**喵。

::: tip 猫咪提示
1. **找零反例要背下来**：硬币 [1, 3, 4] 凑 6，贪心 4 + 1 + 1 = 3 枚，最优 3 + 3 = 2 枚。面试官问「贪心一定对吗」，先把这个反例摆出来。
2. **区间调度记三句话**：按结束时间从早到晚排；记住上一张的结束；开始不早于结束就接。
3. **找不到反例不等于证明**：只能说明这条规则暂时没被抓到把柄；要敢说「它成立」，得讲清两个条件，或者用交换论证说明「换掉不亏」。
:::

::: warn 小心喵
- **边界写错**：课文用 `start >= end`，意思是「上一张结束的那一刻，下一张就能开始」。如果题目规定「同一时刻只能有一张」，那就得改成 `start > end`——读题时先看清这个约定。
- **跳过的活也更新 end**：只有真的接了，才更新结束时间和计数。跳过的时候更新，会把后面的活莫名其妙地挡掉，答案偏小。
- **把「贪心」当成「永远最优」**：贪心是一种策略，不是一张保票。规则对不对，要看题目结构；说不清就找反例。
:::

## 小任务

1. 用 [1, 3, 4] 凑 10：先按「每次拿最大面额」走一遍，数数贪心拿了几枚；再找找有没有更少的拿法。提示：4 + 4 + 1 + 1 是 4 枚，4 + 3 + 3 是 3 枚喵。

3. 用 `[(1, 4), (3, 5), (4, 7)]` 走一遍「按时长从短到长」的规则，看看它为什么只接到 1 张，而正确答案是 2 张；再把「按开始时间」的反例 `[(1, 10), (2, 3), (4, 5)]` 给别的猫讲一遍。

大肥鱼把题板擦干净，尾巴在「贪心」两个字上敲了敲：「记住，贪心不是错，错的是没检查。拿眼前最好的之前，先问自己两句：这一步能不能换进某个最优方案？换完剩下的还是不是同一道题？」本喵把这两句抄在小本子上，爪尖还有点发烫。

可大肥鱼还没打算放本喵走。他把题板翻回找零那道题，指了指 4 + 1 + 1：「你看，贪心翻车的题，往往是因为同一小段被反复算——凑 2 的最优解，凑 3 的最优解，凑 4 的最优解，算了一遍又一遍。算过的，记下来，下次直接查，不就不用重算了吗？」
