## 钩子：橘猫端回来一条生鱼

本喵饿了，冲厨房喊一嗓子：「橘猫——弄点吃的来，别太干！」

橘猫歪头想了想，跑出去，叼回来一条**生鱼**。

本喵想吃的是泡好的猫粮喵。可回头看看本喵那句话：「弄点吃的」是猫粮还是生鱼？「一点」是一口还是一碗？「别太干」到底要多湿？——**这句话一个字都没错，可它什么也没说死。**

上一课《算法入门》里讲过：算法就是一张「怎么把一件事办成」的清单。今天要问的是更细的一层：这张清单**写到什么程度**，别的猫念一遍就能照着做、还不会念歪？

本喵有三套说法，一套比一套说得死喵。

## 说法一：唠嗑版

最省事的一套，就是本喵刚才那样**唠嗑**。这套说法的学名叫**自然语言**——猫和猫平时说话用的那套字。

唠嗑版的好处写在脸上：**快**。本喵喊一嗓子，橘猫立刻动身，不用先听本喵念一张单子。

可它有两个洞：

- **会漏**：本喵没说水温，橘猫就可能倒一瓢凉水。
- **会歪**：本喵说「搅一搅」，橘猫搅了一圈——而本喵心里的「一搅」是十圈。

一句话：唠嗑版**说给人听够用，照着一步步做就不够**。听的人一边干一边猜，猜岔了就得返工。

## 说法二：菜谱版

要照着做，就得换一套说法：把这件事写成**菜谱**。它的学名叫**伪代码（写给别的猫看的菜谱）**——「伪」就是「假」：它长得像代码，却**不是**哪门语言的真代码，电脑一个字都读不懂，**它是写给别的猫看的**。

本喵把泡猫粮写成菜谱，差不多是这样：

```text
泡一碗猫粮：
    拿一只空碗
    倒进一碗温水
    撒进两把猫粮
    搅三圈
    等三分钟
    如果猫粮还硬：
        再等一分钟
    端给本喵
```

这张菜谱比唠嗑版强在哪儿喵：

- **一行一件事**：每行只写一个动作，不把两件事塞进同一行。
- **不挑语言**：不用管哪门语言要分号、哪门要点号，菜谱只顾把事说清楚。
- **谁照着做都一样**：「搅三圈」就是三圈，「等三分钟」就是三分钟——猜不出第二种意思。

它是**猫和猫之间**的写法：本喵写得出来，橘猫照着做得了，换只猫来照样做对。

## 说法三：路线图版

菜谱是竖着一行行念下来的。可这件事里藏着一个「拐弯」：**如果猫粮还硬，就得再等一分钟**——等完还得回头看一眼还硬不硬。竖着念到这儿，容易念晕。

拐弯多的活儿，就得请出第三套说法：**路线图**。它的学名叫**流程图（会分岔的路线图）**——把每一步画成一个框，框和框之间拉箭头，箭头指哪儿就往哪儿走：

```text
[ 拿一只空碗   ]
       ↓
[ 倒进一碗温水 ]
       ↓
[ 撒进两把猫粮 ]
       ↓
[ 搅三圈       ]
       ↓
[ 等三分钟     ]  ←────────────────┐
       ↓                            │
< 猫粮还硬吗？ >                    │
       ↓                            │
       ├── 是 ─> [ 再等一分钟   ] ┘
       ↓
       └── 否 ─> [ 端给本喵     ]
```

（画得潦草喵，看懂意思就行。）

路线图最会画两件事：

- **分岔**：`< 猫粮还硬吗？ >` 这个框是个岔路口，先看一眼情况，再挑一条路走——是就再等一分钟，否就往下去端碗。
- **绕回头**：右边那条线，把「再等一分钟」送回「等三分钟」重新排一次队——**只要还硬，就一圈一圈绕下去**。这一手，正是上一课讲过的**绕鱼干跑圈**。

## 三种说法，说的是同一件事

把三套说法摆在一起看：

| 说法 | 学名 | 最擅长 | 什么时候挑它 |
|---|---|---|---|
| 唠嗑版 | 自然语言 | 快，随口就来 | 说给听得懂的猫听，不要求他一步不差 |
| 菜谱版 | 伪代码 | 一行一件事，谁做都一样 | 要别人照着做，还要做得一模一样 |
| 路线图版 | 流程图 | 分岔、绕回头一眼看得见 | 这件事拐弯多、还要绕回去 |

三套说的是**同一件事**——泡一碗猫粮。挑哪一套，只看你要说给谁听、这件事拐不拐弯喵。

## 菜谱落到代码上

菜谱再清楚，电脑也读不懂它——电脑只认真正某门语言的代码。所以最后一步是：**照着自己写好的菜谱，把它翻译成代码**。

菜谱上那行「搅三圈」，换成 Python 就是这样，跑出来是四行字：

```python
bowl = "温水 + 猫粮"
for i in range(3):
    print(f"搅第 {i + 1} 圈：{bowl}")
print("端给本喵")
```

```text
搅第 1 圈：温水 + 猫粮
搅第 2 圈：温水 + 猫粮
搅第 3 圈：温水 + 猫粮
端给本喵
```

对着看就明白了喵：菜谱的「搅三圈」是 `range(3)` 管的那三圈；菜谱的「端给本喵」是最后那一句。**代码看着吓人，其实只是把菜谱一行一行念给翻译官喵听。**

## 四位翻译官喵，同一张菜谱

同一张菜谱，四位翻译官喵念出来的腔调各不相同，可做的事一模一样：

```compare
c::
#include <stdio.h>

int main() {
    char bowl[] = "温水 + 猫粮";
    for (int i = 0; i < 3; i++) {
        printf("搅第 %d 圈：%s\n", i + 1, bowl);
    }
    printf("端给本喵\n");
    return 0;
}

cpp::
#include <iostream>
#include <string>

int main() {
    std::string bowl = "温水 + 猫粮";
    for (int i = 0; i < 3; i++) {
        std::cout << "搅第 " << i + 1 << " 圈：" << bowl << std::endl;
    }
    std::cout << "端给本喵" << std::endl;
    return 0;
}

java::
public class Main {
    public static void main(String[] args) {
        String bowl = "温水 + 猫粮";
        for (int i = 0; i < 3; i++) {
            System.out.println("搅第 " + (i + 1) + " 圈：" + bowl);
        }
        System.out.println("端给本喵");
    }
}

python::
bowl = "温水 + 猫粮"
for i in range(3):
    print(f"搅第 {i + 1} 圈：{bowl}")
print("端给本喵")
```

```text
搅第 1 圈：温水 + 猫粮
搅第 2 圈：温水 + 猫粮
搅第 3 圈：温水 + 猫粮
端给本喵
```

四段念出来的是**同样四行**。C 和 Java 写 `i + 1`，C++ 把它夹在箭头里拼，Python 干脆把算式塞进句子里——四种写法，同一张菜谱喵。

::: tip 猫咪提示
拿到一件事，先问自己两句话：**这件事要拐弯吗？** 拐弯多就画成路线图，不拐弯就写成菜谱。

给别的猫看的东西，**别停在唠嗑版**：「搅一搅」「等一会儿」「差不多就行」——这种话谁念谁猜。写成「搅三圈」「等三分钟」，才叫把话说死喵。
:::

::: warn 小心喵
菜谱**不是代码**：它长得像代码，可你把它粘进练习场，翻译官喵一个字都读不懂，会当场翻脸。它的用处是**先想清楚再动手**——菜谱在脑子里跑通了，再照着它的意思写成真代码。

另一个坑是写得太细：菜谱写到「拿碗」就够用了，写到「伸出左前爪、爪尖对准碗沿」就是白费力气。**细到别人不会做错就停手**，多一个字都是浪费喵。
:::

## 小任务

今天的小任务，第一件不用碰键盘也能做喵：

1. 挑一件家常事（比如「煮一包方便面」），先写**唠嗑版**，再把它改写成**菜谱版**。改的时候数一数：唠嗑版里有多少个词是「别人只能猜」的？
2. 把课文里那段代码抄进练习场跑一遍，再把 `range(3)` 改成 `range(5)`——屏幕上会多出几行？`i` 又是从几开始数的？
3. 给菜谱版加一条新规矩：**「如果本喵不在家，就把碗放进保温箱」**。再想一想，这一条该画在路线图的哪个位置喵？
