## 钩子：同一个门牌号

上一课《一声开饭，各吃各的》收工时，本喵把一句老话又立了一遍：**加新东西，不动老代码** —— 谁的本事谁自己带着，喊一声就有回应。

下课之前本喵往 Python 那边多瞟了一眼，看到一件更夸张的事：在 Python 里，答得上话的角色名单长得多 —— 本喵冲着光溜溜的一个 3 问「你是谁家的」，它居然也答得上来。（后话，先记一笔。）

先说眼下这堵墙。

本喵前面几课一直用一块招牌：变量（小鱼干仓库）—— 起个名字、把东西装进去。照这个世界的规矩，`b = a` 就是把仓库里的东西**照抄一份**，另开一座新仓库。本喵到了 Python 照样这么想，结果啪一下，撞墙了喵：

```python
a = 3
b = a
print(a is b)
```

```text
True
```

按仓库的规矩，b 该是一座新仓库 —— 怎么跟 a 要到了**同一个门牌号**？今天本喵把 Python 的底牌翻过来看：**名字不是盒子 —— 名字是贴在本体上的**。

## 先看 C：盒子世界观

C 里写下一句 `int a = 3;`，本喵脑子里想的是：**借一只叫 a 的盒子，把 3 装进去**。往后每一句，都是往这个画面上添笔画：

- `a = a + 1;` —— 打开 a 这只盒子，把里面的数**换**成 4；
- `int b = a;` —— 照着 a 的样子**再拗一只盒子**，把里面的 3 **抄**一份进来。

从这一刻起，a 和 b 是**两只互不相干的盒子**：往后谁改了谁，另一只一个字都不会动。这份画面对 C 处处都对得上 —— 连 `&a` 要到的那个门牌号，也是**盒子**的门牌号，跟盒子里的那个 3 没关系。

本喵不是来推翻它的。那块招牌就是照着 C 的盒子画的 —— 在 C 的地盘上，它分毫不差。本喵要说的是：**这块招牌只画了世界的一半**。换上 Python，同一句 `b = a` 里住着的，是另一半。

## Python 的底牌：名字贴在本体上

在 Python 里，`a = 3` 不是「借盒子装东西」，是**把 a 这个名字，贴到 3 这个本体上**。

3 有自己的**身份** —— 内置的 `id()` 一伸手就能要来它；本体在，编号就在。前几课那套「遥控器」的比喻在这里换个摸法：名字攥着线头，指到哪只本体，动起来就动到哪只本体上 —— **名字贴在本体上，不装在盒子里**。两种摸法说的是同一件事，今天这套更贴 Python 的手感。

先看最基础的一手 —— 两个名字贴同一只 3，再给 a 换一只：

```python
a = 3
b = a
print(id(a) == id(b))
print(a is b)
a = a + 1
print(a, b)
print(a is b)
```

```text
True
True
4 3
False
```

一句一句看喵：

- **`b = a`**：Python 里没有「照盒子抄一份」这个动作 —— 只是**多了一个名字**，也贴到那只 3 上。所以前两句都答 True：两个名字的**门牌号一样**（`id(a) == id(b)`），贴的是**同一只**（`a is b`）。
- **`a = a + 1`**：等号右边**先算**：3 + 1 造出一只**新的 4**；等号左边不是「往盒子里塞」，是**把 a 这个名字撕下来，改贴到新的 4 上**。b 从头到尾没人碰，还贴着 3 —— 所以印出来是 `4 3`。
- **最后一句**：False。`is` 只问一件事：**两个名字贴的是不是同一只本体**。现在 a 贴着 4、b 贴着 3，不是同一只。

这里要记住一个小地方：**「改 a」改的是名字贴哪儿，不是把 3 改掉了** —— 3 这种本体天生**改不了**；想让 a 变成 4，只能再造一只新的 4。加法、`None`、小鱼干项链，都是这种改不了的本体。这件事在 C 里看不出来（那边是打开盒子换数），在 Python 里却是一道分水岭。

顺带记一笔闲账：小整数（-5 到 256）是 Python **提前造好、反复发**的 —— 所以（像上面那段开头）先写 `a = 3`、再写一句 `c = 3`，`a is c` 照样是 True：全 Python 的 3 就那一只。当闲账看就行，别拿它当规矩使（数一大就不一定了）。

换一只**改得动**的本体，试试同一件事：

```python
bowl1 = [1]
bowl2 = bowl1
bowl2.append(2)
print(bowl1)
```

```text
[1, 2]
```

`bowl2.append(2)` 是**对着碗本体**添东西 —— 不是「给 bowl2 换一只新碗」。碗只有一只，两个名字都指着它，所以 `bowl1` 里也多了个 2。带着 C 的盒子直觉看这一句，准要踩坑：心里想着「bowl2 是副本，改它关 bowl1 什么事」—— **它俩本来就是同一只碗**。

## 一切皆对象（连 3 都有自己的身份）：它答得出「我是谁家的」

回到开头那个 3。

在 C 的地盘上，「3 是哪家的」这句话**问不出口** —— C 里没有「哪张图纸造的」这回事，3 只是盒子里的家当。C++ 好一点，`typeid` 能问一句，可问到的大多是**编译的时候**就记好的账 —— 例外只有一个：拿猫爪指向牌问它**背后那只真猫本身**（`typeid(*p)`）时，那笔账要跑起来才现翻。Java 里光溜溜的 `int` 也问不出口 —— 得先**装箱**（给 3 照 `Integer` 图纸生一只真猫），才够得着「万物皆有本体」的世界；这一步，往后 Java 语言线「自动装箱」那一课会拆给你看。

Python 这边，**张嘴就答**：

```python
print(type(3))
print(type("喵"))
print(type(print))
print(type(None))
```

```text
<class 'int'>
<class 'str'>
<class 'builtin_function_or_method'>
<class 'NoneType'>
```

3 答 int；「喵」 答 str；**`print` 这个招式本身**答 builtin_function_or_method —— 招式也是照图纸造出来的本体；连「什么都没有」的 `None` 都有自己的家。那图纸自己呢？照它生出来的猫有 `type`，它自己也有：

```python
class Cat:
    def __init__(self, name):
        self.name = name

print(type(Cat))
```

```text
<class 'type'>
```

这句话落到手感上，就是三件顺手的事：**能问 id、能答 type、能被名字贴着到处递** 的东西，在 Python 里不分三六九等 —— 数、字、招式、图纸、`None`，全在名单上。这份底牌为什么值钱？回到上一课那句话：**「新的」不惊动老的**。在 Python 里，能当「新来的」的名单长得多 —— 招式能当小鱼干递给别的招式，图纸能当数据传来传去。今天先把眼镜戴上，这门手艺后面语言线里正经学。

## 四位翻译官喵，同一件「换名字」

同一件小事：给 a 记 3，b 记下 a，再把 a 改成 4 —— 看看最后 b 是多少。

```compare
c::
#include <stdio.h>

int main(void) {
    int a = 3;              /* 盒子 a，装进 3 */
    int b = a;              /* 再拗一只盒子 b，把 3 抄进去 */
    a = a + 1;              /* 把 a 盒子里的数换成 4 */
    printf("b 还是 %d 喵\n", b);
    return 0;
}

cpp::
#include <iostream>
using namespace std;

int main() {
    int a = 3;              // 盒子 a，装进 3
    int b = a;              // 再拗一只盒子 b，把 3 抄进去
    a = a + 1;
    cout << "b 还是 " << b << " 喵" << endl;
    return 0;
}

java::
class Main {
    public static void main(String[] args) {
        int a = 3;          // 光溜溜的家当，照样抄一份
        int b = a;
        a = a + 1;
        System.out.println("b 还是 " + b + " 喵");
    }
}

python::
a = 3          # 名字 a 贴到 3 上
b = a          # 名字 b 贴到同一只 3 上——谁也没抄
a = a + 1      # 给 a 换贴一只新的 4
print(f"b 还是 {b} 喵")
```

```text
b 还是 3 喵
```

四段印出来一模一样 —— 可「b 为什么没跟着变」，四位心里的算盘**完全不一样**：

- **C**：`int b = a;` 是**真的又拗了一只盒子**，3 是抄进去的 —— b 从出生起就和 a 各过各的；
- **C++**：盒子对盒子，同样抄一份；
- **Java**：`int` 是光溜溜的家当，照样抄一份；
- **Python**：压根没有「抄」这个动作 —— b 贴的本来就是 a 贴着的那只 3；`a = a + 1` 是给 a **换了只新的本体**，b 原地不动。

所以「b 还是 3」这一句，四门语言**答得一样、想得不一样**。这正是本喵最担心的那一下：从 C 过来的人，今天这一句会**蒙对** —— 因为 3 改不了；换成一只改得动的碗，请翻回上面 `bowl2.append(2)` 那段再读一遍喵。

## 图纸上的那一份，和每只猫自己的那一份

名字这套底牌，落到图纸上，还有一处分家要看。

前面《`main` 只是一扇门》那一课立过一根界线：有的东西**画在图纸上**，全班共用一份（Java 那边写着 `static`）；有的东西**每只真猫自己带**一份。Python 里这条线更好画 —— **直接写在 `class` 里、不缩进进 `__init__` 的，就是画在图纸上的那一份**。

```python
class Cat:
    legs = 4                  # 画在图纸上的那一份

    def __init__(self, name):
        self.name = name      # 每只猫自己带的那一份

c1 = Cat("橘猫")
c2 = Cat("狸花")
print(c1.legs, c2.legs, Cat.legs)
Cat.legs = 3
print(c1.legs, c2.legs, Cat.legs)
c1.legs = 2
print(c1.legs, c2.legs, Cat.legs)
```

```text
4 4 4
3 3 3
2 3 3
```

一行一行看喵：

- **`4 4 4`**：c1、c2 自己身上都没写过 legs —— 拿真猫名念一个名字时，Python **先看它自己身上有没有；没有，才抬头上图纸找**。两只都从图纸上读到了 4。
- **`Cat.legs = 3`**：拿**图纸名**改图纸上的那一份 —— 两只猫都够得着，全班一起从 4 变 3。（改动的动作还是贴名字那套：把图纸上的 legs 撕下来、改贴到 3 上。）
- **`c1.legs = 2`**：这一回是**给 c1 自己贴了一份**。从这一刻起，念 `c1.legs` 先在自己身上就找到了，不再上图纸；c2 身上没有，照旧跟着图纸走。所以是 `2 3 3` —— 一只开小灶，另一只没动。

再往后，图纸上再改，也只带得动**还没自己那份**的猫；已经有自己那份的（比如 c1），图纸换成什么都不理会。

坑探（挑刺前传）：本喵踩过的那一下 —— 想给橘猫**单独**加一条腿，手一顺，写的是图纸名：

```python
class Cat:
    legs = 4

c1 = Cat()
c2 = Cat()
Cat.legs = 5
print(c1.legs, c2.legs)
```

```text
5 5
```

「本喵只想给橘猫开小灶，狸花猫怎么也多长了一条？」—— 因为 `Cat.legs = 5` 改的是**图纸上那一份**，两只猫身上都没有自己的那份，全班只好跟着变。想开小灶，得拿真猫名：`c1.legs = 5`。

反过来也一样：想改全班、手一顺写成 `c1.legs = 5` —— 程序跑得飞快，只有橘猫变了，图纸一个字没动。**拿图纸名，和拿真猫名，是两件事。**

「static」那一课那句判据句在这里照样好使：**它是不是每只猫自己都得有一份？** 是 → 写进 `__init__`、带 `self.`；不是 → 直接写在 `class` 里。

::: tip 猫咪提示
- 名字不是盒子：`a = 3` 是贴名字；`a = a + 1` 是**换贴**到新造的本体上 —— 那边的 3 一个字没改。
- 三把尺子分家记：`id` 要门牌号，`is` 问是不是同一只本体，`==` 只比长相。
- 图纸上的那一份（写 `class` 里的）全班共用；每只猫自己的那一份（`self.`）各归各。拿真猫名念一个名字，先看自己身上，没有才上图纸。
:::

::: warn 小心喵
- 带着盒子直觉过来，「`b = a` 之后 b 就是副本」这条**今天蒙对、明天栽**：3 这种改不了的本体看不出区别，换成会变的碗立刻现形。
- `Cat.legs = 5` 改的是全班；`c1.legs = 5` 贴的才是 c1 自己 —— 手一顺写反了，程序不报错，账悄悄错。
- `is` 不是「等于」：`bowl1 == [1, 2]` 是 True，`bowl1 is [1, 2]` 是 False —— 右边那句 `[1, 2]` 是新造的**另一只碗**。
:::

## 一句话对照表

| 本喵写下的 | 它的意思 |
|---|---|
| `a = 3` | 把名字 a **贴**到 3 这个本体上（不是往盒子里装） |
| `b = a` | 多一个名字贴到**同一只**本体上 —— 什么也没复制 |
| `a = a + 1` | 先造一只新的 4，再把 a 撕下来改贴过去；b 原地不动 |
| `id(a)` | 直接问本体要门牌号（身份） |
| `a is b` | 两个名字贴的是不是**同一只**本体 |
| `a == b` | 两样东西**长得**是不是一样 |
| `type(x)` | 问一句「x 是哪张图纸造的」 |
| `Cat.legs = 3` | 改类属性（画在图纸上的那一份），全班一起变 |
| `c1.legs = 2` | 写实例属性（每只猫自己带的那一份），从此外面怎么改都不跟 |
