## 钩子：同一个软件，写 C 能跑，写 Java 甩脸子

大肥鱼这几天蹲在一支写代码的软件里：敲了个 C 程序，一按运行——顺顺当当。转头换了个 Java 程序，同一个软件、同一个按钮，回话却是一句「找不到」。

稿子没变、手指没变、按钮也没变，怎么一换语言就翻脸喵？

上一课把「找不到」的三种真凶盘问过了：名字、装没装、路牌。今天换个角度，看问题正中间的那根按钮：**按下去的那一刻，它到底做了什么？**

## 写字台与大宅子：编辑器与 IDE

先认两支软件。最小的一支叫**编辑器**——一支好写字的笔：让你把字敲进去、改、存下来。记事本也算编辑器，只是太素；VS Code 是本机常驻的一支写字台。

再大一号的叫 **IDE**——可以想成一间**大宅子**：写字台还在，可旁边还摆着一摞设备——按语言配好的翻译官喵、一只运行按钮、抓虫的家伙什、认路的档案，全搬进一间屋子。本机的大宅子叫 IDEA（2024.1），Java 课住在里面。

一句话记：**编辑器管写；IDE 是把一整条工具链摆进屋。** 屋子越大，替你干的活越多——替你干得越多，要你有数的小旋钮也越多。

## 「运行」按钮背后，其实是三件小事

你点一下运行，它不是魔法。拆开来，是三件小事：

1. **拼命令**——把你点的那一下，拼成一行真正的**命令**（比如 `python main.py`）；
2. **找翻译官喵**——拿着上一课那张路牌清单，去找这行命令开头那位。找不找得到，就是「配置」管的事；
3. **跑，收输出**——请它干活，把回话贴回按钮下面那扇小窗。

## 配置：两个常坏的旋钮

「配置」这个词听着像玄学，其实多数时候就是两个旋钮：

1. **工具路径**——按钮该请谁上场：请谁、请的是哪一版。同一个软件，写 Python 时指到哪只 `python`，写 Java 时指到哪套 JDK，都记在它的档案里。指错了、或者没指，按钮就空转；
2. **工作目录**——命令「站在哪间屋子的门口」执行：稿子在哪儿，干活出来的东西落在哪儿。

你在练习场里按过无数回的那只运行按钮，其实早替你拧好了这两个旋钮——今天把它们翻出来给你看。以后碰上按钮不灵，就问三句：**它拼了什么命令？请的是谁？站在哪？**

## 参观：三间屋子，与一位老翻译官喵

三间常见的屋子（具体地址以你自己的电脑为准）：

- **IDEA 2024.1**（`<你安装 IDEA 的目录>\IntelliJ IDEA 2024.1`）：Java 课的大宅子。新建项目时它要问：「用哪套 JDK？」「东西造出来放哪？」——那两问，就是上面两个旋钮。《一个箱子三个名字——JDK、JRE 与 JVM》把这一整套箱子讲透，《IDEA 里的大宅子——Project、Module、Package、Class》会带你把这间屋子整个走一遍；
- **VS Code**（`C:\Users\你的用户名\AppData\Local\Programs\Microsoft VS Code`）：常驻的写字台。装 C 的插件、装 Python 的插件，同一支软件就长出不同本事——本事从哪来，配置里找；
- **Dev-C++**（`C:\Program Files (x86)\Dev-Cpp`）：一间老屋子，里面住着一位**老翻译官喵**——TDM-GCC 4.9.2。

说到这位老翻译官喵，本喵得先讲一段真事。同一份稿子，先给练习场自带那套（新翻译官）过目：

```c
#include <stdio.h>

int main(void) {
    for (int i = 1; i <= 3; i++) {
        printf("%d\n", i);
    }
    return 0;
}
```

```text
1
2
3
```

顺顺当当。可同一份稿子、一字不改，交到 Dev-C++ 里那位老翻译官喵手上——它翻脸了。

## 老翻译官喵，为什么不认这行字

它指着稿子的第 4 行，回话原样抄给你（一个字符没改）：

```text
main.c: In function 'main':
main.c:4:5: error: 'for' loop initial declarations are only allowed in C99 or C11 mode
     for (int i = 1; i <= 3; i++) {
     ^
main.c:4:5: note: use option -std=c99, -std=gnu99, -std=c11 or -std=gnu11 to compile your code
```

翻译官喵认的**规矩册也分版本**喵：把 `int i` 直接写在 `for` 的括号里，是「C99」这册新规矩才收进来的写法；老翻译官喵的旧册子（默认按 C89 那本老规矩办事）不收——于是同一份稿子，它当场翻脸。练习场里钉死了按新规矩翻，所以那份稿子在那儿永远顺当。

**换一位翻译官喵，就是换了一册规矩；版本，也是「环境」的一半。** 上一课那句「谁上场」，这就是活标本。

## 心智模型：IDE 不神奇

现在回头看开头的怪事：同一支 VS Code，写 C 能跑、写 Java 甩脸子——不是软件坏了，是「找翻译官」那一环的配置没指到人。

按钮不灵时你会干嘛？现在是拆到**命令**这一层看：拼了什么、请了谁、站在哪。**会看命令的人，换任何一支软件都不慌**——所谓 IDE，不过是替你敲命令的老朋友，换了个皮。

- 想再看一遍「命令」长什么样：回去翻上一课的三件套；
- 想见这只按钮的完整履历：Java 线的综合大项目会把这只按钮接着讲下去；Python 线还有一整课，专门教你怎么按暂停键、一步步抓虫。

## 验收一下：四位翻译官喵，同一句话

不管按钮背后站着谁，四位翻译官喵的本职没变。同一句任务交给它们，写法各异、回话依旧一字不差：

```compare
c::
#include <stdio.h>

int main(void) {
    printf("点一下运行，背后是三件小事喵\n");
    return 0;
}

cpp::
#include <iostream>
using namespace std;

int main() {
    cout << "点一下运行，背后是三件小事喵" << endl;
    return 0;
}

java::
class Main {
    public static void main(String[] args) {
        System.out.println("点一下运行，背后是三件小事喵");
    }
}

python::
print("点一下运行，背后是三件小事喵")
```

```text
点一下运行，背后是三件小事喵
```

::: tip 猫咪提示
这一课的三句话，收好喵：

1. **编辑器管写，IDE 摆一屋子**：运行按钮、翻译官、抓虫家伙什，都是屋子里的设备；
2. **按钮背后三件小事**：拼命令 → 找翻译官喵（拿路牌清单）→ 跑、收输出；
3. **配置两个旋钮**：工具路径（请谁）、工作目录（站哪）——按钮不灵，三连问：拼了什么、请的是谁、站在哪。
:::

::: warn 小心喵
两个坑，本喵标出来：

- **「IDE 坏了」先别重装**：九成的按钮不灵，是配置没指对人或路牌没挂上——重装一遍软件，旋钮该歪还是歪；
- **版本不是小事**：老翻译官喵的故事就在眼前——同一份稿子，换一位上场就是另一个结局。报「找不到」时，别只问「装没装」，还要问「哪一版、哪一位」。
:::

## 小任务

1. **动脑**：把你最近写的一行程序倒着推一遍——它要是变成一行命令，开头那位会是谁？（`python`？`javac`？`gcc`？）
2. **动手**：把上面那段绕圈的稿子抄进练习场跑一遍（预期是 1 2 3）；再想想：同样的 1 2 3，老翻译官喵为什么不认它？
3. **参观**：打开你手边的 IDEA 或 VS Code，找到「设置」里跟运行、翻译官有关的那一栏，看看它指着哪一只家伙什。

按钮会拆了，配置就不怕——但工具链的线还没走完：文件一多，还有个大家伙在等着。下一课《为什么要有管家——构建工具存在的理由》——一个文件时手敲挺帅，三百个文件时手就废了，见喵～ 🐾
