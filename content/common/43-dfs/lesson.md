## 钩子：大肥鱼把本喵丢进了网里

上一课，本喵把一张关系网装进了邻接表：每个点后面挂着一串它认识的点，谁跟谁有边，翻开表就一清二楚。今天面试官大肥鱼把这张网往桌上一拍，拎起本喵的后颈皮就把本喵丢了进去，只丢下一句话：

> 「给你一个起点。走一遍，把能到的点都走给我看——不许漏，也不许在原地打转。」

本喵落在 0 号点上，四面八方都是路。怎么走才既不漏、又不绕圈？本喵想了一秒，给自己立了一条死规矩：**只要前面还有没去过的点，就一头扎进去；扎到没路可走了，才退回来换一条。** 说白了就是——**一条路走到黑，撞墙再退回来**。

这一招有个正经名字，叫**深度优先搜索**（Depth-First Search，简称 **DFS**）。本喵管它叫「一条路走到黑」。这一课就把这条黑路走给大肥鱼看。

## 一条路走到黑，撞墙再退回来

先把网摊开。这一课从头到尾都用同一张图：

`adj = {0: [1, 2], 1: [0, 3, 4], 2: [0, 5], 3: [1], 4: [1], 5: [2]}`

读法跟上一课一样：0 号点认识 1 和 2，1 号点认识 0、3、4，依此类推。**每个点后面那串邻居的先后，就是本喵待会儿先钻哪条路的顺序**——这一点很要命，先记住。

从 0 出发，本喵的走法是这样的：

| 第几爪 | 现在在哪 | 它认识谁 | 下一爪 | 为什么 |
|---|---|---|---|---|
| 1 | 0 | 1、2 | 去 1 | 邻居按挂着的那串顺序看，1 排在前面 |
| 2 | 1 | 0、3、4 | 去 3 | 0 已经来过，跳过；3 没去过，钻 |
| 3 | 3 | 1 | 退回 1 | 唯一的邻居是来路，前面没路了——撞墙 |
| 4 | 1 | 0、3、4 | 去 4 | 3 那条岔路走完了，回来试下一串 |
| 5 | 4 | 1 | 退回 1 | 又是死胡同，退 |
| 6 | 1 | 0、3、4 | 退回 0 | 1 的邻居全试过，这条大路走到头了 |
| 7 | 0 | 1、2 | 去 2 | 0 还有一个没去过的邻居 |
| 8 | 2 | 0、5 | 去 5 | 0 是来路，5 没去过 |
| 9 | 5 | 2 | 退回 2 | 又撞墙 |
| 10 | 2 | 0、5 | 退回 0 | 2 也走完了 |
| 11 | 0 | 1、2 | 收工 | 0 的邻居全试过，整张网走完 |

把「第一次踏上某个点」的先后抄下来，就是：

**0 → 1 → 3 → 4 → 2 → 5**

为什么第 3 步到了 3 不接着去别处？因为 3 只认识 1，而 1 就是本喵刚进来的那扇门——**能走的都走过了，这就叫「走不动」**。走不动怎么办？退回到上一个还有岔路没试的点，换一条接着钻。这个「退回来」的动作有个正式名字，叫**回溯**。

注意「退回来」不是认输。3 号点这条岔路已经探明白了：从 3 出发到不了任何新地方。本喵把结论揣兜里，退回 1，再去试 4——**每退一次，都是因为那条路已经被榨干了**。这就是深度优先的脾气：不撞南墙不回头，撞了南墙才回头。

再体会一下名字里的「深度」：本喵不是把 0 的邻居 1、2 挨个看一眼就完事，而是抓住 1 就一路钻到 3，钻不动了才回来。**沿着一条路能走多深，就走多深**。

## 不盖戳，会在原地绕到天荒地老

上面那张表能走通，靠的是一个不起眼的小动作：**每到一个点，先在它脑门上盖一个「本喵来过」的戳**。

这个戳不是装饰。把图换成两个点 0 和 1，中间连一条边，再从 0 出发——要是不盖戳，会发生什么？

| 谁在看 | 看到谁 | 判断 | 结果 |
|---|---|---|---|
| 0 | 1 | 1 没盖戳 | 去 1 |
| 1 | 0 | 0 也没盖戳 | 回 0 |
| 0 | 1 | 1 还是没盖戳 | 又去 1 |
| 1 | 0 | 0 还是没盖戳 | 又回 0 |

看出来了吗？两个点你推我、我推你，**永远在 0 和 1 之间打乒乓**，DFS 一辈子退不出来。图里只要有一个圈，不盖戳就会绕着圈无限转。

所以规矩得定死：**一进门就盖戳，不是出门才盖**。进门那一刻就把「来过」写死，第二次再被人指到这儿，一看脑门上有戳，扭头就走。要是等出门再盖，圈里的点永远等不到「出门」那一刻，戳一辈子盖不上，照样绕个没完。

盖戳还有第二个好处：**同一个点可能有好几条路都能到，但本喵只在第一次到它的时候记账**。比如本喵从 0 经 1 到了某个点，后来从 2 又摸到它门口，一看有戳，就不再记第二遍——这样输出里每个点只出现一次，不重不漏。

> **本喵提醒**：这个戳的意思是「**来过了，别再安排我走第二遍**」，不是「这条路已经走完了」。两者的区别在判环那一节还会冒出来，先记着。

## 两种写法：自己咬尾巴，和一摞碗

DFS 有两副面孔，骨子里是同一招。

**第一副：自己咬尾巴。** 写一招 `dfs(u)`，它干三件事：

1. 给 `u` 盖戳，把它记进本子；
2. 挨个翻 `u` 的邻居；
3. 碰到没盖戳的邻居 `v`，就**原样再喊一次 `dfs(v)`**。

这在课本上叫递归（自己咬尾巴）：一招里面又喊了自己一次。妙的地方在于，喊完自己这一层不会立刻结束——它会停在原地，等下面那一层回来。**「停在原地」的现场，由调用栈替你保存**：我在哪个点、下一个该看哪个邻居，一层一层摞着，回来的时候照着现场接着干。

**第二副：一摞叠起来的猫粮碗（堆栈）。** 如果不许咬尾巴，那就自己动手摆一摞碗：

- 把起点写在第一只碗上，放上桌；
- 每次从**最上面**拿一只碗，看上面的点；
- 这个点盖过戳，就把碗扔了，拿下一只；
- 没盖过戳，就盖戳、记账，再把它没盖戳的邻居一只只放上去。

最后放上去的碗最先被拿走——这叫**后进先出**。巧了，咬尾巴的写法里，调用栈也是后进先出：**最新钻进去的那一层，最先退回来**。所以两副面孔其实是一回事，一副是系统替你摞碗，一副是你自己摞碗。

不过手动摞碗有个坑，得当场说清：**邻居压进去的顺序，和拿出来的顺序是反的**。0 的邻居是 1、2，你要是先压 1 再压 2，那 2 就躺在最上面，下一只拿到的就是 2，走出来的顺序变成 0、2、……，跟咬尾巴那版对不上。想一模一样，就得**倒着压**：先压 2，再压 1，这样 1 在顶上，先被拿出来。

还有个细节：咬尾巴是「进门就盖戳」，手动这摞碗常常是「拿起来才盖戳」。所以同一个点可能被压进去好几次，等真拿起来一看，脑门上早有戳了，直接扔掉就行——结果不会错，只是白摞了几只碗。

## 先序：先记账，再钻洞

本喵走出来的 0 1 3 4 2 5，在课本里有个名字，叫**先序**。

意思很直白：**到一个点，先把它记进本子，再去看它的邻居**。先记自己，后钻邻居——「先」字说的就是记账在钻洞之前。

这个顺序很重要。要是反过来，等邻居全钻完、准备离开这个点的时候才记账，那记下来的就是另一套顺序（叫后序），起点 0 会被挤到最后。同一趟路，记账的时机不同，抄下来的单子就不同。面试官说「DFS 序」，默认问的是先序——**第一次踏上某个点的先后**。

对照本喵那张表看：0 是第一爪踏上的，1 是第二爪，3 是第三爪，4 是第四爪，2 是第七爪，5 是第八爪。单子上的名次跟「第几爪踏上」完全对得上。

## 连通块：一张网里可能有好几窝

到这儿，本喵一直假设从起点出发能摸到所有点。可现实里的网常常是好几窝：这一窝猫互相认识，那一窝跟谁都不来往。

比如给刚才那张图再添两个点：6 只认识 7，7 只认识 6，跟 0 到 5 一点边都不连。从 0 出发走一遍，本喵能到的只有 **{0, 1, 2, 3, 4, 5}**——6 和 7 根本不在这一窝里，DFS 连它们的门都摸不着。

**一次 DFS 能走到的所有点，就叫一个连通块**（也叫连通分量）。一张图可以只有一个连通块，也可以有好几窝。

那怎么把所有窝都数出来？外面再套一层：**每个点都轮流当一次起点**。从 0 号开始问：「盖过戳没？」没盖过，说明发现新的一窝，窝数加一，从它起一次 DFS，把这一窝全盖上戳；盖过的点直接跳过，因为它所在的那一窝早数过了。

```python
adj = {0: [1, 2], 1: [0, 3, 4], 2: [0, 5], 3: [1], 4: [1], 5: [2], 6: [7], 7: [6]}
visited = [False] * 8

def dfs(u):
    visited[u] = True
    for v in adj[u]:
        if not visited[v]:
            dfs(v)

count = 0
for s in range(8):
    if not visited[s]:
        count += 1
        dfs(s)
print(count)
```

```text
2
```

第一窝是 {0, 1, 2, 3, 4, 5}，第二窝是 {6, 7}，所以答案是 **2**。这个「外面套一层」的架子很常用：数窝、判断两点是否在同一窝、把整张网分堆，都是它。

## 判环：记住是从哪扇门进来的

盖戳能防原地打转，可有时候面试官不问「怎么走」，问的是「**这张网里有没有圈**」。无向图判环，DFS 顺手就能干，只要多记一样东西：**我是从哪个点来的**。

做法是给 DFS 多带一个「来路」：

- 从 `u` 走到没去过的 `v` 时，把 `u` 当作 `v` 的来路递下去；
- 在 `v` 看邻居时，如果某个邻居**盖过戳，而且不是来路**，那就说明——除了刚才那扇门，还有另一条路也能到这个邻居，圈就成了。

拿一个三角形走一遍：0 连 1，1 连 2，2 连 0。

| 现在在 | 从哪来 | 看到谁 | 判断 |
|---|---|---|---|
| 0 | 无 | 1 | 1 没盖戳，去 1，来路记 0 |
| 1 | 0 | 2 | 2 没盖戳，去 2，来路记 1 |
| 2 | 1 | 0 | 0 盖过戳，而且 0 **不是**来路 1——有环！ |

为什么这就算环？因为本喵从 0 出发，沿着 0→1→2 走到了 2，现在又发现 2 和 0 之间有一条边——**从 0 到 2 有两条不同的路**：一条是 0→1→2，一条是直接 0→2。两条路首尾一接，就是一个圈。

那为什么非得排除「来路」？因为无向图的每条边都是双向的：本喵从 0 走到 1，在 1 眼里 0 当然也是邻居，而且盖过戳。要是看到盖过戳的就喊有环，那一棵最普通的树 0—1 都会被判成有环。**来路是「刚进来的那扇门」，不是另一条绕回来的路，得放行**。

> **本喵提醒**：这招「认来路」是给无向图用的。有向图的边只有一个方向，判法不一样，以后碰到再说；这一课先把无向图这一招攥稳。

## 花多少力气：O(V+E)

最后算算账。设点的个数是 **V**，边的条数是 **E**。

- 每个点最多进一次 DFS——因为一进门就盖戳，第二次就被拦在门外了。这是 O(V)。
- 每条边被看几次？无向图里一条边连着两个点，从这头看一次、从那头看一次，一共两次。所有边加起来就是 2E，也就是 O(E)。

两笔账一加，**时间复杂度是 O(V+E)**。注意不是 O(V×E)——本喵不是每个点都把全图的边重扫一遍，每个点只翻自己那串邻居，所有邻居串起来的总长度正好是 2E。

空间呢？盖戳表要给每个点留一个位置，是 O(V)；咬尾巴的写法还要压调用栈，最坏情况是一条长长的链，一层套一层压到 V 层，也是 O(V)。**所以空间是 O(V)**。

还有一个必须说清的边界：**DFS 不保证最短路**。

举个最小的反例：0 和 4 之间直接有一条边，同时 0 还连着 1、1 连着 2、2 连着 3、3 连着 4。0 后面挂的邻居顺序是先 1 后 4。DFS 从 0 一头扎进 1，顺着 1→2→3→4 摸到 4，记下的路是 4 条边；可 0→4 明明一条边就到。等 DFS 退回 0 再看到 4，4 早盖过戳了，那条近路连记都不会记。

所以记住：**DFS 记的是「按邻居顺序第一次摸到它的那条路」，不是「最少几步的那条路」**。要走遍、要数窝、要判环，找 DFS；要问「最少几步」，得换一招——这也是下一课要干的事。

## 落到代码上

把前面那套规矩写成程序。图还是课文开头那张，邻居顺序一个不改：

```python
adj = {
    0: [1, 2],
    1: [0, 3, 4],
    2: [0, 5],
    3: [1],
    4: [1],
    5: [2],
}

visited = [False] * 6
order = []

def dfs(u):
    visited[u] = True
    order.append(u)
    for v in adj[u]:
        if not visited[v]:
            dfs(v)

dfs(0)
print(" ".join(map(str, order)))
```

```text
0 1 3 4 2 5
```

对着代码看三处：

- `visited[u] = True` 就是盖戳，**进门第一件事**，抢在所有邻居之前；
- `order.append(u)` 就是记账，因为它紧跟在盖戳后面，所以记下来的是先序；
- `for v in adj[u]` 按挂着的那串顺序翻邻居，`if not visited[v]` 是门口的门卫——有戳的拦下，没戳的才放进去再喊一次 `dfs(v)`。

本喵在 3 号点那一层：邻居只有 1，`visited[1]` 是 True，门卫拦下，`for` 翻完，这一层自然结束，控制权交回 1 号点那一层。**「退回来」不需要写任何一句专门的代码，这一层跑完就自动回去了**——这就是咬尾巴写法省心的地方。

## 三位翻译官喵，同一张图

同一张图、同一个起点、同一个邻居顺序，三位翻译官喵各写一遍。注意三份的输出必须一个字不差。

```compare
cpp::
#include <iostream>
#include <vector>

std::vector<std::vector<int>> adj = {{1, 2}, {0, 3, 4}, {0, 5}, {1}, {1}, {2}};
std::vector<bool> visited(6, false);
std::vector<int> order;

void dfs(int u) {
    visited[u] = true;
    order.push_back(u);
    for (int v : adj[u]) {
        if (!visited[v]) {
            dfs(v);
        }
    }
}

int main() {
    dfs(0);
    for (size_t i = 0; i < order.size(); ++i) {
        if (i > 0) std::cout << " ";
        std::cout << order[i];
    }
    std::cout << std::endl;
    return 0;
}

java::
```

三份的骨架一模一样：**盖戳 → 记账 → 顺着邻居串一路喊自己 → 这一层结束自动退回**。C++ 用 `vector` 装邻居和单子，Java 用 `int[][]` 和 `ArrayList`，Python 用字典和 `list`——换的是装东西的容器，换不掉的是那条「一条路走到黑」的规矩。

## 小心喵

::: warn 小心喵
三个坑，都是本喵自己踩过的：

- **盖戳别等到出门**：进门就盖。等出门再盖，碰到圈就永远出不了门，戳也永远盖不上，程序会一直转下去。
- **手动摞碗要倒着压邻居**：想复刻咬尾巴那版的顺序，就得把邻居串反过来压；照着原顺序压，弹出来正好反个个儿。
- **别拿 DFS 求最短路**：它只保证走遍、不保证走近。问「最少几步」，得请下一课那位出场。
:::
