## 钩子：表里装不下的答案

上一课，本喵把「把算过的记下来」练成了看家本领——动态规划先算好每一种规模，把结果一格一格填进表里，表填满了，答案就躺在最后一格。那一招专治「只要一个数」的题：最少几步、最多能拿多少、有几种走法，一格一个数，干净利落。

可这回，面试官大肥鱼把小鱼干往桌上一拍，推过来一张空白的棋盘纸：

> 「别给我一个数。把所有方案都摆出来，摆给我看。」

本喵低头一看：n × n 的棋盘，要放 n 个皇后，横、竖、斜都不能互相攻击。表呢？表里一格只能装一个「最优值」，装不下第一种摆法、第二种摆法、第三种摆法……这道题要的是**一整串方案**，不是一个数。

那就没别的路：**一条路一条路地试**。先在最上面一行放一只，再在第二行放一只；放得下去就继续，放不下去就退回来换一个位置。试完这一支，退回来，换下一支。

这一退一进，就是今天的主角——**回溯**。它还有个搭档叫**剪枝**：走到半路就看出此路不通，提前回头，不把整根树枝都长完。

## 先摆三只猫：一条路一条路地试

棋盘先放一放，本喵拿三只猫热热爪子。橘猫、狸花猫、三花猫，三只猫坐三个座位，一个座位一只，问：一共有几种坐法？

三只猫分别记作 橘、狸、三。最笨也最稳的办法，就是按座位一个一个安排：

- 第 1 个座位坐橘猫，剩下狸、三。
  - 第 2 个座位坐狸花猫，第 3 个座位只能坐三花猫 → 得到「橘、狸、三」。
  - 退回第 2 个座位，改坐三花猫，第 3 个座位只能坐狸花猫 → 得到「橘、三、狸」。
  - 第 2 个座位没别的猫了，退回第 1 个座位。
- 第 1 个座位改坐狸花猫，剩下橘、三。
  - 第 2 个座位坐橘猫 → 第 3 个座位三花猫 →「狸、橘、三」。
  - 第 2 个座位坐三花猫 → 第 3 个座位橘猫 →「狸、三、橘」。
- 第 1 个座位改坐三花猫，剩下橘、狸。
  - 得到「三、橘、狸」和「三、狸、橘」。

一共 6 种。数一数：3 × 2 × 1 = 6。

注意本喵刚才做的每一个动作，都能归到三件事里：

1. **做选择**：把一只猫按到座位上，同时在「这只猫已经坐下了」的本子上记一笔。
2. **往下试**：带着这本记满的账，去安排下一个座位；安排完了，方案就完整了。
3. **撤销选择**：把猫从座位上抱起来，把本子上那一笔擦掉，让这只猫重新变成「还没坐」——然后才能换下一只。

这三件事有个固定的节奏：**选中 → 探索 → 撤销**。少任何一步，整台机器就转不动。尤其是第三步，初学者最容易漏：猫抱起来了，本子上的名字忘了擦，下一轮就会以为这只猫还坐着。

## 决策树：每个岔路口都是一次选择

把刚才那张「安排座位」的清单画成树，长这样：

```text
第 1 个座位：      橘           狸           三
                  /  \         /  \         /  \
第 2 个座位：    狸    三     橘    三     橘    狸
                  |     |     |     |     |     |
第 3 个座位：     三    狸    三    橘    狸    橘
```

读法很直白：**从树根往下走一层，就是做了一个选择**。第 1 层选第 1 个座位坐谁，第 2 层选第 2 个座位坐谁，第 3 层选第 3 个座位坐谁。

- 树根到叶子的每一条路，都是一个**完整方案**。这棵树有 6 片叶子，就是 6 种坐法。
- 走到一半的分叉点，是一个**还没做完的决定**：比如「第 1 个座位坐了橘猫」，后面还有 2 个座位没定。
- 叶子就是**没有下一步可选**的节点：座位排满了，方案成立，记账。

这棵树叫**决策树**。它不是题目发下来的，是你在做的过程中一层一层长出来的——每做一个选择，就往下多长一层。这一点很关键，等会儿跟深度优先搜索对照时还要回来看它。

猫数一多，这棵树就疯长。4 只猫是 4 × 3 × 2 × 1 = 24 片叶子；5 只猫 120 片；10 只猫 3,628,800 片。**每多一只猫，叶子就多乘一个数**。这就是为什么「把所有方案列出来」这件事，天生就比「算一个最优值」费爪子。

## 选中、探索、撤销：三步必须成对

把三只猫的流程写成骨架，大概是这个形状（先看骨架，真代码在后面）：

```text
在本子上记下这个选择
往下走一层，继续安排
从下一层回来，把本子上这一笔擦掉
```

有个特别容易写错的地方：**撤销要写在「往下走」回来之后**，而且要和「做选择」严格成对。

假设本喵漏了撤销这一步，会发生什么？走第一条路「橘、狸、三」的时候，本子上记了橘、狸、三，三只猫都打了勾。走到叶子，退回来，本子没擦；再退一层，本子还是没擦。等回到第 1 个座位想换狸花猫时，本子上写着「橘已坐、狸已坐、三已坐」——三只猫全都「已坐」，一个都换不了。六个方案，最后只会数出**一个**。

看，撤销不是「打扫卫生」这种可有可无的收尾，它是**让下一个分支能重新使用同一个位置**的开关。不擦本子，第二个分支从一开始就被自己的历史堵死了。

还有两个细节，都是本喵踩过的坑：

- **撤销的顺序和选择的顺序相反**。最后记下的那笔先擦，最先记下的那笔最后擦——像一摞叠起来的猫粮碗，最后放上去的最先拿下来。放在棋盘上就是：这一层加了「列」「r+c」「r-c」三笔，退回时要把这三笔一起擦干净，一笔都不能剩。
- **加了几笔就擦几笔，别擦错本子**。N 皇后有三个本子，加的时候是三个一起加，擦的时候也得三个一起擦；只擦两个，剩下的那一笔就会在后面的分支里冒充「有人占着」，把真答案挡在门外。

只要这三步成对，整棵树就能被**恰好走一遍**：每个分叉点试遍所有选择，每条路走到叶子，叶子数就是方案数，一个不多一个不少。

## 剪枝：走到一半就知道不行

现在把猫换成皇后，约束一上来，事情就有意思了。

假设 4 × 4 的棋盘，第 0 行第 0 列放了一只皇后，第 1 行第 1 列又放了一只。你盯着棋盘看一眼就知道：这两只在同一斜线上，已经互相攻击了。**后面第 2、3 行无论怎么放，这个局面都救不回来**。

那还往下试吗？当然不。直接在第 1 行这一支上回头，换第 1 行的下一个位置。这个动作就叫**剪枝**：**走到一半就知道不可能，提前回头，不再往下长。**

剪枝的账很好算：

- **不改变答案**。被剪掉的整棵子树里，本来就不存在任何一个合法方案——剪掉的是「废枝」，不是「好果子」。所以剩下的叶子，还是原来那些合法方案，一个不少。
- **只减少尝试**。原来要把废枝上的每个节点都走一遍，现在到岔路口看一眼就回头，省下的是实打实的步数。

但剪枝有个前提：**你用来判断「不可能」的理由必须站得住**。N 皇后里「同一列」「同一条斜线」是硬冲突——只要撞上，这辈子都不可能解开，这种理由可以放心剪。要是你拿一个粗略的估计去剪，比如「这一行大概没位置了」却没算准，那就可能把还藏着答案的枝剪掉，答案就少了。**剪枝剪错，比不剪还糟。**

还有一条必须说清楚的红线：**剪枝再厉害，也改变不了最坏情况下的规模**。它只是让实际走的节点变少，搜索树在最坏情况下该有多大还是多大。N 皇后的搜索规模上界仍然是阶乘级（下面会算给你看），不会因为加了剪枝就变成多项式。谁要跟你说「剪枝一下就从阶乘变多项式了」，那是在吹牛喵。

## N 皇后：一行只放一个

正式上棋盘。n × n 的棋盘，放 n 个皇后，要求任意两个不在同一行、同一列、同一条斜线上。

第一个关键观察，能把题目砍掉一大半：**一共 n 行、n 个皇后，每行最多放一个——那每行就正好放一个。** 既然每行必须有一个，决策的顺序就定死了：**第 0 行放哪一列？第 1 行放哪一列？……第 n-1 行放哪一列？** 一行一层，正好 n 层。

于是决策树变成：第 r 层从 0 到 n-1 里挑一个列号 c，挑完去第 r+1 层。到第 n 层（所有行都放完），就是一个完整方案。

接下来是「怎么查冲突」。要是每次都把整个棋盘扫一遍，太磨爪子。本喵用三个集合当账本：

- **用过的列**：记下所有已经放了皇后的列号 c。
- **一条斜线用 r + c 记**：从右上往左下这条斜线上的格子，r + c 是同一个数。
- **另一条斜线用 r - c 记**：从左上往右下这条斜线上的格子，r - c 是同一个数。

拿 4 × 4 的棋盘验一下，看得最清楚：

| 格子 (r, c) | r + c | r - c |
|---|---|---|
| (0, 0) | 0 | 0 |
| (1, 1) | 2 | 0 |
| (2, 2) | 4 | 0 |
| (3, 3) | 6 | 0 |
| (0, 3) | 3 | -3 |
| (1, 2) | 3 | -1 |
| (2, 1) | 3 | 1 |
| (3, 0) | 3 | 3 |

看第一组：(0,0)、(1,1)、(2,2)、(3,3) 的 r - c 全是 0——它们确实在同一条「左上到右下」的斜线上。看第二组：(0,3)、(1,2)、(2,1)、(3,0) 的 r + c 全是 3——它们也确实在同一条「右上到左下」的斜线上。

所以查冲突只要三句话：**这一列 c 在「用过的列」里吗？r + c 在第一条斜线的本子里吗？r - c 在第二条斜线的本子里吗？** 三个都没有，就能放。

放的时候，三个本子各记一笔；往下走一层；回来时，三个本子各擦一笔。就是上一节说的「选中、探索、撤销」，一笔不多一笔不少。

拿 n = 6 实跑一遍，一共 4 个解。四个解的列号（按行写下来）是：

| 解 | 第 0 行 | 第 1 行 | 第 2 行 | 第 3 行 | 第 4 行 | 第 5 行 |
|---|---|---|---|---|---|---|
| 1 | 1 | 3 | 5 | 0 | 2 | 4 |
| 2 | 2 | 5 | 1 | 4 | 0 | 3 |
| 3 | 3 | 0 | 4 | 1 | 5 | 2 |
| 4 | 4 | 2 | 0 | 5 | 3 | 1 |

n = 8 的棋盘上有 92 个解。这个数不是本喵编的，是程序真跑出来的——等会儿你也能自己跑。

## 落到代码上：三个集合，六行皇后

```python
def solve(n):
    cols = set()
    d1 = set()
    d2 = set()
    count = 0

    def place(r):
        nonlocal count
        if r == n:
            count += 1
            return
        for c in range(n):
            if c in cols or (r + c) in d1 or (r - c) in d2:
                continue
            cols.add(c)
            d1.add(r + c)
            d2.add(r - c)
            place(r + 1)
            d2.remove(r - c)
            d1.remove(r + c)
            cols.remove(c)

    place(0)
    return count

print(solve(6))
```

```text
4
```

逐段看：

- `place(r)` 的意思是「**第 r 行往下的皇后，交给这一手去安排**」。`r == n` 就是所有行都安排完了，数到一个解，`count` 加一，回头。
- 进了这一圈以后，`c` 从 0 试到 n-1：先查三个本子，撞了就用 `continue` 跳过——这就是**剪枝**，撞列的、撞斜线的位置连试都不用试。
- 查通了，三笔一起记（`add`），喊自己安排下一行（`place(r + 1)`）——这就是**探索**。
- 从下一行回来，三笔一起擦（`remove`），这一圈接着试下一个 `c`——这就是**撤销**。

`nonlocal count` 那一句，是因为里面这一手要改外面那一手的记账数，得先打个招呼说「我改的是外头那个 count，不是我自己新开一个」。这一点跟本课的主线无关，照抄就行。

两处最值得盯的地方：

1. **`place(r + 1)` 夹在两组 `add` 和 `remove` 中间**。往下走之前加，回来之后擦——顺序反了，等于没加就往下走，或者擦了个不存在的记号，程序当场翻脸（集合里删没有的东西会报错）。
2. **三个本子的 `remove` 和 `add` 一一对应**。你在 `add` 那三行里加了什么，就在 `remove` 那三行里原样减什么；`r + c` 和 `r - c` 别写串。

## 回溯和深度优先搜索，是同一只手

往前翻几课，本喵讲过「一条路走到黑」——深度优先搜索。那会儿是在一张现成的图上走：点已经画好了，边已经连好了，你从起点出发，能往深处走就往深处走，走不动了退回来换一条边。

今天的回溯，走路的姿势一模一样：**也是一条路走到黑，走到头再退回来**。区别在脚下这张图是谁造的：

- **图上的深度优先搜索**：点在题目里，边在题目里，你只是去拜访它们。走过的点打个「来过」的记号，这个记号一般**不用擦**——每个点访问一次就够了。
- **回溯**：树是你在做选择时**自己长出来的**。第 1 层是你做的第 1 个选择，第 2 层是第 2 个选择……叶子才是完整方案。这里的记号记的是「这个位置被当前这条路占着」，退回时必须擦掉，因为下一条路还要用同一个位置。

可以这么说：**回溯就是在决策树上做深度优先搜索**。骨架是同一副——往下钻、撞墙、回头；只是回溯多背了一个账本，而且账本必须一进一出地对平。

想明白这一层，你就不会把两件事搞混：图搜索里「来过」的记号擦掉反而可能绕圈绕不完；回溯里状态不擦，答案一定少。同样是记号，一个管「来过没有」，一个管「现在占着没有」，用途不同，规矩就不同。

## 它为什么慢：阶乘级的搜索树

来算一算这棵树到底多大。

N 皇后里，第 0 行有 n 个列可以选；到了第 1 行，同一列不能再用，最多剩 n - 1 个；第 2 行最多 n - 2 个……一直到最后一行最多 1 个。所以叶子最多是：

> n × (n - 1) × (n - 2) × … × 1 = n!

n = 6 时是 720，n = 8 时是 40,320，n = 10 时是 3,628,800。这还只是**叶子**的数量，加上中间的分叉点，整棵树的节点更多。所以课本上写 N 皇后的搜索规模是 **O(n!)**——阶乘级，涨得比指数还凶。

这也解释了为什么 n = 8 只有 92 个解，搜索树却按 40,320 片叶子来长——剪枝把大量「撞列、撞斜线」的枝提前砍掉，实际走的节点远少于满树，但**最坏情况下的规模还是 n!**。剪枝省的是实际步数，不是把上界改小。

顺手把今天见到的几种规模记在脑子里：

| 要枚举的东西 | 叶子数量 | n = 10 时 |
|---|---|---|
| n 只猫坐 n 个座位（全排列） | n! | 3,628,800 |
| n 个元素里每个「选或不选」（子集） | 2^n | 1,024 |
| n × n 棋盘放 n 个皇后 | 最多 n! | 最多 3,628,800 |

对照上一课的动态规划：那边是「**用一张表换时间**」，把重叠的小问题算一次记下来，规模通常是多项式；这边是「**用时间换全部答案**」，要把每种组合真的走一遍，规模天然是指数或阶乘。**要不要用回溯，先问自己：题目要的是一个最优值，还是所有方案？** 要一个值，先想想表能不能填；要所有方案，那就老老实实长树。

```compare
cpp::
#include <iostream>
#include <set>

int n = 6;
std::set<int> cols, d1, d2;
int count = 0;

void place(int r) {
    if (r == n) {
        count++;
        return;
    }
    for (int c = 0; c < n; c++) {
        if (cols.count(c) || d1.count(r + c) || d2.count(r - c)) continue;
        cols.insert(c);
        d1.insert(r + c);
        d2.insert(r - c);
        place(r + 1);
        d2.erase(r - c);
        d1.erase(r + c);
        cols.erase(c);
    }
}

int main() {
    place(0);
    std::cout << count << std::endl;
    return 0;
}
```

三段是同一副骨架：**到叶子就记账，查三本账再放，放完往下走，回来擦三笔**。C++ 用 `std::set` 的 `count` 查在不在、`insert`/`erase` 记账；Java 用 `HashSet` 的 `contains`/`add`/`remove`；Python 用 `set` 的 `in`/`add`/`remove`。名字不一样，节奏一模一样。

::: tip 猫咪提示
1. **三步成对**：选中 → 探索 → 撤销。尤其是撤销，别让上一支的账留在本子上，否则下一条分支一开局就被自己的历史堵死。
2. **剪枝先问依据**：只有「确定不可能」的冲突才敢剪；拿不准的估计乱剪，会把真答案一起剪掉。
3. **两个数记牢**：n = 6 有 4 个解，n = 8 有 92 个解。面试官问起来，别把这两个数记混喵。
:::

::: warn 小心喵
- **`place(r + 1)` 前后要夹着 `add` 和 `remove`**：往下走之前加，回来之后擦；顺序反了，等于没做选择就往下走，或者去删一个不存在的记号。
- **三个集合一起加、一起减**：少减一个，后面的分支就会被幽灵占位挡住，答案变少还不报错。
- **剪枝不是降复杂度**：它只减少实际尝试，最坏情况仍然是阶乘级，别在考卷上写「剪枝把最坏复杂度降到多项式」喵。
:::
