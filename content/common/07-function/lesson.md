## 钩子：开饭三步，本喵抄了一百遍

本喵每天给猫们开饭，动作是固定的三步：**端碗、放鱼干、喊一声开饭**。

三只猫还好，抄三遍就是了。可鱼塘边住着一百只猫喵 —— 本喵就得把这三步**一模一样地抄一百遍**。抄到爪子酸还是小事，真正要命的是：哪天规矩改了（比如「端碗之前先洗一遍」），本喵得回头把一百处全改一遍，漏掉一处，那只猫就得用脏碗吃饭。

前面本喵学会了**绕鱼干跑圈**：同一套动作重复很多遍，交给电脑自己去跑。可跑圈解决的是「**一样的事做很多遍**」，它解决不了另一件事 —— **这三步本身，本喵还是每次都得重写一遍。**

前辈猫于是又传下来一招：把这一整套动作**打包起来、起个名字**。以后要开饭，喊一声名字就行啦。

打包好的这一套本领，本喵叫它**技能**，也叫**招式**。术语表里给它的原名是**函数（技能 / 招式）**—— 今天的主角喵。

## 招式：打包好的一套本领

先把这件事说透。**招式就是一个打包好的动作包**：本喵把「做这件事要走的每一步」装进包里，给包起个名字；往后需要它的时候喊名字，包里的动作就按顺序走一遍。

招式替本喵省下三样东西喵：

1. **少写字**：一套动作只写一遍，喊多少次都不用重抄。
2. **改得动**：规矩变了只改包里那一处，所有喊它的地方一起跟着变。
3. **名字就是说明**：喊 `feed_cat`（喂猫）一看就知道是开饭，比一堆散装代码好读多啦。

不过有一件事必须掰清楚，这是零基础最容易含混的地方：**「教」和「喊」是两件事。**

- **教**（定义）：把这一招的动作记下来。教的时候，动作**一次都不会执行**。
- **喊**（调用）：真正让这一招动起来。

顺序不能反 —— **先教、后喊**。没教过的招，喊了电脑也不认识喵。

## 教一招：`def`

教一招的写法长这样（本喵先用 Python 给你看，等下四门语言并排对照）：

```python
def greet():
    print("开饭啦喵")
```

一行一行拆开看，每一样都有讲究喵：

- **`def`** —— 「本喵要教一招」的起手式。它是英文 define（定义）的前三个字母，写完它，电脑就知道接下来跟着的是一个招式。
- **`greet`** —— 招式名，本喵自己起。名字随便起，但得起得让人一看就懂（`greet` 是「打招呼」的意思）。
- **`( )`** —— 投喂口。这一招要投喂什么，写在里面；现在先空着，表示「这一招什么都不用喂」。
- **`:`** —— 冒号，意思是「**接下来缩进里的那几行，全是这一招的动作**」。
- **缩进的那一行** —— 招式真正做的动作。缩进一旦取消，招式就结束了；后面顶格写的代码，跟这一招再没关系。

现在留意一个现象：**把上面这段敲进去、跑一下，屏幕上一个字都不会出现。**

不是本喵敲错了 —— 这段只是「教」，还没「喊」。招式教完就安安静静待在那儿，**不会自己动**。

## 喊一招：`greet()`

教完就该喊了。喊的写法简单到不像话：**招式名 + 一对小括号**。

```python
def greet():
    print("开饭啦喵")

greet()
greet()
```

```text
开饭啦喵
开饭啦喵
```

本喵喊了两声，屏幕上就出现两行喵。喊几下就发生几次 —— 这正是「打包」的意义：`print("开饭啦喵")` 本喵**只写了一遍**，却让它发生了两次。

顺带看一眼招式下面那个**空行**：它是给眼睛用的，让「教」和「喊」两段分得清清楚楚。电脑不在乎空行，但读你代码的猫在乎。

::: warn 小心喵
两个坑，零基础几乎人人踩过：

1. **只教不喊**：写完 `def greet():` 那一段就跑，屏幕上什么都没有 —— 因为招式不会自己动，得另写一行 `greet()` 去喊它。
2. **喊的时候忘了小括号**：写成 `greet` 只是「提了一句这个名字」，写成 `greet()` 才是「真的喊它干活」。少了这对小括号，什么都不会发生，而且**它不会报错**——这是最气猫的一种错。
:::

## 投喂：把小鱼干喂进招式里

上面这一招，每次喊出来的都一样。可本喵想让它对不同的猫打招呼喵 —— 那就在**投喂口**里开个口子：

```python
def greet(name):
    print(name, "开饭啦喵")

greet("橘猫")
greet("大肥鱼")
```

```text
橘猫 开饭啦喵
大肥鱼 开饭啦喵
```

- `def greet(name):` 括号里的 `name`，是**投喂口上的一个占位**。它其实就是招式内部的一只小仓库（跟前面学过的「小鱼干仓库」是一个东西）：招式每被喊一次，喂进来的东西就装进它里面一次。
- 喊的时候，`greet("橘猫")` 括号里的 `"橘猫"` 就是**投喂进来的那条小鱼干** —— 术语表里叫它**参数（投喂的小鱼干）**。
- 所以第一声喊，`name` 里装着 `"橘猫"`；第二声喊，`name` 里换成了 `"大肥鱼"`。**同一招，喂什么就说什么。**

`name` 这个名字也是本喵自己起的，叫 `who`、叫 `x` 都行 —— 它只是招式**内部**的叫法，出了这一招就没人认得了。

还可以开两个口子，投喂两条小鱼干：

```python
def add(a, b):
    print(a + b)

add(3, 4)
```

```text
7
```

`def add(a, b):` 开了两个口子，喊的时候 `add(3, 4)` 就按**顺序对号入座**：第一个喂进去的 `3` 装进 `a`，第二个 `4` 装进 `b`。顺序要是反了，装进去的东西也就反了，这一条往后要留神喵。

顺带记一句：`print` 会把逗号隔开的几样东西，**中间垫上一个空格**再印出来。所以 `print(name, "开饭啦喵")` 印出来是 `橘猫 开饭啦喵`，中间那个空格是 `print` 垫的，不是本喵打的喵。

## 叼回来：`return` 与战利品

到目前为止，本喵的招式都是「在招式里念一句，念完就完事」。可有些招式的本事不在念，而在**算出一个结果交给本喵**。

比如本喵要一招「把一个数变成两倍」：

```python
def double(n):
    return n * 2

result = double(5)
print(result)
```

```text
10
```

逐行看喵：

- `return n * 2` —— `return` 是「**把战利品叼回来**」的动作。电脑先算出 `n * 2` 是 10，然后 `return` 把这个 10 **叼出招式**，交回给喊它的那一行。
- `result = double(5)` —— 喊完以后，`double(5)` 这个位置**已经变成 10 了**，10 被装进 `result` 这只仓库。所以 `print(result)` 印出来是 10。

术语表里管「叼回来的东西」叫**返回值（叼回来的战利品）**。记住这个画面：`return` 就是猫把猎物叼回你脚边放下 —— **放下的那件东西，就是这一招的全部成果**。

### 没有 `return` 会怎样？

这是本课最值得多看两眼的地方。要是把 `return` 换成 `print`：

```python
def double(n):
    print(n * 2)

result = double(5)
print(result)
```

```text
10
None
```

第一行还是 10，因为它真的念了一遍。可第二行冒出来一个 `None` —— 这是 Python 在说「**本喵什么也没叼回来**」。

差别在这儿喵：

- **`print` 是「在招式里念给屏幕听」**：念完就没了，招式**外面**什么也接不到。
- **`return` 是「把东西叼出招式」**：交给外面那一行，外面接得到。

`result = double(5)` 是想接东西的，可这一招从头到尾没叼回任何东西，`result` 里就只能是 `None`。

一句话：**想让招式外面拿到东西，用 `return`；只想让屏幕看到，用 `print`。** 两个都想要，就两句都写。

### `return` 还有个脾气

`return` 一执行，**这一招就当场结束**，后面就算还排着动作也不做了：

```python
def check(n):
    if n > 0:
        return "还有鱼干喵"
    return "吃完啦喵"

print(check(3))
print(check(0))
```

```text
还有鱼干喵
吃完啦喵
```

先认一眼 `if`：它是前面学过的**看鱼干眼色行事** —— 眼色答「真」就走缩进里那条路，答「假」就跳过它。

`check(3)` 进来，眼色 `n > 0` 答「真」，走缩进里那条路，叼回 `"还有鱼干喵"` —— **这一招到此结束**，下面那句 `return "吃完啦喵"` 根本没轮到。而 `check(0)` 进来，眼色答「假」，跳过缩进里那句，才轮到下面那句。

这脾气用好了很省事：**把最特殊的情况用 `return` 提前送走，剩下的路就不用再操心了。**

## 四只翻译官喵一起教一招

同一个任务：教一招 `twice`（投喂一个数，把它的两倍叼回来），再喊它一次打印出来。四门语言写出来是这样：

```compare
c::
#include <stdio.h>

int twice(int n) {
    return n * 2;
}

int main() {
    printf("%d\n", twice(5));
    return 0;
}

cpp::
#include <iostream>

int twice(int n) {
    return n * 2;
}

int main() {
    std::cout << twice(5) << std::endl;
    return 0;
}

java::
public class Main {
    static int twice(int n) {
        return n * 2;
    }

    public static void main(String[] args) {
        System.out.println(twice(5));
    }
}

python::
def twice(n):
    return n * 2

print(twice(5))
```

```text
10
```

四段骨架一模一样：**起手式 + 名字 + 投喂口 → 招式身体 → 喊它**。差别在这几处喵：

- **C / C++ / Java 要先说清「投喂什么、叼回什么」**：`int twice(int n)` 里，括号**前**的 `int` 是「叼回来的东西是个整数」，括号**里**的 `int n` 是「投喂进来的东西是个整数」。Python 这些统统不写，直接 `def twice(n):` 就完事。
- **招式身体怎么圈起来**：C / C++ / Java 用一对大括号 `{ }`，而且招式末尾那一行要写分号；Python 靠**缩进**圈，末尾不写分号。
- **Java 的招式多挂了一块 `static` 的牌子**：因为喊它的 `main` 自己也挂着这块牌子，**挂了同一块牌子的猫才能互相喊**。这张牌子的来龙去脉，等讲到「猫猫图纸」那一课再细说，今天先照抄就行喵。
- **喊它的地方**：C 是 `printf("%d\n", twice(5))`，C++ 是 `std::cout << twice(5)`，Java 是 `System.out.println(twice(5))`，Python 是 `print(twice(5))`。四只翻译官喵喊招式的方式各不一样，可骨子里都是同一句话 —— **名字 + 一对小括号，括号里放投喂的东西**。

::: tip 猫咪提示
本课五句口诀，记牢就够用啦：

1. **招式 = 打包好的一套本领**：写一遍，喊很多遍；改只改一处。
2. **`def` 是教，喊名字是喊**：先教后喊；只教不喊，什么都不会发生。
3. **投喂口在括号里**：`def greet(name):` 的 `name` 是占位，喊的时候把小鱼干喂进去。
4. **`return` 把战利品叼回来**：想让外面接到东西就写 `return`，只想让屏幕看到就写 `print`。
5. **`return` 一执行，这一招就当场结束**。
:::

::: warn 小心喵
再念一遍最容易踩的两个坑：**只教不喊**（跑完一个字都没有），和**喊的时候忘了小括号**（写成 `greet` 而不是 `greet()`）。

还有一个**很安静**的坑：`return` 忘了写，招式不报错、照样跑完，只是**外面永远接不到东西**（Python 会给你一个 `None`）。招式跑得通 ≠ 招式有用喵！
:::
