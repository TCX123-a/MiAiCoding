## 钩子：一个文件挺帅，三百个文件手就废了

大肥鱼这些天挺得意：稿子就一个文件，手敲一行命令，回车——成了。帅。

直到前天，它把一个大项目摊在桌上：三百来个文件——检查的、当家的、干活的、看门的，一大堆。手敲那行命令，长得一眼望不到头；哪个先造哪个后造，得像背菜谱一样背下来；改了一个文件，还得记得把牵连的几块重新来一遍——忘一步，屏幕上就是红字。

大肥鱼：这要是全靠手敲，本喵的手就废了喵。

## 手敲的麻烦，列个清单

把「手敲」的麻烦摊开数一数，一共这么几条：

1. **命令越长越吓人**——文件一多，一行命令能从这头排到那头，少敲一个符号就翻脸；
2. **顺序不能乱**——谁先谁后是死规矩，错了不行；
3. **相互牵连记不住**——某块材料变了，牵连哪几块跟着重造？全靠脑子记，迟早漏；
4. **改一处、重造全部**——老实人干脆每次从头造一遍：五分钟的活变半小时，还容易忘；
5. **每人敲得不一样**——你敲你的、本喵敲本喵的，结局还可能不同。

一句话收束：**「怎么造」这套知识如果只长在人的脑子里，就是迟早要还的债。**

## 把「怎么造」写成一份文件

工程师的还债方式一句话说穿：**请一位管家，把「怎么造」写成一份文件。**

那份文件上写着三件事：**有哪些材料、按什么规矩和顺序造、造出什么**。管家读了这份文件，替你一遍遍把活干完——你只管改稿子，其余交给它。这份文件，本课就叫**工单**。

四门语言，各有各家的工单叫法（只点名，写法各专课细讲）：

| 场合 | 工单文件 | 管家（点名） |
|---|---|---|
| C / C++ 项目 | `Makefile` | `mingw32-make`（本机的名字）；更上一层，`CMakeLists.txt` 指挥 `cmake` |
| Java 大项目 | `pom.xml` | Maven（住在大宅子 IDEA 里） |
| Java 大项目（另一种写法） | `build.gradle` | Gradle（同样常在 IDEA 里） |
| Python 的来料 | `requirements.txt` | `pip` 照单取件（后面细讲） |

先记清一处分寸：**管家不是翻译官喵。** 翻译官把一册稿子翻成电脑的话；管家管的是「三百册稿子按什么顺序、请谁翻、翻到哪一版」。一个是手艺人，一个是管流水线的。

## 只重造变了的那块：增量的直觉

管家最舒服的一手叫**增量**：它拿每块材料的「改动时间」跟成品的「造好时间」比一比——没动的，跳过；动过的，只重造牵连到的那几块。三百个文件的项目，改一行，可能只重造一块。

直觉记住一句就够：**不是每按一次都从零造起，只重造「变了、且被牵连」的那部分。** 具体怎么比、怎么判，各专课会带你拆开看。

## 材料从哪来：依赖这件事

项目一大，材料就不再只有自己写的——一半左右是别人造好的现成件，行话叫**依赖**：你造的东西，欠着它们。

它们从哪来、拿了放哪？也归管家们管：

- Python 线：《给蟒蛇一间自己的屋——venv、pip 与包管理》——`pip` 按 `requirements.txt` 取件，连「放哪」都讲究；
- Java 线：《管家与采买——Maven 与 Gradle 入门》——拿着 `pom.xml`、`build.gradle` 去仓库采买；
- C / C++ 线：《流水线的图纸——Makefile 与 CMake 入门》——把整条流水线画在图纸上。

取件有一句安全话：**清单上写得越死越好**——「要哪一版」也写上。取来的版本不对，造出来的东西就变味。

## 验收一下：四位翻译官喵，同一句话

管家和翻译官喵是接力：翻译官翻稿子，管家排流水线。先看四位翻译官喵各自亮相——语言会换，屏幕上的回话不会变：

```compare
c::
#include <stdio.h>

int main(void) {
    printf("文件多了，管家就得请一个喵\n");
    return 0;
}

cpp::
#include <iostream>
using namespace std;

int main() {
    cout << "文件多了，管家就得请一个喵" << endl;
    return 0;
}

java::
class Main {
    public static void main(String[] args) {
        System.out.println("文件多了，管家就得请一个喵");
    }
}

python::
print("文件多了，管家就得请一个喵")
```

```text
文件多了，管家就得请一个喵
```

四位翻译官喵统一得很。管家的世界也一样：不管哪门语言的工单，目的都是把「怎么造」从人脑里搬进文件——**机器照着文件造，谁经手都一样**。

::: tip 猫咪提示
这一课的三句话，收好喵：

1. **管家治的麻烦**：文件多、顺序乱、牵连记不住、改一处重造全部；
2. **工单三件事**：有哪些材料、按什么顺序造、造出什么；
3. **两个直觉**：增量（只重造「变了、且被牵连」的那块）、依赖（别人的现成件，清单上写死版本）。
:::

::: warn 小心喵
两个坑，本喵标出来：

- **「管家 = 翻译官」是错觉**：翻译官翻一册稿子，管家排一条流水线——把两件事混作一团，排错人还会觉得自己没错；
- **别凭感觉自创工单**：工单是给机器读的，各家格式有各家的死规矩；语言线专课会教你正经写法，先别自由发挥喵。
:::

## 一句话对照表

| 本喵写下的 | 它的意思 |
|---|---|
| 手敲的麻烦 | 命令长、顺序乱、牵连记不住、改一处重造全部、人各敲各的 |
| 工单 | 把「怎么造」写成文件：材料、顺序、成品 |
| `Makefile` / `CMakeLists.txt` | C 系的两层工单（`mingw32-make` / `cmake` 读） |
| `pom.xml` / `build.gradle` | Java 大项目的两种工单（Maven / Gradle 读） |
| `requirements.txt` | Python 的取件清单（`pip` 读） |
| 增量 | 只重造「变了、且被牵连」的那几块 |
| 依赖 | 从别人仓库取来的现成件——写清要哪一版 |
| 管家不是翻译官 | 翻译官翻稿子；管家管「何时、按什么顺序、请谁翻」 |

## 这条线收尾

工具链这趟逛到头了，本喵把整个路线再点名一遍：

- 第 35 课**认了路**——五站路、四位翻译官喵、还有练习场的自带沙箱；
- 第 36 课**学会了被找到**——小纸条与路牌清单，外加「找不到」的三真凶；
- 第 37 课**拆了那只运行按钮**——拼命令、找翻译官、跑；两个旋钮：工具路径与工作目录；
- 第 38 课**请了管家**——把「怎么造」写成工单，增量与依赖。

往后你在任何语言线里撞见「翻译、运行、构建、取件」的场面，都可以拿出这条线对一对：**写、翻、跑、看、修——谁站哪一站，谁管哪一段，清清楚楚。** 这就是工具链这门素养的底子。

## 小任务

1. **动脑**：凭直觉答——三百个文件里改了一个，管家至少要重造几块？（提示：增量那节）
2. **动脑**：用第 35 课的五站路点名——管家把哪几站连成了流水线，替你省下了哪只手？
3. **动手**：把你写过的小程序想象成三个文件：先手敲「哪行先、哪行后」，再改其中一处，数数要重敲几行——回头对一对麻烦清单，看看你中了哪几条。
