## 钩子：十只猫的早饭，本喵忙成了陀螺

早上六点，本喵要给十只猫挨个儿添小鱼干。第一只：走过去，抓一把，放进碗里；第二只：走过去，抓一把，放进碗里……忙到第七只，本喵的爪子已经开始发抖了喵。

抖归抖，本喵忽然想明白一件事：**本喵干活的时候，心里其实一直在念一张清单** —— 先拎起桶，走到第一只猫的碗边，抓一把放进去，再走到下一只。这张清单要是念得清清楚楚，闭着眼睛干都不会漏掉谁；念不清楚，忙到天黑也会漏掉一只。

这张「怎么把一件事办成」的清单，就是今天的主角：**算法**。

## 什么是算法：三步曲

本喵把算法叫「解决一个问题的三步曲」，说穿了就三句话喵：

1. **看清楚要什么** —— 本喵到底要什么结果？「十只碗里，每只都有一条小鱼干」。
2. **把过程拆成一步步** —— 每一步都小到不用动脑子：「走到碗边」「抓一把」「放进碗里」。
3. **照着顺序走一遍** —— 一步接一步，不跳步、不回头。

所以**算法不是代码**。它是「这件事到底该怎么办」的想法。想法可以先在本喵脑子里跑一遍，跑通了，再让翻译官喵把它翻成某门语言写下来。同一张清单，写成 C、C++、Java、Python 都行 —— **清单本身还是同一张**，只是四位翻译官喵念出来的腔调不一样喵。

## 三种基本身法

天底下千变万化的算法，拆到最细，都逃不出三种身法：**一步接一步**、**看鱼干眼色行事**、**绕鱼干跑圈**。

### 一、一步接一步（顺序）

最老实的一种：从上往下，一步接一步。本喵煮猫饭就是这样喵：

```python
bowl = "橘猫的碗"
fish = 3
print(bowl, "里放了", fish, "条小鱼干")
```

```text
橘猫的碗 里放了 3 条小鱼干
```

三行代码，三件事，顺序**不能换**：先把碗的名字放进仓库，念的时候才喊得出来它；`print` 里逗号的位置会各垫一个空格，所以中间那几个空格是 `print` 自己加的，不是本喵手滑喵。要是把最后那句提到最前面，翻译官喵就会当场犯难 —— 因为那时候 `bowl` 这只仓库还没建起来。

### 二、看鱼干眼色行事（选择）

有时候一件事得**先看一眼情况**再决定做不做：碗里的小鱼干够不够吃喵？

```python
fish = 2
if fish >= 3:
    print("够吃啦喵")
else:
    print("再添一点喵")
```

```text
再添一点喵
```

`if` 后面跟一句「条件」，读作「**如果**……」。条件成立，走它下面那条路；不成立，走 `else`（否则）那条路。术语表里给这种「看一眼再决定」的身法起的原名是**条件判断（看鱼干眼色行事）**：条件满足了才动手，不满足就换一条路走喵。

### 三、绕鱼干跑圈（重复）

十只猫的碗，本喵总不能把喂猫那句话抄十遍 —— 那就让同一套动作**绕着鱼干跑圈**，一遍又一遍：

```python
fish = [3, 1, 4]
total = 0
for n in fish:
    total = total + n
print(total)
```

```text
8
```

`for n in fish:` 读作「**把这一排碗里的每一碗，挨个儿交给 `n`**」：第一圈 `n` 是 3，第二圈是 1，第三圈是 4。`total = total + n` 每跑一圈，就把当前这一碗攒进 `total` 这只仓库里 —— 三圈跑完，`total` 是 8。

绕圈的好处写在脸上：**这套动作本喵只写了一遍，剩下的重复全交给电脑自己去跑。** 这一手在术语表里的原名是**循环（绕鱼干跑圈）**。往后本喵说「跑圈」，说的就是它喵。

## 生活里的三个小算法

算法一点也不神秘，本喵一天里能撞见好几个：

- **穿鞋**：先穿袜子、再穿鞋、最后站起来 —— 这是**一步接一步**。袜子穿在鞋外面？听着就好笑，谁都知道这一步的顺序换不得。
- **分小鱼干**：走到每只猫的碗边看一眼 —— 碗里还有就不动，空了就添一条。这里既有**看鱼干眼色行事**，也有**绕鱼干跑圈**（十只碗，挨个儿走一遍）。
- **找最大的一条**：一整排小鱼干里，哪一条最肥？本喵先拿起第一条当「目前最肥的」，再挨个儿比过去：比它肥的，就换成新的一条；比它瘦的，放过。整排走完，手里那条就是最肥的。

最后那个「找最大」值得写成代码看一遍喵：

```python
fish = [3, 1, 4, 1, 5]
biggest = fish[0]
for n in fish:
    if n > biggest:
        biggest = n
print(biggest)
```

```text
5
```

`fish[0]` 是第一碗 —— 编号从 0 起，这是本喵在「一排贴编号的猫粮碗」那一课讲过的规矩喵。`biggest` 先抱住第一碗当「目前最肥的」，然后绕着整排跑圈：**只有**当 `n` 比手里的还大（`n > biggest`）才换新的。三种身法全在这几行里：顺序、看鱼干眼色行事、绕鱼干跑圈，一样都不少。

::: tip 猫咪提示
拿到一件事，先别急着敲代码，照三步曲问自己三句话：

1. **本喵要的结果是什么？**
2. **分几步？每一步都清楚到不用动脑子吗？**
3. **哪一步要看情况？哪一步要重复？**

把这三句答完，代码几乎就自己长出来了喵。
:::

::: warn 小心喵
算法对了、代码写歪了，跑出来的不是你要的东西；反过来，代码写得再花哨，算法错了，跑得再顺也是白跑。**先在本喵脑子里把清单跑一遍，再动手敲代码** —— 这一条能替你省下一半的返工喵。

还有一个小地方别栽跟头：`for n in fish:` 是从**第一碗**开始跑的，可编号是从 0 起的。别把「第一圈」和「编号 0」对错了位喵。
:::

## 四位翻译官喵，同一张清单

同一个算法：一排三碗小鱼干，**挨个儿看一遍** —— 够 3 条就喊「够吃啦喵」，不够就喊「再添一点喵」。四位翻译官喵写出来长这样，看个眼熟就行喵：

```compare
c::
#include <stdio.h>

int main() {
    int fish[3] = {3, 1, 4};
    for (int i = 0; i < 3; i++) {
        if (fish[i] >= 3) {
            printf("第 %d 碗：够吃啦喵\n", i + 1);
        } else {
            printf("第 %d 碗：再添一点喵\n", i + 1);
        }
    }
    return 0;
}

cpp::
#include <iostream>

int main() {
    int fish[3] = {3, 1, 4};
    for (int i = 0; i < 3; i++) {
        if (fish[i] >= 3) {
            std::cout << "第 " << i + 1 << " 碗：够吃啦喵" << std::endl;
        } else {
            std::cout << "第 " << i + 1 << " 碗：再添一点喵" << std::endl;
        }
    }
    return 0;
}

java::
public class Main {
    public static void main(String[] args) {
        int[] fish = {3, 1, 4};
        for (int i = 0; i < 3; i++) {
            if (fish[i] >= 3) {
                System.out.println("第 " + (i + 1) + " 碗：够吃啦喵");
            } else {
                System.out.println("第 " + (i + 1) + " 碗：再添一点喵");
            }
        }
    }
}

python::
fish = [3, 1, 4]
for i in range(3):
    if fish[i] >= 3:
        print(f"第 {i + 1} 碗：够吃啦喵")
    else:
        print(f"第 {i + 1} 碗：再添一点喵")
```

```text
第 1 碗：够吃啦喵
第 2 碗：再添一点喵
第 3 碗：够吃啦喵
```

一眼就能看出门道喵：**三位翻译官喵的「数到第几碗」是靠自己加出来的**（C 和 C++ 写 `i + 1`，Java 写 `(i + 1)`），Python 干脆把算式塞进句子里；可四段跑出来的结果**一个字都不差**。

这就是三步曲最让人安心的地方：**想法是同一张清单，写法各有各的脾气**。往后本喵带你学某一门语言的时候，你会发现真正难的不是语法，而是「这件事到底该怎么一步步做」喵。

## 小任务

今天的小任务，不用碰键盘也能做一半喵：

1. 挑一件事写一张清单 —— 比如「本喵怎么给三只猫分小鱼干」。写的时候数一数：哪几步是**一步接一步**？哪一步在**看鱼干眼色行事**？哪一步在**绕鱼干跑圈**？
2. 再把课文里那段「找最大」的代码抄进练习场，跑一遍。然后把 `n > biggest` 改成 `n < biggest`，再跑一次 —— 猜猜它现在找的是什么喵？
3. 最后一问：如果把 `biggest = fish[0]` 改成 `biggest = 0`，那段代码还能找到 5 吗？（提示：想想 `fish` 里全是正数时会怎样。）
