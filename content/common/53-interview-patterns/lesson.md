## 第一面旗：两根猫爪从两头往中间走

先看一道最朴素的题：**一排数已经从小到大排好队，问里面有没有一对数，加起来正好等于目标值。**

比如 `[2, 7, 11, 15]`，目标 9。

最笨的办法是两只爪子各抓一个，把所有组合都试一遍——四个数要试六次；数一多，次数就按平方往上翻。可这排数**已经排好队**了，这个「排好队」就是旗子：两根猫爪，一根放最左边，一根放最右边，从两头往中间走。这一招的术语叫双指针（两根猫爪从两头走）。

| 左爪指着 | 右爪指着 | 加起来 | 比 9 大还是小 | 下一步 |
|---|---|---|---|---|
| 2 | 15 | 17 | 大了 | 右爪往左挪一格到 11 |
| 2 | 11 | 13 | 大了 | 右爪往左挪一格到 7 |
| 2 | 7 | 9 | 正好 | 收工，找到了 |

三步就完事。为什么敢这么走？看第一步：左爪指着最小的 2，右爪指着最大的 15，加起来 17 已经比 9 大了。**连最小的数配最大的数都嫌大，那 15 跟谁配都只会更大**——15 这一整列可能性可以整列划掉，右爪往左挪。反过来，要是加起来比目标小，那就说明左爪这个数配谁都嫌小，左爪往右挪。

每挪一步，划掉一整列（或一整行）可能性，两根猫爪最多各走完整排一次，所以整个过程只看 `n` 步，复杂度 O(n)。这比「两只爪子乱抓」的 O(n²) 少了一个数量级。

同样的两根猫爪，还能判**回文**：一根指头、一根指尾，字符一样就往中间收一格，不一样就说明不是回文。`abcba` 走两步都对称，收工；`abca` 第一步 a 对 a 一样，第二步 b 对 c 不一样，立刻判否。还有「排好队的一排数去重」：一根慢爪守着已经确认不重复的末尾，一根快爪往前扫，扫到新数就让慢爪往前挪一格、把新数按进去。**快慢两根爪，一个负责探路，一个负责记账。**

> **本喵提醒**：两根猫爪这一招，前提是那排数**已经排好队**。乱糟糟的一排直接走，「和太大就挪右爪」的推理立刻失效——右爪挪一格，新换上来的数可能更大，也可能更小。要是题目只问数值、不问原来的位置，可以先排好队再用这招；要是还要求输出原来的下标，排完队位置就乱了，得换别的路子。

## 第二面旗：一扇会伸缩的窗

再看第二类题：**一段连续的数、或者一段连续的字，问「最长/最短的、满足某个条件的那一段」。**

注意两个词：**连续**、**一段**。只要题面里出现「连续子数组（连续的一段）」「子串」「最长」「最短」这些字眼，脑子里就该亮起一扇窗。

窗户有两根框：左框 `left`、右框 `right`，框住的就是当前这一段。规矩只有两条：

1. **右框负责扩**：每轮先把右框往右挪一格，把新元素圈进来；
2. **窗口不满足条件时，左框负责缩**：左框往右挪，直到窗口重新合法。

拿本课的主角 `"abcabcbb"` 走一遍。要找的是「最长的不含重复字符的子串」。

| 右框走到 | 新字符 | 窗口里发生了什么 | 窗口内容 | 最长记录 |
|---|---|---|---|---|
| 0 | a | 第一次见 a | `a` | 1 |
| 1 | b | 第一次见 b | `ab` | 2 |
| 2 | c | 第一次见 c | `abc` | 3 |
| 3 | a | a 上一次在 0，还在窗口里 | `bca` | 3 |
| 4 | b | b 上一次在 1，还在窗口里 | `cab` | 3 |
| 5 | c | c 上一次在 2，还在窗口里 | `abc` | 3 |
| 6 | b | b 上一次在 4，还在窗口里 | `cb` | 3 |
| 7 | b | b 上一次在 6，还在窗口里 | `b` | 3 |

最后答案是 **3**，对应最早出现的 `abc`（后面还有 `bca`、`cab`，都一样长）。

关键是右框走到 3 的那一行：右框圈进第二个 a，窗口 `abca` 里 a 重复了。这时候左框不是「挪一格试试」，而是**直接跳到 a 上一次出现位置的下一位**——a 上一次在 0，左框就跳到 1，窗口立刻变成 `bca`，重复没了。右框走到 4、5 时也是同一个动作。

为什么可以直接跳？想让窗口继续以 3 号位的 a 结尾、又不出现两个 a，左框就必须越过 0 号位那个旧 a，也就是至少站到 1。站到 1 正好是「不重复」前提下窗口能拉到的最长——再往右挪只会更短。所以不是一格一格试，而是直接站到「上一次出现位置 + 1」。

可这里有个必须拿捏的细节：**上一次出现的位置，可能早就滑出窗口了。** 看 `"abba"`：

- 右框走到第 2 个 b 时，b 上一次在 1，左框跳到 2，窗口变成 `b`；
- 右框走到最后的 a 时，a 上一次在 0——可左框已经在 2 了，0 早就出窗了。

这时候如果无脑执行「左框 = 上一次位置 + 1 = 1」，左框会**倒退**回 1，窗口反而把 `bba` 圈了进来，里面明明有两个 b，算出来的长度却是 3——正确答案是 2（`ab` 或 `ba`），一下就错了。

正确的写法是取两者中靠右的那个：`left = max(left, 上一次出现位置 + 1)`。

翻译成人话：**只有当那个旧位置还在窗口里（`>= left`）时才跳；已经出窗了就别动。** 代码里通常写成 `if last[ch] >= left: left = last[ch] + 1`，和 `max` 是同一件事。

> **小心喵**：同一串 `"abba"` 还能踩另一个坑——「见到重复就只往右挪一格」。右框圈进第二个 b 时，左框只挪一格到 1，窗口 `bb` 里重复还在；再圈进最后的 a，旧 a 已出窗、左框没再动，窗口 `bba` 长度 3 就被记成了答案。正确答案还是 2。**要么跳到「上一次出现位置 + 1」，要么用圈圈反复缩到合法，别缩一半就记账。**

窗口这一招也不是万能的：它靠的是「右框越往右、窗口越难合法；左框越往右、窗口越容易合法」这条方向感。一排数里要是有正有负、要求和正好等于某个值，这种方向感就断了，窗户会漏风——那种题要请前缀和出场。

## 第三面旗：先把账本抄一遍

第三类题：**同一排数，反复问很多次「第 l 个到第 r 个加起来是多少」。**

老实做法是每次问都把区间里的数加一遍。问一次 O(n)，问 m 次 O(nm)；数一多、问得又勤，爪子就磨秃了。

前缀和的做法是：**先花 O(n) 把「从头加到第 i 个」的账本抄一遍，之后每次查区间只做一次减法，O(1)。**

定义：`pre[i]` 表示**前 i 个数**的和，`pre[0] = 0`。注意是「前 i 个」，所以账本比原排多一格，第 0 格是 0。

拿 `[3, 1, 4, 1, 5, 9, 2, 6]` 抄一遍：

| i | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
|---|---|---|---|---|---|---|---|---|---|
| pre[i] | 0 | 3 | 4 | 8 | 9 | 14 | 23 | 25 | 31 |

`pre[3] = 8`，意思是前三个数 3+1+4=8；`pre[8]=31` 就是整排的总和。

现在问：第 2 个到第 5 个（下标从 0 数，含两头）的和是多少？

直接加：4 + 1 + 5 + 9 = 19。
用账本：`pre[6] - pre[2] = 23 - 4 = 19`。对上了。

为什么是 `pre[r+1] - pre[l]`？因为 `pre[r+1]` 是「前 r+1 个数」，也就是从 0 到 r 全部；`pre[l]` 是「前 l 个数」，也就是 0 到 l-1 全部。两者一减，前面 0 到 l-1 的部分被抵消，剩下的正好是 l 到 r。**账本多抄一格（pre[0] 那格 0），就是为了让 l=0 的时候减法也能成立**——`pre[r+1] - pre[0]` 不用特判。

预处理 O(n)、每次查询 O(1)、额外占 O(n) 格。m 次查询总共 O(n + m)，比老实加的 O(nm) 快一大截。

> **本喵提醒**：公式是 `pre[r+1] - pre[l]`，不是 `pre[r] - pre[l]`。少加的那个 1，会把区间右端的 a[r] 漏掉——`pre[r]` 只记到 r-1。区间两头是「含」的，账本的第 i 格记的是「前 i 个」，这两个「i」差的就是那一格。写之前先把 l=0、r=n-1 代进去验一遍，两头都对，中间才不容易错。

## 套路地图：看题面，先认旗

把今天的旗和前面十一关的旗插在同一张地图上：

| 题面长这样 | 先想到的招 |
|---|---|
| 有序的一排里找一对数 / 判断回文 | 双指针（两根猫爪从两头走） |
| 连续子数组（连续的一段数）/ 子串，问最长或最短的合法段 | 滑动窗口 |
| 很多次问「区间和」 | 前缀和 |
| 无权图，问「最少走几步」 | BFS（一圈一圈往外扩） |
| 带权图，边权非负，问最短路 | Dijkstra |
| 只问「谁和谁连通」 | 并查集 |
| 要列出所有方案、所有排列组合 | 回溯 |
| 有重叠的子问题，求最值或方案数 | 动态规划 |
| 每次都要取当前最大/最小 | 堆 |

认旗的顺序也有讲究：**先看数据长什么样，再看问题问什么。**

- 数据「排好队」→ 先想二分、两根猫爪；乱序但元素少 → 先想暴力，再想能不能排好队。
- 问题问「连续的一段」→ 窗口或前缀和；问「任意挑几个」→ 多半是回溯或动规。
- 问「最少/最多」而不是「所有方案」→ 别上回溯，先想 BFS、贪心、动规。
- 问「所有方案」→ 别硬套动规，方案数可以动规，但要**列出每一种**就得回溯。

一张地图不可能把所有题都盖住，但能盖住面试里最常见的那一批。**先认旗，再动手**，比一上来就敲键盘省下的是整段整段的白工。

### 看数据范围，倒推该用多快的招

面试题常常在题面最后塞一句「1 ≤ n ≤ 10^5」。那不是凑字数，那是出题人递给你的梯子：**数据范围反着推，能用的复杂度就框死了。**

| n 的大小 | 大概能过的复杂度 | 常见招 |
|---|---|---|
| n ≤ 11 | O(n!) | 全排列回溯 |
| n ≤ 20 | O(2^n)、O(n·2^n) | 子集回溯、状压 |
| n ≤ 5000 | O(n²) | 双层跑圈、简单动规 |
| n ≤ 10^5 | O(n log n) 或 O(n) | 排好队 + 二分、两根猫爪、窗口、前缀和 |
| n 更大（10^7 起） | O(log n) 或 O(1) | 数学、二分答案、预处理 |

举个例子：n = 10^5 时，O(n²) 是 10^10 次操作，一秒钟根本跑不完；O(n) 只有 10^5 次，绰绰有余。反过来，n ≤ 20 时你写了个 O(2^n)，2^20 约一百万，完全可以；这时候硬要憋一个 O(n log n) 的巧解，反而可能想歪。

> **小心喵**：这张表是**经验尺子，不是法律**。同样的复杂度，C++ 和 Python 跑起来能差几十倍；操作是加法还是取余，也差很多；题目给的时限是一秒还是三秒，同样影响判断。它帮你排掉「明显不可能」的路，不替你拍板。真正稳的做法是：先估一个复杂度，再看它落在表里哪一档，心里有个数，然后动手验证。

### 面试的正确姿势：先问三句，再动爪子

大肥鱼把卷子推过来，本喵没有马上敲键盘，先问了三句：

1. **「这排数有多大？有没有序？有没有重复？」**——范围决定复杂度上限，有序决定两根猫爪能不能用，重复决定窗口和去重的细节。
2. **「能不能用额外的空间？」**——能用，前缀和、记号簿都方便；不能用，就得在原排上挪爪子（比如快慢两根爪去重）。
3. **「要的是数值、下标，还是所有方案？」**——要下标就不能随便排好队；要所有方案就得上回溯。

三句问完，套路基本就浮出来了。接下来才是：**先说出思路和复杂度，再写代码；写完主动报一遍复杂度，再拿边界例子过一遍**——空的一排、只有一个元素、全是一样的字符、有正有负、目标值不存在。面试官要的不是「你背过这道题」，而是「你遇到没见过的题，也知道先看什么」。

一上来就写代码，写到一半发现方向错了，改起来最费劲；先把题面读成「数据长什么样 + 问什么」，三十秒就能少走半小时的弯路。**面试考的是认路，不是跑得快。**

## 落到代码上：让窗口自己量出 3

把第二面旗落到代码上。找 `"abcabcbb"` 里最长的不含重复字符的子串长度：

```python
s = "abcabcbb"
last = {}
left = 0
best = 0
for right in range(len(s)):
    ch = s[right]
    if ch in last and last[ch] >= left:
        left = last[ch] + 1
    last[ch] = right
    best = max(best, right - left + 1)
print(best)
```

```text
3
```

逐句看：

- `last` 是一本「上次见面登记簿」：键是字符，值是它上一次出现的位置。
- 每轮先把右框挪到 `right`，取出字符 `ch`。
- `if ch in last and last[ch] >= left`：这个字符见过，**而且上次出现的位置还在当前窗口里**——那就把左框跳到 `last[ch] + 1`。如果上次位置已经出窗（`< left`），什么都不做，窗口不用缩。
- `last[ch] = right`：登记这一次的位置，覆盖旧的。
- `best = max(best, right - left + 1)`：窗口现在合法，量一下长度，更新最长记录。

跑完 `"abcabcbb"`，`best` 停在 3。整个过程中 `right` 只往右走 n 步，`left` 也只往右走，最多 n 步，所以是 O(n)；`last` 里最多存字符种类数个条目，额外空间 O(字符种类数)——对固定的字符集来说就是 O(1)。

## 三份程序，同一扇窗

同一套「右扩左缩 + 取靠右的跳点」，三位翻译官喵各写一遍：

```compare
cpp::
#include <iostream>
#include <string>
#include <vector>

int main() {
    std::string s = "abcabcbb";
    std::vector<int> last(128, -1);
    int left = 0;
    int best = 0;
    for (int right = 0; right < (int)s.size(); ++right) {
        if (last[s[right]] >= left) {
            left = last[s[right]] + 1;
        }
        last[s[right]] = right;
        if (right - left + 1 > best) {
            best = right - left + 1;
        }
    }
    std::cout << best << std::endl;
    return 0;
}

java::
public class Main {
    public static void main(String[] args) {
        String s = "abcabcbb";
        int[] last = new int[128];
        for (int i = 0; i < 128; i++) {
            last[i] = -1;
        }
        int left = 0;
        int best = 0;
        for (int right = 0; right < s.length(); right++) {
            char ch = s.charAt(right);
            if (last[ch] >= left) {
                left = last[ch] + 1;
            }
            last[ch] = right;
            best = Math.max(best, right - left + 1);
        }
        System.out.println(best);
    }
}

python::
s = "abcabcbb"
last = {}
left = 0
best = 0
for right in range(len(s)):
    ch = s[right]
    if ch in last and last[ch] >= left:
        left = last[ch] + 1
    last[ch] = right
    best = max(best, right - left + 1)
print(best)
```

三份程序的骨架一模一样：`last` 记上一次位置、右框每轮 +1、旧位置还在窗里才跳左框、每轮量一次长度。Python 用字典，C++ 和 Java 用一张按字符编号的表格，做的事情完全相同。**换一门语言，换的是写法；认旗、跳左框、量长度这三件事，一步都没变。**
