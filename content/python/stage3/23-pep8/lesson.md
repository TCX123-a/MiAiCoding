## 钩子：这代码写得太丑啦喵！

本喵把一段刚写完的小本子递出去，对面的猫看一眼就皱眉：「跑是能跑，可这代码写得太丑啦喵！」

丑 —— 就是它唯一的毛病。它没坏，结果也对。可丑本身就是大毛病：三个月后翻回来看的（很可能就是你自己）每读一行都得停下来重新猜。今天本喵把「丑」这件事拆开，一件件改顺眼：

**缩进、行长、名字、空格、空行、注释、import 的顺序** —— 七样都会有真凭实据；最后再请两台机器当值日生。等等，为什么叫「公约」？因为这不是本喵一个人拍脑袋定的 —— 它有个正式名字 **PEP 8**，是 Python 社区给「怎么写才顺眼」立的公约。

先看这段「能跑但真丑」的小本子：

```python
#统计鱼干
def count_fish(l, price):
  total=price*l
  return total


print("一共", count_fish(3, 7), "条")
```

```text
一共 21 条
```

结果没错吧？可你读的时候，眼睛是不是在好几个地方磕了一下：注释和井号挤在一起、`l` 和数字 1 分不清、缩进短了半截、等号两边空荡荡。今天就把这些磕绊一处一处铲平。

## 一、先把公约的来历说清楚

**PEP 8** 这个名字拆开看：PEP 是「Python 改进提案」的编号本子，8 就是第 8 号 —— 2001 年就写好了，是社区在代码长相上最老的那把尺子。它管的事一句话说清：**让大家写出来的代码长得像同一窝猫写的。**

其中排第一的规矩，不是哪个写法更好看，而是 —— **一致性**：

> 一座窝里，统一跟着同一套来，比各自挑「更好看」的写法更要紧。

道理不难想：代码被**读**的次数，远远多过被**写**的次数。读的人（包括未来的你）越少停下来猜，越省事。至于这一套具体是「四格缩进」还是「两格缩进」，反而不是最要命的 —— **要命的是同一窝里不一样。**

::: tip 猫咪提示
考试卷子上，这些「名字」各有各的正式叫法：函数（招式）、类（图纸）、变量（仓库）。本喵这一课照旧用招式、图纸、仓库来念它们 —— 名字该怎么写才顺眼，是同一个问题喵。
:::

## 二、缩进和行长：最容易被眼睛抓住的两样

**缩进。** 公约的数目是：**每往里一层，缩进 4 个空格**。开头那段小本子缩进只用了 2 格 —— 翻译官喵照跑不误，但读的人一眼就看出「这不是这一窝的风格」。空格和 Tab 也别混着来，混了在你机器上没事，换台机器就可能对着同一段本子皱不同的眉头。

**行长。** 一行别太长。公约划的线是 **79 格**；超了就把长句子拆开 —— 拆的办法本喵给它叫「折进括号里」：把一长串塞进一对括号，里面的部分想换行就换行。看这只因为太长被点名的本子：

```python
票根 = ("本喵的小鱼干清单", 12345)

print("这张票根上记着本喵今年攒下来的全部小鱼干：名字叫", 票根[0], "，一条一条数过去，数得本喵眼睛都快花了，加起来一共是", 票根[1], "条")
```

```text
这张票根上记着本喵今年攒下来的全部小鱼干：名字叫 本喵的小鱼干清单 ，一条一条数过去，数得本喵眼睛都快花了，加起来一共是 12345 条
```

跑起来一点毛病没有，可把它存成 `长行本子.py`，递给体检机（第三节先剧透一下这个名字）扫一眼 —— 敲一句 `flake8 长行本子.py`，单子当场就来：

```text
长行本子.py:3:80: E501 line too long (82 > 79 characters)
```

那句的意思是：**第 3 行到第 80 格就破了线，这一行有 82 格长。** 那台摆架机 black 默认把线放宽到 **88 格** —— 记两个数：**79 是公约的线，88 是 black 的默认线**。

## 三、名字怎么写：这一课最值钱的表

| 什么东西 | 名字怎么起 | 例子 |
|---|---|---|
| 招式（函数） | 全小写，词与词用下划线连 | `count_fish` |
| 图纸（类） | 每个词开头大写，不留下划线 | `CatBasket` |
| 常量 | 全大写，词与词用下划线连 | `MAX_SPEED` |
| 仓库（变量） | 全小写，词与词用下划线连 | `price`、`total` |

另有一条**避雷**：单独一个字母的名字里，`l`、`O`、`I` 千万别用 —— 它们跟数字 `1`、`0` 长得太像。开头那段里单独一个 `l`，体检机一眼就把它挑出来点名（E741，「容易混淆的名字」）。

那大写开头的招式名（比如 `CountFish`）呢？有意思的地方来了 —— 本喵把名字换成大写开头试试（顺手留着那个 `l`）：

```python
def CountFish(l, price):
    total = price * l
    return total


print(CountFish(3, 7))
```

```text
21
```

两台机器的反应**不一样**：体检机 flake8 只逮住 `l`（还是那记 E741），**名字的大写它压根不管**；本喵另请了台更严格的体检机 pylint，它当场点名：

> `Function name "CountFish" doesn't conform to snake_case naming style`

翻译一下：**招式名「CountFish」不合「小写加下划线」的写法。** 所以记两件事：① 名字的写法，flake8 默认只管一部分，别以为体检机全绿名字就都对；② 图纸（类）才用大写开头，招式（函数）要用全小写下划线 —— 这正是第三节这张表里最常被用错的一行。

## 四、空格和空行：给眼睛留的呼吸缝

**空格**分两处说：

- **符号两边**：等号、加号、乘号这些两边留一个空格。开头那段里的 `total=price*l` 挤成一团，体检机记的就是一记 E225（「运算符旁边缺空格」）。写成 `total = price * l`，一眼就舒服了；
- **逗号后面**：跟一个空格。`count_fish(l, price)` 里 `l,` 后面那个缝，就是给眼睛留的。

**空行**也一样，是给读的人分段用的：**顶层的东西之间空两行；同一张图纸里头，招式与招式之间空一行。** 空少了体检机也记账 —— 看这只「跟招式只空了一行就接着写」的本子：

```python
def 打招呼():
    print("喵")

打招呼()
```

```text
喵
```

把它存成 `本子己.py`，递给体检机（`flake8 本子己.py`），它记下这一笔：

```text
本子己.py:4:1: E305 expected 2 blank lines after class or function definition, found 1
```

末那句的意思是：**招式那段（定义）后面，本喵只空了一行，它要两行。**

## 五、注释：# 后面留一个空格

注释是写给读的人看的，那就让它也长得顺眼：

- **整行注释**：`#` 后面先跟**一个空格**，再写字 —— `# 统计鱼干`。开头那段写成 `#统计鱼干`（挤在一起），体检机记一记 E265；
- **行内注释**：代码后面想要短注释，`#` 前面**空两格**，再写 `# 注释`。比如 `总 = 0  # 从零开始攒`。

一条顺手的建议：注释写「**为什么**」，别只重复「**做了什么**」。`总 = 0  # 给总归零` 是废话；写着「为什么这里要从 0 开始」才有价值。

## 六、import 的顺序：一行一个，分三组

`import` 的规矩三条喵：

1. **一行请一个**；
2. 分**三组**：先蟒蛇自带的、再别人寄来的箱子、最后本窝自己的本子，**组与组之间空一行**；
3. 组内按名字的**字母顺序**排。

第 1 条最常被踩。看这只图省事挤在一行的：

```python
import sys, os

print(os.name, sys.version_info[0])
```

```text
nt 3
```

存成 `本子丙.py` 递给体检机，敲 `flake8 本子丙.py`，它照例记一笔：

```text
本子丙.py:1:11: E401 multiple imports on one line
```

E401 就是「一行挤了好几个 import」。拆开、顺好，立刻干净：

```python
import os
import sys


print(os.name, sys.version_info[0])
```

```text
nt 3
```

一样的结果，不一样的脸面 —— 第三行往下还照着「空两行」的规矩站着呢。

## 七、请两台机器当值日生：flake8 和 black

人眼会漏，公约又细，所以社区造了两台机器。先请它们进屋（站在哪个窝里喊，就装进哪间屋 —— 第 21 课刚学的规矩）：

```text
python -m pip install flake8 black
```

**第一台：flake8，体检机。** 它把公约里**能自动查**的条目逐条对照，查到就记下来，报格式是「文件:行:列」加一句人话。用法就是把本子递给它：

```text
flake8 统计.py
```

把本课开头那段丑本子递过去，单子长这样：

```text
统计.py:1:1: E265 block comment should start with '# '
统计.py:2:16: E741 ambiguous variable name 'l'
统计.py:3:3: E111 indentation is not a multiple of 4
统计.py:3:8: E225 missing whitespace around operator
统计.py:4:3: E111 indentation is not a multiple of 4
```

**五记红叉，我们来一格一格过**（从头往下扫，跟体检机一个姿势）：


**第二台：black，摆架机。** flake8 只**指出来**，不帮你改；black 反过来 —— 它把「怎么摆」（缩进、空格、空行、折行）一次摆到位，原地覆盖。先问一句要不要摆，再真动手：

```text
black --check 统计.py      ← 先问：这本子要重摆吗
black 统计.py              ← 真动手，摆完原地覆盖
```

`--check` 的答复是 `1 file would be reformatted.`（有一本要重摆）；真摆完的答复是 `1 file reformatted.`（摆好一本）。摆完的它长这样：

```python
# 统计鱼干
def count_fish(l, price):
    total = price * l
    return total


print("一共", count_fish(3, 7), "条")
```

```text
一共 21 条
```

对照开头那版，black 干的三件事一眼可见：**注释补了空格、缩进补到 4 格、等号两边补了空格**。但是 —— 那个 `l` 它**一个字母都没动**。这不是摆架机偷懒，是**分工**：它只管**怎么摆**，不管**叫什么名字**；名字的丑不丑，归第三节那张表和更严格的 pylint 管。

::: warn 小心喵
两张脸要分清楚，别指望错人：

- **flake8 不会替你改** —— 它是体检机，只管出单子；
- **black 不会替你改名** —— 它是摆架机，只管排版；`countFish`、`CountFish`、`l` 这些它都当没看见。

**先 black 摆一遍、再 flake8 扫一遍**，是收工前最顺手的一对上妆镜。
:::

最后，看一眼**从头到尾合公约**的样板（顺便给「常量」这个词一个真身）：

```python
MAX_SPEED = 120


def clamp_speed(speed):
    if speed < 0:
        return 0
    if speed > MAX_SPEED:
        return MAX_SPEED
    return speed


print(clamp_speed(150), clamp_speed(-5), clamp_speed(80))
```

```text
120 0 80
```

常量全大写一次定好、招式名全小写下划线、缩进四格、空行两格、空格齐整 —— 递给 flake8，单子是**空的**（零红叉）。

## 小任务

1. 翻一段自己以前写的小本子，先 `flake8` 扫一遍，再 `black` 摆一遍 —— 摆完两张单子对着看：哪些是 flake8 管过的、哪些是 black 管过的？还有没有**两台都管不着**的（提示：看看名字）？
2. 从自己起过的名字里挑三个，对着第三节那张表核对一遍：招式、常量、仓库各挑一个。
3. 把开头那段「统计鱼干」丑本子**亲手**改到合公约（先别喊 black），改完用 flake8 验收：单子空了没有？再想想 —— 自己改和让 black 摆，各有什么好？
4. 想一个问题：为什么公约把「一致性」排在「哪个写法更好看」前面？（提示：想想读你代码的猫，和三个月后的你自己。）

PEP 8 是个老木匠，2001 年就把尺子递到大家手里：缩进 4 格、长度 79、名字有规矩、空行有空行的排法。机器（flake8、black）管得了**长相**，管不了**叫法**；而最要紧的那一条「一致性」，两样都管不了 —— 它得靠一窝猫自觉守着喵。**让机器管机器该管的，让公约管机器管不了的，剩下的，一起守。** 🐾
