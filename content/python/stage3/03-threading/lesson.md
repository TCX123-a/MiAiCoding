## 钩子：本喵一个人烤到半夜

本喵的「小鱼干铺子」今天接了**三条烤鱼干**的单子。炉子有三口，可本喵只有一双手：烤完第 0 条，擦擦汗，再烤第 1 条……三条烤完，天都黑了喵。

要是能叫上**三只猫**呢？一只守一口炉子，三条鱼干就一起被烤上了。

**线程（好几只猫一起干活）**说的就是这个：让程序里同时跑起好几条小流水线，每条各干各的活儿。

本喵先悄悄说一句：这几只猫其实是**轮流**上场的，电脑换得太快，看起来才像同时。为什么只能轮流、怎么才能真正各干各的，是下一课的主角喵——今天先把「怎么叫猫、怎么等猫」学到手。

先看看**没有猫**的时候长什么样：

```python
def 烤鱼干(编号):
    print(f"第 {编号} 号鱼干烤好啦喵")

for i in range(3):
    烤鱼干(i)
```

```text
第 0 号鱼干烤好啦喵
第 1 号鱼干烤好啦喵
第 2 号鱼干烤好啦喵
```

`def` 写出来的这块本领，本喵叫它**招式（函数）**；喊一次名字就施展一次。上面这个绕鱼干跑圈（循环）里，本喵喊了三声，三条鱼干就**一条接一条**地烤：第 0 条印完了，才轮到第 1 条。

一条接一条，就是今天要改掉的事喵。

## 一、叫一只猫来干活：`Thread`

Python 里叫猫的招式住在 `threading` 这个小仓库里，先把它请进来：

```python
import threading

结果 = [""]

def 烤鱼干():
    结果[0] = "第 0 号鱼干"

t = threading.Thread(target=烤鱼干)
t.start()
t.join()

print(结果[0] + " 烤好啦喵")
```

```text
第 0 号鱼干 烤好啦喵
```

四句新话，一句一句拆开看：

- **`threading.Thread(target=烤鱼干)`** —— 叫一只猫来，交给它一张单子。`target=` 后面写的是**招式本身的名字**，也就是「要它施展哪一招」。
- **`t.start()`** —— 喊开工。这一声喊完，本喵**不等它**，扭头就走，猫自己在那儿烤。
- **`t.join()`** —— 本喵在这儿**等它收工**。等到了，才往下走。
- **`结果[0]`** —— 猫干出来的东西没有直接印出来，而是**放进了本喵给它留的格子里**。等它收工，本喵自己去格子里拿。

最后这一条是本课的第一条规矩，请先记住：

> **猫只管把结果放进格子；要印、要算、要显示，都等 `join()` 之后再由本喵统一来做。**

为什么？因为猫干活快慢**不由你定**，谁先谁后是电脑自己安排的。要是每只猫一干完就抢着 `print`，那印出来的行**每次跑都可能换个顺序**——你就再也说不清「这一行到底该不该在这儿」了喵。

### `target=` 后面为什么不加括号

这是零基础学员最容易摔的一跤，本喵单独拎出来讲。

`烤鱼干` 和 `烤鱼干()` 在 Python 眼里是**两样东西**：

- 写 `烤鱼干`（不带括号）= 把**这张招式的单子**递过去，说「照这个干」。猫接过去，等自己开工时才施展。
- 写 `烤鱼干()`（带括号）= **当场**就把这招施展一遍！括号是「现在就动手」的意思。本喵自己动手烤完了，`Thread` 接到的其实是招式干完活**叼回来的战利品**，而不是招式本身。

这里最坑的一点必须说清：**带括号的写法通常不会报错**。本课的 `烤鱼干` 是只干活、不叼东西的招式，它叼回来的是「什么都没有」（Python 管这个叫 `None`）。`Thread(target=None)` 照样开工，只是**没招式可施展**，空跑一趟就回来了。程序一声不吭，鱼干也确实烤好了——因为那是**本喵自己**烤的，猫从头到尾一点活都没干喵。

判据一句话：**括号一出现，招式当场就施展了**。所以 `target=` 后面要写名字，不带括号喵。

## 二、三只猫一起上

一只猫叫来了，那三只呢？本喵先把三只都叫来、都开工，再挨个等它们收工：

```python
import threading

结果 = ["", "", ""]

def 烤鱼干(编号):
    结果[编号] = f"第 {编号} 号鱼干"

猫们 = []
for i in range(3):
    t = threading.Thread(target=烤鱼干, args=(i,))
    猫们.append(t)
    t.start()

for t in 猫们:
    t.join()

for i in range(3):
    print(结果[i] + " 烤好啦喵")
```

```text
第 0 号鱼干 烤好啦喵
第 1 号鱼干 烤好啦喵
第 2 号鱼干 烤好啦喵
```

看起来和没猫的那版输出一模一样——**这正是本喵想要的效果**喵：猫多了，结果一点没变。改动的地方有三处：

1. **先造一只空储物柜**（`猫们 = []`），用来收留叫来的猫。叫一只就往里塞一只（`猫们.append(t)`），这样本喵手里始终有名单，不会叫完就找不着了。
2. **第一个跑圈里，叫一只、开工一只，本喵不等**。三只猫于是都在自己烤——这就是「一起干活」。
3. **第二个跑圈：本喵挨个等它们收工**（`t.join()`）。三只全等到了，才走到最后的打印。

最后的打印值得多看两眼：本喵是**按编号 0、1、2 挨个去格子里取**的。印出来的顺序是**本喵定的**，跟哪只猫先烤完、后烤完**没有半点关系**。所以这段程序你跑一百遍，印出来都是一模一样的这三行喵。

### 投喂的小鱼干：`args=`

上面那只猫的招式要收一个**编号**，本喵是这么喂进去的：`args=(i,)`。

- **`args=`** 后面装的就是投喂给这招的小鱼干（参数）。喂几样，按**招式收的顺序**一样一样排好。
- **`(i,)` 末尾那个逗号千万别丢**。一对括号里只有一个东西的时候，`(i)` 在 Python 眼里只是「加了个壳的数字 i」，不是「一串只有一个的小鱼干」。少了逗号，等猫开工时翻译官喵会抱怨这串东西没法一个个拆开喂。

只有一样要喂的时候，末尾那个逗号就是它的护身符喵。

## 三、共用一只罐子：要挂锁

前面三只猫各用**自己的格子**（`结果[0]`、`结果[1]`、`结果[2]`），互不打架。

现在换个场景：四只猫往**同一只罐子**里加小鱼干，每只捡 25 条，一共该有 100 条。

```python
import threading

总数 = 0
锁 = threading.Lock()

def 捡鱼干(只数):
    global 总数
    for _ in range(只数):
        with 锁:
            总数 = 总数 + 1

猫们 = []
for i in range(4):
    t = threading.Thread(target=捡鱼干, args=(25,))
    猫们.append(t)
    t.start()

for t in 猫们:
    t.join()

print(f"一共捡到 {总数} 条小鱼干喵")
```

```text
一共捡到 100 条小鱼干喵
```

三个新面孔：

- **`global 总数`** —— 跟翻译官喵打声招呼：这句里要改的 `总数`，是**外面那只罐子**，不是本喵在招式里新造的一只。少了这一句可**一点都不安静**：`总数 = 总数 + 1` 是先**读**后写，招式里那只小罐子还没装东西就要被读，当场摔 `UnboundLocalError`。本喵真跑过（四只猫、每只捡 25 条）：屏幕上**四片红字**，每片一句 `Exception in thread Thread-N (捡鱼干)` 打头，底下写着 `cannot access local variable '总数' where it is not associated with a value`；最后印出来的那一行是 `一共捡到 0 条小鱼干喵` —— 外面那只罐子确实**一动不动**，可不是悄悄不动，是四只猫**一只都没干成活**喵。⚠️ 而且**退出码还是 `0`**：摔的是那些小猫，正门（主程序）自己好好走完了。所以别拿退出码当体检结果，得看屏幕。
- **`锁 = threading.Lock()`** —— 领一把钥匙。
- **`with 锁:`** —— **进屋改数字之前先拿钥匙，出来时自动还回去**。（你在上一课见过的那对会自动收拾的 `with`，今天正好拿来管这把钥匙。）钥匙只有一把，所以同一时刻**只有一只猫能进屋**，别的猫在门口排队。

### 没有钥匙会怎样

这一条本喵要讲得慢一点，因为它错得**特别安静**。

`总数 = 总数 + 1` 看着是一步，其实分成**三步**：① 读出罐子上写的数 → ② 在心里加一 → ③ 把新数写回罐子。

现在两只猫同时来加：

1. 猫甲读到罐子上写着 **5**；
2. 猫甲还没来得及写回去，就被换下场了；
3. 猫乙上场，读到的还是 **5**，加一，写回 **6**；
4. 猫甲再上场，把它心里那个 **6** 写回去。

两只猫各捡了一条，罐子上却只从 5 涨到 6——**凭空少了一条**。程序不会报错，也不会提醒你，只是数字对不上，而盯着代码看半天也看不出毛病。

⚠️ 但本喵得说实话：**这个坑不是每次都能撞上**。本喵把上面那段代码的 `with 锁:` 拆掉真跑了几种形状 ——

- 四只猫各捡 **25** 条（就是上面那段）：跑五遍，**五遍都是 `100`**，一条不差；
- 四只猫各捡 **2000** 条：跑五遍，还是 **`8000`**，一条不差。

猫干得太快了：从「读」到「写回」只要几微秒，一只猫还没轮到被换下场，它就已经写完了 —— **中间没有缝，就撞不上。**

缝从哪来？只要「读」和「写回」中间**夹了任何要等一等的事**（本喵量过：多一句 `time.sleep(0)` 就算），同样四只猫、每只 2000 条，跑出来是 **2000 / 2192 / 2122**（该有 `8000`）—— 而且**每跑一次都不一样**。真实干活时这种缝遍地都是：读文件、上网、烤鱼干（本课前面那只猫就一直在 `time.sleep`）全算。

所以这个坑真正阴的地方是**时灵时不灵**：今天跑对了，不代表你写对了，只代表今天缝隙没凑巧对上。这就是本喵非要你把钥匙挂上的原因 —— 挂上 `with 锁:`，跑多少次都是 `100`。

所以本喵的规矩是：

> **只要是好几只猫改同一个格子、同一个数字，就把钥匙挂上（`with 锁:`）。**

各写各的格子（就像第二节那样）不用挂锁，那是唯一可以偷懒的情况喵。

::: tip 猫咪提示
本课三句话，抄在小本本上：

1. **叫猫**：`threading.Thread(target=招式名, args=(小鱼干,))`——名字**不带括号**，投喂只有一个时**逗号不能丢**。
2. **开工与等待**：喊它 `t.start()`，等它 `t.join()`。本喵要用的结果，**一定在 `join()` 之后才去取**。
3. **先后不定**：猫谁先干完由电脑安排，你说了不算。想让输出每次都一样，就让猫只往格子里放结果，**最后按固定顺序统一印**。
:::

::: warn 小心喵
三只猫一起干活时最容易摔的三跤：

- **`target` 后面带了括号**：`threading.Thread(target=烤鱼干(0))` 会**当场**把招式施展一遍（本喵自己动手烤了），`Thread` 拿到的是招式叼回来的战利品、不是招式。而这一招不叼东西，战利品是 `None`——猫开工后**什么都不干**，**程序还不报错**，表面上结果甚至是对的（那是本喵自己烤的）。你想要的「几只猫一起干活」，就这么悄悄变成了本喵一个人排队干喵。判据：**括号一出现，招式当场就动手了**。
- **忘了 `join()`**：本喵跑到打印那一句时，猫可能还在烤，格子里装的是空的。**程序不报错**，只是印出来的东西不对——这种安安静静的错误最费眼神喵。
- **好几只猫改同一个数字却不挂锁**：数字会莫名其妙地少几条。看见「少了但没报错」，先想想是不是忘了 `with 锁:`。
:::

## 本课小抄

| 想干的事 | 写法 |
|---|---|
| 叫一只猫来干活 | `threading.Thread(target=招式名, args=(小鱼干,))` |
| 喊它开工 | `t.start()` |
| 等它收工 | `t.join()` |
| 一次叫好几只 | 每只都塞进储物柜：`猫们.append(t)`，最后挨个 `t.join()` |
| 好几只猫改同一个格子 | 领钥匙 `锁 = threading.Lock()`，改动时 `with 锁:` |
| 看结果 | 等 `join()` 全部到齐，由本喵按固定顺序统一印 |
| 招式里要改外面的罐子 | 开头写 `global 罐子名` |
