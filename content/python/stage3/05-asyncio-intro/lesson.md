## 钩子：一百位客人，本喵只有两只爪子

本喵今天要给一百位猫客人送小鱼干。每一家的流程都一模一样：

```text
敲门 → 站在门口等主人来开 → 把鱼干放下
```

要是本喵死心眼，敲开小橘家的门就**杵在门口一动不动地等**，等小橘慢悠悠来开门，再走去狸花家……一天下来本喵忙得尾巴都僵了。可你数数看：真正「把鱼干放下」的动作只有一下下，剩下的时间**全花在干等上**了喵。

本喵拍了一下爪子：**等门开的时候，本喵的爪子明明是空着的呀！** 空着为什么不去下一家先敲门呢？

## 电脑也一样：等的时候，爪子是空的

电脑干活的时候，也有一大堆「干等」的场面：

- 水壶架上了，等水开；
- 烤炉里的鱼干还没好，等它出炉；
- 小纸条扔出去了，等鱼塘那头的猫回话；
- 一大包小鱼干，要慢慢从仓库里读出来。

这些活儿有个共同点：**它们不占爪子，占的是时间**。等的时候电脑其实什么都没干，就那么僵着。

所以本喵想的是同一件事：能不能**等这一口锅的时候，先去顾别的锅**？

## 看锅猫：一只猫照看三口锅

本喵在灶台边架起三口锅：左边烧水，中间蒸鱼，右边炖汤。

要是规矩是「架上一口就得站到它好为止」，那本喵只能抱着水壶等水开，蒸鱼和炖汤干瞪眼。聪明一点的做法是这样：

1. 三口锅**都架上**；
2. 哪口锅好了，就去照看哪口；
3. 还没好的那几口，本喵**不站着等**，转头先把蒸鱼的料备好；
4. 一圈一圈看过去，直到三口锅全好。

这套「**一只猫在好几口锅之间来回照看**」的办法，管的事书上叫**事件循环（看锅猫）**。名字太长，本喵往后就叫它「看锅猫」喵。

有一句话要记牢：**从头到尾还是同一只猫**。这不是「叫好几只猫一起干活（多线程）」——本喵没有分身，只是一只在锅与锅之间跑得很快的猫。

这决定了它的脾气：看锅猫**不会真的同时算两样东西**。它的本事是**不干等**——凡是「架上去、等结果」的活儿，它在等的时候都能去顾别的锅。

## 请出看锅猫：`asyncio.run`

理儿讲完了，来看 Python 里怎么使唤它：

```python
import asyncio

async def 打招呼():
    print("喵～本喵来啦")

asyncio.run(打招呼())
```

```text
喵～本喵来啦
```

逐句拆开看喵：

- **`import asyncio`** —— 把看锅猫这套家伙什请进屋。`asyncio` 是 Python 自带的一盒工具，不用另外装。
- **`async def 打招呼():`** —— 定义一招**不着急的招式**。`async` 写在 `def` 前面，意思是「这一招什么时候跑，由看锅猫说了算」。
- **`asyncio.run(打招呼())`** —— **请出看锅猫**，让它把这一招跑完，跑完就收工。

中间那一句最要紧：**`打招呼()` 喊下去，招式里一行都不会跑**。它只叼回来一张「**待办小纸条**」，上头写着「本喵想干这件事」。真正把活儿交到看锅猫爪子里的，是外面的 `asyncio.run(...)`。

所以你要是只写了 `打招呼()`、忘了外面的 `asyncio.run(...)`，程序**一个字都不会印**。它不是坏了，是看锅猫压根没被请出来喵。

⚠️ 不过屏幕也不是全干净的：收尾的时候角落里会冒出一句 `RuntimeWarning: coroutine '打招呼' was never awaited`。那是**警告**，不是报错 —— 本喵真跑过：退出码 `0`、招式里那行 `print` 一个字没出，屏幕上只有这一句警告（197 字节）躺着。看见它别当装饰喵，它就是「**有张纸条没人接**」的告示。

## `await`：等的时候，把爪子让出来

现在让锅真的「等一等」：

```python
import asyncio

async def 烧水():
    print("架上水壶")
    await asyncio.sleep(0.2)
    print("水开啦")

asyncio.run(烧水())
```

```text
架上水壶
水开啦
```

- **`await`** 读作「**等它**」。它后面跟的那一样，就是本喵要等的那口锅。
- **`asyncio.sleep(0.2)`** 就是「等 0.2 秒」这口锅。
- `await` 的妙处全在这个「让」字：**本喵把爪子让出来**，先去看别的锅；等这口到点了，再回来接着走下面那行 `print("水开啦")`。

对照一下以前的等法：要是用 `time.sleep(0.2)`，那是「**抱着爪子死等**」——这 0.2 秒里谁也别想动，旁边的锅只能干瞪眼。`asyncio.sleep` 是**不占爪子的等**，差别就在这里喵。

还有一条规矩：`await` **只能住在 `async def` 的招式里面**。写到外面去，翻译官喵会当场拦下来，跟你说这里不许写 `await`。

## 一口气架上好几口锅：`asyncio.gather`

刚才只架了一口锅。真要看锅猫的本事，得**一次架好几口**：

```python
import asyncio

async def 拿小鱼干(名字, 秒数):
    await asyncio.sleep(秒数)
    return f"{名字}的小鱼干"

async def 主招式():
    结果 = await asyncio.gather(
        拿小鱼干("小橘", 0.3),
        拿小鱼干("狸花", 0.1),
    )
    for 一条 in 结果:
        print(一条)

asyncio.run(主招式())
```

```text
小橘的小鱼干
狸花的小鱼干
```

拆开看喵：

- **`拿小鱼干`** 也是一招不着急的招式。它名字后面括号里那两样，是**投喂给它的**：要谁的鱼干、要等多久。
- **`asyncio.gather(...)`** —— 「**这几口锅一起架上**」。括号里可以塞好几张待办小纸条，它会等**全部**都好了再一起回来。
- 前面那个 `await` 还是它：本喵在等**所有的锅**，等的这段时间爪子全让出去了。
- 回来之后，**`结果` 是一个排好队的储物柜**：`结果[0]` 是第一条，`结果[1]` 是第二条，后面的按这个规矩一条条排下去。

**现在盯住输出的顺序喵。** 狸花那条路线只要 0.1 秒，比小橘的 0.3 秒**先回来**；可印出来的第一行还是**小橘**。

因为 `gather` 有个规矩：**谁先回来不重要，战利品一律按你投放的顺序摆好**。你写的是「先小橘、后狸花」，名单上就永远是这个次序，一条都不会乱。

这条规矩对你特别友好：**不用去猜谁快谁慢**，只要顺序写清楚，结果就永远是那个顺序。

## 看锅猫只管「等」，不管「算」

有一件事必须说清楚，不然你会用错它。

看锅猫的拿手好戏是**等**：等水开、等鱼出炉、等远处的猫回话。可要是某口锅的活是「**本喵抱着铲子拼命翻炒三分钟**」，那爪子就**一直占着**，让不出来。这种时候你架几口锅都没用，看锅猫只能一口一口挨着炒。

所以：

- **大段大段都在等的活儿** —— 看锅猫的主场：等回话、等文件读完、等定时器到点；
- **爪子一直占着的活儿**（拼命算数、反复搬运）—— 看锅猫帮不上忙，得请别的帮手。

下一课，本喵要带你**隔着好几个鱼塘，把小鱼干送给远处的猫**——那正是看锅猫最出风头的地方喵。

::: tip 猫咪提示
今天记住四个口令就够啦：

- **`async def`** —— 定义一招**不着急的招式**；喊它**不会马上跑**，只叼回来一张待办小纸条。
- **`await`** —— 把活儿交给看锅猫看着，本喵先把爪子让出来；好了再回来接着往下走。
- **`asyncio.run(招式())`** —— 请出看锅猫，把主招式跑完。**少了它，一张纸条都不会动**。
- **`asyncio.gather(好几张纸条)`** —— 一口气全架上，全好了再一起叼回来，**按你投放的顺序**摆好。
:::

::: warn 小心喵
三个最容易踩的坑：

- **忘了 `await`**：写成 `结果 = 拿小鱼干("小橘", 0.3)`，本喵拿到的**不是小鱼干**，而是一张待办小纸条。它躺在那儿什么都不干——要 `await` 才会真的跑起来。⚠️ 别以为它**一点动静都没有**：这张没人接的纸条被收走的时候，屏幕上会嘀咕一句 `RuntimeWarning: coroutine '拿小鱼干' was never awaited`（本喵真跑过：正文照印、退出码 `0`，那句警告 266 字节）。是警告不是报错，所以最容易看漏。
- **忘了 `asyncio.run(...)`**：招式写得再漂亮，程序跑完也**一个字都不印**（屏幕上剩下的，只有角落里那句 `RuntimeWarning`）。不是招式坏了，是看锅猫没被请出来。
- **把 `await` 写到招式外面**：`await` 只能住在 `async def` 里面，写到外面翻译官喵会拦下来报错。
:::

## 一句话对照表

| 写下的这一句 | 它干了什么 |
|---|---|
| `import asyncio` | 把看锅猫这套家伙什请进屋 |
| `async def 招式():` | 定义一招「不着急的招式」 |
| `asyncio.run(招式())` | 请出看锅猫，把主招式跑完，收工 |
| `await 一样东西` | 把活儿交出去看着，本喵先让出爪子，好了再回来 |
| `await asyncio.sleep(秒数)` | 不占爪子的等一等（不是抱着爪子死等） |
| `asyncio.gather(...)` | 一口气架好几口锅，全好了再一起叼回来，**按投放顺序**摆好 |
| `结果[0]`、`结果[1]` | 从排好队的储物柜里按位置取战利品 |

## 小任务

本喵把三口锅一起架上了，你照着敲一遍跑跑看：

```python
import asyncio

async def 拿小鱼干(名字, 秒数):
    await asyncio.sleep(秒数)
    return f"{名字}的小鱼干"

async def 主招式():
    结果 = await asyncio.gather(
        拿小鱼干("小橘", 0.3),
        拿小鱼干("狸花", 0.1),
        拿小鱼干("三花", 0.2),
    )
    print(结果)

asyncio.run(主招式())
```

```text
['小橘的小鱼干', '狸花的小鱼干', '三花的小鱼干']
```

**试着改一改**：

1. 把 `三花` 那一条挪到最前面，再跑一遍——印出来的储物柜里，它排第几？为什么？
2. 把 `三花` 的秒数改成 `0.5`，让它变成最慢的那一位。再跑——输出的**顺序**会变吗？（提示：先别急着改，猜一猜再跑喵。）
3. 把 `gather` 那一整段换掉，改成一句一句地 `await`（先 `await 拿小鱼干("小橘", 0.3)`，再 `await 拿小鱼干("狸花", 0.1)`）。印出来的东西**一模一样**，可本喵花掉的等待时间变成多少了？

到这里，本喵已经带你摸到了 asyncio 的门：从「干等」这件小事出发，认识了看锅猫，也学会了四个口令。下一课我们带着它去**隔着鱼塘送小鱼干**喵～ 🐾
