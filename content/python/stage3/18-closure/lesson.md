## 钩子：招式走了，它肚子里的东西还在

本喵最近撞上个怪事。

本喵写了一招「造打招呼的」：它肚子里先摆一间仓库、里面装上「大肥鱼」三个字，再写下一招「打招呼」，最后**把这一招整个叼出去**。

喊一声外层招式，它开演、写完、收工 —— 跟每一招一样，干完活就走。

可本喵把叼出来的那一招收好，隔了很久再喊它，它**居然还叫得出「大肥鱼」**。外层招式早就走得没影了，它肚子里那间仓库却还在，里面的字一个没少。

这门本事叫**闭包** —— 说人话就是「**招式里藏着的记忆**」。这节课就把它拆开看喵。

## 一、招式跑完了，它肚子里的仓库不跟着走

```python
def 造打招呼的():
    名字 = "大肥鱼"
    def 打招呼():
        print("喵～本喵叫", 名字)
    return 打招呼

小招 = 造打招呼的()
print("外边那一招早就跑完了")
小招()
小招()
```

```text
外边那一招早就跑完了
喵～本喵叫 大肥鱼
喵～本喵叫 大肥鱼
```

一行行看：

- **`名字 = "大肥鱼"`** 摆的是**外层招式肚子里的**仓库 —— 既不是门口的，也不是 `打招呼` 自己摆的。
- **`def 打招呼():`** 在肚子里又写下一招。这会儿它**只是被写下来**，里面一个字都还没跑过。
- **`return 打招呼`** 把这一招整个叼出去（`python-stage2-09` 学过：招式本身也是一样东西，能当小鱼干传来传去）。这一行执行完，外层招式的身体就没了。
- **`小招`** 接住的就是**那一招**。往后每喊一次，它都还读得到 `名字` —— 因为**它出身那间屋子里的仓库，被它随身带走了**。

所以闭包一点也不玄：**招式 + 它随身带着的那间小仓库。** 只要那一招还在，仓库就在；仓库在，里面的数就记得住。

::: tip 猫咪提示
「招式叼着仓库走」这件事，用起来就两条：

- **记忆留得住**：外层招式只喊一次，把叼出来的那招收好 —— 往后一直喊它，记忆就跟着它。
- **仓库是自己的**：每喊一次外层招式，肚子里就摆**一间新的**仓库（下一节细说）。所以两只计数器各记各的，不会串账。
:::

## 二、`nonlocal`：要**改**它才需要打招呼

### 只是**读**它：一个字都不用加

```python
def 造乘法器(倍率):
    def 乘一乘(数):
        return 数 * 倍率
    return 乘一乘

三倍 = 造乘法器(3)
五倍 = 造乘法器(5)
print(三倍(7), 五倍(7))
```

```text
21 35
```

`乘一乘` 里用到了 `倍率`，可它**没写任何声明** —— 因为它只**读**，从没给 `倍率` 重新放过东西。只是读，翻译官喵一路放行。

两招各记各的：`三倍` 攥着 `3`，`五倍` 攥着 `5`，井水不犯河水。

### 要**改**它：不打招呼就当场炸毛

本喵把同一招改成「数一数自己被人喊了几次」：

```python
def 造计数器():
    记数 = 0
    def 数一数():
        记数 = 记数 + 1
        return 记数
    return 数一数

数一数 = 造计数器()
print(数一数())
```

```text
Traceback (most recent call last):
    记数 = 记数 + 1
UnboundLocalError: cannot access local variable '记数' where it is not associated with a value
```

（中间本来还有一行 `File "…\main.py", line 4, in 数一数`，那行里带着每次都不一样的路径，本喵把它省掉了。）

最后那句翻成猫话是：**「`记数` 这间仓库你还没往里摆东西，就想读它。」**

可本喵明明在里层招式**外面**摆过 `记数 = 0` 呀？它为什么不认？因为翻译官喵有一条规矩：**招式里只要出现 `记数 = 什么` 这样的赋值，`记数` 就被当成这一招自己肚子里的仓库。** 于是 `记数 = 记数 + 1` 右边那个 `记数` 去翻的是本层肚子 —— 空的，当场炸毛。

::: warn 小心喵
这条规矩跟 `python-stage1-12` 里那条「自带存货的排最后」是同一个脾气：**翻译官喵读一眼就把单子定下来**，它不问你想干什么。

`记数 = 记数 + 1` 这一行，右边那个 `记数` 你想读的是外层的，可左边那个 `记数 =` 先一步把它拽成了「本层肚子里的仓库」。**一句赋值，就把整间仓库换了主人** —— 这是初学者第一大坑喵。
:::

### 打声招呼：`nonlocal`

```python
def 造计数器():
    记数 = 0
    def 数一数():
        nonlocal 记数
        记数 = 记数 + 1
        return 记数
    return 数一数

数一数 = 造计数器()
print(数一数(), 数一数(), 数一数())
```

```text
1 2 3
```

`nonlocal 记数` 这一行的意思是：**「本喵说的 `记数` 不是本喵肚子里的，是外面那层招式肚子里的那一个。」** 打了这个招呼，`记数 = 记数 + 1` 的左右两边就都指着同一间仓库 —— 读得到、改得动，喊三次就是 `1 2 3`。

一句话记牢：**只是读，不用打招呼；要改，就得写 `nonlocal`。**

::: tip 猫咪提示
`nonlocal` 后面跟的那个名字，**必须真的在上层招式肚子里存在**，不然连跑都跑不起来。下面这段是翻译官喵的原话（这份稿子它读一眼就退单，本喵把它摆在这儿给你看）：

```text
def 造计数器():
    def 数一数():
        nonlocal 记数
        return 记数
    return 数一数
```

```text
  File "...\main.py", line 3
    nonlocal 记数
    ^^^^^^^^^^^^^^^
SyntaxError: no binding for nonlocal '记数' found
```

最后那句翻成猫话是「**没找到名叫 `记数` 的外层仓库**」。注意它和上一节那个 `UnboundLocalError` 的**脾气不一样**：这一条是**翻译官喵读一眼就退单**（`SyntaxError`），你写的代码一个字都不会执行；上一节那条是**跑到那一行才炸**的喵。
:::

## 三、记忆的两种丢法

### 丢法一：外层招式被反复喊

```python
def 造计数器():
    记数 = 0
    def 数一数():
        nonlocal 记数
        记数 = 记数 + 1
        return 记数
    return 数一数

甲 = 造计数器()
乙 = 造计数器()
print("甲连喊两次：", 甲(), 甲())
print("乙喊一次：", 乙())
print("回头再喊甲：", 甲())
print("每次重新喊外层：", 造计数器()(), 造计数器()())
```

```text
甲连喊两次： 1 2
乙喊一次： 1
回头再喊甲： 3
每次重新喊外层： 1 1
```

- **`甲` 和 `乙` 是喊了两次 `造计数器` 造出来的**。每喊一次外层，肚子里就摆**一间新的** `记数 = 0` —— 所以甲记甲的、乙记乙的，各不相干。
- **最后一行是 `1 1`**：`造计数器()()` 的意思是「先造一间崭新的、马上喊它一次」。崭新的仓库每回都是从 0 起，所以永远是 1。

想让记忆留住，**外层招式就只能喊一次** —— 喊一次，把叼出来的那招收好，往后一直喊里层那一招。

### 丢法二：自己在里层把仓库清零

```python
def 造计数器():
    记数 = 0
    def 数一数():
        nonlocal 记数
        记数 = 0
        记数 = 记数 + 1
        return 记数
    return 数一数

数一数 = 造计数器()
print(数一数(), 数一数(), 数一数())
```

```text
1 1 1
```

这一版里本喵多写了一行 `记数 = 0`，而且写在了**里层**。于是每喊一次，先清零、再加一，永远都是 1。

它**跑得通、也不报错**，只是这本账再也记不住事了。**记忆要摆在外层肚子里，里层只负责读它、改它**；摆错了地方，招呼打得再对也白搭喵。

## 四、晚绑定：绕圈造出来的一排招式，共用一个仓库

```python
招式们 = []
for 编号 in range(3):
    def 报数():
        return 编号
    招式们.append(报数)

print("三招报出来的数：", 招式们[0](), 招式们[1](), 招式们[2]())
```

```text
三招报出来的数： 2 2 2
```

三招，报出来全是 `2`。为什么喵？

- `for 编号 in range(3):` 绕圈的时候，**只摆了一间仓库 `编号`**，每一圈往里放一个新数 —— 并不是每圈摆一间新的。
- 三招闭包攥着的，**是同一间** `编号`。
- 招式里的句子，**没被喊之前一句都不跑**。等绕完圈、把三招挨着喊一遍的时候，`编号` 里面早停在最后一个值 `2` 上了。

所以最要紧的一句是：**闭包记住的是「那间仓库」，不是「那一刻的数」。** 仓库里现在装着几，喊它的时候就读到几。这个现象有个名字叫**晚绑定** —— 里头的名字**什么时候去取，就取谁当时的值**。

::: warn 小心喵
这个坑最坏的地方是**它不报错**。三招都老老实实报了个数出来，只是三招报的是同一个 —— 一眼扫过去还像「结果本来就该这样」。

要是这三招是分给三只猫各算各的账，那三只猫的账就全串在一起了，而且你得盯着屏幕看半天才发现喵。
:::

## 五、晚绑定的两种修法

```python
def 造报数招(编号):
    def 报数():
        return 编号
    return 报数

一排 = [造报数招(编号) for 编号 in range(3)]
print("用外层招式包一层：", 一排[0](), 一排[1](), 一排[2]())

招式们 = []
for 编号 in range(3):
    def 报数2(钉住的编号=编号):
        return 钉住的编号
    招式们.append(报数2)
print("用自带小鱼干钉住：", 招式们[0](), 招式们[1](), 招式们[2]())
```

```text
用外层招式包一层： 0 1 2
用自带小鱼干钉住： 0 1 2
```

- **修法一（闭包的正统用法）**：让每一招出自**不同的外层招式**。`造报数招(编号)` 每被喊一次，肚子里就摆**一间新的** `编号`，里层攥的就是这一间 —— 三间互不相干，于是 `0 1 2`。
- **修法二（自带的小鱼干钉住）**：`def 报数2(钉住的编号=编号):` —— 自带的那一份，是在**写下这一招的那一刻**就算好、存在招式身上的（就是 `python-stage1-12` 学的「自带的小鱼干」）。它当场把当前的 `编号` **抄了一份**揣着，往后不再去取那间仓库。

两种都行，区别只有一句话：**修法一是让每一招各有一间仓库；修法二是根本不去取仓库，当场抄一份。**

## 六、`lambda` 是同一回事

```python
def 造加法器(加多少):
    return lambda 数: 数 + 加多少

加十 = 造加法器(10)
加百 = 造加法器(100)
print("加十：", 加十(5), "加百：", 加百(5))

一排 = [lambda: 编号 for 编号 in range(3)]
print("一排 lambda 报出来的数：", 一排[0](), 一排[1](), 一排[2]())
```

```text
加十： 15 加百： 105
一排 lambda 报出来的数： 2 2 2
```

- **上半段**：`lambda 数: 数 + 加多少` 就是**一招没写名字的招式**。它一样闭得住外面的 `加多少` —— `加十` 攥着 10、`加百` 攥着 100，喊出来的结果各不相同。**闭包这件事，跟招式有没有名字一点关系都没有。**
- **下半段**：一排 `lambda` 报出来 `2 2 2`，跟第四节那个坑**一模一样** —— 它们共用一个 `编号`，喊的时候都取到最后一个值。

所以别把它们记成两件事：`def` 写的招式、`lambda` 写的招式，闭包的脾气完全相同。

不过 `lambda` 有一位比不上 `def`：它肚子里**只放得下一句式子**，写不了 `nonlocal` 这种声明。所以要**改**外层的数，还是乖乖用 `def`。

## 七、`global`：门口那本账

```python
总数 = 0

def 记一笔():
    global 总数
    总数 = 总数 + 1

记一笔()
记一笔()
记一笔()
print("门口那本账：", 总数)
```

```text
门口那本账： 3
```

最外面那行 `总数 = 0` 摆的是**门口（整个文件）那本账**。里层招式要改它，得写 `global 总数` —— `global` 说的就是「**门口那本**」。

::: tip 猫咪提示
这两位长得像，指的楼层不一样喵：

- **`global`** —— 门口（整个文件）那本账；
- **`nonlocal`** —— **外面那层招式**肚子里的仓库。

一个一路往上找到文件那层，一个只找到上一层招式。要改的账摆在哪儿，就写哪一位。
:::

写错会怎样？本喵把第二节那招计数器里的 `nonlocal` 换成 `global`：

```python
def 造计数器():
    记数 = 0
    def 数一数():
        global 记数
        记数 = 记数 + 1
        return 记数
    return 数一数

数一数 = 造计数器()
print(数一数())
```

```text
Traceback (most recent call last):
    记数 = 记数 + 1
NameError: name '记数' is not defined
```

`global 记数` 让里层招式去**门口**找 `记数`，可门口压根没有这本账（它摆在外层招式肚子里），于是当场炸毛。

::: warn 小心喵
比报错更坏的，是**门口碰巧真有一本同名的账**。本喵真跑过下面这一段：

```text
记数 = 100

def 造计数器():
    记数 = 0
    def 数一数():
        global 记数
        记数 = 记数 + 1
        return 记数
    return 数一数

print(造计数器()())
```

它**不报错**，安安静静把数记到门口那本账上，印出来是 `101`。两段程序都「跑通了」，一个记得对、一个记到别人账上去了 —— 这种错没人拦得住，只能靠你自己先想清楚：**这本账摆在哪儿**喵。
:::

## 八、闭包和「给招式加特效」是同一件事

`python-stage2-09` 那一课教的是「**在外面套一层、招式本身一个字不动**」。今天回头看，那层壳**就是闭包**。

壳里用到了外面喂进来的 `fn`，可从没给 `fn` 重新放过东西 —— **只读，所以那里不用写 `nonlocal`**。第二节那条规矩，在这件事上正好用得上。

反过来也一样：**哪天你想让特效记个「这一招被喊了几次」，仓库就得摆到壳外面去，壳里再写一句 `nonlocal 记数` 把它加上去**（小任务第 4 条就是这个）。

一句话收口：**给招式加特效 = 闭包 + 「招式本身也是一样东西」** —— 那节课你学的是外面那一层，这节课补上了底下这一层喵。
