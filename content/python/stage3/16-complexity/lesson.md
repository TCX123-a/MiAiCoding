## 钩子：同一件事，两种写法，差了五十一倍

本喵手上有 **1024 条小鱼干**，要把它们按重量从小到大排排坐。

排排坐的办法不止一种。本喵真写了两种，每种都配了一个小计数器 —— **干一下基本动作就往计数器上加 1**：
一种报出来是 **523776** 圈，另一种报出来是 **10240** 圈。

同一件事、同一筐鱼干：一个 52 万圈、一个 1 万圈 —— **差了 51 倍还多**。

这两个数不是本喵从别处抄来的，是真跑出来的。第二节会把两段程序原样摆出来，你也能自己跑一遍。

这节课要教的，就是怎么**数出**这样的数，以及数出来之后怎么**一眼看出谁快谁慢**。这门功夫的正式名字叫 **算法复杂度**。

## 一、为什么要量代价：秒表靠不住

问「谁快谁慢」，最直觉的问法是：**掐个秒表不就完了？** 本喵也这么想过，真掐了一次：

```python
import time

几条 = 1024
圈 = 0
起 = time.perf_counter()
for 第一 in range(几条):
    for 第二 in range(第一 + 1, 几条):
        圈 = 圈 + 1
止 = time.perf_counter()
print("圈数", 圈)
print("秒数", round(止 - 起, 3))
```

本喵把**同一段程序**连着跑了三次，三次印出来是这么三组：

- 圈数 523776、秒数 `0.017`
- 圈数 523776、秒数 `0.018`
- 圈数 523776、秒数 `0.017`

同一台机器、同一段程序、**同一个圈数**，秒数却在那儿晃。要是换台更快的电脑、换台手机、换一台当时正开着别的程序的机器，秒数还能差得更远。

::: warn 小心喵
**秒不是一把能带出门的尺子。** 你在自己电脑上量出「A 比 B 快」，换到大肥鱼那边（它常年开着好几条鱼塘）可能就反过来了。秒数里混着机器快慢、当时忙不忙、翻译官喵心情好不好 —— **它量的是这台机器，不是这段写法**。
:::

所以本喵换了把尺子：**数圈数**。上面那段程序的内圈一共转 523776 次 —— 这个数**只跟「有几条鱼干」和「怎么写」有关**，搬到哪台机器上都是 523776。

::: tip 猫咪提示
「圈数」的正式说法是**操作次数**（基本操作的执行次数）。「一下基本动作」指的是比一下大小、搬一条鱼干、加一次加法这种**很小很小的一步**。数它，是因为它跟机器无关 —— 同一段程序，数出来的圈数在谁那儿都一样。
:::

## 二、数圈数：从 523776 到 10240

### 笨办法：两两比

先看笨办法。规矩是「每一条鱼干都跟排在它后面的每一条握一次手」，握手的时候顺手把大的往后挪：

```python
# 笨办法：两两比。每一条都跟它后面每一条比一次
几条 = 1024
一筐 = list(range(几条, 0, -1))
圈 = 0
for 第一 in range(几条 - 1):
    for 第二 in range(几条 - 1 - 第一):
        圈 = 圈 + 1
        if 一筐[第二] > 一筐[第二 + 1]:
            一筐[第二], 一筐[第二 + 1] = 一筐[第二 + 1], 一筐[第二]
print("两两比一共绕了", 圈, "圈")
print("筐里现在是 1 到 1024 吗：", 一筐 == list(range(1, 几条 + 1)))
```

```text
两两比一共绕了 523776 圈
筐里现在是 1 到 1024 吗： True
```

圈数是这么数出来的：`圈 = 圈 + 1` 写在**最里面那一圈**里，所以内圈每转一次就加 1。

- 第 0 号鱼干要跟后面 1023 条握；
- 第 1 号跟后面 1022 条握；
- ……
- 最后一条谁都不用握了。

加起来就是 **1023 + 1022 + 1021 + … + 1 = 1024 × 1023 ÷ 2 = 523776**。

### 乖办法：一层层折半再合起来

再看乖办法：先把鱼干一层层折半分开，再一层层合起来。合的时候两条一对比，小的先放进新筐。

```python
# 乖办法：一层层折半，再一层层合起来
几条 = 1024
一筐 = list(range(几条, 0, -1))
搬了几条 = 0
半宽 = 1
while 半宽 < 几条:
    新筐 = []
    for 起 in range(0, 几条, 半宽 * 2):
        左 = 一筐[起:起 + 半宽]
        右 = 一筐[起 + 半宽:起 + 半宽 * 2]
        i = 0
        j = 0
        while i < len(左) or j < len(右):
            if j >= len(右) or (i < len(左) and 左[i] <= 右[j]):
                新筐.append(左[i])
                i = i + 1
            else:
                新筐.append(右[j])
                j = j + 1
            搬了几条 = 搬了几条 + 1
    一筐 = 新筐
    半宽 = 半宽 * 2
print("折半合起来一共搬了", 搬了几条, "条")
print("筐里现在是 1 到 1024 吗：", 一筐 == list(range(1, 几条 + 1)))
```

```text
折半合起来一共搬了 10240 条
筐里现在是 1 到 1024 吗： True
```

这段的排法**现在不用逐行看懂**（它到底怎么把两半合成一整排，`python-stage3-20` 那一课会拆开讲）。现在只盯那个计数器：**每把一条鱼干放进新筐，就加 1**。

它的 10240 是这么来的：

1. **折半一共 10 层** —— 1024 砍一半是 512，再砍一半是 256……一路砍到 1，正好砍 10 次（1024 就是 2 的 10 次方）；
2. **每一层，1024 条鱼干每一条都要被搬一次**（从旧筐搬进新筐）；
3. 所以是 **10 × 1024 = 10240**。

一边是「1023 + 1022 + …」一路加下去，一边是「10 层 × 1024 条」—— 这就是这一课的两个锚点数字。

::: tip 猫咪提示
有同学要问：一边数的是「比一下」，一边数的是「搬一下」，这两种动作放一起比合适吗喵？

合适 —— 因为它们**都是「一条鱼干的一小步活」**，花的工夫差不多。大 O 记号要做的正是**把这种常数上的小差别抹平**：搬一下就算比比一下贵一倍，到最后也盖不过「量级」那一层的差别（下一节就讲这件事）。
:::

## 三、大 O 记号入门：只留涨得最快的那一项

上面那个圈数，其实能写成一个式子：`几条 × (几条 - 1) ÷ 2`。式子里有乘有减有除，写起来啰嗦，看的人也抓不住重点 —— **重点只有一个：n 变大时，圈数涨得多快。**

本喵换一个更好看的式子来演这件事：

```python
def 圈数(n):
    return 3 * n * n + 5 * n + 7

for n in (10, 100, 1000):
    print(n, "条鱼干，一共", 圈数(n), "圈")
```

```text
10 条鱼干，一共 357 圈
100 条鱼干，一共 30507 圈
1000 条鱼干，一共 3005007 圈
```

看这三行：n 从 10 涨到 100（**10 倍**），圈数从 357 涨到 30507（**85 倍**）；n 再从 100 涨到 1000（**10 倍**），圈数从 30507 涨到 3005007（**98 倍**）。越来越贴近「100 倍」—— 也就是 **n 乘 n 那一档**。

所以这个式子里的东西，该扔的扔掉：

- `3 * n * n` 是**涨得最快的那一项**，留着；
- 前面的 `3` 是**常数**，丢掉 —— 它只让圈数整体大一点，不改涨法；
- `5 * n` 和 `7` 涨得太慢，n 一大就被淹没（n 是 1000 时，`n * n` 有三百万，`5 * n` 才五千），也丢掉。

留下来的就是 **`O(n * n)`**，读作「大 O 的 n 平方」。规矩三条：

1. **只留涨得最快的那一项**；
2. **常数不要**（`3 * n * n` 就写成 `n * n`）；
3. **大 O 说的是上界和增长趋势，不是精确圈数。** 说 `O(n * n)` 不是说你这段程序正好跑 n 乘 n 圈 —— 而是说 n 涨的时候，圈数**最多按这个量级往上长**。上面那个式子实际跑出来是 3005007 圈，标成 `O(n * n)` 一点没错。

把这句话记牢，五个常见量级就好认了：

- `O(1)`：**一次就完事** —— 报个编号直接取那一格；
- `O(log n)`：**折半着来** —— 每砍一次剩一半，1024 条也只要 10 圈；
- `O(n)`：**挨着过一遍** —— 有几条就几圈；
- `O(n log n)`：**折半着排排坐** —— 每层要把 n 条各过一遍，一共 log n 层；
- `O(n * n)`：**两两来** —— 每一条都跟别的握一次手。

## 四、常见量级对照

| 量级 | 一眼认出来的写法 | n = 1024 时要几圈 | n 翻一倍会怎样 |
|---|---|---|---|
| `O(1)` | 报编号直接取：`一排碗[0]` | 1 圈 | 一动不动 |
| `O(log n)` | 一层层折半：`while 宽 < 几条: 宽 = 宽 * 2` | 10 圈 | 只多 1 圈 |
| `O(n)` | 挨着过一遍：`for 批号 in 一排碗:` | 1024 圈 | 翻一倍 |
| `O(n log n)` | 折半着排排坐：`sorted(一排碗)` | 10240 圈 | 略多于一倍 |
| `O(n * n)` | 两两来：内外两个 `for` | 523776 圈 | 翻四倍 |

表格里第三列那两个熟悉的脸 —— **10240 和 523776**，正是第二节里本喵真跑出来的两个数。而 `O(log n)` 那一行要特别记住：**n 翻一倍，它只多 1 圈**。1024 条要 10 圈，2048 条要 11 圈，一百万条也才 20 圈 —— 这就是折半的厉害之处。

::: warn 小心喵
**「能跑通」和「跑得起」是两件事。** 同一道题，`O(n * n)` 的写法在 100 条数据上你根本感觉不到；到了 100 万条，它就卡在那里不动了 —— 而它**不会报错**，屏幕上什么提示都没有，你只会觉得「今天电脑有点慢」。往后写完一段程序，顺手估一下它在表里属于哪一档，是个很值钱的习惯喵。
:::

## 五、最好、最坏、平均：同一个写法也可能差很多

「查一个批号在这排鱼干里有没有」，一排碗要翻几格？**看运气**：

- **最好的情况**：要找的那条正好排在第 0 格 → 1 圈就撞上，收工；
- **最坏的情况**：不在这一排里（或者压在最后） → 1024 格全得翻一遍 → 1024 圈；
- **平均**：大致是一半 → 512 圈上下。

大 O 记号报的是**最坏那一头**（也就是上界）—— 说「一排碗里查批号是 `O(n)`」，意思是**不管运气多坏，圈数也涨不过 n 这个量级**。

第二节那个两两比的程序属于另一种脾气：**它完全不挑运气**，不管鱼干进来是什么顺序，都是 1023 + 1022 + … 一圈不少地走完。会挑运气的写法（撞上就收工那种）才需要把最好、最坏、平均分开说。

## 六、Python 的抓手：换个容器，量级就变了

上一节说「一排碗里查批号最坏要 n 圈」。可 Python 里还有两样东西：**小兜**（`set`）和**字典**（`dict`）。

查它们**根本不用挨着翻**：翻译官喵算一下批号的指纹，直接跳到那一格去看 —— 平均一次就够。

本喵真数过。数法是：给每条鱼干配一本小账，**每次「比一下」就记一笔**：

```python
class 鱼干:
    比了几次 = 0

    def __init__(self, 批号):
        self.批号 = 批号

    def __hash__(self):
        return hash(self.批号)

    def __eq__(self, 别的):
        鱼干.比了几次 = 鱼干.比了几次 + 1
        return self.批号 == 别的.批号


n = 1000
一排碗 = [鱼干(i) for i in range(n)]
小兜 = set(一排碗)

鱼干.比了几次 = 0
鱼干(n + 999) in 一排碗
print("查一个不在册的批号 —— 一排碗：比了", 鱼干.比了几次, "次")

鱼干.比了几次 = 0
鱼干(n + 999) in 小兜
print("查一个不在册的批号 —— 小兜：比了", 鱼干.比了几次, "次")

鱼干.比了几次 = 0
鱼干(7) in 一排碗
print("查一个在册的批号 —— 一排碗：比了", 鱼干.比了几次, "次")

鱼干.比了几次 = 0
鱼干(7) in 小兜
print("查一个在册的批号 —— 小兜：比了", 鱼干.比了几次, "次")
```

```text
查一个不在册的批号 —— 一排碗：比了 1000 次
查一个不在册的批号 —— 小兜：比了 0 次
查一个在册的批号 —— 一排碗：比了 8 次
查一个在册的批号 —— 小兜：比了 1 次
```

四行看下来：

- **小兜那行是 0 次** —— 不是本喵数错了。小兜压根不「比」，它算完指纹跳到那一格，发现是个空格子，掉头就走 → 找不着也不费一下；
- **一排碗那两行是 1000 次和 8 次** —— 它老老实实从头一格一格翻。不在册的那条，1000 格全翻完了才知道「没有」；在册的第 7 号，翻到第 8 格才撞上；
- 换成大 O 记号：**一排碗是 `O(n)`（数据越多翻得越久），小兜是 `O(1)`（几条都一样快）**。

同一件事、同一批鱼干，**只是换了个容器**，量级就整整差了一档 —— 这是 Python 里最值得记的一条「顺手提速」。

::: tip 猫咪提示
小兜有个脾气要记住：**一边绕圈一边往兜里塞新的**，翻译官喵会当场拦住你：

```python
见过 = {1, 2, 3}
for 批号 in 见过:
    见过.add(批号 + 10)
print("装完了", len(见过))
```

```text
Traceback (most recent call last):
    for 批号 in 见过:
RuntimeError: Set changed size during iteration
```

最后那行原话的意思是「**绕圈绕到一半，这兜的格数变了**」。它不让这么干是有道理的：兜里格子一改，接下来该翻哪一格就说不清了。想改也不难 —— **先记下要加的东西，绕完圈再一起塞进去**：

```python
见过 = {1, 2, 3}
新的 = set()
for 批号 in 见过:
    新的.add(批号 + 10)
见过 = 见过 | 新的
print("装完了", len(见过), sorted(见过))
```

```text
装完了 6 [1, 2, 3, 11, 12, 13]
```
:::

顺带说一句 `sorted()`：它是 Python 自带的排排坐招式，属于 **`O(n log n)`** 那一档（就是「折半合起来」那一类，第二节那个 10240 正是这个量级）。它内部到底怎么排的，`python-stage3-20 排序与查找` 那一课会拆开讲。

::: tip 猫咪提示
今天收五句话：

1. **量代价的尺子是圈数（操作次数），不是秒** —— 圈数换台机器也一样，秒数会晃。
2. **数圈数就是数最里面那一圈转了几次**：两两比是 523776，折半合起来是 10240。
3. **大 O 只留涨得最快的那一项、常数不要**，而且它说的是**增长趋势（上界）**，不是精确圈数。
4. **n 翻一倍时看圈数**：`O(1)` 不动、`O(log n)` 只多 1 圈、`O(n)` 翻倍、`O(n * n)` 翻四倍。
5. **换个容器量级就会变**：一排碗（`list`）查是 `O(n)`，小兜（`set`）和字典（`dict`）查是 `O(1)`。
:::

## 小任务

1. 把第二节「两两比」那段程序里的 `几条 = 1024` 改成 `2048`，**先猜**圈数会涨成几倍（猜完写下来），再真跑一遍对照。想清楚为什么是「四倍」而不是「两倍」喵。
2. 把第六节那个「一边绕圈一边往兜里塞」的坏例子改成「先记下来、绕完再塞」，真跑通它 —— 参考写法就在旁边的提示框里，但先自己试一遍再对照。
3. 挑一段你自己写过的程序，估一下它大概要跑多少圈，再看看它在第四节那张表里属于哪一档。有没有可能顺手换个容器，就把它从一档挪到另一档？
4. 用 `time.perf_counter()` 给「两两比」和「折半合起来」各掐一次表，再和它们各自的圈数摆在一起看：**圈数的比值和秒数的比值，是不是差不多？** 要是差得很远，想想差在哪儿。

这一课先把「量代价」这把尺子收进工具箱 —— 从今往后每写一段程序，本喵都会顺手拿它量一量：**这件事要跑多少圈？** 量得多了，你一眼就能看出哪段写法会在数据变多的时候先趴下喵～ 🐾
