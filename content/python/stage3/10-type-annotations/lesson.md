## 钩子：本喵在储物柜门口挂了小木牌

本喵的窝里有一排储物柜，每一格塞一样东西。本喵怕日后忘了哪格装什么，就在每扇柜门旁边**钉了一块小木牌**：这块写「整数」，那块写「一串字」。

后来本喵发现一件怪事：木牌钉得再认真，**往里塞东西的时候压根没有猫抬头看它**。本喵扛了一大袋小鱼干，塞进写着「整数」的那一格 —— 柜门照开，小鱼干照进，一声不吭。

Python 里的**类型注解**，就是这块小木牌喵。

## 注解：名字旁边那块小木牌

先看最省事的样子：

```python
名字: str = "咪爱"
年龄: int = 3
print(名字)
print(年龄)
```

```text
咪爱
3
```

一行一行拆开看：

- **`名字`** —— 小木牌下面那个「小鱼干仓库」的名字。往后按名字喊一声，东西就出来。
- **`: str`** —— **冒号后面这一段，就是木牌**。`str` 的意思是「这里装的是一串字」；写成 `int` 就是说「装的是整数」。
- **`= "咪爱"`** —— **真正塞进去的东西**，等号后面才是货。
- 所以这一行的读法是：「`名字` 这个仓库，**木牌上写着** `str`，**实际装着** `"咪爱"`。」

招式（技能）上也能挂，而且能挂两块：

```python
def 打招呼(名字: str, 次数: int) -> str:
    return 名字 * 次数


print(打招呼("喵", 3))
```

```text
喵喵喵
```

- **投喂口里那几样东西**后面的 `: str`、`: int` —— 两块木牌，说「喂进来的应该分别是一串字和一个整数」。
- **箭头 `-> str`** —— 又一块木牌，挂在**叼回来的战利品**上，说「这招干完活叼回来的是一串字」。
- 中间那句 `return` 的活照老规矩写，木牌一个字都不改它的跑法。

## 头号大事：木牌上写什么，跑起来都不看

现在轮到今天最要紧的一条。本喵故意把木牌写歪：

```python
年龄: int = "本喵三岁啦"
print(年龄)
print(type(年龄))
```

```text
本喵三岁啦
<class 'str'>
```

木牌上明明写着 `int`（整数），塞进去的却是一串字 —— 它**照跑不误**，还老老实实把那串字印了出来。本喵再翻出 `type()` 一验：后面那行印出来的意思是「这东西是一串字」，一个字都没变过。

**这条是今天的头号大事，千万别记反：注解在跑的时候，没有任何猫去看它。** 它不是命令，不是关卡，也不是什么「送货前先验一遍」的规矩 —— 它就是一块钉上去之后**没人管**的小木牌。

所以下面这句听着顺口的话，其实是**错的**：

> ~~「我把木牌写对了，所以这段程序一定不会出错。」~~

错在哪？木牌拦不住任何东西。写对写错，程序照跑喵。

## 木牌不产生东西

木牌还有个脾气，本喵第一次撞见时也愣了一下：

```python
价格: int
print(__annotations__)
print(价格)
```

```text
{'价格': <class 'int'>}
Traceback (most recent call last):
    print(价格)
NameError: name '价格' is not defined
```

第一行**只有名字和木牌、没有等号**，这在 Python 里完全合法：本喵可以把「这里往后会装一个整数」先记上一笔。可它**不会凭空生出一个小鱼干仓库**：

- 第二行读出来的那张清单说明，这一笔**真真切切记下了**（清单长什么样，下面马上讲）。
- 第三行真去取 `价格` —— 当场被甩了一句 `NameError: name '价格' is not defined`，意思是「压根没有叫这个名字的东西」。

**一句话：木牌的活是「记一笔」，不是「造一个」。** 想有东西，等号后面还得给货喵。

## 木牌是一份能读出来的数据

别把木牌当成「只有本喵自己才看的备注」。它真真切切是程序里的一份数据，**随时能读出来**：

```python
名字: str = "咪爱"
年龄: int = 3
print(__annotations__)
```

```text
{'名字': <class 'str'>, '年龄': <class 'int'>}
```

`__annotations__` 就是「这个东西身上所有的木牌」那张清单：**名字连着木牌上写的类型**，一件一条，前后顺序就是挂木牌的顺序。

有一处要盯仔细：清单里后半截**不是一串字，而是那个类型本身**（它印出来长什么样，上面那一行里看得见）。这一点很关键 —— 拿到的不是「写着 str 的一张纸」，是 `str` 这个东西喵。

## 招式上的木牌：多一格叫 `'return'`

招式上的木牌一样能读：

```python
def 打招呼(名字: str, 次数: int) -> str:
    return 名字 * 次数


print(打招呼("喵", 3))
print(打招呼.__annotations__)
```

```text
喵喵喵
{'名字': <class 'str'>, '次数': <class 'int'>, 'return': <class 'str'>}
```

清单里出现了三格：投喂口那两样各一格，**箭头后面那块木牌挂在 `'return'` 这个名目下** —— 那就是「叼回来的战利品」的那一块。名字是 `return` 不是别的，是 Python 定下的写法，照记就行喵。

## `get_type_hints`：照着木牌上的名字去认领

木牌上的类型，有时候是**用引号包起来**写成的 —— 写成一串字，而不是那个类型本身：

```python
from typing import get_type_hints


def 打招呼(名字: "str", 次数: "int") -> "str":
    return 名字 * 次数


print(打招呼.__annotations__)
print(get_type_hints(打招呼))
```

```text
{'名字': 'str', '次数': 'int', 'return': 'str'}
{'名字': <class 'str'>, '次数': <class 'int'>, 'return': <class 'str'>}
```

两行摆在一起，一眼就看明白了：

- **第一行是原样照抄**：木牌上写的是**引号包着的一串字**，读出来就还是那串字（`'str'` 连引号一起）。
- **第二行是 `get_type_hints` 干完活的样子**：它拿着木牌上写的那几个名字，**照着名字去找了一遍**，把 `'str'` 认领成了 `str` 这个东西本身。

所以这两个工具的分工很好记：**`__annotations__` 是原样照抄，`get_type_hints()` 是照着名字认领。** 引号包着写的那种木牌，别指望 `__annotations__` 替你换成真东西。

## 图纸上的木牌也能读：`fields()` 里的 `.type`

本喵前面几课画过图纸（猫猫图纸）、给图纸头顶贴过一层特效，那时候每件东西写成 `名字: str` 这种样子。今天回头看，那一行行**原来全是木牌**：

```python
from dataclasses import dataclass, fields


@dataclass
class 猫档案:
    名字: str
    年龄: int


for f in fields(猫档案):
    print(f.name, f.type)
```

```text
名字 <class 'str'>
年龄 <class 'int'>
```

`fields(猫档案)` 把图纸上每一件东西**挨个**交出来，每一样身上都带着两样：

- **`f.name`** —— 那块名牌的名字。
- **`f.type`** —— 名牌后面那张**木牌上写的类型**。

今天新知道的一件事：图纸里那些木牌**不是死的**，谁来读都读得出来。往后本喵要写的「把档案存进文件、再原样读回来」那种活，靠的正是这个本事喵。

## 一筐整数：新写法 `list[int]` 和老写法 `List[int]`

木牌上不止能写 `int`、`str` 这种「一样东西」的类型，还能写**装东西的家伙**。要写明「这一筐装的全是整数」，两种写法：

- **新写法**：`list[int]` —— 直接拿 `list` 后面跟一对方括号。**Python 3.9 起**就能这么写，不用请任何帮手。
- **老写法**：`List[int]` —— 得先在稿子最上面 `from typing import List`，把 `List` 请出来。老代码里到处都是它。

两种写法**说的是同一个意思**：一筐整数。怎么证明它们是一回事？看它们的「里子」：

```python
from typing import List, get_args, get_origin

print(get_origin(list[int]), get_args(list[int]))
print(get_origin(List[int]), get_args(List[int]))
print(get_origin(list[int]) is get_origin(List[int]))
```

```text
<class 'list'> (<class 'int'>,)
<class 'list'> (<class 'int'>,)
True
```

- **`get_origin(某种写法)`** 看它的**底**是什么。两种写法取出来都是 `list`（一筐）。
- **`get_args(某种写法)`** 看里面**装的是什么**。两种写法取出来都是 `int`（整数）。
- 最后那行 `True`：两边的底是**同一个东西**。

::: warn 小心喵
**别拿 `==` 去比 `list[int]` 和 `List[int]`。** 本喵亲手试过：直接比会得到 `False` —— 它们**不是同一个东西**，只是**两块说了同一句话的木牌**。想验「这俩是不是一个意思」，看上面的**底**（`get_origin`）和**装的东西**（`get_args`），别用 `==` 喵。
:::

## 静态检查：跑之前先把稿子念一遍

到这里，最别扭的一件事浮出来了：**木牌在跑的时候没人看**，那写它干嘛？

因为世上还有一种工具：它**根本不跑**你的程序，只把稿子（源码）从头到尾读一遍。它读木牌上写了什么，也读你把什么东西塞进了哪里，然后把对不上的地方指给你。这一种活法有个名字，叫**静态检查** —— 「静态」说的就是**站着不动**：一次都不执行，光念稿子。

先看**没有它**时会怎样。本喵把前面那个例子搬过来：

```python
def 打招呼(名字: str) -> str:
    return "本喵是" + 名字


print(打招呼(3))
```

```text
Traceback (most recent call last):
    print(打招呼(3))
    return "本喵是" + 名字
TypeError: can only concatenate str (not "int") to str
```

木牌上写着「喂进来的应该是一串字」，本喵偏喂了一个整数 `3`。

- **喂进去那一下，它一声不吭** —— 木牌拦不住，这点前面讲过。
- 一直等到**真拿这个整数去跟字拼在一起**的那一刻（`"本喵是" + 名字`），它才炸：最后那句 `TypeError` 的意思是「字只能跟字拼，你给的这个是整数」。这就是**跑到那一步才知道**的检查，本喵叫它**运行时检查**。

而**静态检查器**干的是另一件事：**不执行**，只读稿子，读到 `打招呼(3)` 这一处就说话了 ——「木牌上写的是 `str`，你塞进去的是个整数，对不上」。它最出名的那只叫 **`mypy`**。

::: warn 小心喵
**这台机器上没有装 `mypy`**，所以本喵今天**只讲思路，不带你真跑它**。别去课文里找「跑一遍看看报什么」那种例子 —— 它跑不起来。你今天要学会的是三件事：它**是什么**、**为什么有用**、跟运行时报错**怎么分工**喵。
:::

### 为什么值得写木牌

静态检查器能看出来的，正是刚说的那一处：稿子上写着 `名字: str`，你却调了 `打招呼(3)`。**它能在你按下运行之前**就把这一处指给你看，而 Python 要等到真跑、真撞上那一步，才甩出那张 `TypeError`。

它读不出来的也有：木牌写没写、写歪没写歪它都在看，可货要是从别处来（比如学员敲进来的东西），它只能照着木牌信你。

### 两套检查怎么分工

| | 谁在说话 | 什么时候说 | 说的是什么 |
|---|---|---|---|
| **静态检查** | 静态检查器（如 `mypy`） | **还没跑**，只念稿子的时候 | 「这一处木牌和实际用法对不上」——它先替你挑出来 |
| **运行时检查** | Python 自己（真跑起来的那一趟） | **真跑、真用到**的那一刻 | 真出事时的 `TypeError` 之类 |

两套不是「谁替代谁」：**静态那套来得早、扫得广**，可它只能看见稿子上写着的东西；**运行时那套来得晚**，可它说的是板上钉钉的真事。所以木牌写得越全、越准，静态那套能替你提前挑出来的就越多。

### 写全木牌的四样好处

1. **出错的活提前干** —— 不用等真跑到那一步才炸，念稿子的时候就能被指出来。
2. **木牌本身就是说明** —— 别人（还有三个月后的你）打开这个文件，看一眼招式上的木牌，就知道该喂什么、会叼回来什么，不用把整段读完。
3. **别的工具也能帮上忙** —— 编辑器之类的工具能照着木牌给你提示、替你补全。
4. **便宜** —— 它只在你自己机器上念稿子，不用上线、不用真跑。

::: tip 猫咪提示
- **注解 = 名字旁边钉的小木牌**：`: 类型` 是木牌，箭头 `-> 类型` 是挂在 `'return'` 上的那块。
- **跑的时候没有猫看木牌**：`年龄: int = "本喵三岁啦"` 照跑不误 —— 这条最要紧。
- **木牌只记一笔、不造东西**：`价格: int` 之后去取 `价格`，照样说没有这个名字。
- **木牌是能读出来的数据**：`__annotations__`（原样照抄）、`get_type_hints()`（照着名字认领）、图纸上每件东西的 `.type`。
- **一筐整数两种写法**：`list[int]`（新，不用帮手）和 `List[int]`（老，要先请 `List`），说的是同一个意思。
- **静态检查 = 不跑、只念稿子**，`mypy` 是最有名的那只；它和运行时报错**分工**，谁也不替谁。
:::

## 一句话对照表

| 写下的这一句 | 它干了什么 |
|---|---|
| `名字: str = "咪爱"` | 钉木牌 + 塞东西（木牌跑的时候没人看） |
| `价格: int` | 只钉木牌，不给货 —— 不产生仓库 |
| `def 打招呼(名字: str) -> str:` | 投喂口钉木牌，箭头那块挂在 `'return'` 上 |
| `__annotations__` | **原样**读出这个文件 / 招式 / 图纸上所有的木牌 |
| `get_type_hints(打招呼)` | 照着木牌上的名字去**认领**，把一串字换成真东西 |
| `fields(猫档案)` 里每一样的 `.type` | 图纸上每件东西的那块木牌 |
| `list[int]` / `List[int]` | 一筐整数：新写法 / 要先请帮手的写法 |
| `get_origin(...)` / `get_args(...)` | 看某种写法的「底」和「里面装的东西」 |
| `mypy` | 不跑程序、只念稿子的静态检查器 |

## 小任务

先照着这段敲一遍，把木牌读出来：

```python
from typing import get_type_hints


def 数鱼(一筐: list[int]) -> int:
    return len(一筐)


print(数鱼([1, 2, 3]))
print(get_type_hints(数鱼))
```

```text
3
{'一筐': list[int], 'return': <class 'int'>}
```

**试着改一改**：

1. 把 `一筐: list[int]` 里的 `list[int]` 换成 `List[int]`，记得在稿子最上面补一句 `from typing import List`。跑一遍 —— 最后那行印出来的东西变了吗？再用 `get_origin` 比一比。
2. 故意把木牌写歪：改成 `一筐: str`，别的都不动，再跑一遍。**它会报错吗？**（想一想今天头号大事那句话，再动手验。）
3. 回头翻你自己以前写的某段代码，给每个小鱼干仓库、每招的投喂口都钉上木牌，最后 `print(__annotations__)` 看一眼本喵都记了些什么。

往后你会发现：真正花时间的从来不是写那几行代码，而是**三个月后回头看**——「这一格当年装的是什么来着？」木牌钉在那儿，那个问题就不存在了。而且它是**免费的**：钉上去不用翻译官喵多干一点活，只是让念稿子的那类工具能替本喵先挑一遍毛病。
