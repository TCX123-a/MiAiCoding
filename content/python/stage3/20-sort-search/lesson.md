## 钩子：一摊乱糟糟的小鱼干

本喵的鱼塘边摊着一筐小鱼干：**5、2、9、1、8、6**，长短不一。大肥鱼要本喵把它们**从短到长**摆成一小排，一条一条摆整齐。

摆整齐这件事，术语表里给的正式名字是「给小鱼干排排坐（排序）」—— 括号里那个词，考试卷子上要认识喵。今天一次讲四件事：

1. 三招**憨办法**：挨着比、挑最短、理牌 —— 它们都能把一摊乱的摆整齐，差别藏在「**比了几次、换了几次**」里；
2. 一招**快办法**：折半着来（快排），它比憨办法快一个档；
3. 「在**已经摆好**的一排里翻格」：砍一半（二分查找）—— 它有一个**铁打的前提**，本喵会用真跑演给你看前提破了会怎样；
4. 最后一件最实用的事：Python 自带的那一招是什么来头，什么时候该直接用它。

第 1 课（`python-stage3-16`）本喵真跑出来的两个锚点数字，这一课还会用到：**1024 条小鱼干，「两两比」要 523776 圈，「折半合起来」只要 10240 条**。今天把「折半合起来」拆开看看它到底怎么合的喵。

## 一、冒泡法：挨着比、慢慢挪

第一招最憨，也最好懂：**从第一只开始，挨着的两只比一比** —— 左边那只比右边长，就换个个儿。这样走完一趟，最长的那只一定被一路换到了最末尾。

```python
# 冒泡：挨着的两只比一比，左边比右边长的就换个个儿
一筐 = [5, 2, 9, 1, 8, 6]
几条 = len(一筐)

for 第一 in range(几条 - 1):
    for 第二 in range(几条 - 1 - 第一):
        if 一筐[第二] > 一筐[第二 + 1]:
            一筐[第二], 一筐[第二 + 1] = 一筐[第二 + 1], 一筐[第二]

print("排排坐：" + " ".join(str(只) for 只 in 一筐))
```

```text
排排坐：1 2 5 6 8 9
```

三句要念清楚喵：

1. **外层那一圈管「走几趟」**：一趟只能把一只送到它该在的位子上，所以最多走 `几条 - 1` 趟。
2. **内层那一圈管「这一趟里比到哪儿」**：写的是 `几条 - 1 - 第一`。那个 `- 第一` 是因为**末尾的那几只已经站好了**，不用再比。
3. **Python 里换位子一句话就够**：`一筐[第二], 一筐[第二 + 1] = 一筐[第二 + 1], 一筐[第二]`。等号右边两只**先一起算好**，再一起放回去，所以不用另外找一只爪子捧着。

下面把**第一趟**一格一格走一遍。盯着「这排鱼干」那一栏，它每一步都是当前真实的摊位；再看右边那本小账：这一趟比了几次、换了几个、末尾站好了几只。

### 内层那一圈，写到哪儿为止

上面那个 `- 第一` 看着不起眼，可它是这一招**唯一一处容易写坏的地方**。要是把它整个删掉、让内层每趟都从 0 号格比到最后一格，会发生什么？本喵真跑了：

```python
一筐 = [5, 2, 9, 1, 8, 6]
几条 = len(一筐)

for 第一 in range(几条 - 1):
    for 第二 in range(几条):
        if 一筐[第二] > 一筐[第二 + 1]:
            一筐[第二], 一筐[第二 + 1] = 一筐[第二 + 1], 一筐[第二]

print("排排坐：", 一筐)
```

```text
Traceback (most recent call last):
    if 一筐[第二] > 一筐[第二 + 1]:
IndexError: list index out of range
```

最后那行原话的意思是「**报回来的格号超出这一排的范围了**」。毛病出在 `一筐[第二 + 1]` 上：`第二` 走到最后一格（5 号格）的时候，它右边那只 `一筐[6]` 压根不存在 —— 这一排只到 0~5 号格。

::: warn 小心喵
**「- 第一」不只是省几次比较，它还管着别伸手伸到摊子外面。** 内层的上限永远要比「剩下的格数」小一格，因为要读 `一筐[第二 + 1]`。

Python 比 C 还多一层脾气：**它是从 0 号格开始数的，可它认负数**。写成 `一筐[-1]` 不报错，它绕到末尾去读最后一只。所以有些越界的写法在 Python 里**不会当场断气**，只是安安静静读错一格——本喵这一节第四部分就会撞上一个长得一模一样的哑巴坑喵。
:::

## 二、三招的差别：比了几次、换了几次

第二招换个思路：**每一轮先扫一遍，挑出剩下的里面最短的那只**，请它和最前面那只换个位子。一轮只换一次，但一轮能定下一只 —— 叫它**挑最短法**。

第三招最像本喵理牌：手里已经理好一小叠，新摸起一张就从后往前比，比它长的都往后挪一格，腾出来的位子就是它的。第一张牌不用理，所以从第二张开始 —— 叫它**理牌法**。

三招到底差在哪儿？光看名字看不出来，得拿小账本数。本喵给每一招都配了两个计数器：**比一下记一笔、换（或者挪）一次记一笔**：

```python
# 三种排法，各配一本小账：比一下记一笔，换/挪一次记一笔
def 冒泡(进来):
    一筐 = list(进来)
    比 = 0
    换 = 0
    几条 = len(一筐)
    for 第一 in range(几条 - 1):
        for 第二 in range(几条 - 1 - 第一):
            比 = 比 + 1
            if 一筐[第二] > 一筐[第二 + 1]:
                一筐[第二], 一筐[第二 + 1] = 一筐[第二 + 1], 一筐[第二]
                换 = 换 + 1
    return 一筐, 比, 换


def 挑最短(进来):
    一筐 = list(进来)
    比 = 0
    换 = 0
    几条 = len(一筐)
    for 第一 in range(几条 - 1):
        最短 = 第一
        for 第二 in range(第一 + 1, 几条):
            比 = 比 + 1
            if 一筐[第二] < 一筐[最短]:
                最短 = 第二
        if 最短 != 第一:
            一筐[第一], 一筐[最短] = 一筐[最短], 一筐[第一]
            换 = 换 + 1
    return 一筐, 比, 换


def 理牌(进来):
    一筐 = list(进来)
    比 = 0
    挪 = 0
    几条 = len(一筐)
    for 第一 in range(1, 几条):
        拿着 = 一筐[第一]
        第二 = 第一 - 1
        while 第二 >= 0:
            比 = 比 + 1
            if 一筐[第二] > 拿着:
                一筐[第二 + 1] = 一筐[第二]
                挪 = 挪 + 1
                第二 = 第二 - 1
            else:
                break
        一筐[第二 + 1] = 拿着
    return 一筐, 比, 挪


原始的 = [5, 2, 9, 1, 8, 6]
摊子们 = [("本来就已经排好", [1, 2, 5, 6, 8, 9]),
          ("完全倒着摆", [9, 8, 6, 5, 2, 1]),
          ("一开始是乱的", 原始的)]

for 名字, 一摊 in 摊子们:
    甲 = 冒泡(一摊)
    乙 = 挑最短(一摊)
    丙 = 理牌(一摊)
    print(f"{名字}：冒泡 比 {甲[1]} 次 / 换 {甲[2]} 次；"
          f"挑最短 比 {乙[1]} 次 / 换 {乙[2]} 次；"
          f"理牌 比 {丙[1]} 次 / 挪 {丙[2]} 次")
print("三招排出来都一样吗：", 甲[0] == 乙[0] == 丙[0] == sorted(原始的))
```

三行数字，把三招的脾气全说出来了喵：

| 摊子长什么样 | 冒泡（比 / 换） | 挑最短（比 / 换） | 理牌（比 / 挪） |
|---|---|---|---|
| 本来就已经排好 | 15 / 0 | 15 / 0 | **5** / 0 |
| 完全倒着摆 | 15 / 15 | 15 / **3** | 15 / 15 |
| 一开始是乱的 | 15 / 7 | 15 / 3 | 10 / 7 |

- **比一比的次数，三招其实差不多**：都是 5 + 4 + 3 + 2 + 1 = 15 那一类的形状 —— 也就是**两两来**那一档（第 1 课的 523776 就是它的真身）。理牌在「已经排好」和「乱的」两种摊子上更省比较（5 次、10 次），但**倒着摆的时候它也得比 15 次**，一次都省不下来。
- **换位子的次数差得就远了**：完全倒着摆时，冒泡换了 15 次、理牌挪了 15 次，而**挑最短只换 3 次**。要是一只鱼干特别沉、搬起来费劲，「比一比很便宜、搬一次很贵」，那挑最短就划算了。
- **理牌法专治「摊子本来就差不多整齐」**：已经排好的六只，它只比了 5 次（每摸起一张，只需要跟前面比一次就发现不用动）—— 另两招还在老老实实走满 15 次。

::: tip 猫咪提示
三招各记一句话喵：**冒泡**是「挨着比、慢慢挪」；**挑最短**是「每轮选冠军、只换一次」；**理牌**是「摸一张、往前插」。

还有一句更要紧的：**「哪一招最好」这个问题，得先问「你的鱼干长什么样」。** 倒着摆的摊子上，「理牌最慢」这话就是不成立的 —— 它跟冒泡一样费爪子，省爪子的是挑最短。数据的样子，决定了该喊哪一招。
:::

## 三、折半着来：比两两比快一个档

三招憨办法有个共同的脾气：**都比了 15 次上下**，也就是「两两来」那一档。第 1 课本喵数过，1024 条鱼干两两比要 **523776 圈**。现在看另一种路子：**折半着来**。

它的规矩是：先把一筐**一层层折半**分开，再**一层层合起来** —— 合的时候两条一对比，短的先放进新筐。这就是本喵第 1 课真跑过的「折半合起来」。第 1 课数的是它**搬了几条**（10240），这一课再补一件事：本喵自己写的**快排**（拿末尾那只当尺子，比它短的往左推、比它长的留下，然后左右两半各自再这么来一遍）到底比了几次。

```python
import random

random.seed(20260920)
几条 = 1024
一筐 = list(range(几条))
random.shuffle(一筐)


def 两两比(进来):
    比 = 0
    for 第一 in range(len(进来)):
        for 第二 in range(第一 + 1, len(进来)):
            比 = 比 + 1
    return 比


def 折半合起来(进来):
    一筐 = list(进来)
    搬 = 0
    半宽 = 1
    while 半宽 < len(一筐):
        新筐 = []
        for 起 in range(0, len(一筐), 半宽 * 2):
            左 = 一筐[起:起 + 半宽]
            右 = 一筐[起 + 半宽:起 + 半宽 * 2]
            i = 0
            j = 0
            while i < len(左) or j < len(右):
                if j >= len(右) or (i < len(左) and 左[i] <= 右[j]):
                    新筐.append(左[i])
                    i = i + 1
                else:
                    新筐.append(右[j])
                    j = j + 1
                搬 = 搬 + 1
        一筐 = 新筐
        半宽 = 半宽 * 2
    return 一筐, 搬


def 快排(进来):
    一筐 = list(进来)
    账 = [0]

    def 排(左, 右):
        if 左 >= 右:
            return
        哨 = 一筐[右]
        小 = 左
        for k in range(左, 右):
            账[0] = 账[0] + 1
            if 一筐[k] < 哨:
                一筐[k], 一筐[小] = 一筐[小], 一筐[k]
                小 = 小 + 1
        一筐[小], 一筐[右] = 一筐[右], 一筐[小]
        排(左, 小 - 1)
        排(小 + 1, 右)

    排(0, len(一筐) - 1)
    return 一筐, 账[0]


print("1024 条小鱼干排排坐，三条路各花多少力气：")
print("两两比一共绕了", 两两比(一筐), "圈")
print("折半合起来一共搬了", 折半合起来(一筐)[1], "条")
print("快排一共比了", 快排(一筐)[1], "次")
print("三条路排出来的都一样吗：", 折半合起来(一筐)[0] == sorted(一筐), 快排(一筐)[0] == sorted(一筐))
```

```text
1024 条小鱼干排排坐，三条路各花多少力气：
两两比一共绕了 523776 圈
折半合起来一共搬了 10240 条
快排一共比了 10541 次
三条路排出来的都一样吗： True True
```

三条路，同样的 1024 条鱼干：

- **两两比 523776 圈** —— 憨办法那一档；
- **折半合起来 10240 条** —— 折半那一档（1024 是 2 的 10 次方，正好折 10 层，每层把 1024 条各搬一遍）；
- **快排 10541 次** —— 跟 10240 一个量级，比 523776 少了 50 倍。

快排为什么快？因为它**每一轮挑一个尺子（哨），把整筐分成「比它短的」和「比它长的」两堆**，然后两堆各自再这么来一遍。每一轮要把当下这一堆整个过一遍（n 次比较），而堆数一层层折半，所以一共大约 `n × 层数` 次 —— 跟上一条「折半合起来」是同一个量级：**`O(n log n)`**。

::: warn 小心喵
快排的「快」**全靠那把尺子挑得好**。本喵拿 256 只小鱼干真试过一次：乱的一摊，快排比了 **1820 次**；可要是这一摊**本来就排好了**，而尺子又偏偏取最末尾那一格，它每轮切出来的两堆里有一堆永远是空的 —— 量级当场掉回去，比出 **32640 次**，正好是 256 × 255 ÷ 2，**跟两两比一模一样**。数据的样子，连「快排」都躲不过。

所以真要排一筐东西，别自己写。往下看第五节：Python 自带的那一招到底是怎么写的喵。
:::

## 四、在一排已经摆好的东西里翻格

### 挨着看 vs 砍一半

鱼塘边摆着一排贴着编号的小碗，编号从小到大：1、3、5、7、9、11、13。本喵要找 13 那一只。最憨的找法是**从第一只挨着看到最后一只**。另一种找法叫**砍一半**（二分查找）：

**先看正中间那一只** —— 中间那只比要找的小，那它左边那些只会更小，整半边砍掉；中间那只比要找的大，那就砍右边。每比一次，有一半的格子被排除掉。

```python
def 挨着看(一筐, 要找的):
    比 = 0
    for 一只 in 一筐:
        比 = 比 + 1
        if 一只 == 要找的:
            return 比
    return -比


def 砍一半(一筐, 要找的):
    头 = 0
    尾 = len(一筐) - 1
    比 = 0
    while 头 <= 尾:
        中 = (头 + 尾) // 2
        比 = 比 + 1
        if 一筐[中] == 要找的:
            return 比
        elif 一筐[中] < 要找的:
            头 = 中 + 1
        else:
            尾 = 中 - 1
    return -比


七只 = [1, 3, 5, 7, 9, 11, 13]

    print(f"找 {要找的}：{甲的话}，{乙的话}")

一千只 = list(range(1024))
print(f"换成 1024 只、找最后那一只：挨着看 {abs(挨着看(一千只, 1023))} 次，砍一半 {abs(砍一半(一千只, 1023))} 次")
```

### 前提：这一排必须已经摆好

砍一半有个**铁打的前提**：这一排必须已经从短到长（或者从长到短）摆好。这不是客气话 —— 本喵真跑了一次，把同一批鱼干**乱摆**着就喊砍一半：

```python
def 砍一半(一筐, 要找的):
    头 = 0
    尾 = len(一筐) - 1
    while 头 <= 尾:
        中 = (头 + 尾) // 2
        if 一筐[中] == 要找的:
            return 中
        elif 一筐[中] < 要找的:
            头 = 中 + 1
        else:
            尾 = 中 - 1
    return -1


乱摆的 = [13, 1, 5, 7, 9, 11, 3]
print("乱摆着找 3：报回来的格号是", 砍一半(乱摆的, 3))
print("先排好再找 3：报回来的格号是", 砍一半(sorted(乱摆的), 3))
print("两遍都没报错，一遍找着了，一遍没找着")
```

```text
乱摆着找 3：报回来的格号是 -1
先排好再找 3：报回来的格号是 1
两遍都没报错，一遍找着了，一遍没找着
```

看清楚了喵：**3 就躺在这一排里**（最后那一格），可乱摆着砍，程序一口咬定「没有这一只」（-1），而且**它不报错**。你要是没盯着前提，只会以为「这批数据里真的没有 3」。

::: warn 小心喵
**没摆好就砍，结果错而不报错** —— 这就是砍一半最危险的地方。中间那只比要找的大，凭什么断定左边全比要找的大？左半边里完全可能藏着一只。这一砍，就把要找的那只连着半排一起砍掉了，程序的答案还是那么一本正经。

所以规矩只有一条：**先摆好，再砍。** 摆在谁身上？这一课第二节那三招，或者往下看一节 —— Python 自带的那一招。
:::

### `中` 怎么写、边界怎么写：两个真跑出来的坏版本

砍一半看着简单，写起来却有两处经典的坑，都出在**那一段是怎么缩短的**上。本喵把两个坏版本都真跑了给你看。

坏版本一：`while 头 < 尾` —— 把 `<=` 写成 `<`：

```python
一筐 = [1, 3, 5, 7, 9, 11, 13]


def 漏找的砍一半(要找的):
    头 = 0
    尾 = len(一筐) - 1
    比 = 0
    while 头 < 尾:                 # 坏：段里只剩一只时，它就不进圈了
        中 = (头 + 尾) // 2
        比 = 比 + 1
        if 一筐[中] == 要找的:
            return 中, 比
        elif 一筐[中] < 要找的:
            头 = 中 + 1
        else:
            尾 = 中 - 1
    return -1, 比


for 要找的 in (13, 1, 7):
    结果 = 漏找的砍一半(要找的)
    print("找", 要找的, "→ 报回来的格号是", str(结果[0]) + "，比了", 结果[1], "次")
print("可 13 在 6 号格、1 在 0 号格里躺着呢 —— 它没报错，只是老老实实答「没找着」")
```

```text
找 13 → 报回来的格号是 -1，比了 2 次
找 1 → 报回来的格号是 -1，比了 2 次
找 7 → 报回来的格号是 3，比了 1 次
可 13 在 6 号格、1 在 0 号格里躺着呢 —— 它没报错，只是老老实实答「没找着」
```

**13 和 1 都漏掉了**，7 却找着了。为什么？你回头看上面那个演示的第 8 步就懂了：段缩成「头尾都是 6」的时候，**段里还剩最后一只**，那一趟不能省。`头 <= 尾` 问的是「段里还有格子吗」，`头 == 尾` 是**还有**，不是空了。写成 `<` 就等于把「最后一只」那一趟整个丢掉了 —— 而答案偏偏常常就压在最后那一趟上。

坏版本二：`尾 = 中` —— 尾巴忘了往前挪一格：

```python
一筐 = [1, 3, 5, 7, 9, 11, 13]


def 转不停的砍一半(要找的):
    头 = 0
    尾 = len(一筐) - 1
    比 = 0
    while 头 <= 尾 and 比 < 100:    # 那个 100 是本喵自己接的保险丝，只为了让它肯停下来
        中 = (头 + 尾) // 2
        比 = 比 + 1
        if 一筐[中] == 要找的:
            return 中, 比
        elif 一筐[中] < 要找的:
            头 = 中 + 1
        else:
            尾 = 中                # 坏：该写 中 - 1。尾巴不往前挪，这段就再也缩不短了
    return -1, 比


结果 = 转不停的砍一半(6)
print("找 6 → 报回来的格号是", str(结果[0]) + "，已经绕了", 结果[1], "圈")
print("保险丝拔了，它会一直绕下去 —— 不报错，就是不吭声地转")
```

```text
找 6 → 报回来的格号是 -1，已经绕了 100 圈
保险丝拔了，它会一直绕下去 —— 不报错，就是不吭声地转
```

这一版更狠：**它不报错、也不给错答案 —— 它压根不给答案**，就在原地一圈一圈转。本喵那个 `比 < 100` 是**自己接上去的保险丝**（没有它，这段程序会一直跑到被外部掐掉为止）；真写的时候手滑写成 `尾 = 中`，屏幕上就是「程序卡住了」，你连它在哪一行绕都不知道。

::: warn 小心喵
两处边界，各记一句话喵：

- **进圈的判据**：`头 <= 尾`（段里还有格子，一只也算有）；
- **缩短的判据**：`头 = 中 + 1`、`尾 = 中 - 1` —— **两边都要把「中间那一格」让出去**。

中间那一格已经比过了：它要就是答案，早就返回了；它不是答案，留着它也不会改变什么 —— 只会让这一段永远缩不短。**「收手」这件事，必须刻在每一句改 `头`、`尾` 的话里。**
:::

## 五、Python 自带的那一招：先用它

上面三招憨办法、一招快排，Python 里**压根不用你手写** —— `sorted()` 和 `一筐.sort()` 就是干这个的。那你可能会问：它到底快不快？

本喵数过。数法是给每只鱼干挂一本小账，**每被拿去比一次就记一笔**：

```python
import random

random.seed(20260920)
几条 = 1024

class 鱼干:
    比了几次 = 0

    def __init__(self, 批号):
        self.批号 = 批号

    def __lt__(self, 别的):
        鱼干.比了几次 = 鱼干.比了几次 + 1
        return self.批号 < 别的.批号


一筐 = [鱼干(random.randrange(100000)) for _ in range(几条)]
鱼干.比了几次 = 0
排好的 = sorted(一筐)
print("内置的排排坐，比了", 鱼干.比了几次, "次")
print("排好了吗：", [x.批号 for x in 排好的] == sorted(x.批号 for x in 一筐))

# 稳定性：同一把秤上，先后顺序会不会被弄乱
鱼干们 = [("大肥鱼", 3), ("小狸", 1), ("本喵", 3), ("大橘", 1)]
print("按重量排：", [只[0] for 只 in sorted(鱼干们, key=lambda 只: 只[1])])
print("按重量倒着排：", [只[0] for 只 in sorted(鱼干们, key=lambda 只: 只[1], reverse=True)])
print("直接比两只（先按小的，再按名字）：", sorted([(2, "乙"), (1, "甲"), (2, "丙")]))
```

```text
内置的排排坐，比了 8926 次
排好了吗： True
按重量排： ['小狸', '大橘', '大肥鱼', '本喵']
按重量倒着排： ['大肥鱼', '本喵', '小狸', '大橘']
直接比两只（先按小的，再按名字）： [(1, '甲'), (2, '丙'), (2, '乙')]
```

同样 1024 条：两两比 523776 圈、本喵自己写的快排 10541 次、**内置的只要 8926 次**。

它为什么还能更省？因为它叫 **Timsort** —— 它顺手把两种憨办法的长处捡了起来：数据里**本来就一小段一小段排好的地方**（比如上一轮刚产生的新数据、或者从别处拿来的半成品），它会先认出来，再去合并这些小段。第 1 课那个「折半合起来」正是它的下半截。所以：

- **量级上它就是 `O(n log n)` 那一档**，跟折半合起来、快排是同一层；
- **它比手写快排还稳**：快排挑尺子挑坏了会掉回去（第三节那个 32640 次就是），Timsort 不会；
- **它不叫「快排」**。快排是第三节那个自己挑尺子的写法（挑坏了会掉回两两比那一档）；`sorted` 用的是 Timsort，抗造得多。你以后要是跟人聊起来，说「Python 的 `sorted` 就是快排」，那是错的喵。

::: tip 猫咪提示
`sorted()` 顺手还带两件你会天天用到的东西：

1. **`key=`**：排之前先拿每一条算一个「按什么排」的凭据 —— `sorted(鱼干们, key=lambda 只: 只[1])` 就是「按重量排」，比写一整个自己比大小的招式省事得多。
2. **它是稳的**：**两张凭据一样的时候，谁原本站在前面，排完还在前面**。上面那行 `按重量排` 里，大肥鱼和小狸都是 3 号重量，排完大肥鱼还在小狸前面 —— 这就是「稳」。

`reverse=True` 是**倒着比大小**，**不是把正着排的结果整个翻过来**：上面「按重量倒着排」里，同样是 3 号重量的两只，大肥鱼还在小狸前面（它们的先后没被翻）。

再补一句元组的脾气：`sorted([(2,"乙"),(1,"甲"),(2,"丙")])` 排出来是 `(1,"甲")`、`(2,"丙")`、`(2,"乙")` —— **先比第一个，第一个一样就比第二个**，一个格子一个格子往后看。
:::

**所以「要不要自己写一个排排坐」这件事，判据是这样的喵**：**内置的先用**；知道原理，是为了在需要的时候**判断** —— 判断什么？

| 量级 | 一眼认出来的写法 | 本喵真跑的数（1024 条） | n 翻一倍会怎样 |
|---|---|---|---|
| `O(n * n)` | 内外两层都跟「剩下多少条」有关：冒泡、挑最短、理牌 | 两两比 523776 圈 | 翻四倍 |
| `O(n log n)` | 一层层折半：折半合起来、快排（平均）、**`sorted()`** | 折半 10240 条 / 快排 10541 次 / 内置 8926 次 | 略多于一倍 |
| `O(log n)` | 每次都砍掉半边，而且**只用在一排已经摆好的东西上**：砍一半 | 11 次 | 只多 1 次 |

- 数据**只有几十条**：三招憨办法里挑一个顺手的就行，差不了多少；
- 数据**上千上万**：`sorted()` 直接上，别手写 —— 手写的凡是踩到「两两来那一档」，1024 条就要五十万圈；
- 数据**已经在手边一小段一小段排好了**（比如新加进来几条、或者本来就是个半成品）：理牌法（插入）反而很香 —— 第二节那张表里「已经排好」那一行就是证据；
- **要「换位子」特别省的场合**（搬一只鱼干很贵）：挑最短法只换 3 次，是那一行里最省的；
- **要在一排东西里反复找**：先把那一排摆好一次，之后每次都砍一半 —— 摆好那一次的代价，很快就省回来了。

## 小任务

1. 把第一节那段冒泡改成「**这一趟一次都没换过就收工**」：多加一个计数器记「这趟换过没有」，外层每趟开头把它清零，一趟走完发现是 0 就 `break`。拿一摊**本来就排好**的鱼干跑一遍，看看它是不是只走了一趟就停手了 —— 它比的是 5 次还是 15 次喵？
2. 把第二节那个「小账本」程序里的 `原始的` 换成你自己手写的一摊（六只，允许有一样长的），跑一遍，再猜一猜：**换个摊子，哪一招的「换位子」次数会变？哪一招的会一点不变？** 猜完看着数字对照一遍。
3. 第四节的坏版本一（`while 头 < 尾`）本喵只漏掉了 13 和 1。把那一排七只**全部**试一遍（`for 要找的 in 一筐:`），数一数：一共漏了几只？漏掉的都是什么样的格子？（提示：想一想「最后那一趟」被省掉的是什么。）
4. 用 `time.perf_counter()` 给「两两比」和 `sorted()` 在同一筐 1024 条鱼干上各掐一次表，再跟它们各自的圈数摆在一起看。**秒数的比值和圈数的比值差不多吗？** 提醒一句喵：秒数每次跑都不一样，别拿它当尺子 —— 能当尺子的只有数出来的那个圈数。

这一课把「排排坐」和「翻格子」这两件事量明白了：三招憨办法是 `n × n` 那一档，折半着来是 `n log n` 那一档，而**在一排已经摆好的东西里翻格子只要 `log n`** —— 前提是**真的摆好了**。量得多了你会发现：写程序的时候真正难的从来不是「能不能排」，而是「该喊哪一招、代价是几档」喵。🐾
