## 钩子：一屋子箱子，谁也不记得是谁请的

本喵的窝最近不太平喵。

记账的本子要旧版的鱼干箱子，贴图的本子要新版的 —— 两只本子住一个窝，箱子只能留一个版本。给记账本子换上新版的那天，贴图本子当场撂挑子：「这箱子的用法变了，不会使了。」本喵蹲在窝里想了半天，想到了它 —— **给每个窝一间自己的屋**。

屋（venv）前面第 13 课点过名：屋里有自己的存货间，请进来的箱子只归这间屋。今天把它讲透。这一课走四步：① 看清翻译官喵找箱子时手里的那串**路牌**；② 请箱子、点箱子、送箱子（pip 三件套）；③ 把「请过谁、哪个版本」写成一张**登记单**（requirements.txt）；④ 顺嘴看一眼另一种管屋子的办法（conda）。

## 一、先给蟒蛇一间自己的屋

第 13 课那三步，本喵先摆出来，今天要往细里看：

```text
python -m venv .venv               ← 造屋：在窝里多长出一间叫 .venv 的屋
.venv\Scripts\activate             ← 进门：往后的命令都跑在这间屋里（Windows 的写法）
deactivate                         ← 收工：走回大院子
```

进门那一步还有个更实在的近亲：**直接喊屋里那台翻译官喵干活** ——

```text
.venv\Scripts\python.exe -m pip install 箱子名
```

念法是：「**这间屋里的翻译官喵**，用他自己的 pip，去办后面这件事。」它跟进门的区别是**不会站错屋**：进门是「把整间屋挪到你脚下」，走着走着容易又站回大院子；写全路径是「指名道姓喊这一间屋的猫」。这一课后面的命令全用指名道姓的写法，省心的就这一条。

## 二、翻译官喵找箱子，看的是那串路牌

本子一喊 `import`，翻译官喵是翻箱倒柜地找吗？才不喵。它手里攥着一串**路牌**，从上往下一格一格看，哪一格撞见箱子名，就进那一格去叼。这串路牌本喵把它打印出来看看：

```python
import os
import site
import sys

本子待的屋 = os.path.dirname(os.path.abspath(__file__))
装盒子的地方 = [一份 for 一份 in sys.path if "site-packages" in 一份]

print("路牌第一站就是脚本待的那间屋吗：", sys.path[0] == 本子待的屋)
print("路牌上能找到 site-packages 吗：", len(装盒子的地方) >= 1)
print("翻译官喵报的地址，也在路牌上吗：", site.getsitepackages()[-1] in sys.path)
```

```text
路牌第一站就是脚本待的那间屋吗： True
路牌上能找到 site-packages 吗： True
翻译官喵报的地址，也在路牌上吗： True
```

三行都得念一遍喵：

1. **第一行 True**：路牌第一站，认的是**这本子自己待的那间屋**。所以把一个散装小本子摆在本子旁边，它扭头就能 `import` 到 —— 沾的就是这一站的光。（这是「把本子当文件直接跑」时的规矩；换成用 `python -m` 的方式喊本子、或者进交互那间屋，第一站会换成「你正站在哪儿」—— 一句活的：**第一站认的是脚下这间屋**。）
2. **第二行 True**：路牌上找得到 `site-packages` 那一格 —— 那是每间屋的**存货间**。本子里喊的箱子，最后都是在这一格里撞见的。
3. **第三行 True**：`site` 这册子能问出「本喵的存货间在哪儿」；拿它和路牌上那一格对一对，对得上 —— 说明它认的就是同一间存货间。**你站哪间屋，路牌就挂哪间屋的**；装箱子，装进的是「某间屋的存货间」。

把刚才那段本子再一格一格走一遍，专盯那串路牌是怎么铺开的：

## 三、找不到箱子的时候

那要是一路翻到底，路牌上的格子全翻遍了还是没找着呢？翻译官喵就撂下这么一段：

```python
import 深海鱼粮库

print("压根跑不到这一行")
```

```text
Traceback (most recent call last):
    import 深海鱼粮库
ModuleNotFoundError: No module named '深海鱼粮库'
```

头一行的 `Traceback` 是「翻旧账」的意思：把它是从哪儿摸到哪儿一条条摆出来。中间那些 `File "..."` 的行写着本子存在哪一格 —— 路径随每台机器变，本喵就没抄进来。要紧的是**末行**：`ModuleNotFoundError`，翻译官喵明说了 —— 路牌上的格子全翻遍了，没找到叫「深海鱼粮库」的箱子。

::: warn 小心喵
「找不到箱子」平时就俩来路：**一是名字写错**（箱子叫 `fishfood`，你喊 `fish_food`，它也照样翻不着）；**二是真没装，或者装到别的屋去了**。撞上这行报错，先别急着改代码 —— 站对屋，喊一声 `pip list` 看看登记单上有没有它，多半就有答案了。
:::

## 四、装、查、卸：pip 三件套

本喵桌上正躺着一只别人送来的箱子 —— 一只**已经打好包的轮子**（wheel，文件名尾巴是 `.whl`，按规矩装好的一只工具箱）。就拿它当例子，全程不出门、不求网。

**装。** 站定这间屋，喊一声：

```text
.venv\Scripts\python.exe -m pip install fishfood-0.1.0-py3-none-any.whl
```

屏幕上滚过一长串，要紧的只有末尾两行：

```text
Installing collected packages: fishfood
Successfully installed fishfood-0.1.0
```

`Successfully installed` 一出，就是装好了。末尾可能还跟着两行 `[notice]` 唠叨新版本的事 —— pip 的老毛病，看不看随你。

**查。** 请完点一点存货间，它把屋里住着的箱子连版本列成一张小表：

```text
.venv\Scripts\python.exe -m pip list
```

```text
Package  Version
-------- -------
fishfood 0.1.0
pip      25.0.1
```

屋里只有两行：一只刚请的箱子，一只 pip 自己。**装了谁、哪个版本，这张表就是底账。**

**登记到单子上。** 想要一张**能带走的**版本清单，喊 `pip freeze`：

```text
.venv\Scripts\python.exe -m pip freeze
```

它把每只箱子按**「箱子名==版本号」**一行一行写出来。本喵这台机器大院子那间屋的登记单很长，随手摘几行（节选）给你看一眼：

```text
astroid==4.3.4
black==26.10.1
flake8==7.4.1
```

`list` 和 `freeze` 的分工记一句：`list` 是**给自己看**的（连 pip 自己都列进去，扫一眼就完）；`freeze` 是**给别的屋照着请**的 —— 一行一个「名字==版本」，正好拿来重搭一间一模一样的屋。（本喵那只 fishfood 是从本地轮子请的，它的登记行会连来路一起记下来，长得很，这里就不抄了。）

把这串抄进窝里的一个本子，起名 `requirements.txt` —— 「这个窝请过的箱子，全在这张单上」。别人（或者三个月后的你）拿到窝，一条命令把单上的箱子一次请齐：

```text
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

那个 `-r` 念作「照着这份单子请」。另有一个常用的小旗子是 `--upgrade`：写在箱子名前面，意思是「有新版本就直接换上」。

**卸。** 某只箱子不再需要了：

```text
.venv\Scripts\python.exe -m pip uninstall -y fishfood
```

它先报一句「找到它了」，再摘掉，最后报一声卸干净 ——

```text
Found existing installation: fishfood 0.1.0
Uninstalling fishfood-0.1.0:
  Successfully uninstalled fishfood-0.1.0
```

末尾那个 `-y` 是「替本喵答『是』」：不写它，pip 会停下来等你敲一个 y，问「确定要卸吗」。

::: tip 猫咪提示
给 pip 立规矩，一条就够：**箱子安在哪间屋，全看你是站在哪间屋里喊的**。所以本喵的习惯是：

1. **一只箱子只请进真正用它的那间屋**，别一股脑全塞进大院子（大院子塞满了，早晚撞版本）；
2. 每间屋配一张 `requirements.txt`，请了新箱子就顺手更新一次；
3. 出怪事的第一步永远是 `pip list` —— 先看清「这间屋里到底住着谁」，再动手。

哦对：从网上请箱子慢的时候，可以给 pip 换一面近处的镜子（叫**镜像源**），在命令后面加 `-i` 和镜子的地址就行。本喵这边走得顺，就没换。
:::

## 五、conda：另一种管屋子的办法（看到能认出来的程度）

venv 只管蟒蛇的箱子。还有一种更大会管事的：**conda** —— 它连**翻译官喵本体**都能一次配好一副，箱子、别的语言的家伙事也一把抓。它把「哪只猫 + 哪批箱子」整个打成一间屋，装、换、搬全归它。

本喵这台机器上没装 conda，就不现场招呼它了（**没跑过的东西，本喵不装作跑过**）。认两点就够：

| | venv + pip | conda |
|---|---|---|
| 管什么 | 只管家门口这批箱子 | 猫本体 + 箱子，还管别的语言的家伙事 |
| 从哪来 | 蟒蛇自带，不用另装 | 要专门装一套 |

以后在别人的机器上看到 `conda create`、`conda activate` 这类命令，知道它和本喵今天讲的 venv 是**同一个问题的两种答法**就行 —— 都在回答「怎么让不同窝的箱子互不打架」。

## 小任务

1. 给自己某个窝造一间屋（`python -m venv .venv`），进门后 `pip list` 点一点：新屋的登记单上只有谁？（照着第四节那张两行的表对一对。）
2. 挑一只你请过的箱子，先 `pip freeze` 抄进 `requirements.txt`，再把箱子卸掉、照着单子请回来 —— 看看登记单是不是原样长回来。
3. 把第二节那段小本子存成文件跑一遍，把 `sys.path` 整个打印出来，数一数：路牌一共几格？第一格是哪儿？
4. 想一个问题：为什么「卸箱子」比「请箱子」用得少，却同样要紧？（提示：想想那间屋越来越胖的后果。）

这一课把「箱子住哪儿」拆开看了：路牌怎么铺、pip 怎么请查卸、单子怎么记。总结起来就一句喵：**站在哪间屋，就是哪间屋的猫；单子记清楚，换台机器也搬得走。** 🐾
