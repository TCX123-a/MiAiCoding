## 钩子：一亿条鱼干，储物柜塞不下

本喵的鱼塘里有一亿条小鱼干。本喵想一条一条地数过去 —— 每数一条印一行。要是照着前面的法子，先把它们**整整齐齐装进一个储物柜**，那柜子当场就被撑爆了：一亿样东西的柜子，内存根本放不下喵。

可本喵转念一想：**本喵真的需要一次攥着一亿条吗？** 本喵只需要「下一条」而已。数完这一条，下一条才轮到上场。

Python 里就有这么一套「**一条一条来**」的机制，它一次只攥着**一样**东西，可你却能顺着它一路走到底。今天本喵要把这套机制从里到外看一遍：`iter`、`next`、`yield`，还有那个最神奇的词 —— **惰性**。

## `iter` 和 `next`：一只会「下一条」的手

```python
bowls = ["小鱼干", "猫粮", "冻干"]

it = iter(bowls)
print(next(it))
print(next(it))
print(next(it))
```

```text
小鱼干
猫粮
冻干
```

- **`iter(一排东西)`** —— 从这一排里请出**一只会「下一条」的手**。这只手自己揣着一个小本本，记着「本喵夹到第几格了」。
- **`next(手)`** —— 「**把下一格的东西叼回来**」。喊一次，它往前走一格。
- 注意 `iter(bowls)` **没有**把碗里的东西复制一份出来，只是请了只手指着这排碗。手走过的地方，**碗还在原地**——所以走完之后 `bowls` 本身一点没变。

跟上一课接上了：`for x in 一排东西:` 之所以能一行行取出来，就是因为 Python 在背地里**先 `iter` 请出手，再一遍遍 `next`**。今天本喵只是把背后那几步搬到台面上来喵。

## 拿完了还喊，会怎么样

```python
bowls = ["小鱼干", "猫粮"]

it = iter(bowls)
print(next(it))
print(next(it))
try:
    print(next(it))
except StopIteration:
    print("碗空啦")
```

```text
小鱼干
猫粮
碗空啦
```

- 只手一共有两格，前两次 `next` 把东西都叼走了。**第三次**再喊，它没东西可给了，会**当场翻脸**，甩出一个叫 `StopIteration` 的东西出来。
- `StopIteration` 是这套机制**故意**留的信号，意思就一句：「**本喵这儿没有下一条了**」。
- `try` / `except` 是前面学过的「**先试一手，翻脸了就走另一条路**」的写法。这里的意思：先试着再要一条，要是它扔出 `StopIteration`，本喵就印一句「碗空啦」，不跟它吵。
- 这也正是 `for` 为什么能安安静静把一排东西走完、也不翻脸 —— 因为 `for` **背后悄悄接住了这个信号**。收到 `StopIteration`，它就当作「走完了」，收工。

## 招式里开个口子：`yield`

```python
def 数鱼干():
    yield 1
    yield 2
    yield 3

it = iter(数鱼干())
print(next(it))
print(next(it))
print(next(it))
```

```text
1
2
3
```

- 招式里一出现 `yield`，这一招就**变了性质**：喊它的时候它**不马上跑**，而是叼回来一只「**会下一条的手**」——和上一课不写括号的招式那种「招式也是东西」是一个脾气，只是它还多带了一只手。
- 每喊一次 `next`，它才**从上次停下的地方接着往下跑**，跑到下一个 `yield` 就停住，把 `yield` 后面的东西递出来。
- 停住的时候，招式里那些仓库（比如数到几了）**原样留着**，下次接着用。所以三次 `next` 才能依次拿到 1、2、3。
- **`yield` 和 `return` 的区别**：`return` 是「本喵干完收摊，整招就这一回」；`yield` 是「本喵先递一样东西出去，**待会儿还回来接着干**」。一个是一次性的，一个是能来回好几趟的喵。

「**停住**」这件事在屏幕上是看不见的 —— 它既没有印出来，也没有报错。本喵把它拆成一步一步，走给你看：

## 惰性：你不喊，它就不动

```python
def 数鱼干():
    print("本喵开始数啦")
    yield 1
    yield 2

print("先把招式放好")
it = iter(数鱼干())
print("现在开始数")
print(next(it))
```

```text
先把招式放好
现在开始数
本喵开始数啦
1
```

盯住输出的**顺序**喵：「本喵开始数啦」居然**排到了最后**，比 `print("现在开始数")` 还晚！

因为喊 `数鱼干()` 的那一刻，招式里**一行都没跑**，只是把手准备好了。直到 `next(it)` 喊下去，它才真的开演。这就叫**惰性**：「**你不喊它就不动**」。

## 用不完的鱼干

```python
def 无限鱼干():
    n = 0
    while True:
        n = n + 1
        yield n

it = iter(无限鱼干())
print(next(it))
print(next(it))
print(next(it))
```

```text
1
2
3
```

这一招**永远数不完**：`while True` 让它一头扎进去，一直转下去。可本喵只取了三条，程序**一点都没卡住** —— 换成一个储物柜试试，早撑爆了。

为什么它不卡？还是那条惰性：它**不会傻乎乎地先把东西全算出来摆好**，而是你要一条、它算一条。这就是生成器最值钱的地方：**要多少给多少，不提前囤**。

## 手走过就走过了，回头没有第二条

```python
def 数鱼干():
    yield "小鱼干"
    yield "猫粮"
    yield "冻干"

it = iter(数鱼干())
print(next(it))
print(list(it))
```

```text
小鱼干
['猫粮', '冻干']
```

- `next(it)` 先叼走第一条「小鱼干」。
- `list(it)` 读作「**把剩下的全都装进一个储物柜里**」。它顺着这只手继续往前走，把手上的东西一样不落全收进去 —— 所以拿到的是**剩下来的两条**，第一条早被叼走了。
- 再加上前面那个「拿完了会翻脸」的例子，就推出一个要紧的规矩：**一只手只能走一遍**。走过去了就回不来了，想再来一次得重新 `iter(数鱼干())` 请一只新的手。

::: tip 猫咪提示
- **`iter(一排东西)`** —— 请出一只记着「夹到第几格了」的手。
- **`next(手)`** —— 把下一格叼回来；没东西了会扔出 `StopIteration`。
- **`for`** —— 背后就是「先 `iter` 请手，再反复 `next`，接住 `StopIteration` 收工」，本喵不用自己写。
- **`yield x`** —— 招式里开个口子：递出 `x`，停在这儿，下次接着往下跑；招式里的仓库原样留着。
- **惰性** —— 你不喊它就不动。这一点让它能对付「永远数不完」的东西，也不怕东西多得装不下。
- **一只手只能走一遍**，走完就空了，想重来就再 `iter` 一只新的。
:::

::: warn 小心喵
三个最容易踩的坑：

- **`yield` 写成了 `return`**。写成 `return 1`，这一招跑一次就收摊了，后面那两行 `yield` 再也轮不到，本喵会以为「怎么只拿到一条」。
- **拿完了还接着 `next`**。它会甩 `StopIteration` 出来。用 `for` 走就没事 —— `for` 自己会接住它；自己手写 `next` 就得留个心。
- **把一只走空的手再走一遍**。走空了之后它**不会自己复原**，接着 `next` 只会继续翻脸，`list(...)` 也只会给一个空储物柜。想重来，得重新请一只手喵。
:::

## 一句话对照表

| 写下的这一句 | 它干了什么 |
|---|---|
| `it = iter(一排东西)` | 请出一只记着「夹到哪了」的手 |
| `next(it)` | 把下一格叼回来；没了就扔出 `StopIteration` |
| `try:` / `except StopIteration:` | 先试一手，翻脸了就换条路走 |
| `def 招式():` 里有 `yield` | 喊它不马上跑，叼回来一只「会下一条的手」 |
| `yield n` | 递出 `n`，停在这儿；下次从这一行接着往下跑 |
| `while True:` + `yield` | 永远数不完的一串 —— 靠惰性才不会卡住 |
| `list(it)` | 把手上的东西全收进一个储物柜里 |

```python
def 数鱼干():
    yield "小鱼干"
    yield "猫粮"
    yield "冻干"
```

3. 把 `数鱼干` 改成永远数不完的那一版（`while True` 里 `yield`），然后写一个 `for` 从它里面取，取够 5 个就用 `break` 跳出来。跑跑看，程序会不会卡住喵。
