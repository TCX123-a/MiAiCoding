## 钩子：出门前，本喵先看一眼猫粮碗

本喵每天早上出门前，都要先低头看一眼猫粮碗：

- 鱼干堆得冒尖 → 今天不慌，先回猫窝晒会儿太阳。
- 只剩两三根 → 得省着点吃，顺便盯着大肥鱼别偷拿。
- 碗底空空的 → 只好去鱼塘边找大肥鱼要点救济。

三条路，本喵看一眼就知道该走哪条。这一眼，术语表里叫**看鱼干眼色行事（条件判断）**，写进代码里靠的就是今天这三个词：`if`、`elif`、`else` 喵。

## 先复习：一个眼色，一条路

前面我们练过让代码算账，今天让代码学会**看着情况选路**。先看最小的形状：

```python
fish = 3

if fish > 0:
    print("碗里还有鱼干，开吃喵")
```

```text
碗里还有鱼干，开吃喵
```

拆开只有三块：

1. **眼色** —— `fish > 0`。这是本喵问电脑的一句话：「碗里的条数比 0 大吗？」电脑只答两种：`True`（真）或者 `False`（假）。
2. **冒号 `:`** —— 眼色问完了的记号，一个都不能少。
3. **往里让的那句话** —— 眼色答「真」才轮到它上场。

只有一条路要挑的时候，一个 `if` 就够了。可本喵今天有三条路，得请另外两个词出场喵。

## `elif`：中间那些眼色

`elif` 是英文「else if」两个词挤在一起写成的，念起来像「否则如果」。本喵把三路眼色一次写全：

```python
fish = 2

if fish >= 5:
    print("鱼干满满，本喵先晒会儿太阳喵")
elif fish > 0:
    print("快见底啦，省着点吃喵")
else:
    print("碗空了，去找大肥鱼要点喵")
```

```text
快见底啦，省着点吃喵
```

读法只有一句话：**从上往下一个一个问，谁先答「真」就走谁那条路，然后整串眼色到此结束。**

本喵把第一行换个数，三条路就都露一次脸：

| `fish` 是几 | 谁答了真 | 屏幕上印出 |
|---|---|---|
| `9` | `fish >= 5` | 鱼干满满，本喵先晒会儿太阳喵 |
| `2` | `elif fish > 0` | 快见底啦，省着点吃喵 |
| `0` | 前面全答假，轮到 `else` | 碗空了，去找大肥鱼要点喵 |

`else` 是这一串的**兜底**：前面每个眼色都答了假，才轮到它。它后面**不写问话** —— 它不用问，它就是「剩下的全归我」。

顺便交代两件事：

- 中间的候补（`elif`）**想排几个排几个**，一路往下排都行；但一串的末尾最多只站一个兜底。
- `else` **不是非写不可**。不写的话，前面全答假就**什么都不做** —— 这一串眼色整体跳过，程序接着往下跑喵。

**记住这条排队规矩**：`if` / `elif` / `else` 是**从上往下一句一句问**的，谁先答「真」就走谁，**问到就停** —— 后面排着队的眼色，电脑一句都不会再看喵。

### 第一个答了真，后面就不问了

这是 `elif` 最要紧的脾气，本喵单独拎出来。看这段：

```python
fish = 3

if fish > 0:
    print("有鱼干，开吃喵")

if fish > 2:
    print("而且还挺多喵")
```

```text
有鱼干，开吃喵
而且还挺多喵
```

两句话都印出来了 —— 因为这是**两个各自独立的眼色**，电脑会一个一个都问一遍，谁答真谁就上场。这跟上一段那种「一串眼色」是两回事：

- **两个独立的 `if`**：两个眼色都会被问，可能两条路一起走。
- **`if` + `elif`**：一串眼色，前面那个答了真，后面的**连问都不问**。

想要「最多只走一条路」，就把它们串成一串（`if` / `elif` / `else`）；想要「每件事各问一句，该走的都走」，就分开写成几个 `if`。用哪种，看你心里的规矩是哪一条喵。

### 顺序反了，结果就变了

既然是「从上往下问」，那**谁排在前头谁说了算**：

```python
score = 95

if score >= 60:
    print("及格喵")
elif score >= 90:
    print("优秀喵")
```

```text
及格喵
```

95 分，屏幕上却只印出「及格喵」。因为第一个眼色「大于等于 60 吗」已经答了真，电脑高高兴兴走了这条路，**后面那句「90 以上吗」根本没被问出口**。这段代码一个错都不报 —— 它只是安安静静给出了不对的结果，这种最费眼神喵。

所以排眼色有一条规矩：**最严的条件放最上面**（先问「90 以上吗」，再问「60 以上吗」）。

## 缩进：Python 用行首的空白划路

下面是今天的重头戏，本喵坐下来慢慢讲。

别的语言（你在通用课里见过的 C、C++、Java）用一对大括号 `{ }` 把「归这条路管的话」圈起来。**Python 不用大括号，它用行首的空白** —— 行首往里让了几格，就是「这句话归谁管」的全部答案。这条规矩本喵分三小段讲喵。

### 规矩一：冒号后面的话，要往里让

```python
fish = 0

if fish > 0:
    print("开吃喵")
    print("吃完记得擦嘴喵")
else:
    print("碗空了喵")
    print("去找大肥鱼喵")
```

```text
碗空了喵
去找大肥鱼喵
```

看清楚这个排版：

- `if fish > 0:` 和 `else:` 这两行**贴着最左边**站 —— 它们是「眼色」本身，是**路口**。
- 它们下面那两句，都**往里让了 4 格** —— 往里让的，就是「归它管的话」。
- 一个眼色管的话可以有好几句。**让它们一样齐，电脑就知道它们是一伙的**：眼色答真，它俩一起上场；答假，它俩一起歇着。

所以看一段 Python 代码，你可以先用眼睛「扫左边」：**左边空白一样多的那几句话，是一伙的。**

### 规矩二：同一伙话必须一样齐

往里让几格？1 格、2 格、4 格其实都能跑，但全世界的猫都约好了：**一次让 4 格**。你照着 4 格写，抄别人的代码、别人抄你的，都不会打架喵。

要紧的是**同一伙话必须让得一样多**。下面这样写就要摔：

```text
fish = 3
if fish > 0:
    print("开吃喵")
   print("再来一条喵")
```

（第二句话让了 3 格，跟上面那句的 4 格对不上。）电脑看见一个它不认识的深度，会当场犯难，甩你一句 `IndentationError`。

以后还会遇到一层套一层的眼色，那时候也是这样：**里头那一层，永远比外面多让 4 格** —— 让几格没有那么神秘，它就是「比外面再深一层」。

### 规矩三：缩回来的话，不归任何一条路管

```python
fish = 0

if fish > 0:
    print("开吃喵")
print("本喵去晒太阳啦喵")
```

```text
本喵去晒太阳啦喵
```

碗是空的，`if` 那条路根本没走，可最后那句话**印出来了**。为什么？因为它的行首**缩回了最左边**，跟 `if` 站同一列 —— 电脑一看就知道：「这话不归那条路管，是外面的话。」外面的话**不管眼色答真还是答假，都会跑**。

反过来也成立：想让一句话「只有碗里有鱼干时才跑」，就得把它**让进 `if` 底下**。

一句话总结：**缩进就是归属**。这是 Python 里「哪句话归哪条路」的唯一答案喵。

### 摔得最多的几个跟头

本喵把新手最常摔的几下摆出来，你把报错的样子认一认，以后一照面就知道是谁在喊你。

**跟头一：冒号后面忘了让。** 写成了这样：

```text
fish = 3
if fish > 0:
print("开吃喵")
```

翻译官喵当场就不干了：

```text
  File "main.py", line 3
    print("开吃喵")
    ^^^^^
IndentationError: expected an indented block after 'if' statement on line 2
```

`IndentationError` 是「行首空白不对」的意思。最后那半句说得很直白：**第 2 行那句 `if` 后面，本喵等着一个往里让的块，结果什么都没等到。**

**跟头二：缩回去的位置对不上。** 本来想让两句都归 `if` 管，手一滑让成了 2 格：

```text
fish = 3
if fish > 0:
    print("开吃喵")
  print("再来一条喵")
```

```text
  File "main.py", line 4
    print("再来一条喵")
                  ^
IndentationError: unindent does not match any outer indentation level
```

最后那句翻过来是：**你缩回来的这个位置，哪一层都对不上。** 电脑心里只有「让 4 格的这一伙」和「贴最左边的这一伙」，你在 2 格的位置冒出来，它不知道该把你算进哪一伙。

**跟头三：冒号漏了，或者用成了中文冒号。** 冒号是「下面要开路」的暗号：

```text
fish = 3
if fish > 0
    print("开吃喵")
```

```text
  File "main.py", line 2
    if fish > 0
               ^
SyntaxError: expected ':'
```

`SyntaxError` 是「这句读不通」。它把心思也写得清清楚楚：`expected ':'` —— **本喵想要一个冒号**。

中文输入法下敲出来的 `：` 更隐蔽：它在屏幕上跟 `:` 几乎长得一样，可翻译官喵眼里它根本不算冒号：

```text
fish = 3
if fish > 0：
    print("开吃喵")
```

```text
SyntaxError: invalid character '：' (U+FF1A)
```

（`U+FF1A` 是它在电脑字典里的编号，也是它「不是冒号」的铁证。）写代码的时候，**输入法记得切回英文**喵。

**还有一个看不见的跟头：Tab 和空格混着用。** 键盘上那个 Tab 键敲出来的空白，和空格键敲出来的四个格，在电脑眼里**是两种不同的东西**。从别处复制来的代码常常一半是 Tab、一半是空格，屏幕上看着整整齐齐，跑起来却甩你一句：

```text
TabError: inconsistent use of tabs and spaces in indentation
```

意思是「你这几行缩进里，Tab 和空格混着用了」。保险做法是**一段代码里只用一种**：本喵一律按空格键，一次四下。（大多数编辑器里按 Tab 键会自动换成 4 个空格，那就放心大胆按喵。）

::: tip 猫咪提示
缩进三句话，背下来就够用啦：

1. **冒号是路口，让进去的话归它管。**
2. **同一伙话必须一样齐** —— 本喵一律让 4 格。
3. **缩回最左边的那句话是「外面的」** —— 不管眼色答真还是答假都会跑。
:::

## 条件表达式：冒号左边那半句

说了半天「眼色」，现在把它的正式名字补上：冒号左边那半句，代码里叫**条件表达式** —— 一句能被电脑答成「真」或「假」的问话。最常用的几个手势是这些：

| 手势 | 本喵问的话 | 什么时候答「真」 |
|---|---|---|
| `>` | 左边比右边大吗 | 左边确实更大 |
| `<` | 左边比右边小吗 | 左边确实更小 |
| `>=` | 大于，或者相等吗 | 满足其中一个就算 |
| `<=` | 小于，或者相等吗 | 满足其中一个就算 |
| `==` | 两边一样吗 | 一模一样才算 |
| `!=` | 两边不一样吗 | 只要不一样就算 |

本喵把眼色**直接印出来**给你看：

```python
fish = 3

print(fish >= 5)
print(fish == 3)
print(fish != 3)
```

```text
False
True
False
```

`True` 是真，`False` 是假 —— 电脑只有这两种脸色，没有「大概吧」「看心情」。`fish` 是 3，所以「3 大于等于 5」答假、「3 和 3 一样」答真、「3 和 3 不一样」答假，屏幕上就依次冒出 `False`、`True`、`False` 喵。

不止数字罐能比，一串小鱼干穿成的项链也能比：`weather == "雨"` 问的是「仓库 `weather` 里那串项链，跟 `"雨"` 一模一样吗」。项链之间只能比「一样不一样」，比不了大小 —— 那是另一回事喵。

### 一个等号，两个等号

这是新手最常摔的一跤，本喵单独拎出来：

- **一个等号 `=`**：把右边**装进**左边的仓库。`fish = 3` 是「把 3 装进 `fish`」。
- **两个等号 `==`**：问一句「两边一样吗」，答真或假。

问眼色要用两个等号。写成 `if fish = 3:` 就是把「装东西」的动作塞进了问话的位置，翻译官喵读不通，会当场甩你一段 `SyntaxError`。

::: warn 小心喵
两个最容易摔的地方，写代码前在心里过一遍：

1. **`=` 是装东西，`==` 才是问话。** 眼色里永远用两个等号。
2. **眼色的顺序：最严的放最上面。** 电脑从上往下问、问到答真的就停手 —— 把宽松的条件排在前面，后面那些细分出来的路就永远走不到了（就像 95 分只印出「及格喵」那样）。
:::
