## 钩子：趴下的翻译官喵

本喵前几天在鱼塘边支了个小摊，帮来串门的猫称小鱼干。称鱼干之前得先问一句「今天带了几条呀」，再把回答变成数字。昨天三花跑来，甩了一句「喵」，本喵手一抖，把程序照这样写了下去：

```text
print("开始称鱼干")
print(int("喵"))
print("称完啦")
```

翻译官喵念到第二行，当场「啪」地趴下了：

```text
Traceback (most recent call last):
  File "...\main.py", line 2, in <module>
    print(int("喵"))
          ^^^^^^^^^
ValueError: invalid literal for int() with base 10: '喵'
```

更扎心的是：后面排队的那只猫明明带了一整袋小鱼干，可那句 `print("称完啦")` 却**一个字都没印出来**。因为**程序一断气，它后面剩下的代码就一行都不会再跑了**。

这一课，本喵就教你一手「**提前铺好软垫**」的写法 —— 让翻译官喵摔下来的时候有地方接着，不至于当场趴下。它的名字叫 `try` 与 `except` 喵。

## 一、异常：开演之后才翻的车

先画一条分界线，往后天天用得上：

- **开演之前就被拦下的**：拼错了名字（把 `print` 写成 `prnt`）、少写一个冒号、括号没配对。这种稿子翻译官喵**根本不肯开演**，它会指着那一行说「这里本喵看不懂」。
- **开演之后才翻的车**：稿子一个字都没写错，可念到某一句时，发现手头的材料**办不到** —— 比如要把「喵」这两个字变成数字。这种跑到半路撞上的岔子，术语里就叫**异常**。

异常像什么呢？像一只猫从窗台上往下跳，半空中才发现**落脚的地方是空的**。稿子（程序）写得没错，可跑到那一步就是办不到。

它最扎人的脾气有两条：

1. **撂挑子**：异常一出现，程序当场断气，后面剩下的代码一行都不跑。
2. **会打报告**：断气之前，翻译官喵甩出一张报告单，告诉你**在哪一行、翻的是哪种车、为什么**。

::: tip 猫咪提示
别把「写错字」和「异常」混成一件事喵：**写错字**是开演前就被翻译官喵拦下（它根本不肯念）；**异常**是开演之后才撞上的岔子（念到那一句才发现办不到）。今天要铺的软垫，专门接后面那一种。
:::

## 二、`try` 与 `except`：提前铺好的软垫

光知道「会摔」没用，得**提前把软垫铺好**。写法就是在可能有危险的那几句外面套一层「万一」：

```python
try:
    print(int("喵"))
except ValueError:
    print("这串字变不成数字喵，本喵先记 0 吧")
```

```text
这串字变不成数字喵，本喵先记 0 吧
```

一行行拆开看：

- **`try:`** 是第一块牌子，意思是「**下面缩进的这一段，本喵先试着跑跑看**」。
- 缩进的那一句 `print(int("喵"))` 就是**可能会翻车的活**。
- **`except ValueError:`** 是第二块牌子，意思是「**万一翻的是 `ValueError` 这种车，就改跑本喵下面缩进的那一段**」—— 而不是当场断气。
- 两块牌子后面**都要跟冒号**，缩进规矩和 `if`、`def` 一样：4 个空格，一整段缩到底。

看仔细这回发生了什么：`int("喵")` 照样翻车了，可翻译官喵**没有趴下**，它照着本喵准备好的台词念了一句，然后……**继续往下跑**。这就是软垫的用处喵。

### 没翻车的时候，`except` 就是摆设

那要是 `try` 里的活儿一点岔子都没出呢？

```python
try:
    print(int("7") + 1)
except ValueError:
    print("这串字变不成数字喵")
```

```text
8
```

`"7"` 是能变成数字的，所以 `try` 里那一句顺顺当当印出了 `8`；而 `except ValueError:` 下面缩进的那一句，**一个字都没跑**。这是 `except` 的脾气：**它只在真翻了这种车的时候才上场**，平时安安静静待在原地。

::: tip 猫咪提示
`try` 和 `except` 是**一对**，谁也离不开谁喵：

1. **`try`** 里放**可能会翻车的活**（比如把别人回答的一串字变成数字）。
2. **`except` 后面写「要接住哪一种车」**，下面缩进的是**接住之后怎么办**。
3. 两块牌子**都要冒号**，两段身体**都要缩进**。
:::

### 网眼不对，照样接不住

`except` 后面那串名字，就是「**本喵要接哪一种车**」。写错了种类，就像拿着捞鱼的网去接打翻的猫粮碗 —— 接不住：

```text
try:
    print(int("喵"))
except ZeroDivisionError:
    print("零不能当分母喵")
```

这段看着挺稳当，可本喵这一回翻的是 `ValueError`，写下的却是 `ZeroDivisionError`。翻译官喵照样趴下，报告单最后一行还是那句：

```text
ValueError: invalid literal for int() with base 10: '喵'
```

所以写 `except` 的时候要先想清楚：**这一段最可能翻的是哪种车**，再把那个名字抄准。名字**一个字母都不能差**，大小写也要对上（`ValueError` 里的 `V` 和 `E` 都是大写）喵。

## 三、常见异常：学会读那张报告单

先学会读报告单。刚才那一大串看着吓人，其实照着四行认就够了：

- **`Traceback (most recent call last):`** —— 「出事记录，越往下的发生得越晚」。
- **`File "...\main.py", line 2`** —— 出事地点：哪个文件、第几行（就是那个 `line 2`）。
- **`^^^^^^^^^`** —— 翻译官喵用小爪子指着那一句里最扎手的一小段。
- **最后一行** —— **结论**：翻的是哪种车，外加一句话说明。

往后看报错，先拉到最底下看最后一行，那里**写着车名**喵。

常见的几种车，先认个脸熟：

| 车名 | 什么时候翻这种车 | 例子 |
|---|---|---|
| `ValueError` | 想把一串字变成数字，可它根本不像数字 | `int("喵")` |
| `ZeroDivisionError` | 拿 `0` 当分母 | `10 / 0` |
| `KeyError` | 名牌柜里压根没挂过这块名牌 | `{"小橘": 3}["三花"]` |
| `NameError` | 喊了一个还没建起来的名字 | 小鱼干仓库还没建，就先 `print(fish)` |

挑两个亲手接一接：

```python
try:
    print(10 / 0)
except ZeroDivisionError:
    print("零不能当分母喵")
```

```text
零不能当分母喵
```

```python
fish = {"小橘": 3}
try:
    print(fish["三花"])
except KeyError:
    print("这块名牌没挂过喵")
```

```text
这块名牌没挂过喵
```

### 把报告单抓在手里：`as e`

除了接住它，你还能把那张报告单**拿在手里看**：

```python
try:
    print(int("喵"))
except ValueError as e:
    print("出岔子了：", e)
```

```text
出岔子了： invalid literal for int() with base 10: '喵'
```

`as e` 的意思是「**把这张报告单抓在手里，起个名字叫 `e`**」。`e` 里装的就是结论那一行。`print(e)` 把它原样念出来 —— 于是你既能先说一句自己的话安慰主人，又能把**翻译官喵的原话**摆出来给他看，他一看就明白是哪儿不对了。

（`e` 是本喵给报告单随便起的名字，你叫它 `err`、叫它 `报告` 都行 —— 只要 `as` 后面写什么、后面就用什么，前后一致就成。）

::: warn 小心喵
三个最容易摔的地方喵：

1. **`except` 后面的车名写错**（写成别的种类、或者大小写不对）—— 网眼对不上，真翻车时程序照样断气。名字一个字母都不能差。
2. **`try:` / `except ...:` 忘写冒号，或者缩进没对齐** —— 这属于「开演前」的错，翻译官喵会直接拦下你，根本不让你开演。
3. **一段 `try` 里塞了十句话** —— 出了岔子本喵根本不知道该先查哪一句。**只把真会翻车的那一两句放进去**，软垫要铺在真正会摔的地方喵。
:::

## 四、`else` 与 `finally`：顺利时的收尾，和不管怎样都要做的事

`try` 和 `except` 还能再带两块牌子。四块凑齐是这样：

```python
try:
    print(int("7") + 1)
except ValueError:
    print("这串字变不成数字喵")
else:
    print("顺顺利利，一条岔路都没走")
finally:
    print("不管怎样，碗都要收")
```

```text
8
顺顺利利，一条岔路都没走
不管怎样，碗都要收
```

四块牌子按顺序看下来：

- **`try:`** 先跑，印出 `8`，一条岔路都没走。
- **`except ValueError:`** 没上场 —— 因为压根没翻车。
- **`else:`** 上场了，印出「顺顺利利，一条岔路都没走」。它的脾气是：**只有 `try` 里一条岔路都没走的时候，它才跑**。
- **`finally:`** 也上场了，印出「不管怎样，碗都要收」。它的脾气是：**不管前面翻没翻车，最后它都要跑一遍**。

换成翻了车的情况，看看哪一句不见了：

```python
try:
    print(int("喵"))
except ValueError:
    print("这串字变不成数字喵")
else:
    print("这句不会印出来")
finally:
    print("不管怎样，碗都要收")
```

```text
这串字变不成数字喵
不管怎样，碗都要收
```

这回 `try` 里翻了车：`except` 上场接住，印出安慰的那句；**`else` 整段被跳过**（所以「这句不会印出来」真的没印出来）；最后 `finally` 照旧收碗。

翻车之后控制流是一格一格走的，本喵走给你看：

### 四块牌子，谁什么时候上场

| 牌子 | 什么时候上场 |
|---|---|
| `try:` | 每次都跑，**第一个**跑 |
| `except 车名:` | 只有 `try` 里**翻了这种车**才上场 |
| `else:` | 只有 `try` 里**一条岔路都没走**才上场 |
| `finally:` | **不管翻没翻车**，最后都要上场 |

`else` 和 `finally` 都不是非写不可的。但 `finally` 那份「**收尾的事一定做完**」的保证特别值钱：锅要端下灶、碗要收进柜、账本要合上 —— 这些事**不能因为半路翻了个车就撂下不管**。现实里的程序出岔子时，最容易漏掉的就是这句「不管怎样都得做」的事，而 `finally` 替你把它焊死了喵。

::: tip 猫咪提示
一句话把顺序记住喵：**`try` 先跑；翻了车就走 `except`，没翻车就走 `else`；不管走了哪一条路，最后都要过一遍 `finally`。**
:::

## 小任务

2. 把 `"喵"` 改成 `"7"` 再跑一遍 —— 盯着看 `except` 下面那一句有没有被印出来。
3. 给第 1 题再加一块 `finally:`，里面印一句「碗收好了」。然后把 `"喵"` 改成 `"7"` 再跑一遍 —— 看看**哪一句是始终都在的**，为什么。
4. 故意把 `except ValueError:` 改成 `except ZeroDivisionError:` 跑一次 —— 亲眼看一眼翻译官喵是怎么照样趴下的。看完再改回来。
