## 钩子：同一本书，两种翻法

本喵想请一位翻译官喵，帮大肥鱼把那本厚厚的《猫粮食谱》翻成猫语。它有两种干法：

- **整本翻完再开演**：把书抱走，关起门从头翻到尾，翻完了才把一叠稿子递给你——你要先等。
- **念一句，翻一句**：坐在你旁边，你念一句它翻一句，你当场就能照着做。

Python 请的翻译官喵，是后一种。这套干法有个正式的名字，叫**解释执行**。名字不用急着背，先记住这个画面就够：**念一句，翻一句，做一句**喵。

## 解释执行：从上往下，念到哪儿做到哪儿

你把代码交给 Python 的翻译官喵，它就从**最上面一行**开始，反复做三个动作：

1. **念一行**：看懂这一行要它干什么
2. **翻一句**：立刻转成电脑能照着做的动作
3. **做一句**：这一行做完了，才轮到下一行

这就是**解释执行**。它带来三个特别要紧的结果：

**第一，写一行就能看一行。** 它不等整份稿子翻完，所以刚开始学的时候特别舒服：写一句、跑一下，当场就知道对不对。

**第二，从上往下的顺序，就是事情发生的顺序。** 它不跳行，也不会提前去念后面的。

**第三，出了问题是「念到那儿」才发现的。** 假设你的第 3 行写的是 `1 / 0`，翻译官喵**不会把前面两行退回来**——前两行它已经老老实实印出来了（本喵真跑过，屏幕上稳稳留着两行），念到第 3 行才炸，然后气鼓鼓地甩给你一段**报错信息**，里面会写清楚它是在**第几行**卡住的。所以记住这条：**屏幕上有报错，不代表前面什么都没发生**——前面做过的，就是做过了。往后本喵带你抓虫的时候，这句话天天要用到喵。

⚠️ 但有一类错是例外，本喵得说清楚：**括号没配齐、引号少一半这种「字写错了」的毛病，压根轮不到第 3 行。** 翻译官喵动手之前会**先把整份稿子从头扫一遍**，扫不过去就当场拦下、**一行都不跑**（本喵试过在第 3 行漏个括号：屏幕上前面两行**一个字都没有**，只有一句 `SyntaxError: '(' was never closed`）。所以上面那句「做过的就是做过了」，说的是**扫完之后、跑起来才出的事**；写字写错了，是开工前的体检就拦下的喵。

有的语言走的是另一条路：先把整份稿子从头到尾翻成电脑能直接执行的稿子，再一口气跑起来（跑得飞快，但开工之前得先等它翻完）。课本、教程和报错信息里，管「念一句翻一句」这位叫**解释器**，管「整份翻完再开演」那位叫**编译器**；本喵一律管它们叫**翻译官喵**，你只要记住 Python 是**边念边翻**的那种就够啦。

## 交互式环境：鱼塘边的问答摊

想立刻试试刚才那句话对不对？本喵带你去一个好地方：**交互式环境**。它就像鱼塘边支起来的一个问答摊——你喊一句，猫咪当场答一句。

进摊子只要两步：

1. 打开电脑上的**命令窗口**（有的系统里叫终端）；
2. 敲两个字 `python`，按回车。

屏幕上就会冒出这么一个记号：

```text
>>>
```

这个 `>>>` 就是猫咪递话筒给你的样子：「本喵在听着，说吧～」现在你可以一句一句地跟它说话了：

```text
>>> print("你好，喵！")
你好，喵！
>>> 1 + 1
2
```

看懂三件事，这个摊子就归你了喵：

- 带 `>>>` 的那行是**你敲进去的**；没有 `>>>` 的那行，是**它当场念出来的**。
- 在摊子里可以偷个小懒：敲 `1 + 1` 的时候不用写 `print`，它也会把算出来的结果（`2`）念给你听——摊子的规矩就是「你说了什么，本喵都当场回你」。
- 逛够了想走，敲 `exit()` 跟它说声再见，就回到原来那个窗口了。

问答摊最大的好处是**快**：试一小口、算个数、看看某个写法对不对，按一下回车就知道答案。最大的短处是**说完就没了**——窗口一关，刚才敲的那些字一个字都不剩。

（这个摊子的英文名字叫 REPL。以后在别的教程里撞见它，记得它就是我们说的「问答摊」就成喵。）

## 在软件里跑 Python 代码：写成文件

试吃归试吃；要留一份能反复做的菜谱，还是得写下来。代码也一样：**写进文件**，才能存住、才能改一改再跑一遍。

**第一步，建个文件、起个名字。** 在写代码的软件里新建一个文件，就叫它 `hello.py`。后面那三个字符 `.py` 是挂在门口的**门牌**，专门给翻译官喵看的：**「这间屋里装的是 Python 代码」**。屋名随你起，门牌可别写错。

**第二步，把代码一行行写进去。** 文件里怎么写就怎么写，只写普通的一行行代码，**没有 `>>>`**——那是问答摊的话筒，不是代码的一部分。

**第三步，喊翻译官喵来跑它。** 打开命令窗口，敲这么一句：

```text
python hello.py
```

这句话分成两截：前面的 `python` 是**喊翻译官喵的名字**（叫它出来干活），后面的 `hello.py` 是**你要它跑的那份文件**。回车一按，翻译官喵就从文件的第一行开始，一行一行往下念、往下做。

本喵把三段喂猫流程写进 `hello.py`，真跑一遍给你看：

```python
print("拿起小鱼干")
print("放进碗里")
print("开饭啦喵！")
```

```text
拿起小鱼干
放进碗里
开饭啦喵！
```

你瞧，念一句做一句：三行代码，屏幕上就依次冒出三行字。**翻译官喵是从第一行开始、一行一行往下走的**，所以屏幕上的顺序就是代码里的顺序。

**从上往下、念一句做一句**——解释执行的全部脾气就在这儿：先看懂这一行，做完它，才轮到下一行。屏幕上的顺序，永远等于代码里的顺序。

现在的写代码软件（VS Code、IDLE、PyCharm 这些）里，都有一个**运行按钮**，按一下代码就跑起来了。其实它背后干的活儿，就是替你在命令窗口里敲了那句 `python hello.py`——只不过把命令窗口藏了起来，只把结果端到你面前。所以记住这句：**按钮是糖，命令是饭**。哪天按钮不灵了，敲命令照样跑得起来喵。

两种方式怎么选？本喵把差别列成一张表：

| | 问答摊（交互式环境） | 写进文件再运行 |
|---|---|---|
| 怎么说话 | 一句一句敲，回车就答 | 一次写一整份，再喊一次跑 |
| 适合干什么 | 试一小口、算个数、验证某个写法 | 一整套程序，想存下来反复跑 |
| 关掉窗口以后 | 刚才敲的全没了 | 文件还在，随时能再跑一遍 |
| `>>>` 是谁写的 | 猫咪自己冒出来的——那是递话筒 | 千万别写进去 |

::: tip 猫咪提示
今天记住三句就够：① Python 的翻译官喵是**念一句翻一句**（解释执行），从上往下、念到哪儿做到哪儿；② 想试一小口，就在命令窗口敲 `python` 回车进**问答摊**，看到 `>>>` 就能说话；③ 想留下成品，就写进 `hello.py`（`.py` 是门牌），再用 `python hello.py` 喊它跑。
:::

::: warn 小心喵
两个最容易踩的坑，本喵先替你标出来：

- **`>>>` 不是代码。** 它是问答摊递话筒的记号。谁要是把它抄进 `hello.py` 里，翻译官喵一读就卡住——它根本不认识这三个字符。
- **文件里不写 `print`，它就不吭声。** 问答摊会把你敲的东西念回来，文件可不会：文件里只有你**明确写出**的 `print`，才会出现在屏幕上。所以「代码明明写好了，怎么屏幕上一个字都没有？」十有八九是漏了 `print` 喵。
:::

## 小任务

跟着本喵的顺序，自己走一遍：

1. 打开命令窗口，敲 `python` 回车。看到 `>>>` 了吗？对它敲一句 `print("问答摊开张啦")`，看它回你什么。
2. 接着敲 `1 + 1`，看看不写 `print` 它到底答不答。
3. 敲 `exit()` 出摊，然后新建一个 `hello.py`，把刚才那三行喂猫代码写进去，再用 `python hello.py` 跑一遍。

同一句话，在摊子上跑一遍、在文件里跑一遍——你就摸到「解释执行」的脾气啦。下一课，本喵带你去看看代码里的数字和文字，是怎么住进小鱼干仓库的喵～ 🐾
