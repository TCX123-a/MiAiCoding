## 钩子：同一句话，念到第三遍就烦了喵

本喵每天早上带三只小猫记账，开场白都得重念一遍：

```text
小橘，早上好，今天也要好好吃饭喵～
狸花，早上好，今天也要好好吃饭喵～
三花，早上好，今天也要好好吃饭喵～
```

三天下来，本喵的舌头都打结了：**只有名字不一样，其余每个字都得重敲一遍。** 更糟的是，哪天想改一句台词，本喵得把三行一起改 —— 漏掉一行，三花就要听到过期的话。

要是能把这段活儿**打包**起来、钉上一块名牌，往后只报名字（再顺手把「今天轮到谁」喂进去），那该多省事喵。

这个「打包」，就是今天的主角：**招式（函数）**。一次登记、随叫随到 —— 这是你亲手造的第一个零件喵。

## 一、`def`：把自己的第一招记下来

登记一招用的是 `def`（英文 define 的缩写，本喵管这一行叫**起手式**）。先看一个最小的：

```python
def greet():
    print("你好喵～")

print("上课前")
greet()
print("下课后")
```

```text
上课前
你好喵～
下课后
```

咦，屏幕上第一条怎么是「上课前」？本喵明明把 `def` 写在最上面呀。逐块拆开看，顺序就明白了：

- **`def greet():`** —— 这一行只是**登记**：本喵在招式簿上写下「有这么一招，名叫 `greet`，里头干这几件事」。**登记的时候，招式一步都不会动**，翻译官喵只是把它记下来。
- **缩进的那一句** —— 招式的身体。缩进 4 个空格，意思是「这句属于上面这一招」。缩进的规矩和 `for`、`if` 那一套一模一样：冒号后面往里让一格，同一层的活儿缩得一样多喵。
- **`greet()`** —— 这才叫**施展**（术语里说「调用」，本喵说「喊一声」）。招式名后面跟一对小括号，招式簿上包着的活儿就从第一句跑到最后一句。
- **空括号 `()`** —— 这一招什么都不要，所以喊它的时候括号里空着。

**「登记」和「施展」是两件事** —— 这是今天的第一个坑，也是最容易摔的那个喵。

::: warn 小心喵
有两个「不报错、但屏幕上什么都没有」的坑，本喵都摔过：

1. **登记了，却没喊一声。** 只写 `def greet():` 和它的身体、忘了写 `greet()`，程序会安安静静地跑完，屏幕上**一个字都没有**。翻译官喵心想「你让我记下来，我记下来了；你又没喊我，我干嘛要动」—— 它一点毛病都没有，你也没法从报错里看出问题。
2. **喊的时候把小括号丢了。** 写 `greet` 是「指着招式簿上这个名字说：喏，就是它」；只有写 `greet()`（**带上小括号**）才是「施展」。少这一对括号，照样不报错、照样什么都不发生。

记住判据：**报名字不带括号 = 只是指了一下；报名字带括号 = 现在立刻动手。**
:::

还有个坑，是眼睛一花就会犯的 —— 把冒号漏了：

```text
def greet()
    print("你好喵～")

greet()
```

本喵把这行敲进翻译官喵的耳朵，它当场翻脸：

```text
  File "...\main.py", line 1
    def greet()
               ^
SyntaxError: expected ':'
```

`SyntaxError` 是「**话没说圆**」—— 句子的形状不对，它连往下读都读不了。最后那句 `expected ':'` 是它在说：「本喵站在这儿，正等着一个冒号呢。」所以记牢：**招式名后面那对小括号、和紧跟的冒号，一个都不能少喵。**

## 二、投喂的小鱼干：让招式别再写死

刚才那一招太死板了 —— 念什么全写死在招式里，想让三只猫各听各的那一句，就得写三招。本喵换个写法：在招式簿上先摆一只**空碗**，碗上写个名牌，施展的时候往里放东西。

```python
def greet(name):
    print(f"你好，{name}喵～")

greet("小橘")
greet("狸花")
```

```text
你好，小橘喵～
你好，狸花喵～
```

- **`def greet(name):` 里的 `name`** —— 登记招式时先摆出来的空碗。术语表里管它叫**投喂的小鱼干（参数）**：它只是「施展时要往这儿放东西」的记号，此刻碗里还是空的。
- **`greet("小橘")`** —— 施展时把 `"小橘"` 这条小鱼干**喂进碗里**。这一趟跑起来，招式里的 `name` 就当作 `"小橘"` 用。
- **`greet("狸花")`** —— 同一招，第二次喂的是 `"狸花"`。所以屏幕上多了一行，两行只差名字。
- 招式里的 `name` 是**招式自己内部的叫法**，和你外头建的仓库互不打扰：招式跑完，这只碗也就收起来了。

**一次登记，喂什么都行** —— 这才是「打包」最值钱的地方：重复的话只写一遍，剩下的交给喂进去的小鱼干。

### 好几只碗：按顺序一一对应

要喂两样东西，就在括号里摆两只碗，用逗号隔开：

```python
def show_fish(name, count):
    print(f"{name}今天有 {count} 条小鱼干喵")

show_fish("小橘", 3)
show_fish("狸花", 5)
```

```text
小橘今天有 3 条小鱼干喵
狸花今天有 5 条小鱼干喵
```

- 登记时 `(name, count)` 摆了两只碗，施展时就得喂两样，**按顺序一一对应**：第一位喂给 `name`，第二位喂给 `count`。
- 喂反了会怎样？写 `show_fish(5, "狸花")`，翻译官喵**不会拦你** —— 它老实照做，然后印出「5今天有 狸花 条小鱼干喵」这种驴唇不对马嘴的话。碗是照名牌收东西的，它不检查你喂进来的到底是不是那个意思。
- 少喂一样也不行。本喵写好招式，喊的时候却忘了喂名字：

```text
def greet(name):
    print(f"你好，{name}喵～")

greet()
```

翻译官喵当场拦下：

```text
Traceback (most recent call last):
  File "...\main.py", line 4, in <module>
    greet()
TypeError: greet() missing 1 required positional argument: 'name'
```

最后那句翻译过来是：「**这一招还缺一样非喂不可的东西，名字叫 `name`。**」喂少了当场断气；喂多了它也照样翻脸。**摆了几只碗，就喂几样 —— 一样不多、一样不少、顺序不错**喵。

::: tip 猫咪提示
投喂三句话，抄在招式簿封皮上：

1. **碗摆在小括号里**（`def greet(name):`），名字随你起，招式里都按这个名字叫它。
2. **喂的东西按位置对号入座**：第一位进第一只碗，第二位进第二只碗。
3. **碗的数目就是喂的数目**：少了、多了，翻译官喵都要炸毛。
:::

## 三、`return`：把战利品叼回来

招式不光能干脏活，还能**顺手叼点东西回来**。叼东西用的是 `return`，术语里叫**叼回来的战利品（返回值）**。

```python
def add_fish(a, b):
    return a + b

total = add_fish(3, 5)
print(total)
print(add_fish(10, 1))
```

```text
8
11
```

- **`return a + b`** —— 招式算完 `3 + 5`，把 `8` **叼回**到喊它的那个地方。
- **`total = add_fish(3, 5)`** —— 喊一声、喂两条小鱼干，招式把 `8` 叼回来，正好落进 `total` 这个仓库。战利品和普通的数一样，**能存进仓库、能接着算、能喂给别的招式**。
- **`print(add_fish(10, 1))`** —— 这一趟喊招式的地方直接就是 `print` 的投喂口，`11` 一被叼回来就顺手印了出去。

战利品还能接着参与运算：

```python
def double(n):
    return n * 2

print(double(3) + double(4))
```

```text
14
```

`double(3)` 叼回 `6`，`double(4)` 叼回 `8`，两个战利品相加得 `14` —— **招式喊出来的东西，就是一个普普通通的值**，放在哪儿都行喵。

### 见好就收：`return` 一跑，招式就收工

`return` 除了「叼东西」，还有个脾气：**它一执行，这一招当场结束** —— 后面就算还排着活儿，也不干了。

```python
def check(n):
    if n > 0:
        return "还有鱼干喵"
    print("这句只在没战利品可叼的时候才轮到")
    return "碗空了喵"

print(check(5))
print(check(0))
```

```text
还有鱼干喵
这句只在没战利品可叼的时候才轮到
碗空了喵
```

- 第一次喊 `check(5)`：眼色答「真」，`return` 当场把战利品叼走，**下面那句 `print` 根本没轮到**。
- 第二次喊 `check(0)`：眼色答「假」，先印那句话，再 `return` 收工。

所以 `return` 还有个别名：**提前收工**。想让它别急着走，就得把 `return` 挪到招式的最末尾。

### `print` 和 `return` 是两回事（今天最扎心的坑）

这两个词长得像、干的活却完全不同，本喵把它们摆在一起比一次：

```python
def add_fish(a, b):
    print(a + b)

total = add_fish(3, 5)
print(total)
```

```text
8
None
```

看清楚：第一行 `8` 是招式里那句 `print` 喊出来的；第二行的 `None` 就蹊跷了 —— `total` 怎么会变成 `None`？

因为这一招**只喊了，没叼**。`print(a + b)` 是把结果**喊出来给主人听**，喊完就散了；喊招式的那个地方手心里空空的，`total` 自然也装不到东西。Python 给「空手」留了一个专门的记号：`None`，意思是「**这儿什么都没有**」。

所以这三句话的分工是：

- **想让屏幕看见** → 用 `print`。
- **想把结果交回给喊招式的地方接着用** → 用 `return`。
- **两个都想要** → 招式里 `return`，外面再 `print` 一次。

::: tip 猫咪提示
今天四样东西，一句话串起来喵：

**`def` 起手式登记招式 → 报名字带 `()` 施展 → 括号里的空碗接住投喂的小鱼干 → `return` 把战利品叼回喊招式的地方。**

再补一条：没写 `return` 的招式，叼回来的是 `None` —— 这不是出错，是「本喵只干活，不带东西回来」喵。
:::

| 写什么 | 本喵的说法 | 干什么用的 |
|---|---|---|
| `def greet(name):` | 起手式 | 在招式簿上登记一招，括号里摆好空碗 |
| `greet("小橘")` | 喊一声施展 | 让招式真的跑一遍，括号里喂小鱼干 |
| `name` | 投喂的小鱼干 | 招式内部对「喂进来那样东西」的叫法 |
| `return a + b` | 叼回来的战利品 | 把结果交回喊招式的地方；不写就是 `None` |
